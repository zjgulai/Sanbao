## 1. 目标与边界

**目标**：把 Sage 自有薄壳消费的内核（seed 41 依赖 = 38 个 `@deepseek-ai/dsh-*` + cordis 族 3 个，加上壳 devDeps 的 `@deepseek-ai/*`）从 0.1.5-rc.2 一次性换装到 **0.2.0-rc.2**，在**当前 Sage 骨架不变形**（自有壳、自有 renderer、自持 FD3/FD4 传输、自有 OIDC 身份、Application Service 边界与数据治理纪律全部保持）的前提下，完成编译面迁移、fixtures/goldens 重锚、协议自有权收口与隔离验证，并给出可一键回退的证据链。

**本轮明确不做**：
- 不改 `vendor/dsh-desktop` fork、legacy 运行链、旧 DMG / release、`~/.dsh` 旧 profile（research/20 §7）。
- 不跟随上游「共享 Web 应用 / localhost URL」新桌面架构——Sage 传输两端自持，换轨是独立产品决策（D2 后果里登记）。
- 不消费上游新增产品面（账号、插件管理器 UI、settings 表单、client UI 新版 primitives）；不把 optional bundles 纳入 seed。
- 不在本任务内改 PMAP 源面 / C2C 外部能力面（登记为后续票，§8）。
- 本轮**零实现**：所有变更由 plan 的 K 票在两会话收口后按前置条件执行。

## 2. 决策

**D1 · 目标与纪律**：单步换装到 0.2.0-rc.2；ADR-0006 立场在执行 Note 里显式记录——「大版本迁移由需求驱动（用户 2026-10-02 立项）；目标为 3 天新鲜的 pre-release；Sage 尚未出货，爆炸半径限开发环境；保留 pin+lock 一键回退」。不取两步式（0.1.7-rc.2 与 0.2.0-rc.1 仅隔 4 天，重复两遍安装/验证无可证收益）。
**D2 · 传输与协议自有权**：上游已删除 FD3/FD4 wire 参照（research/20 §3.1）——Sage 协议 v4 的六个 framing 常量**值不变**（保持兼容），所有权明确归 Sage；`sage-shell-pin` 从「对齐上游 wire.ts」改为「**冻结字面量断言 + 变异自测**」，删除 submodule 参照输入与 degraded-note 路径；执行时配 ADR（承接 ADR-0168 的自有方向；ADR 编号按执行时索引分配，预计 0192+）。这是「参照源消失」的诚实收口，不是放松——检查强度从『会漂移的对照』变成『不能被静默改动的冻结值』。
**D3 · seed 最小演进**：`@deepseek-ai/dsh-code-runtime` → `@deepseek-ai/dsh-ptc-runtime`（worker 提供方由 base bundle 传递）；其余 37 个 `dsh-*` 原位升 0.2.0-rc.2；cordis 族（cordis `4.0.4`、include `1.0.9`、group `1.0.4`）并入两侧同步。**不主动纳入任何新包**（session-format-v3-to-v4 等由依赖闭包传递）；`pnpm-workspace.yaml` 两个 override 原样保留；`dsh.profile.patchReload` 字段按 K3 实测处置（0.2.0 已不再消费该字段）。
**D4 · 隔离验收 + 回退**：一切装、跑、验都在 `SAGE_ROOT=<临时根>` 的隔离实例上（共享数据根在两会话收口前不碰）；回退 = pin/lock/seed 三件回撤 + 重物化（旧 generation 留盘，见 §6）。
**D5 · 隐私默认审计**：0.2.0 把 `session-log-deepseek` 上传改成默认 **true**（另加 OTel / product-analytics）——与 Sage 的凭据/隐私红线冲突面**显式默认关**（Sage profile 叠加行或 config），落独立 ADR。Sage 自有 OIDC 身份与上游 `deepseek-account` 无关；后者在 Sage 启动器（无 `profileContext`）下自动关闭，K6 实测确认。
**D6 · 排程与禁区**：开工前置 = **两会话均收口**（7365c577 已达成；ddd80099 收口后开工）；每个 K 票提交前先 `git status`/`git log origin/main` 复核无新会话提交；**pin 变更（K1）与行为变更（K3+）分开提交**（ADR-0008）。
**D7 · 文档三件套**：证据=research/20；决策=本 spec；任务=plan。一份事实一个家，互相链接。

## 3. 变更面明细（执行时的精确落点）

### 3.1 seed（`apps/sage-shell/seed/package.json`）

- 41 个依赖（38 个 `dsh-*` + cordis 族 3 个）全部精确改版：37 个 `dsh-*` 原位升 `0.2.0-rc.2`，`dsh-code-runtime` 一行替换为 `dsh-ptc-runtime`；cordis `4.0.4` / include `1.0.9` / group `1.0.4`。
- `dsh.profile.bundles` 保持 `[dsh-base, dsh-web-app]`（smoke 断言依赖，勿动）。
- `dsh.profile.patchReload`：0.2.0 app-boot 不再消费（`DEFAULT_PROFILE_PATCH_RELOAD` 已删）——K3 实测「新忽略 vs 判红」；若忽略则删除该字段（减少一处非法源的暗示），若判红则必须删除；两者都同步检查 smoke/测试是否有引用。
- `seed/pnpm-lock.yaml` 重生成（隔离根内 `pnpm install` 产出后入库）。

### 3.2 壳（`apps/sage-shell/package.json` + lock）

- devDependencies 中 7 个 `@deepseek-ai/dsh-*` → `0.2.0-rc.2`；`@deepseek-ai/cordis` `4.0.2` → `4.0.4`；`@deepseek-ai/cordis-plugin-include` `1.0.7` → `1.0.9`；`electron` 保持 `43.3.0`（与 vendor 对照一致性门禁的锚未变）。
- `apps/sage-shell/pnpm-lock.yaml` 重生成；两个 `pnpm-workspace.yaml` 的 `dsh-type-meta` / `dsh-user-interaction` override 原样保留（该两包 npm 依旧 404，实测）。

### 3.3 协议与门禁（`src/protocol.ts` 不动值；`scripts/gates/sage-shell-pin.mjs` 改造）

- `protocol.ts`：**六个常量值冻结不变**（`SHELL_REQUEST_PIPE_FD=3`、`SHELL_RESPONSE_PIPE_FD=4`、`SHELL_PIPE_CHUNK_BYTES=65536`、`FRAME_MAGIC=0x44534833`、`FRAME_HEADER_BYTES=13`、`MAX_CONTROL_PAYLOAD_BYTES=1048576`）+ `SHELL_HOST_PROTOCOL_VERSION=4`（已有断言保留）。
- 门禁改造：删除 `FRAME_PROTOCOL_CONSTANTS` 对照与 `referenceWireText` 输入（`scripts/gate.mjs` 收集处同步删）与 degraded-note 的 wire 分支；改为对 `protocol.ts` 断言上述**冻结字面量**；`sage-shell-pin-selftest` 增一条变异用例（把 fixture 中任一常量改值 → 必须判红；未变异副本必须绿）。remediation 文案同步改写（去掉「以 vendor wire.ts 为准」）。
- 说明与留痕进 D2 的 ADR/Note。

### 3.4 参照与 pin（`vendor/dsh-desktop/deepseek-harness` + `vendor/dsh-desktop.pin`）

- K1 独立提交：子模块检出 `639ed015397290b3745d163aafe02ffee4aa3f84`；pin 文件 `harness-submodule` → 同值、`checked-at` → 2026-10-02；`harness-runtime-source` 行（legacy fork 物化）**不动**（legacy 链不在射程，research/20 §7）。
- 建议顺带在检出内建本地 tag `dsh-v0.2.0-rc.2`（否则浅克隆无 ref 可指向；`FETCH_HEAD` 会被后续 fetch 覆盖）——K1 执行时定夺并在提交信息记录。

### 3.5 fixtures / goldens（K5，按三类处置）

| 类 | 例子 | 处置 |
|---|---|---|
| 机械版本字符串（语义=「当前版本」） | `test/support/runtime-inventory-fixture.ts:40 HARNESS_VERSION` 及其派生断言 | 改 0.2.0-rc.2，跑测试验证 |
| 冻结 golden（内容寻址） | `runtime-inventory.spec.ts:37` canonical 串（含 `harnessVersion`）；C2E.2 的 13 条冻结字面量 golden | **用真实生产者重算后重冻结**（禁手改字面量；沿用「一次性脚本实算→固化」纪律） |
| 任意标记值（语义=「非空版本」） | `host-process.spec.ts` stub、`fixtures/profile*/node_modules/@deepseek-ai/dsh/package.json` | 逐个读断言决定：只当标记则保留；断言等值则升级 |

`fixtures/profile*` 两个 `@deepseek-ai/dsh` fixture manifest 的版本字段与 `TRACKED_FIXTURES` 门禁清单无耦合，可择一保留/升级，K5 记录选择理由。

### 3.6 overlay 复核（K6）

`config/shell.cordis.patch.yml` 的 8 个 id 与 2 个 insert 包名已在两版本预先核验存活（research/20 §3.3）；K6 在隔离实例实测：(a) 启动无「patch: entry ... not found」类告警；(b) `profileContext` 门禁行（settings/hmr/config-editor/plugin-manager/deepseek-account）在 Sage 启动器下如实关闭；(c) `connection: inject:[credentials]` 行在 connection 换代后仍生效。

### 3.7 PMAP 与隐私（K7）

- **PMAP 源面登记**：`runtime-inventory-pmap.ts` 依赖的 `dsh-agent-presets/presets`（包已删）与 `settings.yaml` 静态读（将被导入改名）在 0.2.0 失效/语义迁移——K7 只**登记 + 出后续票口径**，不在换装票内改 PMAP（其收口件在 `7256f4f`，改动另立）。
- **隐私默认**：隔离实例上实测 `session-log-deepseek.enabled`、OTel、product-analytics 的生效面；Sage 组合**默认关**（叠加行），落 ADR。核对新 telemetry 域名变化不进入 Sage 默认面。

# 2026-09-18 · 边框四级改为半透明叠加：把 1.18–1.59 倍的可见度漂移收回到 Harness 口径

关联：[ADR-0104](../../../adr/ADR-0104.md)（Codex 视觉语法与 `dsh-theme-local` 为唯一 token owner）、
[ADR-0115](../../../adr/ADR-0115.md)（alias 全量接管的覆盖口径）、
[ADR-0029](../../../adr/ADR-0029.md)（主题 Token 判据要两侧共同证伪）、
[ADR-0015](../../../adr/ADR-0015.md)（非机械改动必须留痕）。
同一轮的呈现层改动：[2026-09-17-appearance-contrast-and-share.md](2026-09-17-appearance-contrast-and-share.md)。

## Problem

**现象。**「所有组件都有外边框，而且很丑」。这句话一半是错的，一半是真的：

- **错的这一半**：实况暗色主题、dpr=2、视口 1492×940 下，10,473 个元素里只有 **285 个有边框（2.7%）**。
- **真的这一半**：线宽分布 `0.5px → 219（77%）`、`1px → 64`、`2px → 2`；按 token 归属
  `l1 → 172（60%）`、`l2 → 83`、`l3 → 24`、`l4 → 3`；而对比度分档是
  `≤1.10 → 135`、`1.10–1.25 → 17`、**`1.25–1.5 → 105`、`>1.5 → 28`** ——
  **285 条里 133 条（47%）落在「清晰可见」及以上**。上游的意图是发丝线，不是结构线。

**根因（等口径实测，非推断）。** Harness 的边框语言是 **`0.5px` 发丝线 + 6–20% 透明度**：
上游 `dsh-client-ui-*` 的边框声明里 `.5px` **123 条** vs `1px` 8 条（**89% 是 0.5px**），
四级 token 的 shipped 值是 `#0000000a / #0000001a / #0000001f / #00000029`（浅）与
`#ffffff0f / #ffffff1f / #ffffff29 / #ffffff33`（深）。

我们把它们改成了 **不透明的 oklch 混比**（`color-mix(in oklch, #FFF n%, <background>)`）。
`oklch` 的 n% 是**感知明度往白推进整个量程的 n%**，等价的 alpha 远高于 n% —— 在同一个
真实 CSS 引擎里算对比度：

| 级 | Harness shipped | 对比度 | 我们的值（改前） | 对比度 | 漂移倍数 |
|---|---|---|---|---|---|
| **l1**（用量 **60%**） | `#ffffff0f` (5.9%) | 1.159 | `color-mix(in oklch,#FFF 10%,#181C1A)` → `#312c2d` | 1.253 | **1.59×** |
| l2 | `#ffffff1f` (12.2%) | 1.414 | → `#3c3839` | 1.489 | 1.18× |
| l3 | `#ffffff29` (16.1%) | 1.622 | → `#484446` | 1.796 | 1.28× |
| l4 | `#ffffff33` (20%) | 1.870 | → `#595556` | 2.343 | **1.54×** |

**用量最大的 l1 恰是被抬得最狠的一级。** 再乘对比度滑杆 `k(c)=0.6+0.8·(c/100)`，
c=100 时边框等效混比推到 ~42% —— 分隔线在那里开始读成结构。

**一条被证伪的假说（写下来免得下次再猜）。** 曾怀疑「0.5px 偏离设备像素网格 → 被抗锯齿
摊成 2px 模糊带」是主因。**逐边实测不成立**：视口内 top 边框 `8/8` 全对齐、bottom `9/9`
全对齐；只有 left/right 有 40–56% 偏网格，且集中在**行内 `code`**（文本流天然产生小数宽度）。
故与本缺陷无关，未据此改动任何几何。

**两台仪器自身的缺陷（同一轮修掉）。** ①v1 审计把 155 条边框误判成 **2 条**：Chromium 把
`color-mix` 派生的 `border-color` 序列化成 `oklch(L C none)`，而 v1 的正则只认 `rgb()`；
改用 canvas 的 `fillStyle` 做颜色归一化后取到真值。②v2 的 off-grid 指标把四个边的偏移取
`max`，把滚动到 `-25658px` 的**视口外**元素算了进来；改为**逐边**统计并限制在视口内后，
结论从「84% 偏网格」变成「水平边 0% 偏网格」。

## Decision

1. **四个边框级别改为半透明叠加，alpha 取 Harness shipped 值。** 产出形如
   `rgb(255 255 255 / 0.059)`；基线（对比度 50）与上游**逐位相同**
   （实测 `alphaEqual: true`：`0.058824 / 0.121569 / 0.160784 / 0.2`）。参照值以 8 位 hex
   落在 `HARNESS_BORDER_OVERLAYS` 常量里，**下次改动必须与源头争，而不是与手打百分数争**。
2. **边框走独立的 `borderFactor`，不再搭 `scale()` 的车。** `scale()` 是标签/表面/悬停共用
   的系数，动它等于改对比度滑杆的**文字**语义（那是这个控件的主职）。`borderFactor`
   区间收窄为 `0.75 → 1.25`（原 `0.6 → 1.4`），50 基线仍恒等 1。实测 `label-secondary`
   黄金值在 `lightContrast: 100` 下仍是 87%，**未受影响**。
3. **叠加而非不透明混合，是这条决策的实质。** 除了重量正确，alpha 还让线条在
   `bg-layer-1/2` 等抬升表面上自动正确 —— 不透明地由 `background` 派生只在 base 底色上对。
   所调研的每一套设计系统（Radix alpha 阶、Geist "Gray alpha"、shadcn 暗色 10% 白、
   Tailwind v4 交给上下文定义）都用 alpha 台阶承载边框。
4. **把不变量落成测试，不落成散文。** `theme-tokens.test.ts` 新增一条：在对比度
   `0/25/50/75/100` 五个点上，四级边框必须匹配 `/^rgb\((?:0 0 0|255 255 255) \/ (0\.\d+)\)$/`
   （即**仍是叠加**）、必须严格递增、且上限 ≤ `0.25`。突变控制实测：把产出改回不透明混合，
   **4 条测试同时判红**。
5. **`studio.css` 的 21 处发丝线里改 20 处 `1px → 0.5px`，保留 1 处。** 保留的是
   `[data-appearance-swatch-chip]` 的选中环 —— 它的选中态只换 `border-color`，
   **描边是唯一线索**，按「描边作为唯一状态线索时不降权」保留 1px，并在样式表里写明理由。
   设置页的焦点指示与实际边框无关（独立的 `2px` accent `outline` + `offset`），故降宽不削弱焦点可见性。
   错误态同理：`[data-appearance-chip-hex][aria-invalid]` 另有红色文案 `[data-appearance-chip-error]`。
6. **明确不动**（本轮决策）：profile 安装的第三方包 `dsh-better-sidebar` 的 18 条 `1px`
   （不在仓库，改它只能越 ADR-0026 的覆盖红线或向上游提 issue）；品牌徽标
   `dsh-root-brand-local` 的 `dsh-rb-agentic` 1px 绿边（刻意品牌描边）。

## Alternatives considered

- **「去掉所有边框」。** 否。上游 200+ 条边框声明不在我们的层里，要盖掉只能写宽选择器 CSS
  （`* { border-color: transparent }` 一类），与「官方 UI 改写锚禁止钉哈希」同族风险；
  且行业收敛结论明确：**缺陷通常是线的条数而非深浅，但「铺满描边」正是控件边界的必要手段** ——
  当描边是控件唯一的边界线索时要 ≥3:1（M3 `outline` 4.44:1、Radix step 7、shadcn `--ring`），
  一刀切会同时干掉输入框与焦点环。
- **只改颜色不动 `studio.css`。** 否。设置页 21 处 `1px` 是上游语言的**两倍线宽**，
  且整数宽度会被吸附成硬边，不一起改则同类问题只解决了面板那一半。
- **改共享的 `scale()` 区间。** 否。它会连带改动标签与表面的对比度语义 —— 那是滑杆的主职，
  属于把两件事塞进一个系数。独立系数同时保住了既有的 `label-*` 黄金值。
- **把边框 alpha 硬 clamp 到某个上限。** 否。clamp 会在滑杆高段造出**死区**
  （l4 在 c≥70 后不再变化），控件手感上像坏了。收窄区间即可单调且有界。
- **把 `file:` 硬链接和 mode 问题一并处理。** 本轮不做（见 Consequences）。

## Consequences

- **收益**：四级边框的可见度漂移从 `1.18–1.59×` 收到 `1.04–1.10×`；同底时**恰为 1.0000**。
  残余的 1.04–1.10 已归因证明**全部来自底色差异**（我们 `rgb(24,28,26)` vs 上游 `rgb(21,21,23)`），
  而表面相对正是 alpha 应当具有的行为 —— 不是 token 偏差。改后四级对比度
  `1.175 / 1.441 / 1.652 / 1.901`（改前 `1.253 / 1.489 / 1.796 / 2.343`）。
- **受影响面**：一趟改动覆盖全部 285 条边框的**颜色**，其中 219 条 `0.5px` 的线宽本就不动；
  设置页的 20 处线宽减半。字形、强调色、对比度滑杆的**文字**行为全部不变。
- **诚实划界（未做与未验）**：
  1. **端到端实况验收未做**：活动实例此刻仍跑旧主题，新值生效需**重启 DSH**；
     本轮的实况读数是「按新值在本页真实引擎 + 本页真实底色上会画成什么」，不是「已经画成这样」。
  2. **未处理**：`dsh-better-sidebar` 的 18 条 `1px`、品牌徽标 4 条（本轮决策明确不动）；
     故应用里仍存在与 0.5px 语言不一致的线。
  3. **未登记 ADR**：`docs/adr/README.md` 正被**并发会话**持有未提交改动，本 Note 未去改它；
     这条决策目前挂在 ADR-0104 / 0115 / 0029 之下，**尚未取得自己的编号**。
  4. `docs/pitfalls-playbook.md` 应加两条（「仪器正则不认引擎的序列化 ⇒ 假绿」与
     「聚合指标跨语义求和 ⇒ 假红」），该文件同样被并发会话持有，未碰。
  5. 工具缺陷未修：`edit` 工具**无条件**把目标文件写成 `mode 0000`（实测 0644 → `----------`、
     0600 → `----------`），`write` 新建文件写死 `0600`（不遵循 umask=0022）。git 不受影响
     （索引里仍是 `100644`），但工作区文件会变得谁也读不了，须每次 `chmod 644` 修回。
     全仓另有 **1,722 个 `0600` 文件**（agent `write` 的历史产物），未做批量归一（属 R2）。

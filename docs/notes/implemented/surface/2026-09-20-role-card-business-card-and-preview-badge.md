# 决策记录：岗位名片版式与官方预览角标移除——把面板从「信息清单」改成「名片墙」

- 日期：2026-09-20
- 状态：implemented（仓库侧 + 两个装载点已同步 + 重启后实机浏览器验收完成，读数见下）
- 对应 ADR：[ADR-0142](../../../adr/ADR-0142.md)（D1–D5）、[ADR-0019](../../../adr/ADR-0019.md)（D2 被本轮取代）、[ADR-0136](../../../adr/ADR-0136.md)（D4 字形分工）、[ADR-0135](../../../adr/ADR-0135.md) D1（判据读真实值）
- 涉及包：`packages/surfaces/dsh-role-matrix-local`（名片版式 + 字号阶梯）、`packages/platform/dsh-root-brand-local`（角标处置）
- 归属计划：[.scratch/sanbao-reskin/tickets/023-头像自研渲染面.md](../../../../.scratch/sanbao-reskin/tickets/023-头像自研渲染面.md)（自研渲染面延伸）、射程表 20 处可见面

## Problem

三宝换皮把「资产层」做完之后，用户看真机给出的三条反馈，指向的是**同一个根因**：面板与 hero 的
排版语言还停在换皮之前，资产（50 张双色道头像）已经换好了，但**版面还是旧的收法**。

1. **「把对话框上方的 `Preview` 字样去掉」**。它来自官方 `hero.preview` 角标（`预览版`/`Preview`）。
   ADR-0019 D2 的处置是「保持官方节点、只把文本改写成 `Preview`」——那是为「一个叫 Preview 的产品」
   服务的。三宝不是预览版产品，用户裁决直接去掉。
2. **「字号的大小跟实际页面完全不搭，字号的层级关系也需要在这次做深度调整」**。面板里 11/12/13/14px
   四种字号混摊在标题、分区、卡片、徽标、详情五类信息上，**层级不可辨**；实际页面的正文是 13–14px，
   面板通篇偏小一档。
3. **「头像太小，头像要像我们的名片风格一样：左上角是头像、下方是工号，右边是岗位职责简介，
   文字不能太多」「整个卡片框的宽度需要调大，一行就排 3 个名片」**。当时是 34px 圆头像 +
   姓名/岗位 + 一排徽标 + 标准产物行；头像在卡里只是个小图标，**读不出「一个人」**。

值得记一笔的失效模式：这三条都不是「代码写错了」，而是**换了资产却没换版面**——换皮计划把
「资产层 / 渲染面 / 版面」当成一件事排期，实际它们是三层。资产（头像 webp、双色道）落地了，
渲染面（`object-fit`、圆形槽）落地了，**版面（谁大谁小、一张卡放几个字段）没动**，
于是用户看到的是「铺了新头像的旧卡片」。

## Decision

按 [ADR-0142](../../../adr/ADR-0142.md) D1–D5 执行：

- **角标（D1）**：`hero-title.ts` 的隐藏器接管角标——**整节点隐藏**（`display: none` +
  `dsh-rb-hidden` 标记），文本原样不动；原 `official-text.ts`（文本改写 + 独立观察器）删除，
  两个角标文案常量迁到 `hero-title.ts` 作为「不是标题」的排除表。角标仍是**定位官方标题的锚**，
  且它是「被正向识别」的节点，因此读数降级为 `no-candidate`/`ambiguous` 时**角标照旧隐藏**，
  只有标题保持不动。
- **名片（D2）**：`.cardMain`（头像栏 + 正文栏 + 展开指示）替换原 `cardTop`；
  左栏 `cardId` = 96px 圆角方形头像槽 + 居中工号（mono）；右栏 `cardBody` =
  姓名（16/500）· 岗位（13）· 一句话职责（12，`-webkit-line-clamp: 2`）· 徽标行；
  `标准产物` 从名片正文移进展开详情（信息不丢，只是不挤在名片上）。
- **栅格（D3）**：`repeat(auto-fill, minmax(340px, 1fr))`，面板上限 `min(1200px, 94vw)`。
  1440px 视口实测 3 列 × 376px；更窄时按同一条规则降 2 列、1 列，**降列不降字号**。
- **字号阶梯（D4）**：五层，全部走 `--dsw-font-*`：20/500 面板标题 · 16/500 平面名与名片姓名 ·
  13/500 责任域名与详情标签 · 13 名片岗位/搜索/详情正文 · 12 职责简介/用途/计数/chip/页脚 ·
  11 工号与徽标。阶梯写在 `role-matrix.module.css` 文件头，判据钉在 `panel-layout.spec.ts`。
- **一句话职责（D5）**：新增纯函数 `card-brief.ts`，从官方 `description` 里**只做删除**——
  去掉前导【平面·域】、结尾〔…〕、第一个圆括号之后的补充说明与残留标点；删空则原样返回。

### 顺带修掉的一个沉睡缺陷（测试仪器）

`live-anchors.spec.ts` 里那条「React 换掉角标节点」的新用例一开始**永远看不到还原**。根因不在实现：
`installPlugin()` 从未被 dispose，而观察器挂在 `document.documentElement` 上，
`afterEach` 的 `document.body.innerHTML = ''` **摘不掉它**——上一个用例的插件继续对下一个用例的 DOM
动手，并且它记下的「隐藏前状态」其实是上一个用例的读数。修法是把装载过的插件登记进
`hero-fixture.ts` 的实例表，`afterEach` 调 `disposeInstalledPlugins()` 统一收口。
这类缺陷的形状是「仪器跨用例串味」，只有用例本身依赖「前一个用例没做过什么」时才会现形。

## Alternatives considered

| 决断点 | 未采用的方案 | 为什么 |
|---|---|---|
| 角标 | 保留角标、只把文本改成别的词（ADR-0019 原路线） | 用户裁决是**去掉**：角标陈述的是官方产品的发布状态，本产品不处在该状态 |
| 角标 | 只清空文本、留空 pill | 留下一个谁都说不出用途的空壳，比留着文案更糟 |
| 角标 | 角标随标题歧义一起「不隐藏」 | 角标是被正向识别的节点，歧义针对的是「谁是标题」，两者不该互相牵连 |
| 名片 | 圆形 96px 头像 | 圆是「头像」的语言，圆角方形是「名片/工牌」的语言；用户点明要名片风格 |
| 栅格 | `@media` 断点写死 1/2/3 列 | 断点要猜窗口宽度；`minmax(340px, 1fr)` 让**可用宽度**自己决定列数，判据也只需钉一个下限 |
| 职责 | 在宿主 `collect.ts` 里算好 `brief` 字段 | 这是显示投影不是数据事实；动宿主会波及路由/校验/manifest 形状，而 50 个 preset 的零扰动是上一轮的契约 |
| 职责 | 按字数硬截断成新句子 | 截断出来的是「另一句话」，读者分不清是被截了还是原文如此；删除只去掉重复的分区标签与产物清单，长度上限交给 CSS |
| 字号 | 直接写 px | Law C / ADR-0135 D1：规则一律走 `--dsw-font-*`，且断言读解析后的真实值 |

## Consequences

- **正面**：一张名片一眼能读成「一个人」（脸 + 工号 + 岗位 + 一句职责）；三列让 50 张卡在同一屏
  能扫描的数量从 9 张提到 9 张但每张信息量翻倍（实测卡宽 297 → 376px）；字号层级从「四档挤在
  11–14px」变成五档可辨；盘上少了一个模块（`official-text.ts` 删除）。
- **负面 / 已知边界**：
  1. **官方角标的隐藏等于本产品不再披露「上游处于预览版」这一状态**。这是用户裁决，
     但它是一个产品事实的移除，登记在此以免后来者误以为「官方没有这个角标」。
  2. **三列是可用宽度的函数**：面板宽度 < 1092px（≈ 视口 < 1162px）时降到两列。窄窗口下的
     预期是「降列不降字号」，不是「永远三列」。
  3. **展开详情会把该行撑高**（grid 行高由最高单元格决定），邻卡留白。这是既有行为，本轮未处理。
  4. **`cardBrief` 的删除规则依赖 description 的既有形状**（前导【…】+（标准产物：…））。
     上游换写法时它会**原样返回整句**（宁可长，不要空），但这一点**没有门禁盯着**。
     登记为已知边界：判断依据是 50/50 张卡实测同形，不是「形状不会变」。
  5. 官方设置页里的预设卡（同一批头像的**官方渲染面**）仍是圆形头像 + 官方排版，
     与本面板的圆角方形名片不一致——这是「官方面不在本仓射程」的既有残留。
- **验证读数**（2026-09-20，重启后 runId `5cc8220c-6583-43e4-8902-383ccdfceba1`，
  `finalStage=health-commit` / `rendererStatus=healthy`）：

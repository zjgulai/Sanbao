# 侧栏四带契约冻结：共识从「研究稿自证」改为「十项当场裁决 + 一份契约」

- 日期：2026-09-18
- 状态：implemented（契约冻结；P1 实现未开始）
- 对应 ADR：[ADR-0125](../../../adr/ADR-0125.md)
- 相关：ADR-0124（P0 启动带，本条**部分取代**其 D5）、ADR-0079（同列同行轴）、
  决策票 `.scratch/sidebar-research/N1-decision-ticket.md`（十项裁决的唯一记录）、
  总账 P-51（估算当读数）/ P-07（一条事实多个家）

## Problem

侧面导航讨论进入「写代码」与「有共识」脱节的状态，用户原话指出：
「我们还没有形成统一的侧边导航栏修改的共识方案」。取证确认三个结构性缺陷——

1. **编号同名异指**：研究规格 `spec.md` 的 D1–D5 与 `ADR-0124` 的 D1–D6 是两套编号，
   「D5」在两边指两件不同的事（宽度 vs 判据射程），任何引用都无法落位。
2. **记录强度 ≠ 共识强度**：研究规格把四带结构标为 `decisions_locked`，
   但用户只给过 P0 的口头放行（「同意 开始 P0」）；决策 Note 里「逐条批准」是记录时的高估（已订正）。
3. **量化前提证伪**：四带重组的宽度依据（DSH 350pt、五者最宽）是截图文本框范围估算；
   像素实测 279pt，落在参照带 252–280pt 内（基座契约 `layoutInfo.sidebar` 初值 280，双来源互证）。

## Decision

以 `.scratch/sidebar-research/N1-decision-ticket.md` 为载体，让用户在同一会话内**逐项当场裁决**
10 项（S-1…S-4、T-1…T-6），并冻结为一份契约 —— [ADR-0125](../../../adr/ADR-0125.md)：

- 四带结构成立并冻结（启动 / 能力 / 内容 / 系统）；
- 启动带行高 36px 定案（沿用 ADR-0124 的去按钮化形态）；
- **split 恢复为 API 可选形态**（`position` 四值、默认 `stacked`）——用户裁决前 P0 曾删除该实现，
  本轮为其恢复划了判据边界（双形态门禁必须在启用前补齐）；
- 「工作台 ▸」折叠组收编能力带四项；内容带增置顶与搜索，两次增项同进 P1；
- 侧栏宽度目标 **264px**（夹逼区间 [264, 420] 的下界；用户知悉 252 越界后改判）；
- 入口纪律升门禁（含**宽度断言**——补齐 P-51 登记的缺口）。

同步完成的一致性清算：四带前提被证伪的读数在四处出货面订正；「逐条批准」措辞订正；
P0 决策 Note 与 ADR-0124 的日期（误记 2026-09-19，实为 2026-09-18）改正。

## Alternatives considered

- **只冻结 P0 相关三条，其余留到下轮**：用户未选——他要的是「一次把四带契约全部谈完」；
  分两次意味着还没裁决的条目会继续以「默认」身份影响实现。
- **252px（精确比照 Qoder）**：否决——越出基座 `clampWidth(px, 264, 420)` 下界，
  正规路径到不了 252；CSS 强改会让拖拽手柄与渲染宽度脱钩，一拖就跳。
- **split 用户可切换（设置页开关 + 偏好持久化）**：本轮否决——票价选 API 可选以控制范围；
  切换载体另立决策。
- **内容带分期（P1 置顶、P2 搜索）**：用户未选——代价（P1 容量增大）已记入契约后果段。

## Consequences

- **分期重排**：P0（启动带去按钮化）已交付未提交；P1 = 「工作台 ▸」折叠组 + 置顶 + 搜索
  + split 恢复 + 264px 兑现 spike；P2 起为内容带其余增项。
- **门禁新账**：`sidebar-row-axis` 需新增宽度断言（ADR-0125 D8）；启用 split 前必须扩为双形态断言（D3）。
- **残余风险**：① L2 承载方式（官方 slot vs 注入）未决，是 P1 第一个 spike；
  ② 264px 的兑现依赖「插件能否写布局 store」——若不可写，只能由用户拖拽到达；
  ③ 参照宽度的 pt 换算依赖 2x retina 假设（已由契约默认 280 与实测 279 双来源互证）；
  ④ `pnpm run gate:full`、commit / push 均未做（R3 未授权），P0 代码不进入任何提交。

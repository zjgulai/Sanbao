# harness 0.2.0-rc.2 内核换装：pin 前进、帧常量自有权、seed 演进与隔离验收（K1–K6）

日期：2026-10-02 · 分类：architecture · 关联 ADR：[ADR-0192](../../../adr/ADR-0192.md)

## Problem

Sage 薄壳的程序性 pin 停在 deepseek-harness 0.1.5-rc.2；上游 0.2.0-rc.2（2026-09-29）把 FD3/FD4 传输整体删除、`settings.yaml` 退场、session 格式升 v4、包间改精确版本，并留下 0.1.5→0.1.7 窗口的 upgrade guide 缺口。三件套（[research/20](../../../research/20-harness-0.2.0-rc.2-delta.md)、[spec](../../../superpowers/specs/2026-10-02-harness-0.2.0-upgrade-design.md)、[K 票计划](../../../superpowers/plans/2026-10-02-harness-0.2.0-upgrade.md)）评审通过后，本 Note 记录 K1–K6 的执行与读数（K7 隐私默认属 [ADR-0193](../../../adr/ADR-0193.md)，K8 文档终验见后果节）。

## Decision

1. **K1 参照与 pin（`d31cfa1`，pin-only 独立提交）**：`vendor/dsh-desktop/deepseek-harness` 检出 `639ed015397290b3745d163aafe02ffee4aa3f84`（本地 tag `dsh-v0.2.0-rc.2`）；pin 文件 `harness-submodule`/`checked-at` 前进，`upstream-*`/`lute-*`/`harness-runtime-source` 不动；`pin-consistency` 绿。
2. **K2 帧常量自有权（`9d42a5d`）**：`sage-shell-pin` 删除 `referenceWireText` 输入与逐对参照比较，改为对 `protocol.ts` 断言六个冻结字面量（空白归一：`3`/`4`/`64*1024`/`0x44534833`/`13`/`1024*1024`）；selftest 替换为冻结值变异用例。**红/绿双向证明**：负控（关闭冻结循环）恰好让 3 条检测用例判红（18 pass/3 fail），还原后 21/21。
3. **K3+K4 换装与唯一行为适配（`01ceb2c`）**：seed 41 依赖改版（`dsh-code-runtime`→`dsh-ptc-runtime`；37 原位；cordis 族 4.0.4/1.0.9/1.0.4；`patchReload` 删除）；壳 devDeps 同版；两份 lockfile 重生成（seed 锁：2,652 处 0.2.0-rc.2、0 处 0.1.5-rc.2）。隔离根 `--frozen-lockfile` 真装 **598 解析/600 包**并激活 generation。编译面 **typecheck/build 0 错**。唯一行为断点：0.2.0 把不可装载 bundle 改为记入 `skippedBundles` 不抛错——`composeShellPatches` 重建 fail-loud（任一声明 bundle 被跳过即中止，携带上游 reason）；既有 composition 测试不改写即通过。
4. **K5 fixtures/goldens 重锚（`70c0bcc`）**：语义为「当前已装版本」的 fixtures 升 `0.2.0-rc.2`（runtime-inventory 家族 + protocol/host-entry/host-process/materialize 桩）；goldens 以真实生产者重算：**4 条 policy digest + liveness + registrySnapshot 独立未变**，receipt/materializationInstance/instanceAuthority/mainObservationProvenance/health + 稳定对 + host 投影 canonical/摘要重冻结（探针实算后固化，探针已撤）；compatibility/external-capability 的合成场景 fixtures 与两个 profile fixture manifest 刻意不动（非「当前版本」语义，随 C2C.5/MCP-SDK-2 工作再访）。
5. **K6 隔离端到端（本 Note 读数）**：新隔离根（`tmp.fEaCVwelL9`）build→materialize（generation `8e932755`）→ smoke **16/16 PASS**：`protocolVersion=4`、`dshVersion=0.2.0-rc.2`、generation/manifest 双绑定、`loaderPhase=active`、Sage document 200、`/.sage/state|actions` 404×2、`/api|/plugins|/.dsh|/.sanbao` 404×5、traversal 403、shutdown code=0；stderr **零 `patch: entry`/error/fatal 告警**。overlay 探针 **10/10 OK**（7 个 disable 行 + 2 个 insert + `connection inject=[credentials]`；组合条目 185）。会话迁移链 `dsh-session-format-v3-to-v4` 已装载；隔离根与共享根均**无 legacy v3 会话素材**——运行时迁移未实际执行（如实读数：无素材可迁；素材出现时首启路径由该链承担）。

### 操作者要点

- 回退：`git revert` K1/K3/K5 对应提交（或手工回置 pin/seed/devDeps/locks）→ 壳 `pnpm install` → `SAGE_ROOT=<根> pnpm run materialize` 重物化；旧 generation 未被删除。
- dev 循环不变：改 seed/后先 `materialize` 再重启；共享数据根的重物化不属于本次换装动作。
- 门禁语义变化：`sage-shell-pin` 不再读 vendor wire.ts；帧常量漂移 = 冻结表判红（改值须显式同步门禁表）。

## Alternatives considered

| 方案 | 结论 |
| --- | --- |
| K3 与 K4 拆成两个提交 | 否决；K3 单独提交时 composition.spec 处于已知红（0.2.0 skip 语义），违反「提交门禁绿」；合并为一次换装提交。 |
| fixtures 版本只改部分（只动 provider spec） | 否决；「当前版本」语义在家族内一致，部分改会造成同仓两种「当前」读数。 |
| 把探针脚本落仓 | 否决；一次性重算工具按既有纪律不落仓库（golden 与读数进测试与 Note）。 |
| 无 legacy 素材时构造假 v3 会话造迁移演示 | 否决；会引入非真实 fixture 并污染隔离证据；改为如实登记「未执行 + 机制在位」。 |

## Consequences

- **提交链**：`d496953`（K0 三件套）→ `d31cfa1`（K1）→ `9d42a5d`（K2）→ `01ceb2c`（K3+K4）→ `70c0bcc`（K5）；每步 `pnpm run gate` **25/25**（exit 0；K1 时 sage-shell-pin 的参照缺失 note 在 K2 后清除）。
- **测试面**：全量套件 **611 pass + 1 opt-in skip（62 文件）**；goldens 13 字面量重冻结 7+2 条、独立保持 6 条（生产者实算证据见上述 K5 条目）。
- **工件面**：seed 锁由新 manifest 正规重生成（隔离临时目录 `pnpm install --lockfile-only`，7.5s）；两处 npm registry 依赖面 `dsh-type-meta`/`dsh-user-interaction` override 仍为必需（npm 404 实测）。
- **登记遗留**：PMAP 源面适配（`dsh-agent-presets` 路径失效 + `settings.yaml` 流向变化，与 C2E 线协同）；C2C 面受影响评估（`@modelcontextprotocol/client@2.0.0`、`projectContent` 改名）；插件 manifest peer 规则体检；可选 bundle 决策；上游新桌面架构评估——均在 spec §8 索引。

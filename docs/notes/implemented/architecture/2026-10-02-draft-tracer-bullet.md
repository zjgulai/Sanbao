# 002 剩余半边：草案、确认与"以回执为事实"的建项

> 决策与规则见 [ADR-0209](../../../adr/ADR-0209.md)。

## Problem

002 是第一颗示踪弹，前几轮只落了它的"创建半边"（ADR-0201：`create-matter` 走托管分支）。剩下的是
对象与界面：**草案**（本设备对象，US-003/011）、**确认**（US-002/007/009）、**整理不写字段**（US-010）、
**未选前史不带**（US-004），以及"建项后列表可见"。

## Decision

- 草案存 `<Sage root>/drafts/`，AES-256-GCM，设备密钥文件 0600；**未登录即锁**（不列举、不解密、不写），
  重登同设备可恢复；不自动同步（模块无网络依赖，判据有结构性断言）。
- 新建草案把输入存为**前史**，三必填（目标/预期交付/责任）与项目（可选、最多一个）留空；
  只有用户 `update` 写字段；确认入口三条必填齐备前 `disabled`，main 侧同样拒绝 `draft-incomplete`。
- 确认由 main 构造 `create-matter` intent（`matterId: draft:<id>`），经**同一条流水线**（身份→授权→
  创建分支）交托管端口；成功只把**服务回执**写进草案（`matterRef`），已转换草案再次确认就地拒绝。
- 转换请求只带已勾选前史片段；未勾选文本不出现在请求里。
- 命令状态继续进 001 的 `command` 槽（不新增第二份分类）。

## Alternatives considered

- 草案进本地 business-matter 库：正式事项归托管，否决。
- 明文落盘 + 纯界面锁定：与"安全保存"矛盾，否决。
- 钥匙串存设备密钥：本切片不引系统交互依赖，如实登记未闭，否决（记为未闭）。
- renderer 组装 create 载荷：产品判断必须在 main，否决。

## Consequences

- 002 的硬验收各有机器断言（字段不自动写、缺项不提交、未选前史不带、未确认不显示已建项、
  重复确认不再调托管、锁定时不读不写、无网络依赖）。
- 建项真链路唯一：`/.sage/draft/convert` → 同一流水线 → 托管端口。
- 已知未闭：真机端到端未跑（无真实托管方）；设备密钥未绑钥匙串；"获准恢复"的批准一步属权限治理线；
  事项全量列表仍缺托管侧 list provider（本票只列本设备已转换草案及其回执）。

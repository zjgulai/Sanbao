# 003 建项三态：尝试落盘、未知只核对、失败可修正

> 决策与规则见 [ADR-0211](../../../adr/ADR-0211.md)。

## Problem

001 已把命令结果三态做进界面（unknown 显示核对、隐藏重试），但 003 指向的是**草案的建项路径**：
此前只有成功会写回草案，失败与未知都只活在响应体里——刷新即失，用户既看不到"这次可能已生效"，
也无法把"同一个请求"拿出来核对（US-005/119）。同时 US-006 要求取消未提交的确认后回到草案且内容不丢。

## Decision

- 确认时先在草案记录上开 `attempt{correlation,at,state:'pending'}` **再**跑流水线（崩溃也留下"请求存在、
  结果未知"）。
- 托管端口新增 `{unknown:true}` → 流水线 `outcome-unknown`（不可重试）→ 草案记 `unknown`；
  未知态禁用确认入口（文案"结果未知期间不重复建项"），只留**核对**。
- `reconcileDraft` 按 attempt 的 correlation 询问托管侧；已生效才写回执并置 converted；没有查询端口就
  诚实答"仍然未知"；过期应答按 correlation 对号丢弃。
- `failed`＝确定未生效 → 确认入口恢复可用（修正后是新一次尝试）；`cancel` 只清 pending 的 attempt，
  字段/前史/勾选/澄清全不动；`unknown` 不可取消。

## Alternatives considered

- 未知态给"重试建项"：US-119 禁止，会造第二个事项，否决。
- 未知态允许取消：可能抹掉已生效的请求，否决。
- 核对查不到即判失败：把"还不知道"当"没发生"，否决。
- attempt 只留内存：崩溃即失，否决。
- 失败后只能新建草案：US-005 要"原工作面修正"，否决。

## Consequences

- 三态各有入口与断言；拦"未知态冒出重试按钮"的断言直接扫文档里的按钮文案。
- 生产暂无真实托管查询端口 → 核对答"仍然未知"（不假装查到）。
- 已知未闭：真机端到端未跑；"创建中"没有超时自动转未知。

# 深度开发前置基线与执行边界（ADR-0157）

- 日期：2026-09-23
- ADR：[ADR-0157](../../../adr/ADR-0157.md)
- 执行方案：[深度开发前置盘点与增强执行方案](../../../plans/2026-09-23-deep-development-readiness.md)
- 执行状态：[深度开发前置执行 Todo](../../../plans/2026-09-23-deep-development-execution-todo.md)

## Problem

仓库当前不是“没有可开发内容”，而是多个高风险事实面还没有收口：历史发布归档受 [ADR-0067](../../../adr/ADR-0067.md) 保护，但清场工具只扫候选顶层；本地存在 `2.5.0` 制品，但正式发布状态与当前开发基线并未收敛；DA-25 的最小生产恢复仍有未结案事项；两份 handoff 的基线和宿主不同。若直接清理或展开多条开发线，最可能的结果是误删回滚证据、误把历史结论当当前验收，或让生产恢复与功能试验互相污染。

## Decision

用户批准先完成前置盘点与增强。ADR-0157 因此建立四条可执行边界：先建立方案/执行状态/可视化变更记录；前置阶段不删除发布证据或动生产；`2.5.0` 与留存策略保留为显式决策门；DA-25 与 Role Presets 分别按隔离验证和当前 H0 rebase 处理。

首个实施批次只收窄到清场判据：让嵌套归档的发布清单不能再被误判成可清理对象，并用定向回归测试与真实只读读数证明。它不改产品运行时、DMG、发布清单、`latest` 或任何 profile。

## Alternatives considered

- 先按体积删除旧版本：否决。体积无法证明是否存在发布承诺或可恢复副本。
- 先将 `2.5.0` 当正式版补全发布链：否决。制品存在不等于已完成正式分发，且用户尚未给出定位结论。
- 直接沿 handoff 的下一步继续：否决。DA-25 与 Role Presets 的证据时间点不同，不能跳过当前基线核验。
- 用生产 profile 兼做恢复和开发验证：否决。此举会扩大故障面，且无法区分恢复问题与新改动问题。

## Consequences

- 方案、Todo、ADR 和本 Note 成为本轮的记录面；实际完成状态只更新 Todo，避免多个事实源。
- 第一批实现的范围很小且可回退；任何发布物或生产环境改动仍需单独授权。
- 后续必须向用户收集四个具体决定：`2.5.0` 状态、历史制品留存、深开发主线、DA-25 隔离环境。

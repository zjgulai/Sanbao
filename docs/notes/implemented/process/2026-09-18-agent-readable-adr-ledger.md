# 决策记录面向 AGENT：机器可读决策账本 + 2.5.0 清场射程

- 关联 ADR：ADR-0122（决策记录面向 AGENT：机器可读决策账本）、ADR-0123（2.5.0 收口次序、清场射程与并发读数纪律）
- 日期：2026-09-18
- 状态：implemented

## Problem

2026-09-18 的两件事撞在一起，指向同一个缺口。

**第一件：留痕只有人面，没有机器面。** `docs/adr/` 有 121 篇 ADR，编号连续、索引双向一致，形式上完全合规；但 **121/121 全部 `accepted`**（状态字段不承载信息），且 **0 篇**有结构化决策面。本仓库的写入者绝大多数是 agent，而一个新会话的 agent 想知道「平台立过哪些约束」，唯一办法是读 121 篇散文——它不会读。用户因此裁决：「adr 机制需要修复，每一轮决策的结果面向 AGENT 都要做 adr 记录」。

**第二件：我在同一轮里把「证据面」误判成了「垃圾」。** MECE 深查把 `packaging/release/` 的 9 个历史版本 DMG（约 5.7 GB）归为「无用垃圾 J1」，并据此提出「release 7.2 G 迁出」。做出这个判断时，我没有先问一句「这条路径被谁承诺过」。随后取证推翻它：9/9 产物带 `uchg` 锁定、`release-verify.sh` 对「dmg 不在」判 FAIL、ADR-0067 决策段写着用户裁决「不允许删除发布的版本和历史发布的版本」。

两件事的形态是同一个：**一个只被人读、不被机器读的决定，等于没有决定。** ADR-0067 写得很清楚、锁也上了，但只要清场清单一类的东西不读它，它拦不住任何人。

## Decision

1. **ADR-0122**：新增机器可读决策账本 `docs/adr/decisions.json`（**派生面**，源永远是 ADR 文件），新 ADR 必须带 `## 机器可读决策` 的 json 块，历史豁免 `legacyWithoutDecisions` **只减不增**（基线 `git show HEAD:`，与 `exemptions-frozen` 同法）。落地为门禁 `adr-agent-records` + 反向自测 `adr-agent-records-selftest`。这是本仓库第一条**读 ADR 正文**的判据——此前 `adr-index` 只看文件名与索引、`adr-note-links` 只看链接可达，没有一条判据看过 ADR 说了什么。
2. **ADR-0123**：已发布产物一律不在清场射程内（撤销 J1）；清场射程三分（受保护／可删／需先证明）；2.5.0 收口次序为「先清债、再定版本号」；收口作业等并发写入停止（三项读数判据）；门禁终值只在无并发写入时取，并发假红标注但不计绿；「无用垃圾」类结论必须先查「它被谁承诺过」。
3. **本轮决策以 ADR-0122 / ADR-0123 的决策块首次进入机器面**，即这两篇是本账本的前两条带决策面的记录。

## Alternatives considered

- **给 121 篇历史 ADR 全部补决策块，一次性合规。** 否决：历史决策是当时的人拍的，今天由 agent 反向改写它们的决策面，等于把「当时决定了什么」改写成「今天的模型认为当时决定了什么」——伪造留痕比没有留痕更坏。改用显式豁免清单。
- **不做门禁，只提供生成器。** 否决：生成器不会自己跑，这是本仓库反复验证过的「写了但从没跑到」。
- **让门禁发现不一致就自动 `--write`。** 否决：门禁只读是硬约束；会写文件的门禁在并发下会与人的编辑互相覆盖。
- **按原 MECE 清单迁出 release 7.2 G。** 否决（已被取证推翻）：会同时违反 ADR-0067 的用户裁决、让 `release-artifacts-intact` 判红、把「构建侧看不到产物」重新引入。
- **先定版本号（重打同号 / 升 2.5.1）再清债。** 否决：清债会改动出货面，先定号会让产物、tag、清单再次分家；重打同号另违反 ADR-0057 决策 6。
- **不区分并发假红与真红。** 否决：一律按红会让所有人学会忽略红灯；一律按绿会洗掉真实缺陷。选定「标注 + 不计绿」。

## Consequences

- 正面：agent 有了一条命令可读的决策面；「新决策没有机器面」从没人知道变成门禁判红。
- 正面：清场流程多了一道「先查承诺」的前置，堵住的是**这一类**误判。
- 代价：每篇新 ADR 多写一个 json 块；账本手工改会立刻判红（remediation 必须写「重新生成」而非「手工对齐」）。
- 代价：`packaging/release/` 会一直占约 5.7 GB——这是 ADR-0067 的既定代价，不是本轮新增的。
- 未决：118+ 篇历史 ADR 的机器面仍然缺席，由豁免清单显式承载；要不要补、谁来补需要单独决策。`repo-attest-selftest` 的并发敏感性（它断言的是环境而非代码）单独立项。`docs/notes/` 的 class 词汇表与 ADR-0015 声明的 6 类仍不一致（实测 7 类，5 类共 91 篇不在声明里），本篇按**声明里存在的** `process` 归类以不再扩大缺口，但声明本身要不要追上事实是一个待决策项。

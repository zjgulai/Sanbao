# Jev Tier 1.5 基线收口：两处 P-25 措辞/标签修正 + D5 指纹门禁落地

- 关联 ADR：ADR-0138（Jev 落点 SkillOpt Tier 1.5——判据出报告、指纹进门禁、出网上限钉在仓库文本）
- 日期：2026-09-19
- 状态：implemented

## Problem

ADR-0138 把八条决策（D1–D8）收口后，落地分五步 T0–T5。到 T2 基线记分卡跑出第一轮真实读数（7 样本 / 35 读数 / 0 错误）时，出现两个判读问题：

1. **③ 判据的「误报」FP-1688 五连触发（median 0.76）**。按第一反应这是判据③的假阳性，修法似乎是再收窄措辞。
2. **② 判据的 R-F2 召回样本五连不触发（median 0.42 < 0.5）**。按第一反应这是阈值问题，修法似乎是降阈值。

两个「第一反应」都通往 P-25（把平台/判读行为当常量去迁就读数）或 P-15 一族：为了让数字好看去动判据或阈值，而不是先审自己的标注与措辞。同时，ADR-0138 D5 的指纹门禁还没落地——corpus 或判据改了，旧基线报告仍然「有效」，实际指向一份不存在的输入。

## Decision

1. **两处修正都走措辞/标签，不动阈值（P-25 纪律）。** 第一轮的两处问题，一处是**我的标注错**：FP-1688 的语料原文写着「每次调用 MCP `find_product` 必须带 `tags="4306497"`」，MCP 工具参数格式就是判据③自己定义的 agent 运行环境机制——0.76 是判据判对了，错的是我的 `expectFire:false` 标签，改标为召回样本 `R-1688-mcp`，改标缘由写进该样本的 `source` 字段。另一处是**判据措辞缺口**：F2 引文「必须先询问用户再继续」里的「向人询问」被 Jev 读成条件性动作而非停止形态，解法是在 `questions.mjs` 的 q2 文本里显式补「向人询问也是停止的一种形态，只要它被规定为义务即视为符合」——判据文本变了，指纹随之换新，这正是 D6 钉版本的用意。
2. **修正后重跑基线全绿**：q2 召回 10/10、误报 0/5（R-F2 0.42→0.77）；q3 召回 15/15、误报 0/5；漂移 spread ≤0.05；35 读数 0 错误，模型回读 jev-1.13.0。「extremely consistent」作为被测事实复现通过（D8）。
3. **D5 指纹落地为门禁 `jev-tier15-freshness` + `jev-tier15.expected.json`**（同构 `live-presets.expected.json`）：离线、确定性、零 API 调用重算 `sha256(corpus ⊕ 判据文本⊕阈值 ⊕ 模型版本 ⊕ 基线样本集)`，与登记指纹逐项比对；漂了判红并**点名是哪一项**，四项全对而汇总不对单独判红（防手抄哈希）；corpus 0 条或样本 0 条判红不判过（P-15）。注册 `jev-tier15-freshness` 与 `jev-tier15-freshness-selftest`（10 条变异自测）进总 gate。第三方可用性不进门禁关键路径（D8）——门禁只认指纹，不调 API。
4. **state 构成随样本集进指纹**：第二轮实测确认上一轮 0.73→0.06 的区分度读数在本轮 state 组成（description+body_excerpt）下不可迁移——指纹第四项钉的就是含 state 构成原文的 `samples.json`，换拼法旧基线自动失效。

## Alternatives considered

- **降 q2 阈值（0.5→0.4）让 R-F2 过线。** 否决：P-25——阈值是判读契约，第一轮分离边距实测仅 0.33，迁就单条读数调阈值会把「判据没写清楚」洗成「阈值刚好」。先修措辞，让读数自己走过来。
- **再收窄 q3 措辞让 FP-1688 不触发。** 否决：读数是对的，错的是标注。按判据自身定义该语料就是环境机制假设——再收窄会把真缺陷也放跑。
- **把基线报告 `.scratch/jev-tier15/scorecard-baseline.json` 直接进门禁比对。** 否决：报告是语义轨证据（D8 只进报告不进 gate），门禁比对的是它的**输入指纹**而非读数；否则第三方 API 不可用会进 gate 关键路径。指纹的家 = `scripts/gates/jev-tier15.expected.json`。
- **指纹只算判据⊕阈值（不含 corpus/样本集）。** 否决：第二轮实测已证明 state 构成变了旧读数就不成立；语料漂移不进门禁等于「改了语料、旧基线还绿」。
- **expected 漂移时门禁自动重采。** 否决：门禁只读是硬约束（同 ADR-0122 的否决理由）；重采必须人工审查后入库。

## Consequences

- 正面：判据质量证据有了机器可拦的锚——corpus/判据/模型版本/样本集任一漂移，旧基线立刻判红并点名，修法指向重跑语义轨而不是手改文件。
- 正面：样本标注错误被记分卡自己抓出来（FP-1688 案例），语义轨的「标注噪声」从此有第一手教训可循；样本 `source` 字段承载改标缘由，P-01 无名样本纪律继续有效。
- 代价：corpus 是活文件（技能演进会改它），每次改动都会让本门禁判红，修法是重跑记分卡（≈$0.002、单线程分钟级）+ 重采 expected——这是 D5 的设计代价，不是误报。
- 代价：③ 的误报侧样本只剩 FP-sourcing 一条（原 FP-1688 改标为召回），误报分母变薄，校准轮要补真不含环境机制假设的语料样本。
- 未决：key 对所有 agent 会话可读的口子维持「已登记未消除」（ADR-0138 后果 7）；① 越界率判据的「域内但越界」任务句对照集仍单独立项。
- 后续（同日，读数取自随本提交入库的报告）：`LUTE_JEV_API_KEY` 已由用户写入 `~/.dsh/.credentials.yaml` 的 refs 块（解析链实测命中 credentials-refs）；corpus 全量评审（T6）已跑完——292 条 × 2 判据 = 584 读数、0 错误，报告与分诊见 `.scratch/jev-tier15/{corpus-review,triage}.json`：58 条豁免、**162 条短名单待人复核**。

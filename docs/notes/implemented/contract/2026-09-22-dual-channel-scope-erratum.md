# 双通道纪律的适用判据勘误：22:1 不是执行率，是适用面

关联决策：[ADR-0061](../../../adr/ADR-0061.md)（多载体探测，勘误补于后果节）、
[ADR-0046](../../../adr/ADR-0046.md)（可选服务读取纪律）、[ADR-0038](../../../adr/ADR-0038.md)（读不到=拒绝）

## Problem

ADR-0061 决策 1 的「探测多个载体、以方法存在性为准」在此后传播中被读成了普适纪律。
2026-09-22 建立服务消费面登记处（`scripts/gates/service-consumption.json`）后拿到精确
读数：全仓 20 个 `ctx.get` 消费服务里，走 `connection.api` 双通道的只有 1 处——
newapp launcher 本身，即纪律的**原始样板**。若按「执行率 4.5%」读，会得出「21 处违规」
的错误结论并驱动一批无意义的双通道改造。

## Decision

分诊 19 个消费文件（读法证据逐点核对，见工单 DA-23 分诊表）：

1. **适用面只有 1 处**（launcher，合规样板）；
2. **17 处登记豁免**——单载体消费的可选性由 undefined 守卫 / try-catch / 能力探测 API
   各自承担（pair-access ×5 是 ADR-0038 三层兜底样板；deepresearch 缺 web 抛可操作错误；
   jobs 有 `backgroundJobsAvailable()` 能力探测 API）；
3. **2 处补守卫**（agent-team-gui 客户端 connection/locale 无守卫直用——客户端 `ctx.get`
   对缺席服务的语义无实测读数，不赌；宿主侧 systemPrompt 直用——缺席时 warn +
   跳过提示段）。typecheck 干净、66/66 测试绿、装载点 tmp+mv 同步 27 包一致。
4. **ADR-0061 后果节落勘误**：适用判据三条（多载体+差异化回退才要双通道 /
   单载体由守卫承担 / 读不到=拒绝或明确报错），决策原文未动。

## Alternatives considered

- **按「执行率低」补齐 21 处双通道**：否决——绝大多数消费点服务载体唯一，双通道是
  死代码且暗示了不存在的回退路径。
- **桶 C 两处登记豁免**：否决——客户端 `ctx.get` 语义未证实是 ADR-0017 遗留 TODO，
  守卫（各数行）是消除未证实假设的最便宜手段；豁免则把赌注留在运行时。

## Consequences

- 「双通道」从泛化纪律收缩为有判据的工具：多载体 + 差异化回退才用。
- agent-team-gui 在 connection/locale/systemPrompt 缺席时的行为从「无声失败或抛裸异常」
  变为「可操作错误 / warn 降级」。
- DA-24（可选服务失败态抽查）的射程被本轮分诊覆盖大半：19 文件已逐点核对读法，
  剩余工作只有确认无「读不到就放行」的写法（分诊中未发现，抽查收尾即可）。

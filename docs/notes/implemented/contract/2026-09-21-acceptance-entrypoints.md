# 验收入口必须真实执行且失败安全

- 日期：2026-09-21
- 决策：[ADR-0154](../../../adr/ADR-0154.md)

## Problem

上轮 CI 失败检查名相同，但内部违例增加，不能据此宣称零新增红。更新检查包的开发依赖未被根包安装覆盖；发布自测的 BSD `mktemp -t` 在 GNU 环境失败后仍使用空沙箱路径；LoopX 默认命令只收集 `.spec.mjs`，已有三个 `.test.mjs` 隔离用例没有执行。

## Decision

只在 full job 的门禁前，为 `dsh-update-local` 按锁文件安装开发依赖并禁用生命周期脚本；这是用户明确批准的最小 CI 范围，不扩展权限或豁免。发布自测改用带六个尾部 X 的绝对临时路径模板，创建失败、空路径或非目录立即以 2 退出，在注册清理和任何修改命令之前停止。沙箱反向测试接入已有 `release-verify-selftest`，安全前置失败则不继续真实发布自测。

LoopX 默认测试收集 `.spec.mjs` 和 `.test.mjs`；通过临时迷你套件执行清单中的真实命令，确认两种后缀均执行、任一失败均返回非零。环境哨兵测试无论通过还是失败均恢复原环境值，不改生产隔离策略。

## Alternatives considered

- 只比较失败检查名：会遮蔽同一检查内的新增失败对象，否决。
- 全仓安装或增加豁免：超出本次 CI 授权范围，否决。
- 将 Linux 缺少 `chflags` 改为恒成功：破坏归档锁定保证，否决；Linux 恢复锁定能力仍如实未验证。
- 只手工运行遗漏测试：不能保证后续默认验收执行，否决。

## Consequences

本地回归：CI/沙箱 35/35、LoopX 默认 11/11、macOS 发布自测 14/14。修复前 CI 回归报缺安装步骤，沙箱三种失败形态均尝试执行修改命令，LoopX 迷你套件缺少 `.test.mjs` 标记；修复后均通过。评审补充的普通文件输出反例通过。干净更新包副本缺依赖时重现 TS2688，离线锁文件安装后 typecheck exit 0、28/28 测试通过。

独立评审两轴通过，无阻塞问题；唯一 P3 建议已补为持久回归。完整无语料 LoopX 包副本中，正常默认套件 11/11，而透传全部环境的突变为 3 failed / 8 passed；不再出现旧命令 7/7 假绿。

这些是本地证据，不等于新的 GitHub CI 已通过。未推送运行前 CI 状态保持未验证；无运行中 Docker，Linux 实测未运行；DA-06/DA-21 与更新器的 DSH 实机读数仍需带 CDP 的应用实例。

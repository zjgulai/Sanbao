# 深度分析 TOP20 · P0 机制债收口（批次 A）（ADR-0148）

- 日期：2026-09-21
- ADR：[ADR-0148](../../../adr/ADR-0148.md)
- 工单来源：`.scratch/review/2026-09-20-deep-analysis-top20/`（DA-01 / DA-02 / DA-03 / DA-04 / DA-06）
- 复核者：本会话（lute 拍板「A」）

## Problem

2026-09-20 的全仓深度分析产出 TOP20 必做清单，其中 P0 六项全是**文档自认「尚未落地」的机制债**——
pitfalls-playbook 的对应条目都写着「尚无」「只有纪律」「缺口不是成绩」：

- P-17：三态读数在聚合处被压回两态——`ok 54/55 项通过（…跳过 1）` 里藏着一项「从未被核对」，退出码与之同形；
- P-45：写盘把权限位留成 `000`——受害面是门禁入口本身，而**没有任何判据在读权限位**；
- P-48：入库工具的输出会**还原**已占位化的环境值——重跑一次受认可的流程就把构建机路径写回已提交事实源；
- P-49：「无用垃圾」清单按体积排序，排最前的恰是被 ADR 与 `uchg` 保护着的历史发布产物——「先查承诺」只有纪律；
- P-52：observer 乒乓没有专属门禁，单例计数这件事「只活在复盘文字与人的记忆里」。

它们共同的性质是：**复发成本高、关闭成本低，且没有外部依赖**——所以整批做掉，而不是摊到多个窗口。

## Decision

五条机制按「先写红、再见绿」的顺序落地（D 编号与 ADR-0148 一致）：

- **D1（P-17）聚合层三态**：汇总行渲染从 `gate.mjs` 的 `main()` 迁进 `gate-result.mjs` 的
  `renderGateSummary()`（住 `main()` 里的逻辑没有任何注册项测得到）；`skipped > 0` 时独立成句
  「未核对 N 项（不是通过）：<逐项点名>」，不再混进「项通过」那句；`--require-no-skip`（2026-09-16 已落地）
  在账本里**订正**、与日常宽容语义分开写清。反向自测：恒真桩突变下 3/8 用例变红。
- **D2（P-45）权限位判据**：新增 `gate:permission-bits`，射程 = 本轮改动面（与 `changed-packages`
  同一份 `resolveChangedScope` 的四类来源并集，**刻意不全仓扫描**）；判「读位全空（`000/020/040/060`）」
  与「R_OK 被拒」两形态，判红点名「文件 + 权限位」并把**先 stat 再怀疑任何人**写进文案；
  记账单位是**可判文件**，射程无可判文件时给 skip 而不是 pass。RED 重放：`chmod 000 scripts/gate.mjs`
  → 当场判红点名；恒真桩突变下 4/8 用例变红。
- **D3（P-48）入库面占位化**：**首选修法与判据双落**——写入者（`intake-install.mjs` /
  `scan-runtime-deps.mjs`）经 `intake-lib.mjs` 的 `sourceUnitPlaceholder` / `dshHomePlaceholder`
  直接写占位符（`__DSH_HOME__` 语义 = `~/.dsh` 本身，与已提交值一致）；新增 `gate:intake-placeholders`
  读两份清单逐行判 `/Users/…` 与字面 `$HOME`（读不到/射程为空判红）。受控样本实测：/tmp 副本重跑两条命令，
  四字段全部占位符、`/Users/` 命中 0；负例（手工写回）判红并点名第 4 行与第 1668 行。
- **D4（P-49）清场先查承诺**：三步序固化为 `script:scripts/cleanup-inventory.mjs`——①承诺
  （发布清单 / `uchg` / 门禁射程 / ADR 决策段）→②引用（`git grep` 代码目录）→③体积；
  **体积只在①②都为否时出场**。实测：`packaging/release/` 全部 11 个候选（9 版本 + 2 个 `.replaced-*`）
  被①拦下、零个进建议；一个无承诺无引用的临时目录正常进建议。与 `gate:object-store-hygiene`
  的分工（它管**没有承诺**的对象）写进模块注释。
- **D5（P-52）单例计数探针**：`script:scripts/acceptance/singleton-count-live.mjs` 覆盖
  workbench 容器 / 组行 / 设置壳根三类单例（恰好 1 / 至多 1），数到 2 直接点名「重复挂载」，
  「读不到」（CDP 不通 / 选择器求值失败 / 必需单例数到 0）一律 exit 2 并点名；`--self-test`
  9 状态 / 18 断言，恒真桩突变下 6 条断言失效；共享层 `sidebar-entry-core.ts` 的不变量注释加了
  「改 observer 前先数单例」的读数指引（`sync-shared` 保 22 份副本一致）；被证伪的仪器
  （把「探针打点 / 代码内观测」有没有输出当存活证明）登记进 `dead-instruments.json` 第 5 条。

## Alternatives considered

- **只改账本、不动代码**（把 P-17/P-45/P-48/P-49/P-52 的「尚无」改成「已记账」）：否决——
  这正是「知道没有变成拦住」（P-03），五条债全部会原样复发。
- **放宽 skip 语义让门禁更容易全绿**：否决（ADR-0014 与 P-02 的直接约束）——修法是让读数更诚实，
  不是让读数更好看。
- **permission-bits 全仓扫描**：否决——日常权限差异会把判据变噪声，然后被「太吵」关掉（P-07）；
  射程取改动面，覆盖面靠「提交前必跑」而不是「全盘扫」。
- **D3 只加判据、不改写入者**：否决备选优先序——判据会在每次受认可的重跑后判红，
  正确处置变成「每次手工占位化」（把机制又推回纪律）；改写入者是从源头断掉还原。
- **D4 用「有没有人 import」代替承诺面**：否决——那正是 P-49 事故的原清单尺子，
  两把尺子都量不到承诺；三步序的顺序本身就是结论的一部分。
- **等 observer 竞态「可静态判出」再上机制**：否决——运行时竞态**无法静态判出**是设计性边界，
  「不可能全静态」不是不落最小机制的理由（P-52 原文）。

## Consequences

- 正面：五条「只有纪律」的债各有了可执行读数与反向自测；`gate` 注册表新增 4 个判据项与 4 个自测项
  （quick 从 113 → 121 项）。
- 正面：DA-13（.scratch 42 工作流清场）解锁——它的硬前置就是 D4。
- 负面/边界：`gate:permission-bits` 与 `gate:intake-placeholders` 会给「改动面里出现 `000` 文件」
  与「入库面被旧脚本写脏」判红——这两种红都是**要求处置**的，不是噪声。
- 边界：单例探针是**实机读数**，需要应用带 CDP 端口启动由人跑，不进 `pnpm run gate`——
  缺口从「没有任何机器能数」变成「有一个可执行读数、等实况验收轮去跑」。
- 后续：DA-05/DA-12（architecture.md 基座事实 + 生产机现状）仍待做；本批不改任何产品行为，
  全部改动集中在门禁/工具/账本面。

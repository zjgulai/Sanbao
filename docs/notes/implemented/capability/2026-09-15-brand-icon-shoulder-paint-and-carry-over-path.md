# 品牌图标的下装是纯黑：一个非法值怎么活过了 310 枚

- 日期：2026-09-15
- 生命周期：implemented
- 分类：capability
- 对应 ADR：[ADR-0090](../../../adr/ADR-0090.md)
- 相关：[ADR-0089](../../../adr/ADR-0089.md)（全栈 40 条入库，本轮在这里发现它）、
  [ADR-0081](../../../adr/ADR-0081.md)（品牌资产判据的边界）

## Problem

给全栈线新做的 40 枚徽章做像素验收时（本项目要求「双主题预览验收」，而截图看不了就取样），
测到 `sk-fs-tdd` 的**肩带是纯黑 `(0,0,0)`**，而它的 catalog 写的是白衬衫 `W`。

顺藤摸下去，三件事叠在一起：

1. **生成器把名字当值用。** `lute-brand-icons/lib/generator.js` 里，`catalog.js` 的 `shirt`
   字段存的是**名字**（`G`/`GD`/`GL`/`MINT`/`W`），`shoulders()` 的第一个参数要的是**颜色值**，
   而调用点写的是 `shoulders(shirt, …)`。要命的是**紧邻的 `COLLARS` 表用的正是 `${W}`、`${G}`
   这些值**——两个用法并排写在同一个函数里，读起来毫无违和。产物于是写着 `fill="W"` /
   `fill="GD"`，按 CSS 规范是非法值，SVG 回落到默认黑。

2. **它长得像设计。** 「小人像配深色下装」是个非常合理的观感。全库一起错，反而更像风格统一。
   这一条是它活下来的主要原因：**假绿比红灯贵，红灯会被处理，绿灯会被相信**；
   而这里连红灯都没有——是「看起来对」。

3. **没有任何判据在看这个值。** 既有的「图标覆盖」只问「这一行有没有图」，不问
   「这张图能不能正确渲染」。生成器在本机 `~/.dsh/skills/` 下、**不进仓库**，
   所以仓库侧也没有任何东西会去解一次 data URI。

第三条背后还有一条更隐蔽的路径：`assign_lute_icons.py` 里有一段「保留既有自定义图标
（非 81 系）」——它把**上一轮 `skill-icons.json` 里的字节**当事实源。
`self-improvement` / `lieflat-charts` / `agent-browser` 三枚正走这条路，
于是**生成器修好了也照不到它们**：修复被「上一次的产物」挡在门外。修完第一条之后判据仍然红着 3 处，
就是这个原因。

## Decision

1. 生成器补一张衬衫色表并传值：`SHIRT_COLORS = { G, GD, GL, MINT, W }`，
   `shoulders(SHIRT_COLORS[shirt] || G, …)`。
2. **判据挂在被消费的那份产物上**：`verify_static.mjs` 新增「头像 paint 值必须合法」，
   解出全部 data URI 逐个断言，并带一条**空转哨兵**——「解出 N 枚却一个 fill 都没有」
   必须与「零违规」在读数上不同形。不写进生成器：生成器不在仓库，门禁够不着；
   两处都写则是同一事实两个家。
3. 「沿用上一轮的产物」换成显式映射：新增 `EXTRA_ASSIGN` 把三条非 81 系指回 catalog id，
   84 枚全部现算；沿用路径**保留但点名**（命中的名字逐个打印并提示补表），
   既不静默、也不让将来新增的手工头像被悄悄抹掉。

## Alternatives considered

- **只改新加的 40 枚**：同库两种下装风格并存，比统一更糟；且缺陷的家在生成器，
  改一半等于把「一份事实两个家」固化。否决。
- **判据写进生成器的 `build.js`**：能更早拦住，但对**仓库**的出货面没有射程。
  只在仓库侧写。
- **删掉「沿用」路径**：会引入另一种静默（新增手工头像被抹掉）。改为「保留 + 点名」。
- **只查 `fill` 不查 `stroke`**：两者走同一条函数、同一个 bug。只查一半＝留一个洞。

## Consequences

- **实测读数（栅格化取样，肩带带 y≈0.86–0.92）**：

  | 图标 | catalog 衬衫 | 修前 | 修后 |
  | --- | --- | --- | --- |
  | `sk-fs-tdd` | `W` | `(0,0,0)` | `(255,255,255)` |
  | `sk-fs-accessibility` | `G` | `(0,0,0)` | `(88,184,72)` = `#58B848` |
  | `sk-fs-postgres` | `G` | `(0,0,0)` | `(88,184,72)` |
  | `sk-fs-git-commit` | `GL` | `(0,0,0)` | `(143,212,138)` = `#8FD48A` |

- **波及面是全库，不是本批**：按提交前的字节数，**193 枚不同的图**带非法 paint
  （被 230 个清单条目引用：出海 84 + 全栈 70 + 通用 15 + 三类分组 49 + 层头像 12，
  **一枚例外都没有**）。修后 193 枚 / 6720 个 paint 值全合法。
- **负控**：受控变异（把一枚的 `fill="#FFFFFF"` 改回 `fill="W"`）→ 判据当场判红并打印该值；
  沿用路径的负控（塞一条不在任何表里的名字）→ 打印「⚠️ 沿用上一轮字节（1 条…）」。两者还原后复绿。
- **连带重建**：310 枚 → 6 份仓库清单 + `lib/layer-icons.js` +
  **隔壁包 `dsh-algo-skills-local/src/layer-icons.ts`**。两包逐字节相同、有跨包测试守着；
  只重跑一边会被那条测试当场抓住（本轮实测：先只跑本包，测试立刻红）。
- **诚实划界**：判据断言的是「paint 值合法」，**不是**「这枚图看起来对」。图案、构图、
  配色是否合适是人的判断（与 ADR-0081 对品牌资产划的边界同型）。
- **本机资产不进仓库**：`~/.dsh/skills/lute-brand-icons/lib/generator.js` 已修，
  但仓库能守的只有上面第 2 条的判据与第 3 条把来源指回 catalog。

## 顺带完成的两件（同批，另见提交）

- **postgres 的 24 条上游外链**改为包内相对路径。`rewritePaths` 是全局字符串替换，
  而 `SKILL.md` 在根、`references/*.md` 在子目录，同一 URL 需要两个不同的相对目标；
  两处链接的**文字**不同，所以按**整条链接**锚定才分得开——24 条精确规则，
  由脚本从已装文件现场生成并自证（套用后残留外链 0、逐条目标真实存在）。
  同时按用户裁定把上游 PlanetScale 推广块**保留并登记**为已知缺口（写进留底与 `README.usage.md`）。
- **归位表的「协议 §5」引用订正**：`PROTOCOL.md` 只有 §0–§4，「通用方法示例」在 §2 硬规则第 5 条。
  5 处引用指向一个不存在的章节——正是本仓库记的「引用了不存在的东西，而读者无法分辨是文档变了还是引用一直错」。

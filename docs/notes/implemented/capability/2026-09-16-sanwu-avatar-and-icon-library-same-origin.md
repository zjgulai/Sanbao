# 「三无」的头像：冕旒、为什么不能用金色，以及一坨没人读得动的 base64 怎么才不烂

- ADR：[ADR-0092](../../../adr/ADR-0092.md)
- 日期：2026-09-16
- 相关：ADR-0090（品牌图标的下装颜色：判据挂在被消费的产物上）、ADR-0091（三无 preset 与节点轴重建）、
  ADR-0022（岗位头像走官方 `icon` 字段）、ADR-0009（一份事实只有一个家）、ADR-0073（出货预设白名单）、
  总账 P-02（仪器假绿）、P-03（「知道」没有变成「拦住」）、P-07（一条事实多个家）

## Problem

用户要求给「三无 · Agent全栈专家」做一枚**特别的**头像 —— 皇帝老爷爷或管家，且**保持品牌调性一致**。

三件事让这件事不是一个画图问题：

**1. 这枚头像的位置是空的，而且是静默地空着。** `~/.dsh/.agent-presets` 下 53 个 preset 里，
只剩 `agent-fullstack` 与 `lute-cordis` 两枚没有 `icon:` 行（后者已标退役）。平台 schema 只有
name / description / order / **icon** 四个字段，`icon` 是官方卡片显式消费的显示字段
（roster 送到前端，渲染成 `<img class="cardAvatar">`）。缺了它，卡片就是一枚没有脸的卡 ——
**加载、日志、页面读数全部正常**。

**2. 品牌铁律里没有金色。** 规范写明「不引入品牌绿以外的彩色（肤色/发色/白/灰除外）」。
皇帝 = 金色冕冠是最省事的画法，也是最直接的违规范。

**3. 头像的载体是一坨几千字符的 base64。** 它有两个可能的位置，而**两个位置都错**：
只放图标库 → preset.yml 里没有 `icon:`，卡片回落成没有头像；只放 preset.yml → 图标库重画之后
副本还停在上一版的脸。后者尤其安静：两份文本各自合法、界面照常显示，只是显示的是旧脸。

而**判据够不着生成器**：图标库（`~/.dsh/skills/lute-brand-icons/`，327 枚）不在 git 下，
门禁跑在仓库里。ADR-0090 已经为同一件事划过界。

### 我看不见图，所以我不能靠「照着规范写」交付

本会话的模型**不能读图**（无图像输入、无截图工具）。这意味着「看起来对不对」这件事，
以及规范里那些**本该用眼睛判**的条目（头部占比、描边粗细、徽章不越内框），
我一样都判不了。ADR-0091 的诚实划界里已经把这条记过一次（14 枚分组头像「未做像素级验收」）。

所以这次的交付形态一开始就不是「一枚做好的头像」，而是**三枚候选 + 让人来看对照图**。

## Decision

### 1. 三枚候选，用户选：皇帝老爷爷（冕旒）、老管家（燕尾领结）、掌印老臣（梁冠）

只给一枚等于把审美判断藏进一次交付里。三枚的方向差异是**清晰**的：冕旒最「特别」但在
一排克制的 `agt-*` 卡片里最响；管家最贴「三无」（有礼而不谄媚、守边界）；梁冠是折中
（有威仪而不称帝）。用户选了 **`sanwu-emperor` 皇帝老爷爷 · 冕旒**。

### 2. 不用金色：帝王感由**形制**表达，不由配色表达

冕冠画成品牌绿三阶（冠体 `#2E7D3C` + 綖板与垂珠 `#58B848`/白），"老" 由**灰白须眉**表达
（`grayBrows` + 灰白长须），再加交领右衽与印玺徽章。这是本次唯一一处真正的设计取舍：
**形制可以承载等级感，颜色不必**。加金色会一次性违反品牌铁律，而它换来的只是「更像皇帝」这一句。

### 3. 引擎只**追加 key**，并用漂移闸证明既有 324 枚一枚不变

`lib/generator.js` 新增 `crownMian` / `crownBeam` / `beardWhite` / `mustacheWhite` / `monocle` /
`robeJiao` / `bowtie` / `seal` / `serviceBell` / `tally`，并把「画在脸圆之下」的判定提成
`UNDER_FACE` 集合。动笔前的**前置闸**：把 catalog 里 324 条逐条 `buildIcon` 重建，
与磁盘上的字节比对 —— **324/324 逐字节相同，0 例外**。这是非可选的：那些字节被别的包断言着，
而改引擎最容易伤到的就是它们。

### 4. 走 append-only 通道，**不跑 `build.js`**

`build.js` 会 `const manifest = []` 后整体重建，等于把 327 枚产物重算一遍并整体重写清单。
改用 `scripts/append-sanwu-avatars.js`：只生成 3 枚、只 push 3 项、catalog 纯文本插 3 行，
并在写回前用「字节级拼接」独立算一遍与 `JSON.stringify` 对照 —— 相等即证明前 1281053 字节
与原文件完全相同。

它比前一版（`append-fs-cat-m-icons.js`）多一道闸：**部件指纹断言**。
每个新部件登记一条「画出来必然留下的子串」，缺了就是「key 名写错、静默少画一块」——
那正是既有脚本注释里记着的真实缺陷形状。本次 6/6、4/4、6/6 全命中。

### 5. 同源：图标库 manifest 是家，`icon:` 行是物化副本，门禁 import 同一个渲染函数

新增 `sync-fullstack-avatar.mjs`（`loadAvatarEntry` / `renderIconLine` / `extractIcon` /
`replaceIcon`），与 `sync-fullstack-persona.mjs` 同一套契约：渲染函数**只此一处**，
门禁 import 它复算。若门禁自带一份「等价」实现，渲染规则一改就会变成
「门禁校旧规则、同步器写新规则」—— 两种都错，且两种都报绿。

`replaceIcon` 只碰 `icon:` 那一行，name / description / order 与其余字节逐个保留
（断言 `text.startsWith(before)`）。行不存在时**追加**而不是抛弃。

### 6. 仓库侧的判据挂在**被消费的产物**上（preset.yml），不是挂在生成器上

门禁第 7 层分三问，因为它们坏的方式和修法都不同：

- **7a 形状**：`icon` 行在不在；是不是 `data:image/svg+xml;base64,` 开头的 data URI
  （相对路径会 404 成一枚空白头像，**不报错**）；解出来是不是 100×100 的徽章。
- **7b 同源**：是否等于图标库 `sanwu-emperor` 的条目。图标库读不到时**判红并给出修法**——
  不静默降级，否则这条判据会在缺库的机器上空转，而空转仍然报绿。
- **7c paint 合法性**：ADR-0090 的纪律延伸到新载体。**这枚头像的载体就是 preset.yml，
  仓库够得着**，所以仓库这一侧必须自己读它，不能指望本机那两支脚本。

### 7. 图标库自己的两支判据是**本机工具**，不是门禁

`scripts/verify-brand.js`（结构：品牌 9 条不变量 + paint 合法性 + 色板合规 + 几何锚点）
与 `scripts/verify-raster.py`（栅格：内容有没有跑出徽章）。它们住在 `~/.dsh/skills/` 下、
**不在仓库**，所以按 ADR-0090 划过的那条界，它们是本机工具。写出来的直接动因是我看不见图 ——
「像素上有没有越框」是可以量的，量出来的结论强过「我照着规范写的」。

## Alternatives considered

- **手抄 base64 写进 preset.yml**：一次性，且「霉」的时候没有任何东西会响。否。
- **把图标库连同判据搬进仓库**：图标库是开发机资产（327 枚不在 git 下），搬进来会产生第二份
  事实源，且与 ADR-0090 已经判过的结论相抵。否。
- **跑一次 `build.js` 重建全库**：会重算 324 枚已验收字节并整体重写 manifest，风险大于收益。否。
- **用金色画冕冠**：违反品牌铁律「不引入品牌绿以外的彩色」。否 —— 改由形制承载。
- **顺手修掉 `headset` 的越界杆尖**：24 枚图标把麦克风杆尖画到 `cx="5"`，而内容裁剪区从 6.5 起，
  杆尖被切掉一点。这是**既有**缺陷、只影响那几个像素，而修它要改动 24 枚被外部逐字节断言的产物。
  否 —— 登记为具名豁免，且**只减不增**：哪天它被修好，判据会报「豁免已过期」并判红。
- **只交付一枚头像**：把审美判断藏进交付里，而我又看不见图。否 —— 三枚候选 + 对照图。

## Consequences

**产出**：图标库 324 → 327 枚（新增 `sanwu-emperor` / `sanwu-butler` / `sanwu-steward`）；
`preset.yml` 追加 `icon:` 行（4966 字符）；`sync-fullstack-avatar.mjs`；
门禁第 7 层（`verify-agent-fullstack.mjs` 六层 → 七层）；自测 7 条（I0–I7，总数 12 → 19）；
SOP 两处「六层」改写并补上「改头像只改图标库」与「出货登记」两条；gate.mjs 的 note 与修复指引带上头像。

**验证**：漂移闸 324/324 逐字节相同；结构判据 327 枚 4227 项全绿；栅格判据 0 像素外溢
（先在已验收图标上校准，再上新图标）；自测 19/19；`gate` 63/63、`gate:full` 70/70。

**诚实划界**：

- **审美判断没有做，也做不了。** 我能给的是「像素没越框、颜色在色板内、形状按规范」，
  以及一张对照图；「好不好看」是用户的判断。这正是交付三枚候选的原因。
- **判据自身翻车四次**，形状完全一致：探针的语义是我**假设**的，输出却被我当成事实。
  ① 结构判据第一版把**全部 324 枚已验收图标**判红（字符串白名单缺 `rgba(255,255,255,0)`）；
  ② 用临时 grep 扫整个文件，把渐变定义里的 `cx="0.3"` 当成画到框外；
  ③ 把 `stroke-width="2"`、`r="2.9"` 当坐标（第二版仍红 327 枚）；
  ④ 栅格判据第一版不透明背景当内容、又用色板去卡线性渐变的插值色（三枚同样数字）。
  四次都靠同一条纪律挡住：**先拿已验收的产物校准判据，再上新东西**。判据错不是产物错。
- **`agent-fullstack` 未在 `packaging/shipped-presets.json` 登记**，实测
  `select-presets.mjs` 会**拒绝打包并点名**它（未登记 = 没人表过态）。发不发是产品决策，
  本次未擅自表态。
- **24 枚 `headset` 图标的杆尖越界**：既有，未修，具名豁免。
- 卡面头像在宿主装载预设时读取，**改完需重启 DSH 才可见**。

# 2026-09-18 升级扩展中心（Extensions Hub）看板与全屏挂载

## Problem

原「技能中心（Skill Center）」采用右侧 720px 模态浮层（drawer overlay）展现，与「新应用工作台」的全屏 centerCol 视图在交互体验与视觉结构上割裂；且仅覆盖单一 Skill 技术形态，无法满足用户对「Agent 技能包 / MCP 服务 / 应用扩展」三类能力形态的统一发现、场景分类检索与快速试用唤醒诉求。

## Decision

1. **统一视口与路由契约**：将 `dsh-skill-center-local` 的挂载方式重写为与 `dsh-newapp-local` 对齐的全屏工作台（centerCol 宿主），订阅统一视图总线 `dsh:view-change`，扩展中心视图命名为 `extensions`。
2. **三技术形态 Tabs 架构**：
   - `Agent 技能包`：保留 86+ 技能的场景化业务分组（选品、调研、营销、运营等），支持按业务域筛选和关键词全文本检索；每个技能卡片新增参数输入框与一键「执行」按钮，支持回车直发或点击唤醒。
   - `MCP 服务`：接入已有的 `/api/dsh-wanzh-hulian/mcp-servers` 数据源，实时展示 MCP 服务的连接状态、工具清单与服务说明。
   - `应用扩展`：展示独立桌面应用（KOL-Hunter、新应用工作台等）集成状态，并支持一键跨视图直达。
3. **保持视觉轴与门禁契约**：维持侧边栏入口的统一行轴规则（`data-dsh-skill-center-entry`、36px 高、行内对齐），更新视觉测试断言适配全屏响应式布局，所有 20 个行轴断言与 12 个套件 84 项测试全部通过。

## Alternatives considered

- **方案 1：新建独立 package 扩展中心**：需要额外注册 profile、配置 cordis 补丁并重新处理侧边栏顺序声明，成本高且造成存量技能中心入口冗余。
- **方案 2：保持右侧抽屉仅扩展内容**：无法给用户提供宽屏看板的沉浸式体验，在大规模技能和 MCP 列表中缺乏足够的横向排布空间。

## Consequences

- 侧边栏「技能中心」入口无缝升级为「扩展中心」，文案与行为在中英文环境下保持完备一致。
- 业务卡片具备「执行」能力，用户可在面板就地键入参数后唤醒会话执行，并复制到剪贴板兜底。
- 相关单元测试与视觉契约已完整同步更新，构建产物正常生成。

# ADR-0342 · 018 收口 A1：凭据 unset、模型行编辑与语义名单归位

- 相关：设计票 [018](../design-loop/tickets/018-显式测试连接与结果绑定配置版本.md)（未闭项收口）、[ADR-0339](ADR-0339.md)（D2/端口名单设计）、[ADR-0340](ADR-0340.md)

## 背景

018 未闭项中三项属模型面闭环的缺口：凭据 unset UX、既有路由的编辑（baseURL/模型回填）、以及**实机抓出的实现漏改**——主端口 `instance-credential.ts` 仍以固定名单（`APP_CREDENTIAL_NAMES`）拦截非 DEEPSEEK 名，而 ADR-0339 设计明文「语义名单（固定 ∪ 已声明引用）归宿主」（宿主才读得到已保存配置）。批次 D 全程用固定名走查，此路径从未被跑到——「写了但从没跑到」类的又一实例。

## 决策

1. **D1 语义名单归宿主（实现归位）**：主端口删除固定名单门与「循环固定名 describe」，describe 改为**按请求名**；宿主 handler 独占语义名单（固定 ∪ 已声明 apiKeyEnv）。未声明名的具名拒绝位置随之下移到桥（`bridge-credential-name-refused`），与批次 D 文档一致。
2. **D2 unset**：桥 +`credentials/unset`（与 set 同守卫：env 只读源具名拒 `bridge-credential-readonly-source`）；路由 action 扩 `'unset'`（精确键集与 describe 同）；契约 +`removed` 态；端口透传。
3. **D3 行菜单**：列表行操作收敛为 `…` 菜单（编辑/测试连接/清除凭据/删除）——对齐 0.4.4 观测的行形态；清除凭据仅在 `credential.configured` 时出现。
4. **D4 编辑态**：列表读 +`modelIds` 供预填；编辑弹窗锁定供应商（路由身份不漂移）、预填端点与模型、携带 `expectedRevision`（冲突具名）；**API Key 留空=保留现有凭据**——值不可读，未触碰的字段绝不覆盖（同 D5 诚实语义）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 主端口保留固定名单 + 逐个加名 | 否决：与 ADR-0339 设计背反；声明是真名单源，只有宿主读得到。 |
| unset 不做只读源守卫 | 否决：env 层清不掉，报「已清除」是静默谎言。 |
| 编辑时 key 必填 | 否决：值不可读，必填等于逼用户重输或丢失凭据。 |
| 编辑改路由名/apiKeyEnv | 否决：本批只改端点/模型；身份改名=删除+新建，另票。 |

## 后果

- 声明引用名全链可寻址（set/describe/unset）；一次性键名实测闭环且真实 key 零接触。
- 018 未闭项剩：pi-ai 段表单（A2）、D7 inventory overlayPolicyDigest。019 另票。
- A1 的 unset 实机复验随下一次 staging 重烤执行（sage-16 专家批在途，staging 让路；单元/集成 spec 已覆盖）。

# ADR-0149 · 出货架构正式定为 arm64-only（x64/universal 缺口转为决策）

- 状态：accepted（2026-09-21）
- 决策者：用户（lute）——在「只发 arm64（立 ADR）vs 补 universal 构建」的选择器上拍板「只发 arm64」
- 决策记录：[Note](../notes/implemented/contract/2026-09-21-single-arch-arm64-decision.md)
- 相关：ADR-0056/ADR-0057/ADR-0058（DMG 打包与清单）、ADR-0006（上游观察窗）、
  CHANGELOG 2.5.0「x64 缺口单列」（本 ADR 把那条「登记下轮」接住）

## 背景

LUTE 2.5.0 的出货产物是 `DSH-Desktop-LUTE-<版本>-mac-arm64.dmg`，CHANGELOG 在同一版把 x64 缺口单列：
「`fs-ext` 的 darwin-x64 prebuild 不在场，补齐需 `MACOS_UNIVERSAL_NATIVE_ENTRIES` 与 `--dir --universal` 适配，
不阻塞本版，登记下轮。」——即：**Intel Mac 不可用是已登记但未排期的事项**，且它以「缺口」的叙事挂着，
没有决策文、没有适用范围、没有逃生路径。深度分析把它列为 TOP20 #11：缺口挂着不定，下一个人就要重新调研一遍。

## 决策

**D1：出货架构正式定为 arm64-only。** 单一产物 `mac-arm64.dmg`；Intel Mac 不在支持范围。
CHANGELOG 对该项的表述从「缺口」改为「决策」（Unreleased 段指向本 ADR），不再每版重述缺口。

**D2：适用范围与边界。** 新装客户须 Apple Silicon；Apple Silicon 上为原生 arm64（不经 Rosetta）。
不承诺：Intel 机运行、跨架构升级迁移。取证面（`SHA256SUMS`/`manifest.json`/`VERSION` 的 `ARCH=arm64`）
保持不变，不改动打包与校验链任何脚本。

**D3：逃生路径（重新评估的触发条件与做法）。** 一旦出现 Intel 消费方（或跨架构分发成为明确需求），
按两步重启而不是从零调研：
① `MACOS_UNIVERSAL_NATIVE_ENTRIES` 登记 `fs-ext` 的 `darwin-x64` prebuild；
② `--dir --universal` 适配。验证面 = **Intel 机（或等价对照）启动 + `fs-ext` 功能可用 +
运行时物化与接入 SDK 的 intel 兼容性一并核对**（别只测壳）。
届时按 ADR-0006 的观察窗口径同步评估 Electron 与上游的 universal 支持，产物名与清单同批更新（ADR-0056/0057）。

**D4：本决策不触碰签名与发布口径。** 继续用现有签名身份与 DMG SOP；universal 若重启，
`ARCH` 字段与产物名是同一批变更的一部分，不允许只改其一。

## 备选方案

- **补 universal 构建。** 否决（本轮）：需要 Intel 对照机验证且要动打包链（`--dir --universal`），
  而当前没有 Intel 消费方把这件事顶到前面；按 D3 把成本与验证点写清楚后，它可以随时重启而不是被遗忘。
- **保持「缺口」叙事、不决策。** 否决：缺口不排期又不决策，下一个人要重新调研一遍（P-01 的形态）；
  「登记下轮」需要一个接住它的决策文，这就是本 ADR。

## 后果

- 正面：x64 从「挂着的缺口」变成「有适用范围 + 有逃生路径的决策」；CHANGELOG 不再每版重述。
- 代价（如实保留）：Intel Mac 用户本轮不受支持；若真出现该类需求，universal 工作量（M 级 + Intel 对照）
  在 D3 里已经预置，不需要重新调研。
- 后续：本决策与 DA-15 相邻项（接入 SDK 与运行时物化的 intel 兼容性）互为前提——D3 的验证面已包含后者。

# ADR-0292 · iCloud 同步域内的构建干扰与构建根外迁（验收准备批）

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：同意验收准备批）＋ agent（取证与修复）
- 决策记录：[Note](../notes/implemented/packaging/2026-10-11-packaging-outside-icloud.md)（本批实现读数落定后补齐）
- 相关：[ADR-0271](ADR-0271.md)（内测 DMG）、[ADR-0281](ADR-0281.md)（签名归一化）、[ADR-0291](ADR-0291.md)

## 背景

本仓库检出位于 macOS iCloud Drive 管辖范围（`~/project` 经 Desktop & Documents 同步，`bird` 常驻）。2026-10-11 的 DMG 重建批中，producer 连续以两类守卫失败：① profile-template 精确条目校验（顶层出现多余 `.DS_Store`）；② runtime-artifact attestation 的树稳定性守卫（`installed artifact directory changed while it was inspected`）——同步守护进程在构建期向新目录写入 `.DS_Store`（实测一次残留目录内 8 个）。`com.apple.fileprovider.ignore#P` 扩展属性不随子目录继承（实测），无法作为防线。

## 决策

1. **构建根外迁**：`packaging-sage/lib/common.sh` 与 `scripts/lib.mjs` 提供单一家环境覆盖 `PACKAGING_STAGING_ROOT` / `PACKAGING_RELEASE_ROOT`（默认不变）。所有触碰构建根的位置（produce、assemble 的 owned-root 白名单、write-manifest / write-build-metadata / write-dmg-receipt / verify-dmg-volume、accept-dmg 默认值、signing-normalized-tree 的临时目录）统一经 `ownedPackagingRoots()` 读取。iCloud 检出场景以 `PACKAGING_STAGING_ROOT=$HOME/.sage-packaging/staging`（同步域外）运行整条链。
2. **防御性归一化**：producer 在校验前调用 `removeMacosMetadata()`（仅精确移除 `.DS_Store`，计数并打日志，与既有「removed N pnpm metadata files」同款）——外迁后此为纵深防御，不替代决策 1。
3. **接受批的边界（侦察结论）**：打包数据的组织策略文件由 operator 供给且必须在首启之后写入（pristine 门禁）；干跑 A 版（signed-out → 选择拒绝 `identity-session-unavailable`、store 零 `revision-entered`）不依赖任何新授权；B 版（登录后全流程干跑）被 WT-02B.2B（真实 OIDC provider）阻塞，真实模型调用验收另需用户单独授权——两者均登记，不在本批宣称完成。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| fileprovider.ignore xattr 排除 staging | 否决：实测不随子目录继承，构建树每级都需设置，不可维护。 |
| 依赖现有校验自动重试 | 否决：竞态在 digest 窗口内发生，重试只是赌博；P-家族禁止以概率换绿灯。 |
| 迁移整个仓库出 iCloud | 超出本批职权（用户工作区选择）；构建根外迁已消除构建面风险。 |
| 干跑并入 accept-dmg 第三相位 | 暂缓：会改 `sage.packaged-acceptance.v1` 既有判据基线；独立 runner 不扰动已通过证据。 |

## 后果

- 链条在 iCloud 检出的本机上恢复确定性：produce / assemble 在同步域外全绿（真实读数见 Note）。
- `PACKAGING_*` 覆盖是本地运行契约扩展；普通检出零变化。
- 未闭：B 版干跑（等 WT-02B.2B 登录）；真实模型调用验收（等用户授权）；干跑 runner 的最终形态（独立脚本）。

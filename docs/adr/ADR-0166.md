# ADR-0166 · Compatibility 双层 exact-digest：稳定语义摘要与单次完整证据分离

- 状态：accepted（2026-09-28）
- 日期：2026-09-28
- 决策者：用户（lute）
- 决策记录：[Note](../notes/proposed/architecture/2026-09-28-compatibility-authority.md)
- 细化：ADR-0165 D2～D5、D10；不取代其责任分离、fail-closed、availability 分层与产品编排决定

## 背景

WT-02C.1 的 fixed-fixture resolver 直接以完整 `targetDigest + inventoryDigest` 匹配 matrix rule。前者绑定具体 matter/revision，后者绑定 generation、boot 与 observation window；它们适合证明一次求值看到了什么，却不能作为 app-bundled immutable matrix 可预先发布、审阅和撤销的长期匹配键。若按每个 matter、revision 或 boot 动态生成 matrix，会绕过 Sage Compatibility Authority 的发布链。

摘要还只证明 canonical bytes 的内容身份，不证明谁产生、审核或观察了这些内容。[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)要求参与 hash/signature 的 JSON 具有不变表示；[SLSA artifact verification](https://slsa.dev/spec/v1.2/verifying-artifacts)进一步区分 artifact digest、provenance 与预配置 trust root。因此 stable digest 不能替代受信 provider、artifact attestation、Registry provenance 或 main-owned live observation。

## 决策

1. **采用双层 exact-digest。** v2 matrix 只按 `targetSemanticDigest + runtimeDescriptorDigest` 唯一精确匹配；每次 resolution 仍须验证 `targetEvidenceDigest + inventoryEvidenceDigest`。stable pair 只负责 lookup，full pair 证明本次实例。
2. **Stable digest 不是执行 authority。** 它不能替代 current revision、identity / policy、完整 inventory、matrix lifecycle / revocation、availability 或每个真实副作用前的 fresh preflight，也不能作为可重放授权凭证。
3. **Target 分层。** `targetSemanticDigest` 覆盖精确 action policy / effect / decision requirement、permission 与 data-destination 的稳定 policy / contract 语义，以及 Provider / Model / Agent / Preset / Capability 的精确 requirement；`matterId`、`revisionId`、`revisionDigest`、具体组织 / 账户 / 资源、decision、attempt 与时间只进入 full target evidence。
4. **Runtime 分层。** `runtimeDescriptorDigest` 覆盖 Host / Harness / Provider / Model / Agent / Preset / Capability 的稳定 identity、精确版本、实际 artifact / tree、normalized contract / configuration、Registry descriptor、Adapter mapping 与影响行为的 protocol / launch / overlay policy；active generation、receipt、boot、runtime generation、observation window、health / liveness 与 instance authority 只进入 full inventory evidence。
5. **字段必须显式分类。** 每个输入字段只能归入 `semantic-key material`、`full-evidence-only material` 或 `forbidden / unresolved`。未分类、只存在自由文本、使用 mutable alias 或无法证明 canonical subject / provenance 的字段阻断 descriptor 生成，不得默认忽略。
6. **MatrixV2 仍是唯一 exact pair。** rule 至少包含 `ruleId`、`targetSemanticDigest`、`runtimeDescriptorDigest`、`outcome` 与 `reasonCode`；rule ID 与 stable pair 均全局唯一。零命中、重复、冲突、歧义、未知版本或错误 namespace 都返回 `unknown`。首版不引入 SemVer range、wildcard、selector DSL、priority 或 first-match。
7. **v1 冻结，v2 新建合同。** C1 v1 继续作为 fixed-fixture / migration evidence，不原地改变 `targetDigest`、`inventoryDigest` 或 matrix v1 字段语义。v2 使用独立 schema、canonicalization version 与类型隔离的 URN。迁移可以 dual-compute / shadow compare，但不能 dual-authorize，也不能在 v2 miss 时 fallback 到 v1。
8. **未来 evaluation evidence 同时绑定两层事实。** WT-02C.3 的 `CompatibilityEvaluationEvidence` 至少绑定 matter / revision / action scope、full pair、stable pair、`matrixId`、`matchedRuleId`、outcome、evaluation time、resolver contract 与当时 provenance / revocation。历史 outcome 不用当前 matrix 或 descriptor 重算改写。

### 字段分类

| 事实 | Stable target | Stable runtime | Full evidence / evaluation | 约束 |
| --- | --- | --- | --- | --- |
| schema / canonicalization version | 是 | 是 | 是 | 各层独立版本并进入各自 digest。 |
| action scope / effect / decision requirement | 是 | 否 | exact action intent 进入 evaluation | set-like 字段规范化排序。 |
| matter / revision identity | 否 | 否 | target evidence | 必须绑定 current revision。 |
| permission / data destination | policy / contract 语义 | enforcement / endpoint 语义 | exact instance boundary | 自由文本和具体账户不能同时冒充 stable policy。 |
| Provider / Model / Agent / Preset | requirement identity / exact version / artifact / contract | observed stable identity / version / artifact / contract / config | provider provenance 与 instance authority | mutable alias 为 `unknown`。 |
| Capability | requirement identity / version / artifact / contract | artifact / tree / config / contract / Registry / Adapter mapping | attestation、Registry snapshot 与 revocation | 自报 metadata 只是 candidate。 |
| materialization | 否 | 只有跨安装稳定的 portable artifact-set subject 可进入 | generation-specific receipt / materialization | 含路径、时间、generation 或 receipt metadata 时只能进 full evidence。 |
| generation / receipt / boot / observation | 否 | 否 | inventory evidence | 变化必须改变 full digest。 |
| health / liveness / identity-policy result | 否 | 否 | evaluation / fresh preflight | compatibility 不替代 availability 或 authority。 |
| token / secret / raw credential | 禁止 | 禁止 | 禁止进入 compatibility evidence | 仅可引用非秘密、受控的 vault / session reference。 |

v2 使用类型隔离的内容地址：

- `urn:sage:target-semantic:sha256:<64-lowercase-hex>`
- `urn:sage:runtime-descriptor:sha256:<64-lowercase-hex>`
- `urn:sage:target-evidence:sha256:<64-lowercase-hex>`
- `urn:sage:inventory-evidence:sha256:<64-lowercase-hex>`
- `urn:sage:compatibility-matrix:sha256:<64-lowercase-hex>`

所有 digest 都必须定义 canonical subject、算法、编码、版本与字段语义；非空字符串、`sha256:<label>` fixture 或对象自报 digest 不能进入产品 authority。

### Owner 与后续批次

| Owner / ticket | 责任 |
| --- | --- |
| `CompatibilityTargetProvider` | 由 product/security governance 产生 target semantic descriptor 与 full target evidence。 |
| WT-02C.2A～2C / `RuntimeInventoryProvider` | 提供 artifact attestation、boot-scoped observation、外部 capability contract，并由 Electron main 形成 runtime descriptor 与 full inventory evidence。 |
| WT-02C.2D / Capability Registry | 拥有 descriptor provenance、产品 allowlist、Adapter mapping 与 revoke。 |
| Sage Compatibility Authority | 预发布 immutable MatrixV2；禁止 per-instance 动态铸造。 |
| `CompatibilityResolver` | 从 exact-parsed、已验证内容重算 stable / full digest；不接受 UI、Host、插件、模型或普通调用方提交 authoritative digest。 |
| WT-02C.3 / WT-02D | 分别持久化 evaluation evidence、完成 trusted composition 与唯一产品编排。 |

## 备选方案

| 方案 | 为什么未采用 |
| --- | --- |
| 继续使用完整 digest pair | 无法预发布，只能按未来事项和 boot 动态造 matrix。 |
| 从现有 digest 截断或机械删除字段 | digest 不可逆，字段删除也不能证明投影保留全部安全语义。 |
| selector、SemVer range 或 wildcard matrix | 会形成新的策略语言，并引入重叠、优先级与意外放宽。 |
| 人工 compatibility class ID | 裸 ID 可被重绑并发生语义漂移；内容寻址后实质仍是本决策。 |
| 只保存 stable pair | 无法解释具体 revision / boot，也无法阻断跨实例 replay。 |
| v2 miss 后 fallback 到 v1 | 会把 fixed fixture authority 升级成生产允许结论。 |

## 后果

- 正面：matrix 可以随 app 预发布、审阅、内容寻址和撤销，不再依赖未来 matter / boot。
- 正面：不同实例可复用同一 stable pair，同时每次求值仍保留完整 revision、boot、时间与 provenance。
- 代价：必须新增 v2 descriptor / evidence / matrix contract、受信 providers、Registry provenance 与 evaluation evidence。
- P0 风险：semantic projection 漏字段会错误合并不同语义；WT-02C.1B 必须以成对反例和 golden vectors 证明瞬态变化只改 full digest、语义变化同时改变 stable digest。
- P0 风险：stable pair 被当成授权会产生跨 revision、boot、organization 或 action replay；产品只能消费完整 trusted composition。
- P1 风险：远端模型、Provider endpoint 或 mutable alias 无法提供不可变部署身份时必须保持 `unknown`。
- 边界：本 ADR 只决定合同与字段分层，不实现 MatrixV2、ResolverV2、provider、Registry、event schema、Application Service、UI、插件授权或真实动作。

## 背景

侧栏导航的「共识」曾存在三个结构性缺陷，逐一取证确认（研究规格 `.scratch/sidebar-research/spec.md` §7、总账 P-51）：

1. **编号同名异指**：研究规格的 D1–D5 与 ADR-0124 的 D1–D6 是两套编号，「D5」在两处指两件不同的事
   （侧栏宽度 vs 判据射程），引用无法落位。
2. **记录强度 ≠ 共识强度**：ADR-0124 状态 `accepted`，但用户实际只给过 P0 的口头放行（「同意 开始 P0」）；
   研究规格却把四带结构整体标为 `decisions_locked`。用户 2026-09-18 原话证明收口并未发生：
   「我们还没有形成统一的侧边导航栏修改的共识方案」。
3. **量化前提证伪**：四带重组曾引用的「DSH 侧栏 350pt、五者最宽」是截图文范围估算；像素实测 **279pt**，
   落在参照带 252–280pt 之内（基座布局契约 `layoutInfo.sidebar` 初值 280，双来源互证）。

用户选择的收口方式是最严格的一种：**四条结构决策同批、当场、逐项裁决，冻结为本契约**（决策票 S-1：
「一次把四带契约全部裁决」）。裁决全程的可验证凭证是 `.scratch/sidebar-research/N1-decision-ticket.md`。

## 决策

**D1（四带结构）** 侧栏按四层组织并冻结：**启动带 / 能力带 / 内容带 / 系统带**。
任何新的侧栏条目必须先声明它属于哪一带；不属于任何一带的条目不得进入侧栏。

**D2（启动带）** 形态沿用 ADR-0124（两条同轴 `nav-band` 导航行，官方按钮去外壳）；行高定案 **36px**、
行距沿用原生节奏 `margin: 2px 0`（决策票 S-4）。30pt 方案**作废**——它要求三行同改且与 ADR-0079 行轴不同族。

**D3（split 恢复为 API 可选形态）** `position` 还原为四值 `'before' | 'after' | 'split' | 'stacked'`，
宿主默认 `'stacked'`；`applySplitGeometry()` 与宽阈值常量恢复，三份副本逐字节一致的同步约束不变。
**本条取代 ADR-0124 D5 的「split 列退役」前提。** 约束：split 形态**不进当前行轴门禁的射程**——
门禁断言的是宿主启用的默认形态（stacked）；在任何宿主启用 split 之前，必须先扩充
`scripts/gates/sidebar-row-axis.mjs` 使其同时断言两种形态的行轴（否则「可选」只有一半在判据里）。
本轮**不采购**「用户可切换」的偏好载体（决策票 T-2 选了 API 可选以控制范围；切换载体另立决策）。

**D4（能力带）** 任务板 / SSH / 技能中心 / 岗位矩阵收进 **「工作台 ▸」折叠组**：L1 一个入口行，L2 四项。
L2 的承载方式（官方 L2 slot 还是 DOM 注入）是实现期 spike（研究规格 §P1 已倾向首选 slot），不是本契约的内容。

**D5（内容带）** 以会话 / 工作区为主体；**置顶与搜索行同进 P1**（决策票 T-5）。
区内次序：会话 → 工作区 → 置顶 → 搜索。

**D6（系统带）** 冻结：设置 / 帮助 / 账号本轮不纳入重构范围。

**D7（宽度）** 目标 **264px**——基座硬性夹逼区间 `clampWidth(px, 264, 420)` 的下界（决策票 T-1；
用户在知悉 252 越界后由 252 改判 264）。兑现路径按序取证：P1 spike「插件能否写布局 store 的 sidebar 偏好」；
不行则由用户拖拽到达（264 在区间内）。**且宽度从此是判据**——见 D8。

**D8（入口纪律升门禁）** 「官方 UI 改写锚禁止钉哈希」（ADR-0019）与「同列同行轴清单」（ADR-0079 / ADR-0124）
合写为侧栏**入口契约**并升为门禁；**判据面新增宽度断言**（目标值 264px、且读数必须落在夹逼区间之内）——
解决总账 P-51 登记的「宽度无门禁」缺口。

## 备选方案

1. **252px（精确比照 Qoder）。** **否决**。基座 `clampWidth(px, 264, 420)` 决定正规路径到不了 252；
   CSS 强改壳的 inline `grid-template-columns` 会让拖拽手柄（`left: cols.sidebar`）与渲染宽度脱钩，
   拖一次就跳。用户在知悉 264 与 252 只差 12pt 后改判 264。
2. **split 用户可切换（设置页开关 + 偏好持久化）。** **否决**（本轮）：决策票 T-2 选了 API 可选；
   偏好载体另立决策，不在本契约范围。
3. **只冻结前三带（启动/能力/内容）。** **否决**：决策票 T-3 选了四带全冻结。
4. **内容带分期（P1 置顶、P2 搜索）。** **否决**：决策票 T-5 选了两者同进 P1；代价是 P1 容量增大，记入后果。
5. **只写 ADR 不升门禁。** **否决**：决策票 T-6 选了升门禁（含宽度判据）。

## 后果

- **分期重排**：P1 = 「工作台 ▸」折叠组组 + 置顶 + 搜索 + split 恢复（API 可选）+ 264px 兑现 spike；
  P2 起为内容带其余增项。P0（启动带去按钮化）已交付，见 [ADR-0124](ADR-0124.md) 的决策 Note。
- **门禁新账**：`sidebar-row-axis` 需新增宽度判据（D8）；任何宿主启用 split 前必须把它扩成双形态断言（D3）。
- **被取代项**：ADR-0124 D5「split 列退役」前提失效（其断言面与 nav-band 列断言仍有效）；
  研究规格 spec.md 的 D1–D5 编号作废，全文仅留作取证底账。
- **明确不在射程内**：会话行与工作区行的**内容结构**、系统带的细节、L2 承载方式——各待另立契约或实现期 spike。

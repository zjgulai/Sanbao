# ADR-0129 · 管理层（MGT）Preset 以评估载体身份整合，不进出货面

- 状态：accepted（2026-09-19）
- 决策者：用户（lute）+ 管理层整合设计轮
- 决策记录：[Note](../notes/features/contract/2026-09-19-mgt-layer-preset-integration.md)
- 取证附件：[research/16 · 53 数字员工全量机械审计](../research/16-organization-audit-53-roles.md)、执行计划 [docs/plans/2026-09-19-mgt-preset-integration.md](../plans/2026-09-19-mgt-preset-integration.md)
- 相关：ADR-0008（基座只 pin 不改）、ADR-0009（一份事实一个家）、ADR-0015（Note 纪律）、ADR-0020（岗位小队=单 preset）、ADR-0021（声明 vs 供给差必须披露）、ADR-0022（icon 官方字段）、ADR-0056（PRODUCT_MOUNTS 置空）、ADR-0061（agentPresets 双通道）、ADR-0072（skill-subset 白名单）、ADR-0073（出货面白名单）、ADR-0092（新增 preset 先例）、ADR-0093（事务化写盘）、ADR-0094（门禁记账）；材料仓 ADR-0014（管理层决策权平面，注意与本仓 ADR-0014 门禁豁免无关）

## 背景

产品是 toB 跨境电商企业 AI Native 组织转型：50 个数字员工（AGT-001~050）以
`agt-NNN` preset 形式构成经营+管理全链路，全部 `production_authorized=false`、协作关系
为设计期合同、运行时零编排。材料仓（`/Users/lute/project/AI组织变革`，GitHub
zjgulai/AI-Native-Organization）于 2026-09-18 新增**管理层 v2**：3 个 CXO 岗位
（MGT-001 持衡 CEO / MGT-002 驭浪 首席增长官·覆盖 38 岗 / MGT-003 明界 首席治理官·
覆盖 12 岗），定性为**决策权平面**而非 Agent 层级——不与 50 岗会话、不进 Case 执行链、
只读聚合视图、权力仅通过版本化契约（MDC/GOC）与配额生效（材料仓 ADR-0014）。

用户要求把 3 个 CXO 以与 50 岗同范式的 preset 形式整合进来。三个约束塑造了全部决策：

1. **材料侧红线**：「若目标 Host 只能通过 Prompt 层表达口径冻结与复核线隔离，MGT-003
   不得进入 Shadow 阶段」——而 DSH preset 恰是 Prompt 层表达（persona + skill-subset），
   无服务端权限控制能力。
2. **验证状态**：MGT-EVAL-B（决策一致性）2026-09-18 已执行且**未通过**（阶梯归属一致率
   66.7% < 100%）；R0 结构必要性对照臂（单一通用管理 Agent）未获授权——「本层是否应该
   存在」尚未可反证。
3. **爆炸半径**：存量 50 preset 的 shared_source_hashes 覆盖 8 个共享材料文件，任一
   共享源改动 = 50 个全量重生成（research/16 §3.6 定量核实）。

## 决策

九条。D1~D6 是整合本体，D7~D9 是同轮全量审计（53 岗）的处置。

**D1 授权姿态：评估载体 + 本机装配，不进出货面。** mgt-001~003 生成为 profile 可加载
的 preset，用途限定为 MGT-EVAL 评估载体与人在环决策演练；`shipped-presets.json` 走
exclude 档登记（不登记则装配中止，此步不可省）。进出货面的前置条件：MGT-EVAL-A/B 通过
+ R0 对照臂有结论 + 另立 ADR 评审。persona 与 manifest 必须携带状态披露块：未授权
Shadow/生产、EVAL-B 未通过（带时点）、Prompt 层边界不构成服务端权限控制、三条承重
机制（口径冻结签署校验/复核线只读通道/旁路直达）需模型外构件而本 preset 不提供。

**D2 命名空间：mgt-NNN 独立命名空间 + PLN-EXC 投影平面。** 材料侧待决项 MGT-Q1 就此
关闭：MGT 命名空间正式采用，preset 目录 `mgt-001~003`，AGT-001~050 编号不变（ROSTER
「不自动生成第 51 个岗位」原则继续成立）。UI/manifest 分组用新平面 `PLN-EXC`（决策权
平面），order 基座 0（渲染在 4 个执行平面之上），域内 order 101/102/103（CEO 居首）。
**PLN-EXC 是 DSH 投影层平面，不是材料侧第五组织平面**：其显示事实家在
management-catalog.json 新增的 `dsh_integration` 块 + generate.mjs 的 PLANE_BASE；
organization-graph.json 不得新增平面（它在 shared hashes 里，改它即触发 D4 要避免的
全量重生成）。presetId 派生逻辑改命名空间感知（`AGT-→agt-`、`MGT-→mgt-`），修掉
`slice(4)` 会让 MGT-001 撞号 agt-001 的潜在缺陷。

**D3 生成器形态：扩展 generate.mjs 双装载分支。** 同一脚本新增 MGT 装载分支：读
management-catalog.json（MGT 侧共享源）+ 每岗 4 件（岗位卡/soul/playbook/blueprint，
位于材料 `04-organization/management/`）+ 管理层设计文档（MANAGEMENT-LAYER /
DECISION-RIGHTS / ENFORCEMENT / SHADOW-VERIFICATION 状态段）进 mgt manifest 快照。
复用原子写、事务恢复（ADR-0093）、unmanaged-rows 保留、persona 渲染骨架、skill-subset
行（ADR-0072）。MGT 分支差异：无 squad/lead 规则（standalone-only，manifest 记
`case_role_participation: none`）、无产品行（PRODUCT_MOUNTS 本就为空，ADR-0056）、
catalog 的 FLOW 引用归档为组合级指针而非实例化流程记录。**材料侧 eval 状态入共享
快照**：材料仓更新验证状态 → 3 个 MGT preset 自动重生成、披露块自动更新（状态不会
腐烂成谎话）。MGT 共享源与 AGT 共享源在快照中相互独立。

**D4 协作事实落点：MGT 自有归档，存量零扰动。** MGT↔AGT 覆盖关系（owned_role_ids
38+12=50、AGT-005 复核线独立直达、L2b 通道、决策包交换）以 management-catalog.json
为家，只归档进 3 个 MGT manifest；**不写入 collaboration-graph.json / role-catalog.json /
organization-graph.json / ROSTER.md 等任何 AGT 共享源**。零扰动的精确判据（P1 执行时校准）：
存量 50 个的 preset.yml 与 agent.cordis.yml **字节级不变**；manifest.json 仅允许
generator_revision/generator_rules_revision 变化（generate.mjs 自身哈希入快照，改生成器
必然传染，属机械事实）。执行期实证：编辑 ROSTER.md（共享源之一）曾使 50 个 cordis 的
source revision 全部变化，硬判据当即拦下并还原——该判据有效。
role-matrix 需要展示覆盖关系时从 MGT manifest 反查。若未来决定把覆盖关系并入共享图，
必须先明示「53 个全量重生成 + 门禁账本重算」的代价并另立决策。

**D5 技能供给：定制 T0 子集 + 诚实映射。** MGT 的 T0 子集 = 16 项 T0 剔除 3 项（=13 项）：
`meeting-minutes`（纪要/转述语义与管理层「禁止信息中继」直接冲突）、
`xindaya-translator`、`kami`（租户专属工具，「任何岗位都用得上」判据不成立）。16 个
管理技能名进 skill-map.json：可辩护的 partial（如 全局组合排序→weighted-scoring、
结算与对账差异分析→sn-da-*、增长组合设计→ecommerce-quarterly-strategy），其余如实
gap（预计占多数——管理层技能本无平台对应物，这正是 ADR-0021 要披露的事实），每条带
理由，persona「技能供给实况」逐条呈现。

**D6 账本与门禁。** ① shipped-presets.json：exclude + 3 条（why 写明评估载体与出货
前置条件）；pattern `^agt-\d{3}$` 与 expectPatternCount=50 **不动**——pattern 语义保持
纯粹 =「执行面岗位必发且数量相符」。② live-presets.expected.json：presetCount 53→56、
rowCount/rowIdentitySha256 重算（ADR-0094 记账纪律）。③ verify-lossless：L1 改双覆盖
（50 AGT ← role-catalog；3 MGT ← management-catalog）、L10 头像 53 枚唯一、新增 MGT 层
校验（decision_rights 归档、状态披露块存在、T0 剔除项确实不在、eval 状态哈希一致）。
④ 数量断言最小单一事实源化：generate.mjs「期望 50」等硬编码断言改为从材料 catalog 的
role_count 派生 + 显式常量对照（审计发现 C 的本期最小改，彻底源化留债务）。

**D7 collaborates_with 为有向边（审计发现 A 的处置）。** 材料侧 **DECISIONS.md（D-066）**
登记声明：`collaborates_with` 是**有向**声明，声明方 = 协作发起方；枢纽岗
（AGT-021/044/043/013 等控制/合规/平台侧）被指不回指是设计意图而非缺陷。声明不落
role-catalog.json 的 semantics 字段、**也不落 ROSTER.md**——两者都在 AGT 共享快照内
（ROSTER.md 是 12 来源之一），动它即触发存量 50 全量重生成，与 D4 冲突（P1 执行期已
实测并还原）；若未来需要机器可读语义，须先接受重生成代价并另立决策。
门禁只校验悬空引用（指向不存在岗位），**不校验对称性**；66 处既有非对称不得被当作
缺陷「修复」。同一声明在材料侧说明：collaboration-graph.json 是 Case 编排图（角色→
流程/阶段/产物边），角色间协作事实唯一住在 role-catalog（审计发现 F）。

**D8 材料侧待决清单 closure。** MGT-Q1（命名空间）随 D2 关闭；MGT-Q2（MDC/GOC 成为
第六类契约）关闭为**采纳**（mgt manifest 归档 MDC/GOC 引用即以其成立为前提）；MGT-Q3
（Action Intent 策略模板提案权）关闭为**维持不授予**。三条登记进材料仓 DECISIONS.md。
MGT-G8（三条承重处置）、MGT-G9（重排程通道）、MGT-Q5（R0 对照臂授权）**保持待决**，
本 ADR 记录依赖关系：Q5 未授权 = D1 出货前置条件之一未满足。材料仓改动（P0）先于
生成器改动（P1）落地。

**D9 同轮审计其余处置。** B：T0 租户专属工具（xindaya-translator/kami）挂 50 岗的
问题登记为**独立债务**，本期只在 MGT 侧剔除，不动存量（不混入爆炸半径）。D：材料侧
补「责任域（catalog group）与平面（plane_id）两轴正交」说明（纯文档——财务与合规域跨
三平面是独立性设计使然）。E：AGT-002 第 4 项技能的材料侧例外理由登记（纯文档）。

## 备选方案

- **agt-051~053 顺延编号**：管线零改动，但把决策权平面混进执行面编号，违反材料侧
  设计与 ROSTER「不自动生成第 51 个岗位」原则，语义污染最重。弃。
- **立即随包出货**：CXO 层是 toB 产品故事的高点，但 EVAL-B 未通过 + R0 未授权即进
  出货面，正是 pitfalls-playbook 第一条「未验证的事实被钉进出货面」。弃，改为 exclude
  档 + 显式出货前置条件（D1）。
- **材料侧归一化**（把 management-catalog 削成 role-catalog 同构 schema）：生成器几乎
  零特判，但 decision_rights/阶梯/队列语义在 role-catalog schema 无位置，归一化即失真，
  违反全量保真原则。弃。
- **独立 mgt 生成脚本**：隔离干净，但原子写/事务恢复/unmanaged-rows 要抽共享库，且
  两条生成管线会漂移成「怎么生成 preset」的两份事实（ADR-0009）。弃，选双装载分支。
- **协作关系写进 collaboration-graph.json**：协作图保持唯一事实之家，但共享源哈希传染
  → 53 个全量重生成 + 账本重算，且材料仓 ADR-0014 只要求管理图增加 MDC/GOC 引用，
  未要求进协作图。弃（D4），保留为未来可另立决策的选项。
- **MGT 零技能供给**（只有 persona）：供给面最窄，但偏离 standard 基座形态、决策包
  产出无 presentation 能力、且要为 MGT 特判掉 skill-subset 行（与官方 preset lint 的
  兼容性未知）。弃。

## 后果

**正面**：存量 50 preset 字节零扰动（D4 的定量前提由 research/16 §3.6 核实）；管理层
披露诚实（评估载体/未授权/eval 状态自动随材料更新）；MGT-EVAL 获得标准化 prompt 载体
（此前评估用手搓 prompt 文件）；出货面语义更纯粹（pattern=执行面必发，exclude=已评审
不发）；审计五项发现全部有处置归属，无静默遗留。

**负面与代价**：preset 体系从此双命名空间（agt/mgt），generate.mjs 在 1232 行基础上
继续增长（双装载分支）；PLN-EXC「投影层平面 vs 材料侧组织平面」的双重语义需要文档
持续解释（家在 D2 与本 ADR）；MGT 技能供给以 gap 为主，persona 披露段会显著长于执行
岗——这是诚实的代价，不是缺陷。

**后续动作**：执行计划 P0~P6（材料侧决策落地 → 生成能力 → 门禁账本 → UI → 审计脚本
正式化 → 文档收口 → 验收）；债务登记两项（T0 租户工具、数量断言彻底单一事实源化）；
出货评审依赖材料仓 MGT-EVAL-A/B 重跑通过 + R0 对照臂授权（MGT-Q5，仍待决）。

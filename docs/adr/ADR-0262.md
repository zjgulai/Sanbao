# ADR-0262 · Sanbao 承载面：Sage 壳以 sage-sanbao:// 非特权面承载 sanbao UI 并注入 `__SANBAO_HOST__` 壳桥

- 状态：accepted（2026-10-05）
- 日期：2026-10-05
- 决策者：用户（lute，2026-10-05 令「继续通过同样方式执行未闭项 1、2、3」——未闭项 1＝壳侧 adapter 由本票执行）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-05-sanbao-host-surface.md)
- 相关：[ADR-0261](ADR-0261.md)（React renderer 裁决）、[ADR-0178](ADR-0178.md)（预览容器先例）、[ADR-0163](ADR-0163.md)（身份/授权 fail-closed）、[UI 一致性合同](../specs/2026-09-27-sanbao-to-sage-ui-consistency-contract.md)

## 背景

「206 页接线程序」把 sanbao_ui（`zjgulai.github.io/sanbao_ui`，本地 `Sanbao/repository-snapshot/apps/sanbao-prototype`）的全部页面收敛到唯一接缝 `window.__SANBAO_HOST__`（protocolVersion 1；无壳＝fixture 原样、有壳读真事实、缺能力如实 unavailable；账本 206/206）。此前壳侧无实现：没有任何 Electron 主进程会注入该桥。未闭项 1 要求壳侧真实提供它。既有先例：`preview-window.ts` 的非特权承载面（独立 partition、禁导航、禁 window.open、无 preload、无网络）。

## 决策

1. **承载面**：新增 `apps/sage-shell/src/main/sanbao-surface.ts`——`sage-sanbao://` 特权 scheme（standard+secure+stream，与 `dsh-app` 同一处、app ready 前注册）；`protocol.handle` 从注入的本地 root（sanbao 原型 `dist/`）**只读**服务文件，realpath 双前缀防穿越，405/404 兜底；承载文档运行在独立**非持久** partition `sage-sanbao`（sandbox、contextIsolation、nodeIntegration:false、webviewTag:false、禁 window.open、禁出 scheme 导航、webRequest 单向闸门——照 `preview-window.ts` 样板）。
2. **桥**：sandboxed preload（`sanbao-host-preload.cts` → `lib/main/sanbao-host-preload.cjs`）以 `contextBridge.exposeInMainWorld('__SANBAO_HOST__', { protocolVersion: 1, 13 方法 → ipcRenderer.invoke('sanbao-host:call', {method, args}) })`；main 侧 `ipcMain.handle` **方法白名单＋参数形状校验**（未知方法→「壳未提供该方法」、坏参→「参数无效」、异常→honest unavailable，绝不让 renderer 看到堆栈）。
3. **端口**：`createSanbaoHostPort(facts)` 镜像 sanbao `src/runtime/host.ts` 的全部 13 方法与类型（出处注释；**不跨仓 import**）。**生产默认 facts＝每方法 honest unavailable（「壳尚未提供该类事实」）**；facts 可注入，测试/探针以真值证明往返。写方法（提交/停止/回答等）与读方法同一纪律：壳没有真事实就如实拒绝。
4. **证据与门禁**：真实 Electron 探针 `test/support/sanbao-surface-probe.mjs`（live/honest/负控三态，具名读数行＋RESULT JSON，exit 0/2/1；负控把期望名换成永不注入值证明断言会红）＋窗口 spec `test/sanbao-surface-window.spec.ts`（3 用例）纳入既有 Vitest/tsc 流程；截图存 `.birdview/evidence/sanbao-surface-2026-10-05/`。
5. **边界保持**：`/.sage/*`、`dsh-app://`、Host 子进程、FramePolicy 特权窗口合同本票均不改；承载面**不启动 Host、不装载 profile**（facts 注入即可）；零凭据、零真实模型/业务调用；sanbao 仓保持只读。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| A. 直接 iframe/webview 内嵌于既有 renderer | 否决：renderer 是特权面；一致性合同禁 iframe 路线；且需要特权 IPC，破坏 renderer 非特权边界。 |
| B. sage-sanbao:// 非特权承载面＋preload 窄桥（采纳） | 复用预览容器安全样板；桥面＝白名单 13 方法；可独立测试、独立失效。 |
| C. 生产直接加载线上 URL（https://zjgulai.github.io/…） | 未采纳为本票默认：网络依赖与发布漂移不可控；本地 root 优先（_site 同哈希回退）。线上 URL 留作分发选项。 |
| D. 让 Host 子进程注入 | 否决：Host 是 profile 运行时，承载 UI 不是它的职责；注入面必须由 main 拥有。 |

## 后果

- 壳侧首次具备「承载 sanbao UI＋注入真桥」的能力：探针证明 live 组读到注入的工作区真事实与会话往返；honest 组保持 fixture 文案并如实提示；负控证明断言会红。gate quick/full 27/27 保持。
- **未接线（明确登记）**：生产启动时创建/打开该承载面（root 指向、打开时机、窗口归属）留待产品接线批次；`will-navigate` 等沿用预览样板、未接入 FramePolicy 特权窗口合同；写路径（startRequirement 等）在生产 facts 下仍 honest unavailable，真接线随各自 authority 批次。
- 后续 sanbao 页面族的真事实接线以本桥为唯一通道扩展（新增方法＝host.ts 与镜像的加法同步）。

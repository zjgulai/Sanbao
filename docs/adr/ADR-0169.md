# ADR-0169 · External MCP Capability Evidence：同代工具合同、可审计 artifact subject 与 boot-scoped availability 分层

- 状态：accepted（2026-09-28）
- 日期：2026-09-28
- 决策者：用户（lute）
- 决策记录：[External Capability Evidence 架构与交接](../notes/proposed/architecture/2026-09-28-external-capability-evidence.md)
- 关联：[ADR-0165 · Sage Compatibility Authority](ADR-0165.md)、[ADR-0166 · Compatibility 双层 exact-digest](ADR-0166.md)、[ADR-0167 · Runtime Artifact Attestation](ADR-0167.md)、[ADR-0168 · Host live inventory projection](ADR-0168.md)

## 背景

Sage 已分别拥有 materialization-time installed artifact attestation（C2A）与 boot-scoped Host/profile observation（C2B），但它们没有证明 profile 外部或经 MCP bridge 接入的 capability 实际执行了哪些 bytes、暴露了什么完整工具合同、当前连接是否仍是同一代，或者工具列表变化后旧证据是否已经失效。

MCP 2025-11-25 的 `tools/list` 支持 cursor pagination，服务器还可以通过 `notifications/tools/list_changed` 表示工具列表变化；同一规范明确要求客户端把 tool annotations 视为不可信提示，除非服务器本身已经是受信来源。当前 seed pin 为 `@deepseek-ai/dsh-mcp-client@0.1.5-rc.2`，lock 解析到 `@modelcontextprotocol/sdk@1.30.0`。版本字符串、进程存在、连接成功、工具数量或单页 `tools/list` 都不足以构成 Sage authority。

因此 WT-02C.2C 必须先定义可审计、可失效、默认拒绝的 External Capability Evidence；同时保持 C2D Registry、C2E 完整 inventory composition、C3 evaluation evidence 与 WT-02D 产品编排的 owner 分离。

## 决策

1. **由 Electron main 拥有 `ExternalCapabilityEvidenceProvider`。** 它是未来 `RuntimeInventoryProvider` 的子责任。Host / MCP bridge 只提供同一执行连接代上的 raw observation；MCP server、插件、renderer、模型与普通调用方不得提交 authoritative descriptor digest、availability、compatibility outcome 或授权结论。main 负责 exact parse、字段分类、canonicalization、摘要重算、C2B binding、trusted clock 与生命周期失效，但不替 C2D 审批 capability，也不替 Compatibility Authority 发布 matrix。
2. **稳定 descriptor 与单次 observation 分层。** `ExternalCapabilityDescriptorV1` 只包含跨 boot 稳定的 Sage capability identity、已验证 artifact subject、normalized effective tool contract、结构化非秘密 launch/config contract 与 bridge/protocol contract；`ExternalCapabilityObservationV1` 绑定 descriptor、C2B Host projection、MCP connection generation、完整 tool-list observation、具名 discovery/liveness 状态及 `observedAt / expiresAt`。stable digest 不包含 boot、generation、时间、PID、账户或机器路径；full observation 的变化必须改变 observation digest。
3. **Artifact subject 覆盖实际执行闭包。** 首版 local stdio MCP 至少覆盖实际 bridge 与 SDK bytes、launcher / interpreter、server executable / entrypoint、运行时依赖闭包、package / lock 输入、executable bit、安全 link topology，以及会改变行为的结构化非秘密 launch / protocol / overlay policy。package version、package.json、lockfile、命令行、server 自报版本、Git commit、单一 entrypoint hash、启动成功或 `tools/list` 成功都不能单独替代。远端 server 没有可验证 immutable release identity / provenance 时，artifact identity 保持 `unknown`。
4. **Secret、raw command 与机器路径禁止进入证据。** token、cookie、password、API key、refresh token、secret 的 hash、credential path、raw environment、home/cwd/绝对 executable 或 state path、带 credential/query 的 URL、raw shell command 均不得进入 descriptor、observation、日志、denial reason 或持久化 artifact。动态 `PATH`、任意 shell `-c`、command substitution、未分类环境插值、无法闭合的动态 import/plugin root 或 secret/state 与 artifact 无法分离时，返回具名 unavailable，不对“脱敏后的命令字符串”做权威 hash。
5. **工具合同来自同一 MCP connection generation 的完整分页结果。** 第一页不带 cursor；后续只把上一页 opaque `nextCursor` 原样传回。所有页收齐后才形成候选 observation，并跨页拒绝重复 raw tool name、重复或空 continuation cursor、超页数、超工具数、超 canonical bytes 与总 deadline。任一页失败均不产生新证据；cursor、分页边界和服务器页顺序不进入 stable digest。Electron main 不得另开第二条 MCP connection 后把结果冒充执行连接合同。
6. **Normalized tool-contract digest 只证明版本化结构同一性。** stable effective contract 至少包含 raw MCP name、模型实际可见的 description、完整 `inputSchema`、完整 raw `outputSchema` 与 bridge enforcement mode、`execution.taskSupport` 的 effective value、实际 negotiated MCP protocol revision，以及 bridge contract identity。object key 使用与 locale 无关的 code-unit 顺序；工具集合按 raw name 排序；除明确列为 set-like 的字段外不重排数组；不尝试声明不同 JSON Schema 语义等价。`title / icons` 在当前 bridge 未消费时只属 presentation；annotations 是不可信 hints；未登记 `_meta` / extension 阻断 authoritative descriptor，不得静默忽略后继续授权。
7. **`list_changed` 与连接变化是 authority invalidation。** 收到 `notifications/tools/list_changed`、transport close、reconnect、configuration reload、Host / Loader invalidation、active generation / C2A attestation drift、artifact / launch / contract drift、observation expiry、clock rollback或分页不完整时，当前 observation 立即 unavailable。必须在同一新 connection generation 上重新完整分页、exact parse、摘要重算并绑定当前 C2B projection 后才能恢复；bridge 为会话连续性保留旧注册工具，不代表旧 evidence 仍可授权。
8. **Availability 状态不得压成一个 `healthy` boolean。** transport liveness、protocol round-trip、discovery completeness、contract validity 与 operation-specific preflight 是不同事实。C2C.0 / C2C.1 禁止调用真实业务工具；未来 operation preflight 必须由 C2D Registry 与 Capability Adapter 明确登记无副作用语义，受 Identity / Policy 与数据出境边界约束，紧邻真实动作执行，只进入 full evidence，失败即拒绝。tool name、`readOnlyHint`、历史成功调用或工具可见都不能成为 effect / permission authority。
9. **本批只完成治理合同。** WT-02C.2C.0 revision 18 不新增或修改 production source / test，不连接真实 MCP，不执行 `tools/list` 或 `tools/call`，不启用插件，不生成 C2D Registry、完整 `RuntimeDescriptorV2` / `RuntimeInventoryEvidenceV2`、matrix outcome、`CompatibilityEvaluationEvidence`、Application Service 或 UI，也不修改 v1 event schema。

### 后续实现分层

| Ticket | 唯一责任 | 关闭条件 |
| --- | --- | --- |
| `WT-02C.2C.1` | pure descriptor / canonicalization kernel | exact parser、字段三分法、artifact/launch/tool-contract canonicalization、digest namespace、独立 golden 与 hostile fixtures；无 Host/MCP I/O |
| `WT-02C.2C.2` | same-generation raw observation seam | 同一 bridge connection generation 的冻结完整分页 snapshot、bounded limits、list-changed/reconnect/close invalidation；只连隔离 fake server，零业务 `tools/call` |
| `WT-02C.2C.3` | local artifact observer | typed execution manifest、launcher/interpreter/server/dependency closure、bytes/executable/safe links 与动态 shell/PATH/secret refusal |
| `WT-02C.2C.4` | bounded availability/preflight contract | 具名 transport/discovery/contract/preflight 状态、freshness 与稳定无秘密错误码；真实 operation preflight 仍等待 C2D mapping 与 Identity / Policy |
| `WT-02C.2C.5` | main-owned aggregate provider | 把 C2B、descriptor、artifact、same-generation tools 与 trusted clock 组合成 External Capability Evidence；仍不产生完整 inventory 或 matrix outcome |

## 备选方案

| 方案 | 为什么未采用 |
| --- | --- |
| Hash Harness 已注册的 public tools | 会丢失 raw name、分页、raw output schema、bridge 未消费字段与 projection/enforcement 差异。 |
| Electron main 另开 MCP connection 做 inventory | 不是执行连接的同一 generation，工具集可能不同。 |
| 用 package version、lockfile 或 server 自报版本作为 artifact identity | 不证明 resolved SDK、launcher、entrypoint、依赖闭包与实际 bytes。 |
| 只读取第一页 `tools/list` | 分页 server 会得到截断合同。 |
| `list_changed` 后继续沿用旧 evidence | 运行连续性不等于 authority freshness。 |
| 信任 `readOnlyHint`、工具名或描述 | MCP annotations 是 hints，名称与文案都没有 Sage effect / permission authority。 |
| 调用真实工具作为通用 health probe | 可能读取敏感数据、发生出境或产生副作用；MCP core 没有通用 dry-run 保证。 |
| Hash 脱敏后的 raw shell command / environment | 不能证明真实执行语义，secret 或路径 hash 仍可能泄漏。 |
| C2C 直接签发完整 inventory 或 `equivalent` | 越过 C2D Registry、C2E composition、Matrix 与 C3 evidence owner。 |

## 后果

- 正面：C2A installed bytes、C2B Host boot 与 C2C external capability 形成三类独立、可审计事实，不再用“进程起来且有工具”替代完整 runtime evidence。
- 正面：artifact、tool contract、bridge projection 与短生命周期 availability 的变化可以分别定位；`list_changed` 或 reconnect 会立即撤销旧 authority。
- 正面：C2D 可以审批稳定 candidate descriptor，而不是相信 mounted entry、package version 或插件自报。
- 代价：fresh observation 必须排空分页并受 page/tool/byte/deadline 上限约束；当前 bridge 尚需独立 snapshot seam 才能满足同代证据要求。
- 代价：保守 canonicalization 可能让无害 schema 重排改变 digest；首版以 fail closed 优先，不引入 JSON Schema 语义等价器。
- Residual：same-UID 主动篡改、pathname TOCTOU 与远端 server 行为不诚实仍不能完全消除；本合同只证明观察到的内容，不证明 server 的真实业务行为必然符合描述。
- 兼容性边界：实际 negotiated protocol revision 与 pinned bridge behavior 是输入事实；不得用未来 MCP draft/current 语义反向解释旧 client。

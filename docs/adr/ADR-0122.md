# ADR-0122 · 决策记录面向 AGENT：机器可读决策账本（`docs/adr/decisions.json`）

- 状态：accepted（2026-09-18）
- 日期：2026-09-18
- 决策者：用户（lute，明确裁决「adr 机制需要修复，每一轮决策的结果面向 AGENT 都要做 adr 记录」）+ agent（机制与判据设计）
- 决策记录：[Note](../notes/implemented/process/2026-09-18-agent-readable-adr-ledger.md)
- 相关：ADR-0015（决策记录双轨分职，本 ADR 修的是它落下的一半）、ADR-0009（一份事实只有一个家）、ADR-0014（门禁硬门槛，豁免只减不增——本项的 `legacyWithoutDecisions` 复用同一套基线做法）、ADR-0011（能力分组与索引）、ADR-0121（同一批「知道没有变成拦住」的修复）

## 背景

2026-09-18 的文档债务审计给出三条读数，合起来说明**留痕机制把人照顾好了、把 agent 落下了**：

| 读数 | 实测 |
| --- | --- |
| ADR 数量与形式 | 121 篇，编号连续、索引双向一致 —— **形式上完全合规** |
| `状态` 字段的信息量 | **121/121 全部 `accepted`**，没有一条 superseded / withdrawn / proposed ——「这条决策还有效吗」在文件里答不出来 |
| 决策的可机读性 | **0 篇**有结构化决策面。决策只以散文存在 |

而本仓库的写入者绝大多数是 agent。一个新会话的 agent 想「开工前先知道平台立过哪些约束」，唯一办法是把 121 篇 Markdown 读一遍——**它不会读**，于是同一类问题反复返工。这正是本仓库复发故障总账里那条「知道没有变成拦住」的又一个位置。

ADR-0015 强制的是**人读**的四段（`## Problem` / `## Decision` / `## Alternatives considered` / `## Consequences`，由 `verify-agent-note-format` 守着）。它没有、也不该被要求覆盖「机器怎么消费决策」。

另外，`docs/notes/` 的 class 目录实测 7 类，其中 5 类共 91 篇（74.6%）不在 ADR-0015 声明的枚举里，而声明的 `feature/bug-fix/process/testing` 一个目录都没有——**决策记录的元数据面一旦没有被机器读过，它就会漂**。本 ADR 的账本机制正是为了让决策面被机器读。

## 决策

1. **新增机器可读决策账本 `docs/adr/decisions.json`**，它是**派生面**：源永远是 `docs/adr/ADR-NNNN.md`，账本由 `node scripts/gates/adr-agent-records.mjs --write` 生成。两个家会分叉，分叉那天没人知道（ADR-0009）。
2. **新 ADR 必须带 `## 机器可读决策` 块**：该标题下的 ```json 围栏，`decisions` 为非空数组，每项含 `id`（非空字符串）、`text`（非空字符串）、可选 `constraints`（字符串数组）。这是「每一轮决策的结果面向 AGENT 都要做 adr 记录」的机器面。
3. **历史豁免只减不增**：`legacyWithoutDecisions` 记录引入本项时还没有决策块的那批 ADR 编号。**只能变短**——写进一个新编号即判红。基线取 `git show HEAD:docs/adr/decisions.json`，与 `exemptions-frozen` 同一套做法（ADR-0014 / ADR-0056：靠人记得不是工程解）。补上决策块的编号由生成器**自动移出**豁免。
4. **新增门禁 `adr-agent-records`**（含反向自测 `adr-agent-records-selftest`），四条判据：账本与 ADR 文件逐字段一致 · 非豁免 ADR 必须有可解析决策块 · 豁免只减不增 · 分母常显（扫了多少篇 / 有块多少篇 / 豁免多少篇 / 共多少条），射程为空或账本不可读一律判红（P-15）。
5. **`状态` 字段的语义不在本项射程内**。「121/121 全 accepted」这个事实本项**看得见但没有立场判红**——它属于下一轮决策，不是机器能替人拍的那一半。本项只断言账本与文件里那一行的**字面值**一致。
6. **不引入新的目录与第二份实现**：生成器与判据同住 `scripts/gates/adr-agent-records.mjs`，CLI 与门禁共用 `renderLedger()` / `buildLedger()`。

## 备选方案

- **甲：把 121 篇 ADR 全部补上决策块，一次性合规。** 否决。118 篇历史 ADR 的决策是**当时的人**拍的，今天由 agent 反向改写它们的决策面，等于把「当时决定了什么」变成「今天的模型认为当时决定了什么」——那是**伪造留痕**，比没有留痕更坏。豁免清单把这件事**显式**记成「这批还没有机器面」，而不是假装它们有。
- **乙：用 front-matter（YAML）而不是正文里的 json 块。** 否决。front-matter 要求重写 121 个文件的头部，且 YAML 在这个仓库里没有解析器（`yaml` 包的声明本身还是未决债：`dsh-preset-lint-local` 靠探 app 的 node_modules 才解析得到）。正文里的 json 块用零新增依赖就能解析，且**人读时就在决策那一节旁边**——机器面与人面的距离越短，两者越不容易分叉。
- **丙：只在 `docs/notes/` 上加元数据，不动 ADR。** 否决。用户的原话是「每一轮决策的结果面向 AGENT 都要做 **adr** 记录」，且 ADR 是编号时间线（ADR-0015 决策 1）；把机器面挂在 Note 上会让「决策编号」与「可消费决策」分属两个体系。
- **丁：不做判据，只提供生成器。** 否决。生成器不会自己跑；本仓库反复验证过「写了但从没跑到」这一形态（总账 P-04）。判据是这件事唯一的执行者。
- **戊：让门禁自动改写账本（发现不一致就 --write）。** 否决。门禁只读是硬约束；一个会写文件的门禁在并发下会与人的编辑互相覆盖。

## 后果

- 正面：agent 有一条**一条命令可读**的决策面（`docs/adr/decisions.json`），不必读 121 篇散文；「新决策没有机器面」从「没人知道」变成「门禁判红」。
- 正面：`adr-agent-records` 成为本仓库第一条**读 ADR 内容**的判据。此前 `adr-index` 只看文件名与索引、`adr-note-links` 只看链接可达，**没有一条判据看过 ADR 正文说了什么**。
- 负面/代价：每新增一篇 ADR 多写一个 json 块；块写坏时判据会指出具体是哪一项（`decisions[0].text 缺失或不是非空字符串`）。
- 负面/代价：账本是生成物，**手工改它会立刻判红**。这是有意的——但需要在 remediation 里写清楚「重新生成」而不是「手工对齐」。
- 未决/后续：118+ 篇历史 ADR 的机器面**仍然缺席**，由豁免清单显式承载。要不要补、谁来补，是一个需要决策的后续项，不在本 ADR 内假装解决。

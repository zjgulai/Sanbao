# ADR-0148 · 深度分析 TOP20 批次 A：五条机制债收口（聚合层三态 / 权限位判据 / 入库面占位化 / 清场先查承诺 / 单例计数探针）

- 状态：accepted（2026-09-21）
- 决策者：用户（lute）——在「下一批做什么」的选择器里拍板「A（P0 机制债收口）」，工单即
  `.scratch/review/2026-09-20-deep-analysis-top20/` 的 DA-01/02/03/04/06
- 决策记录：[Note](../notes/implemented/contract/2026-09-21-p0-mechanism-debt-batch-a.md)
- 相关：ADR-0075/ADR-0076（三态读数、发布链最后一环）、ADR-0080（已证伪仪器不得再被开成判据）、
  ADR-0014（门禁硬门槛、豁免只减不增）、ADR-0119（入库面）、ADR-0121（对象库卫生）、
  ADR-0067（已发布产物不可删除）、ADR-0111/ADR-0123（清场纪律）、ADR-0115（live 探针家族）

## 背景

2026-09-20 的全仓深度分析（Understand-Anything 增量图谱 + 门禁读数）交出 TOP20 必做清单；
P0 六项全部是 pitfalls-playbook **自己写着「尚无 / 只有纪律 / 缺口不是成绩」**的机制债：
P-17（聚合层把三态压回两态）、P-45（没有任何判据在读权限位）、P-48（入库工具把构建机路径
写回已提交事实源）、P-49（清场清单按体积排序，量不到承诺）、P-52（observer 单例计数只活在
复盘文字里）。它们的共同性质：复发成本高、关闭成本低、彼此无依赖——适合整批收口。

## 决策

**D1（P-17）：聚合层的三态收口 = 汇总行独立成句 + strict 开关，且渲染逻辑必须住在被测得到的地方。**
汇总行渲染从 `scripts/gate.mjs` 的 `main()` 迁进 `scripts/gates/gate-result.mjs` 的
`renderGateSummary()`——`gate.mjs` 导入即执行 `main()`，写在那里的逻辑没有任何注册项测得到；
`skipped > 0` 时输出独立成句「未核对 N 项（不是通过）：<逐项点名>」，不再把「跳过 N」混进
「项通过」那句；`--require-no-skip`（`pnpm run gate:strict`，2026-09-16 已落地）与日常宽容语义
在 help 文本与账本里分开写清。两态与渲染句分离由 `gate:result-selftest` 守。

**D2（P-45）：权限位判据的射程 = 本轮改动面，判「谁都读不了」，记账单位 = 可判文件。**
`gate:permission-bits` 复用 `changed-packages` 的四类来源并集（刻意**不**全仓扫描——噪声会把
判据变成被关掉的判据，P-07）；判「三个读位全空」（`000` 及其变体 `020/040/060`）与「读位齐备但
`R_OK` 被拒」两形态；判红点名「文件 + 权限位」并把**先 stat 再怀疑任何人**写进文案；已删除路径与
非普通文件只进 note 读数；射程里没有可判文件时给 skip 而不是 pass（P-15）。

**D3（P-48）：入库面占位化 = 写入者直写占位符（首选）＋ 判据读入库面（第二重）。**
写入者（`intake-install.mjs` 的 `_meta.from`/`sourceUnit`、`scan-runtime-deps.mjs` 的
`_meta.from`/`venvPython`）经 `intake-lib.mjs` 的 `sourceUnitPlaceholder` / `dshHomePlaceholder`
直接写占位符；`__DSH_HOME__` 的语义 = `~/.dsh` 本身（与已提交值一致）。判据 `gate:intake-placeholders`
只读两份已提交清单，逐行判 `/Users/…` 与字面 `$HOME`，判红点名「文件 + 行」；读不到/射程为空判红。
射程与出货链的 `rewrite-build-paths.mjs`（ADR-0073）划清、不双写。

**D4（P-49）：清场三步序固化进工具，体积只在①②都为否时出场。**
`scripts/cleanup-inventory.mjs`：①承诺（发布清单 `SHA256SUMS`/`*.sha256`、`uchg` 标志、
门禁射程、ADR 决策段）→②引用（`git grep` 代码目录）→③体积；①②任一命中即出局进「证据面」。
顺序是结论的一部分：先量体积再问承诺，结论会整个翻转（P-44 同族）。与 `gate:object-store-hygiene`
（管**没有承诺**的对象）分工写进模块注释；工具是**读数不是门禁**（不判红、不删除）。

**D5（P-52）：observer 单例计数落成可执行探针 + 共享层读数指引 + 死仪器登记。**
`scripts/acceptance/singleton-count-live.mjs` 覆盖 workbench 容器 / 组行 / 设置壳根三类单例
（恰好 1 / 至多 1），数到 2 直接点名「重复挂载」；「读不到」（CDP 不通、选择器求值失败、
必需单例数到 0）一律 exit 2 并点名，绝不当成通过；`--self-test` 9 状态 / 18 断言，恒真桩突变下必红。
`shared/client/sidebar-entry-core.ts` 的不变量注释加「改 observer 前先数单例」的读数指引
（`sync-shared` 保副本一致）；被证伪的仪器（把「探针打点 / 代码内观测」有没有输出当存活证明）
登记进 `scripts/gates/dead-instruments.json`。

## 备选方案

- **只改账本、不动代码**：否。把「尚无」改成「已记账」正是「知道没有变成拦住」（P-03），五条债会原样复发。
- **放宽 skip 语义让门禁更容易全绿**：否。ADR-0014 与 P-02 的直接约束——修法是把读数改诚实，不是改好看。
- **permission-bits 全仓扫描**：否。日常权限差异变噪声后判据会被关掉（P-07）；覆盖面靠「提交前必跑」。
- **D3 只加判据、不改写入者**：否（备选优先序）。判据会在每次受认可的重跑后判红，正确处置退回「每次手工占位化」。
- **D4 沿用「体积 + 有没有人 import」两把尺子**：否。那正是 P-49 事故的原清单；两把尺子都量不到承诺。
- **等 observer 竞态可静态判出再上机制**：否。运行时竞态无法静态判出是设计性边界，不是不落最小机制的理由。

## 后果

- quick 门禁 113 → 121 项（新增 4 判据 + 4 反向自测）；五条「只有纪律」的债各有了可执行读数。
- DA-13（.scratch 42 工作流清场）解锁——硬前置就是 D4。
- 边界：单例探针是实机读数，需要应用带 CDP 端口启动由人跑，不进 `pnpm run gate`；
  D2/D3 会给「改动面出现 000」与「入库面被写脏」判红——这两种红都要求处置，不是噪声。
- 本批不改任何产品行为；DA-05/DA-12（基座事实与生产机现状）仍待做。

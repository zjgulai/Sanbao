# ADR-0160 · 本机活动仓基线与历史能力隔离

- 状态：accepted（2026-09-27）
- 日期：2026-09-27
- 决策者：用户（lute）
- 决策记录：[Note](../notes/implemented/process/2026-09-27-local-active-repository-baseline.md)
- 相关：ADR-0157（深度开发前置基线）、ADR-0159（Sage 自有桌面端）

## 背景

Sage 的原施工仓被整体搬到普通本地文件系统后，仍保留 `main` 与 `origin/main` 分叉、三层 dirty 状态、历史 worktree 元数据、ignored 发布物和大量旧插件/缓存。直接在该状态继续开发，会把 ECC 试验、旧 UI、受控浏览器、legacy 门禁和历史发布链混入新的产品主线；继续在 iCloud 活动开发又会放大 Git 与文件扫描延迟。

## 决策

1. 活动开发仓位于普通本地文件系统，使用 `main`；仓根由 Git 或脚本自身位置动态发现，不在代码、测试或维护命令中新增机器绝对路径。
2. 在重建基线前，以完整物理快照、全 refs bundle、ECC/P0 独立 bundle、staged/unstaged patch 与 untracked 副本建立恢复边界。历史 DMG、stash、`.qoder` 和 worktree 元数据均留在恢复源，不因本次基线重建而删除。
3. `origin/main` 是新基线。七个本地 ECC commits 只归档、不回放；远端三个 revert 保持权威。
4. BASE 只回放已核验的 Sage Shell、Capability Adapter、产品边界、数据隔离、候选品牌资产和当前 ADR。受控浏览器、legacy 门禁、Laya、旧插件、packaging/DMG 接线、缓存和验收证据全部暂缓。
5. 历史名字只在 provenance、许可证、vendor pin、兼容输入和历史记录中保留；当前产品入口统一为 Sage，但不做全仓字符串替换。
6. 裸 `scripts/gate.mjs` 与默认 `pnpm run gate*` 都只运行 Sage BASE 固定 allowlist；Sage 的服务消费登记只扫描 `apps/sage-shell/`。历史平台、旧插件、live profile、旧 UI 和 release / DMG 门禁保留为显式 `gate:legacy*`。BASE 只修复动态仓根与 legacy packaging 路径卫生，不把旧打包线接成 Sage 发布链。

## 备选方案

- **继续在 iCloud 目录开发**：拒绝。当前仓的 Git 状态读取曾出现显著文件系统等待，无法成为高频开发基线。
- **把搬入的旧仓直接视为新基线**：拒绝。它仍是 ahead 7 / behind 3，且 staged、unstaged、untracked 相互叠加。
- **整提交 cherry-pick 临时 Sage 快照**：拒绝。该快照同时包含受控浏览器、scratch、Laya 等本批明确暂缓内容。
- **全仓把旧名字替换为 Sage**：拒绝。会破坏兼容契约、第三方事实、历史证据和负向门禁 fixture。

## 后果

- 活动 `main` 可在最新远端基线上只承载最小 Sage P0；旧插件默认不连接、不作为启动依赖。
- BASE 完成后仍会有一组未提交的受控回放变更；用户未授权 commit/push，因此不把写入误报为已固化。
- 完整恢复集位于仓外的 `Sage-recovery-20260927-base01/`；当前仓不依赖它运行，但删除前必须另行确认。
- ignored 缓存、历史发布物和失效 worktree 注册的物理清理属于后续 CLEAN / 维护任务，不在本 ADR 中授权。
- Sage BASE 门禁通过只证明当前壳、边界、路径和治理记录可继续开发；legacy 门禁未运行或通过，都不能证明 Sage.app 已具备发布能力。

# ADR-0150 · 上游平台名 `DeepSeek Harness` 从可见 UI 面清出（brand-surface 补丁）

- 状态：accepted（2026-09-21）
- 决策者：用户（lute）——「还有页面上的鲨鱼 icon、deepseek harness 水印、探索未至之境 预览版……我要做的是自己的品牌」；
  范围选择题拍板「页眉常量 + 内测声明 + 远程控制对话框」三处，时机拍板「现在就打（应用运行中）」
- 决策记录：[Note](../notes/implemented/surface/2026-09-21-upstream-brand-surface.md)
- 相关：ADR-0147（改名四步成套；其 D2 明确「基座平台名不替换」——本 ADR 把那条例外的**可见 UI 面**收窄到零）、
  ADR-0080（运行中替换 app bundle 红线）、ADR-0068（签名身份与 TCC）、ADR-0019（锚点不钉哈希）

## 背景

改名四步（ADR-0147）落地后，装机 app 仍有**可见位置**显示上游平台名 `DeepSeek Harness`：

- 页眉左侧/窗口标题：layout 的 `productTitle` 常量（`dsh-client-ui-layout/lib/client.js`），运行期覆写 SPA 的 `<title>`；
- 设置 → 模型页的「内测声明」段落（`dsh-client-ui-settings-models/lib/client.js`，含 4 处平台名）；
- 主进程「从其他设备使用这台电脑上的…」远程控制对话框（`lib/electron-runtime-*.js`）。

它们住在 app 包 `node_modules` 的上游包与主进程分块里，而扫描式品牌重放（`brand-replay-strings.py`）
的扫描面**排除 `node_modules`**，且 ADR-0147 D2 明确「基座平台名不替换——很多地方在正确地指代上游事实」。
两条都成立，于是这一小撮可见面既不在扫描射程内、也不该被全量替换波及——需要一个**逐处点名**的独立补丁。

## 决策

**D1 范围 = 三处可见 UI 面**：页眉常量 `productTitle`、模型页内测声明段、主进程远程控制对话框。
判定标准是「装机产物里逐字读到的用户可见文案」，不扩大到手写清单之外。

**D2 实现 = 独立补丁 `dsh-patches/upstream-brand-surface/`**：逐文件声明**期望命中数**
（layout ×1、settings-models ×4、electron-runtime ×4，且该分块必须恰一份），锚点不唯一即拒绝落笔；
写后断言残留为 0；替换名从名源 `dsh-patches/brand-payload-name.txt` 读，不另抄一份。
补丁守卫：`apply`/`--rollback` 要求应用**不在运行**，`--staged` 豁免（出货暂存树）。

**D3 注册三处**：`packaging/verify-patches-v2.sh` 新增 6 条判据（3 正 + 3 否——否证＝「上游名必须缺席」，
覆盖各自文件）；`packaging/assemble.sh` 以 `--staged` 对暂存 app 调用（缺脚本即硬失败）；
`patches-manifest-v3.md` 行 + `packaging/README.md` 锚点数（40 → 46）。

**D4 生效判据 = 重启后「服务端实际发出的字节」**：宿主对 app 内客户端 bundle 按**引导期快照**发送，
运行中改盘不重读。因此本补丁的验收不是「盘上文件改了」，而是重启后按 `window.__DSH_BOOT__`
的 `entries[].url` 取回的字节里上游名归零、`productTitle = "Sanbao"` 命中 1。

**D5 明确不碰的**：`@deepseek-ai/dsh/lib/bin.js` 的 CLI 描述、三方包 `package.json` 描述、
`dsh-client-connection` 的 fixture 数据等——那些位置在**正确指代上游事实**，属 ADR-0147 D2 的保留面。
身份/路径/签名（`appId`、`productName`、数据目录）不因本补丁变动。

## 备选方案

- **A 把这三处并入扫描式品牌重放**：否决——扫描面排除 `node_modules`；放宽扫描面会把「正确指代上游」
  的位置一并改写，属 ADR-0147 D2 明确排除的方向。
- **B 只改页眉（最小集）**：否决——用户逐处点名三处；漏掉内测声明与对话框会让「清干净」的声明与事实不符。
- **C 运行期 DOM 注入改写（不落盘）**：否决——页眉在 React 渲染内、对话框在主进程原生面，
  注入既晚（首屏闪烁）又脆（重渲染即丢），且与「不钉哈希」的锚点纪律冲突。
- **D 改 app.asar/主进程二进制之外的整体重打包**：否决——超出用户点名范围，且触碰签名与身份面（ADR-0068）。

## 后果

- 正面：三处可见面清零且**有否证判据**（上游名必须缺席），升级后锚点漂移由 `--check` 显式报出；
  「盘上改了」与「服务端发出什么」被拆成两个读数，避免把前者当后者（本仓库 P-15 类假绿的形态）。
- 负面/代价：新补丁需随上游版本重放（升级重打包锚点可能漂移）；`node_modules` 内其余三方包品牌串
  仍是已知边界（需 vendor 化，不在本 ADR 射程）。
- 落地读数（2026-09-21 02:20，整重启后）：服务端 layout `productTitle = "Sanbao"` ×1 / 上游名 ×0；
  settings-models 内测声明命中 ×1 / 上游名 ×0；页面 `document.title = "Sanbao"`、品牌座与 hero 均为自有品牌；
  `verify-patches-v2` 翻 `PATCHES v2 ALL VERIFIED`（46 锚点）；TCC 两项授权仍有效。

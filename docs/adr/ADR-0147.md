# ADR-0147 · Sanbao 改名落地四步成套（身份表 / 数据目录 / 显示名 / 重签）；品牌重放改扫描式 + 曾用名

- 状态：accepted（2026-09-20）
- 决策者：用户（lute）——「DSH Desktop 的字符串可以做全文去除吗？我想将新的 app 的名字取做 Sanbao」，并在选择器拍板「连数据目录一起换（要迁移）」与「现在就动装机 app」
- 相关：ADR-0136（品牌名源与派生物：改名 = 改一个源 + 重跑生成）、ADR-0063/ADR-0068（签名身份与 TCC 绑定/失效判据）、ADR-0080/ADR-0081（运行中替换 app bundle 白屏红线、图标资产尺寸与核对）、ADR-0008（vendor 只读）、ADR-0015（决策留痕双轨）

## 背景

产品名从 **LUTE Agentic System → Sanbao**（名源 `shared/client/sanbao-brand-source.ts` 在上一片已改，ADR-0136 D2）。本轮把改名**落到本机装机 app**：`/Applications/DSH Desktop.app` 的显示名、身份表、数据目录与签名。

落地面早有四支工具（身份补丁、迁移脚本、品牌重放、重签器），但真机落地实测暴露三类缺口，全部同源：**「覆盖面」从来没有被判据守过**。

1. **品牌重放的「9 文件清单」不完整**：真机 93 个文本文件里 21 个带品牌名，清单漏了 8 个（`notifications-*`、`tray-locale-*`、`src-*.js`、`native-ui/assets/*` 等分块）。清单式还有一个静态不可见的问题：`--check` 只看得见清单内的漂移，清单外漏成什么样它一无所知（P-02）。
2. **上一位品牌名（LUTE Agentic System）只报不改**：显示名块的 PREV 分支在 `--apply` 下也报 DRIFT 却不动手——永远修不好；`index.html` 的替换锚点写死上游名（`DeepSeek Harness`），PREV 态下 `replace` 不命中**却打印 `patched`**（假绿）。
3. **Helper 与 CFBundleName 的匹配从未被核对**：块 3b 的旧目录名写死首代名（`DSH Desktop Helper`），改名到 LUTE 后再接手时两个分支都不进、静默跳过。后果：外层 CFBundleName 已是 Sanbao 而 helper 还叫 `LUTE Agentic System Helper`，应用启动 **17ms 崩在 `FATAL: Unable to find helper app`**（Electron 按 `Frameworks/<CFBundleName> Helper.app` 查找）。

另有两处身份机制实测：`productName`（内嵌身份表，**两个家**：`lib/bin.js` + `lib/profile-manager-*.js`）决定 Electron userData 目录；真正的数据（profile/会话/设置）在 `~/.dsh`，与产品名无关。

## 决策

**D1 改名落地 = 四步成套，缺一不可**：① 身份表改 `productName`（`dsh-patches/app-identity-sanbao/apply-fixes.sh`，两个家各 1 行，锚点 count==1 才落笔）；② 数据目录迁移（`packaging/scripts/migrate-app-data-dir.sh --apply`，**只复制不删除**，旧目录保留为后路，rsync 排除 `Singleton*`/`DevToolsActivePort`）；③ 显示名/Helper/Info.plist 重放（`dsh-patches/brand-replay.sh --apply`）；④ 同身份重签（`packaging/scripts/refresh-app-brand.sh`）。四步之间 app 必须处于退出状态（各步自带的运行中守卫基于 `packaging/scripts/dsh-running.sh`，判不了即中止）。

**D2 品牌重放改「扫描 + 曾用名清单」，退役文件清单**：扫描面 = app 本体（`Resources/app` 下，排除 `node_modules` 与 `*.orig*` 备份）的文本文件（扩展名白名单），实现落 `dsh-patches/brand-replay-strings.py`；「曾用名」的唯一家 = `brand-replay.sh` 的 `PREV_NAMES`（新→旧，改名时追加）。豁免**按行**判定并显式报 `SKIP`：`productName:` 行归 app-identity 补丁、`app.setPath("userData", …)` 行是路径（路径 join 不可替换）。基座平台名 `DeepSeek Harness` 不替换——很多地方在**正确地指代上游事实**，只有窗口标题位是产品名（归 2b 块，替换器认任意 `<title>…</title>`）。

**D3 Helper 目录与 CFBundleName 同批换，曾用名要认**：`<曾用名> Helper*.app`（含 ` (GPU)`/` (Plugin)`/` (Renderer)` 后缀）→ `<新名> Helper*.app`；plist 的 `CFBundleName`/`CFBundleExecutable` 与 `Contents/MacOS/` 可执行文件名**四处一起换**。「都没找到」是静默跳过（文件不存在=无需处理），「找到了但只换一半」必须判红。

**D4 写路径默认带落笔后校验**：每个替换器写后重读验证——`index.html` 标题（grep 期望值）、helper 四处（CFBundleName 复核 + 可执行文件 `-x`）、扫描器逐文件写后残留检查（按非豁免行统计）。「没命中却报成功」与「PlistBuddy 静默失败」是本轮两次假绿的形态。

**D5 本轮不动 bundle 目录名与签名身份**：`/Applications/DSH Desktop.app` 目录名保留，`appId`（`ai.deepseek.dsh.desktop`）与签名身份（`LUTE Code Signing`）不动——TCC 授权按 `bundle id + 证书 leaf` 记账，同身份重签后授权延续（实测：辅助功能/屏幕录制仍为「身份型（绑证书）→ 本 app 满足」）。

# ADR-0284 · T05-mid step 6：矩阵制品发布与真实 compatibility 步装配（评估时点=最后可信观测）

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：继续主链接线）＋ agent（取证与实施；D4 为显式设计裁决，待用户复核）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-session-prompt-matrix-publication-and-compatibility.md)
- 相关：[ADR-0276](ADR-0276.md)（发布流程 D3：seal requirement + seal matrix）、[ADR-0282](ADR-0282.md)（requirement 半边）、[ADR-0196](ADR-0196.md)（D5：矩阵物理重发此前只登记未执行——本刀即该发布票首执行）、[ADR-0277](ADR-0277.md)（运行时观测线与稳定对）

## 背景

第 5 步（target）已在 ADR-0282 落地；第 6 步 compatibility 在 main 侧无任何装配，且侦察确认三大缺口：矩阵无发布件（`publications/` 只有 requirement snapshot）、resolve 输入所需的完整 `targetSemantic` 无落盘载体（候选线是唯一机械生产者）、`targetEvidence` 的多数字段（revisionDigest / actionIntentDigest / 三类 boundary / attemptId / targetProviderProvenance）无生产者。另有硬约束：kernel 要求 `evaluatedAt ∈ [inventory.observedAt, expiresAt)`（30 秒窗），而完整重观测在负载下 50–200 秒、不能放进请求路径——启动一次读的缓存 30 秒后即失鲜，若不裁决评估语义，第 6 步在生产将永远 unavailable。

## 决策

1. **D1 矩阵发布件**：`CompatibilityMatrixBundleV2` + `CompatibilityMatrixRevocationSourceV2`（空 entries）两件以内核封存落 `apps/sage-shell/publications/`（与 requirement 同树、同加载面）。规则 = owner 裁决的首发稳定对（`rule:sage-session-prompt-v1`，`3da420a7… × e1c7a8b4…`，equivalent）；矩阵窗口 `2026-10-11 → 2027-10-11`（与 requirement 有效窗对齐）；issuer `authority:sage-compatibility`；`providerProvenanceDigest` = 发布决策 + 稳定对的域分隔摘要（第一方 provenance，不宣称外部锚）。
2. **D2 semantic 重建**：`computeTargetSemanticFromRequirement(entry, descriptor)`（与候选线同家，发布/解析同源）；requirement 的 capabilities 非空时 fail closed（C2.2T 条目 5 面 vs semantic 7 面缺口，当前发布件为空集）。
3. **D3 targetEvidence 生产者**：全部字段 main 侧确定性推导——`revisionDigest` ← store 已校验链（D5）；`actionIntentDigest` ← `urn:sage:action-intent:v1:` 域分隔（operation+candidate+payload）；三类 boundary ← `…boundary.organization/account/resource:v1:` 域分隔（组织策略 digest / actorScopeRef / matter+revision）；`decisionDigest` ← identity decisionRef 的域分隔；`attemptId` = `attempt:sage.<requestId>`；`targetProviderProvenanceDigest` ← snapshotId+requirementDigest 域分隔；`issuedAt` = 实例时钟。**outcome 映射：`equivalent`→allowed（不透明 evaluationRef）；`requires-new-revision`→denied（发布规则本身拒绝该配对）；其余一律 unavailable**。
4. **D4 评估时点 = 证据自身的 `observedAt`（最后可信观测）**：重观测不能进请求路径；以证据的观测时刻求值使 kernel 窗口检查保持在证据自身的语义内。**代价（明示）**：墙钟新鲜度语义退化为「最后观测」——boot 后运行时漂移不再自动被时序窗口拦下；恢复机制 = Host 生命周期失效接线（ready 后 transition/fatal/exit/disconnect 立即作废缓存观测），登记为后续票（ADR-0168 语义）。本刀选择该时点是**显式设计裁决**，待用户复核；替代（请求内重观测 50–200s / 不可用-first 封死）不可用或不可交付。
5. **D5 revisionDigest 载体**：store 已校验链（event/head digest）经 `src/main/revision-digest-reader.ts` 暴露（`revisionDigest(matterId, revisionId) → sha256:<hex> | undefined`），单一事实源，不另造第二套摘要。
6. **D6 门禁**：route-authority 新兼容事实组（全输入门控装配、index 装载与观测/修订面、kernel 适配调用、评估时点常量、仅 requires-new-revision 可 denied、loader 经内核 parse 并组装 provider）+ 四条具名突变；note 句更新为「stopping at the absent registry / preflight / persistence steps」。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 每请求重新观测 | 否决：50–200s 全量重读（PMAP 全树+attestation）不能放请求路径。 |
| 缓存失鲜即 unavailable（封死） | 否决：第 6 步在生产永不通过，接线等于摆设。 |
| evaluatedAt = 墙钟 now + 放宽 kernel 窗口 | 否决：改 kernel 语义属另一刀；以 observedAt 求值不改契约。 |
| matrix bundle 只发 digest 对、targetSemantic 由运行时手工重建但不钉 pin | 否决：发布/解析必须逐字节一致——测试已钉重建 digest == 3da420a7…。 |
| boundary/attempt 摘要交外部 provider | 否决（本刀）：无消费者约束前，域分隔确定性推导 + ADR 记录即诚实形态；未来关联规范可收紧。 |

## 后果

- 会话族链真实推进到第 6 步之后，停在 registry/preflight/persistence absent；路由行为保持 unavailable-first（拒绝码不变）。
- 第 6 步在生效窗（2026-10-11 起）与 boot 观测一致时可达 equivalent：目标证据、运行时观测与矩阵配对三者逐字段绑定，任何漂移落为对应 kernel 命名码 → unavailable。
- 恢复墙钟新鲜度的 Host 生命周期失效接线成为已登记后续票；在此之前 compatibility 断言针对 boot 观测（D4 明示）。
- 未闭：Registry 首方 entry（路线已定，实现待批）、preflight/persist/dispatch、stage 进信封。

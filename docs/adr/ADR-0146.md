# ADR-0146 · 右栏宽度设置口：走官方 setRightbar 能力探测，区间镜像外壳，采纳只认拖拽

- 状态：accepted（2026-09-20）
- 决策者：用户（lute）+ 右栏重构线（`dsh-qoder-sidebar-local`）
- 决策记录：[Note](../notes/implemented/surface/2026-09-20-rightbar-width-setting.md)
- 修订：`docs/notes/implemented/surface/2026-09-20-qoder-sidebar-rebuilt.md` 里「`ILayout`
  没有宽度设置口」的断言**作废**——宽度写入口存在（`setRightbar`），只是被 TS `private`
  收在 `LayoutController.panels` 的类型面之外
- 相关：ADR-0143（右栏工作台面板）、ADR-0019（官方 UI 改写锚禁钉哈希）、ADR-0008（vendor
  只读参照）、ADR-0122（决策机器可读）、ADR-0125 D7/D8（**左栏**宽度契约，本轮不动）、
  总账 P-07（一条事实多个家）、P-52（mutation 收养链自激）、P-54（时间采样判据的间歇假红）

## 背景

Qoder 式右栏插件落地后，右栏宽度仍是外壳规矩：store 的 `rightbar` 内存态、首开取视口 45%、
重启即回默认。用户要求「做宽度设置口」。

此前一轮实机量到的硬事实把两条路判了死刑：

1. **覆写 grid 轨道**：frame 的 `grid-template-columns` 是外壳每次提交都重写的内联样式，
   插件侧贴 `!important`（含内联 `!important`）会在 250ms 内被改回原值；要赢只能起
   「每帧跟宿主抢同一属性」的观察器——P-07 / P-52 的形状，不做。
2. **纯压面板**：面板宽是 store 值的投影，只压面板得到「内容变窄、轨道不动」的死缝。

而外壳本来就有正当写入口：layout store 动作集里的 `setRightbar(px)`——拖把手走的就是它。
它没发布在 `ILayout` 上（被 `LayoutController` 收在 TS `private` 字段里），但运行时可见。

另一条实机撞出来的坑：宽度采纳（把外壳自己改的宽度记回偏好）如果挂在
MutationObserver 上**无条件**执行，我们自己 `writer.set()` 触发的外壳重渲染同样会触发
观察器，回调里读到的还是旧轨道——刚写进去的偏好被吃掉退回旧值（实测：播种 420 被
改回 320）。这是 P-52 mutation 收养链的自激回环在本包的复现。

## 决策

**D1 宽度落点 = 官方 `setRightbar`，能力探测式取用。** 探测不猜字段名：把
`ctx.get('layout')` 返回的服务对象自身与一层属性值都当候选，哪个对象上有可调用的
`setRightbar` 就用它（当前实现里是 `LayoutController.panels`），调用时重读该字段。
探不到 = 本包一个像素都不写、宽度交回官方默认，并把结论钉在
`<html data-lute-rightbar-writer="official|unreachable">` 上供实机验收点名——
「上游改形状、我们静默失效」必须被探针拦住而不是被日志吞掉。

**D2 区间镜像外壳 `columns.ts`，不是自创。** `RIGHTBAR_MIN=300` / `RIGHTBAR_MAX_RATIO=0.7` /
`RIGHTBAR_DEFAULT_RATIO=0.45` 镜像进本包纯契约层（`rightbar-width.ts`），唯一目的是让
设置页显示的值**等于外壳真会给的值**（否则「设置写 240、面板渲染 300」的界面说谎状态）。
镜像漂移的风险不由注释兜底，由实机探针两端对钉（请求 200 → 实测 300；请求 9999 →
实测 `min(floor(视口×0.7), 视口−左轨−400)`）。

**D3 偏好只有一个家，未设 = 不写。** `localStorage['dsh-qoder-sidebar:rightbar-width']`，
只接受十进制整数字面量（脏值判 null 回落默认，不猜意图）；跨重启的持久层在本包，
外壳内存态每次生效都让它自己写自己的 store。「未设偏好时一个像素都不写」——
外壳首开按视口 45% 自己算，抢先写一份等于把没人点过的设置变成事实所有者。
「跟随默认」= 清偏好 + 显式把外壳当前宽度送回官方默认值（外壳没有重置动作）。

**D4 拖拽采纳只认「抬手后的第一次提交」。** 观察器**不得**无条件采纳（背景里的自激回环）；
`onPointerUp` 不能直接读（把手在 pointerup 里才把最后一个 dx 提交，样式还要过一次 React
渲染，抬手瞬间读到的是拖拽中的旧值）。收口：pointerup 置「待认领」标记，观察器认领
抬手后的第一次样式变更；两帧 rAF 兜底（提交没动 style 时观察器不响）。拖拽要求窗口
可见，rAF 不会被挂死。

**D5 验收只认渲染进程读数。** `scripts/acceptance/right-sidebar-width-live.mjs`
（`pnpm run accept:right-sidebar-width`）：6 判据 = writer-reachable / width-applied /
floor-pinned / ceiling-pinned / settings-open / settings-row（设置行渲染且 ± 步进真实
落地、localStorage 同步）。前置缺失（端口 / 页面 / 展开控件 / 设置入口）exit 2 并打印
候选，判据不过 exit 1。播种走 localStorage + dispatch resize（落地点订阅 resize 重读
偏好）。页面轮询 evaluate 的 wrapper 超时 90s：窗口隐藏时页面计时器被节流，页内 8s
循环实际可跑 30s+（P-54 同款间歇假红）。

## 备选方案

- **覆写 grid 轨道 / 内联 `!important`**：被实测否决（见背景 1）；A′ 每帧抢属性的形状
  属 P-07 / P-52，不做。
- **自创区间（240–720）**：设置页会显示外壳永远不给的值（下限外壳 300 会把 240 钳成
  300），界面说谎；镜像 + 两端对钉才能把「我们和外壳一致」变成被检查的事实。
- **观察器无条件采纳拖拽结果**：实测吃掉自己的写（回环），见背景 2。
- **`ctx.effect` 里裸读 `ctx.layout`**：cordis 对未声明服务裸读会抛；改惰性 `ctx.get`
  探测（try/catch 包裹），取不到判 unreachable 而不是炸掉整个插件。

## 后果

**正面**：宽度设置口端到端成立——实机 6/6 判据过（含设置行 ± 步进、镜像两端对钉）；
重启前 localStorage 320 → 重启后轨道 320（boot 时经官方写入口落地，跨重启持久实测）；
宽度真源始终只有一个（外壳 store），本包只持有偏好与决定。

**负面与已知边界**：

- 镜像常量是外壳 `columns.ts` 的第二个家；外壳改数字时这里不会自己知道，只能靠
  `accept:right-sidebar-width` 的两端对钉判红（floor/ceiling 两判据）。
- 拖拽采纳的实机验证缺位：合成 pointer 事件带 pointer capture 不可靠，探针没验
  抬手采纳路径（只验了设置行与播种路径）；该路径的失效形态是「拖完宽度没进偏好」，
  不会破坏布局。
- 探针要求应用带 `--remote-debugging-port` 启动且窗口可见性不定（隐藏窗口下轮询
  慢但能过）；探针结束把 localStorage 还原为进场值、面板停在展开态、设置模态点掉一次。
- 未设偏好时本包不写宽度：首开仍是外壳 45% 口径——这是「不抢所有权」的代价，
  想要 Qoder 常态宽度的用户需要在设置口点一次（−40 步进从当前宽度起步）。

**后续动作**：外壳版本跟进时（ADR-0006 观察窗）顺带重跑 `accept:right-sidebar-width`
的 floor/ceiling 两判据；拖拽采纳路径若实机发现失效，优先怀疑 D4 的「第一次提交」
认领窗口。

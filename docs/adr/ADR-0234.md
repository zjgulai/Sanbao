# ADR-0234 · 澄清问答闭环：宿主中继、单发回答与待继续中止

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-035、US-177~182 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-clarification-loop.md)
- 相关：[ADR-0212](ADR-0212.md)（005 会话通道）、[ADR-0231](ADR-0231.md)（007 暂停期登记）、[ADR-0233](ADR-0233.md)（009 纯历史接点）、[ADR-0198](ADR-0198.md)（host 消费登记）

## 背景

工单 034（FW-035，US-177~182）：运行中的澄清问题成卡（问题、候选项、所属运行）；
回答经一条具名写提交所属会话，回执区分**已接收/已生效/结果未知**（未确认前不显示"已回答"）；
候选与自定义同权，答案**不自动写成事项事实或交付字段**；答案进入历史后只读、重开沿历史回看
不重复提交；模式切换触发的确认按当前有效模式生效、过期确认需重新确认；**等待中停止→卡片
转入待继续，不自动继续**。基座事实：提问 = `ask_user_question` 工具调用 `ctx.userQuestions.ask()`
（`user-questions/request` waterfall，`dsh-tool-ask-user`）；官方桌面以 `ctx.remote.$on`
把 waterfall 转发给 webview 客户端；**Agent id 即 session id**（`dsh-agent` 断言
`id === agent.session.id`）；会话日志以 `tool/call`（`{turn,step,callId,name,arguments}`）＋
`tool/result`（`message.callId`）记录问答；`session/cancel` 会中止工具执行信号。

## 决策

1. **D1 宿主中继（claim 或委托）**：`src/host/user-questions-relay.ts` 纯内核
   （claim/list/answer/abort/dispose）＋Cordis 胶水（`installUserQuestionsRelay`）。监听以
   **`prepend: true`** 注册（官方 remotes 可能先注册，靠前监听会把提问吞进无人消费的队列），
   经 `ctx.provide('sageUserQuestionRelay')` 供桥读取；**只认领带 agent 的请求**
   （`agent.id` 即 sessionId），其余一律 `next()` 委托。回答在**resolve 之前**按 asker
   声明的候选项校验（未知 label/覆盖不全/空信号拒绝 `question-answers-invalid`），
   abort 与 teardown 一律 reject（`ASK_ABORTED`），绝不留下卡死的工具。
2. **D2 桥面两枚＋allowlist 治理**：`session/questions`（read，按 sessionId 列活提问）与
   `session/answer`（write，resolve waterfall）进 `BRIDGE_ENDPOINTS`；relay 缺席 =
   `question-relay-unavailable`。**顺带修复 008 的桥面遗漏**：`session/queue-edit` 有处理器
   但从未进 allowlist（真实运行恒 `bridge-endpoint-unsupported`，因函数级测试全用假桥而
   全绿）；补登记并**新增源头守护**——host-readonly-bridge.spec 直接扫描
   `bridge-endpoints.ts` 的 `endpoint === '…'` 字面量，逐个断言在 allowlist 中（知道⇒拦住）。
3. **D3 main 澄清 store＝中继注册表的投影**：`src/main/clarifications.ts`。pending 直接来自
   `session/questions`（"存在即 waterfall 挂起"，不本地推导）；**所属运行**由一次有界
   `session/page`（仅当有待答或待证回执时）取**未闭合运行**（turn/start 无 turn/end）绑定；
   **回执结算**：accepted 仅在 `tool/result`（按 question id 关联 callId）入日志后翻
   `effective`；停止中消失翻 `aborted`；无 ack 即 `unknown`；`verifyOnly` **由活状态派生**
   （aborted/unknown），不冻结于提交时刻。
4. **D4 一题一提交（US-178）**：按 `sessionId:requestId` 冻结提交结局；重复点击/刷新返回同一
   回执，**永不再发**；未过桥的拒绝（无会话/暂停/不在等待/形状非法）不落记录，用户修正或
   继续会话后可再提交。四态文案：已接收（等待生效确认）/已生效/未生效（提问已中止或不在等待
   中；仅可核对）/结果未知（请核对同一操作）——**只给核对入口，不给重试**。
5. **D5 停止→待继续（US-182）**：停止中止 waterfall 后，消失且无回答的卡片以
   `deferred(stopped)` 保留（"停止已中止该提问（未回答）；继续会话后可按需重新发起。"），
   非暂停消失记 `deferred(gone)`；**不自动继续**（零额外桥调用）；暂停态提交回答被拒
   `clarification-paused`（零桥调用）。
6. **D6 渲染面（S8）**：D3 卡内新增澄清区——活卡（问题/header/意图徽章/候选项 radio|checkbox/
   自定义输入**同权**/「提交回答」）、待继续区、回执行（含 [核对]＝只重读一次）；一次点击恰
   一条具名写；US-179：回答路径不触任何 matter/draft 端点，自定义随 `custom` 原样过桥。
7. **D7 历史回看（US-180）**：`session/detail` 增 `clarifications`（`tool/call`＋`tool/result`
   解析：问题+所选+自定义，未闭合 `answered:false`），渲染为只读块、无任何提交控件；
   重开沿纯历史接点（009 判据不破）。
8. **D8 首版不做**：澄清多轮审批化、跨事项澄清模板、plan-review 专用版式（`intent` 仅随卡
   展示与透传）、已提交答案的改写撤回。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 宿主→main 推送式提问通道（新 IPC 方向） | 否决：全仓是 main→host 请求/响应；轮询读（每刷新一次 `session/questions`，仅按需补一页历史）与既有 read 投影同构，无新协议面。 |
| 由会话日志推导 pending（tool/call 无 result） | 否决：日志不含"是否仍挂起"的权威事实；waterfall 注册表才是 live 真相，日志用于**生效证据**而非在场证明。 |
| 回答直连 `ctx.userQuestions`（经新 host 端点） | 否决：Sage 桥是 main→host 具名端点；relay 在 host 内注册才吃得到 scoped waterfall（且需 prepend 防被官方 remotes 截吞）。 |
| 停止后把回答排队到"继续"再派发 | 否决：cancel 已中止 waterfall，继续派发必然 `question-not-found`；如实转待继续、重新发起更诚实。 |
| 旧确认跨模式沿用 | 否决：US-181——提问消失即转待继续/未生效，重新确认才生效（intent 随卡透传）。 |

## 后果

- 验收四条机器断言：① 停止→卡片待继续且零自动继续（调用表断言）；② 回执四态可区分且未知
  只给核对（无重试）；③ 重复点击/刷新不重复派发（恰一条 `session/answer`）；④ 重开沿历史
  只读回看（detail 只调 `session/page`，无任何提交）。
- 桥面 +2 端点（session/questions、session/answer）＋ 1 条 allowlist 修复；消费登记扩
  `sageUserQuestionRelay`；host 库登记 `user-questions-relay.js`；端口名册 +1
  （sessionClarificationAnswer）。
- §1.6：真产物两页——澄清卡（两问：radio 单题 + checkbox 多选 + 自定义 + [提交回答]）、
  待继续行、四种回执行（[核对]）；历史详情只读回看块；交互读数证明一次提交恰一条请求、
  核对零写调用、radio+checkbox+自定义同权合批。
- 已知未闭：plan-review 专用版式、答案改写撤回、多轮澄清审批化后置；真实 Host 未跑
  （relay 的 Cordis 胶水与 prepend 顺序仅类型与单元覆盖）。

# ADR-0159 · Sage 自有桌面端：产品壳、能力适配、独立身份与受控迁移

- 状态：accepted（2026-09-24）
- 日期：2026-09-24
- 决策者：用户（lute；grill-with-docs 设计树决策）
- 决策记录：[Note](../notes/proposed/architecture/2026-09-24-sage-self-owned-desktop-design-tree.md)
- 相关：ADR-0008（基座只 pin 不改）、ADR-0015（ADR / Note 双向留痕）、ADR-0139（既有薄壳骨架）、ADR-0147（旧品牌迁移历史）、ADR-0150（上游可见品牌清理）、ADR-0157（深度开发前置边界）

## 背景

现有 `apps/sage-shell/` 已拥有安全 Electron 窗口、私有协议和独立 Harness host 子进程；它由 `apps/lute-shell/` 受控原子迁移而来，当前仍直接服务上游 `dsh-web-frontend`，依赖上游 Conversation slot 和默认 bundle。它是可复用的运行时基线，不是 Sage 产品壳；当前 DSH Desktop 打包线也不消费它。

Sanbao 原型是静态 React 交互与状态合同，不能作为仓库外 `file:` 依赖、iframe 或第二套导航挂入产品。用户确认 Sage / 三宝为唯一对外品牌，并要求彻底移除原始桌面 chrome，同时保留 Harness 的能力而不篡改第三方事实、许可证或 pin。

## 决策

1. **Sage Shell 拥有产品。** 已受控迁移 `apps/lute-shell/` 至 `apps/sage-shell/`；Sage 拥有 Electron 窗口、路由、导航、交互、产品状态、资产和发布身份。Harness 只通过唯一 Capability Adapter 提供 agent、插件、Cordis、流式输出、工具和产物能力；产品页面不得直接加载上游网页、消费上游 UI slot 或依赖 Cordis 私有 DOM。
2. **首个价值流是经营事项闭环。** 范围固定为事项创建、证据输入、运行活动、澄清 / 人工审批、产物回执和失败重试。Sanbao 原型的 206 条状态进入迁移台账与回归输入，不被误报为已实现功能。
3. **独立身份与可回滚迁移。** Sage 使用新的受控 Bundle ID、隔离数据根、profile 和 host 目录；首次迁移只复制、校验、可回滚导入旧 DSH 数据。旧 DSH Desktop、`~/.dsh/profiles/desktop`、旧数据和发布物保留到 Sage 验收完成，绝不被原地改写或删除。
4. **使用同源但经清洗的主图形。** Sage 的主图形源于 `/Users/lute/project/Sanbao/SanBao_Logo_Kit/svg/A_StarSail_Product_symbol.svg` 的几何。Sage 只出货派生后的 `sage-symbol`、深浅色版、AppIconset / `Sage.icns` 和新的 Sage lockup；不复制含 `SanBao` 路径字标的锁定图、概念图、manifest 或生成记录。派生 SVG 的 `title`、`aria-label` 和文件名全部改为 Sage。
5. **可见面清零，事实面保留。** Sage 的窗口、Dock / Finder、启动、空态、侧栏、设置、错误框、安装器和产品页面不得展示 DeepSeek、Harness、鲨鱼、Preview、Sanbao 或 Lute。Harness / DeepSeek 名称可保留在第三方声明、许可证、依赖、vendor pin 与历史证据中，不能通过删除法律或技术事实达成“清零”。
6. **阶段化发布与清理。** P0 仅产出内部工程验收版，不发 DMG；DMG、签名、公证、更新器、正式 Bundle ID 与公开资产释放进入 P1。清理遵循只读盘点 → 保留 / 归档 / 删除名单 → 明确授权 → 可恢复执行，未知项和历史发布物默认保留。

## 备选方案

| 方案 | 为什么未采用 |
| --- | --- |
| 继续在 DSH Desktop slot 上换皮 | 上游窗口、导航、首启和默认 UI 仍控制产品体验，不能实现自有桌面端。 |
| 把 Sanbao 原型作为外部运行时包、iframe 或 WebView | 会造成两套导航与状态，且外部脏工作区成为出货依赖。 |
| Sage 沿用 `ai.deepseek.dsh.desktop` 和 `~/.dsh` | Sage 与 DSH 不能安全并存，并会继承旧安装、更新和数据身份。 |
| 复制或改写 SanBao lockup | 字标是路径化几何，不能安全文本替换；会把已退役品牌直接带入 Sage。 |
| 立即删除旧 App、数据或历史发布物 | 尚无迁移和回滚证据，删除会破坏可恢复性。 |

## 后果

- 现有薄壳的 Host 子进程、FD3 / FD4 协议、凭证清洗、物化和拆机阶梯是可保留的底座；其上游 asset server、Composer 改写、上游默认 bundle 和 onboarding carousel 不是 Sage 产品面，必须在 Sage 自有 renderer 与 Adapter 出现后退出。
- 源码目录迁移是广泛机械变更，涉及 `.gitignore`、根门禁、`sage-shell-pin`、fixture、架构图、文档和 ADR 账本；它必须是一个显示在 Birdview 中、可验证的原子批，不能靠复制两套壳过渡。
- P0-1 仅迁移源码目录、package / 可见诊断命名和其守卫；`PROFILE_LABEL`、`lute-host`、`LUTE_SHELL_*`、`DSH_HOME` 与资料根仍是 P0-3 的复制、校验、回滚迁移对象。它们作为显式兼容接口保留，不得被误写成 Sage 数据隔离已完成。
- P0 不改 `vendor/**`、pin、当前 `/Applications/DSH Desktop.app`、`~/.dsh/profiles/desktop`、历史发布物或外部 Sanbao 源仓；受控浏览器等既有上游补丁不自动视为 Sage 能力，需要由 Sage 主进程单独移植和验收。
- 公开分发前仍需指定精确反向域名、Apple Team / Developer ID、签名与公证、数据迁移演练和资产权属 / 商标批准。这些是发布门，不是可由代码推断的默认值。

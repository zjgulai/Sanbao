# ADR-0324 · CTX-01C 设备聚合读：冷启动 bootstrap + 失败信封直传真实 stage

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（2026-10-12 v5 走查受阻，确认 F 批修复并重建 v6）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-device-aggregate-read-bootstrap.md)
- 相关：[ADR-0268](ADR-0268.md)（T03/A state 放行）、[ADR-0184](ADR-0184.md)（fixture 开关与 production 恒 null）、CTX-01B（context/select 唯一激活入口）

## 背景

v5 打包版生产冷启动死锁（走查实测）：`/.sage/state` 的 projection-read admission 要求「事项已激活」（`activeMatterContext.snapshot()` 非空）；唯一的激活入口是 `/.sage/context/select`，而它只由 renderer 的「选择事项」按钮触发；按钮只渲染于「事项列表 read」的 state 载荷——载荷被同一道门拦住。链路闭环，冷启动永远停在「工作区待接入」。fixture 旁路（`SAGE_FIXTURE_PROJECTION=1`）跳过 admission，遮掩了缺陷；DMG-06 验收只核对启动日志行。

第二缺陷：路由兜底信封把所有失败 stage 改写成 `'read-policy'`（renderer 谓词还钉死该值）。装版探针实测真实 stage 为 `initial-context`，排障长期被指向错误一环。

## 决策

1. **D1 第四读面=设备聚合读**：新增 `admitDeviceAggregateRead` kernel（投影读 admission 同模块）。仅在「context inactive（`snapshot() === null`）」且 `intent.operation === 'state.read'` 时，runner 走该 kernel；caller 缺席、未登录（`identitySession() === null`）、frame 未 ready/受污染一律 fail closed。stage 用既有词表：caller / initial-context（会话）/ fresh-scope（frame）/ read。
2. **D2 不携 matter 事实**：该读无 policy、无 scope 步，matter 槽保持 production-null（ADR-0184）；读回调收 `null` scope（`ProjectionReadRouteRunner` 读参放宽为 `ProjectionReadScope | null`）。其余 15 个 op 与 active-context 读走原链不动。
3. **D3 读后回响**：读后重读 identity session 与 frame generation，任一移动或不可读 → `unavailable, stage:'read'`（撕读丢弃，不留「最新」）。
4. **D4 失败信封直传**：route-skeleton `runProjectionRead` 对 admission 的类型化失败（state+code+stage+retryable+correlation 齐备且 code 与 state 一致）直传 wire；路由兜底只留给 runner 缺席、畸形结果与抛错。renderer 谓词去掉 `stage === 'read-policy'` 钉（负向 pin 保留）；desktop client 谓词本就接受任意 stage。
5. **D5 门禁与实测**：route-authority 新增 pin（分支 guard 原样、单 call site、kernel 会话/frame 步与回响）+ selftest 突变（放宽 guard / 复制 call site / 去会话步 / 去回响各判红）；新 spec `projection-read-device-aggregate.spec.ts` + production spec 正/负例（未登录必须拒绝）。不新增路由、不改矩阵分母（19/16/10 不变）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 放宽 initial-context 允许无 matter（改 admission 链） | 否决：matter 链语义保持单一；设备读独立成面，pins 可钉死排他性。 |
| bootstrap 路由携带名册 | 否决：同一事实两个家（州载荷已是名册的家）；CAS 代际无处安放。 |
| 继续 fixture 模式走查 | 否决：走查对象必须是生产形态；fixture 旁路正是缺陷被遮掩的原因。 |
| 保留 stage 折叠 | 否决：仪器诚实性——stage 是准入的公开诊断事实，折叠使其失真（P-70 家族）。 |

## 后果

- 生产冷启动可收敛：登录后 state 载荷可读（activeContext inactive + 代际），名册按钮可点，选择流 ensure 进入工作修订。
- 走查步骤 5 的前置缺口（接入工作区 + 关联卡设默认）在手册中补登（本次同提交）。
- 失败诊断面：`/.sage/state` 等读路由的 wire stage 恢复真实值；既存测试断言随之升级（fixture spec、read-policy-allowed-path、探针脚本、route-skeleton）。
- 未登录（signed-out）的 state 仍 fail closed（`initial-context`），名册不暴露。

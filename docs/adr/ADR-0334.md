# ADR-0334 · 实例凭据写入路径：`/.sage/credentials` 三段语法，值写穿不回显

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（2026-10-12「推送，然后执行下一批推荐」授权执行；ADR-0333 D4 具名的票级后续）＋ agent（装配设计）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-instance-credential-write-path.md)
- 相关：[ADR-0333](ADR-0333.md)（D4：凭证写入路径独立成批）、[ADR-0174](ADR-0174.md)（Application Service 唯一编排入口）、[ADR-0325](ADR-0325.md)（bridge-result 应答形状）

## 背景

v9 走查实证：真实模型回合需要 `DEEPSEEK_API_KEY`，缺失得到 `MISSING_CREDENTIAL` 错误回合；宿主凭据服务没有 Sage 面写入路径，测试者只能从启动环境导出。这是内测走查的最后一处环境依赖（walkthrough 前置第 6 条）。ADR-0333 D4 将该写入路径登记为票级后续批。

事实边界（读 dsh 源码 `credentials-local`）：

- `describe(ref)` 返回 `{configured, source?, writable}`，无值槽位；unconfigured `{configured:false, writable:true}`；env 来源 `writable:false`（进程环境只读）；file 来源 `writable:true`。
- `set(ref, value)` 写 provider-managed 文件层并热应用，空值抛错。
- 名称空间是 POSIX 风格 env 变量名；本产品只面对 `DEEPSEEK_API_KEY`。

## 决策

1. **D1 唯一面**：新增 `/.sage/credentials`（POST，JSON），`{action:'describe'|'set', name, value?}` 三段语法——键集精确（describe 恰 [action,name]；set 恰 [action,name,value]）、name `^[A-Z][A-Z0-9_]*$` ≤128、value trim 后 8–512 且无控制字符。越界一律 400 `invalid-credential-request`，不走服务层。
2. **D2 值写穿不回显**：`describe` 应答只有 `{configured, source, writable}`；`set` 应答只有 `{state:'saved', name}`。值在 renderer→route→main port→bridge→host seam→凭据 store 的单程内传递，任何拒绝、日志、错误信封都不含值（含名称具名的拒绝码）。
3. **D3 身份门在 main**：main-owned 端口 `createCredentials`（`src/main/instance-credential.ts`）先查 identity session——未登录一律 `credential-identity-unavailable`（retryable）且零 bridge 调用；名称 allowlist 镜像 host 侧，越界零 bridge 调用。走查实态：Logto 登录后设置，与 session.send 的身份门同向。
4. **D4 host seam 只认应用自有名**：`APP_CREDENTIAL_NAMES=['DEEPSEEK_API_KEY']` 白名单；值语法在 host 再检一遍；**env 来源（`writable:false`）的 set 具名拒绝** `bridge-credential-readonly-source`——启动环境会遮盖文件层，写一个永不生效的值等于假保存（P-56）。file 来源写入后热应用。
5. **D5 renderer 面**：模型设置页新增「实例 API Key」卡（describe 状态行 + 密码输入 + 保存 + 结果通知）。保存成功清空输入并重读；拒绝保留输入并具名原因；值永不回显。卡只在控制器注入时存在（与 preferences controller 同一窄缝规则）。
6. **D6 权威登记从实**：route 矩阵按 protected-effect 登记，`runCommand.actual=false`，`currentAuthority` = `violation / direct-provider-bypass`——该写入有 bespoke main-owned admission（caller 绑定＋身份会话＋名/值语法），但不是任何已登记 admission family 的成员，作为 bypass 显式记账，不混入 local-preference 低估其性质。门禁新增 pin 块钉住语法、身份门、单一调用点与 unavailable-first 默认。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 归入 local-preference（与展示偏好同族） | 否决：密写与 UI 展示偏好不同性质；该族语义会让审计低估爆炸半径（真实计费调用）。 |
| 新建 protected-effect admission family | 否决：实例级凭据无 matter 作用域，套 family 形状＝为登记而造抽象；bespoke 门显式登记 bypass 更诚实。 |
| env 来源允许覆盖写（只写文件层） | 否决：env 遮盖使保存重启后无效——无声失败，违反 P-56。 |
| renderer 直连 dsh 凭据服务 | 否决：renderer 不得成为平行 owner（ADR-0174）；且凭证值不得进入 Host 之外的旁路。 |
| set 后回读 describe 富状态 | 采纳为 UI 侧行为（保存后重读）；不新增回读 route。 |

## 后果

- route 分母 62→63；protected-effect 39、bypass 17（direct 11）；route-authority 门禁基线同步更新并新增凭据 pin。
- bridge 端点表 39→41（credentials/describe read、credentials/set write），既有逐行守卫自动覆盖。
- 走查第 6 条前置可删除：无 env 启动 → 登录 → 界面保存 key → 真实模型回合。
- 后续批：模型编辑器「校验并添加模型」真校验/保存（ADR-0333 剩余）；`unset` 面未开（YAGNI，未请求）。
- retention/legal hold 未确认不影响本批：存储落点是 harness 自己的凭据文件层，值不进仓库、不进 Sage 数据根自管区。

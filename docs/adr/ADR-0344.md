# ADR-0344 · 018 收口 A3：观测 DeepSeek 供应商卡写入面——models 覆盖与 API Key 接线

- 状态：accepted（2026-10-13）
- 日期：2026-10-13
- 决策者：用户（2026-10-13「同意」A3 并行方案）＋ agent（装配设计）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-13-deepseek-provider-card-wiring.md)
- 相关：设计票 [018](../design-loop/tickets/018-显式测试连接与结果绑定配置版本.md)（未闭项「DeepSeek 默认供应商表单写入面」）、[ADR-0339](ADR-0339.md)、[ADR-0342](ADR-0342.md)、[ADR-0343](ADR-0343.md)、tracked 矩阵三行（`QDR.P06.settings.models.{add.deepseek,deepseek.models.open,deepseek.type.open}`）

## 背景

基线事实（按 vendor 源码逐条核验，2026-10-13）：

1. 默认 provider 路由 = `deepseek-official`（`llm-deepseek-api-key/src/index.ts:15`，displayName「DeepSeek」）；目录条目携带 `settingsNs`（Sage 挂载行 `llm-deepseek`）与 `settingsPath`（`[]`）——写面定位可全程取自目录，不钉常量。
2. 插件 Config 有可写 `models` 数组（advisory 目录；默认 `deepseek-flash`/「DeepSeek-V41-Flash」与 `deepseek-v4-pro`/「DeepSeek-V4-Pro」）；该 ns 经 settings 栈路径寻址写（批次 D 已实证）。
3. `llm.resolveModelInfo(provider, model)` 为公开本地读（`llm/src/index.ts:740`），含 `context.contextWindow`——`catalogModel` 必填字段可无损重建。
4. **探测缝已退役**：`llm/test-connection` 不在协议表；`discoverModels` 对该路由离线回答（`config.models` 映射）——任何「测试通过」都会是假绿。
5. 类型「按量付费」为单选项，无可写配置字段。观测初态 0 勾选属新装草稿；Sage 该 provider 恒存在默认。提交后列表行未观测（QB20-07 放弃回空列表）。

## 决策

1. **D1 桥写 `modelConfig/provider-models`**（协议表 +1 write）：provider 必须是**目录成员**（宿主裁定；未知名 `bridge-model-provider-unknown`）；`modelIds` 1..64、去重、每 id 必须 ∈ 该 provider 的活目录（`listModels`）否则 `bridge-model-entry-unresolved`；条目由 `resolveModelInfo` 重建（`name`+`contextWindow` 必达，缺则拒）；`ns`/`path` 全来自目录条目；经 `settingsController.mutate` 写 `set path [..settingsPath,'models']`。
2. **D2 API Key**：`DEEPSEEK_API_KEY` 走既有 credentials 缝（值单向、不回显）；已配置时**留空保留**（A1 语义）。
3. **D3 UI**：DeepSeek 分支接活清单（全选 + 逐项 menuitemcheckbox；目录懒读——菜单打开才读；预填=当前生效模型）；提交=模型先、凭据后，部分失败具名留窗；成功关窗 + 诚实 notice。
4. **D4 诚实边界**：按钮标签保留观测文字「校验并添加模型」，note 明示**保存不触发供应商请求**（ADR-0339 D5 先例）；无网络探测（无探测缝且不应假绿）。类型菜单保持显示；不新增默认 provider 列表行（未观测，不发明）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 「校验」走 `discoverModels` | 否决：该路由离线回答（config.models 映射），标通过即假绿。 |
| 重建旧最小探测（messages ping） | 缓：旧 seam 已退役；重建=一条新的模型调用安全面，须另票（本批不做）。 |
| 硬编码 ns `llm-deepseek` | 否决：目录条目携带 settingsNs；常量会随挂载行漂移。 |
| 校验通过才允许保存 | 否决：无诚实探测缝；与全窗「保存不探测」语义冲突。 |
| 提交后列表加默认 provider 行 | 否决：提交后形态未观测（QB20-07 放弃回空列表），不发明。 |
| 清单预填留空（照观测 0 勾选） | 否决：Sage 该 provider 已存在默认模型，0 勾选会误导为「无模型」。 |

## 后果

- 矩阵三行 DeepSeek（`add.deepseek` / `deepseek.models.open` / `deepseek.type.open`）：ui 与 applicationService → verified（证据：r17b + model-routes 两 spec、路由矩阵、availability note）；electronAcceptance/hostIntegration/visualAcceptance 保持 pending（打包机实测随 sage-16 窗口后补录）。
- 018 未闭项剩 D7（inventory overlayPolicyDigest）。
- 诚实登记：类型菜单仍为显示项；「购买 Token Plan / 获取 API Key」外链未接线。

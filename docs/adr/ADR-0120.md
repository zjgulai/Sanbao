# ADR-0120 · 安全运行时契约主门禁与自动化端到端验收闭环（SEC-RT-010）

- 状态：accepted（2026-09-18）
- 决策者：用户（lute）
- 决策记录：[Note](../notes/implemented/security/2026-09-18-sec-rt-010-security-contract-master-gate.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（豁免只减不增）、ADR-0094（门禁统一结果规范）、ADR-0102（门禁的分母由对象完整集合推出）、ADR-0103（无副作用与自验见证）、ADR-0113（SEC-RT-002 不可变供应链）

## 背景

安全运行时改造（SEC-RT 系列）覆盖了从 SEC-RT-001 到 SEC-RT-009 的多项安全与加固工作：
- SEC-RT-001: 凭据脱敏与秘密擦除
- SEC-RT-002: 不可变供应链与锁定哈希
- SEC-RT-003: 符号链接越权防御与文件白名单
- SEC-RT-003A: 关键路径竞争防御与并发安全
- SEC-RT-004: 回环代理与网络通信隔离
- SEC-RT-005: 敏感数据落盘与原子持久化
- SEC-RT-006: 日志与错误信息脱敏防护
- SEC-RT-007: 危险操作与越权执行阻断
- SEC-RT-008: 会话迁移与 Token 格式兼容防御
- SEC-RT-009: 失败回滚与环境变量隔离保全

在 SEC-RT-010 之前，各子项的安全判据散落在各包的测试套件与局部脚本中。如果缺乏全局汇总门禁，容易导致：
1. **假绿/漏判风险**：某个安全测试文件被遗漏、重命名或跳过，上层门禁由于「未发现所以通过」（ADR-0102 所防范的空射程陷阱）而误判为安全通过。
2. **缺乏不可变的发布阻断器（Release Blocker）**：安全契约若未被主门禁显式列为 release blocker，可能在出货流水线中被当作可选或非致命项忽略。
3. **缺乏端到端一键闭环检验脚本**：无法单命令对所有安全契约的定义完整性、目标文件真实存在性、测试套件真实可执行性及故障注入点进行全量审计。

## 决策

1. **确立单一事实源安全契约登记簿（Security Contract Registry）**：
   在 `scripts/gates/security-contract-registry.mjs` 中定义 `SECURITY_CONTRACT_REGISTRY`，严格包含 10 项安全契约（`SEC-RT-001`、`SEC-RT-002`、`SEC-RT-003`、`SEC-RT-003A`、`SEC-RT-004`、`SEC-RT-005`、`SEC-RT-006`、`SEC-RT-007`、`SEC-RT-008`、`SEC-RT-009`）。每项契约必须声明：
   - `id`: 契约唯一编号
   - `name`: 契约可读名称
   - `owner`: 负责人
   - `targetFiles`: 受保护的目标源文件清单（必须在仓库中真实存在）
   - `testFiles`: 验证测试文件清单（必须在仓库中真实存在）
   - `faultPoints`: 故障注入/攻击场景清单（不得为空）
   - `runTier`: 运行分级（如 quick / full）
   - `releaseBlocker`: 必须恒为 `true`

2. **主门禁静态与存在性硬阻断（Master Gate Audit）**：
   在 `scripts/gates/security-contract-master.mjs` 中实现 `auditSecurityContractMasterGate`。该检查器以确定性的 `requiredIds`（10 项）作为基准分母，任何一项缺失、属性不合规、targetFiles 或 testFiles 路径不存在、未声明故障注入点或未将 releaseBlocker 设为 true，均直接阻断并报违规。

3. **反向突变自测（Selftest with Reverse Mutations）**：
   在 `scripts/gates/security-contract-master.test.mjs` 中建立反向突变测试（缺少必需契约、targetFile 不存在、testFile 不存在、缺少故障注入点、试图将 releaseBlocker 设为 false 等），确保主门禁具有不可穿透的拒绝能力。

4. **端到端自动化验收脚本（E2E Acceptance Runner）**：
   在 `scripts/acceptance/security-runtime-acceptance.mjs` 中构建端到端验收运行器。先运行契约静态审计，若通过则提取所有注册的测试套件，使用由 `nodeCommand()` 派生的受管 Node 解释器真实执行每个测试文件，汇总 23 个套件与 36 个故障注入点的审计结果，并支持 `--json` 输出。

5. **接入全局门禁管道（Gate Integration）**：
   在 `scripts/gate.mjs` 中注册 `security-contract-master` 与 `security-contract-master-selftest`，作为常规 quick 与 full 模式下的必经检查项，守住不可破的安全底线。

## 后果与验证

- **后果**：
  - 所有 10 项 SEC-RT 安全契约被固化为一等公民的发布阻断项，任何后续改动若误删测试、误移目标文件或削弱契约约束，门禁将硬失败。
  - 维护者必须通过更新契约清单来保持安全面的一致性。
- **验证**：
  - `node scripts/acceptance/security-runtime-acceptance.mjs`: 10/10 契约全部通过，36 个故障点全部受审，23 个测试套件运行且 0 失败。
  - `node --test scripts/gates/security-contract-master.test.mjs`: 6/6 反向突变用例全部通过。
  - `node scripts/gate.mjs --mode quick`: `security-contract-master` 与 `security-contract-master-selftest` 均显示 `ok [expected=10, checked=10, failed=0]`。

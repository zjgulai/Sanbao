# ADR-0135 · 换皮的门禁改造与执行契约：单一品牌源 + 不可消除字面量纳入校验 + 六个垂直切片

- 状态：accepted（2026-09-19）
- 决策者：用户（lute）+ WorldPilot 全维度换皮轮
- 射程表：[`.scratch/sanbao-reskin/surface-map.md`](../../.scratch/sanbao-reskin/surface-map.md)
- 执行计划：[`.scratch/sanbao-reskin/plan.md`](../../.scratch/sanbao-reskin/plan.md)
- 相关：ADR-0009、ADR-0014（只减不增的豁免）、ADR-0019、ADR-0056/0057/0058（发布 SOP）、ADR-0131～0134；总账 P-02（仪器假绿）、P-07（一条事实多个家）

## 背景

主色 `#58B848` 实测命中 **33 个文件**（10 个源定义家 / 6 个生成物 / 7 个测试复述 / 4 个校验器 /
3 个未跟踪本地文件），详见 ADR-0131 背景。任何「把绿换成钛银」的做法若不改变这个形状，
就是把 P-07 原样搬进新品牌。

三个约束使「全部归一」在物理上不可能：

1. **补丁锚必须是字面量。** `packaging/verify-patches-v2.sh:105` 与
   `dsh-client-ui-agent-preset/lib/client.js.patch:7` 按**精确文本**匹配安装后的字节，
   无法引用变量或 token。
2. **校验器的价值恰在于独立复述一份期望值。** `brand-css.test.ts` 的文件注释已写明：
   「把版本钉复制进断言等于自证，上游换哈希后它照样绿」——所以不能一律改成读源自证。
3. **`theme-tokens-baseline-frozen` 与 `exemptions.json` 都是只减不增**，
   当前 `exemptions.json` 为 `[]`，**没有任何豁免余量**给换皮用（ADR-0014）。

另外两处结构性风险：

- 射程里有三处（recovery / setup-wizard / desktop-dialog 文案）住在
  `vendor/dsh-desktop/` 这个 **gitignored 嵌套仓**（`.gitignore:37`）里，
  在其中编辑对 git review 不可见、diff 拿不到、回滚靠不住。
- 所谓「视觉基线」`.dsh-root-brand-preview/visual-baseline/*.png` **完全未被跟踪**，
  由 `visual-gate.sh` 用 headless Chrome 现跑现生成——基线不可从仓库重建。

## 决策

**D1 建单一品牌源。** 唯一源是 `--sanbao-*` token 定义文件（ADR-0132 D4）。生成物一律走
`shared-sync` 机制派生；测试与校验器改为 **import 源做断言**，不再复述字面量。
33 个文件里，只有「源 + 生成物 + 补丁锚」三类可以合法持有值，其余必须消失。

**D2 不可消除的字面量纳入校验，而不是假装没有。** 补丁锚那一份字面量消不掉，
于是新增一条断言：**锚值 == 源值**。这与 `theme-tokens-baseline-frozen`、
`exemptions-frozen` 是同一套做法——把消不掉的东西登记进射程并规定其一致性，
而不是为了「零字面量」的洁癖去删掉交叉验证。

**D3 三处 vendor 侧文案一律走 bundle 重放，不改 vendor 源码。** 在 `brand-replay.sh` 里
为这三份 HTML/JS 新增替换声明，纳入既有 `brand-replay-selftest` 的 R1–R6（漂移 / 写入 /
字节相等 / 幂等 / 尺寸不符拒写 / 空资产目录判 MISSING）。vendor 是只读 pin（ADR-0008），
改它等于把参照系变成第二个工作区。

**D4 新增两条常绿可红的判据。** `brand-token-single-source`（扫「出货可见面含退役主色字面量」）
与 `brand-name-leak`（扫「出货可见面含基座原名 / 退役名」）。**扫描面为空一律判红**（P-15）——
「一处都没扫到」与「扫过且合规」必须分开。

**D5 `brand-icons` 门禁必须补形状判据。** 现状只校 PNG IHDR 像素尺寸与 `ICON_PAIRS` 声明一致，
**不校 alpha 通道与圆角**。ADR-0133 D3 的教训正是：素材源仓的 app icon 是
`RGB / hasAlpha: no` 的硬边方块，直接落进 `.icns` 会**静默出货**且门禁照样绿。
新增判据：出货图标必须 `hasAlpha` 且四角透明。

**D6 六个垂直切片，每片可独立验收、可独立回滚。** S1 品牌源与 token → S2 logo 与图标资产 →
S3 头像管线 → S4 命名与文案 → S5 打包链与身份 → S6 收口。切片边界见执行计划。
排序依据：S1 是一切的地基且单独可回滚；S2/S3 互不依赖可并行；S4 依赖 S1 的 token 名；
S5 依赖 S2 的 squircle 与 S4 的名字；S6 必须在最后，因为它要清零复述面。

**D7 不灰度，整体替换。** 皮没有「部分用户先看」的意义；双皮会让射程表需要两套期望值，
并等于在运行时装层重新打开 ADR-0131 D1 已否决的双品牌分层。**分期本身就是风险控制**。
回滚 = 重装上一版 DMG（发布 SOP 的「同号归档」保证拿得到）。

**D8 验收三层，且视觉基线必须入仓。** ①`pnpm run gate` + `gate:full` 全绿（退出码即契约）；
②真机三件套读数（启动 attempt=1 / 看门狗零告警 / CPU 归零，沿用 ADR-0130 D5 标准）；
③视觉基线从 `.dsh-root-brand-preview/visual-baseline/` 搬进受管目录、可重建，
并给出 20 位逐位对照表。**不做**「拿产品截图像素级 diff 素材源仓官网预览图」——
素材源仓是官网不是产品，逐像素对不上是必然，只会造出一条恒红、最终被人手动放开的坏判据。

## 备选方案

| 方案 | 为什么未采用 |
|---|---|
| 33 处各自替换新色，不建源 | 改动机械、可分片，但 P-07 原样保留，下次换皮又是 33 处；且本次必漏——现状已有 3 个未跟踪文件在射程外 |
| 全删复述、一律读源 | 彻底消除字面量，但校验器一旦只读源就变成自证（`brand-css.test.ts` 注释所述），且补丁锚与源同出一门时再没人能发现两者不一致 |
| 继续直接编辑 vendor 源码 | 改在源头、下次构建自然带上，但对 git review 不可见，且把只读 pin 变成第二个工作区（ADR-0008、ADR-0016） |
| profile 层留 skin 开关做灰度 | 现场可逆、不用重装，但等于偷偷做双品牌分层，每条文案位要回答两次，射程表翻倍 |
| 一次性大提交做完全部 | 不存在「半绿半银」中间态，但 6 个门禁 + 7 个测试文件同时动，gate 红时无法归因，回滚粒度是全部；与 ADR-0130 D5 的既有教训相左 |
| 按包切分（theme → root-brand → surfaces） | 边界与目录树对齐，但每个包切完都是半皮，且打断 `layer-icons` 两包字节相同的跨包不变量 |
| 像素级 diff 对素材源仓预览图 | 看起来最严，实则恒红或恒绿 |

## 后果

- **正面**：主色第一次有了单一源与可校验的派生面；出货图标有了形状判据（补上一个会静默出货的盲区）；
  vendor 侧三处品牌改动第一次进入 git 可审面；视觉基线第一次可从仓库重建。
- **负面 / 需跟进**：
  1. 新增两条门禁（`brand-token-single-source`、`brand-name-leak`）本身要写自测，
     且必须能举出反例（P-02）——否则它们只是两条恒绿。
  2. D2 保留了补丁锚这一处字面量，因此「零字面量」不成立；这是**刻意接受**，
     由「锚值 == 源值」断言承担一致性。
  3. S6 排在最后意味着 S1–S5 期间盘上仍有复述面存在，只是它们被改判为读源；
     若中途停下发布，会留下「源已改、复述未清」的中间态——**不得在 S6 之前发版**。
  4. `ensure-signing-identity.sh` 目前只支持单一身份参数，生成 `WorldPilot Code Signing` 后
     旧身份证书是否保留决定老 bundle 能否复现构建，需在 S5 内单独裁决并登记。
  5. 本 ADR 不改变 `~/.dsh/skills/lute-brand-icons` 的仓外地位（ADR-0133 残留 R5），
     退役它是独立一轮。

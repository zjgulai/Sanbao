# ADR-0239 · 目标/计划模式：服务投影只读、具名切换与「不回执不改显示、不写默认」

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-036、US-192~194 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-plan-goal-mode.md)
- 相关：[ADR-0234](ADR-0234.md)（034 澄清中继，plan-review intent 载体）、[ADR-0229](ADR-0229.md)（032 方案投影）、[ADR-0198](ADR-0198.md)（host 消费登记）、[ADR-0236](ADR-0236.md)（036 具名写先例）

## 背景

工单 039（FW-036，US-192~194）：**模式状态由服务投影给出；界面切换是具名请求，回执生效后
才显示为新模式**；**事项内切换不写全局默认、默认值只在设置页明确修改**（与 FW-006 同构）；
**计划模式输出进入方案预览呈现**；**退出计划不留下"已执行"暗示**。基座事实（pin 包
`dsh-plan-mode`）：`ctx.planMode.get(agent)→{active, pending?}` 是投影裁剪视图（`plan` 投影
折叠会话日志，resume/fork 恢复；空日志 fold 为 `active:false`）；`set(agent, active)` 返回
**基座自己的结果词** `committed | queued | cancelled | noop`——开着轮次时选择进入 pending
（下一步被接受的 pre-step 才落日志），**queued 绝不等于已生效**；`exit_plan_mode` 工具经
user-questions 呈 **plan-review**（detail=方案 markdown、intent.approve 命名通过项），034 中继
已镜像同一 intent；D-061 已定"只出方案经交付范围表达、不另设独立计划模式"，模式级审批/团队
策略/自动执行均不在首版。

## 决策

1. **D1 读=服务投影裁剪视图（经桥、诚实归一）**：桥面新增 `session/plan-mode`（read）：
   `agents.get(sessionId)` 解析活代理→`planMode.get(agent)`；返回 `{active, pending}`（缺席=
   `pending:false` 归一，不造值）。提供者缺席=`bridge-provider-unavailable`；**无活代理=
   `bridge-session-not-live`**（恢复中的日志可能 active，绝不假装 inactive）；形状不符=
   `bridge-plan-mode-unreadable`。
2. **D2 切换=一条具名请求、回执词是基座的**：桥面新增 `session/plan-mode-switch`（write）：
   `{sessionId, active}` 恰两键→`planMode.set(agent, active)`；四个结果词**原样过桥**，非四值=
   `bridge-plan-mode-unreadable`——桥端不把 queued 折叠成成功，也不重命名回执。
3. **D3 main store：三族回执＋后读视图，绝不伪造**（`main/plan-mode.ts`）：`switch` 成功后
   以 `session/plan-mode` 再读一次填 `view`（**这保证"未生效显示当前实际模式"有数据依据**；
   后读失败=view:null+viewCode，回执仍如实为 settled）；回执 `family`＝applied（committed）/
   pending（queued）/ unchanged（cancelled/noop），`outcome` 原名保留；无会话=
   `plan-mode-no-session`；**整个 store 只触这两个端点**——不碰 settings、不写任何跨事项默认，
   事项间零泄漏（结构断言）。
4. **D4 渲染面（S8）**：输入区互斥两钮（目标/计划）；**实际模式**标「（当前）」；pending 的
   目标标「（下一步生效）」而**当前模式保持「（当前）」**（回执前不改显示）；注记句区分
   current / pending / unavailable（未接线，带原因）/ no-session；点击后回执按三族各有具名句，
   **退出计划的文案是"退出不等于方案已执行"**；plan-review 澄清卡把 `detail` 渲染为**方案
   预览**并附「接受方案不等于执行其中动作」注记（US-194=US-165 在计划模式输出的呈现位），
   提交机制仍走同一张卡（不另开旁路）。切换按钮在未核验/无会话时禁用（缺项如实）。
5. **D5 首版不做**：模式级审批、模式团队策略下发、计划模式自动执行（工单边界）；
   设置页模式默认的**修改**面不在本票（读面与写面在 §7/046 的只读收口内）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 切换即写设置页默认值 | 否决：US-193 明令不写默认；默认只在设置页明确修改。 |
| 只读 `command/run` 投影推导 pending，不调 `planMode.get` | 否决：controller 的 pending（开轮期 set）不在日志里；`get` 是唯一含裁剪视图+controller-pending 的读。 |
| 桥端把 queued/cancelled 折叠成"未改变"单态 | 否决：回执词是基座的；折叠=在桥处丢信息，三族映射归 main store。 |
| 无活会话时按投影初值显示 `active:false` | 否决：恢复/分叉会话的日志可能 active；假默认=编造事实。 |
| 计划模式输出另建 Sage 方案卡（不接 plan-review 通道） | 否决：`exit_plan_mode` 事实走 user-questions；第二个家必漂。 |

## 后果

- 验收三条机器断言：①事项 A 切换模式不影响新事项默认（store 只调两个会话端点；他事项/新事项
  读取各自独立——no-session 依旧 no-session）；②切换回执三态可区分且未生效显示实际模式
  （family 三族 + view 仍 active:false/pending:true）；③计划模式输出进入方案预览呈现且
  **接受方案≠执行**（plan-review 卡的预览与注记、提交仍同卡）。
- 桥面 +2 端点（`session/plan-mode`/`session/plan-mode-switch`）；消费登记 +`planMode`+`agents`；
  host 表 deliberate +2；端口名册 +1（sessionPlanModeSwitch）；033 装配守护 +1 族。
- §1.6：真产物两宽（1440/660）亲看——模式条「目标模式（当前）」高亮＋「计划模式」；pending 页
  「目标模式（当前）」＋「计划模式（下一步生效）」＋注记「切换已登记：将在下一步生效；当前实际
  为目标模式。」；plan-review 卡方案预览（96 字符 markdown）+「接受方案不等于执行其中动作」；
  flow 页 DOM 读数 `MODE [{"active":true}]`（恰一条 POST）。
- 已知未闭：真实 `dsh-plan-mode` 装载与 `set` 真调用未跑（本机不装载 profile/不启 Host）；
  production 缺 provider 时呈现"未接线"诚实态；模式默认的设置页写面后置。

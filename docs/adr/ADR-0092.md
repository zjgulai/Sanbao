# ADR-0092 · 「三无」的头像：形制承载等级，颜色不承载；图标库是家，`icon:` 行是物化副本

- 状态：accepted
- 日期：2026-09-16
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/capability/2026-09-16-sanwu-avatar-and-icon-library-same-origin.md)
- 相关：ADR-0090（品牌图标的下装颜色：判据挂在被消费的产物上）、ADR-0091（三无 preset 与节点轴重建）、
  ADR-0022（岗位头像走官方 `icon` 字段）、ADR-0009（一份事实只有一个家）、ADR-0015（非机械改动必须留痕）、
  ADR-0073（出货预设白名单）、总账 P-02（仪器假绿）、P-03（「知道」没有变成「拦住」）、P-07（一条事实多个家）

## 背景

「三无 · Agent全栈专家」是 53 个 preset 里**唯一还没有头像的现役 preset**（另一个 `lute-cordis` 已标退役）。
`icon` 是平台 schema 四个字段之一（name / description / order / icon），由官方卡片显式消费 ——
缺了它卡片静默回落成「没有脸」，加载、日志、页面读数全部正常。

用户要求一枚**特别的**头像（皇帝老爷爷或管家）且**保持品牌调性一致**。品牌规范里有一条硬约束：
「不引入品牌绿以外的彩色（肤色/发色/白/灰除外）」—— **色板里没有金色**，而金色是画皇帝最省事的路。

同时，头像的载体是一坨几千字符的 base64，它有两个可能的位置而两个都错：只放图标库 → preset.yml
缺 `icon:` 行；只放 preset.yml → 图标库重画之后副本停在旧脸。图标库本身又是开发机资产
（327 枚不在 git 下），门禁跑在仓库里——ADR-0090 已为同一件事划过界。

还有一条本次特有的约束：**本会话的模型不能读图**。规范里那些本该用眼睛判的条目
（头部占比、描边粗细、徽章是否越内框）我一律判不了，所以交付形态从一开始就不是「一枚做好的头像」。

## 决策

1. **三枚候选，用户定夺**（冕旒 / 燕尾领结 / 梁冠），最终选 `sanwu-emperor` 皇帝老爷爷 · 冕旒。
   只给一枚等于把审美判断藏进交付里，而我又看不见图。
2. **不用金色：帝王感由形制承载，不由配色承载。** 冕冠画成品牌绿三阶 + 白，「老」由灰白须眉表达，
   另加交领右衽与印玺徽章。形制足以读出等级，颜色不必 —— 这是本次唯一真正的设计取舍。
3. **引擎只追加 key，并用漂移闸证明既有 324 枚零变化**：动笔前把 catalog 逐条重建与磁盘比对，
   要求逐字节相同且**零例外**。既有字节被别的包断言着，改引擎最容易伤到的就是它们。
4. **走 append-only 通道，不跑 `build.js`**（后者会整体重建 manifest、重算全部已验收字节）。
   新脚本多一道**部件指纹闸**：每个新部件登记「画出来必然留下的子串」，缺了就判红 ——
   防的是「key 名写错时 `buildIcon` 不抛错、静默少画一块」这个既有缺陷形状。
5. **同源契约**：图标库 manifest 是**唯一事实源**，`preset.yml` 的 `icon:` 行是它渲染出来的
   **物化副本**；`sync-fullstack-avatar.mjs` 是唯一渲染实现，门禁 import 同一份函数复算。
   门禁第 7 层分三问：形状（在不在、是不是 data URI、是不是 100×100 徽章）、同源、**paint 合法性**。
   图标库读不到时**判红并给出修法**，不静默降级 —— 空转的判据仍然报绿，是本仓库登记过的复发形态。
6. **判据挂在被消费的产物上**（ADR-0090 的纪律延伸到新载体）：这枚头像的载体就是 `preset.yml`，
   仓库够得着，所以 paint 合法性由仓库自己读，不指望本机那两支脚本。
7. **图标库自己的两支判据（结构 / 栅格）是本机工具，不是门禁** —— 它们不在仓库，按 ADR-0090
   已划的那条界；写成它们的直接动因是我看不见图，而「像素有没有越框」可以量。

## 备选方案

- **手抄 base64 进 preset.yml**：一次性，「霉」时无人发现。否。
- **把图标库与判据搬进仓库**：与 ADR-0090 的结论相抵，且会产生第二份事实源。否。
- **跑 `build.js` 重建全库**：重算 324 枚已验收字节，风险大于收益。否。
- **用金色画冕冠**：违反品牌铁律，换来的只是「更像皇帝」一句。否 —— 改由形制承载。
- **顺手修 `headset` 的越界杆尖（24 枚）**：会改动被外部逐字节断言的产物。否 ——
  登记为具名豁免且只减不增（修好时判据报「豁免已过期」并判红）。
- **只交付一枚头像**：把审美判断藏进交付里。否 —— 三枚候选 + 对照图。

## 后果

- 图标库 324 → 327 枚；`preset.yml` 追加 4966 字符的 `icon:` 行；门禁六层 → 七层；
  自测 12 → 19 条（I0–I7）；SOP 与 `gate.mjs` 的修复指引同步更新。
- 验证：漂移闸 324/324 逐字节相同；结构判据 327 枚 4227 项全绿；栅格判据 0 像素外溢
  （先在已验收图标上校准）；自测 19/19；`gate` 63/63、`gate:full` 70/70。
- **审美判断未做也做不了**（模型不能读图）：交付的是「像素没越框 + 颜色在色板内 + 形状按规范」
  加一张对照图，好不好看是用户的判断。
- **判据自身翻车四次**，形状一致（探针的语义是被假设的，输出却被当成事实）：结构判据第一版把
  全部 324 枚已验收图标判红；临时 grep 把渐变定义当越界；把 `stroke-width` 当坐标；
  栅格判据把不透明背景当内容、又用色板卡线性渐变的插值色。四次都靠「**先拿已验收产物校准判据**」
  挡住。这条纪律比任何一条具体判据都值得留下。
- **遗留（未擅自表态）**：`agent-fullstack` 未登记进 `packaging/shipped-presets.json`，
  实测 `select-presets.mjs` 会拒绝打包并点名它。发不发是产品决策。
- 卡面头像在宿主装载预设时读取，**改完需重启 DSH 才可见**。

# ADR-0277 · C2D.2A：app-bundled Capability Registry provider（内部阶段空快照首发）

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：T05 中段继续推进，选定非外部阻塞的 C2D.2A 前置项）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-c2d2a-bundled-registry-provider.md)
- 相关：[ADR-0171](ADR-0171.md)（Registry 治理：四态、immutable snapshot、approval gate）、[ADR-0191](ADR-0191.md)（C2E 组合：C2D.2A 到位即在同一 provider 内放行后续阶段）、[ADR-0195](ADR-0195.md)（遗留⑧登记 C2D.2A）、[ADR-0276](ADR-0276.md)（target 候选线；其发布重观测需要 descriptor 生产者可放行）

## 背景

运行时 descriptor 生产者（WT-02C.2E）在其 registry 端口缺席时整段 fail closed——「absence is unavailable, never empty capabilities」（ADR-0191：**C2D.2A/C2C.5 到位即在同一 provider 内放行后续阶段**）。C2D.0 治理与 C2D.1 pure kernel（四态/immutable snapshot/hostile parser）已落，C2D.2 的 real entry 因依赖 C2C.5 verified descriptor 与真实 Adapter mapping 保持外部阻塞；但**装载边界与首发快照**不依赖任何外部输入：内部阶段没有任何外部能力被批准，空快照就是诚实的首发声明。

## 决策

1. **D1 首发快照 = 内部阶段空集**：`EMPTY_INTERNAL_REGISTRY_SNAPSHOT_BODY`（`createdAt` 固定 `2026-10-10T00:00:00Z`——发布是发布动作，不是运行时读钟；`entries: []`）。任何非空条目**不得**通过编辑该常量进入出货面——真实条目的路径是新的已发布快照，且必须先走 `candidate → verified C2C descriptor → owner approval → MatrixV2 rule → Adapter mapping`（ADR-0171 治理链）。
2. **D2 内核封存 + fail-closed 读取**：`createBundledCapabilityRegistryProvider(snapshotBody?)` 每次 `read()` 经 `sealCapabilityRegistrySnapshot`（C2D.1 kernel）封存并返回深冻结快照；不可封存时抛出只带稳定码的错误（无路径、无载荷字节），消费方映射为其稳定的 `registry-unavailable` 阶段结果。构造从不抛出（坏 bundle 不得崩启动）。
3. **D3 生产接线**：`index.ts` 构造 bundled provider 并作为 `registry` 端口交给 `createRuntimeInventoryProvider`——该端口是 descriptor 生产者放行的最后一个缺席输入；接入后，当其余输入全部为真实事实（Host ready + C2A verify + 物化 profile + PMAP + protocol v5 观测）时，inventory 组合按既有语义产出 stable descriptor 与 full evidence。
4. **D4 首发能力面为空的语义**：`capabilities: []` 不是占位——它是「内部阶段没有外部能力被批准」的机械声明（与 ADR-0276 D4 的首发范围一致）；external capability 证据（C2C.2～.5）与 real entry 到达时以新快照放行，不改本 provider 的形态。
5. **D5 门禁登记源码事实**：index 构造与接线、模块的 kernel 封存、fail-closed 读取、空集常量，附五条具名突变；不改 route 权威矩阵与计数。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 继续等待 C2C.5/C2D.2 全链——registry 端口继续缺席 | 否决：descriptor 生产者在可预见的将来恒 unavailable，ADR-0276 的发布重观测与 T05 中段永远没有真实输入。 |
| 非空条目直接放进 bundled 常量 | 否决：绕过 C2C.5 verified descriptor 与 owner approval（ADR-0171 明禁）。 |
| 从文件/bundle 目录装载快照 | 延后：真实多快照的装载边界（bundle 位置、撤销源）属发布票；首发空快照先以常量固化，形态对将来装载开放（provider 接受任意 body 参数）。 |
| 在 provider 内自行解析而不经 kernel | 否决：validation 必须走 C2D.1 内核，provider 不重复也不隐藏校验。 |
| 依赖运行时时钟生成 createdAt | 否决：快照发布时间必须确定性、可复现；运行时读钟会让 snapshotId 漂移。 |

## 后果

- descriptor 生产者第一次具备全部输入（当真实环境满足时即可 `available`），T05 中段的「发布重观测」有了真实对象；空 capabilities 与 ADR-0276 首发范围一致。
- 快照以空集发布是一个可审计的产品事实：内部阶段无任何外部能力获批；非空条目到达时是新快照事件（含撤销源与装载边界），不是常量编辑。
- 遗留⑧（registrySnapshot 变更检测）现在有了检测对象；其机制仍待后续票。
- 未闭：C2C.2 bridge seam（外部）、C2C.5/C2D.2 real entry、真实登录与真机首条消息；T05 不因本刀标记完成。

# ADR-0295 · 投影面 epoch 货币化、评审路径分流与两项政策裁决

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：四项裁决均采纳推荐）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-readout-epoch-and-review-split.md)
- 相关：[ADR-0294](ADR-0294.md)（同族货币性）、[ADR-0293](ADR-0293.md)（收口与 blocked）、[ADR-0283](ADR-0283.md)（证据政策）

## 背景

ADR-0294 登记了两处未闭：UI 插件投影面在宿主 epoch 死亡/移动后仍展示死 epoch 的行；以及回合收口的语义裁决（blocked、产物并存）与 T13-A 的 verified 政策。本次四项裁决：下批排法、blocked 处理、产物并存、verified 升级政策——前后两项属排程，中间两项落为本 ADR 的决策与实现。

## 决策

1. **D1 投影面 epoch 货币化（实现）**：`classifyPlugins` 在行列可行前加两道门——观测非 active → `host-epoch-unavailable`；观测 active 但与 inventory 证据的 bootId/runtimeGeneration 不等 → `inventory-epoch-stale`（复用 `isInventoryObservationCurrent`，其签名放宽为结构参数以覆盖两处消费者）。死 epoch 的插件行不再展示（该面的可用性结论保持诚实）。
2. **D2 blocked = 保持打开（裁决确认）**：blocked 回合不写任何收口事件，attempt 保持 active——blocked 大概率对应「模型提出阻塞问题」，与既有 clarifications 读面同族；最终映射留 clarification 整合票定案。ADR-0293 的该登记项由此转为正式语义。
3. **D3 产物并存 = 策略分流（实现）**：turn-close runner 读当前 revision 策略——被尝试的任一 scope 若 `requiresDecision=true`，completed 回合**不**走轻终态（保持打开，走 artifact/receipt 评审路径）；失败回合不受此门约束（失败无需评审，仍按既有 failAttempt 收口）。默认（无 decision 需求）仍为轻终态。
4. **D4 verified 升级政策（裁决）**：matrix 行升级 verified 仅当五维（UI / Application Service / Host / Electron / 视觉）各自句级证据齐备且经独立复核；`countsAsVerification` 维持 false；implementing 维持现判据。政策写入 T13-A 迁移记录，后续迁移批按其执行。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 投影面仅去重展示（保留行） | 否决：死 epoch 的行是错误声明，不是陈旧但真实。 |
| blocked 映射 attempt-failed | 否决（用户裁决）：把「等待澄清」说成「失败」并强制 reconfirm 仪式，语义错位。 |
| blocked 直接接入 clarification 域流 | 保留为整合票：需要待答卡与回答后继续路径的完整接线，单批吞不下。 |
| 全部回合一律轻终态 | 否决（用户裁决）：拆掉需要评审事项的 artifact/receipt 路径。 |
| verified 单维强证据即升 | 否决（用户裁决）：与票据「五维闭合」原则冲突。 |

## 后果

- 投影面与准入链现在共用同一条货币性判据（一处 forma，两处消费）。
- 收口语义闭环：默认轻终态、评审事项保持评审、失败始终诚实收口、blocked 保持打开待整合票。
- T13-A 升级路径有明文政策；未闭：clarification 整合票、outcome-unknown 对账票（侦察进行中）。

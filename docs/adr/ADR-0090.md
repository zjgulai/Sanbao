# ADR-0090 · 图标的下装颜色：一个「看着像设计」的非法值，与它为什么能活 310 枚

- 状态：accepted
- 日期：2026-09-15
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/capability/2026-09-15-brand-icon-shoulder-paint-and-carry-over-path.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0015（非机械改动必须留痕）、ADR-0089（全栈 40 条入库）、
  总账 P-02（仪器假绿）、P-04（写了但从没跑到）、P-11（判据的射程没有定义）

## 背景

做全栈线 40 枚徽章时顺手把一枚图标栅格化取样，测到**肩带是纯黑 `(0,0,0)`**，
而 catalog 给它写的是白衬衫 `W`。查下去是三件事叠在一起：

1. **生成器把名字当值用。** `lute-brand-icons/lib/generator.js` 里 `catalog.js` 的 `shirt`
   字段存的是**名字**（`G`/`GD`/`GL`/`MINT`/`W`），而 `shoulders()` 的第一个参数要的是**颜色值**。
   调用点写的是 `shoulders(shirt, …)`——紧邻的 `COLLARS` 用的是 `${W}`/`${G}` **值**，
   两者在同一个函数里并排，所以看上去毫无违和。产物于是写着 `fill="W"`、`fill="GD"`，
   都不是合法 CSS 颜色，SVG 按规范回落到默认黑。
2. **它长得像设计。** 「小人像的深色下装」是一个非常合理的观感，**不是**一个看起来像坏值的观感。
   全库 310 枚一起错，反而更像风格统一。
3. **没有任何判据在看这个值。** 既有「图标覆盖」判据只问「这一行有没有图」，
   不问「这张图能不能正确渲染」。生成器在本机 `~/.dsh/skills/` 下、**不进仓库**，
   所以仓库侧也没有任何东西会去解一次 data URI。

第三件还牵出一条更隐蔽的路径：`assign_lute_icons.py` 里有一段
「保留既有自定义图标（非 81 系）」——它把**上一轮 `skill-icons.json` 里的字节**当成事实源。
`self-improvement` / `lieflat-charts` / `agent-browser` 三枚正走这条路。
后果是**生成器修好了也照不到它们**：修复被「上一次的产物」挡在门外。

## 决策

1. **给生成器补一张衬衫色表并传值**：`const SHIRT_COLORS = { G, GD, GL, MINT, W }`，
   调用点改成 `shoulders(SHIRT_COLORS[shirt] || G, …)`。一行的事。
2. **判据挂在被消费的那份产物上**：`scripts/verify_static.mjs` 新增「头像 paint 值必须合法」——
   把全部 193 枚 data URI 解出 SVG，逐个断言 `fill`/`stroke` 的取值属于
   `#RRGGBB` / `url(#…)` / `none` / `rgba()` / `transparent`，并带一条**空转哨兵**
   （「解出 N 枚 SVG 却一个 fill 都没有」与「零违规」必须在读数上不同形）。
   不挂生成器里，因为生成器不在仓库、门禁够不着它。
3. **把「沿用上一轮的产物」换成显式映射**：新增 `EXTRA_ASSIGN` 表把三条非 81 系技能
   指回它们的 catalog id（`agent-browser→qa-tester`、`lieflat-charts→data-scientist`、
   `self-improvement→ai-assistant`），84 枚全部由 catalog 现算。
   沿用路径**保留但不再静默**：命中的名字会逐个打印并提示补进 `EXTRA_ASSIGN`。
4. **不把它当配色调整，而当缺陷修复发布**：**193 枚不同的图**（被 230 个清单条目引用，
   含 12 枚层头像）的下装从黑色变为各自的衬衫色——**无一幸免**。
   这是**产品可见的品牌呈现变更**，故本轮先取得用户明确同意再改，并把变更范围写清。

## 备选方案

- **只改新加的 40 枚，不动既有的 270 枚**：会造成同库里两种下装风格并存，比统一更糟；
  且缺陷的家在生成器，改一半＝把「一份事实两个家」固化下来。否决。
- **把判据写进生成器的 `build.js`**：能更早拦住，但生成器不在仓库，判据对**仓库**的出货面没有射程；
  本仓库的既有纪律是判据只读消费侧产物。两处都写＝同一事实两个家。**只在仓库侧写。**
- **删掉「沿用」路径，只留显式映射**：会让将来新增的手工头像在重跑管线时被静默抹掉，
  那是另一种静默。改为「保留 + 点名」。否决删除。
- **把非法值判据放宽到只查 `fill`**：`stroke` 走同一条函数、同一个 bug，只查一半等于留一个洞。

## 后果

- 实测（栅格化后取样，`240×240`，肩带带 y≈0.86–0.92）：
  | 图标 | 衬衫 | 修前 | 修后 |
  | --- | --- | --- | --- |
  | `sk-fs-tdd` | `W` | `(0,0,0)` | `(255,255,255)` |
  | `sk-fs-accessibility` | `G` | `(0,0,0)` | `(88,184,72)` = `#58B848` |
  | `sk-fs-postgres` | `G` | `(0,0,0)` | `(88,184,72)` |
  | `sk-fs-git-commit` | `GL` | `(0,0,0)` | `(143,212,138)` = `#8FD48A` |
- 判据首跑就抓到 **193 枚不同的图、193 处**非法属性（被 230 个清单条目引用：出海 84 + 全栈 70 +
  通用 15 + 三类分组 49 + 层头像 12，**一枚例外都没有**）；修后 193 枚 / 6720 个 paint 值全合法。
  受控变异（把一枚的 `fill="#FFFFFF"` 改回 `fill="W"`）当场判红，还原后复绿。
- 连带重建：`lute-brand-icons` 310 枚 → 6 份仓库清单 + `lib/layer-icons.js` +
  **隔壁包 `dsh-algo-skills-local/src/layer-icons.ts`**（两包逐字节相同，有跨包测试守着；
  只重跑一边会被那条测试当场抓住）。
- 诚实划界：判据只断言 **paint 值合法**，不断言「这枚图看起来对」——图案、构图、配色是否合适是人的判断，
  机器判不了（与 ADR-0081 的边界同型）。
- 本机资产 `~/.dsh/skills/lute-brand-icons/lib/generator.js` 已修，但它**不进仓库**；
  仓库侧能守的只有上面第 2 条的判据，以及第 3 条把 84 枚的来源指回 catalog。

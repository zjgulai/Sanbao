# ADR-0222 · 应用内提醒：分区与计数即提醒、无第二份未读、负空间由测试守住

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证并实施；负空间的守卫方式是取舍）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-in-app-reminder-discipline.md)
- 相关：[ADR-0221](ADR-0221.md)（事项列表分区——提醒的唯一事实源）

## 背景

工单 023（FW-018，US-114~116）要求：**运行完成与待处理只体现为分区归属与计数**（应用内），不发系统
通知、不申请授权、不改标题闪烁或程序坞徽章；**不另建第二份"未读"状态**；系统通知/徽章/后台到达
后置（届时须区分"已投递系统"与"用户已见"）。取证边界（FW-018 原文）：pin 内无通知相关包、Sage
源码无系统通知使用——首版选应用内标记**不引入新权限面**。

本票性质是**负空间票**：产品行为大多已由 022 的分区/计数承载；要补的是（a）"回到应用即可看到"
的可见标记、（b）把负空间变成机器可守的断言（不是散文承诺）。

## 决策

1. **D1 提醒＝同一投影事实（US-114/115）**：侧栏"经营事项"项加一枚计数 chip（`#nav-matter-count`），
   与列表卡计数**同源于 `matterList.counts`** 的同一渲染趟——一处变化两处同变，没有第二份"未读"。
   chip 仅在 `state==='read'` 且 action 计数>0 时显示（0 或不可读恒隐藏：缺席不读作"无事"）。
2. **D2 负空间由扫描断言守住（US-114/116）**：`test/reminder-discipline.spec.ts` 遍历
   `apps/sage-shell/src` 全部 .ts，禁止出现 `new Notification` / `Notification.requestPermission` /
   `requestPermission` / `setBadgeCount` / `setBadge(` / `flashFrame` / `app.dock` / `dock.setBadge`；
   另断言 renderer 无 `document.title =` / `setTitle` 等标题面改动——未来票要发系统通知必须先改这条
   测试（可见、可审）。
3. **D3 无第二份未读（US-115）**：契约扫描——`contracts.ts` 不得出现字段形 `readonly *unread*` 或
   引号未读态字面量；提醒词汇只有 partition+count。surface 断言 chip 文本 == 卡计数文本（数字同源）。
4. **D4 "回到应用"即随投影更新**：chip/卡计数在每个状态轮询里由同一 payload 重渲（测试用
   setPayload+refresh 断言两处同变），无用户动作、无缓存。
5. **D5 后置边界（US-116）**：系统通知/程序坞徽章/后台到达不做；发出通知≠已读、未聚焦不重复计数
   留待专票——本票不授权也不预置这些接点。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 独立未读计数 store | 否决：US-115 点名；第二份状态必然与投影分叉。 |
| 标题/程序坞徽章 | 否决：US-114 点名不做（Electron 侧也无需新增权限面）。 |
| 只在列表卡显示、不管侧栏 | 否决（本票取舍）："回到应用即可看到"要求任意视图可见；计数同源即可从任一处看到。 |
| 负空间只写散文 | 否决：仓库纪律"知道要变成拦住"——写进扫描断言并由变异电池验证其会红。 |

## 后果

- 两条验收各有机器断言：无通知 API（源码扫描+变异验证）；无独立未读（契约扫描+chip/计数同源）。
- 已知未闭：真机 Electron 未跑；系统通知/徽章/后台到达按 US-116 后置（届时区分已投递/已见）。

# ADR-0153 · 降级自报标志定为「挂起 ≠ 失败」（不可见不判 / 恢复给宽限 / 迟到归位清标志）

- 状态：accepted（2026-09-21）
- 决策者：用户（lute）——批次 E 排期裁决「DA-10 先走，DA-21 紧随」；修法边界由工单写死
  （「语义是挂起 ≠ 失败——别把宽限期整体拉长来掩盖问题；真改版必须仍然响亮降级」）
- 决策记录：[Note](../notes/implemented/surface/2026-09-21-newapp-degrade-window-hidden.md)
- 相关：ADR-0019（不钉类名哈希 + 自报降级——本 ADR 把「自报」的时序语义写清）、
  ADR-0148 D5（单例探针把「放置挂起」与「未装载」分开——同一族读数的另一半）、
  pitfalls-playbook P-04（症状层修复 / 错误归因）、P-52（挂死类故障的观测悖论）

## 背景

2026-09-21 的 DA-06 补读轮在活体故障现场读到：`<html data-dsh-newapp-degraded="entry-unavailable">`
齐备、日志写着「shell generation may have restructured the sidebar」，而**真因是屏幕休眠 11.1 h、
窗口不可见 → Chromium 冻结 rAF → 放置被暂停**。两个缺陷叠在一起：

1. **误归因**：宽限期到点只看「入口行在不在」，不看「窗口看不看得见」——把「暂停」读成「改版」；
2. **陈旧假警**：宽限期是一次性定时器，窗口恢复、入口行归位之后标志**不会被清除**，
   标志从此与事实相反。

受害面是所有把该标志当读数的验收轮（DA-06 的实机读数轮就是这么被污染的）。这是 P-04 的形态：
**以「可被探针读取」为设计目的的自报标志，在常见场景（合盖/锁屏/窗口被盖住）里说假话。**

## 决策

**D1：判定分三态，隐藏不是失败。** 宽限期到点时，若 `document.hidden` 为真 —— 这是**暂停**：
既不报降级、也不重新武装定时器（对着休眠的显示器轮询是纯噪声），只等可见性变化。

**D2：恢复可见给一档短宽限。** `visibilitychange` → 可见时，以 `VISIBLE_GRACE_MS`（1200ms，短于
3000ms 的主宽限）重新武装：rAF 未必已经跑过一帧，此刻判「改版」就是本 ADR 要消灭的误报。
监听点必须是 `document`（该事件在 document 上派发、**不冒泡到 window**，挂在 window 上永远不会触发——
这是实现期被测试抓到的一次真错）。

**D3：标志不得比它的条件活得久。** 已经挂上的 `entry-unavailable` 在入口行**迟到归位**时必须被清除：
放置是自愈的（共享层 MutationObserver + rAF 会把行插回去），标志跟着条件走。实现上在报出降级后
挂一个 `document.body` 的 `childList+subtree` 观察者，观察到入口行即 `reportDegraded(undefined)` 并
拆除全部监听（定时器 / 观察者 / visibilitychange）。

**D4：真改版仍然响亮。** 「可见 + 宽限过后仍无入口行」照旧报 `entry-unavailable` 并 `console.warn`。
**不许用拉长宽限期来掩盖问题**——那只是把误报推迟，还会把真缺陷的发现时间一起推后。

**D5：测试要能说「不」，且不得把状态漏进下一个用例。** 三个新用例（hidden 不报 / 恢复给宽限再判 /
迟到归位清标志）与两条既有「必须报」用例互为反向；另外测试夹具每例结束**统一释放 effects**
（插件装的是 document 级监听与观察者，漏一个就把状态带进下一个用例——实测会把这个套件挂死）。

## 备选方案

- **把 `PLACEMENT_DEADLINE_MS` 从 3s 拉长。** 否决（工单明写）：只推迟误报，且连真改版的发现时间
  一起推迟；症状层修复的形态 P-04。
- **用 `document.visibilityState` 的 `prerender` 等其它状态区分。** 否决：`hidden` 已经覆盖
  「不可见 → rAF 冻结」这一判据所需的全部情形；多引入状态只会增加没人维护的分支。
- **只在 `visibilitychange` 上重判、不保留 MutationObserver。** 否决：迟到放置可能发生在**可见之后**
  且没有可见性变化（慢启动），那时标志必须靠 DOM 变化来清除。
- **把判据搬到共享层 `sidebar-entry-core.ts`。** 否决：共享层知道「怎么放」，**只有消费方知道
  「没放上算不算失败」**——这正是自报留在消费方的理由（ADR-0019 原文口径）。

## 后果

- 正面：`data-dsh-newapp-degraded` 恢复与事实一致；DA-06 那类「休眠→误报」不再污染实机读数轮；
  判据仍能对真改版喊疼（两条既有用例 + 一条新增用例互为反向，恒真桩/恒假桩两侧都能判红）。
- 代价（如实保留）：引入了「可见性变化」这一新的触发源，跨用例的状态清理成为测试夹具的硬要求
  （已用 `afterEach` 统一释放修掉；曾是本套件挂死的真因）。
- 后续：同类自报标志（其它包若有）应按本 ADR 的时序语义自查；实机读数仍待用户重拉一次
  （`singleton-count-live` 需 app 带 CDP 重启）。

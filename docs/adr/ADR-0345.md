# ADR-0345 · 观测菜单同名条目接目录形态（OpenAI / Google / OpenRouter）

- 状态：accepted（2026-10-13）
- 日期：2026-10-13
- 决策者：用户（2026-10-13「同意下一批建议」）＋ agent（装配设计）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-13-observed-catalog-entries.md)
- 相关：[ADR-0343](ADR-0343.md)（目录形态与目录读）、[ADR-0344](ADR-0344.md)（DeepSeek 卡）、L2 证据草稿 `drafts/analysis/analysis-qoder-provider-key-mapping-draft-20261013.md`

## 背景

L2 侦察（本机 Qoder 0.4.4 asar 单遍扫描）确立：观测「更多」组 17 项对应 app 侧 providerKey 词表（`providerIcons` 逐字证据）；其中 **OpenAI / Google / OpenRouter 三项与已装 pi-ai 目录 id 同名且语义一致**（api.openai.com / Google Generative AI / openrouter.ai），目录形态（ADR-0343）是它们的现成接入面。其余观测条目（Kimi/MiniMax/智谱/小米/千问/阿里云百炼）目录映射多候选或缺失——端点层常量不在二进制内（catalog 形态由服务端目录决定），不能从 RE 猜。

## 决策

1. **D1 同名三条目接线**：观测菜单中 `OpenAI → openai`、`Google → google`、`OpenRouter → openrouter` 三条进入目录形态（仅 Key，端点/模型来自已装目录）——静态映射表 `OBSERVED_CATALOG_PROVIDERS`，只收无歧义同名项，证据落 L2 草稿。
2. **D2 其余条目保持惰性**：未映射的观测条目点击不改变表单（不猜映射）。Kimi/MiniMax/智谱/小米/千问/阿里云百炼的接线等「providerKey→端点」的受控网络观察证据（L2 建议票）。
3. **D3 标签显示**：经观测条目进入时供应商字段显示观测标签（OpenAI/Google/OpenRouter）；经「本机内置目录」组进入时显示目录 id。同一 provider 两处入口共享同一路由与状态。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 动态同名匹配（点击时查目录读） | 否决：引入读取时序依赖；证据固定的静态三条更可测。 |
| 顺带映射 Kimi 等「近似」项 | 否决：目录映射二三候选，猜映射=把平台行为当常量。 |
| 观测条目与目录组只保留一个入口 | 否决：观测结构是复刻面、目录组是 Sage 自建面；两者同路由可共存。 |

## 后果

- 观测「更多」组中 4 项（含 DeepSeek）可用；其余 8 项维持惰性并在 L2 草稿中逐项登记判定。
- 矩阵：`provider.open` 行已 verified，无 per-entry 行——零矩阵改动。
- 复用 A2 全部机制（文法/目录读/保存/列表），无新桥端点。

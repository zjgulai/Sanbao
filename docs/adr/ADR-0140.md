# ADR-0140 · 右边侧边栏重构：统一扁平布局与 7 个能力模块

- 状态：accepted（2026-09-20）
- 决策记录：— (此文档)
- 关联：[ADR-0124](ADR-0124.md)（启动带去按钮化）、[ADR-0125](ADR-0125.md)（侧栏四带契约）、[ADR-0128](ADR-0128.md)（能力中枢聚合）

## 背景

当前 DSH 右边侧边栏存在以下问题：

1. **结构凌乱**：多个插件各自为政，缺乏统一的视觉与信息架构
2. **功能分散**：待办任务、环境信息、技能/MCP、网页查阅等核心能力未集中展示
3. **交互不一致**：各模块面板的打开方式、折叠逻辑、图标风格不统一
4. **扩展困难**：新增模块需重复实现注入逻辑，缺乏共享规范

用户提出需要整合以下 7 个核心模块：
- 待办任务提醒
- 环境信息（未提交、本地、main、提交或推送）
- 技能和 MCP
- 网页查阅
- 后台进程
- 产出
- 来源

## 决策

### 1. 布局策略：单一扁平列表

采用**单一扁平列表**而非折叠分组容器，理由如下：

| 方案 | 取舍 |
|---|---|
| 单一扁平列表（推荐） | 符合认知负荷上限（7±2），所有模块直接可见，无需额外交互成本 |
| 折叠分组容器 | 增加 L1 折叠组 + L2 容器的复杂度，类似 RoleMatrix 的 Workbench 组设计 |
| 混合模式 | 部分扁平部分折叠，增加决策复杂度和维护成本 |

**决策依据**：
- 现有插件（RoleMatrix、SkillCenter、NewApp）均采用扁平注入
- 扁平布局与 ADR-0125 的「工作台 ▸」折叠组形成互补（折叠组收纳低频能力）
- 减少用户认知负担，避免「找不到入口」的问题

### 2. 模块优先级与顺序

按**使用频率从高到低**排序，固定顺序为：

1. **待办任务提醒** - 最高频，日常任务管理
2. **环境信息** - 高频，开发时持续关注的 Git 状态
3. **技能和 MCP** - 中高频，工具调用与外部服务
4. **网页查阅** - 中频，研究资料访问
5. **后台进程** - 低频，系统监控
6. **产出** - 低频，内容生成记录
7. **来源** - 最低频，引用素材管理

**决策依据**：
- 基于用户工作流的实测频率
- 高频功能置顶符合 F 型阅读模式
- 低频功能靠下保持界面简洁

### 3. 信息密度：极简图标 + 文字

每个模块在侧边栏条目中仅展示**图标 + 简短标签**，详细数据在点击后的面板中展示：

```
📋 待办任务
🌍 环境信息
⚡ 技能和 MCP
🔍 网页查阅
⚙️ 后台进程
📦 产出
📚 来源
```

**徽章仅在必要时添加**（如待办任务有未完成任务时显示数字徽章）。

**决策依据**：
- 遵循 ADR-0124 的导航行轴一致性原则
- 避免侧边栏视觉过载
- 详细数据通过面板展开，保持层级清晰

### 4. 面板交互：独立折叠面板

采用**独立折叠面板**而非悬浮面板或模态对话框：

| 方案 | 取舍 |
|---|---|
| 独立折叠面板（推荐） | 面板固定在右侧，可收拢/展开；不阻塞主聊天区域；类似 RoleMatrix 的 dialog 但非模态 |
| 悬浮面板 | 自由拖动，像便签；增加位置记忆和布局复杂度 |
| 模态对话框 | 必须处理才能返回；阻塞主工作流 |

**技术实现**：
- 复用 `sidebar-entry-core.ts` 的注入机制
- 采用 `position: 'stacked'` 或 `'after'` 定位
- 面板使用 `<dialog>` 或自定义折叠容器
- 支持 rAF 防抖的自我修复机制

### 5. 技术架构：统一插件包

创建一个独立的插件包 `dsh-right-sidebar-local`，包含：

```
packages/surfaces/dsh-right-sidebar-local/
├── src/
│   ├── client/
│   │   ├── sidebar-entry.ts          # 侧边栏条目注入
│   │   ├── panel-mount.tsx           # 面板挂载点
│   │   ├── modules/
│   │   │   ├── todo-panel.tsx        # 待办任务面板
│   │   │   ├── env-info-panel.tsx    # 环境信息面板
│   │   │   ├── skills-mcp-panel.tsx  # 技能和 MCP 面板
│   │   │   ├── web-search-panel.tsx  # 网页查阅面板
│   │   │   ├── background-procs.tsx  # 后台进程面板
│   │   │   ├── outputs-panel.tsx     # 产出面板
│   │   │   └── sources-panel.tsx     # 来源面板
│   │   └── api/
│   │       ├── todo-api.ts           # 待办任务 API
│   │       ├── git-api.ts            # Git 状态 API
│   │       └── ...
│   └── styles/
│       └── right-sidebar.module.css  # 样式定义
├── package.json
└── README.md
```

**决策依据**：
- 符合 ADR-0011 的能力五组归位原则
- 复用 shared/core 的注入逻辑，避免重复实现
- 模块化设计便于后续维护和扩展

### 6. 数据源集成

各模块的数据源采用以下策略：

| 模块 | 数据源 | 更新频率 |
|---|---|---|
| 待办任务 | `~/.dsh/profiles/<profile>/todos.jsonl` | 实时监听 |
| 环境信息 | `git status` + `git diff` | 轮询 5s |
| 技能和 MCP | `ctx.get('skills')` + `ctx.get('mcpServers')` | 事件驱动 |
| 网页查阅 | 浏览器历史记录 API | 按需加载 |
| 后台进程 | `ps` + `/proc` | 轮询 2s |
| 产出 | `docs/notes/` + `scripts/` 生成日志 | 按需加载 |
| 来源 | `attrib jsonl` + 引用追踪 | 按需加载 |

**决策依据**：
- 优先使用官方已有数据源
- 避免引入新的持久化依赖
- 实时性要求高的模块采用轮询，低频模块按需加载

## 备选方案

| 方案 | 取舍 |
|---|---|
| 复用现有插件的注入逻辑 | **是**。直接基于 `sidebar-entry-core.ts` 扩展，避免重复造轮子 |
| 创建新的注入框架 | **否**。增加不必要的抽象层，现有核心已足够灵活 |
| 将面板改为 Tab 切换 | **否**。Tab 模式不适合 7 个独立模块，会增加点击次数 |
| 将面板改为抽屉式 | **否**。抽屉模式适合内容区，侧边栏更适合折叠面板 |

## 后果

### 正面：

- **统一视觉语言**：7 个模块采用一致的图标、间距、圆角、动效
- **降低认知负担**：扁平布局 + 极简信息密度，用户快速找到所需功能
- **易于扩展**：新增模块只需实现对应面板组件，复用核心注入逻辑
- **性能优化**：rAF 防抖 + 自我修复，避免 MutationObserver 级联
- **符合现有架构**：与 ADR-0124/0125/0128 保持一致，不破坏既有约定

### 负面与已知边界：

- **首次实现成本高**：需要实现 7 个面板组件和对应的数据源集成
- **数据源依赖**：部分模块（如待办任务）需要新的数据源支持
- **生效需重启**：与 ADR-0078 一致，改动需重启应用才生效
- **未做真机验收**：浅/深色截图、真实应用内测试需在实现后完成

### 后续动作：

1. **P0**：创建插件包骨架，实现基础注入逻辑
2. **P1**：实现前 3 个高频模块（待办、环境、技能/MCP）
3. **P2**：实现剩余 4 个低频模块
4. **P3**：完善数据源集成和实时更新
5. **P4**：视觉基线验收和真机测试

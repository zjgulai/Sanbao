# ADR-0282 · T05-mid 发布票第一刀：requirement 落 bundle 与真实 target 步装配

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：要求继续主链剩余切片接线）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-session-prompt-requirement-bundle-and-target.md)
- 相关：[ADR-0276](ADR-0276.md)（T05 中段：候选线与发布流程 D3）、[ADR-0278](ADR-0278.md)（首发发布件的 owner 裁决内容）、[ADR-0280](ADR-0280.md)（首个真实发布件封存）、[ADR-0275](ADR-0275.md)（session 族 identity 第一刀）

## 背景

T05 发布件（requirement/策略文档/提议矩阵规则）在 ADR-0278/0280 已封存，但只被测试引用——运行时**零消费**，会话族准入链真实接线到第 4 步（identity-policy），第 5 步 target 起全 absent（route-authority 门禁事实原文「the chain still stops at the absent target / compatibility / registry steps」）。ADR-0276 D3 已把流程定为：candidate → owner 裁决 → seal requirement + seal matrix → **随壳加载（bundle 位置与加载面属发布票）** → providers 装配接准入 resolveTarget / resolveCompatibility。本刀落 requirement 半边的 bundle 与 target 步；矩阵制品与 compatibility 属下一刀。

## 决策

1. **D1 bundle 制品与位置**：`apps/sage-shell/publications/session-prompt.requirement-snapshot.json` = C2.2T 内核封存的 snapshot（schemaVersion/canonicalizationVersion/createdAt=决策 `decidedAt`（确定性）/publicationDecision=owner 三元/entries=[ADR-0278 封存 requirement 的 body]）。dev 检出与打包运行时使用**同一相对布局**（从 `lib/main/` 或 `src/main/` 上两级即包根 / `<resources>/app`）；producer 将整个 `publications/` 目录拷贝进 app-runtime（produce-inputs 显式拷贝，与 `seed/` 同法）。
2. **D2 加载面不修复**：`loadSessionPromptRequirementBundle()` 启动时读取一次并经内核 `parseCompatibilityTargetRequirementSnapshot` 校验；失败只记一行 stdout（`sage shell: requirement bundle unavailable: …`）并把结果**原样**传给端口——不修复、不默认、不重封。逐请求不重读。
3. **D3 目标端口语义（不可铸造）**：以 `ACTION_AUTHORITY_TABLE[intent.operation]` 取 actionScope → 在 snapshot 中找**唯一**声明该 scope 的 requirement（0 条或 >1 条均 unavailable）→ 经 bundled provider 以 `evaluatedAt = authority.now` resolve。provider 任何失败码（not-effective/expired/revoked/not-found/action-not-declared）→ `unavailable`——**不得**映射 `denied`：治理数据缺失不是策略拒绝。`targetRef = target:<snapshotId>:<requirementDigest>`（重发布即移动，确定性）。
4. **D4 接线开关与可观测面**：仅当 `authority` 与 `requirementBundle` 同时存在才装配（缺 authority 时链已停在 identity，target 不可达）；路由层拒绝码保持 `protected-effect-unavailable`（stage 不入信封）——本刀的可观测变化是**内部 stage 前移**（target → compatibility）与端口级行为，由测试钉住；stage 进入信封属未来协议票。
5. **D5 门禁事实**：route-authority 门禁新增 target 事实组（gated 双开关接线、index 启动装载、表查 scope、唯一声明、targetRef 绑定、失败不得 denied、loader 必须调用内核 parse）＋五条具名突变；note 句更新为「chain now also passes the real target step … before stopping at the absent compatibility / registry steps」。
6. **D6 范围**：不改已登记的 owner 数据（ADR-0278 计划与决策三元）、不写矩阵制品、不接 compatibility/registry/preflight/persist/dispatch；`effectiveAt=2026-10-11T00:00:00Z` 前求值按设计答 unavailable。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 运行时直接读仓外产物（`/Users/pray/tmp/…`） | 否决：违反「随壳加载」与仓根纪律，发布件必须有卫兵与可复现布局。 |
| 把 requirement 内嵌为 TS 常量 | 否决：发布件是治理数据而非代码；内核 parse 是唯一验证门，数据文件让它可替换、可审计。 |
| 把 stage 加入拒绝信封以便路由级观察 | 否决：本轮不扩协议面；端口级测试 + 门禁事实已足够钉住语义。 |
| provider 失败映射 `denied` | 否决：把「治理数据不可用」说成「策略拒绝」，违反 unavailable-first 语义。 |

## 后果

- 「发布 → 运行消费」链首次闭合 requirement 半边：封存件从仓外读数变为随壳制品，启动即内核校验。
- 会话族链真实推进到第 5 步；第 6 步起仍 absent，路由行为保持 unavailable-first（拒绝码不变）。
- 打包链下一次 produce 将把 publications 装进 app-runtime；dmg 验收可观察到 `sage shell: requirement bundle unavailable` **缺席**（装载成功无输出）。
- 未闭：矩阵制品与 resolveCompatibility、targetEvidence 生产者、Registry 首方 entry、persist/dispatch。

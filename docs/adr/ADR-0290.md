# ADR-0290 · T05 prepare 第一刀：受治理的首修订进入 runner 与真实出生修订语义

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：七项裁决与「同意」）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-session-prompt-prepare-step.md)
- 相关：[进入 revision 流裁决](../notes/proposed/architecture/2026-10-11-revision-entry-flow.md)、[ADR-0289](ADR-0289.md)、[ADR-0288](ADR-0288.md)

## 背景

真实 matter 过不了 persist：custody 出生即写 `revision:1`（actionPolicies 空、insufficient 证据；域注释明示「later revision declares what may run」）。七项裁决已定（proposed note）。实现中端到端尝试暴露关键排序事实：**context 在激活时绑定当时的既有 revision**；send 时 prepare 进入新 revision 后，链仍绑定旧 revisionRef → fail closed。send 时钩子无法单独完成「全新 matter」流。

## 决策

1. **D1 注册**：`session.prepare` 进 ACTION_AUTHORITY_TABLE：`{role:owner, scope:'session.prepare', effectClass:'local-write', requiresDecision:false}`——独立于 session.send 的 external-write grant 四元组。
2. **D2 runner 语义 = 确保 current revision 声明 send scope**：current revision 缺失或 policies 不含 send scope（含 custody 出生修订）→ 进入新 revision；已声明 → `not-needed`；matter 未知 → `not-needed`（链自行 fail closed）。守护按链序跑 caller→context→candidate→identity **同一前端端口实例**（context 激活绑定其 revision；本 runner 的重跑面随之更新）；外部效果面（target/compat/registry/preflight/dispatch）不触。
3. **D3 写入**：域 `enterEvidence` authored `revision-entered`；见证 = 用户显式输入（`source:'user-input'`，supported）；policies = requirement.actionRequirements 投影；明文边界/数据去向服务常量；revisionId/evidenceId 服务签发 `revision:sage.<uuid>` / `evidence:sage.<uuid>`；普通幂等 append（`appendId: session-prepare:<requestId>`），证据不随行（本地写不触外部效果评估）。
4. **D4 失败面**：四端口失败按态映射 `protected-effect-{unavailable|denied|stale}`；域拒绝 → `session-prepare-declined`；存储不可判 → unavailable。append 非 appended/replayed 一律 unavailable。
5. **D5 编排（本刀如实登记不完整）**：send 路由先跑 prepare 并尊重其拒绝（composition 钩子）。**但不声称完成全新 matter 流**：context 激活先于 send 且绑定既有 revision，prepare 后的新 revision 需要 context 重绑定——完整流属选择流前置 ensure（下一刀，含端到端）。端到端尝试的发现、推迟原因与预期形状写入 Note。
6. **D6 门禁**：prepare 事实组（注册 local-write、同前端端口与链序、见证、策略投影、拒绝族、域拒绝诚实、幂等 appendId、禁触外部效果面、路由先跑并尊重拒绝）＋八条具名突变；identity 装配 pin 随前端端口提升为常量同步。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| B/C 进入路径 | 否决（前次裁决，proposed note 已录）。 |
| 保留「无 revision 才 prepare」语义 | 否决：custody 出生修订（空 policies）恰恰是真实主用例。 |
| send 时静默重激活 context | 否决：context 激活是选择流治理面（CAS + read-authorization），不在 send handler 职权。 |
| 本批同刀改选择流 | 否决（范围）：选择流 ensure 需要自己的侦察与裁决（含完整端到端），独立成刀。 |
| runner 自建第二套前端端口 | 否决：双实现必漂移（ADR-0289 先例）。 |

## 后果

- `session.prepare` 第一刀落地：注册、仓库方法（`readMatter`/`appendRevision`）、受治理 runner（单元 4/4 夹证）、send 路由钩子（not-needed 路径由 step-10 端到端穿过证明）。
- 未闭（登记下一刀）：选择流前置 ensure（context 绑定新修订）+ 全新 matter 端到端；回合收口流（侦察报告已呈报，含 per-send vs per-revision 粒度裁决）；WT-02B.3、host-lifecycle、撤销运营、真实模型调用验收。

# ADR-0275 · 会话族真实 Identity 准入（T05 第一刀）

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：T05 按多刀推进，选定「会话族真实 Identity」为下一刀）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-session-family-identity-admission.md)
- 相关：[ADR-0174](ADR-0174.md)（Application Service 唯一编排入口与十步顺序）、[ADR-0250](ADR-0250.md)（session-family protected admission）、[ADR-0190](ADR-0190.md)（授权路径与动作表）、[ADR-0201](ADR-0201.md)（登记=让请求可评估，不是授权）、[ADR-0274](ADR-0274.md)（T04 托管）

## 背景

T05「首条真实消息」依赖「真实 runtime/Compatibility/Registry/Adapter authority」。会话族写路由在批次二/三已迁入 protected-effect 准入内核（十步：caller → context → candidate-match → identity-policy → target → compatibility → registry → preflight → persistence → dispatch），但生产只装配前三步——identity 之后全缺、dispatch 被 composition 没收，所有会话效果恒 `protected-effect-unavailable`。其中第 4 步 Identity/Policy 是当前**唯一可接真**的步骤（与命令管线共用的 authority runtime 已存在：vault 会话 + 实例组织策略文件）；且 `ACTION_AUTHORITY_TABLE` 只有 `start-attempt`/`create-matter` 两条，会话操作根本无法组装可评估请求。

## 决策

1. **D1 登记 `session.send`**：`role:owner` / `operation: session.send` / `actionScope: 'session.prompt'` / `effectClass: 'external-write'` / `requiresDecision: false`。登记的作用是让请求可评估（ADR-0201 D4 同一纪律），**不是授权**——真实放行仍取决于组织策略中的精确 grant。聊天继续是事项的基线工作，不做逐条决定门；后续策略代可以收紧，消费者不变。
2. **D2 装配共核**：新增 `assembleSessionCoreAuthorizationRequest`（按操作名查同一张表），既有 `assembleAuthorizationRequest` 改为调用该核心——两个入口一份表，不允许分裂。
3. **D3 唯一适配器 `src/main/session-core-identity.ts`**：操作名 → 表条目 → kernel 请求 → `runtime.resolve`。映射语义：**未登记操作在任何策略读取之前**答 `unavailable`（"该维度尚未声明"＝not-ready，绝不说成 policy denial）；无会话 / 策略不可读 / 无组织线索 → `unavailable`；resolution 非 authorized → `denied`；authorized → 不透明事实 `actorScopeRef`（actor 稳定：issuer+identityHandle+organization 的域分离哈希）与 `decisionRef`（逐次求值绑定：issuer 摘要、handle、组织、角色、操作、action policy、策略摘要、过期与求值时刻）。raw issuer/handle/organization 不出模块。
4. **D4 options-gated 接线**：装配点只在实例授权选项（`options.authority`）存在时合并该端口；缺席维持现状（端口缺席→第 4 步 unavailable）。登记只做 `session.send` **一条**：其余会话族操作保持现状，按各自票据逐条登记（"每条都要先说清在哪一步落、由谁落"）。
5. **D5 门禁登记源码事实**：gated merge、`session.send` 条目与 scope、未登记先于读取、非 authorized→denied、assembly+kernel resolve 齐备，附六条具名突变；route 计数与分类不变。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 维持全部未接 | 否决：第 4 步是唯一可接真的步骤，继续空置等于 T05 第一刀无处可落。 |
| 一次登记全部十七个会话族操作 | 否决：per-operation 的 scope/effectClass/requiresDecision 是策略判断；逐条登记是既有纪律，一次性批发会把未想清楚的策略值钉进表。 |
| 未登记操作答 `denied` | 否决：把"尚未声明"说成"策略拒绝"是假话（ADR-0201 D4 同族）。 |
| 同时接 target/compatibility/registry/persist/dispatch | 否决：中段 authority 的官方路径装配仍 pending（含 bridge-owned seam 等外部前提），且 dispatch 当前不可达——先接就是 P-04「写了但从没跑到」。 |
| 直连 Host prompt 绕过准入 | 否决：违反 WT-02D 唯一编排入口与 protected-effect 内核。 |

## 后果

- 生产会话族的拒答阶段：已登记操作（`session.send`）由 identity-policy 前移到 target；未登记操作保持停在 identity-policy。对外可观察码不变者仍是 `protected-effect-unavailable`，**新出现**的真实拒绝是 `protected-effect-denied`（grant 缺失/会话过期等），全链 prompt 零调用不变。
- 「任一 authority 缺失时 prompt provider 调用为零」第一次有真实咬合：grant 缺失＝具名 denied、未登记/无会话/策略缺失＝not-ready，dispatch 永不运行。
- identity 事实是不透明摘要；`actorScopeRef` 对 actor 稳定可作后续幂等命名空间输入，`decisionRef` 逐次求值新鲜，历史求值不构成 standing authority。
- 未闭：target/compatibility/registry/preflight/persist/dispatch 六步、其余会话族操作登记、真实登录链与真机首条消息；T05 不因本刀标记完成。

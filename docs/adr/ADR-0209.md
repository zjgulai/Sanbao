# ADR-0209 · 草案是本设备对象：加密落盘、登出即锁、确认才转换、缺项与重复都不放行

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证并实施；锁的强度与范围是取舍）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-draft-tracer-bullet.md)
- 相关：[ADR-0201](ADR-0201.md)（建项走托管侧）、[ADR-0190](ADR-0190.md)（授权步骤不放宽）、[ADR-0174](ADR-0174.md)（Application Service 唯一编排入口）

## 背景

工单 002 的剩余半边要求一条最窄端到端：**首页输入 → 草案整理 → 建项确认 → 列表出现事项**，且
草案与正式事项在后端是**不同对象**（US-003）。三条硬验收：AI 整理结果不自动写入交付/责任（US-010）、
未选前史不进正式上下文（US-004）、表单填完但未确认时不得显示为已建项。

既有事实（取证）：建项分支已是**托管侧动作**（ADR-0201：`create-matter` 在第 2 步后分叉，本地库绝不
append、绝不铸号）；`ACTION_AUTHORITY_TABLE` 已登记 `matter.create`；S1 路由 `/.sage/*` 恒由 main 终止。
缺的是：草案对象本身、确认 UI、以及"建项后列表可见"的投影。

## 决策

1. **D1 草案是本设备对象**：存在 Sage 数据根 `drafts/` 下，一草案一文件；**AES-256-GCM 落盘**，
   密钥是 32 字节设备密钥文件（0600，首次写入才创建）。读/写在**未登录时一律拒绝**（`locked`）——
   登出期间不列举、不解密、不写入；重登后同一设备可恢复（US-011）。
   **边界如实**：本切片不绑系统钥匙串，能读设备密钥文件的本地攻击者不在本切片的防护范围；
   界面与 ADR 都按这个口径说话，不暗示更强。
2. **D2 整理不写字段**：新建草案把输入作为**前史**保存，三个必填字段与项目一律留空；只有用户自己的
   `update` 能写字段（US-010）。确认入口在三条必填齐备前 `disabled`，且 **main 侧同样拒绝**
   （`draft-incomplete`）——界面不是唯一防线。
3. **D3 转换＝托管动作**：确认时由 **main** 用草案内容构造 `create-matter` intent（`matterId: draft:<id>`），
   经**同一条流水线**（身份→授权→创建分支）交给托管端口；成功只以**服务回执**为事实写入草案
   （`matterRef`），本地绝不铸号（US-002/003 + ADR-0201）。无托管方 → `persistence-unavailable`，
   草案保持未转换（US-007 的"不得显示为已建项"）。
4. **D4 单次转换**：`status: converted` 的草案再次确认在 main 就地拒绝（`draft-already-converted`），
   托管侧不会被二次调用（"重开不重复创建"）。
5. **D5 前史只带勾选的**：转换请求只包含已勾选片段（`attachedFragments`），未勾选的前史留在本地草案；
   请求里不含任何未选文本（US-004）。
6. **D6 不自动同步**：草案模块不引入任何网络依赖（判据里有一条结构性断言），也没有后台任务；
   界面明说"只保存在当前设备"。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 草案直接进本地 business-matter 库 | 否决：正式事项归托管（ADR-0201 / ADR-0005），本地库不是它的家。 |
| 明文 JSON 落盘 + 只做界面锁定 | 否决：明文与"安全保存"矛盾，且 gating 只停在渲染层。 |
| 绑 macOS 钥匙串存设备密钥 | 本切片不引系统交互依赖；如实登记为未闭（D1 的边界）。 |
| 由 renderer 组装 create-matter 载荷 | 否决：载荷内容属产品判断，必须由 main 从已确认的草案生成（US-004）。 |
| 确认按钮只做前端 disabled | 否决：main 侧必须同样拒绝缺项（fail closed，界面不是唯一防线）。 |

## 后果

- 002 的四条硬验收各有机器断言：字段不自动写（D2）、缺项不提交（D2/界面+main 两侧）、
  未选前史不带（D5）、未确认不显示已建项、重复确认不再调托管（D4）、锁定时不读不写（D1）、
  模块无网络依赖（D6）。
- 建项真链路只有一条：`/.sage/draft/convert` → 同一条流水线 → 托管端口；命令状态仍写进 001 的
  `command` 槽（分类口径不新增第二份）。
- 已知未闭：① 真机端到端未跑（不启动 Host，也没有真实托管方）；② 设备密钥未绑系统钥匙串；
  ③ "获准才恢复"里的**批准**一步属于权限治理线（007/008），本票只做登录门；④ 事项全量列表仍缺
  托管侧 list provider（本票只列"本设备已转换的草案及其回执"）。

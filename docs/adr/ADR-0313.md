# ADR-0313 · T07 会话控制批：授权等待、模型排队、计划步骤与队列（S03/S05/S06/S07）

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：继续执行 R14）＋ agent（并行侦察＋实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-session-control-batch.md)
- 相关：[ADR-0309](ADR-0309.md)（同形壳法）、侦察：R14 T07 understand workflow

## 背景

R14 = 113 行分级榜第 2 名「T07 会话控制批」。理解 workflow（三侦察线 + 边界合成）裁定：S03/S05/S06/S07 可迁（五台机器已在 main）；S04 推迟（组真身是 base 原生 plan 工具卡，壳内零事实可读——迁移即伪造组覆盖）；两处 admission rework（approvals 写路径注册、/.sage/plans 重分类）各自独立成批，本批不顺手改。

## 决策

1. **D1 解析前提与面板同提交（硬前提）**：`parseDesktopSession` 与 `desktop/client` 之外的白名单解析扩进 `sessionApprovals/modelQueue/plans` 与 `channel.pending/queue`——每槽宽容解析（缺省 null / 空表）、面板只渲染事实；解析与面板不可分提交（防静默丢弃假绿）。
2. **D2 S03 授权等待卡**：pending 卡（toolName/reason/raisedAt）；「允许一次/拒绝/撤回等待（withdrawable 时）」post 真实既有 route（body 精确 {matterRef, requestId, outcome}/{matterRef, requestId}）；**protected-effect-unavailable 专用文案**（硬前提：「授权应答尚未接通（接线完成前不会记录任何决定）」）；其余码通用句式。写路径 admission rework 不在本批（route 今日恒 unavailable 即 compliant）。
3. **D3 S05 模型排队卡**：verdict 五态标签（waiting/retrying/ready/unknown；idle 无卡）；重试行显示服务计划延迟为**事实**（不倒数）；verifyOnly/unknown 提供「核对」= 仅 /.sage/state 重读。queued/retrying/ready 自然出现验证，electronAcceptance 保持 pending。
4. **D4 S06 薄切片**：turn/end `blocked` 具名标签「被阻断结束」；MonitorPage 计划步骤 roster（就绪/未就绪（阻断——不派发）/未知（阻断——不派发）+ readinessNote），只读、零 plans action；逐步骤详情无事件源——不装、不造假。
5. **D5 S07 待继续与队列**：channel.pending/queue occurrences 渲染（consumed 冻结只读 honored）；编辑/移除 post 精确 {action, itemId[, text]}（无 matterRef——作用域服务端绑定）；removal 走既有 compliant route。
6. **D6 迁移**：S03/S05/S06/S07 四伞行迁 `ui` `pending→implementing`（evidenceRefs = desktop-session / desktop-session-view 两既有 spec 并集，`countsAsVerification:false`）；`applicationService` 保持 blocked——四族 route 虽登记 compliant，但均为 unavailable-first（写入未生效），沿用 O02/P01 伞行先例不虚升；S04 保持 pending 并改写 blocker（原生卡事实源与 admission rework 依赖具名）。summary 生成器重算（98→102 implementing）。
7. **D7 对抗评审（本批内）**：提交前 4 透镜对抗评审（26 审 → 8 确认 + 完备性批评 3，0 反驳）确认缺陷全部修复、各配真实用例：控制项结果静默（拒绝具名 + 每次应答重读权威面 + 空白草稿本地拒绝）、plans 不可读冒充「无计划」与草稿混入已接受 roster（改：不可读具名 + 草稿计数不判读）、授权 receipt `unknown` 冒充已记录、服务计划延迟被取整（500ms 显示 1s）、队列 positions 被硬编可编辑（仅 `queued` 可编辑，其余具名锁定）、队列快照不可用坍缩为空、display-only 消费者无面板。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 本批兼做 approvals 写路径 admission 注册 | 否决（侦察裁定）：把 identity-policy 语义从恒 unavailable 翻成 denied/allowed 两态——行为变化需独立 ADR/Note。 |
| 本批消 /.sage/plans violation | 否决：policyProfile 重分类 + 三 action 迁 admission 属 main 侧批；本批切片零 plans action，violation 不被放大。 |
| steer 暴露给 composer | 否决：产品决策（基座语义为步骤边界插入非打断），需独立 ADR；维持 mode:'queue'。 |
| 逐步骤详情/阻塞 | 否决：无事件源，制造字段即伪造。 |

## 后果

- 会话页获得四台机器的真实读数面（授权等待/排队/步骤/队列）；矩阵 98→102 implementing。
- 余量：S04（原生卡事实源）、S03 升级为 PermissionCard（可选展示改造）、approvals 注册批、plans admission 批——全部具名登记。

# ADR-0331 · 候选列举的空路径翻译：'' = 根，绝对根才过 base 的列举契约

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（授权修复实测问题）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-root-listing-translation.md)
- 相关：[ADR-0205](ADR-0205.md)（base 拒绝词表映射）、Ticket 013

## 背景

v12 走查步骤 12（工作区文件菜单）：`path:''`（根列举）→ bridge `workspaceFiles/list` → base 拒 `gateway/bad-request` → shell 分类为 `bridge-search-query-rejected` → 面板「读取候选时出错」。子路径列举（如 `packaging-sage`）完全正常。

对齐两侧契约后确认：shell 的候选守卫**有意放行 '' 表根**（注释明示），但 base 的列举契约（dsh-api-workspace-files README）**明文拒绝空路径**，其官方客户端以**绝对根路径**列根（输出侧 `path:''` 表根）。'' 从未是 base 输入侧的合法写法。

## 决策

1. **D1 单点翻译**：`createFileCandidates` 将 `path === ''` 翻译为 `workspaceRoot`（绝对根）再上桥；非空路径规则不变（`isWorkspaceRelativePath` 守卫原样）。
2. **D2 语义不变**：调用方（renderer 路径框、引用流）继续以 '' 表根；翻译只发生在 shell 边界，不出现在 renderer 或 base。
3. **D3 验证**：装版实测——'' → `state:'read'` + 真实候选行（AGENTS.md 等）；spec 断言桥载荷为绝对根。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 改 renderer 初始 path 为绝对根 | 否决：把 base 的寻址语法泄漏进 renderer；且引用/相对语义仍以 '' 为根。 |
| 让 base 接受 '' | 否决：base 契约为既有外部事实，不宜为单调用方改。 |
| 根走独立端点 | 否决：同一操作一条路径，不新增面。 |

## 后果

- 步骤 12 候选面（根与子目录）可用；AGENTS.md 类真实候选可被引用流消费。
- 空路径的根语义只在 shell 边界翻译一次。

# ADR-0278 · 首个 session.prompt target 发布件：owner 裁决落地（策略文档 + 首发发布计划）

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：两项裁决——模型面严格精确钉、策略文档按最小声明发布）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-first-session-prompt-publication.md)
- 相关：[ADR-0276](ADR-0276.md)（候选线与发布流程）、[ADR-0277](ADR-0277.md)（C2D.2A 空快照）、[ADR-0172](ADR-0172.md)（target 治理）、[ADR-0171](ADR-0171.md)（Registry 治理）

## 背景

ADR-0276 把首发 target 的发布流程与候选线定死，并交付 owner 数据裁决清单；其中两项需要产品裁决：(1) 模型面语义——requirement 的模型组件按 schema 只能精确钉（无 range/wildcard），而模型同时是用户设置项，钉死意味着模型面变化即矩阵键事件；(2) permission / data-boundary 策略摘要必须指向真实的 canonical 文档，而仓内尚无该文档形态。用户裁决：模型面**严格精确钉**（发布时重观测）；策略文档**按最小声明发布**。

## 决策

1. **D1 模型面严格精确钉**：首个 requirement 的 provider/model/agent/preset 与 capabilities 逐字段取自**发布时重观测**的 descriptor；任何模型或行为配置变化都使 `targetSemanticDigest` 与稳定对移动——矩阵失配、fail closed，必须重新发布后才能继续 session.prompt。schema 无 range 语义，这是唯一诚实的表达。
2. **D2 策略文档 canonical 化**：新形态 `sage.target-policy-document.v1`（固定键序 canonical JSON；digest 命名空间 `urn:sage:target-policy-document:v1:`）。首发两份，逐字采用裁决声明：`permission:sage.session-prompt`=「实例操作员（role:owner）可发起 session.prompt。」；`data-boundary:sage.model-egress`=「消息文本可发送至用户配置的模型提供方；产物与记录留存本机 Sage 数据根。」。文档版本 `1.0.0`，未来措辞演进=新版本+新摘要（旧 requirement 不变）。
3. **D3 首发发布计划固定**：`requirement:sage-session-prompt` / `1.0.0` / 有效 `2026-10-11T00:00:00Z`–`2027-10-11T00:00:00Z`；actionRequirements 仅 `session.prompt`（external-write / 无决定门，与 action 表一致）；决策三元 `decision:sage-t05-first-session-prompt` / `owner:sage-product` / `2026-10-10T09:00:00Z`（≤ effectiveAt，内核咬住）；提议矩阵规则 `rule:sage-session-prompt-v1`。
4. **D4 组合路径唯一**：`buildSessionPromptPublication(descriptor)` 组合——策略文档引用 → 候选线（组件逐字段复制、策略清单摘要、descriptor 补三策略摘要）→ `sealCandidateTargetRequirement`（C2.2T 内核为唯一校验门）。descriptor 是**输入**（发布必须重观测，ADR-0276 D3）；本批不跑真实观测、不落 bundle、不接端口。
5. **D5 门禁登记 owner 内容事实**：两条声明逐字、requirement 标识与版本、action 元组、决策三元、封存路径齐备，附五条具名突变；route 计数不变。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 模型面用范围/通配表达 | 否决：schema 无 range；且精确钉是治理链的既有纪律。 |
| 策略摘要用任意常量占位 | 否决：摘要必须指向真实 canonical 文档（否则「批准的是什么」不可审计——D2 正是为了消除这一点）。 |
| 策略声明写成英文/泛化措辞 | 否决：裁决声明是产品事实，逐字入文档；措辞变化走版本演进。 |
| 本批直接跑重观测并落 bundle | 收窄：真实观测（物化+Host+组合读）与 bundle/端口接线是独立一步，本批只固定发布件与其内容。 |
| 决策时刻用运行时读钟 | 否决：发布必须确定性、可复现；内核同时强制 decision ≤ effectiveAt。 |

## 后果

- 首发发布件的内容 100% 由裁决决定且可审计：两条声明逐字、计划常量、决策三元、严格模型面；组合路径（候选→内核封存）被测试端到端咬住（fixture descriptor）。
- 真实侧下一步=重观测（隔离/Dev 根跑 E 线组合读）→ 以真实 descriptor 调用 `buildSessionPromptPublication` → 落 bundle（发布票）→ 接 `resolveTarget`/`resolveCompatibility` 端口；模型面挪动即需重发布的运维语义已被测试证明（摘要移动）。
- 未闭：真实重观测与 bundle、端口接线、Registry entry（session.prompt 的 approved entry 仍缺——step 7 将在空集下 unavailable）、persist/dispatch、真实登录与真机首条消息；T05 不因本刀标记完成。

# ADR-0305 · 弹层族第一刀：账号菜单快捷外观子菜单

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：同意 Loop-Q R7）＋ agent（盘点与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-quick-appearance.md)
- 相关：[ADR-0283](ADR-0283.md)（theme/text-size/ui-scale 三行 N/A）、[ADR-0257](ADR-0257.md)（偏好投影）

## 背景

Loop-Q R7 转入弹层族（O 族 26 行 pending）。盘点：O08 MCP 表单 12 行（提交面依赖 T10 治理链）、OBS02 知识 13 行 + OBS03 站点（存储 provider 未接通）、O01–O14 伞行多为待核验登记。可立即装配且数据源齐全者：**OBS04 快捷外观 8 行**——其中 `theme/text-size/ui-scale` 三行已有 N/A 裁决（ADR-0283，本刀不动其 applicability），余 5 行（menu.open + color-mode + language + font-style + content-width）映射到已存在的 device-preferences controller（与设置页同源值域：theme=颜色模式 system/light/dark、language、fontStyle、contentWidth）。

## 决策

1. **D1 子菜单装配**：账号菜单新增「外观」子菜单（`aria-haspopup=menu` 展开/收起）；四项 = 明暗模式（theme）/语言/字体风格/内容宽度，均以 `select` 渲染（点击展开系统原生菜单——与行观察「原生菜单」同形）。选项值取 `DEVICE_PREFERENCE_OPTIONS`（既有单一来源）。
2. **D2 数据与保存**：读取 `preferences.snapshot()` 并订阅（设置页同模式）；变更即 `preferences.save({key})`——唯一权威仍是 device-preferences 路由；不可读时示「偏好不可读（code）」而非臆造值；保存中禁用。
3. **D3 不复制设置页控件逻辑**：仅复用 controller 与选项表；不一致的控件（原生 popper）不另造。
4. **D4**：5 行迁 `ui` `pending→implementing`（tracked-test ref，`countsAsVerification:false`）；`theme/text-size/ui-scale` 三行保持 N/A 不动；blocker 登记视觉验收与「原生菜单=应用内 select 菜单」。summary 生成器重算（30→35 implementing、168→163 pending）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 本刀做 O08 MCP 表单 12 行 | 留后：提交面需先定 T10 治理语义（表单可填、提交 fail closed 的合同要单独立）。 |
| 自绘下拉菜单复刻 Qoder popper | 否决：select 即系统原生菜单，无自绘必要。 |
| 把外观子菜单做成跳设置页 | 否决：行断言是菜单内直接展开（现状「跳设置页」另有行且已 implementing）。 |

## 后果

- 账号菜单具备快捷外观四项（与设置页同权威）；OBS04 可得面收口。
- 弹层族余量：O08 12 行（表单刀）、OBS02/03（存储刀）、伞行（核验刀）。

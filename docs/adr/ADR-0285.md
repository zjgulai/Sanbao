# ADR-0285 · 首方 Registry entry 与能力发布面：first-party provenance 类、7 键 capability 载体、首个非空快照与重发链

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：裁决 ADR-0283 D4 自证等价路线；指示继续下一批）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-first-party-registry-and-republish.md)
- 相关：[ADR-0283](ADR-0283.md)（D4 路线裁决）、[ADR-0171](ADR-0171.md)（Registry 治理）、[ADR-0277](ADR-0277.md)（C2D.2A 空快照）、[ADR-0284](ADR-0284.md)（矩阵发布）、[ADR-0276](ADR-0276.md)（重观测即重发）

## 背景

ADR-0283 D4 裁决 session.prompt 的 approved entry 走**自证等价**路线（provenance = C2A 运行时制品 attestation + 发布决策 + owner 审批，明确不宣称 C2C.5）。落地侦察发现三处结构性障碍：① C2D kernel 的 approved 路径硬性要求 `source:'c2c5'`（capability-registry.ts:398）与运行时收录过滤器同款（runtime-inventory-provider.ts:376-380），first-party 无法通过；② C2.2T requirement 的 capability 载体是恰好 5 键，而 semantic/descriptor 的 capability 面是 7 键（多 registryDescriptorDigest/adapterMappingDigest），真实能力一旦存在，requirement 与 semantic 永远配不成对；③ 非空 approved 条目必然改变 `runtimeDescriptorDigest`（capabilities 在 canonical body 内，已用真实 golden 复现空集摘要逐字相等），矩阵与全部下游 golden 需按「重观测即重发」重锚。

## 决策

1. **D1 first-party provenance 类**：`CapabilityRegistryDescriptorRefV1.source` 扩为 `'candidate' | 'c2c5' | 'first-party'`；`verification` 词表不变（`verified` 的含义由 source 判定的验证路径消歧——c2c5 = 外部 provider seam；first-party = Sage 自有组合：C2A 制品 attestation + 发布决策）。**digest 命名空间按 source 条件化且不可互换**：first-party 的 descriptorDigest = `urn:sage:runtime-descriptor:sha256:…`（批准时观测的运行时描述子）、artifactSubject/launch/tool = `sha256:…` 内容摘要、evidenceDigest = `urn:sage:first-party-capability-evidence:sha256:…`；运行时收录过滤器同步接受 first-party+verified。跨 source 混用命名空间一律拒收。
2. **D2 capability 载体 5→7**：`CompatibilityTargetRequirementBodyV1.capabilities` 改用 `CompatibilityTargetCapabilityRequirementV1`（共享五键 + registryDescriptorDigest + adapterMappingDigest）。**空 capability 列表的规范化字节不变**——旧摘要稳定（已实证：空 caps 的 canonical 与既有发布一致）；候选线复制与 semantic 重建同步改 7 键，重建的 fail-closed 分支（对非空 caps）随之删除——能力现在是可发布的。
3. **D3 首个 registry 快照（字节即裁决）**：`publications/session-prompt.capability-registry.json`，snapshotId `f2df5963…`，单一 approved 条目：`capability:sage.session-prompt` v1.0.0；descriptor = {运行时描述子 `e1c7a8b4…`(批准时观测)、artifactSubject = C2A `89b0d1ef…`、launch = `f6367b27…`、tool = `77012eaf…`、source first-party、verification verified}；operations = [session.send → adapter `adapter:sage.session-channel` 1.0.0（digest 域分隔）、external-write、dataBoundary `sage.model-egress`、输入/输出 contract 摘要为声明的域分隔常量]；approval = `decision:sage.first-party-registry-session-prompt` / `owner:sage.product` / 2026-10-10T09:00:00.000Z；**effectiveAt = 决策时刻**（10-10T09:00Z）——若对齐 requirement 的 10-11 生效窗，descriptor 的 capabilities 会随生效边界二次移动、矩阵右半不稳；expiresAt 2027-10-11。加载面沿用发布件 loader 模式：内核 parse + **重封回同 snapshotId** 证明后才可取代 bundled 空集默认（常量保持空集不变——非空只经已发布快照到达）。
4. **D4 重发链（重观测即重发，ADR-0276 D3 执行）**：`inventory-probe` 与生产 index 同款装载已发布 registry → 隔离根重观测 → 新稳定对：descriptor `208b273e…` × semantic `a9a0feb0…`；requirement v2（snapshotId `1b398a37…`，`supersedesSnapshotId=521b87ac…`，requirementDigest `a00e6303…`）与矩阵 v2（matrixId `304c124f…`，bundleId `b2967eb3…`，撤销源内容不变）同批重封；golden 与 spec 常量按重锚驱动更新。
5. **D5 门禁**：route-authority 的 registry 事实组更新（index 必须经 loader 装载并把 body 交给同一工厂；loader 必须内核 parse + 钉重封一致性）+ 两条自测突变；不变的钉子（provider 常量为空集、kernel 封存、fail-closed read）保持。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 用 c2c5 source 承载自证等价 | 否决：冒充外部验证语义（ADR-0283 D4 明禁），且命名空间检查会诚实拒绝。 |
| 新建平行「first-party registry」结构 | 否决：两套 registry = 两个事实家；四态与 owner 审批治理应唯一。 |
| capability 载体保持 5 键、semantic 侧裁剪 registry/adapter 摘要 | 否决：semantic 与 descriptor 的 capability 面不同构，「稳定对」不再表达同一事实。 |
| 条目 effectiveAt 对齐 10-11 | 否决：descriptor digest 随生效边界二次移动，矩阵发布在他日失配。 |
| 先发 registry、矩阵暂留旧对 | 否决：运行时 10-11 起 no-matching-rule，链路静默变 unavailable——必须同批重发。 |

## 后果

- 首个真实 non-empty approved Registry 条目进入产品链；「candidate → 审批 → 发布快照 → 运行时收录」全链真实执行；`RuntimeDescriptorV2.capabilities` 首次承载真实能力（registryDescriptorDigest 恰绑定批准时观测描述子——自引用被该设计天然避免）。
- 全部 capability 相关发布件与 golden 重锚到 v2 稳定对；空 caps 的规范字节不变使无能力面（provider/model/agent/preset/策略）的旧记录仍可解释。
- 未闭：resolveRegistry 端口接线（本批只到发布与收录；准入第 7 步仍 absent）、Adapter 真实动作、撤销管理真实化、preflight/persist/dispatch。

# ADR-0270 · 设备偏好独立 GET、权威回读与默认桌面设置主链

- 状态：accepted（2026-10-05）
- 日期：2026-10-05
- 决策者：用户（明确确认 `GET /.sage/device-preferences`）＋ Codex（准入与回读合同）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-05-device-preferences-read.md)
- 相关：[ADR-0266](ADR-0266.md)、[ADR-0258](ADR-0258.md)、[Sanbao 集成票据 T13](../plans/2026-10-05-sanbao-in-sage-integration-tickets.md#task-t13)

## 背景

`/.sage/bootstrap` 只负责 runtime/auth 与启动必需的 theme/density，不能承担完整设置页的设备偏好读取。既有 `POST /.sage/preferences` 能保存八项偏好，但默认 Sanbao 桌面没有独立的权威 GET、没有设置表单主链，也没有机制保证 POST 失败、超时或拒绝后不会在 renderer 乐观显示“已保存”。

## 决策

1. 新增 `GET /.sage/device-preferences`，分类为 `local-system`。它不需要 matter/session，但必须经过 verified caller、ready/uncontaminated frame、读前后同一 frame generation 与读中 identity status 不变；任一条件失败统一返回 `device-preferences-unavailable`。
2. 成功 DTO 严格只有 `requested` 八项、`savedAt` 与 `effectiveTheme`。八项枚举、两层 exact keys、canonical ISO `savedAt` 均由 main 验证；姓名、凭据、session、workspace、business object、`systemDark` 与 `applies` 不得进入响应。
3. GET runner 只读 main-owned sealed preference projection，不能调用 `preferencesSave` 或任何 mutation port。signed-out 仍允许读取本设备显示偏好；身份变化中的 torn read 被丢弃。
4. 默认桌面在 root mount 时读取，而不是等用户打开设置页。renderer 只从成功 GET 设置 `data-sage-theme-requested`、`data-sage-theme-effective` 与 `data-sage-density`；不可用时三项均为 `unknown`。
5. 设置页用八个原生 `<select>`。保存固定为 POST 后再次 GET：无论 POST saved、refused、错误或 timeout，都只采用随后权威 GET；不从 POST receipt 或本地 draft 乐观更新 root/form。并发重复保存合并为一个进行中操作。
6. 当前 theme/density 在权威回读后 live apply；其余六项只持久化并在 UI 明示“尚未接入产品显示”，不能用保存成功冒充功能已应用。
7. route authority 分母更新为 60、local-system 更新为 2。bootstrap 与 device-preferences 各有独立 source proof；exact GET/read/provider 与 mutation-negative tests 防止两边协调漂移后形成假绿。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 扩大 bootstrap 为完整设置 DTO | 否决；启动最小事实与设置读取生命周期不同，会扩大每次启动投影。 |
| 只用 POST receipt 更新设置页 | 否决；receipt 不能证明持久化文件可回读，也无法处理拒绝、超时和并发漂移。 |
| renderer 直接读本地文件 | 否决；会产生第二事实 owner，并绕过 main-owned admission 与设备封存。 |
| 八项全部立即应用 | 否决；只有 theme/density 已有产品 token/runtime 合同，其余六项没有消费面。 |

## 后果

- 设置页现在有真实前后端读取/保存/回读链，signed-out 也可安全读取设备显示偏好。
- route/global gate 必须维护 60-route 事实；删除 runner、放宽 DTO、引入 mutation、改成 POST 或偷换 provider 都会具名失败。
- 本决策只完成 T13-A 的最小设置主链；模型、Runtime、Agent、MCP、语音、通知、快捷键、更新等设置仍按各自 authority/owner ticket 推进。
- 本切片不把任何 Sanbao 矩阵行自动标为 integrated；真实 Electron 检查是当次 runtime 证据，不替代五维 tracked acceptance。

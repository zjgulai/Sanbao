## 背景

018 未闭项「pi-ai 段表单」：基座事实链（全部按源码核验）——

1. 已装 pi-ai 目录含 41 个 provider（`getBuiltinProviders()`）；`llm-pi-ai` 明文：**route key 命中已装 provider 时，该 provider 的端点、协议、显示名与模型目录即 profile 的默认值，profile 逐字段覆盖**（`config.ts` 头注释）；不命中时 profile 才是全量声明。⇒「仅 Key」目录路由在基座是合法完整形态（`{apiKeyEnv}` = 一份可服务 profile），经写入校验 `assertServiceable` 放行。
2. `llm.listConfigurableProviders()`（@Remote 读）给出目录全集：**目录条目 `declared: false`，手写声明 `declared: true`**，带 `error` 诊断——渲染端/宿主都不需要硬编码 41 个名字。
3. `discoverModels` 对目录 provider **短路为离线目录回答**（`discovery.ts`）——不是网络探测；在目录路由上标「测试通过」会是假绿。
4. 现状四处缺口：桥文法强制 api+baseURL+models（仅 Key 存不进）；端口列表读跳过无 baseURL 行（存了也不显示）；无目录读接缝；test 对无 baseURL 路由无路可走。

## 决策

1. **D1 目录读进桥**：新桥读 `modelConfig/providers` → `llm.listConfigurableProviders()` 防御映射（`{provider, displayName, declared, error?}`）；再加 `modelConfig/models`（单路由活物化模型表，`llm.listModels`）。两枚都是纯读、零网络（协议表 +2 read）。渲染端**菜单打开时懒读**（挂载不取——选择器先例）。
2. **D2 文法扩目录形态**：profile 键 ⊆ `{displayName, apiKeyEnv}`（无 api/baseURL/models）为「目录形态」；成员资格由**宿主**查目录裁定（`declared === false` 才放行；未知名/手写声明名具名拒 `bridge-model-catalog-unknown`；目录读不可用即拒不放猜）。全量声明不看目录（回归零）。路由端文法与宿主文法同形；`assertServiceable` 是第二道保险（绕过宿主的手写 profile 也会被 settings 写入校验拒）。
3. **D3 test 对目录路由的裁决 = `builtin`**：不调 discoverModels（离线回答=假绿），改读 `llm.listModels(route)`（活物化模型 id），返回 `{state:'builtin', modelIds, revision, credentialConfigured}`；渲染标签「内置目录（N 个模型）· 未做网络探测」。路由未注册（listModels 抛）→ 具名拒。
4. **D4 列表/编辑/端口/契约**：目录行 `catalog: true`、`api/baseURL = null`；模型数从 `modelConfig/models` **活读**（profile 里没有 models）；编辑=仅 Key（路由身份锁定、留空保留现有凭据——A1 语义）；菜单新增「本机内置目录」分组（Sage 自建面，仅列 `declared === false` 条目，带组名标注）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 观测 17 项菜单条目激活目录形态（如 DeepSeek 条目） | 否决：观测语义（Qoder 网关：类型/模型清单）与目录语义（api.deepseek.com）不可分辨；且会改写已被 R17-B spec 钉住的复刻结构。 |
| 观测菜单名 → 目录 id 猜测映射（Kimi→moonshotai/kimi-coding、智谱→zai/zai-coding-cn 等） | 否决：二义/三义，映射臆造；两套词汇表的对照需要独立证据（独立票）。 |
| 目录路由「测试连接」走 discoverModels | 否决：目录 provider 短路离线回答=假绿，不触网却报「测试通过」。 |
| 目录行模型数在保存时固化进 profile | 否决：`{apiKeyEnv}` 形态无 models 字段；目录随版本更新，唯独活读诚实。 |
| 目录路由完整声明强制（沿用现文法） | 否决：等于对 41 个目录 provider 全部关掉「仅 Key」直达能力，A2 名义目标落空。 |
| 宿主不做目录校验、只靠 `assertServiceable` 拒 | 否决：错误码退化为泛化 `settings/rejected`；「该名称不在目录」需要具名，与 A1 具名拒语义一致。 |

## 后果

- 41 个目录 provider 一键接入（仅 Key）；发送路径零改动（目录路由自动入围 ADR-0340 的目录/默认/选择器面）。
- gate 面无新路由（action 扩展不触 route registry）；协议表 +2 read 端点；服务消费登记（服务级）无需变。
- 018 未闭项剩：D7 inventory overlayPolicyDigest。矩阵：A2 目录组与 composer 选择器同为 **Sage 自建面**（非 Sanbao 观测元素），不新增矩阵行，欠项记录在案。
- 观测菜单 17 项与目录 41 项的对照映射：独立待证项（本批不做猜映射）。

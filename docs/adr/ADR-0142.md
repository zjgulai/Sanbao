# ADR-0142 · 岗位名片版式与官方预览角标移除：版面层也是换皮的一层

- 状态：accepted（2026-09-20）
- 决策者：用户（lute）+ Sanbao 全维度换皮轮
- 取代：ADR-0019 D2（官方角标「保持节点、改写成 `Preview`」→ 本轮改为整节点隐藏）
- 相关：ADR-0135（判据读真实值、token 单一源）、ADR-0136（D4 字形分工）、ADR-0125 D7（入口契约）、总账 P-07

## 背景

三宝换皮把资产层（50 张双色道头像）与渲染面（`object-fit: cover`、圆形槽）做完之后，
用户在真机上给出的反馈暴露了一个排期上的合并错误：**换皮计划把「资产 / 渲染面 / 版面」当成一层**，
实际是三层。资产与渲染面落地了，版面还停在换皮之前——旧卡是「34px 圆头像 + 姓名/岗位 +
一排徽标 + 标准产物行」，头像在卡里只是个小图标，**读不出「一个人」**。

三条用户原话各自对应一处版面事实：

1. 「把对话框上方的 `Preview` 字样去掉」——官方 `hero.preview` 角标。ADR-0019 D2 当年的处置是
   「保持官方节点与外观、只把文本 `预览版 → Preview`」，那是为「一个叫 Preview 的产品」服务的。
2. 「字号的大小跟实际页面完全不搭，而且字号的层级关系也需要在这次做深度调整」——面板里
   11/12/13/14px 四种字号摊在五类信息上，层级不可辨；实际页面正文是 13–14px，面板通篇小一档。
3. 「头像太小……要像我们的名片风格一样：左上角是头像、下方是工号，右边是岗位职责简介，
   文字不能太多」「整个卡片框的宽度需要调大，一行就排 3 个名片」。

## 决策

**D1 官方预览角标整节点隐藏，不再改写文本；它同时继续充当定位官方标题的锚。**
`hero-title.ts` 的隐藏器接管角标：`display: none` + `dsh-rb-hidden` 标记，文本原样不动，
卸载时还原。`official-text.ts`（文本改写 + 独立 `MutationObserver`）删除；两个角标文案常量迁到
`hero-title.ts` 作为「不是标题」的排除表。角标是**被正向识别**的节点，因此当标题候选出现歧义
（`no-candidate` / `ambiguous`）时**角标照旧隐藏**，只有标题保持不动。**本条取代 ADR-0019 D2。**

**D2 卡片改为名片版式：左栏头像 + 工号，右栏姓名 / 岗位 / 两行职责。**
左栏 `.cardId` = 96px 圆角方形（14px）头像槽 + 居中工号（mono）；右栏 `.cardBody` =
姓名 16/500 · 岗位 13 · 一句话职责 12（`-webkit-line-clamp: 2`）· 徽标行。
`标准产物` 从名片正文移入展开详情（信息不丢，只是不挤在名片上）。

**D3 栅格按可用宽度定列数，下限 340px；面板上限 `min(1200px, 94vw)`。**
标准桌面窗口一行 **3 张**（1440px 视口实测 3 列 × 376px）；更窄时同一条规则降 2 列、1 列，
**降列不降字号**——把头像与文字一起压小才是要避免的那件事。不写 `@media` 列数断点。

**D4 五级字号阶梯，全部走 `--dsw-font-*`。**

| 层 | 取值 | 归属 |
|---|---|---|
| L1 | 20/500 `--dsw-font-l-20` | 面板标题 |
| L2 | 16/500 `--dsw-font-base-strong-16` | 平面名 · 名片姓名 |
| L3 | 13/500 `--dsw-font-xs-strong-13` / 13 `--dsw-font-xs-13` | 责任域名 · 详情标签 / 名片岗位 · 搜索 · 详情正文 |
| L4 | 12 `--dsw-font-xxs-12` | 职责简介 · 平面用途 · 计数 pill · chip · 页脚 |
| L5 | 11 `--dsw-font-xxxs-11` | 工号 · 卡片徽标 |

**D5 一句话职责由 `description` 纯函数派生：只删除，不改写。**
`card-brief.ts` 去掉前导【平面·域】、结尾〔…〕、第一个圆括号之后的补充说明与残留标点；
**删空则原样返回**（宁可长，不要空）。长度上限交给 CSS 两行截断。
完整 `description` 在展开详情里以 `官方描述` 标签逐字呈现。

## 备选方案

| 决断点 | 未采用 | 为什么 |
|---|---|---|
| 角标 | 保留节点只换文案（ADR-0019 D2 原路线） | 角标陈述的是官方产品的发布状态，本产品不处在该状态；用户裁决去掉 |
| 角标 | 只清空文本、留空 pill | 留下一个谁都说不出用途的空壳 |
| 角标 | 角标与标题同进退（歧义时都不隐藏） | 角标是被正向识别的节点；歧义针对的是「谁是标题」，两者不该互相牵连 |
| 名片 | 圆形 96px 头像 | 圆是「头像」的语言，圆角方形是「名片/工牌」的语言 |
| 栅格 | `@media` 断点写死 1/2/3 列 | 断点要猜窗口宽度；`minmax(340px,1fr)` 让可用宽度自己决定列数，判据只需钉一个下限 |
| 职责 | 宿主 `collect.ts` 里算好 `brief` 字段 | 这是显示投影不是数据事实；动宿主会波及路由/校验/manifest 形状，而 50 个 preset 的零扰动是上一轮的契约 |
| 职责 | 按字数硬截断成新句子 | 截断出来的是「另一句话」，读者分不清是被截了还是原文如此 |
| 字号 | 直接写 px | 规则一律走 `--dsw-font-*`（ADR-0135 D1），断言读解析后的真实值 |

## 后果

- **正面**：一张名片一眼读成「一个人」（脸 + 工号 + 岗位 + 一句职责）；名片宽 297 → 376px，
  同一屏扫到的信息量翻倍；字号从「四档挤在 11–14px」变成五档可辨；盘上少一个模块
  （`official-text.ts` 删除，文本改写观察器不再是第二套机制）。
- **负面 / 已知边界**：
  1. **隐藏角标等于本产品不再披露「上游处于预览版」**。这是用户裁决；登记在此，
     以免后来者误以为官方没有这个角标。
  2. 三列是**可用宽度的函数**：面板宽度 < 1092px（≈ 视口 < 1162px）时降两列。
  3. 展开详情会把该行撑高（grid 行高由最高单元格决定），邻卡留白——既有行为，本轮未处理。
  4. `cardBrief` 的删除规则依赖 description 的既有形状（50/50 实测同形），上游换写法时会
     原样返回整句。该边界当天由门禁 `role-brief-shape` 收口（口径与读数见下条 Note），
     不再是「没人盯着」的已知边界。
  5. 官方设置页的预设卡（同一批头像的官方渲染面）仍是圆形头像 + 官方排版，与本面板不一致——
     「官方面不在本仓射程」的既有残留。
- **验证**：见 [Note](../notes/implemented/surface/2026-09-20-role-card-business-card-and-preview-badge.md)
  （重启后 runId `5cc8220c-…`、`rendererStatus=healthy`；首行 3 张、卡宽 376px、头像槽 96×96/14px、
  角标 `display:none` 且可见文本 0 条、明暗两主题各 50/50 张已解码、页面错误 0）。

# ADR-0335 · profile 启动自愈：五类 kill 窗口收敛，electron 子树 admission

- 状态：accepted（2026-10-13）
- 日期：2026-10-13
- 决策者：用户（2026-10-13「制定下一批计划」授权；ADR-0332 具名后续票）＋ agent（装配设计）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-13-profile-boot-reconcile.md)
- 相关：[ADR-0332](ADR-0332.md)（升级事务与其文档化 kill 窗口）、[ADR-0324](ADR-0324.md)（启动链先例）

## 背景

ADR-0332 的 profile 换位事务有 kill 窗口（`finally` 不跑 → 残留/缺失态），审计确认：**零启动修复、零 GC**。五类状态中三类致命：

1. 同 id 两次 rename 之间被 kill：指针仍旧、代际目录缺失 → `readActiveProfile` 裸 ENOENT → 启动失败退出，只能人工恢复。
2. fresh 装机改名后、指针写入前被 kill：代际目录在、无指针 → pristine 门拒装（且安装已启动，electron/** 必有 Chromium 文件，**清理后门仍拒**）。
3. new-id 改名后、指针写入前被 kill：旧指针可启动，但重试升级永久撞 `refusing … generation already exists`（永久卡旧版）。

另两类为洁癖问题：提交后残留的 displaced-*/部分删除残骸永久堆积；new-id 旧代际无限累积（单代 481MB）。

两条结构事实决定方案形状：

- **C1**：`configureElectronPaths` 之前，Chromium 默认 userData == Sage 根（productName=Sage）；自愈含秒级 await，若排在 configure 前会把 Chromium 写根窗口拉长 → 自伤 pristine 门。次序必须为 ensure → **configure → reconcile → admission → install**。
- **C2**：admission 拒绝任何非预期条目（含 electron/** 内文件）；安装开始后 electron/** 必有 Chromium 文件，故 admission 必须对 electron/** 整体放行，否则窗口 1/2 自愈后仍不可装。

## 决策

1. **D1 自愈模块**（`profile-reconcile.ts`，packaged only，ensure+configure 之后）：先算计划再落效果；**提交动作**（回滚 rename、采纳指针写）失败抛具名 `ProfileReconcileError` 走既有启动失败面；**清理性删除 best-effort**——装饰残留永不 brick 健康根。全部态幂等：自愈中途再被 kill，下次启动重新收敛。
2. **D2 回滚而非前滚**（致命窗口 1）：指针有名、其代际目录缺失时，恰一份 receipt 与指针（generation+sha）一致的 `displaced-*` → rename 回位。回滚后本启动内常规 upgrade 重做同一事务（模板差异持续存在，天然收敛）；0 份 → `active-generation-missing`，≥2 份 → `displaced-ambiguous`（均 fail closed，消息列路径与人工恢复源）。
3. **D3 采纳 = 完成被杀的前滚**（窗口 2/3）：无指针时，唯一 receipt 与**当前签名模板**一致且整代就地过**安装同套验证**（`readGenerationProfile` + attestation sha + `verifyRuntimeArtifactAttestation`）的代际 → `writeActivePointer`（activatedAt 优先取自死亡事务 `verify-profile-current.json`，否则注入时钟）；不匹配 → 删除、fresh 重装。指针存在时同理处理被杀 new-id 前滚；采纳后旧代际保留为回滚源。**不引入第二条信任路径**：采纳验证就是安装验证。
4. **D4 GC keep-1**（新政策，ADR-0332 附记）：无有效 receipt / 非代际的目录一律清除；有效非活动代际保留 mtime 最新一者作回滚源，平局不删。根级 `<pointer>.<uuid>.tmp` 散件（writeActivePointer 内部被 kill）同批清扫。
5. **D5 admission 换位**：`assertBundledProfileAdmissibleSync` 对 `electron/**` 子树不下钻（Chromium 私有域；Sage 自身状态全在根级/harness，继续严厉）；三处注释（admission、install、bootstrap）重写至新不变量；`desktop-entry.spec` 增两条次序断言钉住 configure→reconcile→admission→install。
6. **D6 指针读取拆分**：`readActiveProfilePointer`（裸指针半段，ENOENT→null 不抛）与 `readGenerationProfile`（就地验证半段）导出；自愈只经前者探测指针态，绝不复用 `readActiveProfile` 做探针（其代际 ENOENT 会裸抛）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 前滚（恢复后完成换位+写指针） | 否决：多一条「恢复路径写指针」信任分支；回滚+常规重试同结果、动件更少。 |
| 删除孤儿代际来恢复 pristine | 否决（C2）：不放开 electron/** 时门仍拒；且白扔已装树。 |
| 保持 admission 在 configure 前 | 否决（C1）：自愈 await 会拉长 Chromium 写根窗口，自伤门禁（自造竞态）。 |
| adopt 只校验 receipt sha | 否决：树入活动面必须有签名来源；安装验证三件套复用现成。 |
| GC 全保留（仅清残骸） | 部分采纳：本轮附带给 keep-1（481MB/代），保守者可一行回退。 |

## 后果

- 五类 kill 窗口全部收敛为「启动自愈 + 正常路径重试」；致命窗口 1 实测从「启动失败退出」变为 `rolled-back → existing → host ready`。
- 单实例前提未变（二次实例可能互相清事务；已记 module docstring，单实例锁是独立票）。根级 Chromium 旧遗留（pre-C1 世代）与 `.DS_Store` 仍 fail closed（人工恢复，与现状同）。
- spec：新 `profile-reconcile.spec.ts` 17 例（每窗口 + GC/平局/symlink/坏指针/健康根）；`bundled-profile.spec` 增 admission 回归；夹具抽到 `test/support/profile-fixtures.ts` 一处。
- 后续票候选：单实例锁；`.DS_Store` 容忍；超时 GC（保留时间维度）。

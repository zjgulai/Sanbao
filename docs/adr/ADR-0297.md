# ADR-0297 · 核对入口第一刀：attempt-status 只读查询与不确定门解封

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：同意下一批）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-attempt-status-reconciliation-entry.md)
- 相关：[ADR-0296](ADR-0296.md)（D3 裁决：无痕迹场合待具名核对入口）、[ADR-0251](ADR-0251.md)（projection-read admission）

## 背景

ADR-0296 D3 裁决：dispatch-unknown 的 attempt 凭「晚于基线的新边沿」轻收口；「日志无请求痕迹」的场合保持活跃，待具名核对入口。renderer 侧现状：unknown send 后 `uncertainMatters` 纯内存封锁该 matter 的发送——没有任何解封路径（主链收口后 UI 也无从得知），且封锁理由是纯文案。核对入口需要一个只读查询：以请求作用域的活动 matter 为键，回答「活跃 attempt 的身份、是否 dispatch-unknown、回合证据相对基线的状态、最近一次收口」。

## 决策

1. **D1 具名只读路由**：`POST /.sage/session/attempt-status`（严格 `{}` 体）进入统一 projection-read admission，操作名 `session.attempt.status` 入封闭操作表（第 17 个）；candidate = 活动 matter，读取 owner 仍由请求作用域 ActiveContext 决定。production 无对应 grant 时 unavailable-first；走查手册的 19 条 grants 草案增补该授权行（production-live 的唯一途径）。不新增 fixture bypass（bypass 恒为 `state.read` 一条）。
2. **D2 事实来源**：provider（Electron main）只读两处——matter 事件库（活跃 attempt、`dispatchUnknown` 标记、`observedTurnEndEdge` 基线）与会话 fold（`lastTurnEndEdge`、`execution`）。requestId 经 `sessionRequestIdForAttempt` 从 attempt 身份派生（ADR-0296 D5）。evidence 三态：`turn-running` / `turn-ended`（边沿晚于基线）/ `awaiting-evidence`（含 fold 不可读）。**查询绝不写、绝不收口**——收口唯一作者仍是 observer/reconcile。
3. **D3 renderer 解封只认正面证据**：不确定门（`uncertainMatters`）仅在查询返回 `read`、`matterRef` 匹配且 `active === null` 时解开，并报告 `last.status`（成功/失败）；unavailable、异 matter、仍活跃一律维持封锁。查询随后台读取悬挂触发（不新增用户操作），并带重入保护。
4. **D4 合同**：新 `SessionAttemptStatus`（contracts.ts）为 route↔renderer 唯一共享形状；refusal 合同不改（查询以 matter 为键，不需要 correlation 回传）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| correlation 键控查询（refusal 携带 correlation 回传） | 否决：查询随既有 matter 授权即可，refusal 合同不动。 |
| 把 attempt 事实塞进 state envelope | 否决：state 聚合面按 ADR-0251 D4 已冻结；核对是独立具名读。 |
| fixture bypass 放行该查询 | 否决：bypass 恒为 `state.read` 一条。 |
| 查询内自动收口 / 自动重发 | 否决：只读查询不得产生写；发送门由 renderer 与主链各自 fail closed。 |
| renderer 凭「刷新成功」直接解封 | 否决：读取成功不等于有收口证据——必须由查询给出正面答案。 |

## 后果

- unknown send 的不确定门有了正式解封路径；「无痕迹」的卡死依旧诚实封锁（查询答「仍活跃/待证据」）。
- fixture 模式（无读策略）下查询 unavailable——行为与今日一致，无回归；走查环境（真实策略）全链可验。
- 路由注册面 +1（61），read-only 族 14；门禁事实组 + 三条具名突变。

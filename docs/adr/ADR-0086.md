# ADR-0086 · 技能入库的第零步必须独立成层：它判的是「这台机器现在能不能跑」，不是「来件长得对不对」

- 状态：accepted
- 日期：2026-09-15
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/capability/2026-09-15-intake-runtime-preconditions-and-provenance.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（门禁全量硬门槛 + 只减不增的豁免）、
  ADR-0015（非机械改动必须留痕）、ADR-0040（走 `real-node`：pnpm 下 `process.execPath` 是宿主 Electron）、
  ADR-0052（第三方技能入库 SOP §12）、ADR-0085（归位 ≠ 接线）、
  总账 P-02（仪器假绿）、P-03（「知道」没有变成「拦住」）、P-04（写了但从没跑到）、
  P-11（判据的射程没有定义）、P-17（三态读数在聚合处被压回两态）

## 背景

2026-09-14，本批 592 个第三方来件入库。既有 SOP §12.1–12.9 的判据全部在回答同一个问题：
**「技能引用的 skill id 存在吗」**——目录名唯一、图标覆盖、路由引用无悬空、frontmatter 齐全。
**没有一条在问「这个技能跑得起来吗」。**

实测 T0 精选 15 条：**4 条装完必然报错**——缺 `openpyxl` / `matplotlib` / `python-docx` /
`python-pptx` / `PyMuPDF` / `pdfplumber` / `pypdf` / `reportlab`，Node 侧缺
`vega` / `vega-lite` / `sharp`。而当时**所有门禁全绿**：卡片正常、`installed=true`、
模型看得见、一调用就 `ImportError`。这是 P-02 的形态——假绿比红灯贵，红灯会被处理，
绿灯会被相信。

同一轮还量到两种更隐蔽的形态：

1. **装上了但坏在交付物里。** `matplotlib` 装上后默认字体 `DejaVu Sans` 不含 CJK 字形，
   中文标题渲染成豆腐块。**脚本退出码 0、图也生成了**，坏的是交付物。对一批面向中文组织的
   岗位 preset，这是常态而非边缘情况。
2. **失去 `.git` 之后没有基线。** SOP §12.2 要求安装时不保留 `.git`（那是对的），
   但这样"这条技能从哪来、哪一版、被改过什么"就没有任何记录——升级比对与回滚同时失去依据。

## 决策

**一、运行时前提层是入库的「第零步」，先于安装，且与结构体检分开判。**

- 抽取产物是 `manifest/runtime-deps.json`（自动抽取的基线），人工核对走
  `manifest/runtime-deps.overrides.json`（**逐条读过原文**的结论）。
- 抽取必须**按代码块语言分流**（shell / python / js / 其它）：同一个词在 shell 块里是命令，
  在 python 块里是散文。实测三次误报全部出自这里——`"""… convert .doc to .docx …"""`
  被当成 ImageMagick、正文里的 CSS 术语 `dot` 被当成 Graphviz、
  `npm install -g playwright && npx playwright install chromium` 的 `\s+` 吃掉换行
  把下一行 `node /data/...` 吞成了包名。
- **人工覆盖是替换，不是合并。** 写过就代表核过；合并会把已经判定为误报的条目又带回来。
  每条可标 `optional` 并写 `why`——软依赖不计红，但必须在读数里看得见。

**二、依赖装进受管 venv，且在技能目录之外。**

- `~/.dsh/skills-runtime/.venv`，Python 钉 **3.12**（不是本机的 3.14.7）：
  PyMuPDF / scikit-learn / scipy / pandas 的 macOS 轮子在 3.12 上齐全，3.14 上不一定。
- **不落在 `~/.dsh/skills/`**：那里每个子目录都会被当成一条技能，venv 的几万个文件会污染
  `verify_static.mjs` 的悬空引用判定（它 `readdir` 后并进「合法名字」集合）。
- 两条会**静默出错**的实现细节，写进判据而不是写进注释：
  - ⛔ **探测口径必须跟着 venv 走**。venv 一旦存在，探测就只看 venv。回退到系统 `python3`
    会出现「系统里有 pandas ✓ 但 venv 里没有」——门禁绿、一跑 `ImportError`。
  - ⛔ **installer 必须先建 venv 再探测**。第一版顺序反了，计划漏了 `scipy` / `scikit-learn`，
    跑第二遍才收敛。

**三、「装上了」不等于「能用」：环境前提也要有判据，而那条判据必须是真渲染一次。**

- CJK 配置落在 venv 内：`sitecustomize.py` 设 `MPLCONFIGDIR` 指向 `$VENV/etc/matplotlib`。
  三个更容易想到的位置各有明确的否决理由——不放 `~/.matplotlib` / `~/.config/matplotlib`
  （会作用于**所有** Python，含系统与 DSH 自身）、不直接放 `$VENV/etc/matplotlibrc`
  （matplotlib 3.11 **已不再搜索该路径**，实测 `matplotlib_fname()` 落到 `site-packages/mpl-data`）、
  不改 `site-packages/matplotlib/mpl-data/matplotlibrc`（会被 `uv pip install --reinstall` 抹掉）。
- 自检判据是**真的渲染一次中文标题**，并用 `-W error::UserWarning` 把缺字警告升级成异常。
  **不可用「字体文件存在」代替**——那只是判「装没装」，而坏的是交付物不是退出码；
  「没有渲染就没有读数」。字体按本机实测可用性排序：`PingFang SC` 与 `STHeiti` 是 `.ttc`
  集合，matplotlib 3.11 加载失败，不能进配置。

**四、来源留底是独立产物，承载升级与回滚两个用途。**

- `manifest/intake-provenance.json`：批次 / 原始单元 / **逐文件 sha256** / 许可证结论 /
  已应用的修补 / 已知缺口。失去 `.git` 之后，它是唯一的升级比对与回滚依据。
- 修补与豁免必须**声明**（`staging/intake-repairs.json`：`dropFiles` / `writeFiles` /
  `rewritePaths` / `acceptFatal`），并沿用 ADR-0014 的规矩：**匹配不到任何缺陷的豁免会报错**
  ——过期豁免长期挂账就是假绿。
- 回滚用 `ditto`，**禁用 `cp -R`**（实测会拍平目录）。

**五、局部扫描写 manifest 必须并入，不能整体覆盖。**

`--skills <名单>` 是常态用法（放量时逐批入库）。实测一次试跑把 manifest 从 5 条**缩成 2 条**，
门禁于是不再检查另外 3 条，**继续报绿**——射程被悄悄缩小，而收缩本身没有任何读数（P-11）。

**六、门禁 `gate:skill-runtime-preconditions` 的射程由「接线」决定，不由「清单」决定。**

判据是**已接线技能的声明依赖逐条就位**，射程取自各 `agt-NNN/agent.cordis.yml` 的
`skill-subset`：一条还没接线的技能不拖红，一旦接线就必须齐备。跳过条件写死：
**只有在没有任何已接线技能声明 Python 依赖时**才允许跳过；一旦有技能声明了依赖而 venv 缺失，
那是红。探查器吐不出可解析读数同样判红——调用方无法区分「都核对了」与「有一项没核对」（P-17）。

## 备选方案

- **把依赖装进系统 Python**：本机系统 Python 是 3.14.7，太新、轮子覆盖不全，装崩了会波及
  DSH 自身。否决。
- **venv 放 `~/.dsh/skills/.venv`**（前缀直觉上更自然）：会把几万个文件变成一个「技能目录」，
  污染 `verify_static.mjs` 的悬空引用判定。否决。
- **用「字体文件存在」当 CJK 判据**：判的是安装动作，不是渲染结果；而这一类缺陷的症状恰恰是
  「退出码 0、产物是坏的」。否决。
- **把运行时前提并进 `intake-lint`**：结构体检判的是「来件的形状」（离线、与机器无关），
  运行时前提判的是「这台机器现在能不能跑」（环境事实）。混在一起会让「这台机器没装」
  报成「来件坏了」——同一形状的混淆在 ADR-0085 已被代价教过一次（同一句话把环境事实
  与数据缺陷说成一样，于是那条红既不能驱动重装也不能驱动查数）。否决。
- **给全部 592 条都装依赖**：只装 T0/T1 实际需要的。`libreoffice` 约 700MB 且只服务
  一条技能，而它在 `sn-da-non-spreadsheet-analysis` 里是**软依赖**（只在旧格式
  `.doc` / `.ppt` 上走转换，`.docx` / `.pptx` 直接走 python-docx / python-pptx）。否决。
- **不保留 provenance，升级时重新下载来件比对**：失去 `.git` 后既没有基线，来件 zip 也会被
  清理；且比对结果会被上游重新打包影响。否决。
- **把 `missing` 非空的技能先登记进 `exemptions.json` 放行**：豁免只减不增、到期即拒绝
  （ADR-0014），而这是**新装**技能的依赖，不是存量不达标。用豁免盖住等于把
  「装了但跑不起来」永久合法化。否决。

## 后果

**正面**

- 「装了但跑不起来」不再是安静的选项：判据在接线那一刻生效，且结论来自**真的跑了一次**
  探查器与一次中文渲染。
- T0 15 条里有依赖的 5 条全部落进 `runtime-deps.json` 与 overrides；四条带重型依赖的技能
  做了**真实运行取证**——`chart-gen` 出 PNG（690×390）、`sn-da-excel-workflow` 写读 xlsx
  带条件格式、`sn-da-non-spreadsheet-analysis` 解析 docx/pptx/pdf、`minimax-pdf` 出中文 PDF
  并能回读文本。
- 结构体检的判据**全部来自实测缺陷**，不是想象出来的：592 个来件实测致命 12 条、告警 144 条
  （第一版规则误报 135 条，收窄判据后收敛）。其中 `chart-gen` 一条同时命中三种缺陷
  （损坏的 `_meta.json`、乱码的 `scripts/package.json`、硬编码的原厂沙箱路径），
  修补被逐项登记在 provenance 里。

**代价与约束**

- venv 是**机器状态**，不入库。干净 clone 上只有「没有任何已接线技能声明 Python 依赖」
  这一条路径能跳过，其余情况必须真的装出依赖——这是有意的：判据不能因为换台机器就变绿。
- 判据依赖本机 `~/.dsh/skills` 与 `~/.dsh/.agent-presets`，与 `gate:skill-lines`
  同一射程前提；两者都不在时按同一语义跳过并写明跳过了什么。
- **只保证「依赖就位」**：不管版本是否合适、不管技能逻辑对不对、不管产物内容是否正确。
  诚实划界写在这里，避免这条门禁被当成「技能质量门」。

**后续动作**

- 放量到 T1（约 30 条）与挂岗的约 120 条时，第零步必须重跑；`--skills` 的并入语义
  （决策五）就是为逐批放量准备的。
- 剩余来件的 `missing` 尚未逐条探测——本批只对 T0 做过完整第零步。
- `.scratch/new-skills-intake/DECISIONS-AND-SOP.md` 是本层的**决策过程稿**（含两处被实测推翻的
  原始判断及其更正去向），不是事实源；事实源是 §12.10 与本文列出的三份 manifest。

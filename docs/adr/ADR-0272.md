- 相关：[ADR-0160](ADR-0160.md)、[ADR-0269](ADR-0269.md)、[ADR-0271](ADR-0271.md)、[迁移清理规格](../specs/2026-10-06-portable-handoff-cleanup-spec.md)

## 背景

用户决定把 Sage 移交给另一台电脑上的 Codex 继续开发。当前机器上存在：35 个关联 worktree（约 8.5 GiB；多数回链指向搬迁前路径，两个注册的目录已不存在）；旧预览 / 缓存目录（`.composer-preview`、`.ua` 快照回收站、`.dsh-types` 等）；跨仓默认入口（surface root 解析与 crawl 只按「Sage 同级 Sanbao 快照仓」布局；设计回路资料与判者在仓外目录；品牌源 SVG 在仓外）；以及一条仍在收尾、留有陈旧锁的打包流水线。逐目录拷贝会把失效回链与不可解释的混合状态带去新机；而按「体积 + 有没有人 import」清场会把证据面与承诺面当垃圾清掉（P-49、P-02 族）。

盘点同时实证了清理仪器自身的一个缺口：`cleanup-inventory` 把「git 扫描失败」与「无引用」压成同一读数（对不存在的仓库给出 `suggested`），且射程不含 `packaging-sage`、不看 untracked。

## 决策

1. **先保全，后清理**：删除前对每个关联 worktree 做只读保全——tracked 差异补丁、untracked（非重目录）tar、ignored 证据 tar、唯一提交判定——恢复集固定在仓外 `Sage-recovery-20261006-cleanup/`；任何进入删除的对象必须先有可核对的保全收据。
2. **worktree 回收**：保全核验通过后，注销 Sage 侧 worktree 注册并删除对应目录（含仓内 `.qoder/worktrees/` 未注册孤儿与两个已失效 prunable 注册）。Magpie-Horch 侧旧路径的注册状态不作修改（该仓只读，由其自行 prune）。
3. **Sanbao 原型收纳**：纳入 `vendor/sanbao-prototype/`（含 `.git`；排除 node_modules / .playwright-cli / output）与 `vendor/sanbao-prototype.pin`（HEAD、catalog / ledger / _site 摘要）；surface root 解析（`apps/sage-shell/src/main/sanbao-surface-root.ts`）与 crawl ledger 发现新增仓内候选——env 覆盖仍最先，兄弟仓降为历史回退。
4. **设计回路收纳**：`docs/design-loop/**`（工单 001–050、LOOP.md、规格、合同与 ADR 快照）与 `scripts/design-loop/verify_ticket.mjs`（判者默认改宿主仓相对入口）；历史工单状态与矩阵读数不得冒充现行验收，现行以 tracked matrix 与集成票据为准。
5. **品牌源收纳**：`assets/sanbao-logo-kit/A_StarSail_Product_symbol.svg`（SHA-256 与生成器 `expectedSourceSha256` 逐字节一致）；manifest 的权属 / 商标 / 视觉批准状态不因收纳改变。
6. **清理仪器加固**：`cleanup-inventory` 把引用扫描失败与「无引用」分形（失败落 `unknown`，不得进入删除建议），射程纳入 `--untracked` 与 `packaging-sage/`；以不可用仓库负控与单元测试证明该分支会红也会绿。
7. **不越权边界**：旧 LUTE 签名身份保留（退役链但可回退，不销毁私钥）；`packaging-sage/staging` 的陈旧锁只登记不清理；未提交工作区是交接主体，不自动 commit / push；另一台电脑尚未运行的验证一律标注「待新机验证」。

## 备选方案

- **整目录复制到新机**：拒绝——会带上 35 个失效 worktree 回链、缓存与不可解释的混合状态。
- **直接删除 repo 中「没有 import」的大目录**：拒绝——P-49 实证这样会清掉承诺面与证据面（历史发布清单、ignored 证据）。
- **把设计回路 / 品牌源留在仓外靠文档指路**：拒绝——异机不再有这些兄弟目录，默认入口必须在仓内可解析。
- **新机重新 clone 公开来源**：拒绝——sanbao_ui 为私有仓、Sanbao 快照与设计回路不是 Git 仓库，离线收纳副本是唯一可靠来源。

## 后果

- 本机释放 worktree 与缓存占用；Sage 默认入口（surface / crawl / 生成器 / 判者）不再依赖兄弟仓布局。
- 恢复集是回退入口，不是运行时 / 构建依赖；其内容是保全时刻的读数，不是持续同步的备份。
- `vendor/sanbao-prototype` 成为本地权威副本；上游（私有 `sanbao_ui`）出新版时按 pin 约定 bump 并重跑 `--check-source`。
- legacy `packages/` 的减重与门禁解耦、`.dsh-root-brand-preview` 的归档裁定、陈旧打包锁的正式释放仍待另立任务，本轮只登记不处理。

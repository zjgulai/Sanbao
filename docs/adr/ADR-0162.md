# ADR-0162 · 能力装配契约：外部能力经 MCP client 条目挂入 Sage 壳（首例 Jev 判断层）

- 状态：accepted（2026-09-27）
- 日期：2026-09-27
- 决策者：用户（lute）
- 决策记录：[Note](../notes/proposed/architecture/2026-09-27-capability-mounting-contract.md)
- 相关：ADR-0159（Sage 自有产品与数据边界）、ADR-0160（本机活动仓基线与历史能力隔离，禁止新增机器绝对仓路径）、ADR-0061（外部产品走 profile 本地装配；可选 host 服务双通道探测）、ADR-0139（壳版本与治理事实门禁）、ADR-0165（Compatibility Authority；部分修订本 ADR D2）

## 背景

Sage 设计树决策 3 已定「项目、任务、会话、浏览器、文件与自动化组成通用工作台底座，**Jev 等内容增长能力以模块接入**」（[ADR-0159](../adr/ADR-0159.md) 的 Note），但壳此前**没有装配契约**：什么能力以什么形态、经哪个面、按什么 pin 与隔离纪律挂进来，没有任何一处写死。JEV 侧的判断层（TypeSafe Jev，16 条判断 + 脱敏/出境纪律 + 已在真实材料上跑通的日报闭环）现在是第一个真实案例，迫使该契约落地（交接件见 [research/19](../research/19-jev-dsh-compat-handoff.md)）。

现状事实（2026-09-27 只读核对）：

1. **壳已有三层装配点**：`apps/sage-shell/seed/package.json`（`dsh.profile.bundles` + 精确版本依赖）→ 物化（`scripts/materialize.mjs` → `src/profile/`）→ 启动时合成（`src/host/composition.ts`：bundle 层 → profile 自带用户补丁层 → 壳 overlay）。
2. **物化 profile 自带用户补丁层**：`@deepseek-ai/dsh-app-boot` 的 `loadProfileDirectory` 读取 profile 目录内的 `cordis.patch.yml` 作为 user patch layer（与 ADR-0061 的 legacy 本地装配同形态），该目录位于 Sage 自有数据根，**不在仓库内**。
3. **依赖门禁已就位**：`sage-shell-pin` 要求壳 devDependencies 与 seed dependencies 两侧的 `@deepseek-ai/*` 都非空、精确、同名包同版——新依赖双侧同版即可过门，不是白名单。
4. **MCP 是宿主既有能力**：架构事实（`docs/architecture.md` §1）记「MCP 宿主直挂 `dsh-mcp-client`（ctx.plugin），工具名 `mcp__<server>__<raw>`」；`@deepseek-ai/dsh-mcp-client@0.1.5-rc.2` 在 npm 可装（已实测）。壳当前**没有任何 mcp 条目**。
5. **历史教训已有实物**：2026-09-19 legacy 曾端到端挂过 mcp-jev，后在 profile 改写中丢失接线（本仓 `.scratch/review/2026-09-22-arch-health-top20/HANDOFF-CODEX.md` 记录过）；JEV 侧对现行安装校准了重装块与三个不可省的细节（`insert:` 包装、凭证 spawn 时 source、node 绝对路径）。

## 决策

1. **形态：MCP client 条目。** 外部能力（首例 Jev）以 `@deepseek-ai/dsh-mcp-client` 的 client 条目、stdio 方式托管其进程（JEV 的 `jev-judgments` 服务器：恒定两工具 `list_judgments` / `judge`），挂进壳的装配面。不引入 npm 发布线（红线 1）、不把外部能力包成 cordis 插件、**不改 JEV 源码**。
2. **依赖按消费面精确 pin。** 每一侧出现的 `@deepseek-ai/*` 都必须使用精确版本；两侧同名重叠包必须同版。只有同时被 shell 编译期与 runtime seed 消费的包才要求双侧登记；runtime-only 包可以只进入 `seed/package.json`，但必须进入 lock 与未来可信 runtime inventory 证据。该表述由 [ADR-0165](ADR-0165.md) 部分修订原“任何新依赖均双侧登记”的 D2；继续由 `sage-shell-pin` 守精确 pin 和同名同版。
3. **面归属：壳提供实例本地补丁层，机器相关条目只写进它。** 宿主启动时若 `<Sage root>/cordis.local.patch.yml` 存在，则作为**最后一层**合并（可覆盖仓库层任何行；缺失时零行为、opt-in），实现于 `composeShellPatches` 的可选 `localPatchPath`（缺省不传即旧行为，含测试与变异验证）；带机器路径、凭据落点、本机进程命令的条目只写进该文件，仓库内**不承载任何机器内容**。（原计划写"物化 profile 的 `cordis.patch.yml`"——实测该文件由 seed 复制并被代收据逐文件哈希封印，改一字节即 fail-closed，故以本机制取代。）
4. **装配纪律（三条教训固化为契约）。** ① 条目必须带 `insert:` 包装——否则被当"对既有条目的覆盖"，日志报 not found 后**静默丢弃**；② 凭证不落仓库/日志，按 **spawn 时来源**供给（首例：`zsh -c "source <凭据落点> && exec <绝对 node> <JEV 仓>/src/mcp/main.ts"`——宿主会清洗子进程环境的凭证形状变量，且 Finder 启动的 app 无 PATH）；③ 宿主变更**重启生效**（MCP 挂载在宿主启动时解析）。
5. **数据隔离。** 外部能力的运行状态必须显式指向 **Sage 实例数据根**内的路径（首例经条目传 `JEV_STATE_DIR`）；不得缺省落到与旧 DSH 共存的 `~/.local/state/jev-dsh`，不得读写旧 `~/.dsh` 数据根（ADR-0159/ADR-0160 的隔离要求）。
6. **证据义务与边界。** 装配完成的判据是**端到端真实调用证据**（`mcp__jev__list_judgments` 返回 16 条）+ 失败 fail-closed（无凭据时服务器 `exit 1`、工具面不可用，不得静默空答）；本契约只覆盖**判断层**两个工具；闭环（digest）工具化是 JEV 侧另立开发（其 `tickets/005` 路线 A），不在本契约内。accepted 不等于已装配。

## 备选方案

| 方案 | 为什么未采用 |
| --- | --- |
| Sage 侧薄适配包（`packages/capabilities/*` 托管 JEV 进程） | 走完整 5 组治理（身份三元组、files 清单、profile-files-sync 等）与全部门禁，控制面更重；对 stdio MCP 服务器没有增量收益。等产品面需要 Jev 状态页/设置/权限时再升级为独立决策。 |
| 先把 mcp-jev 装回旧 DSH profile，Sage 侧随后 | 旧 profile 属被隔离的历史环境（AGENTS.md：不得把 `~/.dsh` 当作 Sage 运行时）；在隔离环境取证不建立 Sage 的契约。可作为对照验证，不作首落点。 |
| 把 `mcp-jev` 条目直接写进仓库 `config/shell.cordis.patch.yml` | 会把机器绝对路径（node 路径、JEV 仓位、凭据落点）加进仓库，违反 ADR-0160 的路径纪律；且与 ADR-0061 的本地装配先例相悖。 |
| 内建为壳内服务（不经 MCP） | 需要把 JEV 的引擎/脱敏/凭据逻辑移植进壳仓或新增跨仓依赖，复制既有实现、破坏 JEV 侧"程序永不写批准/凭据只内存取用"的既有纪律；与"Harness 只作可替换能力运行时"的分层也不符。 |

## 后果

- 正面：外部能力挂载有了唯一契约——形态、面归属、pin、隔离、证据五件事各有落点；Jev 成为第一个可复制的样板。
- 正面：仓库保持机器无关；装配与回滚都发生在实例本地（改/删用户层补丁 + 重启）。
- 代价：装配不是"改仓库即生效"——每台实例要各自落一份本地补丁；跨机器的产品化分发需要另立决策（届时大概率走向形态 B）。
- 风险：实例本地层是人工维护、无代收据保护的文件——写坏会在下次启动时**大声报错**（补丁解析失败即 throw，不会静默半应用）；它不随 `materialize` 迁移（位于数据根、不在代内），删文件即回滚。
- 边界：本 ADR 只接受契约，不证明已装配、不证明 shell 端到端启动、不覆盖闭环工具化与产品面集成；判断结果未标定（`action` 恒为 uncalibrated），产品面不得据此自动执行。

## 实施记录（2026-09-27）

- 壳侧实现：`composeShellPatches` 接受可选 `localPatchPath`（存在才 merge、最后合并），宿主入口从 `<Sage root>/cordis.local.patch.yml` 解析并传入；含 2 条测试（合并在最后 / 缺失零行为）与**变异验证**（去掉新分支 → 新测试精准判红）。
- 首例（Jev）装配与证据：`seed/package.json` + `seed/pnpm-lock.yaml` 加 runtime-only 的 `@deepseek-ai/dsh-mcp-client@0.1.5-rc.2`（按经 ADR-0165 校准后的 D2 可 seed-only；壳 devDeps 侧不加——实测会拖入 rc.3 传递子树，正是红线 1 要防的版本混装）；本机 `cordis.local.patch.yml` 落 `mcp-jev` 条目；`materialize` + 无 GUI `smoke` **14/14 通过**；探针实测宿主启动后 **JEV 服务器进程在跑**、宿主 stderr 打出 `jev-judgments: 16 judgments … state in <Sage root>/jev-state`、无 mcp 告警；**负控**：停用本地层 → 无进程、无输出、宿主照常启动。
- 未取证：真实会话里的 `mcp__jev__list_judgments` 工具调用（需要会话/模型侧），以及随之才会出现的 egress 请求行。

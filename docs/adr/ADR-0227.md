# ADR-0227 · 事项管理：可恢复归档、服务裁决重命名、逐项批量

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；D-029/D-066 与 FW-030 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-matter-admin-archive-rename-batch.md)
- 相关：[ADR-0213](ADR-0213.md)（暂停/停止语义）、[ADR-0221](ADR-0221.md)（列表分区与 lifecycle 槽）、[ADR-0201](ADR-0201.md)（托管侧写正式记录）

## 背景

工单 029（FW-030，US-150~154）：归档按 D-029 落地（仅符合条件才允许；退出活动列表、保留事实
与回执、可恢复；不停止执行、不解除未结责任、不删保留数据）；重命名经服务裁决并回读实际生效值；
批量逐项返回结果与权限结论、不对无权项静默跳过、不显示整体成功；隐藏/归档/停止三事实分开。
验收：①归档后仍可恢复且事实与回执保留；②批量结果逐项可核对、无"整体成功"伪报；③重命名回读
显示实际生效值。边界：不做批量审批/批量授权、不做删除与保留策略。

基座与现状事实：事项正式记录归托管侧（ADR-0201；production 无托管方）；022 的列表派生已有
`lifecycle active|archived` 槽位但"无事实来源"；停止=会话暂停（006，会话作用域）；"隐藏"在产品
中无此功能。本票给 lifecycle 接上第一个真实事实来源。

## 决策

1. **D1 归档=可恢复的列表退役（US-150/151）**：新 Sage-owned 模块 `main/matter-admin.ts`——
   记录 {matterRef, archivedAt, ground}（ground=声明 `completed|stopped`）+ 只追加 trail
   （archive/restore + 当时依据）；`knownMatter` 由服务自有记录回答，**不存在与无权同码**
   （`matter-unknown`，不枚举）；重复归档幂等。归档操作**只写自己的记录**——不停止运行、不解除
   未结责任、不扩大读取、不删除数据（读态逐槽 byte-equal 断言）；恢复只回列表呈现（不改执行
   状态、不把完成改成运行中）。022 列表接入 `archivedOf`：归档项 lifecycle='archived'、默认
   折叠、筛选展开后有专属标签「已归档（可恢复；≠停止执行）」。
2. **D2 重命名=服务裁决＋回读（US-152）**：`renameMatter` 端口裁决；视图字段 `requested` 与
   `effective` 分开，**`effective` 只取端口回读值，请求字符串绝不冒充生效**；端口未接线
   （production：正式记录归托管侧）→ `matter-rename-unavailable` 如实。原 D-029 的"经服务裁决"
   在本仓 = Application Service 自有的可选裁决端口，不触碰 fail-closed 管线步骤。
3. **D3 批量=逐项（US-153）**：一次 1–32 项、操作仅 archive/restore（**无批量审批/授权**）；
   每个目标一行裁决 {outcome, code}＋counts——**形状里没有"整体成功"字段**，页面文案明说
   "逐项为准，无整体成功"；无权/不存在不静默跳过（逐行给出同码拒绝）。
4. **D4 三事实分开（US-154）**：归档（列表退役，可恢复）≠ 停止（会话暂停，006 的会话作用域事实）
   ≠ 隐藏（产品无此功能、无入口）；归档卡的文案与断言逐条明说；归档 JSON 内**无 hidden/pause
   词汇**（扫描断言），停止入口仍只在会话卡。
5. **D5 首版不做**：批量审批/批量授权；删除与保留策略（真正删除=独立受控流程，本票无入口，
   仅在文案中注明）；归档持久化（本运行记录，与 013/028 同级的诚实边界）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 归档走 `/.sage/actions` 命令管线 | 否决：管线步骤 3–10 fail-closed（ADR-0190），归档不是 Registry 动作；Sage-owned 事实走 S1 自有路由。 |
| 归档对象=会话（`archiveSession`） | 否决：那是基座的会话归属事实，不是事项的列表退役；两者不能互相顶替。 |
| 重命名直接改本地标题 | 否决：正式记录归托管侧（ADR-0201）；本地改写会让投影与真源分叉。 |
| 批量返回单一成功标志 | 否决：US-153 点名"不显示为整体成功"。 |
| 归档时挂"已停止"标记 | 否决：三事实分开（US-154）；归档不碰执行状态。 |

## 后果

- 验收三条的机器断言：①归档/恢复只动 matterAdmin 槽与列表 lifecycle，其余槽 byte-equal、
  转换回执（matterRef）原样保留；②批量行的逐项裁决与 counts、JSON 无 success 字样；
  ③重命名 effective=回读值 ≠ requested。
- 022 的 lifecycle 槽获得真实事实来源（此前"无事实来源"的注释随之更新）；筛选复选框成为真实
  过滤。
- 已知未闭：归档/重命名/批量记录本运行（持久化后置）；重命名裁决端口生产未接线（等托管侧）；
  真机未跑。

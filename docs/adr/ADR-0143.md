# ADR-0143 · 右侧工作台：一个面板装 7 个可折叠分组，折叠机制照 Qoder CN

- 状态：accepted（2026-09-20）
- 决策者：用户（lute）+ 右侧栏折叠诉求轮
- 取代：ADR-0141（提案「左栏 7 行分三组折叠」——折叠改落在右侧面板，左栏保持扁平）
- 修订：ADR-0140 D4（面板由「一次一个模块」改为一屏全部分组）、D1 保持有效（左栏仍扁平）
- 相关：ADR-0137 D3（被取代的决定不静默改写）、ADR-0132 D3（禁止装饰性彩色辉光）、总账 P-07

## 背景

用户在实机上给出了新的参照：Qoder CN 的右侧栏是**一列可折叠分组**（环境信息 / 后台进程 /
技能与 MCP / 产出 / 网页查阅 / 来源），要求「折叠功能照 Qoder CN 的设计」。

同期暴露了一个更严重的事实：**此前的质感改版（30px 圆角、1.2px 外框、fixed 定位、玻璃渐变）
在实况里一条都没生效**。真机读数是 `position: static`、`border-radius: 0px`、`border-width: 0px`，
面板是一个渲染在视口下方（y=923）的裸 div。根因有两个，都在同一处：

1. **样式表有两个家**：`styles/right-sidebar.module.css`（含质感改版）与
   `src/styles/right-sidebar.module.css`（旧的 380px 版）同时存在。
2. **相对路径多一层**：`src/client/modules/common/panel-shell.tsx` 比 `src/client/modules/*.tsx`
   深一层，`'../../../styles/…'` 实际解析到 `src/styles/…`（旧文件），于是**面板壳**用旧样式、
   **模块内容**用新样式——一半生效一半不生效，肉眼只看到「设计没有任何效果」。

即 ADR-0140 之后的那次质感改版，改的是**一个不是装载点的副本**；声明层面的检查（读源码、
读 CSS、跑门禁）全部通得过。属总账 P-07 的形态。

## 决策

**D1 右侧栏是「一个面板 + N 个可折叠分组」，不是「一次一个模块的面板」。**
面板标题「工作台」，内容是一列分组卡，每个分组对应一个模块，顺序沿用 ADR-0140 D2
（待办 > 环境 > 技能和 MCP > 网页查阅 > 后台进程 > 产出 > 来源）。左栏 7 行**仍是扁平注入**
（ADR-0140 D1 不变）；点某一行 = 打开面板并把那个分组展开、滚进视野。分组内容按需挂载
（首次展开时挂载，之后折叠也留在 DOM 里——保住列表滚动位置与未提交的输入）。

**D2 折叠机制照 Qoder CN：表头整行是开关，内容用自动高度过渡。**
`<button aria-expanded aria-controls>` 包住整条表头；chevron 展开朝下、折叠朝右（rotate）。
内容用 `grid-template-rows: 0fr ↔ 1fr` 过渡——**不写死 `max-height`**，内容多长都不会被截断
（旧实现写的是 `max-height: 1200px`，超过就静默截断）。折叠状态记在
`localStorage['dsh-right-sidebar:collapsed-groups']`，跨开关面板保留；`prefers-reduced-motion`
下过渡归零、状态照切。

**D3 一份样式表、一份模块目录；相对路径的深浅不参与「用哪份样式」的决定。**
`src/styles/right-sidebar.module.css` 删除，全包只留 `styles/right-sidebar.module.css`
（也是 `sidebar-row-axis` 门禁登记的路径）；`panel-shell.tsx` 的导入改到同一份。
模块的 id / 注入行属性 / 图标 / 文案 / 顺序只有一份（`sidebar-entry.ts` 的 `MODULES`），
分组表头与左栏行都从它取；`rowAttribute` / `position` 字面**留在该文件**，因为
`sidebar-row-axis` 门禁按该文件文本发现注入行。

**D4 外框线按「渲染值 ≥1.2px」写，不按「声明值 1.2px」写。**
边框宽度会被渲染器吸附到整设备像素：2x 屏上声明 1.2px 实测渲染 1px（比要求更细）。
面板与分组卡改声明 **1.5px**，2x 屏上正好 3 设备像素、渲染值 1.5px。判据钉在**渲染值**上，
由真机探针读 `getComputedStyle` 断言。

**D5 验收只认真渲染进程的读数，且必须能区分「没量到」与「量了不合格」。**
`scripts/acceptance/right-sidebar-workbench-live.mjs`：CDP 连真渲染进程，点左栏入口打开面板，
读面板/分组卡的计算样式与行框、读 7 个分组结构与 `aria-expanded` 按钮、读折叠前后内容高度、
读折叠记忆键。找不到调试端口 / 找不到页面 / 找不到入口 → exit 2 并打印候选清单；
判据不过 → exit 1。本轮 22 条判据全过（面板 fixed / 30px / 1.5px / 视口内；7 分组；
`aria-controls` 全部可解析；折叠 119px→0→774px；分组卡 20px / 1.5px）。

## 备选方案

- **左栏分三组折叠**（ADR-0141 的提案）：与 ADR-0140 D1「单一扁平列表」相冲，且折叠交互放在
  导航列要额外维护一处 localStorage 与一条 mutation 收养链（该链正是 P-52 黑屏事故的根因面）。
  用户本轮要的是**右侧栏**像 Qoder CN，不是左栏——故折叠落在面板里，左栏不动。
- **面板里做 Tab / 抽屉 / 模态**：ADR-0140 已比较过（Tab 增加点击次数；模态阻塞工作流），
  结论未变。
- **保留「一次一个模块」的面板**：用户要的是一屏看全并自行折叠；且 7 个入口各开一个面板时
  跨模块对照要来回切，与参照形态不符。
- **折叠用 `max-height` + 一个足够大的常量**：旧实现就是这么写的，代价是内容超过常量被静默截断。

## 后果

**正面**：右侧栏与参照形态一致且真机可证；质感改版第一次真正生效（此前声明与渲染分叉）；
样式表与模块目录各收敛到一个家；折叠机制不依赖魔法常量。

**负面与已知边界**：

- 面板展开时 7 个分组的内容组件会各自拉一次数据（面板打开即触发）。分组内容按需挂载，
  用户折叠过的分组不会再挂载，但**默认全展开**时等同于全量加载。
- 折叠记忆是**浏览器存储**（localStorage），不随 profile 走；换机器/清存储即回到默认全展开。
- 验收探针需要应用带 `--remote-debugging-port` 启动，且该参数**只在应用未运行时生效**；
  探针会点一下左栏入口、折叠并展开一个分组（其余只读），结束后面板停在打开状态。
- 分组间距/圆角（12px / 20px）与面板（14px / 30px）是**几何常量写在本仓库样式里**，
  不来自主题 token——主题换肤改不了这两项。

**后续动作**：真机停留观察折叠记忆与轮询负载；若日志显示面板长期开着带来明显开销，
再评估「默认只展开被点开的分组」。

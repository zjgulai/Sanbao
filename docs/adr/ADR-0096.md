# ADR-0096 · Fullstack catalog 先闭合 138，产品 whitelist 只接受批准清单

- 状态：accepted
- 日期：2026-09-16
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/contract/2026-09-16-fullstack-catalog-and-approved-whitelist-boundary.md)
- 相关：ADR-0014（门禁硬门槛）、ADR-0091（Agent 全栈 preset）、ADR-0094（canonical gate result）、总账 P-30

## 背景

全栈目录已经由 `fullstack-mapping.json` 的 70 条和 `fullstack-extra.json` 的 68 条组成 138 条，
但旧 `verify-fullstack.mjs` 只遍历 mapping，真实 Red 仍输出 `70/70 全项通过`。因此 extra 的缺失、
frontmatter、资源和调用开关都不在这条成功结论的射程内。

运行时 `agent-fullstack` 当前有 89 条选择，但 live 文件只能证明“现在装成了什么”，不能证明“产品批准了什么”。
ADR-0091 批准了收窄为 89 条的目标与节点覆盖，没有保存可逐 ID 复核的批准集合、owner 与 reason；直接把 live
文件复制进仓库会把结果反推成意图。

## 决策

1. mapping 与 extra 先通过同一纯函数合成带 `origin`、`sourceName`、`sourceRef` 的 canonical rows；在 Set
   去重前拒绝精确重复、跨源重复、非法 final ID 和 NFKC/case 归一化碰撞。138 不是永久魔数，分母来自两份版本化输入。
2. 两类 row 进入同一逐项契约：manifest 双向全等、安装存在、frontmatter name/title/description、两个 invocation
   flag 的类型、正文非空、artifact 可读且无 symlink，以及 JS/shell/Python 资源语法。`disable-model-invocation`
   的 `true` 与 `false` 都是合法产品状态，不为追求统一计数改写上游语义。
3. `gate:fullstack-catalog` 直接消费 canonical result，独立输出 `expected/checked/skipped/failed`；CLI 与根 gate
   import 同一实现。live 技能根整体不存在时只能 typed skip，目录存在后缺任何一项都 fail。
4. 产品 owner `lute` 于 2026-09-16 明确确认候选 live 集合为 ADR-0091 canonical approved set，集合指纹为
   `4ebfa9f…`（排序、逐行、保留末尾换行）。批准结果物化为 `manifest/agent-fullstack-whitelist.json`，保存
   owner、decisionRef、reason、scope 与 89 IDs；门禁从 IDs 复算指纹，不从 live 自动生成或更新。
5. 本次批准的是**集合**而非展示顺序；manifest 显式写 `orderSignificant:false`。whitelist 作为第二个 root
   canonical gate 独立保留 89 分母；live preset 与批准集合做 missing/unexpected/duplicate 双向全等，并逐项核对
   runtime 的 M00–M13 节点归属是否等于 catalog `nodeId`。
   任何 138/89 变化必须与产品决策同批评审，不能自动吸收目录或 live 漂移。
6. 批准 scope 仅为 `preset-composition-only`；invocation flag 取值继续由技能文件与 `respectFileFlags:true` 管理，
   是否进入 DMG、发布或 promotion 仍是独立决策，本清单不得被解释成发布授权。

## 备选方案

- 只把旧 verifier 的循环再跑一遍 extras：会继续复制两套规则并产生口径漂移，否决；两源先合并再走同一契约。
- 只断言总数 138/89：删一补一或重复一项可维持数量，否决；采用逐 ID 双向差集。
- 从当前 `agent.cordis.yml` 自动生成 approved whitelist：把运行结果升级为产品意图，否决。
- 强制 138 条全部 `disable-model-invocation: false`：会覆盖 5 条明确禁止模型自动调用的上游状态，否决；只校验布尔类型。
- 在 owner 未确认时让 whitelist gate typed skip：批准清单是必备治理输入而非可选环境，否决；确认前保持未完成，确认后才物化 manifest。

## 后果

- 当前本机 catalog 得到 `138/138 = mapping 70 + extra 68`，零 skip、零 failed；旧 `70/70` 成功结论不再存在。
- 19 条 contract 定向测试覆盖 extra 缺失、坏 flag、坏资源、路由目标、跨源重复、归一化碰撞、同数量替换，以及
  whitelist 缺失、批准元数据漂移、catalog 未闭合、越界项、指纹漂移、任意子集、同数替换、重复项和顺序非契约；
  live integration 另覆盖节点错挂，mutation 全部在临时 fixture 中完成。
- 根 gate 分别报告 catalog 138/138 与 approved whitelist 89/89；live acceptance 另报 runtime 89/approved 89、
  owner=lute、14/14 节点、节点错挂 0 与双向差集为空。最终本地 quick 为 67/68、full 为 74/75；两者
  `failed=0`，唯一非 pass 是 `live-presets` 明确登记的 159 个 disabled typed skip。
- QG-010 的本地 L1/L2/L3 工程闭合；进入远端 required CI 仍由 QG-007 完成，不能把本地通过冒充远端 required check。
- 本决策没有修改 `~/.dsh`、preset、技能内容或发布产物；只读核对 live 技能 artifact。

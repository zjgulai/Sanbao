# ADR-0181 · WT-02D.0.2 command pipeline 内核：步骤 2–10 typed port 管道

- 状态：accepted（2026-10-01）
- 日期：2026-10-01
- 决策者：用户（lute）
- 决策记录：[WT-02D.0.2 command pipeline 内核收口](../notes/implemented/architecture/2026-10-01-wt02d02-command-pipeline.md)
- 相关：[ADR-0174](ADR-0174.md)、[ADR-0179](ADR-0179.md)、[ADR-0180](ADR-0180.md)

## 背景

ADR-0174 定义了 Application Service 的 command 顺序步骤 2–10，ADR-0179/0180 交付 main-owned `/.sage/*` route 骨架后，dispatch 对任何 action 恒 503 笼统体（`{error:'identity-unavailable', retryable:false}`），无阶段、无 correlation、无可判别错误类别；步骤 2–10 的顺序、脱敏与存在性不泄漏约束只有文档、没有代码看守。renderer retry 的 POST 处理器是 0.1 遗留的裸 `render(await response.json())`，无法消费 0.2 的 typed denial 形。本票落 command pipeline 内核并接进 dispatch，不接任何真实 provider。

## 决策

1. **D1 完整管道骨架（contracts + kernel）**：`command-contracts.ts` 定义 `SageActionIntentV2`（exact-keys fail-closed parse）、`CommandErrorCode`（13 值联合）与 `CommandPipelinePorts` 九 port 合同（port 返回 `undefined` = provider 不可用、fail closed）；`command-pipeline.ts` 的 `runCommand` 顺序编排步骤 2–10（identity-policy → strictRehydrate → resolveTarget → resolveCompatibility → resolveRegistry → preflightAvailability → persistPreparation → dispatchOperation），任一步非成功立即返回、后续 port 零调用，denial 形统一为 `{code, stage, retryable, correlation}`（可选标志字段 `requiresNewRevision` / `requiresDecision`）。两个映射语义：strictRehydrate not-found 映射 policy-denied 家族（stage 标真实步骤 rehydrate，防事项存在性泄漏）；resolveTarget 缺失映射 `compatibility-unknown` 阻断语义。
2. **D2 接进 main dispatch，production 全 port fail-closed**：`composition.ts` production 九 port 全 undefined，dispatch 走 `runCommand`——retry intent 穿同一管道（correlation 每次新鲜 `randomUUID()`），错误体只携带 code/stage/retryable/correlation（脱敏合同，无 stack/message/raw payload，`cache-control: no-store`）；`route-skeleton.ts` transport parse 拒绝同样映射 typed denial（`invalid-intent`@`intent`/400）。production dispatch 恒 200 + `{code:'identity-unavailable', stage:'identity-policy', retryable:true, correlation}`。
3. **D3 renderer retry 两形守卫**：retry POST 处理器以「`payload.code` 键存在性」判别 CommandDenied 形 vs 旧扁平形——CommandDenied 形归一 `{status:'recovering', message:'Sage 正在重新检查能力运行时服务。', retryable: payload.retryable !== false}`，legacy 扁平形直通 `render(payload)`；transport 在 P0-2 形冻结期仍只开放 retry intent（parse 拒绝其余业务 intent）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 逐段渐进（先 identity + dispatch 两步） | 否决；过渡期持续暴露顺序可绕过与错误体不脱敏面，一次全序内核 + fail-closed 是更小暴露面。 |
| kernel-only（内核先落、composition/transport 0.3 再接） | 否决；不接进 dispatch 的内核没有运行时读数（「写了但从没跑到」家族）。 |
| transport 同步开放完整 intent | 否决；需同时定 renderer 发送面与 202 accepted 语义，超出本票射程。 |

## 后果

- production dispatch 从 503 变 200 + typed body：`{code:'identity-unavailable', stage:'identity-policy', retryable:true, correlation:<uuid>}`，两次调用 correlation 不同（新鲜性）；identity denied 后 `ports.calls === ['identity']`（调用序列断言钉死顺序不可绕过）。
- renderer retry 两形守卫消解 0.1 遗留：CommandDenied 形归一 recovering 态，legacy 扁平形行为与 0.1 一致（回归钉）。
- 步骤 5 domain 重验暂由 target/compat port 承载（显式登记的暂态，非隐藏决定）；port-only 合同（persist/dispatch 等）等待真实 provider；`now` port 是 trusted clock 的注入位——production 无实现时为纯类型占位（composition 仅提供占位实现，内核不消费、全仓零调用、不参与任何判定），真实 trusted clock 随 provider 落地另票。
- 全量回归（2026-10-01，真实数字）：sage-shell 48 files / 453 tests 全绿（10.48s）；typecheck 0 error；仓根 gate 25/25 通过。Task 1–4 的 RED→GREEN 与变异验证证据见 `.superpowers/sdd/2026-10-01-wt02d02-command-pipeline/task-{1..4}-report.md`。
- 本票不接真实 provider、不开放业务 action、不建 202 accepted 路径；ADR-0174 unavailable-first 与 ADR-0179 main-owned route 边界继续成立。

# ADR-0214 · 显示偏好：单一权威值、两种状态分开、失败即回退

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证并实施；记录形态与失败语义是取舍）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-display-preferences.md)
- 相关：[ADR-0209](ADR-0209.md)（设备密封）、[ADR-0213](ADR-0213.md)（待继续记录同族）

## 背景

工单 020 要求三项显示偏好（主题含跟随系统、语言、密度）**单一权威值**持久化，外观页与用户菜单共用；
并明确两条禁令：快捷键/语音/布局偏好不得有入口或用界面状态冒充持久化；不迁入与 D-036 冲突的"内置浏览器"开关。
US-110 还要求"保存请求／已保存版本／实际生效"分开，且"立即保存"文案不等于已持久化；US-111 明暗跟随须由 main 观察。

## 决策

1. **D1 一条记录、两处入口**：偏好存在本设备一份密封记录（与草案/待继续同族 `createDeviceSealer`，0600 密钥）；
   外观页与用户菜单都只从 `state.preferences` 读、只经 `/.sage/preferences` 写——**两处各存一份**被结构上排除（US-108）。
2. **D2 状态分开**：记录里只有 `requested`（当前值）与 `savedAt`（最后一次确认保存的时刻，未保存过为 null）；
   `effectiveTheme` 由 main 计算（`system` 经 `nativeTheme.shouldUseDarkColors` 观察解析，US-111）；
   `applies` 首版恒 `live`。界面文案把"已保存到本设备"只挂在 `savedAt` 上，并在没有 `savedAt` 时明说
   "立即生效不等于已持久化"（US-109/110）。
3. **D3 失败即回退**：写入失败返回 `refused`，界面把两处入口重写回已保存值并挂一句"保存失败：显示值已回退"
   （该句不被 2s 轮询覆盖，沿用别处同款本地提示门）。
4. **D4 不观测就说未核验**：`system` + 无观察 → `effectiveTheme: null`，界面写"还没有系统明暗观察"，
   不猜浅色也不猜深色。
5. **D5 禁令写进卡片**：快捷键/语音/任务监控布局在卡片正文中明确"本版没有入口"，且不存在任何这类控件；
   "内置浏览器"类开关不引入（US-112/113，有文档级断言）。
6. **D6 外观页放在个人资料面板**：外观是交互面，**不进后置只读面板**——026 的"后置面板零控件"断言当场
   抓到了最初放错的位置（这是本票最值得记的一笔：两条既有的机器判据互相对撞，说明放错的是位置，不是判据）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 两处各存一份（localStorage 风格） | 否决：US-108 明文禁止；分叉后无人知道哪份算。 |
| 只存"当前值"，不记 savedAt | 否决：US-110 要求"已保存版本"可区分；无 savedAt 时"已保存"无法证伪。 |
| 跟随系统由 renderer 读 `matchMedia` | 否决：US-111 要求 main 侧观察；renderer 观察会与主进程不一致。 |
| 无观察时按浅色兜底 | 否决：把未核验写成结论。 |
| 把外观卡放在后置只读面板 | 否决（被 026 的零控件断言当场判红）：外观是交互面，位置属个人资料/设置族。 |

## 后果

- 三条验收各有机器断言：两入口同值同变、写入只经一条路由、`savedAt` 缺失时无"已保存"字样、
  失败回退到已保存值、跟随系统未观察时显示"未核验"、无快捷键/语音/布局/浏览器控件。
- 偏好记录与草案、待继续记录共用同一密封实现；三族记录没有一条走明文。
- 已知未闭：真机 Electron 未跑（`nativeTheme` 观察在测试里以注入值证明）；八项外观清单的其余五项
  （FW-039/US-220 扩围）不在本票，等 047。

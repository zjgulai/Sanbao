# ADR-0261 · UI-DECISION-01：renderer 采用 Sage-owned React 19 + esbuild（单文件内联、CSP 零变更）

- 状态：accepted（2026-10-04）
- 日期：2026-10-04
- 决策者：用户（lute，2026-10-04 裁决「同意B,P1开工」：采用 B＝React＋esbuild＋jsdom，P1 基础设施开工）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-04-renderer-stack-decision.md)
- 相关：[ADR-0254](ADR-0254.md)（D5 重决策触发）、[ADR-0260](ADR-0260.md)、[UI 一致性合同](../specs/2026-09-27-sanbao-to-sage-ui-consistency-contract.md) §6 决策 6、ADR-0014（门禁与豁免只减不增）

## 背景

framework-free renderer 已到 `renderer.ts` 7,433 行＋`component-renderer.ts` 866 行（内联 client script 与全部 CSS 都在单一模板里）；批次 12（视觉标度）与批次 13（导航六项）的每次改动都只能在这份巨型模板内做精确字符串手术，复杂焦点、可组合工作台与后续 13 个 adapt 状态的逐条迁移会持续放大该成本。ADR-0254 D5 已要求进入复杂可组合或可写工作台前重新完成 renderer 技术决策；UI 一致性合同要求「选择 React 及具体版本，或给出不采用 React 的同等可维护方案」，并列构建工具、package/lockfile、CSP/asset、测试环境的精确文件范围。2026-10-04 的决策包 Note 给出 A（维持 framework-free）/ B（Sage-owned React＋esbuild）/ C（其他自研组件层）三案与合同七项必答；用户裁决采纳 B 并授权 P1（依赖与 lockfile 变更）开工。

## 决策

1. 采用 B：Sage-owned **React 19**（react/react-dom 19.x）＋ **esbuild** 单文件 bundle ＋ **jsdom** 组件测试环境。A 案否决（7.4k 行模板的改动成本已实证，合同判定不适合 206 状态规模与复杂焦点管理）；C 案否决（无更低维护成本且离原型证据链更远）。
2. 精确版本在 P1 开工时按 registry 现查并以 `-E`（save-exact）钉死，落点为 `apps/sage-shell/package.json` 与 `apps/sage-shell/pnpm-lock.yaml`——**壳是独立 pnpm 项目；根 `pnpm-lock.yaml` 只承载根包，不改**。依赖全部只入 devDependencies（构建期/测试期），不进运行时 profile。
3. **CSP 零变更**：bundle 以 `export const SAGE_APP_BUNDLE = "<JSON 转义后的单文件脚本>"` 产出，由 `renderSageDocument()` 内联进同一文档——现行 `script-src 'unsafe-inline'` 已容许；`SAGE_DOCUMENT_CSP` 与 `host/assets.ts` 均不改。出现体积/调试需求时另开「服务化」票（届时才动 CSP `script-src 'self'` 与 assets 路由）。
4. **构建链**：`tsc` → `scripts/build-renderer.mjs`（esbuild JS API，入口 `src/product/app/main.tsx`，单文件输出、无 code-splitting、无 dev server、不引入 Vite）→ materialize；`HOST_LIB_FILES` 增 `product/app-bundle.js`；源码侧保留同形状占位 `src/product/app-bundle.ts`，使无构建产物时 `tsc --noEmit`、vitest 直读与门禁仍然成立。
5. **测试纪律**：既有 Electron-vitest＋两套窗口探针＋Fake DOM 壳合同测试原样保留为集成/结构层；React 组件级测试新增 `test/product-app/**`（per-file jsdom 环境注释）；**Fake DOM 不接 React**；逐区迁移期间真实 Electron 窗口探针＋1440 截图是可视/行为主判据。
6. **strangler 分阶段迁移**：P1 基础设施（不接管任何区域）→ P2 事项工作台区（main+rail）→ P3「已接线操作面」卡片群 → P4 其余面板。同一区域**单一 owner**；每阶段单提交可回滚；回滚不触 ViewState、路由、authority 与 CSP。
7. **边界保持**：`theme-tokens.ts` 仍是唯一 token owner（React 只消费 `--sage-*`/`--sage-density-*` 与既有 class，不引入 CSS-in-JS 第二色彩/间距家）；fixture 边界（`SAGE_FIXTURE_PROJECTION`/stage、source badge、fail-closed 首帧）不动；`renderSageDocument()` 最终收缩为「骨架＋fail-closed 首帧＋内联 bundle＋挂载点 `#sage-app-root`」，`/.sage/*` 接缝与严格校验顺序保持。
8. P1 票内同步更新 `.birdview/architecture.json` 的 renderer ownership，并先出文件级计划再动产品源码。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| A. 继续 framework-free | 否决：7.4k 行模板改动成本已实证过高，合同判定不适合 206 状态规模、复杂焦点与可组合工作台。 |
| B. React＋esbuild＋jsdom（采纳） | 组件模型与 Sanbao 原型证据同构、可组合；内联路径零 CSP 变更；代价＝6 个 devDependency＋构建链一步。 |
| C. lit/solid 等自研组件层 | 否决：相对 B 无更低维护成本，且离原型组件模型的证据链更远。 |
| Vite / dev server | 否决：单文档本地协议不需要 dev server；保持单文件输出最短链。 |
| 服务化 bundle（`script-src 'self'`） | 延后：本轮内联＝零 CSP 变更；服务化另开票。 |

## 后果

- P1（依赖＋构建脚本＋占位模块＋挂载点＋守卫 spec）2026-10-04 同日开工；不接管任何现有区域，窗口探针与全量套件保持全绿。
- 内联 bundle 抬高文档体积（React 19 生产构建预计 gzip 前 ~130–180KB，本地协议一次性加载可接受）；体积上限进 P1 守卫 spec。
- react/react-dom 代码随 bundle 分发，MIT 许可须进 `THIRD_PARTY_NOTICES`；esbuild/jsdom 仅开发测试期使用。
- 双测试环境（Electron-vitest 默认 + jsdom 局部）共存纪律：目录分离、per-file 环境注释。
- 未决：P2 起点（推荐工作台区）未显式裁决，留待 P2 开工前确认；完整 Qoder UI/UX 13 个 adapt 状态的迁移继续按一致性合同逐条推进。

# ADR-0081 · 图标有两个家：Finder 图标对了，不等于 Dock 图标对了

- 状态：accepted
- 日期：2026-09-13
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-13-runtime-icon-second-home.md)
- 相关：ADR-0080（同一场会话的另一半：那条守「判据收成一家」，本条守「品牌的两个家」）、
  ADR-0063（签名身份与 TCC 授权延续）、ADR-0068（重签与「假的已开启」）、
  ADR-0008（凭证与私钥不落仓库）、总账 P-02（仪器假绿）、P-07（一条事实多个家，只改了其中一处）

## 背景

品牌这条事实在 app 包里住了**两个家**，而 `brand-replay.sh` 长期只守了其中一个：

| 家 | 谁在用 | 第 4 块之前的状态 |
| --- | --- | --- |
| `Contents/Resources/icon.icns` | **Finder**、访达信息面板、`lsregister` 注册的图标 | ROOT 品牌（一直是对的） |
| `Contents/Resources/app.asar.unpacked/build/{app-icon-mac.png,app-icon.png,tray-icon*.png}` | **Dock 与菜单栏托盘** | **官方原样**（从未被品牌化） |

第二个家不是「补充」，它是**覆盖**：`dsh-plugin-desktop` 在启动时显式改图标——

```
const iconFilename = runtime.platform === "darwin" ? "app-icon-mac.png" : "app-icon.png"
const iconPath = fileURLToPath(new URL(`../build/${iconFilename}`, …))
app.dock?.setIcon(icon)          // electron-runtime 的 MacPlatformStrategy.configureApplication
```

于是症状极具欺骗性：**Finder 里是 ROOT、Dock 里是 DSH 原生**，而 `brand-replay.sh --check`
报 `BRAND ALL VERIFIED`——检查只覆盖了其中一个家（P-02 仪器假绿 + P-07 一条事实多个家）。
读数上它甚至看得出来：`app-icon-mac.png` 是 2.2 MB 的官方图标，而 ROOT 图标只有 47 KB。

同一批字节还有第二个入口：**Dock 图标的缓存**。换了字节而 Dock 仍显示旧图是常见形态，
所以落笔之后要 `touch` bundle + `lsregister -f` + `killall Dock` 一起刷。

而 `app.asar.unpacked/**` 在**代码签名封条之内**：就地改它 = seal 破损。seal 破损不只是
「签名难看」——TCC 判定要求时做代码有效性校验，seal 一旦坏了，已授的辅助功能 / 屏幕录制
会被**静默拒绝**（ADR-0068 的「假的已开启」形态）。所以补落已装 app 时必须用**同一个身份**
重签（指定要求是 `identifier + certificate leaf`，与字节无关，故授权延续，ADR-0063）。

## 决策

1. **运行时图标资产入库**：`packaging/assets/brand-icons/`（7 个 PNG）。与 `app-icon.icns`
   同一模式——真相源在 `.dsh-root-brand-preview/root-icon/`（不进仓库），仓库里放它的**可分发副本**。

2. **`brand-replay.sh` 第 5 块**用一张三列表 `ICON_PAIRS`（**目标 : 资产 : 尺寸**）同时管核对与落笔：
   `--check` 报 `DRIFT`、`--apply` 落笔前**量目标的尺寸**并拒绝与声明不符的
   （尺寸不符意味着基座换了图标规格，静默覆盖会把 Dock 图标换成一张模糊图），
   **资产缺失判红而不是静默跳过**（P-02：读不到不等于合格）。

3. **资产随包分发**：`assemble.sh` 在签名前把 `brand-icons/` 拷进载荷 `tools/`，并以
   `BRAND_ICONS_DIR` 显式把**仓库侧**资产传给重放脚本——不让同一批字节在仓库里存第二份（P-07）。

4. **门禁 `brand-icons`** 守那张表的**第三列**：`--apply` 量的是**目标**尺寸，**资产自己错了
   没人管**——512×512 的资产配 1024×1024 的声明，目标与声明相符、`cp` 照落，Dock 图标成一张
   放大的模糊图，而**所有读数都是绿的**（与 P-02 同一形状：仪器量错了对象）。判据：
   表 ↔ 资产目录**两向**逐名对照（少一个多一个都判红）、资产的实际像素 = 声明像素
   （**直接读 PNG 的 IHDR**，不依赖 `sips`/`file`——它们不可用时会让判据静默变成「没什么可比的」）、
   目标名唯一、以及动态半核对已装 app 里目标文件名是否还在（基座改了名字，表就过期，
   而过期的表要到装配时才失败）。射程与分母常显；目标侧不在射程时报 `skip`，静态半照常说话。

5. **`refresh-app-brand.sh`**：把品牌补落到**已安装**的 app 上并**重签**，让用户不必等下一版重装。
   动手前必须先确认没有实例在跑——判据**不在这里**，它调 `dsh-running.sh`（ADR-0080），
   拿到 `4`（判不了）时中止。`--check` 只读，不受这道闸限制。

## 备选方案

- **只品牌化 `icon.icns`（维持现状）**。否决：Dock 与托盘才是用户日常看到的那张图，
  而 `setIcon()` 会把它覆盖掉——「品牌化了」这句话在一半的面上是假的。
- **用 `sips -g pixelWidth` / `file` 读资产尺寸**。否决：外部工具不可用时判据会变成
  「读不出 → 无违规」，正是本项要防的那种静默。PNG 的 IHDR 就在第 16–24 字节，直接读。
- **把资产放在 `dsh-patches/brand-icons/`**（与重放脚本同目录）。否决：`dsh-patches/` 放的是
  补丁与脚本，图标资产与 `packaging/assets/app-icon.icns` 同类，放一起才只有一个「资产在哪」的家。
- **让 `refresh-app-brand.sh` 自己实现「在不在跑」**。否决：那会是同一条判据的第三个家——
  实测它原来的 `pgrep -f` 版本在 DSH 运行时**没有拦住**（ADR-0080 的背景）。
- **只在装配时重放，不做已装 app 的补落**。可行但差：本机与已交付的 2.3.3 用户要等下一版
  才看到 Dock 图标变对，而这次修复的可见收益正是「Dock 里那张图」。

## 后果

- **实测现状（本机，2026-09-13）**：`refresh-app-brand.sh --check` 报 9 处 OK
  （`icon.icns` + 8 个运行时图标），`BRAND ALL VERIFIED`——Dock / 托盘那一套已是品牌态。
- **闸有效**：在 DSH 运行中跑 `--apply`，退出码 **3**、在**任何写入之前**拒绝，
  已装 app 的图标字节 sha256 前后相同（一个字节未动）。这正是它前身那条 `pgrep` 判据
  没能做到的事——当时它读数为空，`--apply` 照跑了下去。
- **升级即自愈**：基座升级会覆盖 `build/` 那一套字节，`--check` 随即报 8 处 `DRIFT`，
  按提示跑 `--apply`（装配时由 `assemble.sh` 自动重放）。
- **代价**：门禁不核「图案对不对」，只核尺寸与清单。图案对不对是人的判断——`--check` 用
  **哈希**判定目标是否等于资产，那才是「品牌态」的判据。
- **代价**：`.icns` 那一半家不在 `ICON_PAIRS` 里（ICNS 容器的尺寸规格由容器自己描述），
  本项不覆盖它，已在模块注释里明写。

**诚实划界（判不出的部分）**

- **Dock 上现在显示的是哪张图，没有任何静态判据能回答。** 它由 LaunchServices 缓存与
  `app.dock.setIcon()` 的运行时调用共同决定；能判的只有「磁盘上的字节是不是品牌态」
  （哈希）与「缓存刷新动作有没有跑」（脚本步骤）。与 ADR-0078 同一处边界。
- **`sips` 读尺寸这一类外部工具**在本项里被刻意绕开，但**重放脚本自身**仍用 `sips` 量目标尺寸
  （它在装配机上跑，且失败时会判红而不是跳过）。

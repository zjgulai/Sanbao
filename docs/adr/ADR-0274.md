# ADR-0274 · 首页耐用事项创建：Sage 自有权威存储成为真实托管方（T04）

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：T04 主链推进，选定「落 Sage 自有权威存储」落点）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-home-durable-matter-custody.md)
- 相关：[ADR-0161](ADR-0161.md)（Sage 拥有权威事件存储、main 是唯一正常写入口、创建只接受 `not-exists`）、[ADR-0200](ADR-0200.md)（步骤 3 接真存储）、[ADR-0201](ADR-0201.md)（创建分支语义；本 ADR 修订其**托管落点**条款）、[ADR-0209](ADR-0209.md)（草案是本设备对象）、[ADR-0211](ADR-0211.md)（建项三态与核对）

## 背景

T04 验收要求「真实 createMatter custody 与 idempotency receipt 落地；新进程可读回已受理事实」。ADR-0201（2026-10-02）把托管定义为服务端职责并否决了当时「自造本地托管」——其前提是托管被设想为一个尚不存在的外部服务。随 Sage 自有桌面主链确立（ADR-0161：Sage 拥有权威库、Electron main 是唯一正常写入口、创建只接受 `not-exists` append；ADR-0200：同一库已成为步骤 3 的真实读 provider），产品内已不存在别的托管候选：创建若不落同一库，matter 列表（源自草案 receipt）与步骤 3 读都将永远空转，T05/T06 无限期 blocked。用户裁决：托管方落在 Sage 自有权威存储。

## 决策

1. **D1 托管方 = Sage 自有权威事件存储**：新增 main-owned `src/main/matter-custody.ts`，以 `openBusinessMatterEventStore` 的 `not-exists` append 落地创建（matter-created + 首个 revision-entered，单事务批次）；ADR-0201 的其余语义（独立创建分支、缺席/拒绝码、回执才成功、不本地私铸双主）全部保留，仅其「本地执行库不是建项落点」的落点条款由本条取代。
2. **D2 正式身份与幂等来自服务签发的 correlation**：`matterId = matter:<correlation>`、`revisionId = revision:1`、`appendId = draft-conversion:<correlation>`；同一尝试的重复调用由 store 的 append 指纹幂等（`replayed`）结算，冲突类结果必须经流内证明（load 比对 creation eventId 与 goal）才可回执，绝不重复建流；renderer 的 `draft:<draftId>` 候选永不成正式身份。
3. **D3 回执只从提交证明产生**：`appended`/`replayed` 或经流内证明的冲突 → `{receiptRef}`；`commit-unknown` → `{unknown:true}`（outcome-unknown，不可重试）；`storage-busy`/`invalid-request`/断言式拒绝 → `{denied:'custody-unavailable'}`（可重试未就绪）；打不开/已关闭/`blocked` → `undefined`（provider 不可用，返回形状与步骤 3 端口同一纪律）。
4. **D4 reconcile 只读流内事实**：按 correlation 派生正式 id 后 `load`；已证明 → `settled`；`not-found` → `unknown`（ADR-0211 D3「查不到仍未知」）；存储不可用 → `unknown/'custodian-query-unavailable'`。生产 index 的占位查询（恒答 `custodian-query-unavailable` 的 stub）退场，该占位不得回到 composition root。
5. **D5 门禁登记源码事实并同步矩阵改述**：route-authority 门禁新增 custody 事实位（index 构造 provider 与两条接线、app-service 显式 options-gated 合并、custody 模块的 not-exists/appendId/correlation 派生/`commit-unknown→unknown`/不可观测查询保持 unknown、占位码不得在 index 出现），附逐条具名突变自测；matrix 的 `draft/convert` 与 `draft/reconcile` 行 `runtimeLevel` 文本同步改述（合规分类与计数不变）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 维持 ADR-0201 原样（托管继续等待服务端） | 否决：产品内不存在该服务，主链 T05/T06 无限期 blocked，「新进程可读回已受理事实」无从落地。 |
| 维持占位并只做 fixture 级「创建」验收 | 否决：把 fixture / placeholder 冒充真实 custody，属本仓反复禁止的失真（P-01/P-02 家族）。 |
| 由 renderer 或 Host 侧落库 | 否决：ADR-0161 明文——main 是唯一正常写入口；renderer、Host 与插件不得拥有或修改该库。 |
| 用草案 id 当正式 matterId | 否决：renderer 侧候选不是托管身份；正式身份从服务签发 correlation 派生。 |
| 冲突结果直接回新回执 | 否决：未证明字节同一就可能把别次/他人的提交当成本次成果——冲突必须经流内证明或诚实 `unknown`。 |
| 创建修订带 `supported` 证据以允许立即运行 | 否决：草案确认不是已观察证据，标 `supported` 是假话；用 `insufficient` 记录起点并靠新修订补证据。 |

## 后果

- 首页确认转换第一次有真实终态：成功 = 权威库中两条事件 + 草案上的 receipt；未登录/策略拒绝零写入；unknown 只留核对（不重复建项）。
- 创建修订携带 `insufficient` 证据（草案确认自身）且不带 actionPolicies：在补证据/政策的新修订前该事项不可运行——这是诚实起点，不是缺省。
- 步骤 3 读与创建写共享同一权威库：新进程可读回已受理事实；草案列表 receipt、会话（T05）挂载与 rehydrate 三者闭环。
- route-authority 门禁以源码事实锁住接线：占位查询回潮、合并降级、append 语义漂移（`not-exists`→`exact`、`commit-unknown`→回执）都会具名红。
- T04 完成不推进 206 矩阵（0 行 owner）；真实登录链（T02）、T05/T06 与 DMG-06 按各自票据验收。

# ADR-0281 · C2A canonicalization v2：机器码 artifact 摘要吸收签名变换（含归零 `__LINKEDIT` vmsize）

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：要求打通内测 DMG 链与打包验收）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-10-runtime-artifact-attestation-signing-normalized.md)
- 相关：[ADR-0167](ADR-0167.md)（C2A 安装时 attestation）、[ADR-0271](ADR-0271.md)（签名归一化装配摘要先例）、[ADR-0279](ADR-0279.md)（内测 DMG 链）、[ADR-0280](ADR-0280.md)（首个真实发布件）

## 背景

首个打包验收（2026-10-10）在 installed-copy 首启时红：`RuntimeArtifactAttestationError: installed runtime artifact set no longer matches its attestation`。全树逐文件对照（27,716 文件）证明差异**恰好**是 13 个被 sign 阶段重签的 Mach-O 原生件——C2A `artifactSetDigest` 在 producer materialize 时对**签前字节**计算，而打包链在 assemble/sign 阶段改写这些字节（`codesign --force` 覆盖 vendor 签名）。更细一层：`codesign --remove-signature` 恢复签名外全部字节，但把 `__LINKEDIT.vmsize` 留在签名期间的布局值（10/13 文件与输入仅此 1–2 字节之差）。即 C2A 摘要按现状**不可能**跨「producer → 打包签名」存活；这不是签名错误或安装错误，而是两条既有事实的冲突：C2A canonical identity 与打包链的合法签名变换。

## 决策

1. **D1 canonicalization 升 v2**：`sage.runtime-artifact-attestation-canonical-json.v1 → v2`。`canonicalizationVersion` 是既有版本化接缝；旧 v1 attestation 在 v2 代码下解析即拒绝（fail closed，不静默错配），打包链必须重跑 producer 记录 v2 摘要。
2. **D2 Mach-O 逐文件归一化**：摘要扫描遇到薄片 64 位 LE Mach-O 时，对私有副本执行 `codesign --remove-signature`（未签名视为 no-op），再把 `__LINKEDIT.vmsize` 归零后哈希；非 Mach-O 文件原样哈希，`executable` 位、路径、symlink 拓扑、installer metadata 语义全部不变。归一化只在扫描的私有临时目录进行，源树不被触碰；TOCTOU 快照双重校验保持。
3. **D3 非薄片 fail closed**：解析器只接受薄片 64 位 LE（打包链以 validate-mach-o 保证 arm64-only）；其它形态抛 `artifact-normalize-failed`，不猜、不跳过。
4. **D4 与 packaging 侧同语义、各自钉住**：`packaging-sage` 的 `signing-normalized-tree.mjs` 与本模块是两份部署物（无共享包），归零规则逐字相同并各自持有回归测试；跨包引用逐条由测试语义钉住。
5. **D5 回归机制**：新增 spec「重签保持同一 content identity」——夹具先 `--remove-signature` 到无签名基线（同种 ad-hoc 重签是字节确定的，会假绿），签名后**显式断言字节已变**，再断言摘要不变；内容篡改仍必须改变摘要。既有「非 pristine」「drift」等守卫语义不变，仅版本字符串同步。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 打包链在签名后重写 attestation / template manifest | 否决：写入者从 producer 变成 packager，还需级联重写 profile-manifest 与 sage-build.json 的归一化摘要，破坏「attestation 是 producer 的安装时观察」并产生自引用链。 |
| 校验器跳过 Mach-O 条目 | 否决：把 native 闭包（恰恰是运行时主体）从内容身份中移出——覆盖损失大于归一化。 |
| attestation 保持 v1、只在打包路径容忍错配 | 否决：同一根因在 dev 与 packaged 两侧分叉语义，且静默掩盖真实漂移。 |
| 只依赖 bundle seal / signing receipt 证明 Mach-O 完整性 | 否决：seal 证明签名有效，不证明内容与 attestation 计划一致；二者职责分开（ADR-0167 语义）。 |

## 后果

- C2A content identity 对「合法签名变换」不变：producer 记录、打包签名、安装时 fresh scan 三方重新一致；drift 检测仍覆盖全部非签名字节与 topology。
- 摘要不再绑定签名字节本身——这是有意的语义收窄：签名有效性与叶身份由 bundle seal 与 signing receipt（`sage.local-signing-receipt.v2`）负责，符合「容器验证与叶身份验证分开」。
- v1 摘要（含已产出的 profile template 与 sage-build metadata）全部作废：内测链必须重跑 `produce-inputs → assemble → sign`。已产出的 `Sage-0.1.0-internal-arm64.dmg` 保留为历史读数（v1 摘要），不作为 v2 验收证据。
- dev materialize 链（无签名）行为不变；机器码文件在两边都为归一化摘要，写读一致。

# ADR-0091 · 「三无 · Agent全栈专家」preset 与全栈目录的节点轴重建

- 状态：accepted
- 日期：2026-09-16
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/capability/2026-09-16-agent-fullstack-preset-and-node-axis.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0015（非机械改动必须留痕）、ADR-0022（岗位头像走官方 `icon` 字段）、
  ADR-0023（删除被会话引用的 preset）、ADR-0024（上下文压缩加固）、ADR-0083（技能开关写在 SKILL.md frontmatter）、
  ADR-0089（全栈线 40 条入库）、ADR-0090（品牌图标的下装颜色）、
  总账 P-02（仪器假绿）、P-03（「知道」没有变成「拦住」）、P-04（写了但从没跑到）、P-07（一条事实多个家）

## 背景

`创造模式（压缩加固）`（id `lute-cordis`）是发行 `cordis` 预设的本地副本，唯一差异是把压缩后端换成
`dsh-dcp`。它解决的是「长中文会话对抗上下文溢出」，但它**没有角色**：模型不知道自己该按什么链路干活，
技能目录也仍然是全量 1700+ 条。

用户的要求是把这条 preset 变成一个有名字有执业准则的全栈专家，并指名两个外部来源：
`zjgulai/vibecoding_config`（M00–M13 的全生命周期 Prompt Chain + Coding Agent 配置系统）与
`phuryn/pm-skills`（产品侧技能集）。于是问题从「换一个压缩后端」变成三件必须同时成立的事：

1. **人格**要有可执行的准则与派活表，而不是一段形容词；
2. **技能目录**要收窄到这条链真正用得上的那一批；
3. **页面**上看到的组织方式必须与人格里那张派活表同轴，否则模型说「走 M09」时人在页面上找不到 M09。

调研阶段先纠正了三处自己写错的事实（都被实测推翻，逐条记在 Note 里）：`retro` 并非 STUB、
`implement-spec` 不是 `write-spec` 的重复、42 个 `commands/*.md` 合计 175KB 不能折叠。
最终入库 **138 条**（存量 70 + 新增 68）、白名单 **89 条**覆盖 M00–M13 十四个节点。

## 决策

1. **preset 的身份、人格与开关。** `agent-fullstack` 以发行 `cordis` 组合为基座，只做三件事：
   persona 换成自己的行；压缩后端回到**官方** `compaction-basic`（`dsh-dcp` 私有键会被
   `validateKeys` 拒绝并让**整行不加载**，症状是「以为有压缩，实际没有」）；挂 `dsh-skill-subset`
   收窄到 89 条白名单并打开 `respectFileFlags`。

   `respectFileFlags` 是这条 preset 存在的**唯一理由**：它缺省 `false`，那一刻子集内每条技能都被强制
   `modelInvocable/userInvocable = true`，技能文件里的 `disable-model-invocation` 与 `user-invocable`
   完全失效，而加载、日志、页面读数一律正常（ADR-0083 那条用户状态被静默覆盖）。

2. **人格一份事实一个家：`SOUL.md`。** 人格正文的家是仓库内的
   `packages/capabilities/dsh-overseas-skills/presets/agent-fullstack/SOUL.md`；
   `agent.cordis.yml` 的 persona 行是它**渲染出来的物化副本**（`sync-fullstack-persona.mjs`），
   `verify-agent-fullstack.mjs` 用**同一个**渲染函数复算并逐字比对。

   门禁不只比字节，还独立断言：三无三条逐条在文、M00–M13 十四个节点逐条在文、`{{model}}`/`{{cwd}}`
   两个运行时占位符仍在、正文长度不低于下限、不是 P1 留下的骨架占位。理由：人格的腐烂形态是
   **完全不可见**的（加载、日志、页面读数全正常），而「源与副本一起被删」这种改法逐字比对挡不住。

3. **全栈目录的分组轴由「做法」改为「交付节点」。** 页面（技能中心 → AI全栈）原本按 8 个做法类分组
   （需求澄清 / 规格规划 / 架构设计 / 实现 / 质量排查 / 工程基建 / 协作复盘 / 写作内容），改按
   **M00–M13 十四个节点**分组，与 persona 派活表、白名单注释同轴。分组键 `m00`…`m13`。

   节点键与标题的唯一事实源是 `scripts/build-fullstack-catalog.mjs` 的 `NODES`，它派生三份产物
   （`fullstack-mapping.json` 的 `categories`、`manifest/fullstack-skills.json`、
   `manifest/taxonomy-v3.json` 的 `fullstackNames`）。`verify_static.mjs` 的判据**不写任何数字**，
   一律与 `NODES` / `mergeRows()` 对账 —— 数字写在判据里就是第三个家。

4. **`lute-cordis` 保留目录，只标为已退役。** 不删目录：`remove-preset.mjs` 的引用面预检实测
   **329 个会话**（302 个 subagent 子会话 + 27 个顶层，其中 16 个有人类用户消息、1709 条用户消息、400MB）
   的 `agentPreset` 指向它，删掉会让它们 resume 时 `agent-preset/not-found`——
   这正是 2026-09-15 发生过一次的事故。改动只落在 `preset.yml`：名字加「· 已退役」、
   描述写明被谁取代与保留原因、`order` 排到最后。

   之所以不能用「隐藏但仍可解析」这种更干净的做法：`@deepseek-ai/dsh-agent-presets` 的元数据 schema
   只有 `name` / `description` / `order` / `icon` 四个字段，**没有 hidden**。

## 备选方案

- **人格只写在 persona 行里**：DSH 预设加载器不展开任何 include，写在外面等于没写；但反过来只写在
  `SOUL.md` 里同样不行（人格不落到 persona 行＝不存在）。故取「源 + 物化副本 + 门禁」三件套。
- **人格只写在 `SOUL.md`、同步器由人手动跑**：那就退回「靠纪律守住只有机制能守住的东西」，
  且漂移的方向是静默的。故同步与复核共用同一个渲染函数，门禁 import 它。
- **把 M00–M13 的详细打法也塞进人格**：人格是每次请求都注入的常驻文本，
  节点级打法属于渐进式披露的那一层（对应 skill），常驻的只留路由表。
- **沿用 8 个做法类分组，只在标题里加 M 编号**：一个技能只落一个组，两套轴不可能通过改标题重合；
  且「grilling 属于需求澄清」与「grilling 服务于 M03」回答的是不同问题。
- **13 组（M01–M13，M00 不进页面）**：M00 的 4 条技能仍需落点，且白名单与 persona 都是 14 个节点。
  用户 2026-09-16 明确选择 14 组。
- **`--force` 删除 `lute-cordis`**：字面满足「归档」，代价是打断 329 个会话；用户选择保留。
- **先迁移会话里的 preset 引用再删**：要改 zstd 压缩的用户会话 JSONL，侵入性强，
  且 302 个子会话的父方未必都拿得到。

## 后果

**正面。**

- 模型与页面同轴：人格里的 M00–M13 就是页面上的十四个分组，白名单按同一组注释，门禁按同一组判。
- 人格从「埋在一个 500 行组合文件中间」变成可评审、可 diff、可回滚的一篇 Markdown。
- 全栈线从 8 组 / 70 行变成 14 组 / 138 行，且**新增了三条此前不存在的判据**：
  分组头像必须存在且**互不相同**（`build_preset_catalog.py` 在缺键时会回落到出海线的
  `agent-tools` 头像——那不是空值，所以「是合法 data URI」这条判据看不见它）、
  分组轴与行数与事实源逐条对账、README 的条数与**组数**都必须等于实测值。
  此前全栈线的分组头像一条判据都没有。
- 14 枚节点头像在 `lib/catalog.js` 里烘进产物，页面不依赖品牌技能是否装在目标机器上（与层头像同法）。

**负面 / 代价。**

- `lute-cordis` 仍留在抽屉里（标着「已退役」）。这是引用面的代价，不是疏忽。
- 68 条新增技能没有各自的专属头像，页面回落到所属节点的分组头像；回落名单由
  `assign_lute_icons.py` 打印点名，不静默。
- 人格正文 4224 字符进入每次请求的 system prompt。取舍写在 Note 的「代价」一节。
- 本机 `~/.dsh/skills/lute-brand-icons` 的品牌清单从 310 枚变 324 枚（14 枚节点头像）。
  该目录**不在仓库、不在 git 下**，所以「谁跑一次 `scripts/build.js` 会不会把它们丢掉」只由
  `catalog.js` 同步追加来保证；`assets/preview-*.html` 仍是 310 枚旧版（未重跑预览）。
- **像素级视觉验收未做**：14 枚新头像只过了结构判据（品牌 9 条不变量、徽章图形确实画上、
  与重算逐字节相同），没有渲染截图或双主题预览。判据断言的是「合规」，不是「好看」——
  与 ADR-0090 的诚实划界同型。
- 页面生效需要**重启 DSH**：宿主在插件装载时 `import` 了 `lib/catalog.js`，本会话内改文件不会热更新。

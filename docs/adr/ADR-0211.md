# ADR-0211 · 建项的三态：尝试在发出前落盘、未知只给核对、失败可修正、取消不丢内容

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证并实施；"尝试先落盘"与"未知不可取消"是取舍）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-draft-creation-attempts.md)
- 相关：[ADR-0209](ADR-0209.md)（草案与回执）、[ADR-0201](ADR-0201.md)（建项走托管）、[ADR-0190](ADR-0190.md)（步骤不放宽）

## 背景

工单 003 的三条验收：未知态**只有核对**没有"重试建项"（US-119）、核对到已生效后列表**只出现一个**事项、
取消未提交确认**回到草案且内容不丢**（US-006）。001 已把命令结果的三态分类做好（unknown 显示核对、
隐藏重试），但**草案的建项路径**此前只把成功写回草案：失败与未知都只留在响应里，刷新即失。

## 决策

1. **D1 尝试先落盘**：确认时先在草案记录上开一条 `attempt {correlation, at, state:'pending'}` **再**跑
   流水线。崩溃/断电发生在"发出"与"应答"之间时，磁盘上仍留有"这个请求存在、结果未知"的事实（US-005）。
2. **D2 未知是一等状态**：托管端口新增 `{unknown:true}` → 流水线以 `outcome-unknown`（**不可重试**）收口；
   草案的 attempt 记 `unknown`。未知态下确认入口被禁用且文案为"结果未知期间不重复建项"，
   **只出现核对入口**（US-119）。
3. **D3 核对问的是同一个请求**：`reconcileDraft` 用 attempt 里记下的 `correlation` 向托管侧查询；
   查到已生效 → 写回执并把草案置为 `converted`（列表因此只有一条）；查不到或没有查询端口 →
   仍是 `unknown`（**绝不自动判定为已生效**）。过期应答不得改写更新的 attempt（按 correlation 对号）。
4. **D4 失败可原地修正**：`failed` 是"确定没有生效"，因此确认入口恢复可用——用户改完字段再确认，
   这是**新的一次尝试**（旧 attempt 被新的 correlation 取代），不是未知态的重放。
5. **D5 取消只取消未提交的确认**：`cancel` 仅清除 `pending` 的 attempt；字段、前史、勾选、澄清
   一律不动（断言）。`unknown` 不允许取消——请求可能已经在托管侧生效，抹掉它等于把"可能已存在"变成
   "已不存在"。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 未知态给"重试建项" | 否决：US-119 明文禁止；重放会造出第二个事项。 |
| 未知态允许取消 | 否决：抹掉的可能已生效的请求，事实会丢。 |
| 核对查不到就判定失败 | 否决：查不到是"还不知道"，不是"没发生"。 |
| attempt 只留内存 | 否决：崩溃/重开即失，"同次请求关联"无从谈起（US-005）。 |
| 失败后禁止再确认（要求新建草案） | 否决：US-005 要求"失败可在原工作面修正"。 |

## 后果

- 三态各有入口与断言：未知→只有核对（且文档里不存在"重试建项"按钮）；失败→修正后再确认；
  pending→等待或取消（内容不丢）；核对到已生效→列表只有一条。
- `reconcileDraftCreation` 在 main 侧**暂无真实托管查询端口**，因此生产里的核对诚实地答"仍然未知"
  （`custodian-query-unavailable`），不假装查到。
- 已知未闭：真机端到端未跑；"创建中"没有超时自动转未知（当前由托管端口返回 unknown 或由用户点核对）。

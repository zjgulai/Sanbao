# ADR-0226 · 行动项、要求更正与项目汇总：Sage 自建对象、关联式更正、纯分组合并

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；D-060/D-057/D-089 与 FW-029 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-action-items-corrections-projects.md)
- 相关：[ADR-0212](ADR-0212.md)（会话通道）、[ADR-0213](ADR-0213.md)（暂停与待继续）、[ADR-0224](ADR-0224.md)（确认机制）

## 背景

工单 028（FW-029，US-146~149）：行动项属于事项、可分派与跟踪，**不等同交付项、待办请求、工具
调用或一次运行**（D-012/060）；执行记录可回看并**关联当时依据**；「另补要求更正」以关联原要求
的消息＋生效回执表达、不覆盖不重放（D-057）；项目视图只做归属与汇总、**不自动改变主责、可见
范围或事项事实**（D-007/016/089）。验收：①要求更正可追溯到原要求与生效回执；②项目汇总不自动
共享或改变主责（有断言）。边界：不做分派给他人、跨项目批量改属、项目级权限继承（矩阵首版不做）。

基座事实：无 action-item / project / correction 概念——三者都是 Sage 自建对象。已有可复用的真实
读数：会话发送的 `accepted/deferred/refused` 受理结果（005）、待继续/队列项的
`pending/submitted/consumed` 状态（006，**submitted=仍在队列、consumed=已离开队列被基座取走**）。

## 决策

1. **D1 行动项=事项内工作记录（US-146/147）**：新纯模块 `main/action-items.ts`。状态机
   `open → in-progress → done`；**「标记完成」只是状态变更**：不追加执行记录、不发任何消息、
   不触达任何其他存储（有断言）。`登记一次执行` 追加**执行记录并冻结当时依据**（记录登记时的
   revision + title/note 快照）；`update` 把 revision+1，旧记录永不改写。v1 无 reopen
   （done 后 start=拒绝 `action-done`）。视图九键钉住，不含 receipt/delivery/toolCall/run 词汇；
   记录仅本运行存在（如实文案；持久化后置）。
2. **D2 更正=关联原要求的新消息（US-148，D-057）**：`submitCorrection` 把**新文本**经会话通道的
   同一发送路径发出（受理≠执行≠生效沿 005/006 既有合同），**原要求绝不重发**；一次更正恰好一次
   发送。回执三态**只能从真实读数升级**：`accepted`→已接收（requestId，受理≠生效，永不冒充实效）；
   `deferred`+队列项状态→待应用（在待继续/队列中；无消费读数时也停在待应用）；队列项
   `consumed`→**已生效**（基座消费读数——不撤销既有外部效果、不重放旧动作）；`refused` 原码记录、
   **不重试**。原要求以 `{text, at}` 关联留存，视图同时呈现两者。
3. **D3 项目=纯分组（US-149，D-089）**：`main/matter-projects.ts`——项目只有 name/createdAt/refs；
   事项**最多一个**项目，变更=move 并保留 trail（action/from/to/at，D-089 当时依据）；汇总按 ref
   引用**同一事项记录、绝不复制事实**（视图键钉住，无 responsibility/visibility/revision 字段）。
   归属变化**只动自己**：读态逐槽断言——matter/draft（含主责字段）/matterLinks/readout 等
   byte-equal，仅 projects 槽变化。
4. **D4 路由与槽**：`/.sage/action-items`（create/update/start/complete 命名动作，精确体）、
   `/.sage/corrections`、`/.sage/projects`（create/assign/unassign）；状态槽 `actionItems`、
   `projects`；未接线时各码如实（`action-items-unavailable`/`projects-unavailable`）。
5. **D5 首版不做**：分派给他人（矩阵点名）；跨项目批量改属（无批量路由，单事项一体）；项目级
   权限继承（项目无任何权限字段）；行动项持久化（本运行；与 013 引用同级的诚实边界）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 完成时补一条"成功"执行记录 | 否决：D-060 点名"不能仅凭勾选行动项就伪造执行成功"。 |
| 更正=编辑原消息本体 | 否决：D-057 要求保留原消息、以关联新要求表达；编辑面另有其票。 |
| 更正未生效前自动重试 | 否决：不重放未知结果；拒绝原码落账。 |
| 回执直接用 send accepted 当"已生效" | 否决：D-012 点名接收≠生效；升级唯一证据=队列消费读数。 |
| 项目存事项快照字段 | 否决：D-089 汇总引用同一记录；快照会复制事实并静默腐化。 |
| 一个事项可属多项目 | 否决：D-089 明确"最多一个"。 |

## 后果

- 验收两条各有机器断言：更正可追溯（original {text,at} 留存 + 回执按真队列读数升级，route 层
  用真 pending store 驱动 deferred→queued→consumed）；归属不改变主责/可见范围/事实（readState
  逐槽 byte-equal，draft.responsibility 原样）。
- 语义区分有断言：完成不追加记录、不发消息；视图键钉住无交付/工具/运行词汇；页面文案明说四类
  对象互不替代。
- 已知未闭：行动项/项目/更正是本运行记录（持久化后置）；"分派给他人"与项目权限后置；真机未跑。

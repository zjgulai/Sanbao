# ADR-0170 · C2C same-generation observation seam：bridge-owned 受控只读端口

- 状态：accepted（2026-09-29）
- 日期：2026-09-29
- 决策者：用户（lute）
- 决策记录：[External Capability Evidence 与 seam 决策](../notes/proposed/architecture/2026-09-28-external-capability-evidence.md#10-c2c-seam-decision-revision-20)
- 关联：[ADR-0169 · External MCP Capability Evidence](ADR-0169.md)、[ADR-0168 · Host live inventory projection](ADR-0168.md)、[ADR-0165 · Sage Compatibility Authority](ADR-0165.md)

## 背景

`WT-02C.2C.1 revision 19` 已完成无 I/O 的 candidate descriptor / canonicalization kernel，但 `WT-02C.2C.2` 还必须从**执行中的同一 MCP connection generation**取得完整、可失效的 `tools/list` 观察。只读取已经注册到 `ctx.tools` 的公开工具会丢失 raw name、分页边界、raw output schema 与 bridge projection / enforcement；Electron main 另开 `Client` 又不能证明它与真正执行的连接是同代。

本次只读核对了 pinned `@deepseek-ai/dsh-mcp-client@0.1.5-rc.2` 的发布包、类型声明、实现与项目 seed lock：

- 包的公开导出只有 `Config`、`apply`、`inject`、`name`；`ConnectionHandle` 只有 `ready` 与 `dispose`；
- `Client`、transport、`startConnection`、`syncTools` 与分页请求均由桥内部持有，`tools/list` 完成后只留下 `ctx.tools` 注册结果；
- `notifications/tools/list_changed`、reconnect、close 与 generation 队列同样由桥内部串行管理；
- 发布包声明的 `src` 导出路径在实际 tarball 中没有可供 Sage 直接导入的源码。

官方 MCP Tools 合同要求客户端支持 `tools/list` cursor pagination，并允许服务端发送 `notifications/tools/list_changed`；因此 registry 结果不能反推出完整 raw contract 或当前 generation。

## 决策

1. **唯一目标选择 bridge-owned seam。** 未来由 pinned bridge 的正式源码 / 正式发布版本暴露受控只读 observation port；Sage 不创建第二条 MCP 连接，也不从公开工具注册表反推 raw contract。
2. **桥继续拥有连接与生命周期。** bridge 继续独占 `Client`、transport、分页队列、`list_changed`、reconnect、close 与 tool-registration swap。seam 只能接收结构化、只读、同代的观察，不得取得 `Client`、transport、registry disposer 或执行函数句柄。
3. **seam 的最低合同。** 后续正式 API 至少需要在同一 generation 内提供：
   - 不带 cursor 的第一页与后续 opaque cursor 原样分页结果；
   - 收齐全部页后、tool projection / registry swap 前的完整 raw snapshot；
   - 不暴露 secret、raw environment、机器路径或原始异常文本的稳定失败状态；
   - opaque connection-generation reference 与 protocol/server facts；
   - `list_changed`、transport close、reconnect、dispose、分页失败与超限等立即失效事件。
4. **正式 release 才能改依赖边界。** 若 pinned bridge 没有该 seam，必须先在其源码仓 / Sage-owned 可复现 fork 中实现并发布一个明确版本，再由独立 ticket 更新 dependency specifier / lockfile。当前不直接改 `node_modules`、vendor tarball、已解析 store 或运行时 monkey patch。
5. **C2C.2 的关闭条件。** 只使用隔离 fake MCP server；证明完整有界分页、跨页 raw-name 唯一、空 / 重复 cursor、页数 / tool 数 / canonical bytes / deadline 上限、同代 snapshot、`list_changed` / close / reconnect 失效；`tools/call` 调用数必须为 0。没有正式 seam 与这些证据前，C2C.2 保持 pending / blocked，不得宣称 `ExternalCapabilityEvidence` available。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| Hash `ctx.tools` 已注册工具 | 否决；丢失 raw contract、分页、bridge projection / enforcement 与同代边界。 |
| Electron main 另开第二个 MCP `Client` | 否决；第二连接不能代表真正执行连接的 generation。 |
| Sage wrapper 复用 pinned bridge 公共 `apply` | 否决；公共 API 不返回 raw `Client` 或 snapshot，最终只能回到 registry 反推或另开连接。 |
| 直接修改 `node_modules`、vendor tarball 或运行时 monkey patch | 否决；不可复现、绕过 pin / lock 与 owner 边界，也无法形成可审计发布证据。 |
| 现在完整 fork / 替换 bridge | 暂不采用；只有正式 bridge seam 长期不可获得时，才另开 migration ADR，重新裁定连接 owner、包发布与兼容风险。 |

## 后果

- 正面：同一条执行连接仍只有一个 owner；raw observation、tool projection、reconnect 与失效事件不会被 Sage 旁路拼接。
- 正面：C2C.1 的 pure kernel 可以继续复用，而 C2C.2 的 I/O 只在正式 seam 和 fake-server 证据齐备后落地。
- 代价：C2C.2 暂时受 pinned bridge 发布能力阻塞；不能用“已经能列出工具”制造假绿灯。
- 代价：后续需要一个明确的 bridge release / fork 变更与独立 lockfile 验收；这不属于本决策批。
- 边界：本 ADR 不启用插件、不连接真实 MCP、不运行 `tools/list` / `tools/call`，不修改 v1 event schema、UI、Registry、Application Service 或产品调用面。

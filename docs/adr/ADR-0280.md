# ADR-0280 · target requirement 组件身份语法对齐运行时（首个真实发布件封存）

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：并行推进主链）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/security/2026-10-10-target-identity-grammar-alignment.md)
- 相关：[ADR-0276](ADR-0276.md)（候选线与发布流程）、[ADR-0278](ADR-0278.md)（首发发布件内容）、[ADR-0172](ADR-0172.md)（target 治理）、[ADR-0279](ADR-0279.md)（同次真实重观测）

## 背景

ADR-0278 的发布件只用夹具 descriptor 验证过。首次用**真实重观测**的 descriptor 调 `buildSessionPromptPublication` 时，C2.2T 内核以 `requirement-entry-invalid` 拒绝了发布件：V1 requirement 的 `COMPONENT_IDENTITY` 语法钉死「冒号后必须以 `sage` 开头」（`provider:sage-fixture` 等夹具时代的锚定），而运行时侧真实身份是 `provider:deepseek-official`、`model:deepseek-official/deepseek-flash`、`agent:@deepseek-ai/dsh-agent`、`preset:set`——**同一个稳定对的两半对身份语法各说各话**：V2 descriptor/语义侧一直接受裸字符串，V1 侧则拒绝了每一条真实身份。契约裂缝属夹具假设与真实发布输入之间的第一枚真实翻车。

## 决策

1. **D1 组件身份语法对齐运行时**：`COMPONENT_IDENTITY` 改为 `^[a-z][a-z0-9._-]{0,31}:@?[a-z0-9][a-z0-9._@/-]*$`——requirement 必须能逐字命名 sealed descriptor 命名的对象（含 scoped 包名与斜杠路径）；垃圾仍拒绝（小写 kind、非空余段、有界字符集与长度 128）。
2. **D2 策略身份语法不动**：`POLICY_IDENTITY` 保持 `:sage…` 治理命名空间（已发布的两份策略文档 `permission:sage.session-prompt` / `data-boundary:sage.model-egress` 均在语法内）；组件身份镜像运行时、策略身份属 Sage 治理——两类事实两种语法，此差异在代码注释中登记。
3. **D3 真实发布件封存**：用真实重观测 descriptor（`urn:sage:runtime-descriptor:sha256:e1c7a8b4…`）经 `buildSessionPromptPublication` 封存首个真实发布件；稳定对落地为 `urn:sage:target-semantic:sha256:3da420a7…` × `e1c7a8b4…`（模型面严格精确钉真实生效：`model:deepseek-official/deepseek-flash @0.2.0-rc.2`）。产物 JSON 落仓外 `/Users/pray/tmp/reobs-publication.json`，bundle/加载面属发布票。
4. **D4 夹具与真实输入的语法差由测试咬住**：requirement spec 新增真实身份形态的接受用例与垃圾拒绝用例——夹具不再能掩盖「语法只认 sage」这类假设。
5. **D5 发布件时窗**：首发计划 `effectiveAt=2026-10-11T00:00:00Z` 保持不变——真实求值（target provider）在生效时点前会答 `requirement-not-effective`，属设计而非缺陷。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 让运行时身份改成 `:sage…` 形式 | 否决：运行时身份已被 E 线 goldens 冻结（`provider:deepseek-official` 等真实行身份），改运行时等于改稳定对与全部已冻结读数——本末倒置。 |
| V1 组件身份也放宽为裸字符串（与 V2 完全一致） | 否决：V1 是 security 内核，保留有界语法拒绝垃圾输入；对齐的是「可表达真实身份」，不是放弃校验。 |
| 只修语法不补测试 | 否决：P-03——夹具假设必须由测试拦住，真实身份形态进接受用例。 |
| 一并放宽 POLICY_IDENTITY | 否决：策略身份是 Sage 治理命名空间，无真实输入要求放宽；两类语法分职即文档化差异。 |

## 后果

- requirement 可以逐字命名真实运行时组件；首个真实发布件的两半（target 语义与运行时 descriptor）首次共享同一批真实身份。
- 发布件从「夹具验证」升级为「真实重观测验证」；稳定对可直接进入矩阵规则发布（bundle 与端口接线属后续票）。
- 未闭：bundle 落盘与加载面、`resolveTarget`/`resolveCompatibility` 端口、Registry 首方 entry 裁决、persist/dispatch、真实登录与真机首条消息。

# ADR-0174 · Electron-main Application Service 唯一编排边界

- 状态：accepted（2026-09-30）
- 日期：2026-09-30
- 决策者：用户（lute）
- 决策记录：[WT-02D Application Service 边界](../notes/proposed/architecture/2026-09-30-application-service-boundary.md)
- 相关：[ADR-0159](ADR-0159.md)、[ADR-0163](ADR-0163.md)、[ADR-0165](ADR-0165.md)、[ADR-0171](ADR-0171.md)、[ADR-0173](ADR-0173.md)

## 背景

Sage 已分别建立 BusinessMatter、Identity / Policy、Compatibility、Registry、evidence persistence 和 renderer-facing projection / preview，但尚无受信产品边界把它们按固定顺序组合。当前 `/.sage/state` 与 `/.sage/actions` 仍由 Host child 处理，唯一 action 只是 runtime availability retry；UI preview 也明确尚未提交。若直接在 renderer、Host 或插件内接 provider，会形成第二套 authority 和不可审计的副作用路径。

WT-02D.0-ARCH revision 37 先冻结 owner、route、ports、import firewall、authority ordering 与失败语义。本 ADR 只记录架构决定，不修改 runtime route 或任何源码。

## 决策

1. **Electron main 独占 Application Service。** Application Service 是 BusinessMatter command 与安全 projection 的唯一产品入口。目标形态的 `/.sage/*` 业务 route 在 main 精确终止；Host、renderer、插件和模型不得注册平行业务 route、调用领域 command 或写 event store。
2. **公开端口分为 projection read 与 command submission。** renderer 只读取脱敏 `ViewState`、提交 exact `ActionIntent`。Projection query / body 不接受 caller 自选 session reference；main 验证 transport caller binding 后注入 active non-bearer session context。Intent 的产品 provenance `origin` 不是 transport caller identity 或授权输入；main 必须用不可由 body 自报的 transport / sender 事实独立绑定调用方，missing / unverifiable 时 fail closed，具体机制留给 `.0.1` 以当前 Electron pin 证明。Intent 不接受 actor、authority、compatibility outcome、matrix/digest、Registry approval、execution snapshot 或 completed；当前 `SageActionPreview` 继续保持 `not-submitted`。
3. **读取授权与动作授权分离。** 真实事项 projection 需要独立 read policy 和最小数据投影：main-side caller binding → main-injected active session → read policy → 最小 lookup / projection / redaction；缺任一环节 unavailable-first，未授权 denied / not-found 不枚举事项存在性。每个 action 另做 fresh Identity / Policy 求值。action grant、Host ready、历史 decision / equivalent 或 UI 可见性不能推导读取权或 standing action authority。
4. **固定依赖与 authority 顺序。** 本 ADR 细化但不改写 ADR-0165 第 8 条：main-side verified caller binding + exact route validation → session resolution + initial matter-load / access Identity / Policy precheck → strict rehydrate current matter / revision → trusted target / action policy → fresh action-scoped Identity / Policy → trusted clock + runtime inventory + MatrixV2 / resolver → Registry mapping + availability preflight → BusinessMatter 重验 → main-owned evidence / event transaction → Capability Adapter → artifact / failure / receipt / reconciliation。initial precheck 只授权定位与载入，不能替代后续 action authorization；步骤 4～7 不是 standing authority，任何 authority-scoped 持久写入前与真实 Adapter dispatch 前都分别重新核验 caller/session、Identity / Policy、current revision / operation，重新生成或核验 current target requirement / target evidence 的 provenance、effective / expiry / revoke 状态，以 current inventory / matrix / revocation 重跑 Compatibility Resolver，再核验 Registry mapping 与 availability preflight；任一漂移、`unknown`、`requires-new-revision` 或不可用即 fail closed。事务只保存经 WT-02B.3 批准的最小、不可重放 `Persistable AuthorityEvidence` 与本次实际使用的 compatibility evidence，绝不保存 runtime `AuthoritySnapshot` 或秘密；任一步失败即停止，Adapter 不被调用。
5. **Production composition unavailable-first。** 缺任一真实 provider、trusted clock、完整 inventory、matrix/revocation、Registry real entry、Adapter mapping、preflight 或 store/evidence port 时返回稳定 unavailable / blocked；fixture、placeholder、默认 digest、Host ready 和历史绿灯都不能补 authority。
6. **Service 拥有幂等、取消、重试与未知结果。** caller `requestId` 仅关联重发。每次请求先验证易变的 main-side transport caller binding，但 durable replay lookup / uniqueness key 使用 fresh Identity / Policy 产生的稳定、opaque Sage-internal actor / subject scope + organization + matter + `requestId`，不得使用 raw subject、token、session、window 或 frame。记录不可变绑定 canonical intent digest：命中同一 key 且 digest 相同才返回原 operation / receipt，digest 不同返回 conflict；service 再从 scoped request key + digest 签发并持久化 operation / idempotency identity。dispatch 前可取消；dispatch 后断线不能宣称取消。`retry-capability` 不重放业务 action；可能已执行但回执丢失时记录 `outcome-unknown`，禁止自动再次 dispatch。receipt lookup / 严格无副作用的本地 status query 每次重新做 caller binding 与最小 read / access authorization，并保持 anti-oracle；任何 Adapter query / cancel、receipt append、domain transition、re-dispatch 或人工裁定都属于具名 reconciliation action / 受治理 system principal 操作，必须重新走 full action authorization、领域重验与 durable transaction。只读 query 不能把 unknown 改成 resolved。
7. **错误与 receipt 稳定、脱敏且不冒充领域完成。** 产品面只返回可枚举错误类别、安全 stage / retry 指示和 correlation / operation reference；不泄漏 token、session、raw subject、secret、路径、stack、Host/MCP raw error、matrix bytes 或未分类 payload。Service receipt 只证明 exact intent 的处理阶段，`BusinessMatter.completed` 仍由领域规则与责任人 receipt 决定。
8. **分批实施。** `.0.1` 只做 main-owned route / port skeleton、unavailable-first composition 和 import firewall；`.1` 只做零真实数据、零外部副作用的 fixture / blocked read-only E2E；`.2` 必须等待真实 Identity / Policy、WT-02B.3 最小 `Persistable AuthorityEvidence` schema / governance / persistence、C2/C3、Registry real entry、trusted clock、数据治理和 idempotency / reconciliation 门后另行确认。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 保持 Host-owned 业务 route 并直接接 domain/security/store | 否决；Host 会同时拥有 runtime Context、产品 authority 与业务状态。 |
| renderer 汇合 provider 后提交“已验证”结果 | 否决；renderer 不受信，无法统一 freshness、顺序、原子性和审计。 |
| 插件各自注册 command route | 否决；会绕过 policy、compatibility、Registry、domain decision 和 receipt。 |
| 把 preview 或 fixture 当 production command / authority | 否决；二者只用于显示与测试，不能补真实 provider。 |
| 超时或断线后自动重放 Adapter | 否决；首次 operation 可能已产生副作用，必须先 reconciliation。 |
| 本批同时实现 `.0.1` skeleton | 否决；revision 37 的确认范围是六文件治理批，源码需另票确认。 |

## 后果

- renderer、Host、插件和模型不再有合法的平行业务 command / projection 路径；所有真实动作必须在 main-owned service 内重新求值。
- projection、authorization、compatibility、Registry、availability 与 domain decision 保持正交；缺项显式 unavailable / blocked。
- 真实 action 延后到生产 provider、data governance、durable idempotency 和 outcome reconciliation 均可证明之后。
- 后续必须以测试和门禁把 import、route、ordering、no-fixture-fallback 与 retry / cancellation 机制化；本 ADR 本身不等于实现。
- 当前 Host-owned `/.sage/state` / `/.sage/actions`、源码、测试、package / lockfile、v1 event、UI、插件、真实数据与外部 action 均保持未变；revision 37 不暂存、不提交、不推送。

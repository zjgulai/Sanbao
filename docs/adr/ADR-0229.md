# ADR-0229 · 方案预览与步骤执行：接受只记回执、未知即阻断、执行以投影为唯一读数

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；D-013/014/022/042/043/055/056/061/071/091 与 FW-034 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-plans-step-readiness-exit-guide-env.md)
- 相关：[ADR-0224](ADR-0224.md)（执行前确认单卡）、[ADR-0226](ADR-0226.md)（028 行动项回执纪律）、[ADR-0228](ADR-0228.md)（031 投影不合成）

## 背景

工单 032（FW-034，US-165~171）：方案的接受与执行必须结构分离——**接受=
对这份交付的回执**，不派发、不铸确认卡、不碰会话（D-043/061）；步骤执行按**动作前提**判定
就绪，安全或权限未知呈现为**阻断而非失败**、不就绪项**不被派发**（D-056/071，沿 025 的
前置纪律）；执行必须针对明确动作、携带一次性凭据（D-055）；退出前把影响说清——进行中任务、
待继续输入与未保存草案逐项列出（D-013/014），**关闭窗口不等于退出、停止不承诺撤回外部
操作**（D-022）；首版引导只读讲解、**引导不替代登录与授权、不自动修改任何配置**；环境
只读显示当前环境及来源（D-042），**事项的默认执行环境来自关联事实并在派发前逐次核验**
（D-091）。验收：①接受方案≠执行方案；②阶段就绪按前提判断，未知按阻断。

基座事实：执行本身归属 fail-closed 流水线（ADR-0190 步骤 3–10 保持收紧），生产不接
执行主体；025 的共享确认 store（prepare/consume/retire、指纹=canonical intent+facts）是本
工单唯一可复用的凭据机制；011 的关联事实（matterLinks 默认环境）与工作区折叠是"环境是否
仍存在"的既有家。

## 决策

1. **D1 接受方案=回执（US-165/166）**：新纯模块 `main/plans.ts`。`accept` 只把计划
   标为 accepted + 记 `acceptedAt`，**不铸卡、不消耗、不派发、不触会话**——结构断言
   （prepared/consumeAttempts 计数为 0、lastStepRun 保持 null）。`create` 守卫标题/步数/
   数量上限；重复 accept 幂等（回执时间不复写）。
2. **D2 步骤就绪按动作前提，未知即阻断（US-167）**：readiness 每次请求**重推导**——
   前提读不出来=unknown（文案"按阻断处理，不派发"，**不出现"失败"**）；环境已不在最近
   成功折叠=not-ready；未选定环境=ready（不阻断：沿 011 逐次核验合同）。**prepare 只对
   ready 铸卡**（not-ready/unknown 在铸卡之前拒绝：`step-not-ready`/`step-premise-unknown`），
   所以"不就绪项不被派发"是结构性事实；渲染面同一条：**只有 ready 行渲染 prepare 按钮**。
3. **D3 执行=两步且以投影为唯一读数（US-168）**：`prepare-step` 铸**单张卡**（骑 025
   共享 store，目标=plan:planId:step:N，前提/资源写在卡上；重铸即退役旧卡）→
   `execute-step` **先重验新鲜度**（前提变了→retire+拒绝，旧卡标死），再 consume
   （required/stale/consumed 原码直传），**端口缺席（生产未接线）=not-ready 且不消耗**——
   确认卡保持可用、重放给出同一诚实答案；`deps.executeStep` 唯一执行入口（成功=settled+
   receiptRef、未知=unknown、拒绝=denied）。**每次尝试都写 `lastStepRun` 入槽投影**，
   且响应体**随行携带同一份投影**（`plans: status()`）——渲染端以投影渲染结果句
   （未接线：'没有伪造运行，也不消耗确认'），local notice 只为**未记录态**保留
   （plans-unavailable/传输失败/无法识别），不再遮蔽投影。
4. **D4 退出检查=投影事实＋真实未保存字段合成（US-169/170）**：影响清单三类——进行中
   任务（会话 executing，停止的后果说清）、待继续输入（pending 非 consumed 计数）、
   **草案未保存的改动按输入框真实值 vs 投影字段对比**（中文标签逐项）；空清单给 D-014 句
   （不额外增加确认）。**取消=关闭对话框、零请求保持后台运行**；停止=发 `/.sage/session/stop`
   （沿 006 通道）并明说"不能承诺撤回/不等于远端效果已知"；**本页没有退出触发器**——
   关闭窗口≠退出（沿 D-013）。
5. **D5 引导只读、环境只读（US-171）**：引导展开/收起=本地状态（**零请求、零配置写入**）；
   文案钉住"引导不替代登录与授权、不自动修改任何配置""实验不直通生产"（本版无实验入口）。
   环境卡三行事实各自标源：运行时（runtime 投影）、事项默认环境（011 关联事实）、工作区
   折叠（存在性来源）；**无装配/跨设备/远端执行入口**（远端不会自动接替）。
6. **D6 首版不做**：方案持久化打磨、步骤依赖图与自动接力、生产执行主体接线（executeStep
   端口缺席即 fail-closed 的组成部分）、退出流程的系统窗口联动。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 接受方案顺带铸卡/预派发 | 否决：D-043/061 点名"接受只记回执"；US-165 的结构分离是验收线。 |
| 就绪判断缓存到计划记录 | 否决：环境会变（D-091 派发前逐次核验）；缓存必然过期发假绿灯。 |
| 未就绪用"失败"措辞 | 否决：D-056/071"安全或权限未知呈现为阻断而非失败"。 |
| 执行结果只用 local notice 呈现 | 否决：notice 会遮蔽投影且刷新即失；结果面以 lastStepRun 投影为唯一读数（响应随行同一投影）。 |
| 未接线执行器伪造一次执行 | 否决：fail-closed（ADR-0190）；not-ready 不消耗确认、凭据可重放才是诚实答案。 |
| 退出面板直接提供"退出应用" | 否决：D-013"关闭窗口≠退出"；应用退出沿用系统窗口行为。 |

## 后果

- 验收两条的机器断言：接受零派发（计数 0 + lastStepRun null）；阻断结构性（prepare 拒绝在
  铸卡前 + 非 ready 行无执行入口）；未接线不消耗且可重放；新鲜度重验下线旧卡（retire+
  stale）；一卡一次（replay=confirmation-consumed）。
- 渲染面：8 项文案/行为断言（未接线句、阻断句、退出三类事实、取消零请求、stop 精确体、
  引导零请求、环境三源、徽章三态）。
- 已知未闭：生产执行主体未接线（not-ready 如实）；方案为运行内存储（持久化后置）；
  环境卡"存在性"依赖最近成功折叠（未读取即 unknown 阻断）；真机未跑。

# ADR-0232 · 会话内队列：queue/steer 双模式、权威快照投影与逐项修改

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-020、US-025~030 与 005/006/007 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-session-queue-modes-and-item-ops.md)
- 相关：[ADR-0212](ADR-0212.md)（005 会话通道）、[ADR-0213](ADR-0213.md)（006 停止/待继续）、[ADR-0231](ADR-0231.md)（007 暂停期登记）

## 背景

工单 008（FW-020，US-025~030）：发送可选 `queue`（本轮结束后处理）或 `steer`（**下一步骤
边界**插入），且 **steer 文案不得写成"已打断当前步骤"**；待处理项可查看/修改/移除，项已被
消费时按 `queue-item-not-found` 如实提示"已开始处理"，不静默丢弃、不重复提交；**队列呈现以
基座权威快照为准**（含 `queued|steering|context` 三种位置）；暂停态下队列入口只显示待继续；
首版**无定时/循环自动化入口**、不以只读空列表冒充能力。基座已具备：`session/prompt` 的
`mode:'steer'`（host 桥早已过白名单但 send 恒发 'queue'）、`sessionController.updateQueue`
的 `{kind:'remove'|'edit'(文本块)|'steer'}` 与 `session/queue-item-not-found`、
`session/control` 投影的 `queues[sessionId]=[{id,placement,rpcId,message}]`。

## 决策

1. **D1 双发送模式（US-025）**：`send` 增可选 `mode:'queue'|'steer'`（默认 queue，白名单外
   落回 queue）；路由精确体接受 3–4 键（mode 仅 'queue'|'steer'）；ack 回执**回显所载模式**；
   渲染面新增「发送方式」选择（**只在选择 steer 时随请求携带**，默认排队少一个键）；暂停态下
   steer 发送与普通发送同权——**只登记待继续、对桥零调用**。
2. **D2 队列投影=权威快照（US-028）**：`read` 增做一次有界 `session/control` 快照读，投影
   `queue:{state:'read'|'unavailable', occurrences:[{queueItemId, position, requestId, preview}]}`
   ——position 逐字取 `placement`，preview 仅取首条文本块且 **≤140 字符**（整条消息永不跨界）；
   既不由本地 echo 推导，也不把缺席说成空列表（`unavailable` 自报；渲染句"不以空列表冒充"）。
3. **D3 逐项编辑/移除（US-027）**：host 桥 `updateQueue` 声明扩 `edit`（文本块）并在
   `session/queue-edit` 端点构造与 prompt 同源的内容块；classifier 增
   `session/queue-item-not-found → bridge-queue-item-not-found`。main 通道 `queueItem`：
   编辑裁剪去空白（空/超 16384=`queue-edit-invalid`）、缺会话=`queue-no-session`；
   被消费的项映射 `queue-item-not-found`，渲染句**"已开始处理（不在队列里了）：如实提示，不静默
   丢弃、不重复提交——如需补充请重新发送"**（一次点击恰一条请求，拒绝不触发自动重发）。
4. **D4 暂停与措辞纪律（US-026/029）**：暂停态渲染**只显示待继续**（队列行不渲染），队列区
   文案说明"恢复后才按顺序派发"；steer 所有文案只承诺**步骤边界消费**——静态/动态两处断言
   `不打断当前步骤` 且全页无"已打断"字样。
5. **D5 负空间（US-030）**：文案明示「本版没有定时或循环自动化入口」；队列区控件名册钉住
   （每行恰 [保存修改][移除]），按钮文本不含 定时/循环/自动化/计划任务。
6. **D6 首版不做**：定时/循环自动化、队列项 steer 搬移动作（发送面 steer 已覆盖该场景）、
   批量队列操作、跨会话队列。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 队列由本地 echo/回执推导 | 否决：US-028 点名权威快照；本地推导必然与消费竞态分叉。 |
| steer 文案写"已打断当前步骤" | 否决：US-026 明令；基座语义本就是步骤边界。 |
| 投影透传整条消息 | 否决：preview 有界（≤140）即够呈现，原始载荷不再跨界。 |
| 直接给 `updateQueue` 开一个通用 action 端点 | 否决：沿 006 先例，逐动作命名端点各自精确体（remove/edit 两枚）。 |
| 队列读取失败显示空列表 | 否决：US-030 语义——空列表是"队列为空"的事实，缺席是未核验。 |

## 后果

- 验收三条机器断言：①消费竞态不静默丢弃（`queue-item-not-found` 具名句 + 恰一条请求）；
  ②队列呈现与权威快照一致（placement/preview 直取帧；流断=unavailable；不由 echo 推导）；
  ③无定时/自动化入口（文案+控件名册双断言）且空态不冒充能力。
- host 桥面 +1 端点（session/queue-edit）与 1 条分类映射；005/006 断言 deliberate 更新
  （ack 回显 mode；read 多一次 control 快照读）。
- §1.6：D3 卡「发送方式 steer」「三位置队列行」「已开始处理」句以真实页面两宽实测；交互读数
  dump-dom 逐项核。
- 已知未闭：定时/循环自动化后置；队列项 steer 搬移后置；真机 Electron 未跑。

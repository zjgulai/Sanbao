# ADR-0330 · 端点表与端点正则必须同集：`workspaceFiles/*` 被自家门拒杀整桥

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（授权修复实测问题）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-endpoint-gate-parity.md)
- 相关：[ADR-0325](ADR-0325.md)（桥契约）、[ADR-0327](ADR-0327.md)、[ADR-0329](ADR-0329.md)（外围失效过滤的两次修正）

## 背景

v11 走查实测（回合终点的产物观察）取证链：

- shell 侧出站校验探针：`[invalid-out] {"type":"bridge-call","endpoint":"workspaceFiles/changes",…}`；
- 随即 `[host-fail] fatal sage shell: invalid Electron IPC command`（host 的 `isHostCommand` 拒绝）→ host 自杀 → response pipe ended / IPC disconnected → **整桥死亡** → 后续一切读面 `fresh-scope`/`bridge-host-not-ready`。

根因：`BRIDGE_ENDPOINT = /^[a-z][a-z0-9-]*\/[a-z][a-z0-9-]*$/u`（只收全小写段）与端点表自相矛盾——`workspaceFiles/list|stat|read|readBytes|readAll|changes` 六个 camelCase 段端点**自身不过自家正则**。凡调用即拒 → fatal。回合**收尾**的 artifact 观察恰走 `workspaceFiles/changes`——「回合后连读面塌」「dispatch 回执丢失成 outcome-unknown」「失败回合后桥死」等的共同真身；ADR-0327/0329 修正的懒激活与 scoped 拆除误报是真实存在的**外围**问题，但主导性断桥一直是本条。

## 决策

1. **D1 正则与表同集**：`BRIDGE_ENDPOINT` 改为 `/^[a-z][a-zA-Z0-9-]*\/[a-z][a-zA-Z0-9-]*$/u`（段首仍小写；段内允许 camelCase）——与表内既有命名共存。
2. **D2 防复发护栏（P 类：知道⇒拦住）**：`protocol.spec.ts` 新增用例——**表内每个端点必须通过 `isHostCommand`**（缺任一即红）。表与门从此互为锁。
3. **D3 不新增名单**：不改表、不重命名端点；命名兼容面为零。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 重命名六端点为小写（workspace-files/*） | 否决：波及 host handler、shell 调用、测试与历史语义；正则才是过窄的一侧。 |
| 仅放宽正则不加护栏 | 否决：表与门的同集性必须机械守住，否则复发无人拦（本 ADR 的教训本身）。 |

## 后果

- 回合终点产物观察、run-log、edit-drafts 源读、文件候选等 `workspaceFiles/*` 全族恢复可用；桥不再因合法调用自杀。
- `outcome-unknown` 的「回执丢失」诱因之一解除；连读面在回合后保持可用（v12 装机实测为准）。
- ADR-0327/0329 保留（各自证据成立的外围修正）；本 ADR 为断桥主因。

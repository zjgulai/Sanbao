# ADR-0283 · T13-A 治理裁决：外观三族 not-applicable、verified 证据政策、入口语义重述与 Registry 自证等价路线

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute，四项裁决全部采纳 agent 推荐）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/process/2026-10-10-t13a-governance-rulings.md)
- 相关：[ADR-0257](ADR-0257.md)/[ADR-0258](ADR-0258.md)（语义 token 与 density 单源）、[ADR-0270](ADR-0270.md)（device-preferences DTO 八项钉死）、[ADR-0171](ADR-0171.md)（Capability Registry 治理）、[ADR-0277](ADR-0277.md)（C2D.2A 空快照）

## 背景

T13-A 记账盘点（2026-10-10）浮出四项需要 owner 裁决的治理问题：① Sanbao 观察中的文字大小/界面缩放/主题色板在 Sage 无落点（扩 DTO 还是记 N/A）；② `implementing→verified` 所需的 live 证据该落在哪个 tracked 路径（`.birdview` 被门禁禁止，导致 UI 行永远封顶 implementing）；③ `appearance.entry` 的入口语义与 Sage 真实形态不一致；④ session.prompt 首方 Registry entry 的 provenance 路线（ADR-0277 后果节：step 7 将在空集下 unavailable）。用户逐项裁决，全部采纳推荐。

## 决策

1. **D1 外观三族记 `not-applicable`**（QDR.OBS04.appearance 的 theme/text-size/ui-scale 三行）：Sage 语义 token 面（ADR-0257/0258）只承诺 light/dark/system 与 density 请求/生效值；缩放由平台手段承担（Chromium zoom，已有 200% reflow 验收），应用级字号/缩放任一 DTO 都会与窗口缩放语义冲突或铸造无需求证据的新持久化契约。行落 `applicability/integrationStatus = not-applicable` + `notApplicableDecisionRef = docs/adr/ADR-0283.md` + 逐行 rationale；未来收编=新 ADR + 新 DTO + **新矩阵行**，不在旧观察行内兑现。
2. **D2 verified 证据政策 = 机器读数原样入仓**：打包/live 验收的 `acceptance-result.json`（`sage.packaged-acceptance.v1`）以稳定命名提交进 tracked 文档区（`docs/notes/implemented/packaging/evidence/`），行以 `countsAsVerification:true` 引用该文件 + 对应 spec 测试路径 + route matrix（applicationService 维度另需已登记 routeRef）。**截图不入 git**；文件内的机器路径（ps 命令行等）是 sanctioned「历史证据例外」，原样保留不改写。`visualAcceptance` 维度的 verified 仍需更严门槛（像素级人工回看记录），本政策不覆盖。
3. **D3 `appearance.entry` 按 Sage 真实入口重述**：Sage 无「设置导航→外观」两级入口；真实形态为账号菜单 → 外观与显示表单。行语义按此重述（不改产品形态），状态留待句级证据批次。`*.open` 族的「下拉展开」观察同理重述为「控件存在 + 选项集 + 权威值 + 保存/回读」（macOS 原生 select 弹层无法被 CDP 驱动，DMG note 十二追加实证）。
4. **D4 Registry 首方 entry 走自证等价路线**：session.prompt 的 approved entry 的 provenance = **C2A 运行时制品 attestation（真实观测）+ 发布决策**，由 owner 审批入 Registry；**明确不宣称** C2C.5 外部能力等价（外部锚是 bridge-owned seam 的未来层，可叠加不推翻）。Registry 四态与 owner 审批治理（ADR-0171）不变；实现归 Registry 接线批次。
5. **D5 首次应用**：依 D2 政策把 8 条外观族行（default + 7 个 `*.open`）的 `ui`/`applicationService`/`electronAcceptance` 三维升 `verified`，证据=tracked spec + v2 验收读数 + route matrix；`hostIntegration`/`visualAcceptance` 保持 pending。B3 三行落 N/A。矩阵 `summary` 按派生规则重算，PIN 零改动。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 三族全部收编扩 DTO | 否决：无需求证据的设计系统扩展；zoom 已有平台承担与验收；色板=新 ADR 新行专属。 |
| verified 只认代码测试路径 | 否决：UI/打包维度永远无法 verified，矩阵承诺形同虚设；机器读数是可复算的非口头证据。 |
| 读数+截图都入仓 | 否决：仓库体积与保留策略成本；像素级证据留待单独门槛。 |
| Registry 等 bridge-owned C2C.5 seam | 否决：session.prompt 是内建能力，为它空等外部锚或伪造 C2C.5 都不诚实；自证等价明示边界即可。 |
| 手工 owner entry（无 provenance 绑定） | 否决：违背 Registry 治理精神（provenance 必须可复验）。 |

## 后果

- 矩阵 206 行首次出现 `not-applicable` 与 verified 维度；`integrated` 仍为 0（hostIntegration 等维度未达）。
- 验收读数开始入库（首件：`docs/notes/implemented/packaging/evidence/2026-10-10-dmg06-v2-acceptance-result.json`），此后每次打包验收一份、旧版本转 `archive/`。
- Registry step-7 的接线路径被选定；实现前 session.prompt 仍按设计 unavailable。
- 未闭：visualAcceptance 门槛、`appearance.entry` 句级证据、其余 `*.open`/B3 类行的逐行语义重述批、Registry 自证等价的具体实现与 ADR（实现时落 ADR-0171 修订或新 ADR）。

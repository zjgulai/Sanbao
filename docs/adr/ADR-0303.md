# ADR-0303 · 执行模块第五刀：上下文占用提示（快照投影）与 P16 复盘

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：同意 Loop-Q R5）＋ agent（盘点与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-context-usage.md)
- 相关：[ADR-0301](ADR-0301.md)（fold 基线）、基座 `token-meter` ContextPressureProjection

## 背景

Loop-Q R5 原计划两行：`QDR.S10.context.usage`（上下文占用提示：同一提示的数值变体 15%→16%；T10）与 `QDR.P16.review.summary`（任务监控区回顾卡；T10）。盘点：

- S10 数据源可得：基座 `token-meter` 在会话投影里计算 `ContextPressureProjection`（`pressureTokens`=最近一次请求的提示规模、`contextWindow`=最新已知路由容量；文档明言“user-facing reference, not a billing or gating input”），并随 `snapshot.projections` 送达；Sage 通道 fold 此前忽略 `projections`。
- P16 需要的「任务监控区」在 desktop 线**不存在**——整面装配超单行范围，登记为 Loop-Q 下一轮监控面刀，P16 保持 pending 并改写 blocker（不假闭）。

## 决策

1. **D1 fold 读投影**：快照分支提取 `projections.contextPressure`（整数校验；两字段独立保存——新容量可能配对旧压力，基座语义如此）；缺或非法 → null（绝不猜）；页面重放合并取「有者优先」。
2. **D2 契约与解析**：`SessionChannelStatus.contextUsage: {pressureTokens|null, contextWindow|null} | null`（三构造齐）；desktop 宽容解析。
3. **D3 renderer**：composer 提示行前置「上下文 NN%」chip（仅两值齐备时渲染；title 附 tokens 原值）——同一提示的数值变体即同一条目的两次读数，不拆界面。
4. **D4 范围诚实**：S10 迁 `ui` `pending→implementing`（tracked-test refs，`countsAsVerification:false`；blocker 登记：真实宿主是否送达投影走真机验证；明细/压缩两面行注未观测，不装）。summary 生成器重算（28→29 implementing、170→169 pending、verified 8 不变）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| Sage 自算 token 占用（无投影时） | 否决：无权威计数即无数字——静态或估算数字违 T10 纪律；缺席即无 chip。 |
| R5 一并装任务监控面 | 否决（盘点裁定）：整面属独立刀（区域 + 数据 + 证据），塞入单行批会把两件事做半。 |
| 百分比圆整后再展示小数值变体 | 采纳：`Math.round` 与行观察（15%/16%）同粒度。 |

## 后果

- 上下文占用提示上线（宿主携带投影时）；缺席时无 chip，诚实。
- 执行回流面 10/11 行完成迁移；P16 转入监控面刀（下一轮）。

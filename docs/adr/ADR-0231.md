# ADR-0231 · 暂停期新输入只登记不唤醒：冻结派发、活的清单与队列版本对账

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-003、US-020/021 与 006 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-paused-deferral-frozen-dispatch.md)
- 相关：[ADR-0212](ADR-0212.md)（005 会话通道）、[ADR-0213](ADR-0213.md)（006 停止与待继续）

## 背景

工单 007（FW-003，US-020/021）：**暂停态下发送新内容只保存为待继续并反馈"已收到，尚未
执行"，不唤醒 Agent**；**查看/编辑/移除待继续输入都不唤醒执行**；**发送与继续并发时按
队列版本对账，不悄悄把未含内容送入执行**。006 已落基础（暂停态发送进设备本地待继续、
stop 排空与竞态分账、resume 按序派发），但缺口有三：派发过程对"进行中的一条"没有冻结
（编辑竞改已派发文本、记录与事实背离）、resume 只读一次快照（派发间隙的编辑/新增不生效）、
且**边界条件与版本没有一等表达**（re-pause 竞态无状态、修订号不存在）。

## 决策

1. **D1 暂停态发送=登记（US-020）**：`send` 在暂停态把文本入设备本地清单并返回
   `{state:'deferred'}`；该路径对桥零调用（无 create/prompt/stream——"不唤醒"是结构事实，
   有断言）；渲染端回执句钉住"已收到，尚未执行……点「继续」才按顺序派发"。带附件的暂停
   发送整体拒绝（`session-paused-attachments`，沿 014 的寿命语义）。
2. **D2 查看/编辑/移除不唤醒（US-021）**：三动作只触待继续存储（零桥调用，有断言）；
   查看=会话读通道把条目原样投影（`editable` 只对 `pending`）。
3. **D3 冻结派发（US-021 核心）**：待继续状态机加 `dispatching`——resume 对每条**先
   `beginDispatch` 冻结再发 prompt**：派发中的文本==记录文本（期间的编辑/移除一律
   `item-frozen`）；prompt 被拒/未识= `revertDispatch` 回 `pending`（可再续），回执成功才
   `markSubmitted`。渲染面 `派发中（已冻结，不可编辑）` 只读呈现。
4. **D4 活的清单 + 重暂停止步**：resume 每轮**重新读活的清单**取下一 `pending`（派发间隙的
   编辑/新增立即生效，绝不按陈旧快照派发）；每轮先查暂停位——**重暂停（stop 与 resume 竞态）
   在当前条之后止步**，返回新态 `interrupted`（paused=true，dispatched 如实、其余留 pending），
   渲染句钉住"未含内容没有被送出"。
5. **D5 队列版本对账（US-021）**：待继续记录加**单调 revision**（每次变更+1，快照携带）；
   resume 收束后按权威队列快照折叠一次——**只增记**：occurrence 在=记 `queueItemId`；
   不在=保持 submitted（刚受理的 prompt 可能尚未物化，误判"被取走"会冻结用户还等着的输入；
   `absent:'consumed'` 语义保留给 stop 的排空对账）。快照拿不到就带 code 说明，不假装对过账。
6. **D6 首版不做**：旧输入合并/顺序细则（沿工单边界）、并发多 resume 去重、跨设备待继续
   同步（后置）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 仅靠 JS 单线程串行化、不冻结 | 否决：prompt await 期间编辑窗口真实存在（本轮测试当场复现记录/事实背离）。 |
| resume 按开始时的快照派发 | 否决：派发间隙的编辑/新增会被静默跳过——"未含内容"的另一种形态。 |
| 重暂停时继续把剩余项派完 | 否决：US-020 点名"暂停不唤醒"；再暂停后任何派发都是唤醒。 |
| resume 折叠沿 stop 的 absent=consumed | 否决：受理后快照可能尚未物化，会误冻用户还在等的输入（本轮测试当场红过）。 |
| 不要 revision、只按 requestId | 否决：修订号是"这段派发在哪一版清单下收束"的机器面（快照携带、回执回报）。 |

## 后果

- 验收两条机器断言：①暂停态发送对桥零调用（deferred + 清单可读）；②冻结/活清单/重暂停/
  折叠四竞态各有具名断言（编辑被拒于派发中、下一项派编辑后文本、interrupted 后不再发送、
  resume 后 occurrence 增记）。
- §1.6：D3 卡五态行（派发中/待继续×2/已提交/已消费）＋deferred 与 interrupted 两句以真实页面
  两宽实测；交互读数由 dump-dom 逐项核对。
- 已知未闭：多 resume 并发去重与跨设备待继续同步后置；真机 Electron 未跑。

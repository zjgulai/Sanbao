# ADR-0220 · 搜索两区：事项本地匹配 + 基座会话检索、引擎缺席是其自己的状态、命中只读

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证并实施；两区边界与缺席语义是取舍）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-search-two-sections.md)
- 相关：[ADR-0212](ADR-0212.md)（会话通道）、[ADR-0218](ADR-0218.md)（产物面同款"不可用≠无结果"纪律）

## 背景

工单 021（FW-014，US-085~089）要求：一次输入两区结果——事项按标题/关键属性**本地**匹配、会话走基座
检索；会话检索按 cursor 分页、有界调用、只返回可见会话；provider（`dsh-session-query`）未挂载时不
伪装"无结果"；搜索是读取面（命中不打开会话、不激活执行、不加载正文）；事项正文检索与统一排序后置。

基座取证（逐字）：`sessionController.search({query}, signal)` → `{items:[{sessionId, snippet}], hasMore}`
（≤20 条、snippet 截 240 码点）；其实现首行即 `ctx.get("sessionQuery")`，缺席时抛
`gateway/internal`"…does not mount @deepseek-ai/dsh-session-query"；内部按 `nextCursor` 循环、
`SEARCH_PROVIDER_CALL_LIMIT = 100` 有界、只收 `header.cwd` 可见会话、surface=current 的
user/assistant 命中；查询边界：非空、≤500 UTF-16 码元、无 NUL。

## 决策

1. **D1 两区各自成源（US-085）**：事项区在 Sage 本地记录上匹配（已建项草案的事实：goal 作标题 +
   deliverable/responsibility/projectRef 关键属性；同一 matterRef 去重、上限 20）；会话区只经
   bridge 的 `session/search`（read）到基座，一次调用（基座内部分页有界），`hasMore` 如实显示
   "还有更多未列出"。**跨对象统一排序不做**（US-089）。
2. **D2 引擎缺席是它自己的状态（US-087）**：桥在调用前检查 `ctx.get('sessionQuery')`（与控制器
   首检同源）——缺席即 `bridge-search-unavailable`；main 映射为会话区 `unavailable`；渲染面
   "会话检索不可用：运行时没有挂载 dsh-session-query（这不是'无结果'…）"与空结果句
   "没有命中的会话（'无结果'说的是这件事）"**互斥且各有断言**；事项区不受影响照常匹配。
3. **D3 查询边界三道（US-086）**：渲染器（非空即发）→ route 解析（trim、≤500、无 NUL，否则 400）
   → 桥端点（同界再验、`bridge-search-query-rejected`）；基座自己还有一道。空关键词不发请求。
4. **D4 命中只读（US-088）**：search 模块的全部桥流量=恰好一条 `session/search`（模块测试断言逐条）；
   渲染面命中只是文本（本地记录 tag/检索 tag + snippet），**没有任何打开/跳转动作**；搜索框在途时
   再点/回车被忽略——同一时刻至多一个查询（"分页不并发重复"）。搜索不改会话绑定、不建会话、
   不 prompt、不 follow、不 page、不 stat/read 正文。
5. **D5 答案形状校验（US-086）**：main 对 `{items,hasMore}` 逐字段校验，不合法即
   `bridge-answer-unrecognised`；snippet/sessionId 原样透传（不重拼、不截断二次加工）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 事项检索也走基座（把事项当会话搜） | 否决：事项是 Sage 自有对象（工单"数据层无新增存储"），基座没有事项概念。 |
| 引擎缺席显示"无结果" | 否决：US-087 点名两种呈现分开——把缺席说成没有就是伪装。 |
| 多页"加载更多"按钮（真 cursor 外露） | 否决（本票）：公开 `session/search` 无 cursor 参数，分页是基座内部有界机制；首版如实显示 hasMore。 |
| 命中可点开会话 | 否决：US-088 点名命中不打开不激活；打开走 005 的既有路径而非搜索。 |
| 两区合并排序 | 否决：US-089 明确后置。 |

## 后果

- 两条验收各有机器断言：搜索零写副作用（桥流量恰好一条 read）、不可用与无结果两句互斥。
- 服务消费登记新增 `sessionQuery`（门禁当场抓到漏登记并当场补齐）。
- 已知未闭：真机 Electron 未跑；`hasMore` 的后续分页交互未做（基座公开面无 cursor）；事项正文
  全文检索与跨对象排序后置（US-089）。

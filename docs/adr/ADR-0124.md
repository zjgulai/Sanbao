- 修订：2026-09-18 [ADR-0125](ADR-0125.md) 恢复了 `split` 作为 **API 可选形态**（`position` 四值、默认 `stacked`）：

## 背景

用户提的是两个具体现象——**新会话与新应用两个入口要调小**、**颜色不搭**——并要求把侧边栏当一次
**能力图谱整合**来讨论，不当作一次样式微调。按「先定位物理成因，再谈方案」取证后，两个现象各有
一个可测量的成因，且**都不是尺寸问题**。

**成因一：视觉权重倒挂。** 官方的「新建会话」是这条列上最重的元素：

```
.EXfQ3q_newSession{height:38px;margin:0 2px 8px;padding:8px 16px;border:.5px solid var(--dsw-alias-border-l3);
  background:var(--dsw-alias-button-elevated-fill);border-radius:12px;font-size:14px;font-weight:500;gap:6px}
```

38px 高 + 抬升底色 + 14px/500 字重 + 6px 内距 + 居中——**同一列里的会话行、工作区行都是 30–36px 的
无壳文本行**。而全列**使用频率最低**的恰是这两个启动动作（会话与工作区才是日常主体）。用「最重的
形态」承载「最少的点击」，这就是「要调小」的真实诉求：不是把数字改小，而是**把按钮降级成行**。

**成因二：颜色双轨。** 官方按钮走 neutral 系（`--dsw-alias-button-elevated-fill` + `--dsw-alias-border-l3`），
而自建「新应用」行（`position:'split'` 时代）走 `--lute-brand` 品牌绿实底。**同一列里两套色系各管一段**，
且两者都不是对方的分层——这不是审美分歧，是没有任何一处规定「这一列的颜色该由谁管」。

**参照面（实测四款同类产品，非外推）：** Codex（随 `/Applications/ChatGPT.app` 分发，v153.0.8010.36）、
Qoder CN、Minimax Design、Accio——**四款的启动动作全部是 chrome-free 文本行**（无边框无实底，hover 才出
底色），行距 30–38pt；侧边栏宽**实测 252–280pt，DSH 279pt**（原文「175–300pt，而 DSH 是 350pt」系截图文本框范围估算，2026-09-18 经像素实测**证伪**）。也就是说「按钮形态」在这类产品里没有先例。

## 决策

**D1（形态）** 「新建会话」与「新应用」是**两条导航行**，不是两个按钮。官方按钮由插件**去外壳**：
去边框、去抬升底色、左对齐、8px 圆角、36px 行高、13px 字号、24px 图标盒；自建行紧随其下。
两者同轴同宽——`nav-band` 轴：`box-sizing: border-box` + `width: 100%` + `margin-inline: 0` +
`padding-inline: 10px`（与 ADR-0079 的原生导航列同轴）。

**D2（几何归属）** 几何**不再由核心内联计算**。核心删掉 `applySplitGeometry()` 与 `SPLIT_COLLAPSED_LIMIT`，
只做一件事：给官方按钮写/撤 `data-lute-navrow` 标记。几何由**被标记的那条属性锚规则**承担
（`button[class*="newSession"][data-lute-navrow]`）——锚是**属性**，不是类名哈希（ADR-0019）。

**D3（收起态）** 布点宽 `< STACKED_COLLAPSED_LIMIT`（60px）时，核心**撤掉标记**，行样式表整体让位，
官方按钮回到它自己的 rail 形态（36×36、`background:0 0`、`border-color:#0000`），自建行沿用同一 rail
度量（36×36，标签隐藏）。

**D4（行高 36px，不是 30pt）** 规格草案写的是 30pt；落地取 **36px**。理由：同列注入行（岗位矩阵、
技能中心）与 ADR-0079 的行轴就是 `height:36px` + `margin:2px 0` + `padding:0 10px`，
**同列必须同族**。要动 30pt 就得三行同改，那是另一条决策，不在本条范围。

**D5（判据射程）** `scripts/gates/sidebar-row-axis.mjs` 的列注册表新增 `nav-band` 列（`split` 列退役），
并新增 **`RESTYLED_SHELL_ROWS`**：**被插件改写的官方行**（官方按钮本身）也进判据面——断言它的属性锚
在核心源码里被写入、且它的声明块与所在列同轴。**这条是本 ADR 最可复用的部分**：此前「官方行」与
「注入行」分属两个世界，改写官方行等于在判据射程之外动刀。

**D6（颜色归属）** 启动带不用品牌色实底：行文字走 `--dsw-alias-label-secondary`，品牌绿只留给
**徽标**与 **3px 活动指示条**。做到这一条，「颜色不搭」就不再是审美问题，而是**有唯一归属**的规则。

## 备选方案

1. **只把两个按钮调小（保留按钮形态）。** 最省事，但没碰成因：权重倒挂的根源是「按钮 vs 行」的
   *形态*差异，把 38px 改 30px、14px 改 13px 之后它仍是这条列上唯一的圆角实底块。
   否决依据：四款参照产品在启动位上**一个按钮都没有**。
2. **保留按钮但统一色系（都用品牌绿实底）。** 解决「双轨」，但把这条列变成品牌色最重的一块，
   与 D6「品牌色只做状态」相反，且在深浅两个主题下都要重算对比度。否决。
3. **把两个启动动作收进一个折叠组（如「工作台▸」）。** 结构上更接近 Codex，但**首屏少一条最重要的路**：
   新建会话是一级动作。本条只做「降级成行」，启动位保持一级可见。
4. **两行都改 30pt 以对齐规格草案。** 见 D4：会与同列既有两行脱族，且 ADR-0079 的行轴判据当场判红。
5. **给 newapp 的 `split` 规格文件改写成 stacked 版本（保留两份同形测试）。** 否决：`sidebar-entry-core.ts`
   在三个包里是 `scripts/sync-shared.mjs` 守着的**逐字节副本**，契约测试写两份等于给同一条事实两个家
   （P-07）。删掉 newapp 那份，契约由 role-matrix 的 `sidebar-entry-stacked.spec.ts` 与 sync 门禁共同守。

## 后果

**正面**

- 「新会话」「新应用」从这条列上最重的两个块变成两条普通行：实测官方按钮 `border:none`、
  `background:rgba(0,0,0,0)`、`border-radius:8px`、`justify-content:flex-start`、13px 字号，
  与自建行**逐项同轴**（两行同 36px 高、同宽 256px、同左缘 12px、标签同偏 42px）。
- 启动带的行进量从 46px 变 80px，下方工作区整体下移 34px；2.0 的侧边栏 root 是 `height:100%`，
  这 34px 由 `flex:1` 的 `regionArea` 等高吸收（实测 region 574 → 540）。
- 判据面扩到官方行之后，「改写官方行」这件事第一次有了机器在守：属性锚从核心消失、或改写规则的
  水平轴与所在列不一致，门禁当场判红（第 ⑫⑬⑭ 条反向自测分别钉住这三种突变）。
- 颜色归属唯一：行文字是 token，品牌色只出现在徽标与指示条。

**负面 / 代价**

- **生效要重启应用**（ADR-0078）：几何与样式都在装载点，`lib/` 变了不等于页面变了。
- 官方按钮的几何现在依赖**一条属性锚规则**存活；如果上游把按钮换成别的元素或去掉 `newSession` 类，
  改写会静默失效到「看起来还行」——这正是 D5 把官方行纳入断言的原因：断言锚在核心源码里被写，
  但**类名本身仍可能在下次基座升级时改名**，那一步只能靠升级后的巡检发现。
- 删除 `split` 实现是**破坏性 API 变更**：`applySplitGeometry` / `SPLIT_COLLAPSED_LIMIT` 从共享核心移除，
  三个包的生成副本与类型声明随之更新；任何仓库外引用会直接编译失败（这正是想要的）。
- 「被插件改写的官方行」这个能力一旦存在，就会被用来改写更多官方 UI。本条不设闸门，只在
  `RESTYLED_SHELL_ROWS` 里要求**逐条登记**（未登记者不进断言面，但也不会被误认为已守）。

**后续动作**

- P1：把任务板 / SSH / 技能中心 / 岗位矩阵收进「工作台▸」折叠组，一级行 ≤ 4；砍掉 `99+` 徽标。
- P2：置顶区、搜索/过滤行、工作区次级信息（当前 31 个会话规模下「找到某会话 ≤ 2 次操作」）。
- P3：系统带（设置/账户下沉）、预留「消息渠道」行；为四带契约登记 ADR 与门禁。
- ~~D5 未定项：侧边栏宽度 350pt → 280/290/300pt 三选一~~ **已作废（2026-09-18）**：宽度是可拖拽用户偏好，基座契约默认 280px、实测渲染 279pt，DSH 不在参照带之外，本轮不做宽度改动。

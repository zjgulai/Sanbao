# ADR-0079 · 同一列里的注入式侧边栏行必须声明同一条行轴；一致性由「清单 + 显式期望值」守，不由纪律守

- 状态：accepted
- 日期：2026-09-13
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-13-injected-row-axis-single-home.md)
- 相关：ADR-0009（一份事实一个家）、ADR-0069（清单本身即判据）、ADR-0075（判据的射程与空射程）、
  ADR-0078（同一场会话的另一半：那条守「改完怎么生效」，本条守「两处一致不一致」）、
  总账 P-07（一条事实多个家，只改了其中一处）、P-08（用纪律守只有机制能守住的东西）、
  P-02（仪器假绿）

## 背景

DSH 的侧边栏 shell 没有可注册的 slot，本地插件用 DOM 注入把自己的行插进「新建会话」按钮与
工作区浏览区之间。**注入逻辑共享**（`sidebar-entry-core.ts`，两包各持一份同步副本），
**样式不共享**：每行自带一个 CSS module，只经核心取 `.entry` / `.entryIcon` / `.entryLabel`。

于是「一行侧边栏导航行长什么样」**住了两个家而没有一处是清单**，两行各带一套宽度约定：
`role-matrix` 是 `width: calc(100% - 8px)` + `margin: 2px 4px` + `padding: 6px 8px`（content-box），
`skill-center` 是 `box-sizing: border-box` + `width: 100%` + `padding: 0 10px`。
重启后 AX 实测行框 68…316 与 64…320，两行左右缘各差 4px。

关键事实是**这个缺陷当天已经被修过一次、只修了一半**：先修的是字段可见的「文字居中」
（`text-align` 是继承属性，`<button>` 的 UA 默认 `center` 继承到 `flex:1` 的标签 span），
修时留下的注释准确写出了根因并引用了 P-07，**几何那半却原样留着**。可见「记住了根因」
不等于「有一处机制在对照」——P-08 的形态。

同一场取证还推翻了一个**分组错误**：把底部「深度研究」与导航两行并成一组会得出相反结论
（它走官方 `sidebar.footer.action` slot，实测 62…314，与同节原生「知识库」逐像素重合，
**与导航列不同才是对的**）。据此确立了本条对「列」的定义：**判据按列分组，不按「看起来像不像」**。

## 决策

1. **同列同行轴**：同一列（同一父容器、同一套几何算法）里的注入行，其水平轴元组
   ——`box-sizing` / `width` / 水平 `margin` / 水平 `padding`——必须完全相同。垂直轴
   （高度、行距 `margin-block`）**不在判据内**：行距允许逐行不同。

2. **期望值是声明出来的，不是推导出来的**：每一列在门禁里显式写下一个期望轴
   （导航列 = 原生侧边栏行轴 `border-box` / `100%` / 水平 0 / `padding-inline 10px`）。
   **禁止「拿第一个行当基准」**——那种写法在第一行本身就错时恒绿，正是 P-02。

3. **清单本身即判据**（沿用 ADR-0069 的形态）：扫出仓库里所有注入行，未登记即判红；
   登记项指向不存在的入口、或行的 `position` 与清单不符，同样判红。所以清单只减不增不会腐烂，
   新增注入行也不会静默逃逸。

4. **不追求「一处共享样式」**：两个包各有品牌与交互细节，抽共享样式包在 `file:` 装配下
   只会引入**新的**需要同步的副本（用一份新副本取消两份旧副本是净亏）。本 ADR 只把
   **一致性**机器化，把「家」的数量留给架构上真正值得合并时再谈。

5. **判据的射程与边界必须自己报出来**：射程为空判红而不是报通过；读数常显
   `已登记 N 个注入行、M 列；其中 K 行断言了行轴`。本项**只读声明文本、不读渲染结果**，
   边界写进模块注释。`split` 列（几何由 `applySplitGeometry()` 运行时算）与底部官方 slot
   的行（与原生行一致才是对的）**明确不纳入**，并写明理由。

## 备选方案

- **只修这一次，靠注释与纪律**：已被证伪——同一天就是这么失败的。
- **AX 探针进门禁**：判据会绑在「机器上恰好开着 GUI」，时红时绿比静态判据更坏；
  渲染一致性改由验收时的 AX 读数负责，两者分工写明。
- **抽共享样式包**：见决策 4。
- **把底部 slot 的行一起统一**：会让它们背离自己那一节的原生行，是反向修复。

## 后果

**正面**：两行落在同一条轴上，且是**构造性**的（同父节点、同元素、同样的盒模型与 padding）。
门禁有 13 条反向自测，含恒真桩突变（只核对「登记了没有」的实现必须失效）；
并在**真实树上**端到端验过它会咬人（改回缺陷形状当场报三条违规，随后逐字节还原）。

**负面 / 代价**：判据读声明不读渲染，挡不住「声明一致而渲染不一致」；`REGISTRY` 需人工维护
（这正是设计意图：让「忘了」变红灯）。几何生效仍需**重启应用**（ADR-0078）。

# ADR-0204 · 桥加"流式调用"：帧有界、序号为序、重连以基线对账

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：用户（lute：在"加流式通道／本地另记一份／只取一次快照"中选 A——加流式通道）+ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-workspace-follow-stream.md)
- 相关：[ADR-0203](ADR-0203.md)（桥从只读扩成受控方法）、[ADR-0198](ADR-0198.md)（host 侧消费与登记）

## 背景

工单 012 的验收（"重连后列表与 baseline 完全对账""增量乱序不产生幽灵项"）要求真的订阅。取证：基座**没有**平铺的工作区列表方法，唯一来源是 `workspace/follow`，而它是流——`baseline` 一帧 + `upsert` / `remove` / `order` / `archived` 四类增量。ADR-0203 的桥是请求/应答形状（一次 call 一次 result），没有推送位。

## 决策

1. **D1 新帧型**：`HostEvent` 增 `bridge-frame { callId, seq, frame }`；`bridge-call` 复用同一帧型做订阅请求。端点表的 kind 增 `stream`，`workspace/follow` 是第一个（也是当前唯一）stream 端点。
2. **D2 帧有界**：`MAX_BRIDGE_STREAM_FRAMES = 256`，超出即以 `bridge-stream-overflow` 终止订阅——一条订阅不得无界增长。两侧各自判：host 侧迭代时判，child 侧 emitter 返回 false 时以 `bridge-stream-closed` 收口。
3. **D3 序号即序**：`seq` 由 host 侧单调递增，main 侧对 `seq <= lastSeq` 的帧**直接丢弃**（重复或乱序都不合并），因此重放不能复活过期行。
4. **D4 重连＝重新折叠**：`readWorkspaceList` 每次都从空状态开始折叠，新 baseline 覆盖一切；这是"重连对账"的实现方式，而不是把增量并进旧视图。
5. **D5 增量不得造行**：`order` 帧只能给"已存在的 id"排序，未知 id 忽略（幽灵行正是本票禁止的对象）；`upsert` 可以新增（存在性由基座裁决）；`remove` 只删已有；`archived` 只改计数。
6. **D6 形状自检在消费侧**：桥只保证"纯数据"，不保证是本流认识的形状；折叠器逐帧判型，不认识的帧**计数**而不套用（静默跳过会读成"没变化"）。
7. **D7 一次调用一个消费者**：`bridgeCall` 对 stream 端点直接拒绝（`bridge-stream-requires-consumer`），避免有人用请求/应答 API 订阅流、把帧全丢掉还自以为拿到了列表。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 本地另记 Sage 自己采纳过的工作区 | 否决：工作区事实变两个家（P-07），删除/重命名永远对不上。 |
| 只取 follow 的第一帧当快照 | 否决：能显示列表，但"增量不乱"这条验收没有对象——不假装达成。 |
| 不设帧上限，订阅长开 | 否决：一条订阅可无界增长，正是 ADR-0190 那类"没有上限的通道"要避免的。 |
| 让 main 替 host 排序（按心跳/时间戳） | 否决：序号必须由生产者给，消费者猜序会把乱序伪装成有序。 |

## 后果

- 桥现在有第三种调用形态（read / interactive / write / stream），并且**流是唯一有显式上限的形态**：其它三种天然一次一答。
- 消费侧第一次持有"订阅期状态"（折叠），因此重连语义必须写成"从空折叠"——这是本票验收的机制，不是实现细节。
- **顺带修掉一处真实接线缺陷**：child 侧 `bridgeCall(endpoint)` 丢掉了 payload，导致任何带参数的端点（如 `workspace/create`）在真实链路上必然以 `bridge-payload-invalid` 结束；已改为 `bridgeCall(endpoint, payload)` 并有 010/012 两条探针覆盖。
- 已知未闭：删除/重命名/排序的用户面（`workspace/delete|rename|insertBefore`）未接；"删除工作区 ≠ 删除目录内容"这条 UI 区分待做。

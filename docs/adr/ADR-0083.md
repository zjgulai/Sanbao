# ADR-0083 · frontmatter 重写必须保留键的原位：字节不变是开关的承诺，而键序看不见

- 状态：accepted
- 日期：2026-09-14
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-14-switch-rewrite-key-position.md)
- 相关：ADR-0041（`dsh-algo-skills-local` 入库：分类的运行时家是已安装技能本体）、
  ADR-0014（门禁硬门槛）、ADR-0015（非机械改动必须留痕）、
  总账 P-16（格式层的不变量没有读者，只有字节比对看得见）

## 背景

`lib` 里只有一处写 `~/.dsh/skills`：算法技能页的开关（`disable-model-invocation` /
`user-invocable`），实现在 `packages/surfaces/dsh-algo-skills-local/src/frontmatter.ts` 的
`rebuildFrontmatter`。它对用户的承诺写在自己的注释里：**点两下开关 = 磁盘上一个字节都没变。**

原实现把这两个键**从块里摘掉、追加到块尾**（`kept` 数组 + 两个 `write(...)`）。这个写法在
「两个键本来就在块尾」的卡上完全正确——而它恰好是组装器（`assemble-skills.mjs:173-175`）
产出的形状，也就是写这段代码时看得到的形状。

但语料里有第二种形状。带精选线换底字段的卡（`rebase_evidence_*`）把这两个键排在**中间**：
`rebase_*` 是后来由 vault 侧追加的，追加发生在开关之后，于是开关不再位于块尾。

实测（2026-09-13，1390 张已装卡全量）：

| 形状 | 张数 | 原实现下的结果 |
| --- | --- | --- |
| 无 `rebase_*` 键（开关天然在块尾） | 1245 | 字节不变 ✅ |
| 有 `rebase_*` 键（开关在中间） | 145 | **每张都漂移** ❌ |

漂移的形态是纯粹的**键序变化**：`… enabled / disable-model-invocation / rebase_*`
回来变成 `… enabled / rebase_* / disable-model-invocation`。

## 决策

**`rebuildFrontmatter` 保留每个开关键的原位。**

- 块里已有的键 → **就地在原行改写**，不移动；
- 块里没有的键 → 追加到块尾（先 `disable-model-invocation`、后 `user-invocable`，与组装器的顺序一致）；
- 重复出现的键 → 只保留**最后一次**出现的那一行（那是加载器实际读到的），并留在它原来的槽位上。

即：「替换而非追加」这条语义不变，但**替换发生在原位**。键序是文档字节的一部分，
而字节不变是开关对用户的承诺。

## 备选方案

1. **改测试**（把「字节不变」放宽成「值不变 + 键集合不变」）。
   否决：那把产品缺陷变成测试的错。用户点两下开关，磁盘上少了两行、多了一行——这类
   不可见的变化正是这条测试存在的理由；放宽它等于亲手拆掉唯一的守卫。
2. **改语料**（把 145 张卡的键重排成「开关在块尾」）。
   否决：语料是上游产物的实物（`rebase_*` 由 vault 侧写入，本仓库没有它的写入器），
   把实物改成代码喜欢的形状，就是 ADR-0082 说的「用改数据去修仪器」。而且下次重装
   上游产物会把改动洗掉，漂移原样回来。
3. **只靠语料测试守着**（不补纯函数单测）。
   否决：语料测试在**没有语料的机器上会跳过**（注释自己承认「worth nothing on a machine
   with no cards」），CI 与全新检出都拿不到这条保护。见「后果」第二条。
4. **接受漂移，在注释里写明**（把它降级成已知限制）。
   否决：这条不变量**没有读者**——键序不进任何解析结果，值也原样往返，所以漂移在系统里
   完全不可见，只有字节比对能发现。一个没有读者的不变量如果只写在注释里，它迟早会变成
   又一次静默的数据改写。

## 后果

**正面**

- 开关的承诺在**全部 1390 张**卡上成立（此前 1245 张）。实测：修复后全量语料
  `UNCHANGED=1390 / DRIFTED=0`。
- 补了三条**纯函数**单测（键在块中间、重复键收敛到最后一个槽位、只缺一个键），
  它们不依赖本机语料，在 CI 与全新检出上同样有效——这是把守卫从「环境依赖」变成
  「语言无关」的那一步。

**负面 / 残余**

- 块内**混用行尾**时仍按首行的风格归一（既有残余，本次未变）。
- 键序的实现依赖「先记槽位、再按槽位回填」这一手法；改动该函数时若退回「收集 + 追加」，
  漂移会原样回来。这正是那三条纯函数单测存在的理由——它们能在**没有语料**的机器上判红。

# ADR-0168 · Boot-scoped Host live inventory projection 与生命周期失效

- 状态：accepted（2026-09-28）
- 日期：2026-09-28
- 决策者：用户（lute）
- 决策记录：[Host Live Inventory 架构与交接](../notes/proposed/architecture/2026-09-28-host-live-inventory.md)
- 关联：[ADR-0139 · 自有 Electron 薄壳](ADR-0139.md)、[ADR-0165 · Sage Compatibility Authority](ADR-0165.md)、[ADR-0166 · Compatibility 双层 exact-digest](ADR-0166.md)、[ADR-0167 · Runtime Artifact Attestation](ADR-0167.md)

## 背景

WT-02C.2A 已能在 profile 激活前重算并封存安装后文件，但安装时 attestation 不能证明某个当前 Host boot 正在使用该 generation，也不能证明 Loader 仍处于已验收的 active 状态。原有 Host `ready` 只携带 protocol 与 Harness version；Electron main 没有 boot identity、runtime epoch、可读取的冻结快照或 ready 后失效事件，因而无法把 active profile、receipt、安装 attestation 与当前进程生命周期绑定。

同时，Compatibility V2 的 `RuntimeInventoryEvidenceV2.activeGeneration` 被错误定义为 number，而真实 profile generation 是受约束的 string；`runtimeGeneration` 又允许 0。若不先校准，这条接缝会迫使调用方丢失真实 generation identity 或制造无法审计的映射。

WT-02C.2B 只关闭 boot-scoped Host live observation 缺口。完整 runtime inventory 还需要外部 capability evidence、Capability Registry、可信 provider composition 与 evaluation evidence，不能在缺项时用 placeholder 补齐。

## 决策

1. **由 Electron main 拥有 boot identity 与 runtime epoch。** 每个新 Host child 获得新的 namespaced UUID `bootId` 与正整数 `runtimeGeneration`；Host 不产生或回传这两个 authority-owned 字段。main 对外只提供冻结的 active / unavailable runtime snapshot。
2. **Sage Host IPC lifecycle event protocol 升级为 v4，FD3/FD4 frame 继续保持 DSH3 v3。** `ready` 必须精确回报已验证的 profile generation、raw lowercase manifest SHA-256、`loaderPhase: "active"`、Host lifecycle protocol version 与 Harness version。ready 发生在 Loader settle 与 ACTIVE audit 之后；陈旧 child 的 ready 不得激活新 epoch。`SHELL_REQUEST_PIPE_FD`、`SHELL_RESPONSE_PIPE_FD`、`SHELL_PIPE_CHUNK_BYTES`、`FRAME_MAGIC`、`FRAME_HEADER_BYTES` 与 `MAX_CONTROL_PAYLOAD_BYTES` 继续逐值 pin 上游 frame wire；`SHELL_HOST_PROTOCOL_VERSION` 只版本化 Sage↔Host IPC lifecycle event，不再要求等于 vendor `DESKTOP_HOST_PROTOCOL_VERSION`。本项以前向决策取代 ADR-0139 D1/D4 中“七个协议常量全部逐值相等”的部分，子进程、FD3/FD4 framing 与其余六个常量的原决策不变。
3. **生命周期变化立即失效。** ready 后任一 Cordis Loader status transition，以及 Host `runtime-invalidated`、fatal、exit、disconnect 或显式 stop，都让当前快照同步变为 unavailable 并推进 runtime epoch；生命周期失效优先于时间窗。
4. **只从 receipt-verified active profile 读取 C2A binding。** active profile 解析同时暴露 receipt 已封存的 runtime attestation row；旧 generation 若没有该 row 仍可被一般 profile 读取，但不能产生 live projection，也不做隐式 backfill。
5. **投影采用双 Host / 双 profile 观察。** provider 依次读取 Host snapshot A、active profile A、fresh verify C2A attestation、active profile B 与 Host snapshot B。两次 Host 与 profile binding 必须逐项一致；任一 pointer、receipt、generation、manifest、boot、runtime epoch、Loader 或 attestation 漂移均返回稳定 unavailable code。
6. **最后取时钟，固定半开 freshness window。** 只有全部文件与进程观察稳定后才调用 main-owned clock；`observedAt` 到 `expiresAt` 固定为 30 秒半开窗口。时钟回退、无效时间或已过期结果默认拒绝，不延长旧 observation。
7. **建立独立、canonical、冻结的 `HostLiveInventoryProjectionV1`。** projection 精确绑定本次 Host facts、active profile / receipt 与 C2A artifact / attestation digests，并以版本化 canonical JSON 计算 SHA-256 digest。返回值与嵌套对象均冻结；未知字段、错误 namespace 或非 canonical 输入不得被默认为安全。
8. **校准 Compatibility V2 generation grammar，冻结 V1。** V2 `activeGeneration` 改为真实 generation string，`runtimeGeneration` 只接受 positive safe integer；只重算受影响的 V2 inventory evidence goldens。V1 类型、canonical bytes、digest namespace 与 goldens逐字保持。
9. **保持证据边界。** Host live projection 只证明一次 boot-scoped observation；它不包含或替代 external capability descriptor、Registry / revoke、Matrix outcome、health / liveness placeholder、Identity / Policy、完整 `RuntimeInventoryEvidenceV2`、产品授权或副作用执行权限。
10. **本批不接产品。** 不修改 `main/index.ts`，不调用 `CompatibilityResolver`，不扩展 `BusinessMatter` v1 event schema，也不启用插件、Adapter、renderer 或 UI。WT-02C.2C、WT-02C.2D、WT-02C.3 与 WT-02D 继续独立推进。

## 备选方案

| 方案 | 为什么未采用 |
| --- | --- |
| 把安装时 attestation 直接当 live inventory | 它没有 boot、runtime epoch、Loader 生命周期或 observation time，无法证明当前进程仍在使用该 generation。 |
| 由 Host 自报 `bootId`、runtime generation 或完整 authority | 被观察对象不能自行铸造观察 authority；这些 identity 必须由 Electron main 创建并绑定 child 生命周期。 |
| 只依赖 Host `ready` | ready 是一个瞬时事件；没有可读取快照和 post-ready invalidation 时，后续 Loader / process 漂移仍可能沿用旧结果。 |
| 只读一次 Host 与 active pointer | 扫描期间发生 pointer、receipt 或 child epoch 切换会形成混合时点证据；双快照可以检测可观察漂移。 |
| 在本批直接构造完整 `RuntimeInventoryEvidenceV2` | C2C external capability、C2D Registry / Adapter mapping 与 trusted composition 尚不存在；填空会把未知伪装成已验证事实。 |
| 用时间戳或进程 PID 充当 boot identity | PID 可复用，时间戳可能回退或碰撞；namespaced random UUID 更适合不透明 boot identity。 |
| 给旧 generation 自动生成 attestation | backfill 无法重建当时 activation transaction 的观察边界，会把事后扫描伪装成历史封存事实。 |
| 保留 V2 numeric generation 并在 composition 中映射 | 会丢失真实 generation identity，且把错误合同扩散到尚未接产品的调用链；当前是最低风险修正窗口。 |

## 后果

- 正面：Electron main 可以读取一个与具体 child、active profile、receipt 和安装 attestation 同时绑定的冻结 observation；进程或 Loader 生命周期变化会立即撤销它。
- 正面：string generation 贯穿 profile、Host 与 Compatibility V2，不再需要不可逆 numeric 映射；V1 迁移证据保持冻结。
- 正面：旧 generation 仍保持可读，不因缺少新 attestation 被破坏；只有需要 live projection 的路径 fail closed。
- 正面：Sage lifecycle event 可以按自有 ready / invalidation 合同演进，同时继续逐值 pin 不曾改变的 DSH3 v3 frame transport；两类版本不再互相冒充。
- 代价：每次投影都需要两次 Host / profile 观察与一次 C2A fresh tree verification，成本随安装树规模增长；30 秒只限制结果可复用时间，不减少本次扫描成本。
- Residual：profile 与 Host 观察仍基于 pathname / process message，不能消除同一 UID 主动攻击者在极窄 TOCTOU 窗口内的所有能力；生命周期 invalidation 与双快照只缩小并检测可观察漂移。
- Residual：projection 没有证明外部 MCP / capability artifact、normalized tool contract、health、Registry allowlist / revoke 或 Adapter mapping；这些缺口保持 unknown，不能由 product composition 猜测。
- 边界：本地 Green、隔离 Host smoke、固定 TTL 与某次耗时都不是发布、生产 SLO 或完整 compatibility authority 证明。

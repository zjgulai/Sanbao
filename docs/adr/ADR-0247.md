# ADR-0247 · 建项责任默认值：main 登录投影一处取值、表单面默认与「改责任不动权限」

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-022、US-008 已定方向；用户裁决「走真环境」）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-draft-responsibility-default.md)
- 相关：[ADR-0209](ADR-0209.md)（002 草案是本设备对象：未登录即锁、字段只由用户 update 写）、[ADR-0183](ADR-0183.md)（2B.2B 真 OIDC 登录适配与 5s→轮询收敛）、[ADR-0198](ADR-0198.md)（host 消费登记——本票零新增）

## 背景

工单 004（US-008，FW-022）：**责任字段默认填入当前已认证身份，且 UI 自报身份不作为授权依据**。
依赖面曾因「真实 Organization Policy Provider 未就绪」暂缓；本次按用户裁决**走真环境**（真实
Logto 部署输入已在树内，公开客户端 + PKCE），在真机完成登录→默认→编辑保存→登出的全链取证。

## 决策

1. **D1 默认值只从 main 的身份投影取**：责任默认 = 同一份 `service.auth` 投影（`status`/
   `displayName`，来自真登录链的 vault 快照）——renderer 不自造、不从任何 UI 文本推身份；
   identity handle 是 main 内部运行期引用（2B.2E「绝不进入 renderer 面」），**不落进本设备
   草案记录**，也不写进表单值。
2. **D2 默认只在表单面提供、随用户保存落盘**：saved 的 `fields.responsibility` 非空时优先，
   默认位让开；默认文本仅在输入框为空或仍等于上次注入值时注入（用户正在输入的文本不被覆盖）；
   只在用户点「保存草案」时随其保存动作落盘（US-010「字段只由用户 update 写」不破）。
3. **D3 无身份不伪造**：signed-out＝空＋「未认证：责任字段没有默认值——登录后自动填入当前
   身份（不用占位身份填充）」；pending＝「登录中」；signed-in 而无显示名＝「显示名未提供——
   不伪造（可手动填写）」。身份态变化（登录/登出/换名）按 `updatedAt|status|name` 修订号重算，
   未被动过的默认会被撤回，改为缺失说明。
4. **D4 改责任值不改变任何权限判定**（入口面 + 结构面 + 读出面三重）：草案路由**不接受任何
   identity 形状成员**（顶层与 fields 双层精确键，走私一律 400）；一次责任编辑恰好触发一个
   port（draft-update），命令/授权管线（`commandPorts` 全 spy）**零调用**；编辑前后
   `service.auth`/`reason`/`command` 逐字节不变。
5. **D5 真机探针抓到并修复一个 Fake DOM 盲区缺陷**：`draftSelections()` 直呼
   `children.filter`——真 DOM 的 `HTMLCollection` 没有数组方法，导致**实机「保存草案」点击
   抛 TypeError、整条保存链不发包**（此前全部证据来自 Fake DOM，其 `children` 是数组）。
   改为 `Array.from(...)`；此类实机专属缺陷电池（Fake DOM 面）抓不住，只能靠真机探针，
   已在 LOOP 行坦登记。
6. **D6 首版不做**：组织岗位/协作管理/主责交接（工单边界）；跨组织任职与主责指定仍待
   Identity/Policy 面后续。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 默认写进草案记录（create 即填） | 否决：破 US-010「字段只由用户 update 写」；且草案是本设备对象，默认该在表单面给。 |
| 把 identity handle 填进表单/存进草案 | 否决：handle 是运行期内部引用、绝不进入 renderer 面；且进程本地随机值不可跨重启引用。 |
| renderer 从页面文本/URL 自取身份名 | 否决：US-008「UI 自报身份不作为授权依据」；只用 main 投影同值。 |
| 登出后保留未保存的默认文本 | 否决：身份态变化后旧默认会误导；未被动过的默认撤回为空＋缺失说明。 |
| 默认由 main 在 update 路由里代填 | 否决：写路径保持纯用户驱动（同 ADR-0209 纪律）；默认是表单层建议。 |

## 后果

- 验收两条机器断言：①未认证不伪造（渲染契约面：空＋缺失句；真机面：登出后草案面整体锁定
  per ADR-0209，create=locked）；②改责任值不改变任何权限判定（走私 400＋单 port＋管线零调用＋
  投影逐字节不变）。
- 真机读数（真实 Logto，隔离 SAGE_ROOT，CDP 探针）：点击登录 → `pending` → `signed-in`
  `displayName="PrayChow"`；建草案后 `#draft-responsibility.value="PrayChow"`＋默认句；改
  「探针代填·钱十」→ 点保存 → `state.draft.drafts[*].fields.responsibility="探针代填·钱十"`
  （落盘）；点退出登录 → `signed-out`，create 回 `locked`。截图 `real-default.png` /
  `real-after-logout.png` 在 `/tmp/wk004/`。
- 真机链排查并修复两处**真机专属**问题：①`HTMLCollection.filter`（上 D5）；②**失败构建仍
  产出**：反引号注释破坏模板字面量→tsc 报 TS1005 但**默认仍 emit**，materialize 把这个损坏
  emit 固化进 profile（§1.6 页面截断、UI 全死）——教训：模板字面量里的注释禁写反引号；
  `npx tsc | head` 后的 `$?` 是 head 的退出码（P-17 复发），构建判绿必须不带管道取退出码，
  且 dev 循环「先干净构建 → 再 materialize → 再启动」。
- 面/装配：渲染（`renderDraft` 责任默认块＋`#draft-responsibility-note`）＋`Array.from` 修复；
  路由/装配零改动（复用既有 draft-update）；名册与 host 消费登记零新增。
- §1.6：离线两宽（1440/660）已在真机截图外补齐三态渲染证据。

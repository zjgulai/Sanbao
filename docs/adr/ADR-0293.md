# ADR-0293 · 回合收口：轻终态事件、cursor 边沿与重复发送解锁

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：同意回合收口粒度推荐）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-turn-close-step.md)
- 相关：[ADR-0289](ADR-0289.md)（dispatch v1 不写收口）、[ADR-0291](ADR-0291.md)、[回合收口侦察（2026-10-11 报告，随本批入 Note）]

## 背景

dispatch v1 故意不写域收口：一次真实 send 成功后 attempt 保持 active，同一 matter 的第二次 send 在 persist 处被 `active-attempt` 拒绝。域既有收口路径是 artifact→receipt 两段（receipt 语义为**人工评审回执**，actor 必须等值建单人）——对每条聊天回合执行该循环会把会话变成逐条评审队列，且 receipt 的 actor 映射今天不存在。侦察报告提出 per-send vs per-revision/session 的粒度疑问；用户裁决采纳「域扩展轻终态事件、per-send attempt 保留」。

## 决策

1. **D1 轻终态事件 `attempt-succeeded`**：域词汇表第 12 型（codec EVENT_TYPES + 载荷 `{attemptId}` + strict replay 分支 + 投影：attempt succeeded、activeAttemptId 清空、stage 回 `evidence`——同一 revision 内立即可起下一次 attempt）。人工 receipt/artifact 评审路径原样保留，供需要评审的事项使用。
2. **D2 turn-end 边沿 = `${cursor}:${kind}`**：`SessionChannelStatus.lastTurnEndEdge` 新字段（Fold 内累积；`lastTurnEnd` 纯 kind 字符串保持不变——UI 以 `=== 'error'` 分支消费）。修复「同 kind 连续回合漏触发」缺陷（旧观察器只比对 kind）。
3. **D3 收口 runner（main-owned，观察驱动）**：`completed` → `attempt-succeeded`；`error|max-tokens|aborted` → 既有 `attempt-failed`（source `runtime`；matter 入 `failed-retry`，其再入仪式已存在）；`blocked` 与未知 kind **保持 attempt 打开**（无诚实终态语义，登记裁决项）。appendId = `turn-close:<attemptId>:<kind>` 幂等；fire-and-forget，从不向观察路径抛错；无活动 attempt 即 no-op。
4. **D4 观察顺序**：新边沿先在 artifact 观察（Ticket 015）之前触发收口。运行入口沿用既有「一回合一次、绝不定时器」的观察读。
5. **D5 门禁**：收口事实组（边沿键、观察顺序、kind 分类表、域 authored、runtime 来源、幂等 appendId、blocked 保持打开）+ 六条具名突变；域侧由 12 型完备性 pin 与载荷突变夹具守（rehydration spec）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| artifact+receipt 循环收口每回合 | 否决：聊天变逐条评审队列；receipt actor 映射不存在。 |
| per-revision/session 粒度（域大改） | 否决（用户裁决）：拆掉逐消息审计；轻终态以最小域改动达成同一目标。 |
| 改 `lastTurnEnd` 为复合串 | 否决：UI 按 kind 字符串分支（`=== 'error'`），加法字段才安全。 |
| blocked 强行映射 fail/succeed | 否决：无诚实语义时保持打开，登记裁决。 |
| send 前 reconcile 兜底 | 首刀登记（侦察 C 版）；**2026-10-11 增补实现**：发送路径先于 prepare 以 best-effort 对账（无 active 即零通道读、执行中绝不打断、复用同一收口 runner）——观察器缺席的卡死自愈。 |

## 后果

- 重复发送解锁：completed 回合收口后，同一 revision 立即可起下一次 attempt（spec 以真实库实证）。
- 失败回合进入既有 failed-retry 仪式；blocked 诚实保持打开。
- 未闭：send 前 reconcile 兜底、blocked 语义裁决、回合产物（artifact/receipt）与轻路径的并存策略、宿主生命周期失效。

# ADR-0254 · UI-IA-01：BusinessMatter 默认只读工作台与三栏信息架构

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：用户（lute，确认执行 UI-IA-01）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-business-matter-readonly-workbench-batch-7.md)
- 相关：[ADR-0159](ADR-0159.md)、[ADR-0248](ADR-0248.md)、[UI 一致性合同](../specs/2026-09-27-sanbao-to-sage-ui-consistency-contract.md)

## 背景

Sage 已有 exact nested `matter` envelope 与严格 ViewState，但默认仍展示装饰性 Overview，真实事项详情位于长卡片墙之后；责任、事实计数、澄清、决定、尝试、产物与回执没有形成当前事项优先的空间结构。固定 Overview trace 还可能把示意状态误读为真实进度。

## 决策

1. `BusinessMatter` 成为默认首屏：Matter tab、panel、fallback 和启动视图统一激活；左侧增加当前事项只读语境，Overview 降为次级视图。
2. 宽屏采用 Sage-owned 左语境 / 中事项 / 右脉络三栏。中栏显示事项身份、目标、责任、阶段、澄清和只读 ActionPreview；右栏显示证据 / 未知 / 依赖计数及决定、执行尝试、产物、回执与阻断事实。
3. 全部内容只取已校验 `SageMatterViewState`；空数组显示空态，不合成 completed 或固定进度。null、malformed 和读取失败必须清空新增 context、计数、澄清、rows 与 previews。
4. 新 composer 不含 form、input、textarea 或业务按钮，不新增 ActionIntent、POST、provider 或 bridge 调用。右栏 drawer 只做本地打开 / 关闭；Escape 关闭并把焦点还给触发器。
5. 900px 以下先收右栏 drawer，800px 以下再压缩左栏，保证中央事项优先。既有已接线操作面保留在工作台下方，本批不改其 route、handler 或 authority。
6. 继续使用 framework-free renderer 只是 UI-IA-01 的有界交付选择：不新增 dependency、package 或 lockfile；完整可组合 / 可写 UI 进入实施前，React 版本、bundler 与测试栈仍须独立 ADR。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 复制或嵌入 Qoder / Sanbao 产品壳 | 否决：外部原型只作证据，不是 Sage runtime dependency。 |
| 保留 Overview 默认并继续固定 trace | 否决：主对象不在首屏，固定状态还会制造假进度。 |
| 从 attempts / artifacts 推导事项 completed | 否决：这些事实不等于 `BusinessMatter` conclusion。 |
| 同批迁移既有写操作到新 composer | 否决：会扩大到 Application Service、authority 与 ActionIntent，不属于本批。 |
| 本批直接引入 React / bundler | 后置：技术栈仍需按 UI-01 前置独立确认。 |

## 后果

- Sage 默认进入当前事项工作台；宽屏三栏、窄宽右栏 drawer 的 IA 有了 Sage-owned 实现。
- 事项责任、计数、澄清和四类 trace rows 均由 exact ViewState 驱动，并随 null / malformed 清场。
- 新 composer 与 drawer 不增加业务 mutation；既有操作面仍位于其下，不能扩大为“事项页全只读”的声明。
- 本 ADR 只完成 UI-IA-01，不声明完整 UI-01、双主题、像素级复刻、AUTH-02E、真实 provider 或生产执行能力完成。

# ADR-0264 · dev 可见承载面：`SAGE_SANBAO_SURFACE=1` 打开 sanbao 承载窗（honest 壳桥）

- 状态：accepted（2026-10-05）
- 日期：2026-10-05
- 决策者：用户（lute，2026-10-05「这206个页面你确认你都集成装配到当前的 Sage 上了，为什么我看见基本都没有做」——L3 层缺口由用户当面点名并以目标形式直接授权补齐）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-05-sanbao-in-sage-visible-hosting.md)
- 相关：[ADR-0262](ADR-0262.md)（承载面与壳桥能力；本次接通其登记的产品接线）、[ADR-0263](ADR-0263.md)（dev 环境提供注入通道）、[打包决策包](../notes/proposed/process/2026-10-05-sage-packaging-decision-package.md)（生产打开形态输入）

## 背景

206 页接线程序此前完成两层：sanbao_ui 原型侧 206/206 桥接与部署（L1）；Sage 侧 `sage-sanbao://` 承载面＋13 方法壳桥（L2，ADR-0262）。但 ADR-0262 明确登记「生产启动创建/打开承载面的产品接线（root 指向与时机、窗口归属）」为未接线——`createSanbaoSurface` 在 `src/` 零调用，运行中的 Sage 从不打开承载面，「206/206」在应用窗口里不可见。用户以「为什么我看见基本都没有做，连主页面的 AI 对话框我都没有看见」纠偏：**L3（Sage 内可见可检）是本轮必须闭合的层**，验收口径按 L1/L2/L3 分层、不许混为一谈。

## 决策

1. **dev 门控打开**：`SAGE_SANBAO_SURFACE=1`（常由 `pnpm dev:debug` 默认注入）时，main 在 ready、主窗加载后打开承载窗（`createSanbaoSurface` 默认独立窗口形态）并 `load()` 入口；未设置该 env 一律不打开——生产默认零变化（打开时机与窗口归属仍是产品决策，见决策包输入）。
2. **honest 桥**：打开时不注入任何 facts——页面按协议如实显示「壳尚未提供该类事实」、fixture 文案保留；绝不伪造业务事实。
3. **失败不致命**：root 缺失/创建/加载失败只打一行诊断（`sage shell: sanbao 承载面未打开——…`），应用照常启动；主窗关闭联动 `destroy()`。
4. **root 解析唯一家**：解析逻辑（env 覆盖 → 同级快照仓 → dist/_site 完整性门）从 test support 迁入 `src/main/sanbao-surface-root.ts`；探针经编译产物 lib 引用、spec 经 src 引用，删除旧薄层。
5. **dev 工具默认开**：`dev:debug` 默认打开（`--no-sanbao` 关、`--sanbao-root` 指定根）；纯开发面，不构成发布/DMG 证据。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| A. 继续只留能力（现状） | 否决：用户已当面点名 L3 缺口；能力无入口＝不可见不可检。 |
| B. env 门控 dev 打开＋honest 桥（采纳） | 最小面接通 ADR-0262 登记的产品接线；生产零变化；失败不阻启动。 |
| C. 直接生产默认打开 | 否决：窗口归属/打开时机/资产打包均未决策（决策包 P0/P1），先越权。 |
| D. 注入 fixture facts 让页面"全亮" | 否决：违反 honest 纪律（fixture 冒充成功）。 |

## 后果

- dev 一条命令即可在 Sage 内看到 sanbao 206 页（真实 Electron）；L3 另以爬检脚本（`apps/sage-shell/scripts/crawl-sanbao-in-sage.mjs`）在真实应用内逐 state 验收。
- 生产打开形态、FramePolicy 合同、写路径、资产打包仍各归其批次（登记在 Note 的 T3/T4）。
- 承载面安全姿态不变（非持久 partition、sandbox、单向 webRequest 门、导航/window.open 拦截）。

# ADR-0253 · UI 接线第六批：attachment upload admission 收口

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：用户（lute，确认执行 AUTH-02D）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-attachment-upload-admission-batch-6.md)
- 相关：[ADR-0174](ADR-0174.md)、[ADR-0217](ADR-0217.md)、[ADR-0249](ADR-0249.md)、[ADR-0252](ADR-0252.md)

## 背景

第五批之后仍有 24 条 protected-effect route 直达 provider。`POST /.sage/attachments/upload` 只有 `upload` 一个 operation 且带显式 `matterRef`，适合作为下一条独立收口；但它当前把 `{ itemId, matterRef, workspaceRoot }` 原样交给 raw attachment owner。该 owner 使用 run-local candidate 与 renderer-supplied root 取得 session，随后建立 Host upload-begin 状态，并在首个 chunk 前启动 upload-commit。它没有 durable operation / idempotency identity，也没有 `outcome-unknown` reconciliation，不能成为合法 production dispatch / persistence provider。

## 决策

1. 本批只关闭 `POST /.sage/attachments/upload` 的 direct-provider bypass。稳定 operation 为 `session.attachment.upload`，candidate 精确为 `{ kind: 'matter', matterRef: request.matterRef }`；不把 `pick`、`cancel` 或其他 route 混入同一完成声明。
2. protected intent payload 只包含 `{ itemId: request.itemId }`。`itemId` 只是未来 main-owned resolver 的 opaque clue，不是 authority；`workspaceRoot`、path、digest、bytes、session / upload / receipt / attachment identifiers、bridge endpoint / chunk / response 与 Host facts 都不得进入 intent、candidate 或 authority ports。
3. production 当前仍缺完整 Identity / Policy、trusted attachment target、Compatibility、Registry、preflight、durable persistence 与 dispatch ports，因此保持 unavailable-first。任何 unavailable / denied / stale 都在 raw owner 前终止；raw `attachmentsUpload`、`ensureSession`、Host upload begin / chunk / commit / abort 与本地 file stream 调用数均为 0。
4. 现有 raw owner 的 run-local candidate、renderer root、upload-begin / commit external state 与缺失 durable scoped request key、canonical intent digest、operation identity、idempotency 和 `outcome-unknown` reconciliation，不满足 ADR-0174；真实上传必须等待另票补齐这些前置与窄 dispatch port。
5. protected admission 数从 11 增至 12，direct-provider bypass 从 24 降至 23；route 总数和 classification 分母不变。本批只证明 bypass 收口，不声明 attachment upload 可用；不改 `pick` / `cancel`、renderer、Host、kernel、dependency、package 或 lockfile，不运行真实 upload E2E，不 commit、不 push。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 保留 direct provider，只依赖候选封存摘要或 UI stage | 否决：它们不能替代 authority ordering，也不能阻止 Host 与 file I/O 副作用。 |
| `matterRef` 匹配 ActiveContext 后直接调用 raw owner | 否决：context 不是 standing authority，后续 authority、trusted target 与 durable dispatch 仍缺。 |
| 把 `workspaceRoot`、candidate path 或 digest 当 trusted target | 否决：renderer path 与 candidate metadata 不是 authority；main 必须 fresh 重算并绑定 exact sealed record。 |
| 将现有 raw owner 作为 dispatch / persistence | 否决：run-local candidate 与 begin / commit external state 没有 durable operation、idempotency 或未知结果收口。 |
| 同批迁移 `pick` / `cancel` | 否决：OS dialog、device / frame、candidate minting 与 opaque item scope 需要各自 authority 设计，不能机械复用 upload admission。 |
| 把现有 domain / Host tests 视为 production upload E2E | 否决：局部语义测试不能证明 Application Service authority、真实 provider 或产品可用。 |

## 后果

- attachment upload 不再有合法 direct-provider 路径；production 缺 port 时稳定 refusal，raw upload、Host endpoints 与文件读取零调用。
- `itemId` 保持非 authority clue；`workspaceRoot`、path、digest、bytes 与 bridge / Host facts 不进入 protected intent 或 authorization。
- raw owner 继续只承载隔离的封存、流式上传和 receipt 语义；未来真实上传必须另票补 durable operation / idempotency identity、trusted target、dispatch freshness 与 reconciliation。
- authority truth 更新为 12 条 protected admission、23 条 bypass；`pick` / `cancel`、剩余 bypass 与真实 upload E2E 保持显式未完成。
- 本 ADR 不构成视觉迁移、dependency 变更、附件上传可用、发布、commit 或 push 证明；验证结果须以本批实际命令回填。

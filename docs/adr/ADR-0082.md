# ADR-0082 · 精选线接入分类底本：只增不改、阻断可见，且工具自己的断言必须先有牙

- 状态：accepted
- 日期：2026-09-13
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/capability/2026-09-13-curated-line-append-and-two-false-greens.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（门禁豁免只减不增）、ADR-0015（非机械改动必须留痕）、
  ADR-0074（技能出货面白名单）、总账 P-02（仪器假绿）、P-04（写了但从没跑到）、P-07（一条事实多个家）、
  P-09（死指针）、P-11（判据的射程没有定义）

## 背景

`staging/<L2 域>/<slug>/SKILL.md` 是产品侧卡的**实物**，`data/classification.json` 是它的
**分类底本**，两者必须对得上：

- 只往 staging 放新目录而不动底本 ⇒ `scripts/verify-install.mjs` 把「占用 `p2s-` 前缀、但底本里
  没有」的目录判成**编外目录**并 exit 1；
- S12 的消费口闸门反过来把「契约引用了精选线 id 但技能目录里没有」记成 `待装线`（实测 14 条），
  并明文写着这是 S5 换底的前置依赖。

两处指的是同一件事：**底本落后于实物**。本次把它落地：`classification.json` 1338 → 1390（+52），
`card-facets.json` 随动重算，`manifest/paper2skills.json` 进目录，并新增唯一 writer
`scripts/append-selected-line.mjs`。

落地过程中暴露的不是数据问题，而是**工具的判据问题**：这个 writer 自带的两条「纪律断言」
**都是恒真的**（改了 `if (false)` 也照样全绿），而它要守的纪律恰恰是「只增不改」。同一批
还核出一条**已存在的**词表分歧。

## 决策

1. **分类底本的增量只从事实源搬运，不在产品侧新造。** writer 的全部输入是 vault 的
   `07-资源库/card-classification.json`（F5 的 146 张卡端事实源）与 `lib/taxonomy.js` 的判据实现
   （`slugFor` / `resolveFacets`）。一个 L3 都不改写、一个 slot 都不新增；每条新增带
   `_provenance`（`from` / `source` / `vault_path` / `added_by`），出处可逐条回溯。

2. **slug 撞车与非法 slug 一律报红，绝不静默改名。** `slugFor()` 把非 ASCII 折成 `-`，
   全中文卡名会折出非法的 `p2s-`（实测命中 1 张：`Skill-大规模消费者评论方面情感分析`）。
   在 writer 里替它改名 = **自造第二套 slug 规则**，S12 的 id→slug 换算会算错。故登记为
   **可见阻断**（`--allow-blocked` 才继续），改名决策留给 `slugFor` 的归属方。
   ⇒ **本次达成的是 52/53，不是 53/53。这条账不许被写成「已全部落地」。**

3. **「只增不改」必须是一条真会判红的判据，且先量后写定口径。** 只比两侧 schema 都有的
   分类事实字段（`l3` / `confidence` / `note`）；不比 `title`（底本存卡面长标题，精选线只有 id
   短名，不是同一事实）、不比 `facets`/`planes`/`domains`（由 `resolveFacets()` 从 `l3` 展开的
   派生量）、不比 `slug`（由 `slugFor()` 派生）。实测射程 93 条：`l3` 93/93、`confidence` 93/93
   逐字一致；`note` 81 条逐字相同 + 12 条「空 ↔ 占位说明 `（产品侧流水线的逐卡理由为空）`」
   ——**同一事实的两种写法**，故比对前规范化，但把「规范化了几条」当**读数**打印，不静默吞掉。
   **射程为 0 单独判红**：「没比对」不等于「没差异」（P-11）。

4. **`--check` 在「有待接入」时必须判红。** 它原先无条件打印「✅ 计划与现场一致」——
   把底本回退到接入前（52 条待接入）实测仍然 ✅ + exit 0。这是本文件里第二条恒真断言。

5. **venue 词表的投递副本与产品侧读端是两件事，不许混记。** `data/venue-tiers.json` 是
   PHASE6-S10 的**已投递、待接读**资产：writer 是仓外
   `paper2skills-research/scripts/build_venue_tiers.py --sync-product`，J9 断言「投递副本与规范表
   逐字节相等」在该脚本里实现并自带三条自测（T9 缺副本→红 / T9b 漂移→红 / T9c 一致→绿）。
   **但产品侧目前还没有 reader**（`lib/axis.js` 仍是硬编码），故此刻它是**尚未生效的事实源**。

## 备选方案

- **在 writer 里给那张卡编一个 ASCII slug**。否决：那是第二套 slug 规则，且 S12 的 id→slug
  换算会随之算错——把一个可见的缺口换成一个静默的错误。
- **把 53 张里的第 53 张先排除出 staging，凑齐「底本 = 实物」**。否决：实物不该为底本的缺口让路，
  那会把「底本落后」变成「实物缺失」，而后者更难发现。
- **把 `note` 的「空 ↔ 占位说明」也判红**。否决：那不是分歧而是同一事实的两种写法，
  判红会让这条判据常红，而常红的判据等于没有（与 P-12「豁免不会过期」同族）。
- **让 `--check` 保持「只出计划、不下结论」**。否决：它已经打出了 `✅`，那就是在**下结论**；
  一个会说 ✅ 而实际有 52 条不一致的开关，比没有这个开关更坏。
- **在本次一并给 `lib/axis.js` 接上 venue 词表的 reader**。否决（本次不做）：接线属 S10 的
  工作包，且要与 J9 的核对方式一起决定（谁在跑、跑在哪一侧、失败算谁的）。本次只把
  「已投递、待接读」这个状态**写清楚**，并登记分歧，不假装它已经生效。

## 后果

- **正面**：底本与实物的落差清零（1390 = 1390，`verify-install` 不再报编外目录），
  新增条目的出处可逐条回溯；工具的两条恒真断言变成真判据，并各带一次 A/B 反向读数。
- **正面**：`--check` 现在是一个**能说不**的开关（正向 0 条→exit 0；反向 52 条→exit 1），
  可安全地放进「换底是否已完成」的验收步骤。
- **代价（未完成的账，如实留着）**：52/53。第 53 张卡要等 `slugFor` 的归属方做命名决策。
- **代价**：`data/venue-tiers.json` 与 `lib/axis.js` 的 `VENUE_LEGACY_PENDING` **已经分歧**——
  投递副本的 `tier_alias` 已把 `workshop` / `demo` / `findings` / `short-paper` 定为 `preprint`，
  而 `axis.js:58` 仍写 `to: null`「留给 S10 决定」。同一事实的两个家（P-07），接线时必须一起改，
  否则「按 axis.js 判」与「按投递副本判」会给出不同答案。
- **已知未挂（本次不修，另行处置）**：S12 的核对器 `check-contract-gate.mjs` 及其 13 组 / 27 条
  变异自测**不在 `pnpm run gate` 的射程内**（`scripts/gate.mjs` 无 `contract-gate` 项）——
  自测从不运行，属 P-04。修它要顺带决定它该挂在哪一步（它的成本与射程都不同于现有 55 项）。
- **已知死指针（P-09）**：`scripts/role-presets/generate.mjs:73` 与
  `packages/capabilities/dsh-paper2skills/lib/contract-gate.js:28` 都把核对器写成
  `scripts/check-contract-gate.mjs`，该路径不存在（实在包内 `scripts/` 下）。

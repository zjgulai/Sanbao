# ADR-0219 · CSV 预览：按实测定标的上限、切在明处、解析失败与空文件分开

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证、实测并实施；上限取值与失败分类是取舍）
- 决策记录：[Note（实现）](../notes/implemented/architecture/2026-10-02-csv-preview-caps-measured.md)、该 Note 同时是容量实测记录
- 相关：[ADR-0218](ADR-0218.md)（产物卡与侧面预览——本票在其预览面内做表格化）

## 背景

工单 016（FW-005，US-039/041）要求：在预览面内对 CSV 做表格解析与呈现；**产品上限来自实测记录，
不照抄基座默认上限**；超限与解析失败各有可区分提示；解析失败不得伪装空文档。矩阵给出基座默认边界
（单次文本页 2MiB、完整文件 32MiB、5000 行、目录 2000 项）——它们是实现默认值，不是产品规格。

## 决策

1. **D1 上限＝本仓实测定标**：`CSV_PREVIEW_CAPS = { maxRows: 2000, maxColumns: 64, maxCellCharacters: 200 }`。
   依据（Note 记录，命令可复现）：上限内最重的可读形状 2000×64×12 实测合计 **38.47ms**（预算 ≤ ~50ms），
   且 1,701,397 字节低于读取页 byte 上限；50,000×32 实测 **1255.51ms**（34× 预算）明确排除；
   2000×16×200 实测 **149.90ms** 且 6.4MB 超出读取页上限 ⇒ 200 字符作显示截断、超长输入由读取层
   拒绝。基座默认值只作为"读取页边界事实"引用，不作产品承诺。
2. **D2 上限与记录互锁**：`test/csv-caps.spec.ts` 解析 Note 的机器可读块并与代码常量逐字段比对，
   另断言记录仍含命令与决定性命中行——记录与实现不许漂移。
3. **D3 切在明处**：行数上限以 `limit = maxRows + 1` 向读取层索取，`eof=false` 即"未读完"；
   列数与单元格超限各自计数；表格下方逐条写明（"只显示前 N 行"、"有 X 个列超出上限"、
   "有 Y 个单元格过长已截断显示"）。**没有任何一种超出是静默丢弃**。
4. **D4 三种事实三种话**：`parse-failed`（未闭合引号、引号后杂字符、未引号字段中出引号）＝
   `artifact-csv-parse-failed`（不可重试，渲染会变成猜测）；真空文件＝`empty` 状态、文档内独句
   "空文件：没有可解析的行（这与'解析失败'是两回事）"；超限＝读取层 `too-large` ⇒
   `artifact-too-large`（可重试同版本）。渲染面两句为不同句子（016 面测试断言互斥）。
5. **D5 解析器纪律**：RFC 4180 引号（含双引号转义、引号内换行）、CRLF/LF、tab 分隔（.tsv）、
   行内列数不齐不判失败；解析只在纯函数里做（`src/main/csv.ts`），表格文档脚本禁用、只读。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 沿用基座默认（5000 行/2MiB）当产品上限 | 否决：US-041 点名不照抄；且 2MiB 只是读取页约束，不是解析预算。 |
| 不设上限、读到哪算哪 | 否决：50k 行实测 1.25s，打开预览会卡住交互；上限与实测预算绑定。 |
| 解析失败时显示空表格或原始行 | 否决：空表格把失败伪装成"空文件"（US-039 反例）；原始行让用户自己猜。 |
| 引号宽松解析（容错收尾） | 否决：会把错位内容当真实单元格，等于替生成方猜测。 |

## 后果

- 两条验收各有机器断言：超限/解析失败两句互斥且各自出现；caps 与实测记录块互锁（漂移即红）。
- 015 的失败句由裸 code 升级为分句表（`ARTIFACT_FAILURE_SENTENCE`），旧句断言同步更新。
- 已知未闭：真机 Electron 未跑（表格在容器内呈现属 015 容器链，替身全测）；列宽自适应/冻结列等
  呈现细节未做（查看为主）；表格编辑与导出改造按工单"明确不做"。

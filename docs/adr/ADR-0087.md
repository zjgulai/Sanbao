# ADR-0087 · 设置页呈现层：锚点取 ARIA 语义而非类名解析；分组是登记制，且「不连续」必须拒绝

- 状态：accepted
- 日期：2026-09-15
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-15-settings-shell-reachability-and-grouping.md)
- 相关：ADR-0008（基座只 pin 不改）、ADR-0009（一份事实只有一个家）、
  ADR-0011（能力五组归位）、ADR-0015（非机械改动必须留痕）、
  ADR-0019（官方 UI 改写锚禁止钉哈希）、
  总账 P-02（仪器假绿）、P-07（一条事实多个家）、P-15（写进磁盘 ≠ 已经生效）

## 背景

用户报「设置面板不自适应、品牌一致性不高、侧边导航没有分类」。实测后两条与描述不符：

- 官方 CSS 已有 `max-width: calc(100vw - 48px)`，缺的是**大屏扩张**；
  1580px 窗口里面板只占 60.6%。
- 导航 **18 项需 852px、面板可用 752px**，官方 `nav` 无 `overflow`、
  `panel` 是 `overflow:hidden` —— **最后两个设置页被裁成 1px 高，完全不可达且不报错**。
  这不是观感问题，是功能缺陷。

分组在契约层面**不存在**：`settings.section` 只投影 `id`/`order`/`label`，
没有 group 字段，而 shell 自己「零自有文案、纯组合面」。

三个约束同时成立：基座只 pin 不改（不能碰官方包）、官方类名是内容哈希
（`MI-_Aa_panel`，跨版本必变，ADR-0019 明令禁钉）、
已经有第三方插件（`dsh-better-sidebar`）在同一个 DOM 上做注入（不能与它打架）。

## 决策

**一、锚点层级：ARIA 语义优先于类名解析。**

设置 shell 的 DOM 自带公开语义 —— `[role="dialog"][aria-modal="true"]`
（且直接子元素含 `<nav>`）、`nav` 内的 `button`、当前项的 `aria-current="true"`。
用它们定位，**一个类名都不解析**。

这比项目既有的「包路径锚 + 局部名负向断言」（`dsh-root-brand/live-selectors.ts`）
少依赖一层「模块文件名」，且避开了「同一机制写第二份实现」的分叉风险。
列表容器由按钮**反推**共同父元素，不写 `div:last-child` 这类结构猜法。
`validate-build.mjs` 加反向自测：产物中出现哈希形状选择器即判红。

**二、三态读数：「没量到」与「量到但不对」必须分开。**

`absent`（设置页没开，正常）/ 解析成功 / `drift`（结构变了）。
但 `drift` 只在**曾经成功解析过**之后才可能触发 —— 页面上随时有别的 modal，
它们没有 `<nav>` 是正常的；一律报漂移会把读数变成噪声，最终被无视（P-02）。

**三、分组是登记制，且用三条拒绝条件守住正确性。**

`groups.ts` 的 `SETTINGS_GROUPS` 是分组唯一的家；未登记 section 落「其他」组
而**不会消失**。三条拒绝条件（宁可没有分组，也不错着显示）：

1. 注册表条数 ≠ DOM 按钮数 → 不注入；
2. 某组在渲染顺序里**被别的组打断** → 不注入；
3. 期望状态已成立 → **一个字节都不写**（观察器监听整个 `body`，写就自激）。

第 2 条是实际踩到的：order 28 上挂了两个 section（`generic-skills` 与
`wanzh-hulian`），按语义最优划分会让 `algo-skills`(29) 显示在**「扩展」标题之下** ——
归属错位，且看起来完全正常。故分组表按「每组在渲染顺序里连续」重划，
并把连续性做成**判据**而不是纪律。

**四、品牌色只做点缀，不做大面积染色。**

当前项左侧指示条 + 键盘焦点环。浅色模式用加深变体 `#3d8a33`（白底 4.30:1），
深色用原色 `#58B848`（深色面板 5.24:1）—— 原色在白底上只有 2.51:1，不达标。

**五、尺寸走保守档。**

宽度上限 800→960px、纵向边距 48→32px。不一步放到 1100px+：
14 个非官方设置页从未为宽屏设计过，放大幅度是独立决策，不夹带在本轮。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 改官方包 / 替换 shell | 基座只 pin 不改；碰 `sidebar.settings` 即碰 shadows-shipped-ui 红线 |
| 包路径锚 + 局部名负向断言 | 可用但多依赖「模块文件名」；且要重写一份已有实现（P-07） |
| 按 `textContent === label` 认行 | 文案一变即静默错位；本包能读注册表，没有这个约束 |
| 纯 CSS 伪元素分组标题 | `nth-child` 把当前顺序钉死，插件增删即整张错位 |
| 分组表按语义最优、不做连续性检查 | **实际踩到**：会让 `algo-skills` 落到别人的标题下 |
| 面板宽度一步到 1120px+ | 14 个第三方设置页需逐个验收，留作独立决策 |
| 折叠（disclosure）替代滚动 | Apple HIG 首选，但每项多一步点击；留作 L3 |

## 后果

- **可达性恢复**：18 项全部可达；窗口再矮也只是滚动，不再静默消失。
- **归属成为登记制**：新插件不改表也不会消失（落「其他」）；
  要进对的组必须往 `groups.ts` 加一行 —— 归属是产品判断，不该由启发式猜。
- **连续性从纪律变成判据**：将来有人把某 section 的 order 挪到别组中间，
  分组会整体拒绝并在诊断属性写明 `non-contiguous`，而不是错着显示。
- **与第三方注入共存**：本包只插 `<div data-dsh-ss-group>`，不碰任何 button、
  不改按钮 ARIA，故 `dsh-better-sidebar` 的 `[role="dialog"] nav button` 标记不受影响。
- **生效路径**：改 → 构建 → `sync-profile.mjs --apply --loadpoint` → **重启应用**。
  刷新页面在打包应用里原理上就不是生效路径（P-15）；「重启是唯一路径」的三条独立读数，
  以及「核对产物必须认准应用包内那一份（0.1.2-rc.1，而非 /opt/homebrew 的 0.1.5-rc.2）」
  这条差点写错的判据，均记在 [Note](../notes/implemented/surface/2026-09-15-settings-shell-reachability-and-grouping.md)。
- **L1 已在真引擎证成**：官方 CSS + 官方 DOM 结构 + 真实产物在 Chrome 里跑 A/B ——
  官方原样静止时 15/18 项可见，本包 18/18 可达，按钮高度恒 40px（不靠压扁来假装箱），
  真实产物读数为 `grouped:5`。方法与逐项读数在 Note 里，此处不复述（ADR-0009）。
- **未验证的部分**：活页面重启后的首次读数。经上述真引擎验证后，残余风险已收窄到
  **装载路径**（profile → 模块图 → HTTP → 渲染进程）这一条。

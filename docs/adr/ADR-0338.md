# ADR-0338 · 启动链补遗：单实例锁与 admission 具名容忍

- 状态：accepted（2026-10-13）
- 日期：2026-10-13
- 决策者：用户（2026-10-13「对于遗留事项，请继续进行处理」）＋ agent（装配设计）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-13-startup-chain-followups.md)
- 相关：[ADR-0335](ADR-0335.md)（自愈模块与次序）、[ADR-0332](ADR-0332.md)（profile 事务）

## 背景

ADR-0335 的两条具名遗留：

1. **无单实例锁**：两个同根实例互相可见对方的自愈与事务面——实例 B 可能清掉实例 A 在途的 staging/displaced。产品形态是桌面单实例应用（双击两次启动就复现）。
2. **admission 仍拒绝两类无害条目**：Finder 的 `.DS_Store`（任意层）与 pre-ADR-0335 世代在根级留下的 Chromium 文件（`Local State` / `DevToolsActivePort` / `Singleton*` / `Crashpad`）——后者只在旧启动序（configure 前允许 Chromium 写根）下产生，升级到新版本的用户根可能带着它们，指针缺失即拒装。

## 决策

1. **D1 单实例锁（packaged only）**：`bootstrap` 在 `configureElectronPaths` 之后、自愈之前调 `app.requestSingleInstanceLock()`（锁按**已配置**的 userData 分根：dev 根、探针根、Sage 根互不干扰）。第二实例：stdout 一行 `second instance refused` 后 `app.exit(0)` 立即返回，不触碰根。`second-instance` 事件聚焦既有主窗（无窗则静默）。非 packaged（dev / 探针 spec）不加锁——探针机件同根顺序双进程语义保持不变。
2. **D2 admission 具名容忍**：`.DS_Store` 任意层跳过（Finder 闲逛非产品动作）；根级 `Local State` / `DevToolsActivePort` / `SingletonLock` / `SingletonSocket` / `SingletonCookie` / `Crashpad` 按名跳过（pre-0335 世代遗留；现世代启动序不可能再产生）。两类均只按**名单**放行：同名条目出现在根以外仍严格拒绝，名单外的未知条目、符号链接、owned 目录内的文件全部保持 fail closed。
3. **D3 不做**：不为容忍名单写「来源探测」（旧/新世代字节无法可靠区分）；不做锁的跨根协调（不同根＝不同产品实例，应允许并行）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 全世代加锁（含 dev/探针） | 否决：探针 spec 的并发语义会被改；dev 多实例是开发常态。 |
| 锁按默认 userData | 否决：所有 SAGE_ROOT 会互相顶掉——这正是当前 bug 的形状。 |
| 容忍名单含通配（如 `Singleton*`） | 否决：通配是黑洞；精确六个名字＋根级限定，误放面最小。 |
| 把遗留垃圾自动清除而非容忍 | 否决：删除用户真实根里的文件超出「启动健壮」边界；容忍已足够让安装前进。 |

## 后果

- 同根第二实例零副作用退出；`second-instance` 聚焦既有窗口。
- 升级用户的垃圾遗留根可正常安装；名单外依旧 fail closed（负例 spec 钉住）。
- spec：admission 容忍正/负例（含「harness 下的 `Local State` 仍拒」）；单实例行为由 live 实测覆盖（packaged-only 分支无法在 jsdom 层复现）。
- 实测中发现的方法学教训：验证第二实例必须带 `SAGE_ROOT`——漏掉时它会以真实根启动并**升级真实根的 profile**（事务正确、可自愈：回到对应 app 版本时模板差异会再次换位；无损坏，但属测试污染的诚实披露）。

# ADR-0225 · 事项修改稿：绑定源版本的快照、按内容比较的 Diff、独立具名的回写

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证并实施；按所依据版本比较、独立回写、Git 后置是 D-009/010/053 与 FW-028 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-edit-drafts-version-bound.md)
- 相关：[ADR-0207](ADR-0207.md)（本地引用与版本重核）、[ADR-0209](ADR-0209.md)（设备本地密封）、[ADR-0224](ADR-0224.md)（执行前确认）

## 背景

工单 027（FW-028，US-140~145）：在已采纳工作区的文件上生成事项修改稿，直接查看它与**所依据
版本**的 Diff；回写是独立具名动作、首版不自动回写；修改稿存在≠共享文件已更新；下载/导出不产生
回写；Git 提交/推送/分支与 Worktree 写操作无入口；文件修改类工具活动只显示受控修改信息与目标
版本、不透传原始 payload。验收三条：修改稿生成后源文件保持未变（有断言）；回写确认卡显示目标
版本与影响、未确认不写入；界面无 Git 提交/推送/分支入口。

基座取证（`dsh-api-workspace-files` 的声明类）：`workspaceFiles` 只有 read/readBytes/readAll/
readRelated/stat/list/changes——**没有任何写动词**；`WorkspaceFileStat.version` 是"stat 时刻的
不透明新鲜度令牌，永不解析"。即：版本可比较、内容可读，**回写语义在基座不存在**。

## 决策

1. **D1 修改稿＝源版本上的快照＋工作副本（US-140）**：新纯模块 `main/edit-drafts.ts`（复用 013
   的桥回答解析与路径守卫）。从**已有引用**生成：stat 一次（引用版本必须等于当前版本，否则
   `source-changed` 拒绝），read 一页（上限 400 行，未读完即 `draft-source-too-large` 整拒——
   不生成半份修改稿）。记录含：matterRef、工作区相对路径、绝对路径（仅 main 内）、basedVersion、
   basedText（快照，永不出 main）、proposedText（工作副本）。**生成只读取**；视图是受控形状
   （13 个键钉住）：无 workspaceRoot/absolutePath/basedText/payload 字段；源文件后来的新内容
   绝不经视图泄漏。
2. **D2 Diff 按内容、不依赖 Git（US-141）**：Sage 侧行级 LCS 比较 basedText 与 proposedText
   （两侧同用线上的"末尾 \n 终止最后一行"规则；超 400×400 单元退化为整文件替换，仍有界）；
   每次比较都重 stat 并标注 `basedVersion`/`currentVersion`/`sourceChanged`——版本令牌只比较、
   不解析。源变化是一等状态：不回退 basedVersion、不自动合并（D-010 的完整合并机制后置，
   首版对源变化的态度是"重新生成"）。
3. **D3 回写＝独立具名动作、一次性确认、检查先于消耗（US-143/125/126）**：`prepare-writeback`
   铸单张回写卡（对象＝matter·path·draft、动作 `writeback-source-file`、目标版本、当前版本、
   影响＝增删行数、费用预估如实 unavailable、`effect:'not-yet-happened'`），凭据骑共享的
   `ActionConfirmationStore`（025 同一家；意图指纹＝path+basedVersion+proposed 摘要）。执行序：
   先 fresh-stat（源变→拒绝 `writeback-source-changed` 并 **retire** 旧卡，恢复旧字节也不复活）；
   再看执行端口存在性（缺席→`not-ready writeback-unavailable`，**确认不消耗**）；再 consume
   （required/stale/consumed）；最后过执行端口。`executeWriteback` 是**唯一写入路径**，生产
   不接线（基座无写动词）；模块不 import 任何可写文件系统能力（有扫描断言）。只有执行回执才
   产生 `written`；执行器抛错＝`unknown`（可能已发生），绝不 `failed`/`written`。
4. **D4 下载/导出无回写效果（US-142）**：首版不增任何下载/导出控件；生成/保存/Diff 全流程对
   源文件字节零写入（S5 真字节断言：每步前后文件 base64 相同）。
5. **D5 无版本控制入口（US-144）**：路由表没有 git/commit/worktree/export 动词（扫描断言）；
   页面上该卡互动控件被钉死为五枚（保存修改稿/查看 Diff/准备回写/确认回写/取消确认），且不含
   提交/推送/分支/下载/导出词。回写不做任何版本库操作（D-053）。
6. **D6 受控修改信息（US-145）**：修改稿视图只含路径/版本/状态/工作副本；投影 JSON 无
   payload/arguments/toolInput 字段（有断言）。工具活动在全链路的呈现边界（transcript 仍只
   文本条目）不变。
7. **D7 首版不做**：真实 Git 接线与 Worktree 写操作（D-053 后置）；Office 原格式预览；D-010 的
   自动合并/冲突定位（源变即拒绝并请重新生成）；回写端口的生产接线（基座无写动词，等 seam）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 修改稿存绝对内容直接改写源 | 否决：D-009 先稿后写；写入语义基座不存在，Sage main 不得绕过 base 的 scope/权限写用户文件。 |
| Diff 依赖 Git | 否决：D-053 点名"Diff 不以 Git 为必需前提"。 |
| 源变时自动合并 | 否决：D-010 合并机制未契约化；首版诚实拒绝（重新生成），不假装合并成功。 |
| 回写走 `/.sage/actions` 流水线 | 否决：写回不在 Registry 动作面；独立路由族＋独立具名动作（FW-028 原话）。 |
| 确认先消耗再看端口 | 否决：生产无端口时会把卡白白烧掉；"检查先于消耗"保留凭据到能力就绪。 |
| 视图携带源快照供 renderer diff | 否决：Sage 计算 diff；快照留在 main，视图不泄漏源字节。 |

## 后果

- 验收三条各有机器断言：S5 真字节——生成/保存/Diff 后源文件字节不变；回写卡含目标版本与影响、
  未确认不写入（执行器零调用）；控件与路由均无 Git/下载/导出入口。
- S5 真实性：测试用本地临时目录＋真文件字节（stat 读真 mtime/size 做版本令牌、read 读真内容、
  确认后的假执行器写真字节），含"还原旧字节与旧 mtime 也不复活旧卡"（US-126 持续性）。
- 已知未闭：回写端口生产未接线（not-ready 诚实；等基座写 seam）；D-010 合并与冲突定位后置；
  真机未跑。

# ADR-0268 · 设备聚合读的 collection 授权（T03/A）

- 状态：accepted（2026-10-05）
- 日期：2026-10-05
- 决策者：用户（对 A/B/C 三选项明确选 A：active-matter 授权覆盖 `/state` 聚合读）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-05-read-policy-wiring-t03.md)（T03 注记追加）
- 相关：[ADR-0267](ADR-0267.md)、[投影读准入批-4](../notes/implemented/architecture/2026-10-03-projection-read-admission-and-owner-batch-4.md)

## 背景

T03 接线后，read-only 面在真实会话＋实例策略授予＋明确选择绑定时可走到真实读取，但 `/.sage/state` 的路由候选是 `{kind:'collection', collection:'state'}`，而 runner 的 candidate-match 对所有 collection 一律 `unavailable`（批-4 时代的保守默认，登记在门禁 note 与 `projection-read-production.spec.ts` 护栏「不得把一个事项授权扩到 collection 读」）。默认桌面的工作区列表、事项关联与会话投影都组装在该聚合响应里，因此不解决这一步，登录后主界面依然读不到任何真数据。选项 A（授权覆盖聚合读）／B（窄化响应到事项槽位）／C（维持封锁、另开有界读路由）呈报后，用户选择 A。

## 决策

1. `createProjectionReadRunner` 的 candidate-match 对 `collection:'state'` 放行（candidateRef `collection:state`）；`file-reference` 是当前唯一允许的 opaque resolver，只有 main-owned reference 同时匹配 fresh scope 的 `matterRef` 与 `trustedWorkspaceRoot` 时才放行。其余 collection（search 跨多事项与全局 session）以及 artifact、current-artifact、edit-draft 等 opaque 资源维持 `unavailable`，直到各自拥有 main-owned object resolver。
2. 放行的前提不变且已由既有准入链保证：caller 绑定、initial-context、独立的 main-owned 读策略（身份会话＋实例本地组织策略，local-read）、fresh scope（exact matter/revision/workspace/actorScope/context 与 frame 世代）、读前后新鲜度；其中任一不成立仍是 unavailable/denied/stale。unknown、跨事项和跨 workspace 的 file-reference 共享同一 unavailable 结果，不暴露对象存在性。
3. 门禁把该放行登记为逐行事实（`return candidate.collection === 'state'`＋file-reference 的双绑定＋旧的全封禁语句不得回），并新增具名突变；`projection-read-production.spec.ts` 的护栏覆盖 state 放行、search 封锁、其他 opaque 封锁以及 file-reference 的 matching/unknown/cross-scope 分支。
4. `/.sage/edit-drafts/create` 继续保留 `protected-effect` route 分类，因为它在 main 内创建本地 edit-draft；但其 source file read 必须先经独立 `edit-drafts.create` projection-read operation，以 opaque file-reference candidate 进入 fresh scope，provider 的 matterRef 只能来自 `scope.matterRef`。这项 source-read admission 不等于完整 protected command authority，runCommand 仍未接通。
5. 诚实性约束：聚合响应只含 main-owned 投影（组合层组装，无 renderer/Host 直通）；设备级槽位（工作区列表路径、模型配置状态、设置叶等）随该授权对已签入会话可见——这是 A 的已知暴露面，用户已接受；B 的窄化如将来需要，另开票。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| B 窄化 `/state` 响应到事项槽位 | 不采用（本轮）；语义最干净但需要组合层按调用场景裁剪多个槽位，改动面大，且工作区列表本身就是设备级事实。 |
| C 维持封锁、另开有界读路由 | 不采用；需要新路由与门禁分母变更，收益与 A 相同但成本更高。 |
| 保持批-4 保守默认不动 | 不采用；用户已明确主界面要在登录后读到真数据，封锁使 T03 的验收无法达成。 |

## 后果

`/.sage/state` 在授权链完整时返回真实聚合投影；无会话、无授予、未选择或世代漂移时表现与接线前一致（unavailable/denied/stale）。search 与 opaque 读维持封锁。T04/T05/T06 与登录链路不受影响，仍按各自票据验收；本决策不宣称成功聊天链。

# ADR-0085 · 归位 ≠ 接线：技能入库必须分两个平面各有一条判据，且判据的前提要能分辨「环境不在」与「数据不对」

- 状态：accepted
- 日期：2026-09-15
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/capability/2026-09-15-generic-line-wiring-and-skill-lines-gate.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（门禁全量硬门槛 + 只减不增的豁免）、
  ADR-0015（非机械改动必须留痕）、ADR-0052（第三方技能入库 SOP §12）、ADR-0056（本机装配不进出货面）、
  总账 P-02（仪器假绿）、P-03（「知道」没有变成「拦住」）、P-04（写了但从没跑到）、
  P-11（判据的射程没有定义）、P-17（三态读数在聚合处被压回两态）

## 背景

本批 592 个第三方来件里，T0 精选 15 条（通用办公能力）已按 SOP §12 装进 `~/.dsh/skills/`：
四件套齐全、结构体检通过、运行时前提齐备（P0 层）、设置页可见。**所有既有判据全绿。**

而按设计意图，这 15 条应当**常挂全部 50 个岗位 preset**——「通用」在装配上的含义就是
「每个岗位各挂一份同样的名单」。实测：`scripts/role-presets/generate.mjs` 生成的
`skill-subset` 里**一条都没有**。对会话而言这 15 条等于不存在，而没有任何一处报错。

同一轮还量到两处结构性洞：

1. **`pnpm run gate` 里没有任何一项跑过 `verify_static.mjs`。** SOP §4 的验收清单与
   `scripts/pipeline.sh` 一直写着「要跑它」，但它只有人工执行这一条路——
   「技能入库要跑 verify_static」只活在文档与人的自觉里（P-03）。同一条也盖住了
   `verify-generic.mjs`（本轮新建）与 `verify-fullstack.mjs`。
2. **`verify-fullstack.mjs` 恒红。** 它断言 `~/.dsh/.agent-presets/ai-product-developer/skills/`
   下三个副本存在，报「预设副本丢失」；真相是该 preset 组在 v3 重组时已移出本机
   （现存只有 `agt-001..050` + `bobo-cto` + `lute-cordis`）。这是 **2026-09-12 一次改动里
   显式判定为「既有环境漂移、留待单独处置」的债**，此后无人处置，于是判据一直红着。

## 决策

**一、技能落点分为两个平面，各自必须有独立判据。**

- **归位**（`manifest/*.json` + `role-assignments.json` + taxonomy 名单）：回答「这条技能属于
  哪些岗位、喂给哪个页面」。
- **接线**（`agent.cordis.yml` 的 `skill-subset`）：回答「哪个会话在什么条件下会真的用到它」。

两者不是同一个动作，因此不能共用一条判据，也不能用其中一条的读数去证明另一条。
判据必须读**消费侧的产物**（会话可见的白名单），不能读登记表或生成器的意图。

**二、新增第三条线「通用技能」（`genericNames`），其 T0 档进全部 50 个岗位 preset。**

- 归位写入 `manifest/generic-skills.json`（**唯一一份发布副本**，派生自 `staging/intake-localize.json`
  与 `manifest/intake-provenance.json`，派生器 `scripts/build-generic-manifest.mjs`）。
  派生是机械的，**唯一的人工判断**是「哪几条算 T0」——那个判断的家是派生器里的 `T0_NAMES`
  常量，其余四处（设置页、图标分配、`verify_static`、`generate.mjs`）全部读派生产物，不手改 tier。
  全栈线保留其既有的两份文件形态（`scripts/fullstack-mapping.json` + `manifest/fullstack-skills.json`），
  本次不动——路径依赖已成立，改它属于另一件事。
- 接线写入 `scripts/role-presets/generate.mjs`：T0 并入点放在**契约闸门之后**。
  闸门判的是 `p2s-` 卡的契约引用，第三方通用技能没有契约可挂；放闸门之前它们会被算成
  `pending`，一旦 `P2S_CONTRACT_GATE=enforce` 就会被**静默删掉**——一条与计量模式无关的
  接线不该跟着另一个开关的档位改变生死。
- 接线判据读**回落的字节**：写盘后重新读回 `agent.cordis.yml` 逐条核对，缺一条即 `exit 1`。

**三、新增门禁项 `gate:skill-lines`，把三条线的验证器收进 `pnpm run gate` 的射程。**

射程里有四个验证器：三个量**数据**（`verify_static` / `verify-generic` / `verify-fullstack`），
第四个量**负载形状**（包自身的 `test/*.spec.mjs`，含三个路由拼出来的页面负载）。
第四个非加不可的理由：`buildGroupsLegacy` 靠 `skill.category === cat.key` 配对，清单里的分组
key 与 catalog 里的 category 一旦写岔，返回的就是 N 个**空组**——页面显示成一片空白，
而不是报错；这段只有真的 `apply` 一遍插件才跑得到，没有任何静态判据看得见。

射程前提统一为「本机有没有 `~/.dsh/skills` 与 `~/.dsh/.agent-presets`」：
两者都不在 → **跳过并写明跳过了什么**（`passed: true` + note），与 `patch-anchors` /
`theme-tokens` 同一语义，不假绿也不假红；目录在 → 任一验证器非零退出即红，原文回传输出。

本项自带反向自测（`gate:skill-lines-selftest`，7 条）。该项目里每一条新判据都要能证明
自己会说不（P-02/P-03），而本项尤其需要：它自己就是为「判据从来没有跑到」而建的，
一个只会判绿的聚合器会让「三条线都验过了」变成一句谁也没核过的话。自测里有一条专钉
「红桩 key 打错字」这种**静默变空转**的反向用例——第一版把 `verify_static.mjs` 写成
`verify-static.mjs`，本该红的桩一次也没生效，用例绿着通过。

**四、判据必须能分辨「环境前提不在」与「数据不对」。**

`verify-fullstack.mjs` 的预设副本判据改为：目录不在 → 跳过并说明；目录在 → 逐条核对，
且期望条数**改从 `presets/preset-skills.json` 读**，不再硬编码 3
（硬编码让「少了一条」与「改过清单」无法区分，而这两种情况要修的地方完全不同）。

## 备选方案

- **把 T0 名单写成 `generate.mjs` 里的常量数组**（原 P3 方案的字面写法）：同一份 15 条还要被
  设置页（显示 tier）、图标分配、`verify_static`（三线名单防漂移）读。常量放进去就等于有
  第二个家，而第二个家只能靠人对齐——那是纪律不是机制（ADR-0009）。否决。
- **不加「通用」这一条线，只把 15 条塞进各岗位的 `skill-map.json` 供给**：供给表按岗位语义
  映射材料业务技能名，通用件不对应任何材料岗位；塞进去会让「这条技能为什么在这个岗位」
  变成一个无法回答的问题。否决。
- **给通用技能硬派一个出海场景（如 `h-enable`）以复用 `/list`**：通用线的 8 个用途分组回答
  「这条技能干什么用」，出海线的 8 大场景回答「属于出海业务的哪一段」，是两个问题。
  用一个错误的坐标去满足一个不该存在的形状要求，会让「通用」这个定语失去意义。否决。
- **把 `verify_static` 的失败登记进 `exemptions.json`**：豁免只减不增、到期即拒绝（ADR-0014），
  且本轮的两处红**都不是存量不达标**——一处是本次改动尚未重建目录（预期红），一处是判据
  自身在说假话。用豁免盖住后者，等于把「判据坏了」永久合法化。否决。
- **直接删除 `verify-fullstack.mjs` 的预设副本判据**：该判据在 preset 装着的机器上仍然有效，
  删掉是把「环境耦合」误诊成「判据无用」。改为带前提的跳过。否决。
- **为 T0 单独生成一批 `agt-*` 之外的通用 preset**：DSH 的技能可见性由
  `dsh-skill-subset` 的 `skills:` 白名单 + `hideOthers` 决定，没有「全局技能」这一层。
  用户仍要逐个岗位切换才能用上通用技能，等于没接。否决。

## 后果

**正面**

- 「挂上了没有」这一维度首次有判据：`gate:skill-lines` + `verify-generic.mjs` +
  `generate.mjs` 的落盘回读，三层都读消费侧产物。
- 三条线的验证器首次进入 `pnpm run gate`（55 项）。
- `taxonomy-v3.json` 的 `overseasNames` / `fullstackNames` 从**无人校验的死数据**变成活的：
  一条判据同时锁三个名单，成本近乎为零。这两个名单此前写在 SOP §12 里却没有任何消费者。
- 上线当天 `gate:skill-lines` 抓到两件事，第二件（`verify-fullstack` 恒红）是 2026-09-12
  显式挂账、此后无人处置的既有债，本轮一并关闭。
- 设置页新增第 28 项「通用技能」，8 个用途分组 + 15 行，与出海（26）/ 全栈（27）并列。

**代价与约束**

- 每个岗位会话的技能目录多约 **1,900 tok**。这是 T0「常挂全部岗位」的必然成本，
  也是把 T0 压在 15 条（而非 40 条）的理由。
- `lib/catalog.js` 由 `build_preset_catalog.py` 生成，新增线必须重跑该脚本；
  未重建时 `verify_static` 会以「缺 `SKILLS_GN`」判红（不是静默空页）。
- 通用线的图标走 `gn-cat-<key>` / `sk-gn-<name>` 两个 id 约定，缺 id 时
  `assign_lute_icons.py` 会 `SystemExit` 点名，不会静默写空图。
- T1（按岗位族挂）本批为空。`generate.mjs` 会把非 T0 成员打印出来，
  明确说明它们**未被接线**——避免「清单里有 = 已经挂了」的误读。

**后续动作**

- 放量到 T1（约 30 条）时：在 `build-generic-manifest.mjs` 的 `T0_NAMES` 之外新增
  `TIER_BY_NAME` 条目，并为 T1 决定岗位族映射（该决定尚未做出）。
- 592 条来件里剩余约 120 条挂岗件、17 条方法论与 68 条择优件仍走 §12.5 路径 A。

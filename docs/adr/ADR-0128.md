# ADR-0128 · 能力目录只读聚合，调度面挂 shell.overlay

- 状态：accepted（2026-09-19）
- 决策者：用户（lute）+ 能力中枢整合轮
- 决策记录：[Note](../notes/implemented/surface/2026-09-19-capability-hub-palette.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0019（官方 UI 改写锚禁止钉哈希）、ADR-0041（安装态技能体是运行时之家）、ADR-0125（侧栏四带与行轴）、ADR-0014（门禁硬门槛）

## 背景

本机已经发布五个能力切片——技能三线（223+138+16）、MCP 工具业务清单（101）、岗位
（50）、产品（装机相关）、业务系统（31）——但**能力图谱被侧栏入口行切碎**：技能住扩展
中心、工具住万物互联、岗位住岗位矩阵、产品与系统住新应用抽屉，各有各的搜索框、卡片
语法与空态。用户的问题从来不是「这个功能住在哪个入口」，而是「我想干 X，从哪进」，而
这个问题此前没有任何一个界面能回答。

两项前置取证已结案：基座 `main` keyed slot 可用（[research/14](../research/14-main-keyed-slot-spike.md)），
五切片数据源与统一 schema 定稿（[research/15](../research/15-capability-catalog-sources.md)）。
关键事实是**五切片的 UI 已经全部走 loopback HTTP 只读通道**，且跨包 HTTP 读在本仓库
已有先例并被契约化（newapp 读 role-matrix 的 roster，并把该依赖声明为 `COMPOSED_SOURCES`
发布在 health 上）。

## 决策

新增 `packages/surfaces/dsh-capability-hub-local`，五条：

**D1 聚合层永远只读。** 能力目录只对既有 loopback 路由发 GET，不落第二份存储、不缓存
到磁盘、不写任何切片的数据。路由清单的单一事实源是 `src/client/catalog.ts` 的
`CAPABILITY_ROUTES`；每条路由的响应形状由 `tests/mappers.spec.ts` 用逐字段取自各 handler
构造代码的样本冻结——上游改形状时测试先红，这是漂移警报而不是静默漂移。某条路由 404
= 对应包未安装，记为空切片（`missing`），**不是错误**。

**D2 调度面挂 `shell.overlay`，模态一律 `<dialog showModal()>`。** `shell.overlay` 是帧级
additive 官方座位（点击穿透、root 作用域），能力调度跨会话且不属于任何单条会话，因此
不挂 `conversation.input.overlay`（那是 composer 内浮层、会话作用域，`/` 命令源的家）。
面板走 top layer，全文件零 z-index。

**D3 action 是判别联合，执行只走既有通道。** `execute-skill` → 回到会话（`selectPanel(null)`
+ `dsh:view-change`(chat)）＋ 草稿预填／剪贴板兜底；`prefill-draft` → `setDraft`；
`open-panel` → 目标已注册为 `main` key 时走官方 `selectPanel(key)`，否则回退
`dsh:view-change` 广播；`open-system` → POST slug。不发明新机制，也不把
动作压成字符串（五个切片的执行机制互不相同，字符串承载不了）。

> 2026-09-19 修订：本条原文写的 `execute-skill` → `dsh:skill-execute` 事件已删除——实测
> 全仓 + 基座**零听者**，广播不承载任何事实；`open-panel` 的 `selectPanel` 分支与交付通道
> 的单一实现见 [ADR-0130](ADR-0130.md) D6。

**D4 设计 token 走自建 `--lute-*` 命名空间。** 平台没有 spacing / radius 的 token 家族
（`--dsw-alias-radius-*` 之类从未被官方定义，引用即幻觉 token，门禁 baseline 已登记）。
`--lute-space-{1..5}` / `--lute-radius-{row,card,chip}` / `--lute-brand-line` 由
`shared/client/lute-tokens.ts` 在 apply 期幂等注入；数值不是新发明，是既有读数的收敛
（行圆角 8px 出自 ADR-0125 行轴，间距取整到 4px 栅格）。**消费方不得在 dispose 时移除
该标签**——它可能是兄弟插件注入的，且值是静态常量，残留无害。

**D5 `prefillDraft` 提为共享源。** 实现在 `shared/client/prefill-draft.ts`，能力中枢与
岗位矩阵各自持生成副本；岗位矩阵的 `prefill.ts` 改为 re-export 该副本并保留自己拥有的
`prefillPrompt`（那句话的语义属于 hero 供给卡，不属于共享层）。此前它是岗位矩阵的私有
模块，第二个消费方出现即意味着两个家。

## 备选方案

| 方案 | 为什么未采用 |
|---|---|
| host 侧新增聚合路由 `/api/dsh-capability-hub` | 需要跨包 host 调用，而 feature 包之间禁止 runtime import 对方的值；client 侧 fetch 已是家族既有通道，且各路由自带 loopback 围栏，聚合层不必重复实现信任边界 |
| 每个切片各自补一个搜索框 | 正是现状的问题：五套搜索、五套卡片语法、五套空态，用户仍要先进对入口 |
| 面板挂 `conversation.input.overlay` | 会话作用域 + composer 内浮层，与「跨会话的帧级调度面」语义不符；且会与 `/` 命令源抢同一个座位 |
| 把 `--lute-*` 收进 `theme-tokens` 门禁射程 | 该门禁的判据是「平台命名空间的名字必须由官方主题包定义」；自建命名空间不在此列，收进来只会造假阳性（门禁注释已论证假阳性会训练人忽略输出） |
| 直接改五切片的存储，做一张统一大表 | 违反 ADR-0009；且会让「安装态技能体是运行时之家」（ADR-0041）等既有不变量失效 |

## 后果

- **正面**：能力第一次有了一个统一调度面（Cmd/Ctrl+K）；五切片零改动、零新增存储；
  mapper 测试把无类型的路由约定变成了会红的契约。
- **负面 / 需跟进**：
  1. 面板目前**只有快捷键入口**——不加侧栏行是侧栏收敛决策（计划 D2）的直接结果，
     可见入口按计划落在 S4 的 hero 橱窗（hero 是命令面板的静态投影）。
  2. 岗位的动作是「打开岗位矩阵」而非预填：一句话预填需要从 manifest 派生，要求与
     hero 供给卡的既有拼装对齐，不造第二套（research/15 开放风险 #3）。
  3. `open-panel` 仍走 `dsh:view-change`；S3 把 workbench 面板迁到 `main` keyed slot 后
     换成 `selectPanel`——只有 dispatcher 一处需要改。
  4. 中英混排搜索未实测（research/15 开放风险 #1）；评分是子串 > tag > 摘要 > 子序列的
     简单方案，实测不满意再换算法，`searchItems` 接口不变。
- **判据射程**：本 ADR 只覆盖「聚合层只读 + 调度面挂 shell.overlay + token 命名空间」。
  **不**为「所有能力都该进命令面板」背书——低频配置类入口（连接授权、外观、插件管理）
  仍留在设置页与系统带；命令面板收的是「用户想干 X」这一类可执行能力。

# ADR-0332 · 既有根 profile 事务升级：模板清单不同即换位，指针写入为提交点

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（授权修复实测问题；本 ADR 为后续宿主修复的交付通道）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-profile-upgrade-transaction.md)
- 相关：[ADR-0328](ADR-0328.md)、[ADR-0329](ADR-0329.md)、[ADR-0330](ADR-0330.md)（本轮被迫手工同步根 profile 的历次）

## 背景

`installBundledProfileTemplate` 对已激活根一律 `existing` 短路——模板再新也不进；换 id 又因「destination 已存在」拒装；build 号被批次契约钉死。结果：**任何宿主侧修复（sage-host/**）都无法经正常安装抵达既有根**——今夜三次靠手工 rsync + 改指针（与事务升级等价的人工操作）绕过。交付通道本身必须成为产品件。

约束（第一性原理）：升级对象是**可执行资产**，必须 (1) 只被**已验签模板**替换；(2) 事务可回滚；(3) 幂等；(4) 无指针+残留照旧拒绝（不放松 pristine 语义）。

## 决策

1. **D1 升级判据**：每次启动读模板 manifest（验形状+摘要）；活动清单（generation+manifestSha256）与之一致 → `existing`（幂等）；不同 → **升级**。
2. **D2 换位事务**：staging 复用与 fresh 完全相同的验证块（收据摘要、指针回读、attestation verify——提取为 `stageTemplateGeneration` 共享）；同 id → 旧树 rename 到 staging `displaced-*`、新树 rename 就位；换 id → 新树直接就位（旧 generation 保留作回滚源）。
3. **D3 提交点=指针原子写**（`writeActivePointer` 的 temp+rename）：之前任何失败回滚（移回旧树）；成功后删除 displaced 备份。kill -9 落在两次 rename 之间 = 已知窗口：指针仍旧、树缺失 → 启动 fail closed，displaced 副本即人工恢复源（Note 记载）。
4. **D4 新态 `upgraded`**：结果并入日志（`bundled profile upgraded`）；DMG-06 空根验收不受影响（空根恒 installed）。
5. **D5 不放松**：无指针 + destination 存在仍拒绝（防未认证残留）；attestation/收据校验一字不减。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 提升 build 号走新 generation | 批内不可（build 钉死）；即便可行，replacement-on-same-id 仍需要（无指针残留场景除外）。 |
| 自动拉取远端 profile | 否决：引入未被模板验签的输入源。 |
| 双 generation 并存 + 指针切换 | 部分采用（换 id 路径）；同 id 场景必须换位。 |

## 后果

- 宿主修复随正常安装抵达既有根；手工同步/整根重置退场。
- 每次启动多一次模板清单读取（本机磁盘，可忽略）。
- 升级路径有 kill 窗口（文档化 + 备份副本可恢复）；下一步可加启动自愈（扫描 displaced-* 与指针不一致）作为独立票。

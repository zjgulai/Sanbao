# ADR-0296 · 收口证据域定界：turn-end 边沿按 attempt 基线定界，兼 dispatch-unknown 四项裁决

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：四项裁决均采纳推荐）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-closure-evidence-scoping.md)
- 相关：[ADR-0293](ADR-0293.md)（收口与 reconcile 兜底）、[ADR-0295](ADR-0295.md)（评审分流）、[ADR-0289](ADR-0289.md)（dispatch 契约）

## 背景

C2 侦察（outcome-unknown 对账，2026-10-11）确认一个已出货缺陷：observer 与 send-path reconcile 两条收口路径都用「会话内最后一个 turn-end 边沿」收口当前活跃 attempt，但从不校验**该边沿晚于本 attempt 开始**。dispatch 未抵达（unknown）且用户重发时，fold 里只剩 attempt 开始前的旧边沿——收口会用旧回合的证据把这个 attempt 记成 succeeded/failed，记录错误事实。更尖锐的是 observer 的 `lastTurnEndSeen` 去重为纯内存：进程重启后首次读会把旧边沿当新边沿重放，同一洞在 observer 路径独立成立。根因：attempt 开始时未记录边沿基线（侦察报告「attempt-start 时未记录边沿/sequence 基线，是根因」）。

## 决策

1. **D1 边沿基线入 attempt-started（实现）**：persist 步在撰写事件前读取 session fold 的 `lastTurnEndEdge`（新读端口 `readObservedTurnEndEdge`；fold 不可读 → 步骤 `unavailable` fail closed——没有基线的 attempt 不可裁决，宁可不记）。基线以可选字段 `observedTurnEndEdge`（`string | null`）写入 `attempt-started` 载荷；域输入可选仅为旧记录逐字节重放保真（缺省 = 无基线，绝不自动收口），persist 恒传。
2. **D2 收口守卫单一出口（实现）**：runner（`session-turn-close.ts`）为两条路径的唯一守卫——仅当 `attempt.observedTurnEndEdge !== undefined && attempt.observedTurnEndEdge !== edge` 才允许收口；相等（陈旧重放）或无基线（旧记录）一律拒绝。observer 传 `status.lastTurnEndEdge`，reconcile 传 `fold.lastTurnEndEdge`。未知 kind/blocked、review 分流、失败映射语义不变。
3. **D3 收口证据政策**：SESSION durable log 中「晚于基线的新 turn-end 边沿」视为足够证据，observer/reconcile 可对（含 dispatch-unknown 的）attempt 轻收口。无请求痕迹（边沿等于基线、永不前进）的场合保持活跃，另设具名核对入口（下一批）。不为 unknown 另建全链 ActionIntent 仪式。
4. **D4 unknown 持久记录（已实施）**：域新增第 13 型事件 `attempt-dispatch-unknown`（载荷 `attemptId` + `occurredAt`；投影标记 `dispatchUnknown`，零状态变动）。写入点：dispatch 捕获通道抛错后、返回 unknown 之前，经独立 main-owned recorder（best-effort、幂等 appendId `attempt-unknown:<attemptId>`）。
5. **D5 requestId 归属（已实施）**：通道 requestId 由 attempt 身份派生（`sessionRequestIdForAttempt` = `req-<attemptId stem>`；channel 已支持 caller 提供 requestId）——零新持久字段，核对期从 matter 记录重新派生比对宿主 `source.rpcId`。不做 channel 回传铸造值的契约改动。
6. **D6 分票**：blocked 映射随 clarification 整合票；dispatch-unknown 的标记/核对/UI correlation 随对账票。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 仅在 reconcile 加守卫 | 否决：observer 重启重放路径同洞，守卫必须在两条路径的共同出口（runner）。 |
| fold 不可读时记 `null` 基线 | 否决：与「观测到无此前边沿」不可区分，会产生过度收口；fail closed。 |
| 基线放 dispatch 步（attempt-dispatched 事件） | 否决（本刀）：persist→dispatch 间崩溃即无基线；基线是 attempt 开始时刻的事实。 |
| requestId 由 channel 返回铸造值 | 否决（用户裁决）：需改失败路径契约；身份在 attempt 铸造时刻已存在，派生即可。 |
| unknown 一律走全链对账仪式 | 否决（用户裁决）：边沿证据足够；复刻 ADR-0293 已否决的逐条评审队列成本。 |

## 后果

- 旧边沿收口新 attempt 的洞在两条路径同时关闭；重启重放与 dispatch-unknown 重发场景不再产生错误收口记录。
- 附代价：无基线旧记录（仅开发库）与「日志无痕迹」的活跃 attempt 不再自动收口——诚实保持活跃，等待具名核对入口（已立对账票）。
- 门禁新增事实组 + 五条具名突变（守卫删除、等值比较退化、fail-closed 删除、index 接线漂移、reconcile 边沿卸载）。

# ADR-0133 · 图形资产落位：资产入仓 + pin 校验、logo 五形态映射、macOS squircle 重画、头像双轨承载

- 状态：accepted（2026-09-19）
- 决策者：用户（lute）+ WorldPilot 全维度换皮轮
- 相关：ADR-0013（资产分级处置）、ADR-0022（头像走官方 `icon` 字段，图标库是唯一事实之家）、ADR-0008（基座只 pin 不改）、ADR-0019（官方 UI 改写锚禁止钉哈希）、ADR-0131（射程 16 处）、ADR-0132（色彩与排印）；总账 P-01（未验证的事实被钉进出货面）、P-07

## 背景

**出货图标的家不在版本管理里。** `packaging/scripts/build-app-icon.sh:22` 在构建时读
`$HOME/.dsh/skills/lute-brand-icons` 产出 `icon.icns`，而该目录实测
`git rev-parse` 返回 `fatal: not a git repository`——5.6M 内容，靠
`catalog.js.bak-pre-layer-icons-20260912120027` 这类**时间戳 .bak 文件**做版本控制。
ADR-0022 的标题却认证它是「唯一事实之家」。这是一条被 ADR 背书、却不可复现的出货事实（P-01）。
同样不受跟踪的还有 `.dsh-root-brand-preview/`（含唯一的可编辑矢量源 `tray-colored.svg` 与
「视觉基线」`visual-baseline/*.png`）——即所谓视觉基线不可从仓库重建。

**素材源仓的 app icon 不是 macOS-ready 的。** 实测：

| 资产 | 色彩类型 | hasAlpha | 后果 |
| --- | --- | --- | --- |
| `app-icons/worldpilot-app-dark-1024.png` | **RGB** | **no** | 完全不透明硬边方块 |
| `app-icons/worldpilot-app-light-1024.png` | **RGB** | **no** | 同上 |
| 现状 `packaging/assets/brand-icons/icon-1024.png` | RGBA | **yes** | 圆角 squircle + 透明角 |

macOS 不给应用图标做圆角遮罩，直接放进 `.icns` 会在 Dock/Finder 里成为硬边方块。
而 `brand-icons` 门禁只校验 PNG IHDR 像素尺寸与 `ICON_PAIRS` 声明一致——**形状错了它照样绿**。

**头像承载与素材形态不可兼得。** 官方 loader 在 `dsh-agent-presets/lib/index.js.patch:9` 用
**白名单构造** record（`...record.icon === void 0 ? {} : { icon: record.icon }`），
`preset.yml` 里多写的字段被直接丢弃；即 `icon` 是**单值**。而素材源仓每位员工有
**明暗双色道 × 7 档尺寸**，且其 README:29 明确「深色产品背景推荐中性炭灰，浅色推荐纯白或冷白；
头像已有对应的低饱和底色」——用错色道会显脏。
同时 `verify-lossless.mjs:912-945` 的 L10 断言要求 `icon` 必须是 **inline SVG data URI**、
与 `manifest.json` 同串、全员互异——而新素材是位图。

**体量与 ADR-0013 冲突。** 头像全量 183M（其中原生 PNG 约 85M/色道，7 档 webp 仅约 5.6M/色道），
生产源图 `sources/` 另有 180M。ADR-0013 当年判定一个 **32.9MB** 的
`v4-ten-contact-sheet.html` 就该「持续拖慢工具链」而归档出工作树。

**素材源仓的岗数被高估过。** 实测 102 条记录中：AGT-001…050 与本仓 `role-catalog.json v2.0`
逐条同源（职责 50/50、花名 50/50）；AGT-051 BoBo（管理员）、AGT-052 筑程（全栈工程师）为已配置新增；
**AGT-053…102 共 50 条是纯占位**（`job: 待分配岗位`、`plane: 扩展成员`、`deliver: 待岗位配置后确定`）。

## 决策

**D1 资产之家：最小集入仓 + 素材源仓 pin 校验。** 出货必需的最小集纳入本仓受管目录
（logo SVG 132K + app-icons 156K + 头像单档×双色道约 0.8M，合计 **<3M**，远低于 ADR-0013 的归档线）；
生产源图与大尺寸档不入仓。新增 `vendor/worldpilot.pin` 记录素材源仓 commit，构建时校验盘上资产哈希与 pin 一致。
**（注：按 ADR-0136 D1，该 pin 的语义是「视觉语言上游」而非「品牌目标」，pin 文件注释须写明这一点，
否则未来读者会误以为产品要长成 WorldPilot。）**
本仓不克隆素材源仓（它是只读上游，与 `vendor/dsh-desktop` 同性质），只 pin。

**D2 logo 五形态按素材源仓使用规范逐位落位。** 映射表见
`.scratch/sanbao-reskin/surface-map.md`；要点：启动屏 `stacked`、侧栏 `mark` 28×25 `contain` + 17px 字标、
hero `mark` 34、tray 各档 `mark` + `black`/`white` 做 template、`worldpilot-favicon.svg` 直落、
PWA 清单接 app-icons。依据是 `brand/logo/README.md:28-31` 的自陈规范，不是本仓的编排。

**D3 macOS 应用图标重画为 squircle，深色底 + 钛银 mark。** 用透明底的 `mark`/`square` 形态
生成圆角连续曲率图标，底取 `#0b1521`，留边沿用素材源比例。这是本仓**新增的一项资产产出**，
必须由可复现脚本生成（落在 `packaging/scripts/build-app-icon.sh`，顺带替换掉已废弃的
`LUTE_ICON_ENGINE` 分支），不得手工处理不留生成器。

**D4 头像双轨承载。** 官方预设卡的 `icon` 继续放**一份深色兜底 data URI**（保证离线、
服务未起时也能渲染）；本仓完全自控的渲染点（岗位矩阵、能力中枢、详情面板）改吃
**资产路径 + 主题与尺寸自适应**，解锁双色道 × 7 档。同一岗位的两处供给由 D1 的 pin+哈希保证不分叉。
**不扩官方 loader 补丁白名单透传 `iconLight`**——那是本仓最脆的一面（ADR-0019 的存在理由），
代价是官方卡在浅色主题下仍显示深色底头像，登记为已知残留。

**D5 纯皮不动内容：本轮只入 AGT-001…050。** AGT-051/052 与 50 个占位岗全部留到内容轮。
理由：换皮必须是可证明的「同内容、换皮」——夹带新增岗就无法给出「50 产物零扰动」这类读数
（本仓 MGT 轮已有此先例），且与 ADR-0008「pin 变更与行为变更分开提交」同构。

**D6 不引入知识图谱 hero，只引入 `earth-texture` 背景纹理。** 图谱不是图形资产，
它是 7 域本体论的可视化，与 ADR-0132 D6 同源被否。

## 备选方案

| 方案 | 为什么未采用 |
|---|---|
| 资产全量入仓（183M+） | 离线复现最自洽，但直接违反 ADR-0013，且拖慢 glob/搜索/打包扫描与门禁 |
| 全不入仓、构建时从 pin 物化 | 最纯粹的「一事实一家」，但素材源仓只有 `main` HEAD、无发布 tag，把构建变成网络依赖对 DMG 发布 SOP 是新增故障面，且与 `immutable-supply-chain` 的反浮动引用精神相悖 |
| 维持仓外技能目录模式 | 零迁移，但把「出货图标之家不在版本管理」这个缺陷原封不动带进新品牌，且 .bak 当版本控制的做法会复制到 WorldPilot 资产上 |
| app icon 直接用素材源仓原图 | 零加工最忠实，但 macOS 下是硬边不透明方块；`brand-icons` 门禁只校尺寸不校形状，会**假绿** |
| app icon 一次性手工处理不留生成器 | 省事，但下次上游换标就要手工重做，违反可复现构建与 ADR-0013 的资产归属纪律 |
| 头像全内联单档单色道 | 与现有管线完全同构、改动最小，但浅色主题头像显脏（素材源仓自陈），且 7 档尺寸全部浪费 |
| 扩官方补丁透传 iconDark/iconLight | 品牌保真度最完整，但要动本仓最脆的官方 UI 补丁面，`patch-anchors` 锚点随之重切 |
| 102 全入、占位标 unconfigured | 后续配岗零搬运，但盘上多 50 个无主资产 + 一份会腐烂的「哪些岗没配」清单，且 L10 的「全员互异」断言被无岗资产撑开 |

## 后果

- **正面**：出货图标与头像第一次有了版本管理与哈希可校验的家；logo 落位从编排变成照抄上游规范；
  双色道 × 7 档在自研面完整可用；换皮提交可自证「内容零扰动」。
- **负面 / 需跟进**：
  1. **官方卡在浅色主题下仍是深色底头像**——这是本 ADR 主动接受的残留，不是遗漏，必须在射程表登记。
  2. L10 断言的 MIME 面必须改判（inline SVG data URI → inline data URI + MIME 与字节头一致 + 全员互异 + 与 manifest 同串）；
     **不得**用 `<svg><image href="data:image/webp;base64,…"/></svg>` 包一层骗过旧断言——那是 P-02 仪器假绿。
  3. 新增 squircle 生成脚本意味着本仓多一项资产产出，其输入（mark SVG）与输出（icns/png）都要进 pin 校验面。
  4. `brand-icons` 门禁是双向的（多一个少一个都判红），换资产必须与 `brand-replay.sh:266-275` 的
     `ICON_PAIRS` 同一次提交改。
  5. **该门禁只校像素尺寸不校形状**，D3 的 squircle 需要新增形状/alpha 判据，否则「硬边方块」这类错误会静默出货。
  6. `~/.dsh/skills/lute-brand-icons` 在换皮后不再是头像事实之家，但 `layer-icons`（12 个平面/域图标）与
     overseas-skills 的四份图标集仍在引用它——退役它需要单独一轮，本轮只停止新增依赖。

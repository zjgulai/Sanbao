# ADR-0207 · 文件读面的 scope 来自真实会话；引用建立只 stat、取用先重核版本

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：agent（取证并实施；scope 归属与失效判据是取舍，见备选）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-file-reference-scope.md)
- 相关：[ADR-0205](ADR-0205.md)（服务面取自声明）、[ADR-0206](ADR-0206.md)（流式读收束）、[ADR-0203](ADR-0203.md)（受控方法桥）

## 背景

工单 013 要"从已采纳工作区内选择文件形成候选引用，实际使用时经 `workspaceFiles` 实时读取并重核版本"。
逐字读基座声明（`@deepseek-ai/dsh-api-workspace-files/lib/types/index.d.ts`）：

- 方法签名是**位置参数**：`list/stat/read(workspaceFileScope, path, signal)`；`WorkspaceFileScope = {sessionId, workspaceRoot}`；
- 该 scope 由基座的 `workspaceFileScope` **lookup** 从线上的 `SessionId` 解析：`workspaceRoot = header.cwd ?? sandboxPolicy.workspaceRoot`
  （`lib/index.js` 的注册体），也就是**范围来自会话**，不是任意目录；
- `WorkspaceFileStat.version` 是 **opaque freshness token，never parsed**；
- `list` 走 `confine` 判 `outside-workspace`；`read/stat` 允许工作区外路径（声明明文），错误码含
  `not-found / too-large / not-text / not-regular-file / not-directory`。

本 shell 目前没有任何会话（聊天面是 002/005 的事），而 scope 又不能凭空造。

## 决策

1. **D1 scope 必须来自真实会话**：桥只用 `ctx.get('sessions').list()` 里 `header.cwd` 等于所请求 `workspaceRoot`
   的活会话构造 scope；没有这样的会话就答 `bridge-file-scope-unavailable`（unavailable-first），
   文件服务一次也不碰。**不铸 session id、不用沙箱根顶替、不拿别的工作区的会话**。
2. **D2 引用只从候选建立**：候选来自 `list`（工作区限定）；main 侧另设早一道门——路径必须是
   工作区相对（拒绝对路径、`.`/`..`、空段，码 `file-path-outside-workspace`，且**不触桥**）。
3. **D3 建立引用＝一次 stat**：`create` 的桥调用序列必须恰好是 `['workspaceFiles/stat']`——没有 `read`、
   没有目录扫描；记录里存创建时的 `version` 与 `absolutePath`，此后**不再改写**（"历史指向当时来源版本"）。
4. **D4 取用先重核，token 不等即阻断**：`use` 先 `stat`，与记录里的 token 比对；
   - 不等 → `source-changed`，**在任何 `read` 之前**返回，`text: null`；
   - `read` 自己返回的 token 与持有 token 不符 → 同样按 `source-changed` 处理（不交付不匹配内容）；
   - token 相等才 `read`（显式 `{offset:1, limit:200}`，不依赖基座默认）。
5. **D5 取不到的说法自成一格**：`not-found` 归 `source-not-readable`，界面文案说"这次取不到"并明说
   "不表示源文件已被删除、也没有改换来源"——**引用不换源、不自动重指向**。
6. **D6 记录只在本次运行**：引用列表是进程内记录（未持久化），界面明说"引用记录只存在于本次运行"，
   不假装成已落库。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 桥自己造一个 scope（自铸 sessionId 或直接传沙箱根） | 否决：伪造会话身份；且 `list` 的 confine 会按错根判定，工作区语义当场失真。 |
| 让 UI 手输绝对路径建引用 | 否决：工作区外的路径本就不该成为引用（工单明确不做），候选即边界。 |
| 取用时直接用新版本内容（"反正读的是最新"） | 否决：工单要"源变更即阻断"，自动换版本会把用户确认过的来源悄悄换掉。 |
| 把 `version` 解析成时间戳/哈希来给出"何时变的" | 否决：基座声明 never parsed；解析即依赖未承诺的内部形状。 |
| 引用落库（matter store / 本地文件） | 否决：事务/归属未定（002 的草案存储未决），先落库=先造第二个家；本票记 in-process 并写明。 |

## 后果

- 文件读面在"有会话绑定该工作区"之前恒 `bridge-file-scope-unavailable`；这不是缺陷而是当前 shell 的真实状态，
  002/005 接上会话后自然可用（真机端到端未跑，本票不启动 Host）。
- 引用链的三条验收各有机器断言：建立＝单次 stat（D3）、变更＝阻断且无 read（D4）、
  工作区外＝早门拒绝且不触桥（D2）。
- 边界诚实：`source-not-readable` 只说"这次取不到"；界面文案有反例断言（不得出现删除式表述）。
- 引用记录不落库、进程结束即失；真机版本重核与"失效原因分级"的成本上限（工单备注的核验项）留待真机实测。

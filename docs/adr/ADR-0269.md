# ADR-0269 · Sanbao 206 状态采用逐行五维交付矩阵，不以页面目录代替集成

- 状态：accepted（2026-10-05）
- 日期：2026-10-05
- 决策者：用户（要求围绕 206 页面制定完整目标、拆分 spec/tickets 并执行）＋ Codex（证据边界与门禁）
- 决策记录：[Note](../notes/implemented/process/2026-10-05-sanbao-206-delivery-matrix.md)
- 相关：[Sanbao → Sage UI 一致性合同](../specs/2026-09-27-sanbao-to-sage-ui-consistency-contract.md)、[集成规格](../specs/2026-10-05-sanbao-in-sage-integration-spec.md)、[执行票据](../plans/2026-10-05-sanbao-in-sage-integration-tickets.md)

## 背景

Sanbao 原型在 pin `b861d046013fb8bee9a1f3224ed0965efcf42111` 下提供 59 个组、206 个可见状态。既有机器可读文件只描述原型页面、状态与迁移线索，不能证明这些状态已经进入 Sage 默认窗口、已经连接 Application Service、已经由 Host 支撑或已经通过真实 Electron 验收。若只统计路由、React 组件、截图或 Pages 页面，会把“目录存在”误报成“产品集成完成”。

## 决策

1. `docs/specs/2026-09-27-sanbao-to-sage-ui-state-map.json` 是 206 状态在 Sage 的唯一 tracked 进度事实家。它固定 Sanbao source pin、catalog/ledger digest，并要求 206 distinct IDs 与 59 groups 双向等集。
2. 每一行分别记录 UI、Application Service、Host、Electron acceptance、visual acceptance 五个维度。只有 required 维度全部 `verified` 且证据是 Git tracked、非 fixture、非 ignored、非 candidate-only，行才可成为 `integrated`；N/A 必须有 tracked decision 与 rationale。
3. 原型的 `wired`、`honest`、`entry-verified` 仅保留为 prototype observation，不能提升 Sage 状态。Pages、旧 renderer、旧 DSH DMG、截图文件存在、ignored CSV 或局部测试均不能关闭行。
4. 由 `scripts/gen-sage-sanbao-state-matrix.mjs` 从 pin 的 catalog/ledger 与规则重建或 `--check`；独立 matrix gate 校验逐行事实与派生 summary，并进入 Sage global gate allowlist 与 `test:gate`。
5. 工作拆为 T01–T14 与 DMG-INTERNAL。首个内部 DMG 可在全量 T14 前并行形成，但必须报告当时真实矩阵计数；能打包不等于 206 状态已集成。
6. 初始基线明确为 `integrated=0/206`。已有 4 条 UI implementing 与 202 条 UI pending 是施工状态，206 条 Application Service blocked 是当前事实，不是失败的隐藏或待人工口头折算。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 直接把 206 条标成 integrated，再逐步补后端 | 否决；会让计划状态冒充交付，并使拒绝态、失效与真实窗口证据不可追踪。 |
| 只维护一张人工 CSV | 否决；ignored/candidate 文件不可作为提交、门禁与复验的共同事实家。 |
| 只按 59 个页面组追踪 | 否决；同组内正常、空、错误、拒绝、加载与操作态的后端和验收差异会被抹平。 |
| 把 DMG 完成作为 206/206 的替代验收 | 否决；可安装性与功能集成是正交事实。 |

## 后果

- 正面：任何“还差多少”都可从同一 tracked 文件重算；新增 UI、route 或 DMG 不会自动放大完成率。
- 代价：每个状态必须补五维证据，交付速度按真实闭环而不是页面拷贝数量计数。
- 当前事实：矩阵门禁为绿，计数仍是 `integrated=0/206`；后续只能随 owner ticket 的真实证据逐行推进。

# ADR-0175 · Electron 43.3 caller-binding 预检与 WT-02D.0.1 阻断

- 状态：accepted（2026-09-30）
- 日期：2026-09-30
- 决策者：用户（lute）
- 决策记录：[Note](../notes/proposed/architecture/2026-09-30-electron-caller-binding.md)
- 相关：[ADR-0174](ADR-0174.md)

## 背景

[ADR-0174](ADR-0174.md) 要求未来 Application Service 只接受由 Electron main 建立、不能由 request body、URL 或不受信 header 自报的 caller binding，并把具体机制留给 WT-02D.0.1 针对当前 Electron pin 证明。当前 browser-fetch route 经过 `Session.webRequest.onBeforeRequest()` 与 `protocol.handle()`；前者可观察 `WebContents` / frame，后者在 Electron 43.3.0 只收到标准 `Request`。

WT-02D.0.1-PREFLIGHT revision 38 因此先用隔离的真实 Electron 43.3.0 browser process 检验：请求进入 handler 前能否绑定允许的 main frame 并拒绝其他来源，以及已经放行的请求在 caller 导航或销毁后能否可靠失效。本 ADR 只决定预检结果与后续分支，不实现 production route、Application Service 或业务动作。

## 决策

1. **revision 38 的结论为 NO-GO。** `onBeforeRequest` 能在 `protocol.handle` 前观察并校验当前 `WebContents`、Session、main frame、frame origin 与 resource type；对同源 subframe、同 Session 的其他窗口、opaque frame、`Session.fetch()`、main-frame navigation 和不同 partition 均能在 handler 前取消。这个局部能力本身成立。
2. **当前 browser-fetch transport 不能满足完整 caller-binding 合同。** trusted main-frame 请求通过 gate 并进入 `protocol.handle` 后，无论 caller 随即导航、对应 `WebContents` 被销毁，还是 renderer 显式执行 `AbortController.abort()`，Electron 43.3.0 的 handler `Request.signal` 在 2 秒有界观察窗内都没有 abort；前两种场景的 renderer 请求也没有在 3 秒内形成可归责终态。handler 又没有 sender / frame 身份可供副作用前重新绑定，因此不能证明 stale / destroyed / explicitly cancelled caller 会在未来 Host / Application Service 调用前 fail closed。
3. **WT-02D.0.1 保持 blocked。** 当前 Host-owned `GET /.sage/state` 与 `POST /.sage/actions` 保持不变；不得把入口时的一次校验、`Origin` / `Referer` / body / query / custom header、URL token 或事件顺序关联当成持续 caller identity，也不得在该缺口存在时迁移 production route 或接业务副作用。
4. **绿色测试只表示 NO-GO 证据可重复。** 隔离 probe 保留 `passed=false` 与三条精确失败；外层 test 对事件、顺序、取消、handler 次数和失败读数独立断言。测试通过不表示 transport 通过、production guard 已实现、授权已完成或 route 已上线。
5. **替代机制必须另票决策与确认。** IPC / preload sender binding、Electron pin 升级或其他 main-owned transport 均不得在 revision 38 内自动启用；新方案必须重新建立 Birdview 计划、版本证据、安全边界和回归门。
6. **本批只保留预检证据与治理记录。** 射程严格为两个隔离 probe 文件、本 ADR、对应 Note、ADR 索引、派生 ledger 与执行计划；production `src/**`、package / lockfile、Electron pin、UI、provider、Adapter、legacy 与 release 均不修改，也不暂存、不提交、不推送。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 只要求请求进入 gate 时 caller 有效，放行后不再关心 caller 生命周期 | 否决；未来 action 可能在 caller 已导航或销毁后继续产生副作用。 |
| 用 `Origin`、`Referer`、body、query 或 custom header 补 sender identity | 否决；这些值缺失、可由调用方影响，或不能证明具体 live window / frame。 |
| 用 URL token、请求顺序或时间窗口把 `webRequest` event 与 handler `Request` 拼接 | 否决；当前 API 没有提供不可伪造、可证明的一一关联。 |
| 本批改成 IPC / preload sender binding | 暂不执行；会改变 renderer transport、权限面和测试边界，必须另立方案并确认。 |
| 本批升级 Electron pin | 暂不执行；dependency / pin 变更必须与行为修改分开决策和验证。 |
| 忽略失败，继续建立 `.0.1` production skeleton | 否决；这会在安全前提未成立时先迁移 route ownership。 |

## 后果

- revision 38 得到可重复的局部正证据和关键反证据，但最终决策是 NO-GO；不得简写为“caller binding 已验证”。
- WT-02D.0.1、`.1` 与 `.2` 均不因本票获得源码或生产授权；`.0.1` 在新 transport 决策前保持 blocked。
- 当前 browser-fetch / Host-owned route 继续作为现状存在，但本 ADR 不把它认定为满足 ADR-0174 的 caller-binding 安全边界。
- 后续若选择 IPC / preload、升级 Electron 或其他方案，需要重新验证 sender identity、caller 生命周期、取消、单一 owner、import firewall、rollback 与生产回归。
- probe 是平台行为证据，不调用 Host、Adapter、store 或外部 action；没有产生生产数据或外部副作用。

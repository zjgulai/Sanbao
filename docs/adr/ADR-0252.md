# ADR-0252 · UI 接线第五批：correction submit admission 收口

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（用户确认继续执行第五批）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-correction-submit-admission-batch-5.md)
- 相关：[ADR-0251](ADR-0251.md)、[ADR-0174](ADR-0174.md)

## 背景

第四批之后仍有 25 条 protected-effect route 直达 provider。`POST /.sage/corrections` 只有 `submit` 一个 operation 且带显式 `matterRef`，适合作为下一条独立收口；但其现有 raw owner 先调用 send、后追加 correction record，不满足 Application Service 的 durable-before-dispatch、idempotency 与 `outcome-unknown` reconciliation 合同。body 中的 `workspaceRoot` 也只是 renderer 自报路径，不能成为 authority 或 trusted root。

## 决策

1. 本批只关闭 `POST /.sage/corrections` 的 `submit` direct-provider bypass。稳定 operation 为 `session.correction.submit`，candidate 为 request 的 `matterRef`；不把 action-items、projects 或其他 route 混入同一完成声明。
2. protected intent payload 只包含 `originalText`、可选 `originalAt` 与 `text`。`workspaceRoot` 不是 authority，不进入 intent，不传给 authority ports；未来 trusted root 只能由 main 从 fresh ActiveContext 与受信 stores 重算。
3. production 当前仍缺完整 Identity / Policy、target、Compatibility、Registry、preflight、durable persistence 与 dispatch ports，因此保持 unavailable-first。任何 unavailable / denied / stale 都在 raw `correctionCreate` 前终止，raw provider 与其下游 send 调用数均为 0。
4. 现有 correction raw owner 先 send、后记录，不作为合法 production dispatch / persistence 实现。真实发送必须等待 durable operation / idempotency identity、dispatch 前 freshness barrier、窄 Adapter port 与 `outcome-unknown` reconciliation 合同。
5. protected admission 数从 10 增至 11，direct-provider bypass 从 25 降至 24；route 总数和 classification 分母不变。本批只证明 bypass 收口，不声明 correction 发送可用；不改视觉 / IA、dependency、package 或 lockfile，不 commit、不 push。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 保留 direct provider，只依赖 route/parser 或 UI 文案 | 否决：它们不能替代 authority ordering，也不能阻止 raw 副作用。 |
| `matterRef` 匹配 ActiveContext 后直接调用 raw owner | 否决：context 不是 standing authority，后续 authority 与 durable dispatch 仍缺。 |
| 把 `workspaceRoot` 当 trusted root | 否决：renderer 自报路径不是 authority，必须由 main fresh 重算。 |
| 将现有 raw owner 作为 dispatch / persistence | 否决：先 send 后记录，无法证明 durable-before-dispatch 或可靠收口未知结果。 |
| 一次收口多条 action route | 否决：不同 operation 的 object scope 未证明，route-level green 会掩盖 authority 缺口。 |

## 后果

- corrections submit 不再有合法 direct-provider 路径；production 缺 port 时稳定 refusal，raw provider 与 send 零调用。
- `workspaceRoot` 保持非 authority，即使 transport 暂时仍接受该字段，也不得进入 intent 或 dispatch 信任边界。
- raw owner 继续只承载隔离的 correction domain semantics；未来真实发送必须另票补 durable persistence、idempotency、Adapter 与 reconciliation。
- authority truth 更新为 11 条 protected admission、24 条 bypass；剩余 bypass 必须继续逐 operation / object scope 收口。
- 本 ADR 不构成视觉迁移、dependency 变更、发送可用、发布、commit 或 push 证明。

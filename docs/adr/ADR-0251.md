# ADR-0251 · UI 接线第四批：projection read admission 与 request-scoped owner

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（用户确认继续执行第四批）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-projection-read-admission-and-owner-batch-4.md)
- 相关：[ADR-0250](ADR-0250.md)、[ADR-0174](ADR-0174.md)、[ADR-0163](ADR-0163.md)、[ADR-0164](ADR-0164.md)

## 背景

第三批已建立显式事项选择与 ActiveContext，但 13 条 read-only route 仍直达 provider；main 的部分 provider 还以“最新 converted draft”推断 current matter。读取同样需要独立 projection-read policy，draft recency、已登录、列表可见、action grant、fixture 或旧 ActiveContext 都不能证明当前请求可读取某个 matter/object。`/.sage/state` 与 `/.sage/search` 还包含跨事项或全局数据，不能被单一 active matter scope 覆盖。

## 决策

1. 13 条 read-only route 的 15 个稳定 operation 统一进入一个 async projection-read admission seam；顺序固定为 caller → initial context → independent read policy → fresh scope → candidate match → pre-read freshness → raw read → runtime decode → post-read freshness。只有全链明确 allowed、read value 通过 runtime decode 且 post-read token 与 pre-read 一致时才可返回。
2. production 当前缺 matter/object-bound projection-read policy，因此统一接线后仍 unavailable-first；缺失、异常或畸形 authority 时 raw provider 调用数为 0。现有 action authorization、`external-read`、instance-operator role、列表可见与 fixture 均不得补 read grant。
3. Electron main 以 `projectionReadScope.run/current` 的 `AsyncLocalStorage` 建立一次 admitted callback 内有效的 request scope；需要 current matter 的 provider 只读取该 scope 的 ActiveContext facts。禁止继续以 newest converted draft 推断，也禁止 scope 缺失时 fallback。
4. read admission 消费 ActiveContext 但不激活或替换它；显式 selection 仍是唯一 context owner。GET、search、draft conversion、Host observation 与上一次请求不得产生或续借 active context。
5. `/.sage/state` 是多事项/设备 aggregate，`/.sage/search` 是跨事项与全局 session/search；在集合级 policy、逐对象裁剪/redaction 与 anti-oracle 未定义前，production 保持 unavailable/blocked，不借单一 active matter 放行。production state 只返回专门的 blocked envelope，search 只返回稳定 unavailable；二者的 raw provider 都不得调用。显式 `SAGE_FIXTURE_PROJECTION=1` 仅允许本地 fixture window probe 调用 state projection，保持 fixture 标识与 action blocked，不构成 production authority。
6. 13 条 read-only 分母保持不变。验收只允许声明 bypass 收口、scope owner 与 unavailable-first 行为可验证，不得声明真实事项读取可用。本批不改 dependency/package/lockfile，不做视觉迁移，不 commit、不 push。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| read-only route 保持 direct provider | 否决：数据读取同样受 authority 约束，direct path 是并行绕过。 |
| 复用 action grant 或 `external-read` | 否决：action 与 projection read 分权，当前 grant 没有 matter/object read scope。 |
| newest converted draft 作为 current matter | 否决：设备级 recency 不是 request-scoped owner，可能跨窗口、重排与转换串读。 |
| 只要 ActiveContext 存在就放行 | 否决：context 不是 standing authority，每次 read 仍需 fresh policy 与 candidate match。 |
| 用 active matter 放行 state/search | 否决：单对象权限不能扩张到集合与全局数据。 |
| 把 fixture state bypass 当成 production allow | 否决：fixture 只服务显式验证，不是 production identity/policy/object authority。 |

## 后果

- 13 条 read-only route 后续只有一个合法 authority 入口；新增绕过应由 matrix/gate 阻断。
- 真实 read policy 缺失期间，相关读取会稳定 unavailable/blocked 且 raw provider 零调用；入口存在不等于功能可用。
- provider 的 current matter 改由 admitted request scope 提供，请求结束即失效；draft recency 不再拥有读取语境。
- state/search 继续是显式 backlog，必须另给集合 policy、裁剪/redaction 与 anti-oracle 证据。
- 当前改动留在 dirty integration worktree，未提交、未推送，也不构成发布或生产验收。

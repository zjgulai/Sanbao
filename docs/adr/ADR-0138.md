# ADR-0138 · 引入 Jev 作 SkillOpt 的 Tier 1.5 语义判读层；判据出报告、内容寻址指纹进门禁；出网上限钉在仓库文本

- 状态：accepted（2026-09-19）
- 决策者：用户（lute）+ 本轮 Jev 落点调研
- 相关：ADR-0014（豁免只减不增）、ADR-0015（非机械改动留痕）、ADR-0061（本机装配走 profile）、ADR-0122（机读决策账本）、ADR-0131/0136（产品名与出货面）；总账 P-01、P-02、P-04、P-07、P-13、P-25
- 术语：`CONTEXT.md` 的「Jev 与语义判读」段

## 背景

评估外部产品 TypeSafe Jev（System One 判断模型：把自然语言与应用状态转成带概率的**类型化判断**，不生成文本）
在本仓的落点。下列全部是本轮**真实命令输出**，不是文档转述：

- `POST https://api.typesafe.ai/v1/systemone` → HTTP 200、`jev-1.13.0`、0.73–0.88s；单个请求并发
  noul + choice + score 三问可用。
- 中文实测：**全中文** `state` + criteria → confidence 1.0 且判对（连 question id 用中文也对）；
  **中英混写**那组掉到 0.54 且选错。→ 真风险是语言混杂，不是 CJK 本身。
- 成本：1265 输入 token/条 → 292 条外推 ≈ **$0.0155**、单线程 ≈ 4.4 分钟。钱与时延都不是约束。
  但官方明写限流「**动态调整中，可能无通知变化**」（正在超载），且输入**仅文本**、不可靠计数、
  不做日期算术、字面读题、**不 per-account 微调**。
- 官方失效模式第 6 条对本仓最锋利：「**state 不被当敌意处理**；为自身分类辩护的文本可以移动答案」。
  这直接否掉「拿它当 coding agent 输出裁判」这一热门玩法——被审文本完全能写得让裁判偏向通过。

三条结构性事实使"接进出货面"和"接进硬契约"都不成立：

1. 三宝是 **Electron 本地优先、无服务端**（`apps/lute-shell` + profile 本地装配）。出货路径直调付费
   第三方 API ⇒ key 必然被打进 app bundle，每台安装都持有同一把账单；同时卖家数据出境。
2. `~/.dsh/.credentials.yaml` 的官方 README 自陈：**「只有你的 OS 用户能读取该文件，但 agent 的工具
   进程以同一用户身份运行，因此该存储无法向 agent 隔离机密。」** 而本仓实测有 **64% 的 agent 步在跑
   bash**。任何放这里的密钥对所有未来会话可读。
3. `~/.dsh/scratch/attrib/` 实测 `mine.jsonl` 43.4MB + `other.jsonl` 18.8MB 的**完整会话转录**，
   两份都含 `danger-full-access`，前 300KB 即命中密钥形态正则。外发它 = 外发全部工作记录。

**最要紧的一条：这件事已经有家。** `docs/skillopt-optimization-report.md` 已做过 246 个技能的
全量静态评估并产出 `triggers`/`workflow` 建议；`scripts/skillopt-tier1-apply.py` 已实现
「建议 → 机械校验 → 落盘 → `SKILL.md.bak/.t1` 双快照」；`docs/skill-contract-plan.md` 已把
frontmatter `example` 键定义为「真实业务场景示例」。我要造的"技能指令体检"与它们**是同一条事实**。
而那份报告 §三 关键发现 1 是本仓自己写下的结论：**静态评估永远发现不了文档-实现脱节，轨迹驱动是必要的。**

两轮真实实验（第二轮是对第一轮结论的证伪尝试）：

| 判据 | 第一轮（我现编的通用任务样例） | 第二轮（仓库内真实电商场景句 / 收窄措辞） |
| --- | --- | --- |
| ① 误触发 | 正例 0.44 ≈ 真实语料 0.45，**无区分度** | 0.34/0.39 vs 1.74/1.14，拉开了；但同时暴露它测的是**相关度**不是**宽度** |
| ② 无例外停止 | 0.64 vs 0.16/0.31，**有效**（边距仅 0.33） | 复现，0.64 vs 0.16/0.28 |
| ③ 环境机制依赖 | 两条**已修好**的真实语料被判 0.90/0.81 → **射程未定义**（P-25 形状） | 显式排除平台名/SaaS 后：真实语料 0.73→**0.06**，缺陷样本 0.96→**0.97** |
| ④ 高影响未确认 | 0.04–0.20，本语料**无方差** | 同上 |

并实测到官方警告的形状：Score 返回了 **1.74** 这种级间插值值。

## 决策

**D1 落点域 = 内部研发回路，出货面本轮不接。** 理由不是"还没做"，是 bundle 持钥 + 数据出境 +
限流即可用性三条在当前架构下无解。将来若要接，第一刀是"key 在哪一层"而不是"接哪个功能"。

**D2 出网上限 = 仓库内 git 跟踪的文本。** `~/.dsh/scratch/attrib/**` 永久禁止进入任何请求 `state`。
这条可机检：任何把 attrib 内容读进 outbound state 的代码路径都必须不存在，而不是靠人记得。

**D3 家 = 并入 SkillOpt，作 Tier 1.5 语义判读层。** 输出沿用既有 `sug-*.json`（`name` / `skip` /
建议字段），下游复用 `skillopt-tier1-apply.py` 的机械校验与 `.bak/.t1` 快照；对照样例复用
skill-contract 的 `example` 键；**不新建第二个体检报告、不新建第二套待办格式**（P-07）。
Tier 1.5 的定位一句话：它只做「纯文本可读出的缺陷」，而**不接管**轨迹层——关键发现 1 的结论不被推翻，
本轮只补它前面那一段。

**D4 判据集三条进主集、一条出主集。** ① 由单条 Score 改为**逐任务一个 Noul、越界率由代码算**
（官方 counting 章节的推荐形状：在代码里迭代候选、逐个问、自己加起来；同时避开 score 不得插值的禁令）；
② 保留无例外停止 Noul；③ 采用收窄措辞（只算 agent 运行环境机制：shell 前缀、上下文压缩策略、固定绝对
路径、本地 CLI 必然可用；**显式排除**目标电商平台名、外部网站、SaaS、需联网的数据源）；
④「高影响未确认」**移出主集**，仅在动作型技能子集上跑——本语料实测无方差，留在主集就是一条恒绿判据。

**D5 门禁语义 = 内容寻址输入指纹，不拿时钟当凭据。** gate 重算
`sha256(待审语料 ⊕ 判据文本 ⊕ 阈值 ⊕ 模型版本)` 与产物内登记的指纹比对：语料与判据没改 → 旧产物永远
有效（零 API 调用、完全离线、确定性）；改了 → 判红并点名哪一项变了。第三方可用性**不进** gate 关键路径。
同构先例：`live-presets.expected.json` 这类期望值文件。

**D6 钉版本、单文件、回读模型 id。** 请求钉 `jev-1.13.0` 而非 `jev-latest`（官方：别名随发布漂移，
调过阈值必须钉版本），同时把响应 `model` 字段的回读值写进产物；判据文本与全部阈值住**一个文件**，
因为人唯一需要复核的就是这两样。

**D7 凭证 = `~/.dsh/.credentials.yaml` 的 `refs`，名 `LUTE_JEV_API_KEY`，只读不写。** 不占产品
provider 名以免与基座配置碰撞；dev 侧按官方优先级链（启动环境快照 > 存储文件 > 项目 `.env` >
`$DSH_HOME/.env`）解析，不新增家、不反写该文件。本条**机制未变**；「key 对所有 agent 会话可读」
这一风险面的处置（2026-09-20 重判为明确接受）见后果 2。

**D8 验收双轨。** 工程轨**离线**（fake transport 断言请求体/重试/预算/降级），typecheck + node:test，
进 gate；语义轨是基线记分卡（F1–F10 当召回集、已修好文本当误报集、同文本连打 5 次测漂移——把官方那句
「extremely consistent」当**被测事实**而不是常量），只进报告。

## 后果

**正面**：一条外部能力被接到了**已有**的家上而不是新开一个；判据质量拿到了两轮可复现的实测数字而不
是"看起来合理"；gate 的确定性没有被概率模型污染，同时"写了从没跑到"仍被指纹新鲜度按住。

**负面 / 欠账（不闭口，逐条登记）**：

1. **D2 的出网边界：原文登记为「仍是纪律，没有门禁」——已由机制收口（2026-09-20）。** 原文的判词是
   「要真守住需要一条判据扫『outbound state 的来源是否落在 git 跟踪集内』，而『来源』是运行期数据流，
   静态扫不出来」；这句话只对了一半：**静态**扫不出，**运行期**可判。闸门
   `scripts/jev/egress-boundary.mjs` 现在装在两个装载器（`loadCorpus` / `loadSamples`）上，
   仓外/未跟踪的来源在装载那一刻被拒并点名本条决策；守住这条闸门的仪器是门禁 `jev-egress-boundary`
   + 反例自测（口径与读数见 [Note](../notes/implemented/process/2026-09-20-jev-egress-boundary.md)）。
   残余仍如实保留：**文件被跟踪 ≠ 内容清白**——跟踪集内被写入敏感文本这一段只能靠人复核。
2. **key 对所有 agent 会话可读**这条，2026-09-20 **已重判为「明确接受」**（原文登记为「只被登记、没有消除」）。
   重判依据是实测而非推理：Keychain 的**默认形态**（`security add-generic-password`，多数工具的用法）
   对同用户进程**零收益**——非交互一行 `security find-generic-password -s <服务名> -w` 即读到明文
   （实测 `rc=0`）；唯一真正改变暴露的是**收紧 ACL**（`-T` 不把 `/usr/bin/security` 列为可信应用，
   实测 `rc=128`、零字节、非交互直接失败），代价是每次取用需人工授权、agent 触发的非交互跑批不可用。
   接受的理由与缓解：key 是**专用、可吊销、按次计费、只用于内部研发回路**的凭据（D1 已钉出货面不接），
   跑批成本 ≈$0.0155/轮；门禁路径根本不碰 key（D5 指纹门禁离线、零 API 调用），暴露窗口只在跑语义轨那一刻。
   **前置条件**：日后若要把 Jev 交给无人值守自动化，必须先上收紧 ACL 的 Keychain（或等价的「人在环取用」）
   方案，再谈自动化。口径与读数见 [Note](../notes/implemented/process/2026-09-20-jev-credentials-keychain-rejudge.md)。
3. **项目级 skill 装在本机 `.qoder/skills/typesafe-ai/`，被 `.gitignore:14` 的通配 `*` 排除**，
   故不随克隆走；且与 `~/.agents/skills/typesafe-ai` 内容逐字节相同（sha1 一致），而官方建议
   「Choose one installation method to avoid duplicate copies」。要么给 `.qoder/skills/` 与
   `skills-lock.json` 加白名单入库，要么接受"只在本机有效"——留待下一轮，本轮不承诺。
4. **三条判据的阈值全是待校准初值。** ② 的分离边距实测只有 0.33；① 改成逐任务后越界率的判定线尚未在
   任何数据上定过。
5. **SkillOpt 的 `ROOT` 是 `~/.dsh/skills`（已安装技能），不是仓内 292 条 corpus。** 两者不是同一份
   东西，Tier 1.5 跑哪一份必须先定，否则会出现"体检报告说 A 有问题、apply 改的是 B"。本轮未决。
6. 本轮**未**写任何实现代码。工具落地按 `grill-with-docs → to-spec → to-tickets → implement` 推进，
   实现提交须按 ADR-0015 附 Note。

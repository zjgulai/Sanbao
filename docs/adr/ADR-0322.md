# ADR-0322 · 启动失败可见面：ready 后前显对话框 + 稳定退出

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（2026-10-12「同意下一建议，开始执行」）＋ agent（设计）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-startup-failure-surface.md)
- 相关：[ADR-0271](ADR-0271.md)（打包链）、白屏事故取证（2026-10-13 本机，`packaged-sage-launch-traps` 记忆）

## 背景

打包首启失败（根非 pristine / 路径含 symlink / profile 拒装）走旧 catch：pre-ready `dialog.showErrorBox` + exit。实测缺陷：对话框可被空白窗口遮挡、进程无限等待——用户只见白屏（拒装本身是正确行为，呈现不是）。失败信息只落在 launcher stderr，用户不可知。

## 决策

1. **D1 单家模块**：新 `startup-failure.ts` 收口全部启动失败呈现：full stack → launcher stderr；await ready（对话框因此前显）；一个具名错误框（标题 `Sage 启动失败`，内容=error.message）；dismiss 后 exit(1)。
2. **D2 never-throws 契约**：日志/ready/对话框任一步失败都不吞错——最后必然 exit(1)；无显示的平台上仍稳定退出。
3. **D3 index.ts catch 改走模块**（原内联三行删除）；不改任何拒装判据与退出码。
4. **D4 验证边界**：单测锁顺序与契约；**打包内实机验证随下一次 produce（v5 链）**——本批不重打 DMG。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 失败窗用 BrowserWindow 渲染 | 否决：对话框语义足够；引入窗口生命周期与 CSP 面不值。 |
| 放宽 pristine 允许 policy 文件 | 否决：policy 先落根即破坏首启事务判据；保持门禁，改呈现。 |
| 硬超时兜底 exit | 否决（本批）：可见对话框前显后等待 dismiss 是正确语义；无显示平台已由 catch 兜住。 |

## 后果

- 打包启动失败从「白窗+隐匿日志」变为「前显具名对话框」，用户可自解（检查根/按手册顺序）。
- 打包实测待 v5 produce；本批单测 2 例钉顺序与 never-throws。

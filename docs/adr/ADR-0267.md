# ADR-0267 · 读策略接线：选择时读授权与投影读取策略（T03 授权）

- 状态：accepted（2026-10-05）
- 日期：2026-10-05
- 决策者：用户（授权 T03 接线：读策略端口接线与 route-authority 门禁注册事实扩展）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-05-read-policy-wiring-t03.md)
- 相关：[ADR-0266](ADR-0266.md)、[ADR-0265](ADR-0265.md)、[Application Service 边界](../notes/proposed/architecture/2026-09-30-application-service-boundary.md)

## 背景

T01/T02 之后默认桌面与设备入口可用，但 `/.sage/state` 等 13 条 read-only 路由的 projection-read admission 恒停在 read-policy 阶段：`index.ts` 的 `authorizeMatterRead` 与 `authorizeProjectionRead` 被钉死为 `() => undefined`（unavailable-first），route-authority 门禁把这两个钉死事实登记为生产护栏（"projection-read request owner or production unavailable-first policy drifted"）。T03 已备好 `src/main/projection-read-policy.ts`（选择铸造高熵 actor scope 绑 (session,matter,policyDigest) 内存账本；读取逐操作 `projection.read`/`matter.read` local-read 授予；策略不可读→unavailable、负答/越界/无绑定/跨策略版本→denied）并完成桌面三槽位消费与工作区接入入口，唯独接线本身是门禁注册事实变更，须单独授权。

## 决策

1. 在 `index.ts` 组装唯一 memoised 读策略对象（`readPolicyFor()`；账本必须跨请求存活，禁止每请求重建），并把两个钉点接为 `authorizeMatterRead: (request) => readPolicyFor().authorizeMatterRead(request)` 与 `authorizeProjectionRead: (request) => readPolicyFor().authorizeProjectionRead(request)`。
2. 读策略语义（已在 `projection-read-policy.ts` 落地并有 7 条测试）：授权只覆盖 `local-read` 且 `requiresDecision === false` 的授予；选择时的 matter 读走 `matter.read` 操作/作用域，投影读取按具体 operation 走 `projection.read` 作用域；运行判定输入为真实身份会话（vault）与实例本地组织策略文件（每次现读），无会话或文件不可读→unavailable，负答→denied，未绑定选择/跨 matter/跨策略版本→denied。
3. 门禁按 T02 先例扩展为逐行事实：`projectionReadOwnerMatches` 由“钉死 unavailable-first”改为“接线索（policy 导入、memoised 单例、双接线语句、旧钉死不得回、账本禁止每请求重建的负向针）”；成功 note 与矩阵 `runtimeLevel`（`/.sage/state`、`/.sage/context/select`）同步改述；自测新增 4 条具名突变（unwire projection / unwire matter / drop import / per-request rebuild）。
4. 接线不放宽任何既有 fail-closed 语义：无会话、无策略文件、无授予、未绑定选择一律照旧 unavailable/denied；collection/opaque-object 读取仍缺 main-owned object resolver，维持 unavailable；写面（protected-effect）与 local-system 面不动。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 保持钉死，等登录链路全部就绪再接线 | 不采用；读策略本身就是后续票（T04/T05/T06）的前置，接线与登录解耦可各自验收。 |
| 每请求新建策略对象 | 不采用；绑定的 actor scope 账本随对象销毁，选择与读取将永远对不上。 |
| 用 policy 模块内的决定性 hash 伪装 subject | 不采用；scope 必须高熵随机且只存在于 main 内存（AGENTS.md 红线段）。 |

## 后果

read-only 面在有真实身份会话 + 实例策略授予 + 明确选择绑定时可走到真实读取；其余状态全部保持诚实 unavailable/denied。无登录会话的现状下对外表现不变（仍 unavailable），门禁持续以源码事实锁住接线形态。T04 建项/custody、T05/T06 真实消息链不改，仍按各自票据验收。

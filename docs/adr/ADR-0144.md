# ADR-0144 · 配色改判为 Qoder CN 中性灰 + 灰绿：立面模型反转、只动主题包（取代 ADR-0132 的配色部分）

- 状态：accepted（2026-09-20）
- 决策者：用户（lute）+ Qoder 视觉语言轮（规格 [2026-09-20-qoder-visual-language](../specs/2026-09-20-qoder-visual-language.md)）
- 取代：**ADR-0132 D1 的配色部分**——钛银主色（暗 `#C4D0DC` / 亮 `#3D566E`）与深海军蓝中性阶（`#0b1521` / `#142332` 一族）退役，强调色改登记为 Qoder 灰绿 `#5C9363` 一族。ADR-0132 的其余部分继续有效：D2（1 套品牌 × 明暗双色道）、D3（材质解禁）、D4（`--sanbao-*` 命名空间与双轨 token）、D5（Inter 默认字体）、D6（不纳入七色分类板）；D1 里与色值无关的那半（`--radius 8px`、动效 160/260/520ms）本轮不动，仍按 ADR-0132 登记执行
- 相关：ADR-0135（判据读真实值、token 单一源）、ADR-0008（vendor 只读参照）、ADR-0019（官方 UI 改写锚禁钉哈希）、ADR-0122（决策面向 agent 可机读）、ADR-0125 D7/D8（侧栏宽度契约，本轮不动）；总账 P-07（一条事实多个家）

## 背景

当前界面是**两套色系并存**：

- 主区/左栏走 Sanbao 契约——深海军蓝底 `#0b1521`、面板 `#142332`、钛银 `#C4D0DC` 强调；
- 右栏「工作台」是照 Qoder 抄来的中性灰（`#202228 → #16181c`，CSS 硬编码，不跟主题走）。

两套**立面模型彼此相反**（我们「画布最暗、越抬越亮」；Qoder「画布最亮、越抬越暗」），并置即脏。
用户在真机上的裁决是原话「我很讨厌这种蓝色，我就喜欢的是 Qcode CN 的布局 和配色，以及页面设计」——
被点名的正是这套蓝。规格的 D1 据此改判：**配色整套照搬 Qoder CN，品牌契约改判**，并要求同片写一篇
ADR 取代 ADR-0132 的配色部分。

改判依据是实机采样，不是印象（规格 §2.1；方法：`macos-harness see` 截其窗口 → 逐点采样 +
横向扫描定位列边界）：

| 区域 | 实测值 | 说明 |
| --- | --- | --- |
| 左栏 rail | `#242624` | 暖中性灰 |
| 画布 | `#232523` | 与 rail 几乎同色 |
| 右栏面板 / 顶栏 | `#191B1A` | **比画布更暗** |
| 卡片 / 浮层 | `#131413` | 越抬越暗 |
| 强调色 | `#5C9363`（按钮）/ `#609966`（选中 chip） | 灰绿 |
| 列边界 | `#171918` / `#191B1A` | 低对比分界 |

这张表同时解释了为什么「只换灰阶」不是一条路：**立面方向与配色是同一条契约的两半**——旧契约的
「越抬越亮」本身就是为深蓝暗底服务的，只搬色值会得到「Qoder 的灰 + 反过来的立体感」，两套语言
仍在同一屏上。因此本 ADR 取代的是 ADR-0132 D1 的**色值部分**（配色 + 由配色决定的立面方向），
而不是整篇 ADR-0132：命名空间、双轨 token、材质、字体是结构决策，不因换色而作废。

## 决策

**D1 配色契约改判：暗色道取 Qoder CN 实机实测值，钛银与深海军蓝退役，灰绿 `#5C9363` 一族重新
登记为品牌强调色。** 12 个默认色值按上表（规格 §2.1）换血，强调色取 `#5C9363`（按钮）、选中
chip 的 `#609966` 与其同族；`--sanbao-accent` 名下不再装钛银，品牌强调色与色道值同源。**本条取代
ADR-0132 D1 的配色部分**。色值的家仍是 ADR-0132 D4 立的那一套：
`packages/platform/dsh-theme-local/src/theme-settings.ts` 的默认值是唯一源，`theme-tokens.ts` 派生，
`shared/client/sanbao-tokens.ts` 是源面、其副本由 `node scripts/sync-shared.mjs --write` 生成
（**不得手改副本**）。明色道**照抄 Qoder 真值、不推导**：等采样到再落值，采样前不动亮色道。
两条落地纪律：`#5C9363` 目前是截屏采样值（可能受色彩配置影响），落地前必须用第二个来源交叉核对，
偏差 >2 阶取更可靠者并记录来源；验收要给 WCAG 实测读数（强调色 on 画布 ≥ 4.5:1、正文 ≥ 7:1），
不达标的处置是**回采强调色**，不得就地放宽阈值。

**D2 立面模型反转为 Qoder 式：画布最亮，面板/卡片/浮层越抬越暗。** 画布（`bg-base`）是整屏最亮
层，rail 与画布几乎同色，面板更暗，卡片/浮层最暗。反转落在 `theme-tokens.ts` 的**派生式**上：
`bg-layer-2/3`、`bg-module-platform`、`bg-overlay` 由「往 `#FFFFFF` 混（提亮）」改为「往更暗混」，
token 名、层级数与消费面一律不动——所有吃这些 token 的面自动跟皮。这是**方向**的裁决不是新增
token；亮色道同样按 Qoder 的立面方向（画布最亮、面板更暗），取值以采样真值为准。

**D3 本轮只动主题包：官方壳只换 token，不改结构；vendor 只读、官方 UI 改写锚禁钉哈希。**
射程是 `packages/platform/dsh-theme-local/**`（默认色值 + 派生式 + 其单测），外加 `--sanbao-*`
源面的值随源同步。官方壳（对话流内部布局、聊天卡片结构）是 pin 的只读参照（ADR-0008），**本轮
不改结构**；官方 UI 的换色只经 token 派生，对官方 UI 的改写锚一律运行时解析、**禁钉哈希**
（ADR-0019）。同时不动的还有：自有面布局、`TARGET_SIDEBAR_WIDTH = 264`（`sidebar-row-axis`
门禁钉住的契约；Qoder 的 278px 要另开一条并同步改门禁 TARGET 与 ADR-0125 D7/D8 的登记）、
以及并发会话所有的 `packages/surfaces/dsh-right-sidebar-local/**`（规格 D7）。生效路径是
「默认值 → token 派生 → 全 app 跟皮」，落地必须走两条同步（loadpoint 与 vendor）+ 完整重启，
不接受「改了源码就算生效」。

## 备选方案

| 决断点 | 未采用 | 为什么 |
|---|---|---|
| 配色 | 保留钛银、只把中性阶换成 Qoder 灰 | 钛银 `#C4D0DC` 是**蓝相冷银**（B 通道最大），铺在暖中性灰画布上仍是一块蓝；用户点名讨厌的正是这个蓝，「只换灰阶」把两套语言留在同一屏，问题原样在 |
| 配色 | 保留钛银做强调、灰绿只给状态色 | 强调色的归属一分为二（按钮一个色、状态一个色），而用户要的是 Qoder 一整套；`--sanbao-accent` 名下装钛银又是「名字撞谎」那类坏法——值换了、名字还指着旧契约（ADR-0132 的备选方案里登记过） |
| 明色道 | 从暗色道推导（反演/提亮算出亮色值） | Qoder 明色道不是暗色道的数学反演——它的暗色道立面已被实测证伪了「反演」这个前提；推导产出的是猜值，真值一到就要重做一遍，盘上留下两版亮色值（P-07）。采一次样的成本远低于把猜值铺到全 app |
| 立面 | 只换色、保留「越抬越亮」的立面 | 立面方向与配色是同一条契约的两半；两套立面并置正是 §1 记录的「并置即脏」本体——只换色会得到「Qoder 的灰 + 反过来的立体感」 |
| 立面 | 主区维持旧立面、只把右栏改成 Qoder 式 | 立面方向会出现两个家（同一屏两套），而右栏包归另一会话——跨包改立面等于把并发边界与换色揉进一条变更 |
| 密度 | 同片把行高 36→32、右栏 440→360、圆角/边框一并收 | 换色与改契约必须分开：改宽度要同步改门禁 `TARGET_SIDEBAR_WIDTH` 与 ADR-0125 D7/D8 的登记，混在一条变更里出问题时**分不清是色还是尺寸**（规格 D3/D4 的裁决） |
| 落点 | 在消费面逐个写死新色值 | 一条事实多个家（P-07）：下次换色要改 N 处，且官方壳的消费面根本改不到；契约的家只能是「默认值 + 派生式」 |

## 后果

- **正面**：界面从两套相反色系回到一套——12 个默认色值 + 强调色换成 Qoder 实测值，立面模型统一为
  「画布最亮、越抬越暗」；改判只落在 ADR-0132 的配色一句话上，命名空间/双轨 token/材质/字体这些
  结构决策原样保留，避免整篇重写；右栏那套抄自 Qoder 的硬编码灰与主区语言第一次同族（同一套灰阶，
  不再是两套色系）。
- **负面 / 已知边界**：
  1. **右栏窗口期**：`packages/surfaces/dsh-right-sidebar-local/**` 当前是硬编码灰，本轮不并行动它，
     所以 P0 落地后存在「右栏不跟主题走」的窗口期，直到它的 owner 会话把值改指 token（规格 §7）。
  2. **明色道真值未采**（规格 §6 未决 1）：采样前只落暗色道，亮色道维持既有值 —— 切换主题时两个
     色道的视觉语言不同步，这是显式接受的时间差。
  3. **`#5C9363` 是单一来源的截屏采样值**（规格 §6 未决 3）：二次核对是落地前置，不核对就铺到
     全 app 是「未验证的事实被钉进出货面」。
  4. **立面反转影响面最大**（规格 §7）：所有消费 `bg-layer-*` 的面都会变，可能出现「深色卡片叠
     深色画布」的对比不足。缓解是单独一期 + 逐屏实机看 + 对比度脚本兜底；门禁不会替你发现
     「看着不对」。
  5. **密度与形状不在本轮**：行高 36→32、右栏 440→360、圆角/边框收敛属规格的 P2，等右栏 owner
     收口后单独出计划；264px 侧栏宽不动（门禁钉着，改动要另开一条）。
  6. 「像不像 Qoder」不是判据：验收口径是**实机采样 rail/画布/面板/强调四值与规格 §2.1 逐值一致 +
     对比度读数**（ADR-0135：判据读真实值）。
- **验证**：本 ADR 只做改判与边界登记；落地读数（四值实机采样、对比度脚本输出、逐屏截图）由本轮
  P0/P1 的验收记录回填规格 §4。

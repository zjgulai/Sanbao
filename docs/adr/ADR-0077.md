# ADR-0077 · 交付形态是产物的属性，不是文档的属性：卷内清单只有一个家，且由门禁与产物逐名对照

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：agent（本次实测、判据设计与落地；用户指令「需要，清理残留，保持完整，干净，有序」）
- 决策记录：[Note](../notes/implemented/contract/2026-09-13-dmg-layout-single-home.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（门禁是硬门槛）、ADR-0067（已发布产物不可删除）、
  ADR-0071（复发故障总账）、ADR-0075（判据的射程从 git 里的家推导、射程为空必须报跳过）

## 背景

2026-09-13 复核 2.3.3 实物时，把 `docs/sop/dmg-release.md` §5（终验）逐条对着磁盘跑了一遍。
三条命令，三处不成立——**同一个根因的三张脸**：

| 位置 | SOP 写的 | 实物 |
| --- | --- | --- |
| §5.1 | `codesign --verify … "packaging/release/$VERSION/DSH Desktop.app"` | 该目录下只有 DMG 与三件清单，**没有解开的 app** |
| §5.2 | `# 应看到 DSH Desktop.app 与 Applications 快捷方式` | 卷根是 `DSH Desktop.app.tar.gz` + `install.sh` + `LUTE Setup.app` + 四个 tarball，**没有 `.app`、没有快捷方式** |
| §5.4 | 「把 DMG 里的 app 拖到 `/Applications`」 | 交付形态是**离线安装器载荷**，没有可拖拽的 app |

三处都不是笔误。那些句子是**上一版交付形态**的快照，而 2.3.3 换了形态（可拖拽安装盘 → 离线安装器
载荷）。**快照不会因为产物形态变了而自己报错**——所以所有门禁都是绿的：它们量的是补丁锚点、
TCC 判据、文档链接、出货白名单，没有任何一条把「文档断言的清单」与「产物真实的清单」比过一次。

更坏的第二层：这条事实**本来有家，而且那个家是对的**。`packaging/INSTALL-GUIDE.md` §2 的入口表
准确描述了 2.3.3 的卷内清单（逐行说明每个文件是什么、该怎么用，并明确「只有两个是可点入口」）。
于是这是一次 P-07：同一条事实两个家，用户向的跟着形态改了，工程向的没有——
**而漏掉的那个正好是复核者会读的那个**（P-01）。

第三层是反过来查出的：把入口表与卷内清单逐名对照，卷上有一个 `completeness.json` 从未登记。
它不是一个误入的临时文件——`assemble.sh` 第 650 行显式断言它必须写进 payload，
`smoke-test.sh` 拿它比对 bundle / 技能 / 预设清单。即：**表是描述交付面的，而它是交付面的一部分，
却在表外**。

## 决策

1. **「卷里有什么」收成单一家。** `docs/sop/dmg-release.md` §5.2 改为**指向**
   `packaging/INSTALL-GUIDE.md` 第 2 节，并明确写入「本节不复述清单」。一句「应看到 X 与 Y」的
   真假由产物决定，而它住在文档里，没人会去比——去掉这类句子比让它保持正确便宜得多。

2. **给这条事实装一副牙：门禁 `dmg-layout-doc`。** 落在 `scripts/gates/dmg-layout.mjs`
   （纯函数 + 15 个反向用例，含恒真桩突变），判据分两半，**射程公开写在读数里**：
   - 静态半（永远可判）：**R1 单一家**（SOP 必须链接安装手册）；**R2 形态断言**（SOP 不得断言
     拖拽式交付形态）。
   - 动态半（产物在场才判）：**R3 未登记条目**、**R4 幽灵条目**、**R5 入口可点**。

3. **诚实划界：R2 是「廉价但精确」，不是全称保证。** 它拦的是一种**已经发生过**的写法
   （黑名单），挡不住下一句新的。全称保证由动态半在产物在场时给出。这一点写进模块注释，
   不让它看起来像一条全称红线（P-03 的诚实读法）。

4. **射程跟着 git 走，不跟着磁盘走**（沿用 ADR-0075 / P-11）。`selectLayoutTargets` 把**已打 tag
   的版本**排除出扫描面，并在读数里点名「谁退出了、为什么」。理由是具体的：下一版往载荷里加一个
   文件、手册随之更新，所有还挂载着的旧卷就会**永久**判红，而那条红与「手册和当前载荷对不上」
   在输出上不可区分——清理挂载于是成了让它变绿的唯一手段。默认错误方向选**多量**：读不到 tag
   （浅克隆）时全部纳入；卷名解析不出版本号时也纳入。

5. **把「对的家」补全，而不是把错的家删掉。** `completeness.json` 补进安装手册第 2 节的入口表；
   「大约十个文件」改为**「下表就是卷内文件的完整清单」**——既然门禁逐名守着这张表，
   它就可以承诺自己是完整的。

6. **判不出的一类要明写判不出。** §5.1 那种「SOP 里写着一个不存在的路径」本项**判不出**：
   `$VERSION` 展开成哪一版取决于人，而 `packaging/release/.staging.XXXXXX` 这类**故意**不存在的
   路径会让通用路径判据满是误报（会误报的校验很快会被关掉，P-02）。该处由人工修正，
   并在模块注释与 Note 里明写「不假装它被拦住了」。

## 备选方案

- **只改 SOP 三处措辞，不加门禁**：这正是 P-03。而这次的事实比「复发」更锋利——
  §5 那三条命令**从写下那一刻起就没有被执行过一次**，且它们与同一份文件 §2 的
  「预期产物：`staging/$VERSION/payload/DSH Desktop.app.tar.gz`」**自相矛盾**。
  一次都没跑过的东西，靠提醒不会变得会跑；只有判据会。靠人记得不是工程解。
- **把禁用短语表做成判据的全部**：挡得住已经写过的句子，挡不住下一句新的。故它只占静态半的一条。
- **让静态半解析 SOP 里所有 `packaging/…` 路径并逐一验存在（想覆盖 §5.1）**：
  见决策 6，误报风险大于收益。否决。
- **动态半射程放宽到「所有挂载卷」**：能立刻量到 2.3.3，但下一版就产生永久红。否决。
- **在 SOP 里保留一个「卷应为 N 个文件」的数字**：数字比清单更容易过期，且同样没有判据。

## 后果

- 门禁新增两项：`dmg-layout-doc`、`dmg-layout-doc-selftest`（15 个反向用例，
  含用 2026-09-13 **缺陷原文**当输入的恒真桩突变）。
- 安装手册第 2 节从「大约十个文件」变成可承诺的**完整清单**，多登记 `completeness.json`。
- SOP §5.1 / §5.2 / §5.4 三处改为与 2.3.3 实物一致的安装器形态，每处保留
  「原来写的是什么、为什么会错」的原址说明。
- 复发故障总账新增 **P-14**。
- **遗留一**：本机此刻既无未打 tag 的 payload、挂载的 2.3.3 卷也已打 tag，故动态半报 `skip`
  ——本次**没有校验任何卷内清单**。这不是缺陷，是射程如实；下一次装配会自动把它纳入。
- **遗留二**：§5.1 那一类仍无判据（见备选方案），靠人工复核。
- **遗留三**：本条与 ADR-0076（GitHub Releases 分发面）出自**同日两个并发会话**，
  两者都要改 `scripts/gate.mjs` 与 `docs/adr/README.md`。编号已按落盘顺序让开（本条取 0077），
  但「两个会话同时改同一批文件」这件事本身仍无机制，这是一条已发生的事实，不是假设。

# ADR-0326 · 跨代重观测即重发：发布器 refresh 模式 + 证据等价性外部证明

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（2026-10-12 授权测试与观测；发送链实测发现矩阵 pair 失配）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-cross-generation-republish.md)
- 相关：[ADR-0284](ADR-0284.md)（矩阵发布）、[ADR-0285](ADR-0285.md)（D4 重观测即重发先例）、[ADR-0317](ADR-0317.md)（publications 再封印/发布器）、[ADR-0325](ADR-0325.md)

## 背景

v7 装机实测步骤 7（发送）：admission 止于 `compatibility`（`matrix-pair-not-found`）。装版探针读数：规则声明的 runtime pair = `208b273e…`（录制于旧 profile 世代），live Host 的 `runtimeDescriptorDigest = db60b818…`（对应现行 `artifactSetDigest 09c1ae99…`）。全链唯一差异 = `host/harness.artifactDigest`（profile 字节随每次 produce 重物化而变）；**生产发送的 compatibility 步因此结构性永远过不了**——直到本次，真实发送从未跑通过（冷启动死锁遮蔽）。

维护缺口：`publish-session-controls.mjs` 是 v1→controls 的一次性迁移器（base 已是 controls 世代即拒绝）；ADR-0285 D4 那代跨代重发靠手工编辑 + spec 常量重锚，无可复用的 refresh 路径。

## 决策

1. **D1 refresh 模式**：发布器新增 `--refresh`（跨代重观测重发）与 `--fixture <path>`（录制输入覆盖；`--write` 时 fixture 恒写回仓内路径）。refresh 模式下：生成守卫改判「须为 v1 基座」（组合输入恒为 v1）；两条 v1-round-trip 检查（迁移期断言 fixture×v1 一致）显式跳过并留 note——跨代重发的正是该 pair。
2. **D2 等价性外部证明（替换被跳过的检查）**：重发前必须用**上一版 fixture** 干跑一次：组合输出与当前已装出版物**逐字节比对**（本次：三件全部 IDENTICAL）。证明组合管线保真 + v1 基座保真后，才允许以新 fixture 落地。
3. **D3 过程与录入**：恢复 v1 基座（迁移提交 `3d074f09^` 的三件）→ `inventory-probe` 对现行根重录制 → 外部等价证明 → `--refresh --fixture <new> --write`。净变更仅矩阵包（4 条规则的 runtime pair 与 prompt 语义重导）+ fixture；requirement/registry 逐字节不变。
4. **D4 测试重锚**：spec 中钉旧 pair 的常量（matrixId/bundleId/targetSemantic）按加载器现值重锚；「窗口/生效期」类测试的固定日期前提（录制早于 2026-10-11）随重录制翻转——改为**由录制驱动**（默认窗镜像 shipped 窗；迟到窗/迟到生效期用 `observedAt+Δ` 动态推导），不再钉陈旧字面量。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 手改矩阵 bundle 字节 | 否决：sealed 治理件禁手改；跳过 kernel 校验。 |
| 每次 produce 时自动重录制重发布 | 否决（本轮）：录制需真实 Host 观测，构建链内自动重录制会给「出货即配对」假安全感；重发是显式运维动作。 |
| 保留旧 pair 并放宽 kernel 匹配 | 否决：compatibility 的核心语义即精确 pair；放宽=拆掉证据链。 |
| 恢复 v1 后不用外部证明直接重发 | 否决：被跳过的 v1-round-trip 检查必须以更强的外部等价性证明补位。 |

## 后果

- 生产发送链的 compatibility 步在 v8 起可与 live descriptor 配对（4 op 规则同 pair）。
- 重录制/重发成为有据可依的例行程序（本 ADR 的 D2/D3 即步骤）；每次 profile 世代变化都需要同样的重发。
- spec 的窗口/生效期前提改为录制驱动，后续重录制不再连带重锚固定日期。
- 已知边界：重发验证的是「组合管线逐字节保真 + 规则配对」，不等于运行时的端到端验收——后者由 v8 装机后的发送实测给出。

# ADR-0130 · LUTE 面改乘基座官方 slot：`main` keyed 面板 + `sidebar.panellist` 官方行，DOM 注入行退役

- 状态：accepted（2026-09-19）
- 决策者：用户（lute）+ 能力中枢整合轮
- 决策记录：[Note](../notes/implemented/surface/2026-09-19-skill-center-keyed-slot.md)
- 取证附件：[research/14 · main keyed slot spike](../research/14-main-keyed-slot-spike.md)、执行计划 [docs/plans/2026-09-19-capability-hub.md](../plans/2026-09-19-capability-hub.md) S3
- 相关：ADR-0008（基座只 pin 不改）、ADR-0009（一份事实一个家）、ADR-0015（Note 纪律）、ADR-0019（官方 UI 改写锚禁止钉哈希）、ADR-0075（射程必须落读数）、ADR-0125（侧栏行轴 / 折叠组）、ADR-0128（能力中枢 D2 零 z-index）；总账 P-07（行轴漂移）、P-52（挂死主线程的观测悖论）

## 背景

LUTE 的每个可视化面（技能中心、岗位矩阵、新应用、任务板、SSH）都用同一套**自造承载**
落在基座界面上：

1. **侧栏行靠 DOM 注入**：`shared/client/sidebar-entry-core.ts`（约 460 行）在基座渲染完
   之后往侧栏里 `insertBefore` 一个 `<button>`，并用 MutationObserver 在 React 重渲染后
   自愈。该文件按「同步副本」分发到每个消费包（技能中心、岗位矩阵、新应用各持一份）。
2. **面板靠自管浮层**：技能中心把整页挂在 `document.body` 下的 `.overlay`/`.drawer`
   里，自管层号 `--dsh-skill-center-overlay-layer: 2147482000`、自管入场动画、自管
   Escape 与点击遮罩关闭、自造 `dsh:view-change` 事件总线做显隐。

这套承载的代价已经全部落过账：

- **行轴漂移（P-07）**：注入行的左右缘由每个包自己的 CSS 决定，没有单一住处，于是
  「两行并排但标签 x 不同」反复发生，最终只能靠 `sidebar-row-axis` 门禁把期望轴抄成
  清单来守。
- **注入顺序由落位竞态决定**：共享核心 `'after'` 的锚点是「家族里最后一个成员之后」，
  家族清单一旦不对称，顺序就随挂载先后翻转。2026-09-13 技能中心与岗位矩阵互换位置
  就是这个原因，修法是让两份清单**有意不对称**——用清单措辞守一个本该由机制守的事实。
- **黑屏事故（P-52）**：折叠组的挂载竞态把渲染主线程拖进微任务乒乓，CPU 100%、
  inspector 超时、console 零输出。根因在注入/自愈这条路径上，而不在任何业务代码里。
- **层级竞赛**：自管浮层要选一个「比基座高、又比 Settings 低」的层号，于是有了
  2147482000 这种魔数；ADR-0128 D2 已经为命令面板定了「零 z-index + top layer」。

而基座**本来就提供了官方座位**，且 research/14 已实测可用（三种模式下均可）：

- `main` 是 **keyed** 根 slot：`renderSlot('main', {}, { entryKey })`，谁被渲染由
  `layout.activePanelId` 决定；插件卸载时 `retainMainPanels()` 自动回落到会话。
- `sidebar.panellist` 是 list slot：基座从 `entriesOfSlot` 自动派生导航行（`{id, order,
  label}`，label 支持函数并在 locale 切换时重算），行壳（标签、点击 → `selectPanel(id)`、
  `aria-current`、收起 rail 的图标尺寸）全部官方渲染，插件只画图标位。
- `selectPanel` 对未注册的 key 抛错——**判据内建**，不需要外部清单来守。

## 决策

LUTE 面一律改乘官方 slot，五条：

**D1 中心列面板挂 `main` keyed slot，侧栏行挂 `sidebar.panellist`，两者共用一个 id。**
标准配方（research/14 推出、本 ADR 冻结）：

```ts
export const PANEL_KEY = 'extensions'
ctx.slots.inject('main', () => ctx.slots.register(
  { name: 'main', key: PANEL_KEY, inject: () => ({ /* 面板 face */ }) }, Panel))
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
  { name: 'sidebar.panellist', id: PANEL_KEY, order: 40, label: () => tt('entry.label'),
    inject: () => ({ /* 图标 face */ }) }, PanelIcon))
```

`id` 必须等于 `main` 的 `key`：这是官方行点击 → `selectPanel(id)` → keyed 渲染的联动
契约，写歪了行会点不动（`selectPanel` 抛错）。

**D2 迁移后的面不得自带层叠。** 面板文件里 `z-index:` 声明数 = 0、`position: fixed` = 0、
`@keyframes` = 0、自管层号变量删除。显隐归 slot（`activePanelId === key`），层叠归基座。
判据钉的是**层号声明**而不是定位方式：`position: absolute` 仍可出现在局部装饰上
（图标角上的计数徽标、开关滑块），它不建立浮层。

**D3 「离开视图」只走官方 `layout.selectPanel(null)`。** 面板不再有「关闭」语义（它不是
浮层），只有「离开」；`onExit` 由 apply 闭包供给，`layout` 服务缺席时回退旧事件总线并
出声。**任何留在面板里的退出路径都必须改走 onExit**——本轮实测到的缺陷正是卡片「执行」
仍广播 `dsh:view-change`(chat)，而那个听者随注入形态一起退役了，结果是提示词交付了、
用户却还盯着扩展中心页面。

**D4 `sidebar-row-axis` 门禁只登记仍走 DOM 注入的行。** 迁移一个面就从 REGISTRY 摘一行，
并且**同一次提交里改它的反向自测**（fixture 树必须与 REGISTRY 同形，否则 fixture 里那个
已退役的行会被判成「未登记的注入行」，把红指向错误的地方）。等最后一个注入行退役，本
门禁的射程归零——那时它必须被改判为「panellist 行轴由官方渲染，几何天然合规」并整体
退役，而不是留着恒绿。

**D5 迁移顺序：技能中心先走，作为模式验证。** 它是唯一一个「注入行 + 自管浮层 + 事件
总线显隐」三件全占的面，也是徽标（活数字）这类自绘元素最多的面；它过了，岗位矩阵与
新应用只是重复同一配方。

**D6 自造事件总线随迁移逐条退役，交付通道只留一份实现。** 迁移暴露出三条广播的真实
听者面：`dsh:view-change` 只剩两个听者（注入行的 `data-active` 与 newapp 抽屉的开关），
`dsh:skill-execute` **全仓 + 基座零听者**——它被技能卡与命令面板两处广播，却从未被任何
代码接收（P-04「写了但从没跑到」）。处置：

- `dsh:skill-execute` 两处广播一起删（只删一半会让「这条通道存在」的说法在另一半里继续
  活着）；交付事实改由返回值承载。
- 提示词交付只有一份实现：`shared/client/prefill-draft.ts` 的 `deliverPrompt`
  （`setDraft` 优先 → 剪贴板兜底 → 两级降级都出声 → 成败如实返回）。它原本住在能力中枢
  的 dispatcher 里，技能卡成为第二个消费方即提为共享源（ADR-0128 D5 的同一把尺）。
- 任何「把提示词交给用户」的动作，交付前必须先取消 keyed 面板选中：面板是中心列视图，
  它盖着 composer——不取消选中，草稿写进了用户看不见的地方（S3.1 实测到的缺陷形状）。
- `open-panel` 的目标是否已迁移，判据与基座**同源**：`ctx.slots.entries('main')` 里有没有
  这个 key（正是 `DesktopLayoutState` 决定 `selectPanel` 该不该抛错的那条判据）。不抄
  「哪些面已迁移」的清单——那份清单每迁一个面就腐烂一次（ADR-0009）。回退到旧广播时
  **必须出声**：目标面没迁时广播可能没有听者（岗位矩阵就是），静默的死点击比报错难查。

## 备选方案

| 方案 | 为什么未采用 |
|---|---|
| 保留 DOM 注入，只把顺序/行轴问题修干净 | 修的是症状。顺序由落位竞态决定、行轴没有单一住处、自愈 observer 与 React 重渲染互相触发（P-52 的温床）——三条都是「自造承载」这个选择的固有属性，官方 slot 一次性消掉全部三条 |
| 面板挂 `shell.overlay`（像命令面板那样） | 语义不符：`shell.overlay` 是帧级 additive 座位，适合**跨会话、叠在界面上**的调度面；扩展中心是一个**取代中心列**的工作面，该由 `activePanelId` 决定它在不在，而不是由插件自己决定 |
| 继续用自造 `dsh:view-change` 总线做显隐 | 总线的听者就是注入形态本身；注入退役后它没有听者，广播即静默失败。官方已有 `selectPanel` 这一条带判据的通道（未注册 key 会抛错） |
| 把注入行改成「注入到 panellist 的 DOM 里」 | 那是把自造承载搬到官方区域内部，行壳、active 态、收起 rail、ARIA 仍要自己实现，且要钉官方 DOM 结构（ADR-0019 禁止钉哈希，而钉结构同样脆） |
| 一次性迁完三个面再验收 | 三个面同时换承载，出问题时无法归因；技能中心先走能把配方、门禁改动、验收读数三件事都跑通一遍 |

## 后果

- **正面**：
  1. 技能中心少 3 个文件（`panel-mount.tsx` / `sidebar-entry.ts` / `sidebar-entry-core.ts`
     同步副本，约 700 行）与 1 个层号魔数；侧栏行第一次有了**官方** active 态
     （`aria-current="page"`）、官方收起 rail 行为、官方 ARIA 与键盘可达性。
  2. 面板成为真正的中心列视图：实测 `elementFromPoint(600,400)` 的祖先链是
     `panelPage → centerCol → frame`，且**没有任何 fixed/高层号祖先**；退出后会话
     composer 回到完全相同的几何（x296 y389 w610 h52）。
  3. 行轴与注入顺序不再需要清单来守：官方行壳只有一种几何。`sidebar-row-axis` 的
     REGISTRY 从 3 行降到 2 行，射程读数照实写进 note。
- **负面 / 需跟进**：
  1. **中间态的侧栏是分裂的**：官方 panellist 区域渲染在注入块**之后**，所以「扩展中心」
     行现在落在「岗位矩阵」（仍是注入行，在工作台折叠组里）下方。S3.3 把岗位矩阵也迁
     进 panellist 后两行才重新同区。
  2. `dsh:view-change` / `dsh:skill-execute` 两条自造事件仍在多处广播，而
     `dsh:skill-execute` **全仓 + 基座零听者**（本轮实测）。要么接线、要么两处一起删，
     不能只删一半——留给 S4 与命令面板的执行通道一并决定。
  3. 技能卡的「执行」仍以**剪贴板**为唯一交付通道（命令面板用的是 `setDraft` 预填）。
     本轮只把它的失败从静默改成出声（`console.warn`），未统一到共享 `prefillDraft`
     （ADR-0128 D5）——那要往技能中心接 `sessions` / `conversation` 两个服务，属独立改动。
  4. `shared/client/sidebar-entry-core.ts` 与它的两份副本仍在（岗位矩阵、新应用还依赖），
     S3.2 / S3.3 迁完后才能整体退役；在那之前 P-52 的不变量（「对被观察子树的写操作，
     移动一次后不得再满足移动条件」）继续由纪律 + 门禁守着。
  5. CSS 里 `:global([data-dsh-frame][data-sidebar-collapsed])` 这半个选择器在当前 shell
     **从不命中**（帧元素带的是 CSS module 类名，不是 `data-dsh-frame`）；起作用的是
     `:global([data-sidebar-collapsed])` 那半个。双写是历史防御，实测只剩一半有射程。
- **判据射程**：本 ADR 覆盖「LUTE 面如何承载在基座界面上」。**不**为「所有面都该成为
  main 面板」背书——低频配置类入口仍留设置页；也不改变 ADR-0128 D2 对调度面的判断
  （命令面板是叠加层，该挂 `shell.overlay`）。

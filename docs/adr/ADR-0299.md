# ADR-0299 · Markdown 渲染接线：流式与最终回复共用单一渲染器

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（lute：依赖路线裁决 = 引入成熟库）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-markdown-rendering.md)
- 相关：[ADR-0298](ADR-0298.md)（D4：本行待 Markdown 裁决）、[ADR-0257](ADR-0257.md)（visual 维度纪律）

## 背景

ADR-0298 D4：`QDR.S01.session.streaming` 因缺 Markdown 渲染面不迁移。全仓（desktop 线 + app 线）回复均为纯文本 `white-space: pre-wrap`，而 Qoder 行断言为「Markdown 标题／列表逐步出现」。引入渲染库属治理级依赖新增（仓库 runtime deps 为空，devDeps 全部精确钉版）。用户裁决（2026-10-11）：引入成熟库（react-markdown + remark-gfm）。

## 决策

1. **D1 依赖**：`react-markdown@10.1.0` + `remark-gfm@4.0.1`，`--save-exact` 进 devDependencies（经 esbuild 打包进 renderer bundle；runtime deps 保持为空）。传递依赖进入 pnpm-lock，接受其供应链面。
2. **D2 单一渲染器**：`MarkdownText`（`src/product/app/markdown.tsx`）——流式气泡与 durable 回复共用；默认不渲染 raw HTML（react-markdown 语义，XSS 面收窄）；链接暂渲染为文本 affordance（受控 external-link 路径为登记后续）；GFM 表格/删除线开启。
3. **D3 契约更新**：desktop-session-view 旧「字面保留 Markdown」断言按新裁决重写——**用户输入保持字面**（pre-wrap 不变），**助手回复渲染 Markdown**；新增 raw HTML 不落 DOM 的安全断言。
4. **D4 行迁移**：`QDR.S01.session.streaming` ui `pending→implementing`（evidenceRefs 全部 `countsAsVerification:false`：session-channel / desktop-session / desktop-session-view / projection-read-routes 四 tracked spec）；blocker 诚实登记（假流验证边界、真机 SSE 取消语义、applicationService/hostIntegration/visualAcceptance 仍 pending）。summary 由生成器原函数重算（19→20 implementing、179→178 pending、verified 8 不变）。
5. **app 线（*-view.tsx / bridge 渲染图）不在本刀**：回复仍纯文本；同步渲染为登记后续（独立面、独立证据）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 自写最小 Markdown 子集 | 否决（用户裁决）：违「不重写常见功能」，长期维护差。 |
| 暂缓 Markdown | 否决（用户裁决）：行继续挂起，执行面复刻不完整。 |
| rehype-raw 渲染内嵌 HTML | 否决：扩大 XSS 面，无行断言需求。 |
| 链接直通 `<a href>` | 否决：Sage 的受控 external-link 路径是唯一外链门，本刀链接仅文本化。 |

## 后果

- 执行面（流式 + 最终回复）具备真实 Markdown 保真；`QDR.S01.session.streaming` 迁 implementing。
- 依赖面新增两个根包（精确钉版）；renderer bundle 体积增大（esbuild 报告为证）。
- visualAcceptance 仍待真机人工回看；app 线渲染同步与链接外链化登记后续。

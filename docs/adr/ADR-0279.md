# ADR-0279 · 内测 DMG 链首跑修复：构建脚本批准确认、pnpm 版本单源、运行时内建识别

- 状态：accepted（2026-10-10）
- 日期：2026-10-10
- 决策者：用户（lute：要求并行推进、尽快得到可安装的内测产物）＋ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/packaging/2026-10-10-dmg-chain-first-real-run.md)
- 相关：[ADR-0271](ADR-0271.md)（内测 DMG 链）、[ADR-0161](ADR-0161.md)（Sage 自有权威库——`node:sqlite` 的使用方）、[ADR-0040](ADR-0040.md)（脚本起子进程的解释器纪律）、[ADR-0197](ADR-0197.md)（seed peer 闭包）

## 背景

`packaging-sage/` 的 DMG-00~05 脚本与合同早已实施，但**从未真跑过一次**（`release/` 为空）。2026-10-10 首次真实执行按顺序暴露三枚潜伏缺陷 + 一个缺省前置：

1. `apps/sage-shell/pnpm-workspace.yaml` 的 `allowBuilds.esbuild` 是**未填的占位符字符串**（`set this to true or false`）——新 pnpm 的构建脚本批准门直接拒装；任何全新 clone 的安装（含 CI）都会翻车；
2. 全仓没有任何 `packageManager` 声明——producer 的隔离安装 HOME 里 corepack 回退「最新已知版本」（拉到一个布局不兼容的 pnpm），而版本事实只存在于 CI 的 `PNPM_VERSION`（四处事实，零守卫）；
3. 闭包遍历器 `runtime-graph.mjs` 的 BUILTINS 来自**构建宿主** Node 的 `builtinModules`，宿主 Node 22 没有 `sqlite`——壳源码里的 `node:sqlite`（打包运行时 Electron 43 = Node 24.18 提供）被误判为需安装的 npm 包；
4. 缺省前置：producer 离线安装用的 pnpm store 需要先 `pnpm fetch` 补齐（seed 的 601 包集在本机 store 缺失，历史安装代际漂移）。

## 决策

1. **D1 构建脚本批准确认**：`allowBuilds.esbuild: true`——esbuild 是壳的既有构建链 devDependency（`build-renderer.mjs` 依赖），其安装脚本按种子配置的既有格式（`@deepseek-ai/dsh-subprocess-local: true` 同款）显式批准。占位符不得留在任何 manifest。
2. **D2 pnpm 版本单源**：根 / `apps/sage-shell` / `apps/sage-shell/seed` 三处 manifest 钉 `"packageManager": "pnpm@11.8.0"`（= CI `PNPM_VERSION`）。corepack 在**任何 HOME**（隔离安装环境、新 clone、CI）都解析到同一版本；隔离环境不再回退「最新已知版本」。
3. **D3 版本一致性由门禁守住**：`ci-workflow` 门禁新增逐字检查——CI 的 `PNPM_VERSION` 必须等于三处 `packageManager`；缺字段或不一致具名判红（附突变自测）。四份拷贝（CI + 三 manifest）从此由一个机制守着，不靠评审。
4. **D4 运行时内建显式登记**：`runtime-graph.mjs` 的 BUILTINS 显式加入运行时（Electron/Node 24）超出宿主 Node 列表的内建（首发条目 `sqlite`），并新增纯合同回归测试 `runtime-graph-builtins-test.mjs`（fixture 断言 `node:sqlite` 永不进入 `externalPackages`）；打包测试清单 12→13、层级计数与自测同步。
5. **D5 首跑前置文档化**：离线安装所需的 store 预取（`pnpm fetch`）登记为内测打包的操作前置；probe/装配/签发/验收的后续读数以 Note 为唯一事实源，未跑的步骤照实写「未运行」。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| `allowBuilds.esbuild: false`（拒绝脚本） | 否决：esbuild 的安装脚本负责平台二进制校验；拒绝会把失败推迟到构建期，且与种子先例（批准）不一致。 |
| 只修本机环境（继续全局装 11.8.0），不改 manifest | 否决：隔离 HOME（producer/materialize/CI）各自解析版本，事故会在每个新环境重演——版本事实必须在事实源里。 |
| 只钉一处 manifest | 否决：producer 复制 `apps/sage-shell/package.json`、materialize 用 seed、CI 用 action-setup——三处各是真实入口。 |
| 遍历器改用 `process.getBuiltinModule` 探测 | 否决：探测的是**宿主**能力，而闭包要匹配的是**运行时**能力；宿主 Node 22 同样缺少 `sqlite`，探测解决不了。 |
| 不做回归测试（只靠重跑成功） | 否决：P-03——修复必须变成拦住下一次的机制；pure 测试是既有清单的自然入口。 |

## 后果

- 内测 DMG 链第一次真实通过 producer（production inputs 产出：app-runtime + profile-template，receipt 绑定、全 arm64）与装配（unsigned `Sage.app` 29892 文件）；签发与 DMG 生成待用户过 SecurityAgent 信任弹窗后继续。
- 任何全新安装环境（CI、新 clone、隔离 HOME）装上正确版本的 pnpm；版本漂移由门禁逐字拦截。
- `node:sqlite` 及未来同类运行时内建不再被误当 npm 包；新增运行时内建需编辑该显式列表（有意为之的登记点）。
- 未闭：真实的 sign/dmg/acceptance 读数（用户交互前置）、DMG-06 主链依赖。

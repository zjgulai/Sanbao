# ADR-0317 · 审批写路径落装（B 批）阶段一：声明层与 kernel 六态

- 状态：accepted（2026-10-11）
- 日期：2026-10-11
- 决策者：用户（2026-10-11 授权按推荐优先级执行）＋ agent（设计经对抗反驳折入）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-11-approval-write-path-stage-1.md)
- 相关：B 线设计 draft（本地 drafts，反驳修正已折入）、[ADR-0315](ADR-0315.md)（壳批口径）、[ADR-0283](ADR-0283.md)（首批出版物 owner 裁决先例）

## 背景

会话控制写路径（approval answer/withdraw、pending edit/remove、queue edit/remove）恒 unavailable 的**第一断点**：`ACTION_AUTHORITY_TABLE` 未注册六 operation，identity-policy 步对未注册操作一律 unavailable；后续 target/compatibility/registry/preflight/persistence 五 port 同表过滤、dispatch 硬编码只认 `session.send`。设计经逐条对抗反驳（06 处表述推翻 + 10 项补缺）后按七阶段推进；本 ADR 仅覆盖**阶段一**与全批路线。

## 决策

1. **D1 声明层六行 + effectClass 裁定**：`ACTION_AUTHORITY_TABLE` 增六行——`session.approval.answer` = external-write + **requiresDecision:true**（放行外部效应的决策本身）；`session.approval.withdraw` = external-write + false；`session.pending.edit/remove` = local-write + false（仅 Sage 自有 store，与 prepare 同类）；`session.queue.edit/remove` = external-write + false。actionScope 三个新族：`session.approval` / `session.pending` / `session.queue`。
2. **D2 kernel 六态 detail + 守卫**：`SessionCoreDispatchDetail` 增 `approval-answer-recorded` / `approval-withdraw-recorded`（携 requestId）与 `pending-edited` / `pending-removed` / `queue-edited` / `queue-removed`（携 itemId）；守卫同步扩展，畸形 detail → outcome-unknown（拒绝伪收据）。每路由应答命名的收据身份，绝不裸「ok」。
3. **D3 行为影响与边界**：本阶段后——**已登录且 policy 无对应 grant → 四路由答 `denied`**（不再 unavailable；链在 identity 步真实求值）；未登录/无 session → 仍 unavailable（fail closed）。**真实生效（allowed→实呼）需阶段二 publications 再封印 + 用户 policy grants**——v4-final DMG（171d06b7…）冻结于本阶段之前，真机走查不受影响。
4. **D4 分批路线（本 ADR 登记全批）**：阶段二 publications 三件套再封印（requirement 三条新 scope 条目 + registry 六 operations + matrix 规则自动重铸）——**新条目携带 ownerDecision=需用户裁定，禁止代拟**（C4/ADR-0165-0171 治理红线；照 ADR-0283 D4 自证等价先例）；阶段三 dispatch 解硬编码 + app-service 装配；阶段四 persistence 按操作落各自 durable 凭证（三册口径：persist 准入意图 / approvals 进程内 receipts（非 durable）/ host session log 决策证据——互不冒充）；阶段五 composition 四方法消费真实 provider（含 `pendingUpdate` 新 wiring）；阶段六 gate mode 拆分（四路由专属分支）；阶段七 UI denied/unavailable 文案分叉 + retryable 契约（route 响应体加字段 vs code 集合推导，二选一待裁）。
5. **D5 表钉子随批扩**：authorization-assembly 精确钉子扩为十行 + 六行逐条映射断言（新 action type 必须是此处有意的编辑）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 一次全落地 | 否决：publications 再封印需 owner 裁定与封印流程，非机械扩展；分批各有独立验证。 |
| 只改 composition 直连既有 main 实现 | 否决：绕过 admission 链即深化 bypass，违反红线。 |
| 沿用 attempt-started 事件做六 op 的 persist | 否决（反驳折入）：语义不同——准入意图 ≠ attempt 生命周期；三册口径独立登记。 |

## 后果

- 恒 unavailable 的第一断点已除；identity 步对六 op 真实求值（denied/allowed 两态按 grant）。
- **阶段二已于当日落地**（用户点名授权 grant 清单与 first-party 自证机制）：requirement 快照 v2（4 条目，`fa2b7cae…`）、registry v2（单条目 7 operations + 第二 approval，`6d3434c5…`）、matrix v2（4 规则同一 runtime 对，`f5d8c7ce…`）；回溯自检（基线往返/声明==派生/7 操作双准入 dry-run/装载往返）全绿。端到端生效只需用户 policy grants（走查 policy 草案不含六 op，属预期）。
- runner 内置三道自检在落地中当场抓出四处真缺陷并修复：URN 双重包装、同 scope 双 tuple（内核禁重）、快照条目须先剥 requirementDigest、**descriptor 换面后摘要与 evidence 自摘要必须重算**（否则规则配对与内核 evidence 校验双失）。
- **阶段三已于当日落地**：dispatch 解硬编码（按表七 op 分发到六个真实 handler 端口；缺 handler 的 op 恒 not-dispatched）；composition 四路由把 dispatched 收据 1:1 映射为 route 应答（错配 detail → 保守 outcome-unknown）；approval 收据随 detail 过 kernel 守卫（防伪收据）；index.ts 接 `pendingUpdate`/`queueItemUpdate` 真身。approval.answer 全链 e2e 过真身份/目标/compat/registry/preflight/persist。
- **requiresDecision 两个家已裁定**：table/grant 层管身份能力（answer 的 grant 须 decision-capable）；revision.actionPolicies 层管执行前提（answer 所在 scope 不得声明 requiresDecision:true，否则 startAttempt 要求先行事项 decision——循环死锁；answer 本身就是活决策）。
- **阶段四已于当日落地**：控制类 op 的 attempt 在 dispatch 内同步闭合（receipt → `attempt-succeeded`；确定拒绝 → `attempt-failed`；unknown → 既有 marker、attempt 保持 open fail-closed 待 per-op reconcile）。闭合经 main-owned recorder（best-effort、按 attempt 幂等）；否则 open attempt 永不闭合会锁死后续 attempt（turn-end 永不为其触发）。
- 回归门：全量 2037 passed | 1 skipped（含新 shipped-facts pin spec 4 例 + closure spec 3 例 + e2e 解锁断言）；六态 detail 正反例 + 表十行钉子入 spec。

# ADR-0241 · 外部授权等待：中继作答、封闭词表与「失效不兑现、不伪造已批准」

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-037、US-197~199 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-approval-waits.md)
- 相关：[ADR-0234](ADR-0234.md)（034 中继先例）、[ADR-0236](ADR-0236.md)（036 具名写先例）、[ADR-0198](ADR-0198.md)（host 消费登记）

## 背景

工单 041（FW-037，US-197~199）：权限申请/外部授权**以待确认态显示所请求范围与来源**；
**未获授权前不派发依赖它的动作**；等待期间**显示等待原因与撤回入口，不显示为失败，也不显示
为已批准**；**设备离线或授权过期使该等待失效并需重新申请；旧等待不自动兑现为执行条件**。
原产品证据（Sanbao S03：`PermissionCard`/`waiting-permission`/等待用户在浏览器中授权）。
基座事实（pin 包 `dsh-user-approval`）：`ctx.approval.request(req)` 走 agent 作用域
`approval/request` waterfall——**要求开着的轮次**，audit 对 `approval/asked`/`approval/decided`
写会话日志；**封闭词表** `allowed-once | rejected | cancelled | unavailable`（`allowed-once`
是唯一授权）；answerer 缺席/抛错归一 `unavailable`（fail-closed），signal 中止归一
`cancelled`，非词表返回值归一 `unavailable`；会话级 `approval/policy`（ask|never）。

## 决策

1. **D1 宿主中继=Shell 作答链（镜像 034）**：`host/approval-relay.ts` 以
   `ctx.on('approval/request', …, {prepend:true})` 认领**带 agent 的请求**（agent.id=session id），
   其余 `next()` 让位；`provide('sageApprovalRelay')`；桥 +`session/approvals`（read）/
   `session/approve`（write）/`session/approval-withdraw`（write）。
2. **D2 只有两个用户决定词 + 封闭撤回**：`answer` 仅接受 `allowed-once`（**仅此一次的授权**）
   与 `rejected`，其他值拒为 `approval-outcome-invalid`——中继**从不制造授权**；`withdraw`
   以**封闭词 `cancelled`** 结算（基座词表内，工具保持未派发），答后/撤后一律 not-found；
   asker 侧 signal 中止同样归 `cancelled`；dispose 把全部未决 waits 以 `cancelled` 收口
   （fail-closed，绝不落授权）。
3. **D3 main store 证据化收口**（`main/approvals.ts`）：读=中继活登记表（可撤回=true）；
   提交成功=`accepted`＋所选词；**桥未确认=`unknown`（只给核对，绝不为已批准）**；
   `effective` **仅在会话日志出现同 id 的 `approval/decided` 且与所选词一致时**；日志显示
   `cancelled`/`unavailable`＝`lapsed`（**失效需重新申请**）；暂停下消失=`lapsed`
   (stopped)；**lapsed 回执不回带任何可读作批准的结果**；暂停/无会话/非等待中以具名 code 拒答。
4. **D4 渲染面（S8）**：等待卡=「等待授权：<工具>｜来源：<asker 说明>｜调用：<callId>」＋
   **[批准（仅此一次）][拒绝][撤回等待]**；注记「等待≠失败，也≠已批准」；提交后
   「已提交…等待生效证据——未生效前不显示为已批准」；lapsed=「已失效…需重新申请；旧等待不会
   自动兑现为执行条件」；unknown=「结果未知：只给核对」（核对=只读重读，零 POST）；不可撤回
   时明说「请求方未提供取消能力」。
5. **D5 首版不做**：多级审批与授权策略下发（§7.1/§7.3）、修改 `approval/policy`
   （never/ask 开关）、凭据读取；真实工具审批链的真机验核后置。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 撤回改用 signal.abort | 否决：relay 只持有只读 signal，无 controller；且 `cancelled` 本就是词表内可由 answerer 返回，语义等价且可测。 |
| 提交即显示「已批准」 | 否决：US-198 明令；未确认前必须 attempt（何况 unknown 存在）。 |
| 失效等待回带原提交词 | 否决：lapsed 结果不得读作批准——回执 outcome 归 null。 |
| 不做撤回（只答批准/拒绝） | 否决：US-198 要求撤回入口；基座词表支持且一条具名写即可。 |
| 在 Sage 侧自建审批队列 | 否决：基座 audit 对+waterfall 就是事实通道；第二个家必漂。 |

## 后果

- 验收三条机器断言：①未获授权依赖动作不派发且界面为阻断态（等待卡+「依赖动作保持阻断」注记；
  中继从不产授权）；②过期/离线后旧等待失效并需重新申请（lapsed 三来源：日志 cancelled/
  unavailable、暂停下消失、无证据消失——均含「需重新申请」且不回带批准）；③撤回是具名动作且
  有回执（一条 `/.sage/session/approval-withdraw`＋accepted/unknown 三态回执）。
- 桥面 +3 端点；消费登记 +`sageApprovalRelay`；host 表 deliberate +3；端口名册 +2
  （sessionApprovalAnswer/Withdraw）；033 装配守护 +1 族。
- §1.6：真产物两宽（1440/660）亲看——等待卡（工具/来源/调用三要素+三按钮）＋lapsed 句＋
  unknown 回执+[核对（重新读取）]＋effective「已批准（仅此一次，有日志证据）」；flow 页点击
  批准后 `POSTS [{path:'/.sage/session/approval-answer', body:{matterRef:'matter:q3-review',
  requestId:'appr-1', outcome:'allowed-once'}}]`（恰一条）＋注记「批准已提交（仅此一次）——
  等待生效证据；未生效前不显示为已批准。」。
- 已知未闭：真实 `ctx.approval.request` 真机链路未跑（本机不装载 profile/不启 Host）；真实
  tool-ask 来源、`approval/policy` 读面与真机 audit 回读后置；matter 投影生产恒 null（同族
  fixture 投影边界）。

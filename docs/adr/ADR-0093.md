# ADR-0093 · preset/skill 破坏性操作使用 direct-child 证明与 journaled directory transaction

- 状态：accepted
- 日期：2026-09-16
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/contract/2026-09-16-preset-skill-journaled-transactions.md)
- 相关：ADR-0014（门禁硬门槛）、ADR-0023（preset 删除与恢复）、ADR-0052（第三方技能来源）、总账 P-23 / P-28

## 背景

`remove-preset.mjs` 曾把未经校验的 `--ids` 直接拼到 user/archive root，再用递归删除提交；
`install-fullstack-skills.mjs` 只校验来源 `name`，却用未校验的 `installAs` 组成目标，而且逐项边校验边写。
这两条路径都允许尾项失败留下半批状态；文件数与总字节数也不能发现同尺寸篡改。

## 决策

1. preset 与 skill 共用一套 final-name、canonical root、direct-child containment、symlink/hard-link、dev/ino
   与逐文件 SHA-256 契约。任何名称、来源、引用面或目标证明失败都发生在 live rename 之前。
2. live mutation 必须显式 `--apply`；默认只输出 canonical 目标、动作与 digest 的 dry-run JSON。
3. 每个 root 同时只允许一个 owner。锁是全批 payload preflight 后的第一项 control-plane 写入；锁后再次核验
   root/parent/target 身份，再 staging、fsync、写 durable intent，最后逐项执行
   `old → backup/quarantine`、`stage → target`。
4. 多目录没有伪装成单点原子提交：本实现明确采用 journaled crash consistency。任一普通失败逆序 rollback；
   硬退出保留 lock/journal/backup/quarantine，恢复工具只有在 batch/token 相等且原 PID 已不存在时，才允许显式
   `--adopt-orphan-lock` 接管。
5. preset 删除先把整批复制到 retained archive 并写 SHA-256 manifest，再把 live 目录 rename 到 quarantine；
   本层不提供 GC，也不做立即递归删除。restore 只接受结构化 manifest 且逐树 digest 相等的归档。
6. skill 更新以完整目录为 swap 单元，旧目录留在 backup，resources 与 `SKILL.md` 一起恢复。
   第三方新技能的真实 `--apply` 在 SEC-RT-002 提供 immutable approval/license/source-digest ledger 前保持拒绝。

## 备选方案

- 继续用 `ditto`/`cp` 后比文件数与字节数：不能识别同尺寸篡改，也不能回滚半批，否决。
- 先删目标再重建：故障窗口会直接丢 resources，否决。
- 宣称 generation pointer 一步切换整批：现有 DSH 消费的是多个固定 direct-child 路径，没有单一 pointer，否决。
- 自动删除“看起来过期”的锁：无法区分慢事务、PID 复用和真实崩溃，否决；改为 journal 绑定的显式接管。
- 把实现扩成通用文件事务框架：超出本卡；模块只接受同一 root 的 direct-child directory replace/remove。

## 后果

- 成功与失败都会保留可审计 workspace；容量需要由后续明确 GC/retention 策略管理，不能静默清理。
- 批次对外可见性仍可能经历“前几项目标已换、后几项未换”的短窗口；journal 保证的是最终完整 before/after
  与可恢复性，不是多目录线性化原子性。
- Node 的路径 API 没有在此提供 dirfd-relative `openat/renameat` 封装；实现通过 private canonical root、
  `O_NOFOLLOW`、dev/ino 与 rename 前复核缩小竞态，但不声称能抵御同权限恶意进程持续抢占路径。
- 本轮只在临时 root/HOME 做 mutation；真实 `~/.dsh` 只运行了第三方 installer dry-run 与审批拒绝验证。

# ADR-0236 · 已发消息的编辑与重发：版本链、同入口单身份与核对解冻

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-035、US-185~187 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-sent-message-edit-resend.md)
- 相关：[ADR-0212](ADR-0212.md)（005 会话通道与发送入口）、[ADR-0235](ADR-0235.md)（035 消息身份）、[ADR-0226](ADR-0226.md)（028 更正关联）、[ADR-0224](ADR-0224.md)（025 一次性凭据）

## 背景

工单 036（FW-035，US-185~187）：编辑已发送消息**产生新内容与版本、保留原版本及提交关系**，
不改写已消费输入或历史执行依据；**重发只针对编辑后内容走同一命令入口**，重复点击不并行
发起、原消息不重复派发；**结果未知先核对同一操作**，不自动重试、不直接放回可重发队列。
产品证据（O12 编辑重发）。基座事实：`sessionController.prompt` **按 `source.rpcId` 全量去重**
（`hasPromptRequest` 查 live inbox（nextTurn/nextStep）＋ durable `user/message` 事件）——同一
request 身份**永远不会二次派发**；`user/message` 落史带 `source:{kind:'user', rpcId}`；005 的
发送入口（`/.sage/session/send` → `session/prompt`）即"同一命令入口"。

## 决策

1. **D1 版本链与不可改写的原消息（US-185）**：`main/session-edits.ts` 的 `save` 在首次保存时
   从**通道最近一次读取的 transcript**（会话日志的 `user/message` 行，036 起带 `messageRef`）
   捕获原文并从此不可变；每次保存追加一个版本（≤16：text/savedAt/requestId/提交状态），
   `activeVersion` 指向当前版；保存只动本地版本链——**零桥调用**。渲染面把「原消息（未改写）」
   与 `v1/v2…` 版本链并排回看（历史不被改写）。
2. **D2 同入口、单版本单身份（US-186）**：`resend` 走**通道自己的 `send`**（同一条
   `session/prompt` 路径、同一路由族），携带**每版本铸造一次**的 requestId
   （`edit-<editId>-v<n>`，存于版本记录、跨点击稳定）；**原消息的 rpcId 永不出现在重发
   身份里**（原消息不重复派发）；基座按 rpcId 去重 + 本店 `inFlight` 闸（在途时
   `edit-inflight` 拒绝）⇒ 重复点击既不并行、也不可能二次派发；已接收/已生效后的重复点击
   **返回同一回执、零调用**。
3. **D3 未知只给核对（US-187）**：无 ack（bridge 失败）→ 版本 `unknown`；此状态
   **重发被拒 `edit-verify-required`**（不放回可重发队列、不自动重试），唯一入口是
   `verify`＝一次有界 `session/page` 按**该版本的 requestId** 查 `user/message.source.rpcId`：
   命中→`effective`；未命中且原为 unknown→`not-delivered`（**只有这次显式核对**之后才允许
   再次显式重发，身份不变）；未命中且原为 accepted→保持 accepted（已受理但尚未见落史，
   `edit-version-not-visible`，不猜测）。暂停态重发被拒 `edit-paused`（版本回到未提交——
   不把无身份的 deferred 记成已接收）。
4. **D4 身份随行**：005 的 `SessionChannelEntry` 增可选 `messageRef`（echo 行=echo.requestId；
   历史行=折叠的 rpcId）；`send` 增可选 `requestId`（缺省仍随机铸；格式非法拒绝
   `session-request-id-invalid`）。
5. **D5 首版不做**：历史消息删除、他人消息编辑、编辑后自动继续执行。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 重发复用原消息 rpcId | 否决：基座按 rpcId 去重会把"改后内容"当成原消息的重复而**拒收**——编辑内容永远到不了；原消息的"不重复派发"由「身份永不复用」保证。 |
| 编辑老消息体（改写历史） | 否决：US-185 明令不改写已消费输入或历史执行依据；基座也无此动词。 |
| 保存时由客户端提交原文 | 否决：原版本必须锚在日志说过的内容（通道上次读取），不是客户端声明。 |
| 未知后直接放回重发按钮 | 否决：US-187 明令；核对确认未送达后才解冻（且仍须显式点击）。 |
| 暂停态把编辑内容并入待继续 | 否决：待继续记录无 request 身份，会半留（FW-002 边界）；整条拒绝更诚实。 |

## 后果

- 验收三条机器断言：① 原版本与提交关系可回看（版本链+原文不变，多次保存后原文一致）；
  ② 重发不重复派发（同版本重复点击恰一条 send；换版本换身份；原 rpcId 从不作为重发身份）；
  ③ 未知不自动重试且不放回队列（unknown 后重发被拒，核对确认未送达后才允许显式再发）。
- 路由 `/.sage/session/edits`（save 3 键/resend 2–3 键/verify 2 键精确体）；端口名册 +3；
  033 装配守护 +1 族；005 deliberate 扩展（transcript 行带 messageRef、send 收可选 requestId、
  新增同步 `transcriptOf`）。
- §1.6：真产物两页——会话行 [编辑]、编辑器（消息 req-original-1（原消息不变））、版本链
  （原消息（未改写）/v1/v2（当前）＋状态与 [重发 v2]）；真实 Chrome DOM 读数：保存+重发恰两条
  请求（save{messageRef,text}、resend{editId,workspaceRoot}）、未知态只有 [核对同一操作]
  且重发缺席、核对后「核对确认未送达：可再次显式重发（不自动）」。
- 已知未闭：历史删除、他人消息编辑、自动继续后置；版本链为进程内记录（重开清空，沿 028 先例）；
  真机 Electron 未跑。

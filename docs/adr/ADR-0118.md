# ADR-0118 · profile 插件对官方 UI 的依赖必须成为**可被判据读取的声明**；官方 hero 标题按关系定位而非类名

- 状态：accepted（2026-09-18）
- 决策者：用户（lute）+ 2.0.10 收口轮
- 决策记录：[Note](../notes/implemented/contract/2026-09-18-plugin-ui-anchor-mirror-and-hero-title-relation.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（门禁硬门槛 + 豁免只减不增）、ADR-0019（品牌插件的运行时解析锚）、ADR-0067（已发布版本归档，不复判）、ADR-0075（射程跟着 git 走）、ADR-0080（已证伪的仪器登记簿）、ADR-0102（门禁的分母）、ADR-0116（同一形状在配置面的第一次应用）

## 背景

2.0.10 装机后，用户看到空会话 hero 里官方那句「探索未至之境」重新出现。实测取证（全部一手）：

| # | 事实 | 读数 |
| --- | --- | --- |
| 1 | 官方 hero 结构被重构，**独立文本元素消失** | 2.0.10 的 `HeroShell.module.css` 局部名：`root, stack, headline, titleGroup, previewBadge, fishHitbox, fish, body, …`——**没有 `headlineText`** |
| 2 | 标题变成一个**无类名**的 span | 产物 JSX：`div.headline > span.fishHitbox + span.titleGroup > [span(无类名), span.previewBadge]`；`headline` 已由 grid 改 flex |
| 3 | 插件的隐藏规则**根本没生成** | 活应用 `data-dsh-root-brand-anchors = "degraded:heroHeadlineText,statsLineRoot"`；生成的锚点 CSS 只剩一条对 flex 无效的 `grid-template-columns` |
| 4 | 第二个伤亡：统计条折叠 | `StatsLine.module.css` 在 2.0.10 里**整个模块不存在**（上游换成 `StatsPills.module.css`，胶囊设计） |
| 5 | 插件产物本身**不是旧的** | profile 装载点与仓库构建 sha256 相同（排除了「改了没生效」这条歧义） |
| 6 | **镜子早就存在，而且一直是红的** | 插件的 `degraded` 自报 + Console warn 一直在跑，只是没有任何判据在读它 |
| 7 | 三条能拦住它的射程全空 | 门禁零 acceptance 接线；发布 SOP §0 无实况验收；品牌探针最后一次留下产物是装机**之前**，且它在新基座上**第一步就死**（按旧结构找已退役的 `StatsLine` 模块，exit 3） |
| 8 | 插件的真实产物接缝**整段静默** | `test/official-artifacts.ts` 的路径常量钉在 2.0.5 的 asar 布局（`app.asar.unpacked/…`），2.0.10 是 no-ASAR → 5 个用例 `skipIf` 掉，`pnpm test` 依旧全绿 |

第 6/7/8 条是同一条根因的三个面：**「知道」没有变成「拦住」**（P-02 仪器假绿 / P-08 用纪律守只有机制能守住的东西）。打包层的品牌重放有 `verify-patches` 逐锚核对，**profile 插件面一条核对都没有**。

## 决策

1. **插件的上游依赖成为一份可被判据读取的声明**：包根的 `ui-anchors.json` 是**唯一家**（`id` / `moduleId` / `localName` / `purpose`）。插件源码 import 它做运行时定位，门禁读它做产物核对——两边读同一份，因此不可能出现「代码依赖了 A、门禁只量了 B」。
2. **代码词汇与声明互为子集，由机制保证**：`ANCHOR_KEYS`（编译期类型）+ 清单 id（运行时事实）在模块初始化时做**双向**断言，不一致即抛。方向不对称是故意的——「规则存在但永远解析不到」才是静默方向，必须拦住。
3. **官方标题按关系定位，不再按类名**：以唯一声明的锚（`previewBadge`）找到角标，再取**它的父容器里唯一的、有文字的叶子兄弟**作为标题，用 inline `display:none` + 标记属性隐藏（`hero-title.ts`）。
4. **找不到时不猜**：候选 0 或多于 1 → **不隐藏新的东西**，报 `degraded:<code>`；此前已正向识别并隐藏的元素**保持隐藏**（事后歧义不构成撤销识别的理由）。读数分 `ok` / `idle`（hero 未挂载，不是缺陷）/ 各 degraded 码。
5. **退役统计条折叠**：上游把模块换成了另一种设计，保留它等于永久留一个解析不到的锚。规则、锚、用例一并删除。
6. **新增门禁 `plugin-ui-anchor-drift`（阻塞）**：把「声明 × 产物」逐条核一遍，射程 = 本机 `/Applications` ∪ **未打 tag** 的 staging 树（复用 `patch-anchor-scope.mjs` 的射程决定）；其中「上游改了名字」（0 候选）与「前缀形态超出认识的字符集」（含连字符等）必须报**不同的原因**；射程为空报 skip 不报 pass；分母守恒 `expected = checked + skipped + failed`。配反向自测项 `plugin-ui-anchor-drift-selftest`。
7. **插件的真实产物接缝改为硬前置**：路径的家是 `scripts/lib/app-resources.mjs`（no-ASAR / asar 双形态），读不到就**判红**而不是 `skipIf`。另加一条断言钉住「官方词典文案 == 插件常量」，防止上游改文案后角标改写静默失效。
8. **实况探针进发布 SOP §0**：本版触及的 UI 面必须逐条跑绿（品牌面为必跑项），「没跑」与「跑了且绿」是两种读数。
9. **退役 `packaging/staging/` 的构建树**：它是装配中间态，且是 `preset-config-schema` 永久红的唯一来源。`.freeze-*` 冻结指纹（被 ADR-0073 引用）与装配日志保留。

## 备选方案与否决理由

- **只改插件的锚点重锚（把 `headlineText` 换成 `titleGroup`）**：否决。那只是把同一个「版本知识」换成新的值——上游下次改结构照样静默失手。真正的修法是把「依赖什么」变成可被机器读取并核对的东西。
- **按类名找标题（`titleGroup > span:first-child`）**：否决。它仍然钉在上游的类名与子元素顺序上；而 2.0.10 的事实恰恰是**官方把标题的类名拿掉了**，「关系」比「名字」稳。
- **加一条类名无关的结构降级（失手时隐藏 hero 行的全部文字叶子）**：否决。失手时我们不知道哪个是角标，可能把 `预览版` 一起隐藏；而那种状态已经会被门禁与实况验收挡住。宁可有第二句多出来，也不隐藏一个不该隐藏的东西。
- **让门禁调用插件自己的解析器**：否决。拿被测代码验被测代码会在两边一起错（自证式断言，本仓库已登记）。门禁按同一套 CSS-module 规则**独立实现**，真值取自产物字节。
- **把包测试接进 `pnpm run gate`**：本轮**未做**（见「后果」），因为那会改变「门禁对所有包意味着什么」，需要单独决策。
- **删除 `packaging/release/` 的历史版本目录**：**未做**。原计划的前置是「先核对仓库外归档持有同一份 DMG」，核对结果是否定的——`~/project/magpie-horch-backups/` 里只有上游基座 DMG，没有我们的发布 DMG。前置不成立就不动。

## 后果

- **门禁读数**：`plugin-ui-anchor-drift` 先红后绿，两次读数都留档——
  修复前 `[expected=8, discovered=8, checked=4, skipped=0, failed=4]`（两个产物各两条：`heroHeadlineText` / `statsLineRoot`，原因可区分）；
  修复后（staging 退役前）`[expected=2, discovered=2, checked=2, skipped=0, failed=0]`，退役后 `[expected=1, checked=1, failed=0]`（只剩装机 app 一个面）。
- **整门读数**：`ok 87/90 项通过（mode=quick，跳过 3；objects: expected=2305, checked=2144, skipped=161, failed=0）`，退出码 0。
- **插件测试**：`22 passed / 0 skipped`（修复前 `9 passed / 5 skipped`——被跳过的那 5 条正是唯一量真产物的两条支线）。
- **实况验收**：`root-brand-live-anchors.mjs` 重写后 **21/21 PASS**（真实 Chromium、本机官方 CSS、含「结构不唯一时不猜」与「卸载还原」）。
- **磁盘**：staging 构建树 5.1G → 164K。
- **已知边界**：包测试（vitest）目前只在 `pnpm --filter dsh-root-brand test` 下跑，**不在 `pnpm run gate` 与 CI 的射程内**——门禁守住的是锚的解析，行为面靠实况验收；把包测试接线是下一项独立决定。
- **未做**：没有 commit / push；没有重装 DMG。`hero.headline` 的**文案**依赖由测试（`officialLocaleValue === OFFICIAL_PREVIEW_TEXT`）守住，不进 `ui-anchors.json`（那份清单只管类名）——这是有意的边界，不是遗漏。
- **未做**：`packaging/release/` 的历史版本目录一个未删（前置核对不成立）；`~/.dsh/profiles/desktop.pre-lute-*` 与 `/Applications/*.pre-lute-*` 的清理同样待定。

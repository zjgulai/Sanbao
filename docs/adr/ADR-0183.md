# ADR-0183 · WT-02B.2B 真实 OIDC 登录链路（Logto 切片一）：全注入 adapter + 纯内存 vault + login/logout 路由

- 状态：accepted（2026-10-01）
- 日期：2026-10-01
- 决策者：用户（lute）
- 决策记录：[WT-02B.2B OIDC 登录链路收口](../notes/implemented/security/2026-10-01-wt02b2b-oidc-login-adapter.md)
- 相关：[ADR-0163](ADR-0163.md)、[ADR-0164](ADR-0164.md)、[ADR-0174](ADR-0174.md)、[ADR-0182](ADR-0182.md)

## 背景

ADR-0182 的验证纯内核就位后，Sage 仍无真实登录链路：renderer 无登录面、main 不接 IdP、token 无去处。真实 IdP（Logto）参数已探测核验：issuer `https://dk7z03.logto.app/oidc`、redirect `http://127.0.0.1:3000/callback`、scopes `openid profile offline_access`、签名算法 ES384（JWKS 唯一 key: EC P-384）、token auth method none（PKCE-only public client，client_secret 架构上不存在）。clientId 在 2026-10-01 验收期订正：原 `lck70zxqbzr62dw39ykqh` 为 Traditional Web（confidential）应用，该形态实测拒绝无 secret 的 PKCE-only token exchange（`401 invalid_client`，与桌面 public client 架构冲突）；真实归档为 **Native 应用** `cmg2ty121m1tlsd0fgiuv`（public client，bogus-code 探测回 `invalid_grant` 佐证 PKCE-only 可用）。设计 spec `docs/superpowers/specs/2026-10-01-wt02b2b-oidc-login-adapter-design.md`（切片一，用户 A/A/A 确认）定三裁决；Task 1–5（commits `d9ae5b0` / `be20c4d` / `55378cb` / `a5f95fb` / `8b322f9`，BASE `10bff66`）交付内核 ES384 扩展、纯内存 vault、全注入 adapter、auth 合同 + login/logout 路由 + renderer 登录面与 main 生产接线，本 ADR 收口其决策及其后的验收修复。

## 决策

1. **D1 完整登录链路 + 全注入 adapter（密码学真实网络假）**：`createOidcAdapter(deps)` 编排 state/nonce/PKCE 生成 → loopback 监听 → `openExternal` 唤起系统浏览器 → callback 一次性消费 → token exchange → 内核全链验证（ES384）→ vault 签入；`OidcAdapterDeps` 注入 `fetchImpl` / `openExternal` / `listen` / `randomBytes` / `now`，单测打真 ES384 密码学 + fake 网络，生产 deps（`createLoopbackTransport` 真实 `node:http` 一次性 server + `guardOpenExternalCloseListen`）由 main 组装。refresh/revocation/auto-renewal/多账户留第二票。
2. **D2 登录进 state 合同（复用 0.1/0.2 骨架，不另开 owner）**：`ServiceStatus.auth: AuthStatus` 三态（signed-in/signed-out/pending——pending 由 main 接线从 `vault.status()` 合成，测试期遗留①由此闭环），`service.reason` 在非 signed-out 时升级为 `authenticated`；`GET /.sage/login` / `POST /.sage/logout` 两条 route；login 失败沿 0.2 脱敏合同返回 `{code, stage, retryable, correlation}`（LoginErrorCode 六值，含验收修复新增的 `login-superseded`）；renderer 登录面沿既有两形守卫扩展，并以 **2s state 轮询收敛**（验收期实测 Electron 43 的 custom-protocol fetch 不响应 `AbortController.abort()`，收敛不得依赖 click fetch 的 5s 截止或 settle）。
3. **D3 纯内存 vault（token 零读取出口 + 状态机收紧）**：session 只驻 main 进程内存闭包；`snapshot()` 只吐 `{status, displayName}`，accessToken/idToken 无任何读取出口（类型面即合同）；`signOut()` 置空引用。状态机在验收修复中收紧为全函数：`beginPending()` 仅自 signed-out 进入（spec §4.1——signed-in 须先登出），`signIn()` 仅在 pending 时生效并返回是否应用——**logout（任意态）永远获胜，完成中的登录流不得复活已退出的 session**。safeStorage 落盘否决（retention 红线）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| mock 验签（只测流程编排） | 否决；tampered signature / 攻击者密钥 / nonce 不匹配 / DER 形负例必须打在真 crypto 上。 |
| safeStorage 持久化 session | 否决；违反「retention/legal hold 未确认时禁止持久化」红线（ADR-0164），重启重登可接受。 |
| 独立 login route 进程 / 独立登录窗口 | 否决（裁决 B）；复用 0.1 caller binding + 0.2 typed 响应骨架，不另开 command owner 面。 |
| 引入 jose 等验签库承载 ES384 | 否决；零新依赖纪律，node:crypto 原生 p1363 已覆盖 P-384。 |
| 内核自守输入尺寸 | 否决；沿 ADR-0182——尺寸上界是注入层合同，本票在 adapter 注入层兑现。 |

## 后果

- **全量回归**（2026-10-01，真实数字）：sage-shell 55 files / 528 tests 全 PASS（10.24s）；typecheck 0 error；仓根 gate 25/25 通过。变异验证逐条咬住：ES384 三负例、vault pending/置空、adapter discovery 尺寸上界与错误码映射、runtime one-shot/guard 兜底/disabled 复位均红（Task 3 Mut3 重放存活有据：kernel 强制 + `state-replayed` 负例，adapter 层结构不可达）。
- **ES384（方向 1）+ seam 兑现**：内核 `acceptedAlgs` 扩 `'ES384'`；`state`/`nonce`/PKCE challenge/`iss` 比较换 `timingSafeEqual`（长度前置检查）。尺寸上界（discovery ≤64KiB、JWKS ≤256KiB、token 响应 ≤64KiB、JWKS keys ≤16）在注入层 fail closed。
- **验收修复（2026-10-01 现场复现后，本 ADR 同批）**：真实 Logto 首次联调暴露两处缺陷——① **复活竞态**：login 流完成写入无条件，窗口期内的 logout 会被完成中的流覆盖（活体复现：logout 后 `authFinal=signed-in`）；② **UI 不收敛**：登录流实际约 5–10s（浏览器往返），renderer 无轮询且 Electron 43 的 custom-protocol fetch 不响应 abort，post-login 状态不落 UI（用户症状：登录后窗口无反应/退出登录无效）。修复：vault 状态机收紧（见 D3）、adapter 新增 `login-superseded`（见 D2）、main 接线合成 pending 态、renderer 2s 轮询；测试 55 files / 536 tests 全 PASS、typecheck 0、gate 25/25；变异验证四组咬住（signIn 无条件→3 红、beginPending 回退→2 红、删轮询→1 红、reason 回退→2 红）；活体彩排（CDP 驱动真实 app + 真实 Logto）：logout-during-pending 后终态保持 signed-out、pending 渲染「正在登录…」、流完成后 ≤2s 自动翻转 signed-in、退出点击 3.5s 内回 signed-out。附带事实：Electron 43 custom-protocol fetch 不受 `AbortController` 影响（5s 超时不中止请求）——收敛机制不依赖它。
- **遗留（后续票候选）**：~~① pending 期 snapshot 报 signed-out~~（已由验收修复闭环：main 从 `vault.status()` 合成 pending 进 state）；② 端口 3000 冲突与 IdP 不可达统一映射 `idp-unreachable`（不扩错误码合同）；~~③ login main 侧最长 5 分钟长阻塞~~（验收修复后在轮询收敛 + 状态机收紧下不再影响 UI；请求本体仍随流自然结束，无堆积）；④ 尺寸上界在 `response.text()` 后才查（非流式截断，HTTPS 钉 Logto 低险——content-length 预检候选）。
- **端到端验收（2026-10-01 完成）**：控制器受控彩排（CDP 驱动真实浏览器链路）后由用户复验通过——Logto 账号设置 Name 后登录，界面正确显示用户名（活体读数 `displayName` 非空、`reason=authenticated`、`auth-name` 渲染用户名）；点「退出登录」回 signed-out（登录按钮复现且重臂、退出按钮消失）。此前实测该账号 `name`/`username` 均为 null——提取逻辑 `name ?? username` 正确，displayName 按 spec 如实为空，验收要求账号设有显示名。spec §8.6 五步：登录/用户名/退出/signed-out 已由用户核过；重放拒绝由单测负例矩阵承接。ADR-0163/0164 fail closed 与 ADR-0174 unavailable-first 边界继续成立；identity handle / organization mapping / authority grant（2B 后半）不在本票范围。

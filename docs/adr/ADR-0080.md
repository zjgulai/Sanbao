# ADR-0080 · 已证伪的仪器不得再被开成判据；「在不在跑」收成一家，且「读不到」必须与「没有」分开

- 状态：accepted
- 日期：2026-09-13
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/contract/2026-09-13-dead-instrument-prescription-binding.md)
- 相关：ADR-0069（清单本身即判据）、ADR-0075（判据的射程与空射程）、ADR-0078（同一族：仪器读数为空）、
  ADR-0064（变量名被多字节吞掉——本条的实现在写完后当场被那条判据咬了一口）、
  总账 P-02（仪器假绿）、P-03（「知道」没有变成「拦住」）、P-07（一条事实多个家，只改了其中一处）

## 背景

发布前检查清单 `docs/sop/dmg-release.md` §0 里有一条：

```
- [ ] 本机无运行中的 DSH 实例（「pgrep -f "/Applications/DSH Desktop.app/Contents/MacOS/"」为空；…白屏，2026-09-13 实测）。
```

**这条判据在本机实测为空，而它量的那个进程确实在跑。** 同机同时刻的读数：

```
$ ps -Ao pid=,comm=
87357 /Applications/DSH Desktop.app/Contents/MacOS/DSH Desktop     ← 靶子在这里，读得到
$ 「pgrep -f '/Applications/DSH Desktop.app/Contents/MacOS/'」
(无输出)                                                          ← 清单里的判据：0 条，exit=1
$ 「pgrep -f 'Contents/MacOS/'」
222 条                                                            ← 不是 pgrep 坏了，是它对**这个**进程盲
```

（上面两条死仪器写成 `「…」` **不是排版**：本 ADR 落库时**被它自己提出的那条门禁当场判红过三处**
——围栏代码块是「会被人照着敲」的面，而 `「…」` 在仓库约定里是**引用**。这行说明本身就是那条
约定的用例。）

阳性对照把范围钉死了：把 `/bin/sleep` 拷贝成 `<…>/Contents/MacOS/DSH Desktop` 并启动，
**同一条模式**当场命中它的 pid（`99354`）；杀掉后为 0。所以失效不是「pgrep 不好用」，
而是**这个 Electron 主进程在 macOS 上 `pgrep -f` 看不见**。原因未查明——本条不需要解释它，
只需要不再用它（未查明的部分在下文「诚实划界」里明写）。

失效的方向是最坏的一种：清单项返回空 → 复核者得出「没有实例在跑」→ **在运行中替换 app bundle**
（宿主 HMR 热更 → 生产 renderer 无完整热替换 runtime → 整屏白屏）。**这道闸守的白屏红线，
而它等于没有守。**

更贵的是这件事的**形状**：同一条事实（`pgrep -f` 看不见那个进程）**早就写在
`packaging/scripts/first-launch-test.sh` 的注释里**（2026-09-12 实测，连「原因不明」都写了）。
它没有变成任何机制，于是同一条判据又在三个地方各写了一遍——安装器 0b 步、品牌重放脚本、
发布前清单；**修的时候只修了看得见的那一处**（安装器），清单照旧是一条死仪器（P-07）。
「知道了、写下来了」离「下次不会再犯」之间，隔着一条判据的距离（P-03）。

## 决策

1. **「在不在跑」只有一个家**：`packaging/scripts/dsh-running.sh`（随包分发到载荷 `tools/`）。
   安装器 0b 步、首启验收、品牌重放、发布前清单四处**不再各自写一遍**，一律调它。
   前两者的就地实现本次删除。

2. **退出码是契约，且「读不到」与「没有」分开**：

   | 码 | 含义 | 调用方必须怎么做 |
   | --- | --- | --- |
   | 0 | 有实例在跑 | 退出它（安装器）或拒绝动手（品牌重放） |
   | 1 | 没有实例在跑（**可判定**，含 app 未安装） | 继续 |
   | 2 | 用法错误 | 修调用 |
   | 4 | **判不了**（`ps` 读不出进程表） | **中止**——不得当成「没有在跑」 |

   4 这一档是本条的重点：把它并进 1，得到的正是前身那条判据的死法。

3. **判据读 `ps -Ao pid=,comm=`**（可执行文件**全路径**）而不是 argv。不扫 argv 有两个好处：
   精确（不命中路径里恰好含该串的别的进程）、不会被调用者自己的命令行误命中（self-match）。
   `--any` 用于「本机有没有任何一份 DSH 在跑」（首启验收要的是这个：干扰源可能是隔离目录里
   那一份），用**尾锚定**认 bundle 名。

4. **已证伪的仪器登记进机器可读的簿子，并由此产生一条门禁**：
   `scripts/gates/dead-instruments.json`（每条必须带 `provenOn` / `reading` / `why` / `useInstead`）
   + 门禁 `dead-instrument`。射程＝`git ls-files` 里的 `*.md` / `*.sh` / `*.bash`；
   **「判据面」只算三种会被照着跑的形态**：文档的清单行（含其续行）、围栏代码块里的行、
   脚本里去掉注释后仍有内容的行。命中 `「…」` 引用的不算使用（仓库约定）。
   读数常显分母（`扫 N 个文件 / M 行判据面；登记 K 种已证伪仪器`）；登记簿为空、字段不全、
   射程取不到、判据面抽出 0 行——**一律判红**，因为「一个都没比」不能长得像「都比过且干净」。

5. **SOP §0 那条检查项改为指向判据本身**，不复述命令：清单项里写命令，就会有人照着敲，
   所以它必须真的读得出东西——这条要求现在由门禁逐行核对，而不是靠评审记得。

## 备选方案

- **只改 SOP 那一行**（最小改动）。否决：安装器、首启验收、品牌重放里各还有一份同源判据，
  只修一处就是本条背景里那个 P-07 的重演——而且下一处修不修，取决于谁先看到哪一份。
- **保留就地实现，仅在注释里指向 `dsh-running.sh`**。否决：「注释里的指向」正是
  `first-launch-test.sh` 已经证明无效的那种机制（知道，但没有东西会因此停下来）。
- **让判据扫 argv（`ps -ax -o command=`）**。可行但更差：会命中调用者自己的命令行（需要
  `grep -v grep` 这类补丁，而那个补丁本身会漏），且路径里恰好含该串的别的进程会误命中。
- **把「已证伪的仪器」写成一条 prose 约定**（在总账里写「别用 pgrep 判断 app 在不在跑」）。
  否决：这正是 P-03 的形态——一张靠自觉维护的清单，三个月后就是一句谎。
- **把射程扩到全文档（含散文）**。否决：机器分不出「叙述」与「规定」，一条正确叙述
  （「`pgrep -f` 看不见这个进程」）会立刻变成假红，而**会误报的校验很快会被关掉**（P-02）。
  代价照实写在模块注释里：把死仪器写进散文里的操作步骤，本项看不见。

## 后果

- **正向**：那条白屏红线第一次有了**一个**实现和**四种**消费者；「读不到」不再能伪装成
  「没有在跑」（安装器在 `ps` 不可读时拒绝安装——宁可不装也不瞎装）；新增一种死仪器的成本
  = 往登记簿加一条（含读数与替代物），不需要改判据代码；SOP §0 的检查项从此受门禁保护。
- **正向（副作用）**：本次实现写完后**当场被本仓库已有的判据咬了一口**——门禁
  `shell-var-multibyte`（ADR-0064）报出我新写的三处 `$VAR` 紧跟全角括号（`$DSH_ST）`、
  `$DSH_RUN_TOOL（`、`$DSH_ANY）`），bash 会把多字节字节并入变量名、`set -u` 下直接中断。
  这条判据存在的原因与作用被再次证明；三处已改为 `${VAR}`。
- **负向 / 代价**：`dead-instrument` 是**模式匹配**，不理解上下文——一处「用对了」的写法
  （例如拿死仪器的输出证明它自己坏了）也会被判红，必须写成 `「…」` 引用。判据面之外的散文
  不在射程内（明写在模块注释的「本项不检查什么」一节）。
- **负向 / 代价**：`dsh-running.sh` 只在 macOS 上验过，且依赖 `ps -Ao comm=` 给未截断的全路径
  （本机实测如此）。Linux 的 `comm` 是 15 字符截断量，在那里本判据会恒判「没有在跑」——
  安装器本身有 `uname -s` 前置校验，故不为此加分支，但在脚本头部写明了。
- **后续动作**：`packaging/scripts/first-launch-test.sh` 现用 `--any`；品牌重放脚本改用同一判据
  （随 ADR-0081 一并落库——那条改动同时是「图标有两个家」的修复）。

**诚实划界（判不出的部分）**

- **`pgrep -f` 为什么对这个进程盲，没有查明。** 本条记录的是**读数**（可复现：三条命令 +
  一个阳性对照），不是**机制**。不解释它不影响决策，但也不假装知道原因（P-01）。
  `dsh-running-test.sh` 的 R7 每次都把 `pgrep -f` 的对照读数打出来：它哪天开始能看见这个
  进程，说明 macOS 变了，那时本 ADR 的读数需要重新取一次。
- **判据只回答「有没有」，不回答「是不是同一个 app」。** `--app` 只比路径，不校验签名身份与
  版本；要判「跑的是不是已装那一份」，用 `lsof` 那条归因判据（`verify-tcc-runtime.sh`）。
- **散文里的死仪器判不出**（见「备选方案」最后一条），不假装被拦住了。

# ADR-0167 · 安装后 Runtime Artifact Attestation 与 profile 激活前封存

- 状态：accepted（2026-09-28）
- 日期：2026-09-28
- 决策者：用户（lute）
- 决策记录：[Runtime Artifact Attestation 架构与交接](../notes/proposed/architecture/2026-09-28-runtime-artifact-attestation.md)
- 关联：[ADR-0165 · Sage Compatibility Authority](ADR-0165.md)、[ADR-0166 · Compatibility 双层 exact-digest](ADR-0166.md)

## 背景

Sage 已能把 seed、Host runtime 与 composed packages 复制到一次性 staging profile，并以 profile receipt 封存 copy-plan owned files；但 pnpm install 随后生成的真实 `node_modules` bytes、可执行位与 symlink topology 不在原有 receipt 的 canonical subject 内。仅凭 package version、lockfile、Host ready、插件自报 metadata 或测试 fixture，无法证明待激活 generation 实际安装了什么。

ADR-0165 要求 Electron main-owned runtime inventory 同时拥有安装后 artifact attestation 与 boot-scoped observation；ADR-0166 又把跨实例稳定的 runtime descriptor 与 generation / boot 相关的完整 evidence 分开。WT-02C.2A 因而需要先在 materialization transaction 内建立最小、可重算、默认拒绝的 C2A 安装事实，同时不能越界产生 Registry、Matrix、availability、compatibility 或 execution authority。

## 决策

1. **建立 portable `InstalledArtifactSetV1`。** canonical subject 固定包含根 `package.json` 与 `pnpm-lock.yaml` 的 SHA-256，以及 generation-relative `node_modules/**` entry。普通文件逐逻辑路径记录实际 bytes 的 SHA-256 与 executable bit；hardlink 不按 inode 合并，每个逻辑路径都重新读取并记录 bytes。目录只参与扫描稳定性验证，不进入 portable subject。
2. **只记录安全 symlink topology。** symlink entry 只保存 generation-relative link path 与原始 relative target。绝对、词法逃逸、物理逃逸、悬空、循环或扫描中变化的 symlink 均拒绝；特殊文件、缺失或非真实目录的 `node_modules` 也拒绝。
3. **精确隔离 installer metadata。** 只有 `node_modules/.modules.yaml` 与 `node_modules/.pnpm-workspace-state-v1.json` 两个精确路径不进入 portable set；其实际 bytes 另行进入 versioned `installerMetadataDigest`。禁止用 glob 排除近似名称；例如 `.modules.yaml.bak` 仍是 portable file entry。机器 store path、prune time 等 metadata 因此不会污染跨 generation 的 artifact identity，但其变化仍会使本次 attestation 失效。
4. **固定 canonicalization 与 digest。** `sage.runtime-artifact-attestation-canonical-json.v1` 先 exact-parse，再按固定字段顺序重建对象；entry 使用与 locale 无关的 code-unit 顺序，摘要为 UTF-8 canonical JSON 的 `sha256:<64-lowercase-hex>`。未知字段、错误 schema/version、重复 path、非 canonical persisted bytes 或伪造摘要默认拒绝。
5. **建立 generation-bound `RuntimeArtifactAttestationV1`。** attestation body 精确绑定 `generation`、`ownedProfileDigest`、`artifactSetDigest`、`installerMetadataDigest` 与 `producerContractVersion`，再计算 `artifactAttestationDigest`。完整 wire shape 只有八个字段：`schemaVersion`、`canonicalizationVersion`、`producerContractVersion`、`generation`、`ownedProfileDigest`、`artifactSetDigest`、`installerMetadataDigest`、`artifactAttestationDigest`；不包含时间、绝对路径、provenance、Registry、compatibility、availability 或 execution authority。
6. **在激活前创建并复验。** materialization 顺序固定为 copy / compose → snapshot owned files → install → 复核 owned files → 计算 `ownedProfileDigest` → 创建 attestation → fresh verify → 把固定文件 `runtime-artifact-attestation.json` 作为普通文件纳入 profile receipt → 写入并复验 receipt → rename generation → 原子切换 active pointer。attestation 使用 exclusive create，以 `0600` regular file 写入；它不绑定最终 receipt digest，以避免 attestation 与 receipt 自引用。
7. **扫描与验证 fail closed。** 文件读取使用 `lstat → open(O_NOFOLLOW) → bounded streaming read → fstat / path lstat`，并验证目录 entry set 与 stat 前后不变。公开 inspection 执行两次完整观察；materialization 的 create 与 fresh verify 形成两次独立观察。任何 I/O、类型、bytes、path、mode、link、metadata 或 binding 漂移均返回稳定错误 code，并在 activation 前终止。
8. **事务失败不降级。** attestation、fresh verify 或 receipt 失败时不 rename generation、不切 active pointer，并清理 disposable staging；旧 active generation 保持可读。若 generation 已 rename 后 pointer 写入失败，新 generation 保留以便恢复，旧 pointer 不被伪装成已成功切换。
9. **内容身份不是 authority。** `artifactSetDigest` 只标识 portable canonical content；`artifactAttestationDigest` 只标识一次 materialization observation。二者都不证明 producer provenance、Capability Registry allowlist / revoke、Matrix 发布与撤销、boot freshness、health、availability、semantic compatibility、Identity / Policy 或真实副作用执行权限。
10. **保持后续责任与事件边界。** WT-02C.2B boot-scoped live inventory、WT-02C.2C external capability evidence、WT-02C.2D Registry、WT-02C.3 evaluation evidence 与 WT-02D trusted composition 继续 pending。本批不修改 `BusinessMatter` v1 event schema，也不把 attestation 写成领域事件。

## 备选方案

| 方案 | 为什么未采用 |
| --- | --- |
| 只信任 `package.json`、lockfile 或 package version | 它们不证明 install 后的真实 bytes、mode、logical path 与 link topology。 |
| 把整个 profile 目录直接打包或 hash | 会把 generation path、receipt、时间与其他实例 metadata 混入 stable subject，并产生 attestation / receipt 自引用问题。 |
| 按 inode 去重 hardlink | inode 和 link layout 是机器实例事实；去重会遗漏某个逻辑路径被替换或移走。 |
| 跟随 symlink 后只 hash 最终 bytes | 会丢失 pnpm link topology，也可能允许 absolute、逃逸、悬空或循环 link 被误认为普通文件。 |
| 拒绝全部 symlink 或 hardlink | 与 pnpm 合法 virtual store / `.bin` 结构不兼容，无法验证真实 materialization。 |
| 将全部 pnpm metadata 放入 portable set | `.modules.yaml` 等可能含机器 store path 与时间，会使等价安装无法共享 stable artifact identity。 |
| 忽略 installer metadata | 会漏掉影响本次安装实例解释与复验的重要漂移；因此单独形成 `installerMetadataDigest`。 |
| attestation 直接绑定最终 receipt digest | receipt 又必须封存 attestation 文件，会形成不可解的自引用环。 |
| 由 Host、plugin 或 Matrix resolver 运行时自报安装事实 | owner 错置，且激活前无法 fail closed；C2A 必须由 Sage-owned materializer 产生。 |

## 后果

- 正面：profile 在 active pointer 切换前拥有可重算的真实安装树证据，package / lock / file bytes / path / executable / link / metadata 漂移都会阻断验证。
- 正面：portable artifact set 可跨 generation 比较，而 generation、owned profile 与 installer metadata 仍被完整 attestation 绑定。
- 正面：固定 attestation 文件被现有 receipt 当作普通 sealed file 再次封存，materialization transaction 保持单一激活门。
- 代价：安装后需要至少两次顺序扫描大型 pnpm tree；实现以 64 KiB bounded streaming hash 限制内存，但总耗时仍随文件数与 bytes 增长。
- Residual：同一 UID 的主动攻击者仍可能利用 pathname-based directory traversal 的极窄 TOCTOU 窗口；当前 `O_NOFOLLOW`、open-handle stat、directory double-check 与双观察只能缩小并检测可观察漂移，不能替代 fd-relative `openat` sandbox、独立权限边界或签名 provenance。
- Residual：attestation 只覆盖 staged profile 的 canonical inputs 与 `node_modules`。installer scripts 对网络、用户目录、系统配置、缓存或其他 profile 外位置的副作用不在 subject 内，必须由未来 sandbox / policy / provenance 控制。
- 边界：本地 Green、真实 materialize 与摘要只证明当前工作树和当前机器样本；不得把单机耗时、文件数、package 数或某次 digest 固化为产品常量、SLO 或发布结论。

# ADR-0271 · Sage 0.1.0 采用独立本机自签内测 DMG 链

- 状态：accepted（2026-10-05）
- 日期：2026-10-05
- 决策者：用户（确认 `com.lute.sage`、`0.1.0`、本机自签、仅内测）＋ Codex（出货边界与验收合同）
- 决策记录：[Note](../notes/implemented/packaging/2026-10-05-sage-internal-dmg.md)
- 相关：[ADR-0159](ADR-0159.md)、[ADR-0160](ADR-0160.md)、[ADR-0269](ADR-0269.md)、[Sanbao 集成票据 DMG-INTERNAL](../plans/2026-10-05-sanbao-in-sage-integration-tickets.md#dmg-internal)

## 背景

Sage 过去只有开发启动方式，没有自己的装配、签名、DMG 与安装后验收链；旧 `packaging/` 属于 DSH/LUTE 历史发布线，不能改名后冒充 Sage 产物。首个可安装版本只面向本机内部验证，不具备 Developer ID、公证、自动更新或外部分发授权，同时必须带上真实 production renderer/main 与 first-run bundled profile，而不是源码树、当前用户 profile、fixture 或 Pages 页面。

## 决策

1. Sage 专属链只存在于 `packaging-sage/`，与 legacy `packaging/` 零调用、零复用。唯一机器可读产品配置固定为 `Sage`、Bundle ID `com.lute.sage`、version `0.1.0`、build `1`、`arm64` 与 `internal`。
2. production input 由专属 producer 生成：从已构建 Electron main 入口求 reachable JavaScript graph，构造可离线搬移且 symlink 不越界的 dependency closure；另用 Sage 既有 `materializeProfile` 在隔离根生成 profile，再裁为 first-run consumer 唯一接受的 `template-manifest.json + profile/`。第三方 published package 默认完整保留；只有 exact package/version/path 的平台投影允许删除，当前唯一例外是 `node-pty@1.2.0-beta.15` 的已登记非 `darwin-arm64` payload，未知版本或路径漂移 fail closed。
3. 装配只接受显式 app-runtime/profile-template 输入。对 product-owned payload 拒绝 TypeScript 空 placeholder、开发源码、测试、source map 与声明文件；对全树拒绝外部绝对 symlink、错误架构 Mach-O、ELF、PE、当前用户资料根及 `profile-current.json`。输出固定为 unpacked `Contents/Resources/app`，便于逐件检查与签名。
4. bundle 身份固定为 `com.lute.sage`；helper IDs 由它派生。装配替换 Electron 外壳名称与 `Sage.icns`，移除未使用的 camera、microphone、Bluetooth 与 unrestricted ATS 声明，不引入 entitlement。
5. 内测签名只接受 exact common name `Sage Local Code Signing` 的 Sage 专用本机自签 identity，按 Mach-O / framework / helper / outer app 叶到根签名，`--timestamp=none`；hardened runtime、App Sandbox 与 notarization 均为 false。现有其他本机 identity 不得复用。专用 wrapper 为当次执行生成短期证书与私有 keychain，并要求操作者通过 macOS SecurityAgent 人工增加和移除 code-signing trust；该人工门不能被自动化完成声明替代。成功签名还必须生成并验证 `sage.local-signing-receipt.v2`，逐 plan target 证明相同 SHA-256/SHA-1/CN signer。
6. 签名与 DMG 的 mutation 路径必须显式 `--execute`，plan 只写计划；producer/assembler 由显式命令执行，覆盖既有 owned output 另需 `--replace`。DMG 固定为 UDZO `Sage-0.1.0-internal-arm64.dmg`，创建后必须 verify、只读 mount、复制安装副本、复验 seal/relocatability，并要求 staged app 与安装副本 tree digest 相同。
7. mutable output 只允许进入 ignored 的 `packaging-sage/staging/` 与 `packaging-sage/release/`；manifest 只记相对路径与摘要，不写源码、secret 或构建机绝对路径。metadata schema v4 分开保存 source input raw digest 与 assembly signing-normalized digest；HEAD 只是 source context，相关 tracked/untracked dirty 由 boolean 如实记录。dirty 产物不得声称由该 commit 单独可重建，byte provenance 以 inputs 与 packaging definition digest 为准。
8. DMG-06 必须以新 `SAGE_ROOT` 对安装副本做真实首启与同根第二进程重启：唯一产品窗、Host ready、bundled profile install/existing、设备偏好 exact GET、设置八项控件、保存后权威回读、重启持久化、1440/660/320 reflow 与零异常。只有 `sage.packaged-acceptance.v1` 的 `passed=true` evidence 与 artifact hash、截图、cleanup/detach 读数齐全才算通过；acceptance harness 或 ADR 存在本身不是验收结果。该验收不等于 T05 真实模型调用、T06 全主链闭环或 206 状态完成。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 复用旧 LUTE/DSH DMG 脚本 | 否决；产品身份、资料根、profile、运行时与验收合同不同，会把 legacy 证据跨产品升格。 |
| 直接打包整个仓库或开发 `node_modules` | 否决；会携带源码、测试、机器路径和非 reachable 依赖，无法证明 relocatable production closure。 |
| ad-hoc `codesign -` | 否决；无法证明 Sage 专用 identity，也无法阻止误用其他本机签名身份。 |
| 首个内测就启用 Developer ID / hardened runtime / notarization | 本批不采用；需要独立账号凭据、entitlements、网络公证与外部分发决策。 |
| 仅验证 DMG 可挂载 | 否决；安装副本可能在空根启动、first-run profile 或第二进程持久化上失败。 |

## 后果

- 得到一个产品身份、输入、签名与验收均独立于 legacy 的 Sage 内测通道；它只能在受控本机用于工程验证。
- 本机自签证书不是公众信任链，未公证 DMG 也不是可外发版本；后续 Developer ID、notarization、更新 feed 与公开发布必须另行决策。
- 产物成功不会改变 Sanbao 206 矩阵；每一行仍需 UI、Application Service、Host、Electron 与视觉五维证据。
- production input/profile 物化成本较高，但该成本换来显式闭包、可搬移校验与 first-run consumer 对钉。

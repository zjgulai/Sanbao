# ADR-0327 · Host 运行时失效只听实质劣化 fiber：会话首发不再打死桥

- 状态：accepted（2026-10-12）
- 日期：2026-10-12
- 决策者：用户（授权测试与观测）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-12-host-invalidation-filter.md)
- 相关：[ADR-0294](ADR-0294.md)（epoch 失效）

## 背景

v8 装机实测发送：首个实例 dispatch 后 `attempt-dispatch-unknown`；此后每个实例 select+send 后**整个桥静默死亡**（每次折叠/读都 `bridge-host-not-ready`），Host 进程却活着。装版探针链逐层定位：

- `bridge-guard`：`{kind:'unavailable', terminal:true}`，非崩溃；
- `invalidateSnapshot('invalidated')` 栈 → `handleMessage` 的 `'runtime-invalidated'` 分支（Host 主动上报）；
- Host 侧监听 = `hostCtx.on('internal/status', ...)`：cordis 对**每个 fiber 的每次状态迁移**都发此事件（PENDING→LOADING→ACTIVE 的懒激活也在内）；宿主在 ready 后 arm，任何一次迁移即判「runtime invalidated」。会话首发恰好懒加载整个 prompt 栈 → **每次首发都打死桥**（并令 dispatch 回执丢失 → outcome-unknown）。v5 前的死锁遮蔽了此面，真实发送从未跑通。

## 决策

1. **D1 只听实质劣化**：监听器改为仅当 `fiber.state ∈ {3 FAILED, 4 DISPOSED, 5 UNLOADING}` 时失效（实测迁移：boot/懒激活 0→1→2；teardown 2→5）。拆除（dispose）仍触发一次（既有生命期 spec 不改判据）。
2. **D2 单点**：只改 `src/host/index.ts` 的监听器；`onRuntimeInvalidated` → IPC → shell 的失效链不变。
3. **D3 门禁**：`sage-route-authority` 新增 `hostEntryText` 输入与 pin（过滤条件在位、无参形态不得回）+ 突变。
4. **D4 e2e 验证**：v9 装机后发送实测为验证（本批不替代）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 在 shell 侧忽略 runtime-invalidated | 否决：Host 的失效是权威事实，shell 忽略=拆证据链。 |
| 列出可容忍的插件白名单 | 否决：名单会腐烂；状态语义（劣化）才是判据。 |
| 只在 dispatch 期间豁免 | 否决：窗口期是症状不是根因；懒激活遍布会话路径。 |

## 后果

- 会话首发不再打死桥；dispatch 回执可完整返回（outcome-unknown 的诱因解除其一）。
- dispose/失败仍逐一失效（一次，幂等守卫）。
- 门禁分母不变；hostEntryText 增一输入。

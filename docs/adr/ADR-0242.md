# ADR-0242 · 模型排队三态：日志事实折叠、就绪无计时器与「超时=结果未知、不重复提交」

- 状态：accepted（2026-10-03）
- 日期：2026-10-03
- 决策者：agent（取证并实施；FW-037、US-200~202 已定方向）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-03-model-queue-verdict.md)
- 相关：[ADR-0237](ADR-0237.md)（037 错误三态与重试纪律）、[ADR-0184](ADR-0184.md)（unavailable-first 先例）、[ADR-0229](ADR-0229.md)（032 投影先例）

## 背景

工单 042（FW-037，US-200~202）：**排队中/就绪/重试三态来自服务事实并与错误三态不混用**；
**排队与重试不重复提交**；**就绪提示不由界面计时器推断；超时显示结果未知并只给核对入口**；
重试仅针对确定失败、沿用同一请求标识、不并行重复运行。原产品证据（Sanbao S05，
static-only）：`ModelQueueSegment` 对 `queued`/`retrying`/`ready` 分支、`data-model-queue-status`、
`modelQueue.estimatedWait`——**未实测**（不人为耗尽额度）。基座事实（pin 包 `dsh-llm-retry`，
durable、非 surface）：`llm/retry`＝provider 路由的重试排定（`{retryId,turn,step,provider,mode,
policyKey,retry,maxRetries?,delayMs,failure}`）；`llm/retry-started`＝**等待成功、下次尝试开始
前**的转换（`{retryId,turn,step,retry}`）。

## 决策

1. **D1 三态=同一份日志事实的折叠**（`main/model-queue.ts`，纯读，唯一桥调用=一次有界
   `session/page`）：收集窗口内 `llm/retry`（按 retryId 去重、≤8、逐字段有界）并匹配
   `llm/retry-started`；取**最后一条**重试的匹配态＋其轮次开合（turn/start…turn/end）＋
   其后是否有 `assistant/message`：
   - 未匹配＋轮次未闭＝**waiting（排队等待恢复）**；
   - 已匹配＋无消息＋轮次未闭＝**retrying（重试进行中）**；
   - 已匹配＋其后有消息＝**ready（已恢复/就绪）**；
   - 轮次已闭而未见恢复证据（两种形态）＝**unknown（结果未知，verify-only）**。
2. **D2 就绪不是界面计时器**：`delayMs` 只作**服务端安排的延迟**展示（不倒数、不推断剩余时间）；
   三态只在日志转换时翻转——ready 的服务事实= `llm/retry-started`＋其后消息。
3. **D3 超时=结果未知、只给核对**：轮次已闭且无恢复证据→verdict `unknown`＋`verifyOnly:true`
   ＋具名 reason（`model-queue-unresolved`）——**不是失败、不给重试**；核对=只读重读（零 POST）。
4. **D4 与错误三态分家**：词表独立（排队等待/重试进行中/已恢复 vs 确定失败/结果未知/未就绪）；
   文案不出现「请重试」「确定失败」；`waiting` 明说"不是失败，也不是需要重复提交"。
5. **D5 排队与重试不重复提交（结构）**：store 无写路径（不接触 send/queue/prompt 任何端点），
   重试是基座自有策略；spec 断言调用表恰 `['session/page']`。首版不做排队优先级、跨账号配额
   调度与模型自动故障切换（工单边界）；S05 原产品实测仍后置（不人为触发限流）。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 用 `estimatedWait` 倒计时呈现 | 否决：US-201 明令不用界面计时器；`delayMs` 只作服务事实展示。 |
| 把 llm/retry 的超时并入「确定失败」（错误三态） | 否决：US-200 不混用；超时=结果未知。 |
| 未知态给「重试上一轮」按钮 | 否决：重试仅针对确定失败（037 已立）；未知只给核对。 |
| 另建 Sage 队列状态机（不折叠日志） | 否决：第二个家必漂；`llm/retry`×`retry-started` 就是服务事实。 |
| 无重试时也显示空三态面板 | 否决：idle 明确成句（"当前没有进行中的模型排队或重试"），不造空状态。 |

## 后果

- 验收三条机器断言：①排队/重试期间零提交（调用表恰 `session/page`；核对零 POST）；②超时
  （轮次已闭无恢复证据）verdict=unknown＋verifyOnly，渲染面只给「核对（重新读取）」；
  ③就绪可追溯服务事实（ready 判据= `llm/retry-started`＋其后 `assistant/message`，渲染句
  自带来源标注）。
- 端口/装配：`modelQueue` 只读槽（SageServiceState＋composition 默认 unavailable＋app-service
  转发＋index 装配）；**无新桥端点、无新路由、无消费登记增量**。
- §1.6：真产物两宽（1440/660）亲看——标签＋注记「排队等待恢复（第 2/3 次，全部为服务事实）：
  服务端安排 4000 ms 后继续，原因 server_error——就绪只看日志事实，不用界面倒计时。」＋两行
  （第 N/3 次·服务端延迟 X ms｜提供方·原因｜等待中（服务端安排））；unknown flow 页
  DOM 读数 `POSTS []`（核对零 POST）＋「核对=只读，不会重复提交任何请求」。
- 已知未闭：S05 原产品真实态未采集（static-only）；真实 `llm/retry` 真机出现未跑（本机不
  装载 profile/不启 Host）；排队优先级/配额调度/自动故障切换后置。

# ADR-0171 · Sage-owned Capability Registry：不可变 allowlist 与生命周期分层

- 状态：accepted（2026-09-29）
- 日期：2026-09-29
- 决策者：用户（lute）
- 决策记录：[Capability Registry 治理记录](../notes/proposed/architecture/2026-09-29-capability-registry-governance.md)
- 相关：[ADR-0165](ADR-0165.md)、[ADR-0169](ADR-0169.md)、[ADR-0170](ADR-0170.md)

## 背景

`WT-02C.2C.1 revision 19` 已冻结 candidate descriptor 的纯解析与摘要边界，`C2C.2` 仍等待 pinned bridge 提供正式的同代 raw observation seam。运行时可见、已装配、工具注册、Host ready 或历史进程都不能把继承的 DSH entry 变成 Sage 的产品 capability；如果没有一份由 Sage 拥有的 Registry，`mounted / observed / enabled / approved / compatible / authorized / available` 很容易被压成一个含义不明的“已接入”。

本票只关闭 `WT-02C.2D.0` 的治理合同，源码、provider、真实 entry、Adapter、插件启用和产品调用均为 0。它必须能在 C2C.2 阻塞期间独立冻结，不得用 typed policy URN、fixture descriptor、package version 或 `ctx.tools` 投影冒充审批依据。

## 决策

1. **Registry 属于 Sage product/security governance。** Registry 是产品 allowlist 与安全生命周期的唯一 owner；Host、MCP bridge、插件、renderer、模型、Compatibility Resolver 和普通调用方只能提交候选或 observation，不能写入 `approved`、`authorized`、`compatible` 或 `available` 结论。
2. **Entry 必须绑定可验证 provenance。** 每个 entry 至少绑定 Sage 分配的 `capabilityId`、candidate / verified descriptor reference、descriptor stable/full digest、artifact / launch / tool-contract digest、来源与 schema version、精确 operation mapping、product/security decision reference 及有效时间。只有 typed policy URN 或自报 digest，没有 C2C verified descriptor/provider 的 entry 不能进入 `approved`。
3. **生命周期状态保持四态且不可压缩。** Registry 只使用 `candidate | approved | disabled | revoked`。`mounted`、`observed`、`enabled`、`compatible`、`authorized`、`available` 是其他事实轴，不是 Registry 状态；任何状态轴通过都不能自动抬升其他轴。
4. **状态迁移产生新的 immutable snapshot。** `candidate → approved` 需要 verified descriptor、明确 operation → Adapter mapping、product/security owner 批准和未过期的 provenance；`approved → disabled | revoked` 立即阻断新动作；`disabled → approved` 必须重新验证 evidence、mapping 和批准；`revoked` 是终态，恢复只能创建新 `capabilityId` 或新版本 entry。任何迁移都生成新的内容寻址 `snapshotId`，禁止原地修改或用可变 `latest` 别名回放。
5. **Operation mapping 是批准的必要条件。** 每个可批准 operation 必须明确 Adapter identity/version/digest、operation name、effect class、data boundary、输入/输出 contract digest、无副作用 preflight 语义及 revoke 行为。没有真实 Adapter mapping、mapping 冲突、effect 未知或 data boundary 未知时，entry 只能保持 `candidate` 或返回 fail-closed，不得铸造授权。
6. **Registry 不替代 Compatibility、Identity / Policy 或 Application Service。** Registry 只证明产品 allowlist 与生命周期；Compatibility Authority 仍独占 `equivalent`，Identity / Policy 仍独占当前授权，Application Service 仍是唯一产品编排入口。真实动作前必须重新取得 C2C/C2D/C2E、Identity / Policy、Matrix 与 operation preflight 的新鲜证据。

## 状态迁移与拒绝边界

| 迁移 / 输入 | 结论 | 必要条件 |
| --- | --- | --- |
| 新候选 | `candidate` | descriptor 可解析；provenance、mapping、owner 与证据仍可待补 |
| candidate → approved | 允许 | C2C.5 verified descriptor/provider、完整 artifact / contract provenance、精确 Adapter mapping、product/security 批准、未过期且未撤销 |
| approved → disabled | 允许 | 新 snapshot 记录 owner、原因和生效时间；立即阻断新动作 |
| approved / disabled → revoked | 允许 | 新 snapshot 记录 revoke 原因、范围、owner 和生效时间；历史 bytes 按 retention 保留 |
| disabled → approved | 受限允许 | 重新完成与首次批准同等的 evidence / mapping / approval；不能只改一个状态位 |
| revoked → 任意旧 entry | 拒绝 | 只允许创建新的 identity / descriptor version / snapshot |
| fixture、mounted、observed、工具可见、进程存在、package version、`ctx.tools` | 拒绝批准 | 这些最多是 candidate metadata 或局部 observation，不是 provenance / authority |
| duplicate、conflict、unknown schema、缺 mapping、缺 provenance、过期或 revoked | fail closed | 不产生 approved entry，也不回退到旧 snapshot |

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 以 `mounted` / `enabled` 代替 Registry approval | 否决；装配事实不等于产品 allowlist、兼容或授权。 |
| 让 C2C provider 或 Compatibility Resolver 自动批准 capability | 否决；C2C 只观察，Resolver 只判断 compatibility，二者都不拥有产品/security allowlist。 |
| 用 package version、工具数量或 `ctx.tools` hash 作为 entry identity | 否决；缺少实际 artifact closure、raw contract、同代 generation 与 provenance。 |
| 用一个可变 `latest` Registry 文件覆盖旧状态 | 否决；破坏历史回放、撤销审计与 snapshot 可追溯性。 |
| 允许 revoked entry 原地 re-enable | 否决；会把撤销边界变成不可审计的状态改写。 |
| 先落真实 Jev / DSH entry 再补合同 | 否决；C2C.5、Adapter mapping、Identity / Policy 与产品编排尚未完成，先落会制造假 authority。 |

## 后果

- 正面：能力是否“已装配”“被观察”“获准进入产品”“当前兼容”“当前授权”“当前可用”可以分别审计，UI 只能展示这些独立投影。
- 正面：每次生命周期迁移都保留新 snapshot，撤销不会抹掉历史 provenance；C2C、Compatibility、Identity / Policy 和 Application Service 的 owner 不被 Registry 越权替代。
- 代价：首次 real entry 必须等待 C2C.5 verified descriptor/provider 与真实 Adapter mapping；本批不能借 fixture 或现有 Jev 装配提前放行。
- 代价：后续 C2D.1 pure kernel 需要严格处理 duplicate、conflict、unknown version、disabled、revoked 与 snapshot digest；C2D.2 provider 只能消费经批准的 immutable input。
- 边界：本 ADR 不实现 Registry、provider、entry、Adapter、插件启用、Identity / Policy、CompatibilityEvaluationEvidence、Application Service、UI 或任何真实动作；`WT-02C.2C.2` 的 bridge seam 仍按 ADR-0170 保持 pending / blocked。

# ADR-0202 · 模型配置只读面：结构、层级与凭据状态上屏，值一律不上屏，连通性自成一格

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：用户（lute：全量授权接线 UI/UX 与后端）+ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-model-config-readout.md)
- 相关：[ADR-0198](ADR-0198.md)（只读桥与登记）、[ADR-0199](ADR-0199.md)（三态分离的同类先例）、[ADR-0164](ADR-0164.md)（凭据与真实身份数据治理）

## 背景

工单 017（US-043/044/047）要求：配置**保存成功**与**可调用**在界面上是两个字段；部分失败不显示整项完成；凭据值不出现在日志或投影里。

取证：基座 `settings/describe` 的真实返回结构是

```
{ writable, hasDocument, namespaces: [{ ns, schema, value, base?, user?, applies: 'live'|'restart',
                                        secrets: [{ path: string[], set: boolean }], revision }] }
```

它天然给了三样本轮需要的东西——层级（`user` = 用户已保存 / 只有 `value` = 出厂默认）、生效语义（`live` / `restart`）、凭据**状态**（`set` 布尔，无值）。而 `schema`/`value`/`base`/`user` 里可能带完整配置值（甚至路径），不能整体上屏。

## 决策

1. **D1 只投结构与状态**：分类器（`src/main/settings-readout.ts`）只保留 `ns / revision / applies / saved(层级) / secrets{set,total}`；**值、schema、base/user 内容、秘密的 key 路径全部丢弃**（un 秘密的 `path` 也不上屏：那是配置内部结构的指纹）。
2. **D2 形状不认识就拒**：整份 answer 不是可识别的记录、缺 `writable/hasDocument/namespaces` 之一 → `state:'unavailable'`＋`reason:'not-plain-data'`，**不做部分渲染**（部分渲染会把"读不懂"伪装成"配置就这些"）。
3. **D3 已保存与连通性分开且都由投影驱动**：投影带 `connectivityTest:'untested'`（没有跑过连通性测试这一事实本身），界面按它措辞；值不认识时显示"无法核验"，**不得**默认成"已测试"。行级用 `saved`（已保存/仅默认值/未配置）＋生效语义两枚标签。
4. **D4 部分失败不算完成**：只要有命名空间缺凭据，汇总句就说"仍有 N 个命名空间缺凭据，缺凭据的项不算配置完成"，不写"配置完成"。
5. **D5 只读且无编辑入口**：本票不含任何写路径（保存配置、写入凭据属后续票），卡片内无 `button/form/input`，脚本的 fetch 目标仍只有那三个既有常量。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 直接透出 `settings/describe` 原文 | 否决：`value/user` 可能带完整配置值与路径；且等于把全量 settings 编辑器塞进产品面。 |
| 只显示"已保存/未保存"两态 | 否决：正是本票要治的失真——保存与可调用是两件事，层级（用户/默认）也是不同事实。 |
| 现在就接保存与凭据写入 | 否决：写侧属 017 后半与 018（显式测试连接），且需要写桥与冲突核对，不能夹带。 |
| 用 `secrets` 的 path 名称做展示 | 否决：秘密的 key 路径不上屏，避免暴露配置内部结构与内部命名。 |

## 后果

- 模型配置第一次有只读面：命名空间结构、层级、生效语义、凭据设置数、以及**独立的**"未测试"字段；所有值与秘密留在主进程内。
- 只读桥（ADR-0198/050）第一次被生产消费：`main/index.ts` 通过 `host.callReadOnly('settings/describe')` 取数，失败（拒绝/不可用）走同一条分类路径成"未核验＋原因"。
- 已知未闭：保存与凭据写入（US-045/046 面）未做；连通性测试属 018。`settings/describe` 里的 `applies` 只做展示，重启语义的真实生效仍待后续票。

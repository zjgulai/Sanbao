# ADR-0203 · 桥从"只读"扩成"受控方法"：端点带类型，逐个登记，创建目录的调用永不入表

- 状态：accepted（2026-10-02）
- 日期：2026-10-02
- 决策者：用户（lute：在"扩桥"与"另起通道"之间选择 A——扩桥）+ agent（取证与实施）
- 决策记录：[Note](../notes/implemented/architecture/2026-10-02-controlled-method-bridge.md)
- 相关：[ADR-0198](ADR-0198.md)（host 侧消费与登记）、[ADR-0174](ADR-0174.md)、[ADR-0179](ADR-0179.md)

## 背景

工单 010 要的两件基座能力都不是"读"：`directoryPicker.pick` 是**交互**（可能弹系统选择器、等人），`workspaceRegistry.create` 是**写**（在本机工作区登记里落一条）。而 050/ADR-0198 给桥的定义写死为"只读"：端点集合叫 `READONLY_BRIDGE_ENDPOINTS`、结果必须过纯数据判定、ADR-0198 D4 明写"不开任何写侧 RPC"。

两条路：扩桥（把"只读桥"改成"受控方法桥"），或另起一条通道。用户选扩桥。

## 决策

1. **D1 端点表带类型**：`protocol.ts` 的 `READONLY_BRIDGE_ENDPOINTS: Set` 改为 `BRIDGE_ENDPOINTS: Readonly<Record<string, 'read'|'interactive'|'write'>>`，三个端点各自声明类型；`settings/describe`＝read、`directory/pick`＝interactive、`workspace/create`＝write。**写端点必须显式命名，不得从动词推断**。
2. **D2 守卫一条不删**：端点必须在表中（两端各自判一次）、调用前判宿主活跃世代与连接、结果仍必须过纯数据判定、拒绝仍用既有机器码。新增两类拒绝：`bridge-payload-invalid`（参数个数/形状不对）、`bridge-path-invalid`（路径不是可采纳的绝对路径）。
3. **D3 采纳只认已存在目录**：路径必须是绝对、非空、无 `\u0000`、≤4096 字符；**桥面永不包含 `directoryPicker/createDirectory`**——首版不新建目录，且该缺失由断言钉住，防止"顺手"加回来。
4. **D4 取消是事实不是失败**：`pick()` 返回 `null` 即用户取消，桥回 `{ok:true, result:{path:null}}`；消费侧据此不落任何记录。宿主不可用/供应商缺席仍是拒绝。
5. **D5 消费登记随行**：`sage-service-consumption.json` 的条目随文件改名同步为 `apps/sage-shell/src/host/bridge-endpoints.ts → [settingsController, workspaceRegistry, directoryPicker]`；`host/readonly-bridge.ts` 文件与旧的 `callReadOnly` 方法名一并退场（名字要跟事实一致，不留"只读"的旧名）。
6. **D6 桥不做授权判断**：桥只负责"这个端点存在、参数合法、供应商在、结果能过界"；某个动作是否被允许，仍由 Application Service 与 Authority 决定。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 保住只读桥，另起一条 pick/create 通道 | 否决（用户选 A）：两条通道两套守卫、两处登记，是"一条事实两个家"的温床。 |
| 把 workspace/create 伪装成"读"塞进只读桥 | 否决：改名不改行为，等于骗守卫与读者。 |
| 端点类型省略，只留一个集合 | 否决：交互端点会阻塞在人身上、写端点会改本机状态，两者与读的行为差异必须写在契约里。 |
| 顺手把 createDirectory 也加进表 | 否决：工单 010 明确首版只采纳已有目录。 |

## 后果

- 桥的守卫形态不变（白名单＋活跃世代＋纯数据＋拒绝码），但表面变大且**每个端点的性质可见**；050 的判据因改名需重跑（spec 的端点钉子已改为三条目精确钉）。
- `workspace/create` 的幂等与"取消无副作用"由基座的工作区登记保证，Sage 侧只做参数与结果把关；重复采纳同一目录是否会新增工作区，由后续票在真实宿主上核验（本票只保证桥不制造重复）。
- 消费半边同批落地：`POST /.sage/workspace/adopt` 走"先 pick、仅在拿到路径后才 create"的固定顺序（取消时第二次调用不发生），结果投影为 `adopted／cancelled／refused` 三态，`ServiceProviders` 因此从 4 个端口变 5 个（端口钉子同步收紧为五条目）。
- 已知边界：桥现在能触达写端点，因此**端点表的每次扩项都是一次需要评审的动作**——新增 write 端点应附明确用途与拒绝路径，不能只改一行。

# 深度开发前置盘点与增强执行方案

## 0. 目标、边界与完成定义

**目标**：把当前仓库从「可继续开发、但发布事实、交接状态与生产恢复边界混杂」收敛为一个可安全进入深度开发的基线。此计划只安排可证明的前置工作；不以历史绿灯、旧截图或 handoff 路线图代替当前验收。

**本轮不做**：

- 不删除 `packaging/release/`、`.archive/`、仓库外归档或未知来源的未跟踪项；历史制品保留规则仍由 [ADR-0067](../adr/ADR-0067.md) 管辖。
- 不声明 `2.5.0` 已正式发布或未发布；其正式状态要由 tag、发布资产、校验和和分发渠道共同核实。
- 不改生产 profile、锁文件、MCP 挂载、安装状态或运行中的 DSH；DA-25 仅能在用户指定的隔离环境继续。
- 不把 `apps/lute-shell` 当作现有 DSH Desktop 的可发布替代品；它仍受 [ADR-0139](../adr/ADR-0139.md) 的未完成项约束。
- 不改 `vendor/dsh-desktop`、`deepseek-harness` 或 pin。

**完成定义**：后续选定一条价值流前，必须同时具备：发布状态账本、未跟踪项处置账本、交接入口、隔离验证边界、首批防误判门禁，以及一份明确选择的产品主线。各项的唯一执行状态见 [执行 Todo](2026-09-23-deep-development-execution-todo.md)。

## 1. 已确认的起点与权威来源

| 事实面 | 权威来源 | 本计划的处理方式 |
| --- | --- | --- |
| 生产恢复仍未结案 | [DA-25 handoff](../../.scratch/review/2026-09-22-arch-health-top20/HANDOFF-CODEX.md) | 视为活动安全边界；只读/隔离验证与功能开发分开。 |
| 角色预设 handoff 的基线已落后 | [Role presets handoff](../../.scratch/role-presets-handoff/handoff.md) 与当前生成器 | 先重做当前 50 AGT + 3 MGT 的 H0 基线，不沿用旧 `50/5106` 结论。 |
| 历史发布物是回滚证据 | [ADR-0067](../adr/ADR-0067.md)、[DMG SOP](../sop/dmg-release.md) | 删除前提不是磁盘体积，而是新的留存决策、逐字节外部副本和回滚演练。 |
| 清理读数有结构性盲区 | [`cleanup-inventory.mjs`](../../scripts/lib/cleanup-inventory.mjs) | 第一项代码修复：递归识别归档子目录中的发布清单，并用回归测试锁住。 |
| 产品双壳尚未收敛 | [ADR-0139](../adr/ADR-0139.md) | 每个后续任务必须标注目标宿主：既有 DSH、Lute Shell 或仅文档/工具。 |

当前主分支存在用户既有的未跟踪交付。它们不属于本计划的自动清理范围；只有来源、owner、恢复路径和替代证据齐全后，才可进入单独的处置批次。

## 2. 执行原则

1. **先防误判，再做清理。** 清理工具、发布账本和回滚链先于任何删除动作。
2. **先隔离生产，再做实机验证。** DA-25 的恢复证据与新功能验收不得互相借用。
3. **先重放当前事实，再消费 handoff。** handoff 是线索，不是当前完成状态；过期基线需重做只读 H0。
4. **一份事实一个家。** 本文只定义顺序与出口；决策在 ADR，执行状态在 Todo，产品/发布事实留在既有权威文件。
5. **计划与实际分开记录。** 每个代码批次先展示 Birdview 文件级范围；完成后再记录真实命令、退出码与未验证项。

## 3. 分阶段方案

### 阶段 A：建立安全基线（当前批）

| 项目 | 动作 | 输出 | 出口判据 |
| --- | --- | --- | --- |
| A1 | 固化前置决策 | ADR-0157 与对应 Note | 新 ADR 有机器可读决策、ADR 索引与派生账本一致。 |
| A2 | 固化执行面 | 本计划与执行 Todo | 每项有 owner/授权边界、验证命令和状态；未决项不可伪装为完成。 |
| A3 | 可视化首批变更 | Birdview `planned` 活动 | 展示影响模块、文件、行为、不变量和验证，再获得明确实施确认。 |

### 阶段 B：修复清场判据的 P0 盲区（首个代码批）

**问题**：现有 `scanReleaseManifests()` 只读取候选目录的顶层文件；`packaging/release/.archive/` 的发布清单位于版本子目录，因此可能被错误列入建议清单。

**最小改动**：

- 让清单扫描递归返回相对路径；只遍历真实目录，不跟随符号链接。
- 增加嵌套 `SHA256SUMS` 的回归夹具；根层行为与普通无承诺候选保持不变。
- 用真实 `.archive/` 运行只读清单，证明其结果为 `protected`；不修改任何 DMG、清单、锁位或归档路径。

**验证**：`node --test scripts/lib/cleanup-inventory.test.mjs`、`node scripts/cleanup-inventory.mjs packaging/release/.archive --json`、`git diff --check`，以及 ADR/Note 对应校验。全仓 `pnpm run gate` 只在本批文件稳定、无并发写入时作为收口检查执行。

### 阶段 C：发布事实收敛（只读核验，需产品决定）

1. 建立每个版本的 source commit、tag、GitHub Release、DMG 校验和、`latest` 指针、仓库外副本和品牌名的核验表。
2. 先由用户确认 `2.5.0` 是正式发布还是内部制品；若正式发布，按既有 SOP 补齐发布链，而不是重打同号；若内部制品，明确标记和保存方式，而不是隐式删除。
3. 若要修改历史制品留存期、归档位置或删除策略，必须以新的独立 ADR 明确覆盖/修订 ADR-0067，并先证明外部可恢复副本与回滚演练。

### 阶段 D：未跟踪交付与 handoff 收口（只读分类后再处理）

1. 建一张**交接/未跟踪项注册表**：对象、来源、owner、目标宿主、状态、保留期限、恢复路径、下一步和授权边界。
2. 将 DA-25 标为生产恢复 lane；将 Role Presets 标为“待当前 H0 rebase”的路线图；其余产品/设计草稿不得借这两份 handoff 的完成状态。
3. 未知项默认 `retain-pending-classification`；只有被当前提交替代、可复现、无引用且 owner 确认的项，才可提出归档或删除申请。

### 阶段 E：隔离验证与产品选择（需要用户授权）

1. 用户指定一个可丢弃的非生产 profile/应用目录或其他隔离验证主体。
2. DA-25 单独定义恢复验证、稳定性观察和回滚演练；不能把本机状态或历史日志算作通过。
3. 在发布、双壳、生产恢复、角色预设四条 lane 中选择**一条**主线进入深开发。每张任务卡都要写明目标宿主、数据/权限边界、回退方式和验收场景。

### 阶段 F：第二批机制与产品事实增强（在阶段 C–E 后排期）

| 优先级 | 事项 | 前置 | 完成判据 |
| --- | --- | --- | --- |
| P1 | 修复 `service-consumption` 同行多调用漏检 | 阶段 B 绿 | 新回归测试同时识别两个 `ctx.get()` 调用，原射程可解释。 |
| P1 | 定义 AgentTeam `systemPrompt` 是可选还是必需 | 目标宿主确认 | 缺失/存在两种 host 用例与注入契约一致。 |
| P1 | 从受管包发现结果校验 README/架构地图 | 发布与品牌口径确认 | 包数、安装路径、分发说明和目标壳不再相互矛盾。 |
| P1 | Lute Shell 的发布门 | 产品主线选中 Lute Shell | profile 隔离、目录选择、agent-preset 注入和可重复 smoke 都有证据。 |

## 4. 必须由用户作出的决定

| 决定 | 可选结论 | 不作决定时的默认安全行为 |
| --- | --- | --- |
| `2.5.0` 定位 | 正式发布 / 内部制品 / 需进一步取证 | 保留制品，不打 tag、不改 `latest`、不删除。 |
| 历史发布物留存 | 延续 ADR-0067 / 新留存期与归档家 / 删除方案 | 延续 ADR-0067，删除清单为空。 |
| 深开发主线 | 既有 DSH、Lute Shell、Role Presets、Sanbao UX 或其他明确价值流 | 不并行切换多条主线。 |
| DA-25 验证环境 | 具体的隔离环境及可执行权限 | 不触碰生产 profile、安装或重启行为。 |

## 5. 风险、回退与报告口径

- 清场工具本身只生成读数；即使它报告 `suggested`，也不是删除授权。
- 本批若代码测试失败，回退只限本批脚本/测试改动；发布物和运行时目录不在回退射程。
- 报告必须区分 `当前实跑`、`历史证据`、`未运行`、`环境受限`；没有运行的门禁不得用“预计通过”替代。
- 每次变更结束前记录：实际文件、实际命令与退出码、未验证项、下一项需要的用户决定。

# 规格 · 全站三主题与统一排版（Qoder CN 风）

- 状态：方向已确认，实施与全站验收未完成
- 日期：2026-09-20
- 决策者：用户（lute）
- 相关：ADR-0132（配色由 ADR-0144 取代；双色道与排印签名按本规格更新）、ADR-0008 / ADR-0019（基座只读、禁钉哈希）、ADR-0125 D7/D8（侧栏宽度契约）、ADR-0140/0141（右侧栏）
- 触发：用户原话「我很讨厌这种蓝色，我就喜欢的是 Qcode CN 的布局 和配色，以及页面设计，你能帮我做出来吗？所有」；后续明确「亮色、暗色、暖粉白」三选一，并要求所有页面字体、标题、字号及新对话品牌区统一打磨。

## 0. 已确认的扩展范围

本节与 [ADR-0145](../adr/ADR-0145.md) 取代下文旧分期中“双主题、只动主题包、预设墙另做”的限制。实现按独立验收切片推进，最终交付分母仍是全部页面与子页面，不以主页通过冒充全站通过。亮色不套用暗色压暗公式；参考色和可读文字色分工，旧强调色对比不足不通过反复采样或降低阈值解决。

### 0.1 三个第一类主题通道

- 产品身份固定为 `light | dark | warm-pink`，显示名为「亮色 / 暗色 / 暖粉白」。暖粉白不是亮色预设，不复用亮色身份保存。
- 浏览器/官方双态适配仅将 `dark` 映射为暗，其余两个映射为亮；CSS `color-scheme` 仍只有平台支持的 `light / dark`。身份、配色、显示名不得从该布尔值反推。
- 三通道消费同一套语义键：画布、左右栏、面板、控件、浮层、正文、次级、边框、强调及其前景、交互与状态、代码。暖粉白单独拥有完整值，不在各页面复制粉色 CSS。
- 主题身份通过现有 Host settings 保存与广播；客户端缓存只负责首屏，不形成另一个可写权威。切换、重开页面及恢复均保留身份，不让 Host 的亮态回灌抹掉暖粉白。
- 字体、字号、代码字体及减弱动态独立于配色；切换或重置主题不能重置这些偏好。旧配色不再成为渲染输入，旧设置迁移保留有效非颜色偏好，不清空无关存储。
- 全站面清单与运行环境分类使用[原计划的页面覆盖表](../plans/2026-09-20-qoder-visual-language.md#页面覆盖表注册与产物证据尚未逐页视觉验收)。独立 HTML、自有 iframe、原生窗口逐项接入；用户文档和第三方网页内容不重染。

### 0.2 统一排版标准

目标是让用户先看到当前任务与主标题，再顺畅阅读正文和执行操作。导航保持紧凑，阅读面留足行间距；不是把所有文字改成同一个字号，也不是把官网海报字号搬进工具界面。

借鉴依据为 [GitHub Primer](https://primer.style/product/primitives/typography)、[Atlassian](https://atlassian.design/foundations/typography/) 与 [IBM Carbon](https://carbondesignsystem.com/elements/typography/type-sets/) 的“控件排版与阅读排版分开”机制；下表是本产品的设计值，不是对 Qoder 字号的实测声明。正常密度与 100% 字号时：

| 语义 | 字号 / 行高 | 字重 | 使用范围 |
| --- | --- | --- | --- |
| 品牌标题 | 36 / 44px，窄屏 28 / 36px | 600 | 新对话品牌句，不套到导航和列表 |
| 页面标题 | 28 / 36px | 600 | 新应用、岗位矩阵、设置内容页等主标题 |
| 区块标题 | 20 / 28px | 600 | 页面内主要分区、对话正文二级标题 |
| 面板标题 | 16 / 24px | 600 | 右栏、弹窗小节、卡片名称 |
| 阅读正文 | 16 / 28px | 400 | 会话回答、报告、Markdown、长说明 |
| 界面正文 | 14 / 22px | 400 | 设置说明、列表说明、表单帮助与错误 |
| 操作文字 | 14 / 20px | 400；选中 500 | 导航、按钮、标签页、表单值 |
| 辅助信息 | 13 / 18px | 400 | 时间、计数、简短状态；不可承载关键说明 |
| 代码正文 | 14 / 22px | 400 | 代码块、技术详情；使用独立等宽字体 |

字体沿用已内置的 Inter 与用户选择；中文通过系统无衬线字体回退，不下载新字体。中文正文与操作文字字距为正常；标题不使用原官网 `-.055em / -.045em` 的紧缩签名。可复用角色依字号设置等比缩放；使用 `font` 语义 token，避免单独 `font-size` 被后写 shorthand 覆盖。尺寸相邻的角色允许同号，通过字重、位置与留白区分，不机械要求每级 1.25 倍。

间距采用 4px 基准：标题与说明 8px、说明与操作/正文 16px、同区块内容 12–16px、主区块间 24–32px；中文段落行宽目标 36–44 个全角字，短窄侧栏自动回流，不强制撑到该宽度。长 URL/标识可断行，代码和表格仅在自身容器滚动。

新对话品牌图形目标 56px、窄屏 48px，保留现有标识与文案；品牌句与副标题形成明显主次，与输入框至少 24px 间距。短视口与放大字号时允许整体纵向滚动，不靠隐藏品牌或压小文字把输入框塞回首屏。

### 0.3 排版验收

- 三主题的字号、行高与布局角色相同，切主题不改变字号偏好；用真实浏览器计算样式验证，不只断言 CSS 字符串存在。
- 覆盖主导航、新对话品牌/输入、会话与代码、设置和子页、岗位/新应用/能力中枢、右栏及文档、独立管理页与自有窗口；每项明确来源与是否实际运行。
- 桌面、窄视口、长中文/英文、空态/错误态及 200% 文字缩放可读且操作可达；无文字裁切、互盖、标题挤成单字列。真实应用不可访问的 case 标记 blocked，不计 pass。
- 按 [WCAG Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) 与 [Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) 验证 200% 缩放和用户行高/字距覆盖，不把覆盖测试值误作默认设计值。
- 不用全局 `*` 字号强推，不破坏第三方文档、代码编辑器与图标字体。既有 264px 导航水平轴和设置页恰好覆盖主页面的契约继续有效。

以下保留 Qoder 取色依据与原分期记录；涉及范围的冲突以本节为准。

## 1. 问题

当前界面是**两套色系并存**：

- 主区/左栏走 Sanbao 契约（深海军蓝 `#0b1521` 底、`#142332` 面板、钛银 `#C4D0DC` 强调）；
- 右栏「工作台」是 Qoder 抄来的中性灰（`#202228 → #16181c`，CSS 硬编码，不跟主题走）。

两套立面模型彼此相反（我们「画布最暗、越抬越亮」；Qoder「画布最亮、越抬越暗」），并置即脏。用户对蓝色的评价是「很讨厌」，并明确要 Qoder CN 的配色与布局。

## 2. 证据（全部为实机实测，非印象）

### 2.1 Qoder CN 暗色道实测值

方法：`macos-harness see` 截其窗口 → 逐点采样 + 横向扫描定位列边界。

| 区域 | 实测值 | 说明 |
| --- | --- | --- |
| 左栏 rail | `#242624` | 暖中性灰 |
| 画布 | `#232523` | 与 rail 几乎同色 |
| 右栏面板 / 顶栏 | `#191B1A` | **比画布更暗** |
| 卡片 / 浮层 | `#131413` | 越抬越暗 |
| 强调色 | `#5C9363`（按钮）/ `#609966`（选中 chip） | 灰绿 |
| 列边界 | `#171918` / `#191B1A` | 低对比分界 |

### 2.2 Qoder CN 布局度量（同一次扫描）

| 量 | 实测 | 我们现在 |
| --- | --- | --- |
| 左栏宽 | ≈278px（1389px 窗口） | 264px（基座夹逼 [264,420]，门禁钉 TARGET=264） |
| 画布宽 | ≈755px | 自适应 |
| 右栏宽 | ≈330px | 440px |
| 导航行距 | ≈32px | 36px |

### 2.3 约束包络（先查过再承诺）

- `scripts/gates/sidebar-row-axis.mjs` 只钉**水平轴**（`box-sizing:border-box` / `width:100%` / `marginInline:0` / `paddingInline:10px`）与 **TARGET_SIDEBAR_WIDTH=264 ⊂ [264,420]**；**行高、圆角、颜色、字体不在门禁内**。
- 官方壳（对话流内部布局、聊天卡片结构）是 pin 的只读参照，**不改**（ADR-0008）；官方 UI 改写锚**禁钉哈希**（ADR-0019）。

## 3. 决策

- **D1 配色整套照搬 Qoder CN，品牌契约改判。** 暗色道采用 §2.1 实测值；「钛银 + 深海军蓝」退役，绿（`#5C9363` 一族）重新登记为品牌强调色。**本规格落地时同片写一篇 ADR 取代 ADR-0132 的配色部分**（ADR-0132 的其余部分——命名空间 `--sanbao-*`、双轨 token、材质解禁——不受影响）。
- **D2 立面模型反转为 Qoder 式。** 画布为最亮层，面板/卡片/浮层逐级变暗；派生式方向反过来（现在 `bg-layer-*` 越抬越亮）。
- **D3 密度一次收到 Qoder 档。** 行高 36→32px；右栏宽 440→360px；圆角与边框按 Qoder 的克制风收（低对比 1px 边框、去彩色辉光）。
- **D4 左栏宽度维持 264px 不动。** Qoder 的 278px 落在基座夹逼区间内，但改动要同步改门禁 TARGET 与 ADR-0125 D7/D8 的登记；本轮不做，避免把「换色」与「改契约」混在一条变更里。若用户后续想要 278px，单独开一条。
- **D5 明色道照抄其真值，不推导。** 待用户在 Qoder CN 切到明色道后采样（见 §6）。
- **D6 官方壳只换 token，不改结构。** 全部换色经 `dsh-theme-local` 的 token 派生；自有面（左栏注入行、设置壳、抽屉、各面板）另外按 Qoder 密度收排版。
- **D7 并发边界。** 右侧栏包 `packages/surfaces/dsh-right-sidebar-local/**` 归另一会话；本规格的 P0/P1 只动 `dsh-theme-local`，不与其冲突。边界消息已发出，待回执。

| 期 | 范围 | 落点 | 验收 |
| --- | --- | --- | --- |

## 5. 不做什么（YAGNI）

- 不动 vendor 与官方壳结构（D6）。
- 不为「像 Qoder」引入新的组件库或布局框架。
- 不改 264px 侧栏宽（D4）。
- 不在本轮做预设墙收敛（那是既有工单 014 的范围）。

## 6. 未决

1. **明色道真值**：等用户把 Qoder CN 切到明色道并告知；采样后回填 P0。
2. **另一会话回执**：右栏分界与收口时间（P2 依赖它）。
3. **Qoder 的 `#5C9363` 是截屏采样值**（可能受色彩配置影响）。P0 落地前用第二个来源交叉核对一次（例如其按钮的 CSS 计算值或更精确的截图区域），偏差 >2 阶则取更可靠者并记录来源。

## 7. 风险

- **立面反转（P1）影响面最大**：所有消费 `bg-layer-*` 的面都会变，可能出现「深色卡片叠深色画布」的对比不足。缓解：P1 单独一期 + 实机逐屏看 + 对比度脚本兜底。
- **右栏 440→360** 会压缩其内容（7 个模块面板）；缓解：P2 与右栏 owner 会话一起定，必要时只收 token 不收宽度。
- **两套色系并存的窗口期**：P0 落地后右栏仍是硬编码灰，直到另一会话改指 token；缓解：先只做 P0（全局变色），右栏交给它，不并行改同一文件。

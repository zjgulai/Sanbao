五条最重要的结论

① 系统形态已定型：双基座 + 五组包 + 薄壳 + 一条门禁

pin 已到 upstream v2.0.10 / runtime 0.1.5-rc.2（vendor/dsh-desktop.pin，checked-at 2026-09-17），LUTE 2.5.0 已发布（packaging/release/2.5.0/VERSION，SOURCE_DIRTY=0）。28 个包按 capabilities / contract / infra / platform / surfaces 五组归位；apps/lute-shell 是脱离 fork 的自有 Electron 薄壳。

② 治理平面是本仓库最强的部分——且当前干净

scripts/gates/exemptions.json = []（零豁免=存量全部达标）；28 个包全部有 typecheck + test 脚本；门禁 0 失败；dead-instruments 登记簿在执行（3 类已证伪仪器被拦）。这套「判据化 + 反向自测」的纪律是本仓区别于一般二开仓库的根本。

③ 结构热点首次被量化：三包独大 + 巨型入口

dsh-deepresearch-local（81 文件 / 281 函数）、dsh-overseas-skills（79 / 159）、dsh-agent-team-gui-local（60 / 124）构成前三大包。源码热点：src/investigation.ts（32 函数）、src/client/ResearchView.tsx（39 函数）与纯 JS 包 dsh-wanzh-hulian/lib/index.js（31 函数，源即产物）。

④ 测试「存在性」满分，「纵深」靠自觉

图谱只连出 85 条 tested_by 边：dsh-browser-local（52 文件）、dsh-paper2skills（49）、dsh-algo-skills-local（41）生产节点零覆盖边；changed-packages 门禁只管「包有没有 test 脚本」，管不到「你这次改的函数有没有被测」。纵深缺口需要显式计划。

⑤ 两处已核实的「文档-真身漂移」（P-14 形态的现场实例）

A · 加功能（新插件 / 新能力）

产出物：一个新包 + 门禁全绿 + profile 可装载
  1. 选组落位：capabilities（能力）/ surfaces（界面）/ platform（宿主扩展）/ contract（契约）/ infra。目录必须是 packages/<组>/<包名>/（package-layout 只认这一种布局）。
  2. 身份三字段：luteOrigin（self/internalized/npm-pinned）/ luteOwner / lutePublish —— 缺任一项 package-identity 判红。
  3. 发布契约：files 清单必须覆盖「入口可达闭包」的所有运行时文件（package-files-coverage 与真实 npm pack 逐文件校准）；宿主插件走 dsh.bundle.patch → cordis.patch.yml；界面插件声明 dsh.client.platform/inject（inject 里解析不到的包名会静默跳过——本仓用 validate-build 双向断言拦住）。
  4. 脚本三件套：typecheck + test + build（changed-packages 门禁要求改动的包必须有前两者，缺失即阻塞）。
  5. 挂载路径二选一：本机装配走 profile cordis.patch.yml 的 file: 显式挂载（ADR-0061）；出货则必须同时过 shipped-presets 白名单（外部产品永不进出货 preset，ADR-0056）。
  6. 生效链走完：build → node scripts/sync-profile.mjs --apply --loadpoint → 重启应用 → 读实况（AX 几何/截图），不要用「刷新页面」当验收。

B · 改架构（跨包结构 / 基座交互）

产出物：ADR 决策 + Note 理由 + 兼容迁移
  1. 先定位事实之家：同一结论只写一处。改前 grep -rn 它的全部出现位置；复制一条事实时同步问「它的清单在哪」（P-07）。
  2. pin 纪律：vendor/dsh-desktop.pin 的 bump 与行为变更分开提交；pin-consistency 校验子模块 HEAD。
  3. 官方 UI 改写锚禁止钉哈希（红线 7）：有公开 ARIA/DOM 语义则用 marker 路径（Settings 见 ADR-0098）；必须命中私有节点时用「官方样式标签包路径 + 模块局部名负向断言」运行时推导（ADR-0019）。解析失败必须自报降级，不能静默失效。
  4. 可选 host 服务双通道探测：ctx.get('x') 与 connection.api.x 都要试，以「存在可调用 select」为准（ADR-0061）；ctx.<name> 属性读对未 inject 服务会抛，可选判据一律包保护且失败按最保守结论走（ADR-0038）。
  5. 共享层不变量：改 shared/client/sidebar-entry-core.ts 的 observer 必须维持「对被观察子树的写操作，移动一次后不得再满足移动条件」——这是 P-52 黑屏事故的血价不变量。
  6. 变更包级门禁：本次改动涉及的包必须已有 typecheck+test；根级治理文件变更会把射程扩到全部包。

C · 做优化（性能 / 体积 / 质量）

产出物：基线读数 + 可复现的对比证据
  1. 先量基线再动手：任何优化前记录当前读数（时间/体积/调用数），禁止拿记忆当基线（P-01）。
  2. 仪器三原则（写任何新判据时）：① 读不到 = 失败或显式跳过，不是通过；② 读状态一律「值 + 绑定身份」一起读；③ 交付前做恒真桩突变，红不了就是没测。
  3. 几何/时间类结论必须像素或契约读数（P-51：OCR 估算把 279pt 估成 350pt，方向还偏向了既有叙事）；时间相关断言用带截止的轮询（P-54）。
  4. 性能候选面：巨型源文件拆分（见 TOP20 #7）；tsc -b 增量缓存利用率；DMG 打包链（3 分半构建记录在 SOP）。
  5. 存量违规清账：theme-tokens 基线等「只减不增」清单按 gate:full 读数逐次清，条目失效即被门禁拒绝。

D · 做重构（含批量修复）

产出物：行为不变的证据 + 清账读数
  1. 豁免纪律：scripts/gates/exemptions.json 只减不增、到期即拒——当前为空是好状态，任何新增豁免都是治理事件，需 owner + deadline。
  2. 收成一家，不要「都改对」：同一判据出现在两处以上时，先合并实现（P-07 五例前科：13 个家、4 个家、2 个家…）。
  3. 成对动作写清单（注册/回收、开端口/关端口）：判据断言两个集合全等，并为卸载/异常路径各写一条真实用例（P-32）。
  4. 批处理先建 plan：把「最终会交给 open/copy/rename 的名字」列成 immutable plan，全批校验完才拿锁（P-28）。
  5. 临时资源回收写信号路径：只写 finally/test.after 等于没写——进程被 kill 时一个都不收（P-34，实测 2,066 个残留根）。
  6. try 里返回 promise 一律 return await（P-33：三处主通路曾全部静默悬挂）。
  7. 验证重构不改行为：跑受影响包的 test + 相关 acceptance 脚本 + gate；重构与行为变更分开提交。

红线清单（改动前必读 · 摘自 architecture.md §2）

  1. 只用内置 alpha SDK（@deepseek-ai/*），不引入 npm 发布线（防双实例）。
  2. 不碰壳内 UI 的 shadows-shipped-ui slot。
  3. 凭证永不落仓库/日志/模型上下文；子进程环境经凭证擦洗。
  4. 编辑工具会打破 file: 硬链接 inode——改后必须 tmp+mv 同步 profile。
  1. 补丁锚点为精确原文，restore 会回滚全部补丁。
  2. MCP 工具模型侧描述不可覆写——业务中文层走技能速查表桥接。
  3. 官方 UI 改写锚禁止钉哈希（见上 B-3）。

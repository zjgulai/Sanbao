# 005 · 会话发送与流式对账（ack≠开始执行）

**Blocked by**: 002
**覆盖需求**: US-012, US-013
**接缝**: S1 / S4 / S8

## 目标

打通最窄执行路径：事项主对话发出一条输入，基座受理并流式回传，界面把“已受理”和“执行中/已完成”分开显示，结束时与最终历史对账。

## 涉及层

- [ ] 数据层：会话记录与消息历史关联事项
- [ ] 逻辑层：Host窄桥调用create/prompt/follow，ack语义保留
- [ ] UI层：状态分区显示；流结束后以历史为最终态
- [ ] 测试：S1+fake Host断言ack与执行状态不混同、最终对账一致

## 验收标准（须给真实证据，未跑就写“未运行”）

- ack出现时不显示“模型已开始工作”
- 流断后重新对账得到与历史一致的最终文本
- 重开不重复发送

## 明确不做

不做工具审批、不做预算与取消续跑细节（见006）

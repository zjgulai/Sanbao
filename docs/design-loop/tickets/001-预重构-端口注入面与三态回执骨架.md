# 001 · 预重构：端口注入面与三态回执骨架

**Blocked by**: 无
**覆盖需求**: US-117, US-118, US-120, US-121, US-122, US-123
**接缝**: S1 / S2 / S3

## 目标

让后续每颗示踪弹都能在Application Service路由上注入真实provider替身，并把命令管线的确定失败/结果未知/未就绪三类结果原样送进ViewState，界面有统一映射点。

## 涉及层

- [ ] 数据层：denial结构（code/stage/retryable/correlation）与outcome-unknown归一字段进入投影契约
- [ ] 逻辑层：ports注入点保留fail-closed默认，测试/开发可替换；retry意图解析不变
- [ ] UI层：ViewState消费三态并选择对应入口（重试/核对/说明缺项），不新增业务动作
- [ ] 测试：在S1接缝用替身ports驱动三类结果，断言回执与入口映射；含未就绪不显示为失败的负例

## 验收标准（须给真实证据，未跑就写“未运行”）

- denial结构与三态映射有S1层测试输出（命令+退出码），非口头通过
- 未就绪时production matter槽仍为null，不用fixture补齐；fixture只在显式开关下出现
- 结果未知态不出现重试按钮；重试只对retryable的确定失败可用
- 文案不泄露机器路径、凭据或内部堆栈

## 明确不做

不做错误码全量字典；不做审批路由；不改门禁判定标准

## 基线差集（2026-10-02 对 `4c4b127` 取证后修订，不要重做已完成部分）

> 执行状态只看 [LOOP.md](LOOP.md) §6 的账本行；本节只描述差集本身。

已在基线里、**本票不得重复实现**：

- 端口注入面：`src/appservice/composition.ts` 的 `PRODUCTION_FAIL_CLOSED_PORTS` 共 10 端口（含 `now`）全 fail-closed，`ServiceOptions` 已允许 main 侧覆盖；WT-02D.2A 已把真 step-2 端口与 availability 端口合并进 `createSageAppServiceProviders`（步骤 3–10 仍 fail-closed）。
- denial 结构：`CommandDenied{code,stage,retryable,correlation}`（`command-contracts.ts`），route 层 `invalid-intent` 也按同一形状返回。
- 三态词汇与校验：`SageAvailabilityState = available|unavailable|recovering|unknown`、`SageActionability`、`SageDenialReasonCode`；`blocked ⇒ denialReason 必填`已由 `view-state.ts` 断言。
- S1 层替身测试已存在一部分：`test/appservice-authorization.spec.ts` 用替身 ports 断言 `{code:'identity-unavailable', stage, retryable:true}` 与 `{availability:'available'}`（含 step-3 rehydrate 的 denial 形状）。

本票**真差集**（做完即达 US-117~123 合同）：

1. 投影缺“命令结果未知”这条独立语义：`outcome-unknown` 只在管线内部归一，ViewState 的 `unknown` 属**可用性**维度，界面无法区分“结果未知”与“能力未知”。
2. renderer 无“核对同一操作”入口：全量 grep `src/product/*.ts` 无 `核对|reconcile|verify` 命中，只有隐藏的 `#retry` 按钮与 `is-blocked` 类；US-119/121 要求“未知只给核对、不给重试”，界面上无处可达。
3. 缺一条端到端三态映射测试：在 `/.sage/actions` 上用替身 ports 驱动确定失败 / 结果未知 / 未就绪三态，断言**入口不同**（重试 vs 核对 vs 缺项说明），含“未就绪不显示为失败”的负例。

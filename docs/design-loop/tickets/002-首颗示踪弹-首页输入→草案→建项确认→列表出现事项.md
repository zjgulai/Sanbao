# 002 · 首颗示踪弹：首页输入→草案→建项确认→列表出现事项

**Blocked by**: 001
**覆盖需求**: US-001, US-002, US-003, US-004, US-007, US-009, US-010, US-011
**接缝**: S1 / S8

## 目标

一条最窄的端到端路径：用户在首页输入需求，看到草案整理，在同一工作面确认建项，事项随即出现在事项列表；草案与正式事项在后端是不同对象。

## 涉及层

- [ ] 数据层：本地草案记录（设备内保存）、转换请求与正式事项及两者关联
- [ ] 逻辑层：建项命令（目标/交付/责任三项必填，项目可选且最多一个）→ 事项创建 → 投影更新
- [ ] UI层：草案整理→创建确认→原地切为主对话标题态；必填缺项不可提交
- [ ] 测试：S1层跑通“填→确认→列表可见”，含登出加密锁定与重登恢复、不自动同步的断言

## 验收标准（须给真实证据，未跑就写“未运行”）

- 同一请求成功建项后列表可见该事项，重开不重复创建
- AI整理结果不自动写入交付/责任字段（有断言）
- 未选前史不进入正式事项对话上下文（有断言）
- 表单填完但未确认时不得显示为已建项

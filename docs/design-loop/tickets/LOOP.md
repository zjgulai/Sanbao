## 1. 每票的机器可判标准（五条，全中才算“绿到可审”；改了可见产物再加 §1.6）

1. **消费侧断言**：该票 §验收标准 每条都有对应测试，且断言读**消费者真正拿到的产物**（投影/帧/文件字节/HTTP 响应），不是读内部调用次数或 mock 被调。
2. **先红后绿**：留下实现前该测试失败的原始输出（缺失模块、断言差异均可），再留实现后通过的输出。
3. **类型与套件**：`npx tsc --noEmit` 退出 0；`node scripts/test.mjs run` 全量 0 失败（本项目测试器是 vitest，勿裸跑 `npx vitest`）。
4. **门禁全过且 skip=0**：`pnpm run gate`（quick）与 `gate:strict`（无 skip 许可）按票风险选；**skip 项数必须写进 §6**，非 0 即未达标。
5. **至少一条变异红**：把本票新引入的**一个**守卫反转（allowlist 放宽、ready/未就绪守卫删除、纯数据校验旁路、注册表漏登记、类型判别改写），必须有**具名测试**变红或 tsc 报错；随后原样还原。**只看退出码不算数**——要写出红的是哪一条。**突变必须落在可达路径上**：本会话撞到一枚"假突变"——把 enabled 分支的 `reason: null` 改成 `reason: preset.broken ?? null`，而该分支的前提就是 `broken === undefined`，改动等价于没改，于是它"存活"得毫无信息。判据是：突变后的代码路径**必须存在**一条输入能走到并产生不同行为；等价突变要换掉，不能记成覆盖洞。

### 1.6 界面实测（改了可见产物的票必做；机器判不了，所以单列）

前五条全是机器判据，但**它们对"人看到的东西"是盲的**：工单 045 五条全 PASS 之后，把渲染出的文档真在 Chrome 里打开，才看到一处语法断裂的说明文案和一处贴死的行距——DOM 桩只读 `hidden/textContent`，样式与文案成不成句它一概不知。所以改 `src/product/**` 可见产物的票，除 §1.1–1.5 外还要：

1. 用 `lib/` 构建产物把文档写到临时目录，在浏览器里打开（`file://` 即可，不启动 Host、不装载 profile）。
2. 覆盖该票的**每个可见态**：改 `window.fetch` 桩后调用页面自己的 `refresh()`（真实渲染路径），逐态读 DOM 计算样式与文本。
3. 截图**回看**（不是只断言），至少含最窄断点（本壳 680px 一带）与桌面宽；检查横向溢出、遮挡、文案成句。
4. 读数写进 §6 该票行；抓到的缺陷要么本票修掉，要么登记成"既存缺陷＋是否另开一票"，不得只写在对话里。

判据执行器不实现这一条（它跑断言与突变，不看像素）——这一条的"判"仍是人眼看截图，因此 §6 要留图片路径。

## 2. 边界（越界即停，不得用放宽换绿灯）

- 不放宽 [ADR-0190](../../adr/ADR-0190.md) 步骤 3–10 的 fail-closed；缺真实 authority 就保持 unavailable-first（ADR-0184）。
- 不改 `vendor/`、pin、Sanbao 快照；不放宽 `/.sage*`、`/api*`、`/plugins*`、`/.dsh/*`、`/.sanbao*` 的 renderer 拒绝面。
- **门禁与 `exemptions.json` 不可动**：契约级校验一律阻塞；豁免清单只减不增。绕过检查字面而做其禁止之事（例如换个写法躲开 `ctx.get(` 词法位）＝违规，不是技巧。
- 不碰并发会话 `73c5c577-…`（WT-02C.2E.2）的射程：`apps/sage-shell/src/main/index.ts`、`app-service` options 形状。
- 零凭据、零真实模型/业务调用；不装载 profile、不启动 Host、不创建真实 session。
- 不 `commit`、不 `push`（逐次授权才可）。
- 非机械改动必须同批落仓 Note + ADR 登记（Sage AGENTS.md）；稿件绿 ≠ 已归档，Note 未写即未达标。

## 3. 角色：plan / build / judge

- **plan**：选票、读票与规格边界，列出本票要引入的守卫（变异候选）。
- **build**：只写实现与测试，**不得改验收条件、不得改门禁判据、不得改 §1**。
- **judge（独立且确定性）**：一条命令跑完 §1 的五条判据（含机器复跑的变异电池）：
  ```
  cd /Users/lute/project/Sage-ui-wiring-design
  node tools/verify_ticket.mjs --ticket <NNN> --specs “test/<本票spec>” \
       --mutate “file:::needle:::replacement”   # 可重复；needle 必须恰好出现一次
  ```
  脚本内部依次跑 `npx tsc --noEmit` → 本票 spec → 全量套件 → `pnpm run gate`（解析聚合行的 skipped/failed/expected==discovered 并逐条打印 fail 项）→ 每条突变”备份→突变→复跑→无条件还原→还原后再复跑”。
  judge 与 build 不同心智：判据是退出码＋**具名**红，不是”看起来对”；`--mutate` 不给或给的 needle 不存在都会判红，未被任何测试覆盖的突变会以”具名红=0”报**漏网**。

## 4. 阻尼与停点

- 同一票连续 3 次判红不收敛 → 停，带读数上报，不做猜测性修复。
- 一轮最多 3 票；每轮回报：跑过的命令、退出码、skip 数、变异红条目、实测成本。
- **立即停**（不等 3 票）：需要动门禁/豁免、需要放宽 fail-closed、需要触碰并发会话射程、需要真凭据或真实调用、需要启动 Host 才能取证。
- 红线：验收由人翻；责任不外移；loop 是工人不是验收员。

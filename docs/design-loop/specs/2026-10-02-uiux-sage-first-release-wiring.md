## 一、问题陈述

现有 UI/UX 页面族（Sanbao 原型 59 组 / 206 条状态）描述的是用户可见结果，而 Sage 活动仓当前的产品输入面只到本地草案与静态呈现：`/.sage/*` 路由虽恒由 Electron main 终止，Application Service 的 composition ports 仍是 fail-closed（返回 `undefined`），matter 投影槽在 production 恒为 `null`。也就是说，**基座具备会话引擎、文件读取、配置与目录选择等能力，但界面与这些能力之间没有产品接线**。

由此产生三个具体缺口：

1. 用户动作没有可追溯的后端归属——按钮合同写了 78 条动作边，但没有一份说明“每条边落在哪个 Sage 端口、返回什么状态”的规格。
2. 基座语义与产品语义不等价——例如 `prompt` 的 ack 只表示进入 inbox、`follow` 对冷会话会促发 Agent、`selectModel` 附带默认值写入、`workspaceFiles` 的 version 是 stat 时刻的 opaque token。直接包一层会把“已受理”误报成“已执行”。
3. 首版范围未被限定——工作区创建、附件列表、协作管理、审批路由、插件启用等能力若不加边界，实现会顺带把治理专题拉回主线。
4. 覆盖清单曾被人工维护——首轮综合按自记的组索引判断“已全覆盖”，用 Sanbao 原型 `catalog-data.json` 逐组复核后发现 20 组 / 53 条既未接线也未标为不做（最大项是事项修改稿与回写、能力目录、运行监控与用量、行动项与项目汇总、归档与批量）。本规格第 4 节因此把 P～V 六个补漏族列为编号需求，写入与治理面一律进 §7，完整性判定以 catalog 与 `tools/verify_mece.py` 输出为准，不以人工汇总为准。

本规格的作用：把已达成共识转成**可独立验证的编号需求 + 明确接缝 + 明确不做**，供 `to-tickets` 切分工单。

## 二、方案概述

以 **Application Service 为唯一产品编排入口**，界面只经该层读写；对基座能力经**窄端口适配**而非直接暴露 namespace：

- 读侧：`ViewState` 投影承载列表分区、产物卡状态、队列快照、错误三态与来源版本；production 缺 authority 时保持 unavailable-first，禁止 fixture 冒充。
- 写侧：`ActionIntent` → 命令管线十步序 → 基座能力或本地服务；回执区分已接收 / 已生效 / 结果未知。
- 基座侧：复用 `ctx.remote.session`（create/prompt/follow/cancel/page/list/search/updateQueue/selectModel/modelCatalog）、`workspaceFiles`、`settings`+`credentials`、`workspace`+`directoryPicker`、`dsh-client-file-upload`+`dsh-attachment`。
- 呈现侧：产物与预览走 main 加载的侧面容器；HTML 沿用离线交互容器与帧禁用不变量。

Sage 需要**自建**而非复用的部分：暂停/待继续状态与持久待处理记录、事项↔工作区多关联记录、行动需求分区推导、偏好读写口与订阅、附件与事项范围绑定、结果未知核对入口；补漏族另需自建事项修改稿对象与版本比较器（基座只有 stat token 与实时读取，无 diff/回写语义）、行动项与项目汇总对象、归档态与批量逐项回执、监控四轴与运行日志的只读投影。

## 四、用户故事（编号需求，每条可独立验证）

约定：`[待核验]` = 本批只做静态取证、未运行；`[需补建]` = 基座无对应能力或 Sage 无实现；引用编号为决策溯源。

### A. 首页草案与建项确认

- US-001 用户在首页输入需求并发送后，进入对话式工作面看到草案整理与澄清，不需要跳到独立草案页（FW-001）
- US-002 建项确认在该工作面内展开，创建成功后原地切换为正式事项主对话，用户不需重输内容（FW-001）
- US-003 草案与正式事项在后端为不同对象，主对话初始状态取自服务结果，而非仅改标题（FW-001）
- US-004 转换只带入已确认整理结果与用户主动选附片段；未选前史留在本地草案可回看，不进入正式对话或执行上下文（D-083、FW-001）
- US-005 创建中或结果未知时保留输入并与同次请求关联；失败可在原工作面修正，未知先核对且不重复建项（FW-001、FW-021）
- US-006 取消未提交确认返回草案编辑；创建已生效后返回/刷新不重复转换、不自动启动业务运行（FW-001）
- US-007 建项表单要求目标、预期交付、责任三项必填，缺项时不能提交（FW-022）
- US-008 责任字段默认当前登录身份且可改；UI 自报身份不作为授权依据 `[待核验]`（FW-022，依赖 Identity/Policy 后置专题）
- US-009 项目归属可选且最多一个；不选项目也能建项（D-089、FW-022）
- US-010 AI 整理结果不自动写入交付或责任字段（FW-022）
- US-011 本地草案仅在当前设备安全保存，登出后加密锁定，重新登录并获准才恢复；不自动同步或换机接续（D-081/082）

### B. 会话主链：发送、流式、停止与待继续

- US-012 发送 ack 与开始执行分离显示：ack 表示已受理进入队列，不显示为“模型已开始工作”（FW-002/020、矩阵首闭环反例）
- US-013 流式输出结束后与最终历史对账，最终态以历史为准（矩阵首闭环反例）
- US-014 执行中点击停止：取消当前可取消工作，并阻止本事项后续输入自动进入执行（FW-002）
- US-015 停止时尚未执行的输入保留为“待继续”，可查看、编辑、移除（FW-002）
- US-016 切页、重连、重开应用或收到迟到结果都不自动续跑；不影响其他事项（FW-002）
- US-017 只有用户明确点击继续，才按当前有效内容与执行条件恢复处理（FW-002）
- US-018 后端区分尚未派发 / 已提交基座 / 已被消费 / 结果待核对四种状态；不得先把输入送入会自动唤醒的 inbox 再靠前端拦截（FW-002）`[需补建]`
- US-019 无法确认尚未执行的输入不得直接放回可重发队列，先进入待核对（FW-002）
- US-020 暂停期间发送新输入只保存为待继续并反馈“已收到，尚未执行”，不唤醒 Agent（FW-003）
- US-021 查看/编辑/移除待继续输入都不唤醒执行（FW-003）
- US-022 编辑或移除只影响尚未执行项的后续内容，不改写已消费输入或历史执行依据（FW-002）
- US-023 继续请求与真正恢复执行分开；重复点击/重连不重复派发（FW-002/003）
- US-024 重开历史事项时读取历史走纯历史接点，不因打开历史而促发 Agent（FW-017、`follow` 冷激活差异）`[待核验]`

### C. 队列与自动化边界

- US-025 发送时可选 `queue`（本轮结束后处理）或 `steer`（下一步骤边界插入）（FW-020）
- US-026 `steer` 的界面文案不得写成“已打断当前步骤”，只说在步骤边界消费（FW-020）
- US-027 待处理项可查看、修改、移除；项已被消费时按 `queue-item-not-found` 如实提示“已开始处理”，不静默丢弃、不重复提交（FW-020）
- US-028 队列呈现以基座权威快照为准，含 `queued|steering|context` 三种位置（FW-020）
- US-029 暂停态下队列入口只显示待继续，不调用会唤醒 Agent 的动作；恢复时才按顺序派发（FW-020 与 FW-002/003 一致）
- US-030 首版不提供定时/循环自动化入口，也不以只读空列表冒充已有自动化能力（FW-020）

### D. 产物卡与预览

- US-031 产物版本确认可读后，在对话与产物列表显示卡片与就绪状态（FW-004）
- US-032 用户点击卡片才在侧面打开该准确版本；不自动展开、不抢输入焦点、不替换正在查看的内容（FW-004）
- US-033 卡片呈现本身不创建或加载预览容器（FW-004）
- US-034 生成中/同步中/不可读取分别如实显示，不以文件名出现或工具调用成功代替内容就绪（FW-004）
- US-035 内容在点击时已失效或资源不足显示失败与“同版本重试”，不静默切到最新版本、不重跑生成（FW-004）
- US-036 连续点击不同产物时，迟到的旧加载结果不覆盖当前选择；关闭后不被迟到结果重新打开（FW-004）
- US-037 关闭预览回到原工作面，保留对话与输入，不停止执行、不改验收或产物记录（FW-004）
- US-038 首批预览支持纯文本、Markdown、代码、PNG/JPEG、离线 HTML、PDF、CSV 表格，以查看为主（FW-005）
- US-039 CSV 需要表格解析与呈现适配 `[需补建]`（FW-005）
- US-040 DOCX/XLSX/PPTX 原格式内置预览后置，仍显示准确版本文件卡与已有导出路径；不把可下载写成可预览、不自动转换（FW-005）
- US-041 容量与格式子集以实施验证确定，不沿用基座默认上限作产品承诺 `[待核验]`（FW-005）
- US-042 HTML 预览继续采用离线交互容器与帧禁用不变量（D-034、ADR-0178）

### E. 模型配置、测试与选用

- US-043 模型表单结构校验通过后可先保存，回读显示“已保存、未测试”（FW-007）

- US-218 工作区索引页只读显示索引覆盖范围与更新时间；触发重建或全量扫描不在首版（与 D-090 不扫描一致）
- US-219 任务监控设置页显示“布局偏好当前不可配置”及原因，不与只读监控面板混为可写面

### AA. 外观项持久化清单扩围（FW-039）

- US-220 可持久化外观项扩为：主题（含跟随系统）、语言、密度/缩放、字体风格、内容宽度、终端主题、文件图标、图标外观；仍由同一偏好端口（S9）持有
- US-221 每个外观项在设置页与快捷菜单读写同值并订阅变更；任一处保存失败不得显示为已生效
- US-222 清单外的外观/输入项（快捷键、语音、监控浮层布局）继续后置并显式标注（§7.9），不留下“看起来能改”的控件

### AB. 反馈入口与结构化诊断（FW-040）

- US-223 反馈只提交用户输入文本与结构化诊断（code/stage/correlation），不自动附日志、原始堆栈、机器路径或凭据
- US-224 反馈回执区分已接收与结果未知；未知只给核对同一提交的入口，不重复提交

### AC. 任务分组对象（FW-041）

- US-225 任务分组是 Sage 自有组织对象：建立、改名、移除为具名命令并逐项回执，不隐式产生
- US-226 分组只改变列表组织方式，不改变事项事实、可见范围、责任或权限


## 五、已定决策（不可翻案清单）

- 功能取舍：FW-001～FW-021 逐条确认；FW-022～FW-027 经用户批准按推荐默认批量落档、待终审；FW-028～FW-034 为组级 MECE 核对后补入的首版范围（读取面进票、治理面入 §7）
- FW-035～FW-041 为**状态级**核对（206 条逐条落账）后补入的首版范围，按用户“全部补成 US 进首版”的决定收口：澄清问答与消息操作、输入区选择器与模式、授权等待与模型排队、终端与独立预览窗口、11 张设置叶子页只读、外观八项持久化、反馈与任务分组；其中写操作与治理面仍一律留在 §7
- 范围完整性依据：Sanbao 原型 catalog-data.json（59 组 / 206 状态，多归属计数 235）与 32 个页面实现文件；矩阵条数列已按该文件重算。**判定单位是状态而非组**：`tools/mece_states.py` 逐条把 206 条状态落到 US/§7/纯UI/组聚合四态，任一条既无 US 也未显式后置即退出码 2；组级三桶穷尽（`tools/verify_mece.py`）不足以支撑“全覆盖”结论
- 首版“只做/不做”：工作区只采纳已有目录（FW-008）；附件走基座上传链、随消息展示（FW-010/011）；本地引用限工作区内且实时读取（FW-012/013）；错误三态分开（FW-021）；协作管理、审批路由、知识发布、Registry 授权、发布链全部后置（FW-023～027）
- 治理既有边界不解除：D-071 执行设备绑定、D-072/073 上传与模型传输逐次核验、D-079 不用业务内容做通用训练/产品改进、D-091 默认环境逐次核验、D-093 快照模型（仅实现后置）
- 呈现原则：unavailable-first（S3/ADR-0184）；自报不等于权威；界面不得把“已保存/已受理/已发送”写成“已执行/已生效”

## 六、测试决策

- **主测试面选 S1（Application Service route）**：绝大多数 US 应能在 `/.sage/*` 层用替身 ports（S3）驱动命令、断言 ViewState 投影，而不下沉到 renderer 细节；基座能力用 S4 的 fake controller 断言提交参数与状态归一。
- **必须下沉到其他接缝的例外**：
  - S5/S6：文件版本重核、流式上传取消——需以真实（或本地临时目录）字节验证，替身会掩盖 `version` 是 opaque token 的语义差异
  - S7：预览容器与帧禁用——需 main 加载行为验证，含“迟到结果不覆盖当前选择”的时序用例
  - S9：偏好单一权威值——需两入口读写同值的一致性用例
- **“完成”的判定标准**（每条 US 都要给真实输出，未跑就写“未运行”）：状态机四问可回答——已接收？已生效？实际使用值？失败/未知的下一步入口？
- **必测反例（来自矩阵首闭环，不得省略）**：发送 ack ≠ 开始执行；流式与最终对账；停止不自动续跑队列；冷历史读取不激活执行；重开不重复发送；产物内容真实可读；结果未知不重放；未挂载不显示为已停用
- **补漏族的必测反例（P～V，同样不得省略）**：生成修改稿 ≠ 共享文件已更新，且下载/导出不产生回写效果（S5/S1）；回写未确认时不得出现“已回写”态（S1/S2）；归档 ≠ 停止执行 ≠ 隐藏，三者断言分开（S1/S8）；批量部分失败不得显示整体成功（S2/S8）；“已配置”“已启用”“可用”三者不得互相顶替（S3/S4）；监控四轴与详情/列表读同一投影，折叠或关闭面板不取消运行（S8）；接受方案 ≠ 执行方案，执行仍需动作级确认（S1/S2）；结果内不执行脚本、raw payload 不透传（S5/S7）
- **FW-035～041 的必测反例**：澄清回答未回执不得显示“已回答”；澄清等待中停止后不得自动续跑；锚点定位不得触发 prompt/follow；编辑不得覆盖原版本、重发不得重复派发已消费内容；技能/插件选择不得改变启用状态；事项内切模式不得写全局默认；未获授权不得派发依赖动作；排队与重试不得产生并行重复运行；就绪不得由界面计时器推断；终端输出不得进入对话历史或产物列表；独立窗口不得在显式动作前创建；设置叶子页与个人资料页不得接受 renderer 自报身份，不得出现凭据、token、raw subject、机器路径；外观八项任一处保存失败不得显示已生效；清单外项不得出现可交互控件；反馈不得自动附日志或堆栈；分组不改变可见范围与责任。
- **补漏族的测试面选择**：P～V 与 W～AC 均不新增接缝，按上表落在 S1/S2/S3/S4/S5/S7/S8；其中只有“修改稿按版本比较”和“运行日志只读取用”需要在 S5 用本地临时目录的真实字节验证，其余在 S1 用替身 ports 即可断言
- **不采用的验收**：门禁绿灯、类型检查通过、基座包存在、单测 mock 成功——均不得作为“功能已接线”的证据

## 七、明确不做

1. **身份与授权治理**：真实 provider 参数、组织岗位授权、AuthoritySnapshot、retention/legal hold 与删除传播；相关既有安全边界不因本规格放松

4. **知识治理**：知识候选的创建、编辑、晋级发布、退役，以及偏好记忆的保存/遗忘传播（首版只读呈现来源与版本）
5. **能力启用面**：插件/扩展/MCP 的安装、更新、启用、停用、撤销与授权，Registry approved 条目与 provenance，MCP 写配置与深链安装确认
6. **执行写操作**：定时与循环自动化、后台执行主体、预算预留与结算、设备代次与换机接管、子执行/并行合同（首版只读监控、用量与运行日志呈现；日志导出按独立权限核验，压缩策略不可配置）
7. **文件写与回写链**：Git 提交/推送/分支与 Worktree 接线、事项修改稿的自动回写、Office 原格式内置预览与自动转换、图片批注
8. **发布与升级**：Sage.app 装配/签名/公证/发布链、检查更新与自动更新、发布验收（旧 DMG 绿灯不充当 Sage 证据）
9. **输入与外设**：语音转写与麦克风设备枚举、快捷键自定义、任务监控浮层与布局偏好、程序坞图标等原生项
10. **呈现与本地化**：主题全量 token 审计、无障碍与对比度验收、多语言文案审计
11. 本地资料受控快照（D-093 机制，模型已定、实现后置）；两次运行及其产物的版本对照
12. 本规格不授权修改 Sage / Sanbao / pin 源码，不授权装载 profile、启动 Host、创建真实 session、读取凭据或调用模型与业务工具

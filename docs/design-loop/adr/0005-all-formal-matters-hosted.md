# ADR-0005 · 所有正式事项统一托管，可见范围独立控制

- 编号范围：本轮仓外设计。

- 前序：[ADR-0004](0004-shared-matter-service-authority.md)；其本机执行边界与单一裁决原则继续有效。
- 后续细化：同一讨论工作稿D-067～073已明确主/侧对话同步、候选分享、交付同步、执行设备、本地引用与模型发送边界；下文相应“仍需明确”保留为本决定时的历史状态，当前分类见[接线矩阵](../ui-wiring-matrix.md#数据位置与可见性接线)。D-074/075进一步确定[中国内地单一区域起步](0006-single-mainland-hosting-region.md)；具体供应商、保留与传输协议仍未决定。

## Problem

ADR-0004只确定共享事项由协作服务裁决，未决定尚未共享的正式事项归属。若私人正式事项由本机独立裁决，后续共享需迁移整条权威记录，并处理失败恢复、在途运行与双主风险；而统一托管会增加个人正式内容进入服务端的范围，必须明确告知。

## Decision

用户选择所有正式事项统一由Sage托管服务保存并裁决正式状态，无论是否共享。个人可见或组织内共享是独立的访问范围，不是本机/服务端位置的别名。

确认建项时明确展示进入托管服务的正式记录范围。未共享正式事项不必通过迁移权威才能邀请协作者，但共享仍须单独核验权限，不自动公开给组织成员。

此决定前向补齐ADR-0004的私人未共享事项问题，将统一裁决范围从共享正式事项扩展到全部正式事项；本机不再作为某类正式事项的第二个最终裁决点。任务仍本地执行，本机保留必要的执行事实记录与安全缓存，服务端不能仅凭收到请求声称执行成功。

建项前草案、原始附件、机器路径、秘密或全部本机资料不自动上传。具体对话记录、成果内容与资料引用的同步范围仍需明确；用户确认建项不是授权上传整个工作目录。服务端不可用时不得在本机偷偷创建一条同身份的正式事项再事后合并。

## Alternatives considered

- 未共享正式事项由本机管理、共享时交接权威：可减少个人正式内容上传，但需维护两类生命周期、在途处理与可恢复的单向交接；用户选择统一托管减少该复杂度。
- 可见范围与存储位置共用“个人/组织”开关：不采用，容易让用户误认为个人可见就没有服务端存储。

## Consequences

正式创建、版本、决定、验收、归档与整体状态需由托管服务受权处理；本机执行与结果上报协议仍需设计。客户端必须区分本地输入/未确认草案、服务已接受记录、实际执行和结果同步状态。

对现行Sage ADR-0161/0174的前向演进范围扩至全部正式事项，历史记录解释仍不得改写。数据地域、tenant隔离、加密、保留/删除、备份和服务不可用策略必须作为真实数据门；本记录只确定目标，源仓ADR/源码/配置均保持不变。

D-065已决定首版由Sage产品方托管，但云厂商、数据库、身份供应商、部署地域与费用仍未选定。本决定不授权当前上传、部署或迁移。

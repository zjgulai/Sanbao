# ADR-0003 · 按动作必要前提判断就绪

- 日期：2026-10-01

- 演进依据：[ADR-0002](0002-controlled-contract-evolution.md)

## Problem

现有领域核要求revision中所有unknown清零、全部依赖ready，才允许attempt开始。该窄合同不能区分“需要通过获准调研解决的问题”与“执行本动作之前必须满足的前提”，可能让调研本身被整体未知阻断。

## Decision

用户选择按动作前提推进。每个动作明确所需证据、依赖、权限与预算；必要条件具备的步骤可以先行，未就绪部分继续阻断。用于解决其他未知的调研不必等待整个事项的所有问题解决。

权限、数据目的地、动作效果、关键安全条件或其他本动作必要前提未知时，仍必须拒绝执行。不得以“只读”“调研”或模型自述“无影响”替代这些条件，也不得将未知直接改成不适用来放行。

动作与前提的关联及其变更须可验证、可追溯，并由受信产品合同与相应专业责任约束；具体规则来源与确认机制尚待设计。事项层的整体资源、授权和相互依赖约束仍有效；本决定不自动允许并行，不扩大执行范围或完成标准。

## Alternatives considered

- 整个事项齐备后运行：实现集中、保守，但可能要求用户在事项外完成本应由系统进行的补证工作。
- 由AI临场决定忽略哪些未知：不采用；无法证明没有漏掉必要依赖或安全前提。

## Consequences

后端需要动作级前提、证据/依赖关联、当前就绪判断和失效传播；界面应分别显示可推进与被阻断部分，以及安全的阻断原因。执行前仍须核验当前revision、身份/政策、兼容性、Registry、能力可用性和预算，不将局部ready视为整体授权。

后续验证至少包括：不相关未知不阻断独立动作、必要未知必阻断、权限/数据边界未知必阻断、前提失效立即影响相关动作、相互依赖和资源冲突不被忽略。历史v1语义保持不变，具体版本化演进方案另议；不在本轮删除现有检查或修改源码/共享计划。

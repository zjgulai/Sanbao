# ADR-0004 · 共享事项由协作服务统一裁决，本机保持执行边界

- 日期：2026-10-01
- 状态：accepted-design-only；仅批准目标分工，未实施、未部署或迁移。
- 编号范围：本轮仓外设计，不属于Sage仓正式ADR序列。
- 用户决定：[讨论工作稿](../discussion.md) D-062～064。
- 当前基线：[Sage ADR-0161](../../adr/ADR-0161.md)、[Sage ADR-0174](../../adr/ADR-0174.md)。
- 后续补充：[ADR-0005](0005-all-formal-matters-hosted.md) 将统一裁决范围扩展至所有正式事项；D-065确认Sage产品方托管，下文相应待决描述保留为本次决定时的历史状态。

## Problem

正式首版需要不同成员在各自电脑协作，并且发起设备离线时，其他在线成员仍能对已同步成果完成评审与验收。当前本机Electron main独占BusinessMatter权威库和编排的合同无法直接实现该要求；仅把请求暂存在服务器、等发起机确认，却显示验收已生效，会给出虚假结果。

## Decision

共享事项的正式版本、审批、验收和整体状态由Sage-owned独立协作服务统一裁决。本机负责受控执行和真实执行事实记录，保留必要的本地执行账及安全缓存；同一正式共享事项状态不能在服务端和客户端成为双主。

协作服务可以按当前权限和指定的已同步成果版本确认验收，不依赖发起电脑在线；本机执行状态只能来自可核验的执行事实。服务端收到消息、批准或文件，不等于本机已执行、能力兼容或业务已完成。

本机main仍负责设备侧调用方、窗口/进程与本地资源边界，通过受控Adapter消费Host能力；renderer、插件、模型和Host不能成为平行业务权威。服务端与本机之间的身份、调用权、fresh authority、执行委派及结果验证协议必须另行定义，不能拿组织用户token直接下发给Host，也不能让服务器指令成为任意本机命令入口。

仅同步明确纳入协作且获准的数据。私人草案、全部附件、原始日志、机器路径和秘密不因本决定自动上传；共享名称或资源引用也不自动提供底层访问权。服务和客户端均继续遵守当前权限、最小化及保留规则，客户端自身离线不得靠缓存权限写入。

## Alternatives considered

- 按记录类型分权：服务端独占评审/验收，本机独占事项/执行记录，通过协议协调。并非不可行，但跨记录版本、撤销、迟到结果及整体完成需要更多一致性协调，容易出现验收已生效而整体事项无法确认的分裂。
- 发起电脑在线时才处理：与已确认的离线协作可用性要求不符。
- 两端各自更新同一事项，随后合并：不采用；相同事实双主会使审批、版本和完成裁决发生冲突。

独立的质疑、交付和故障视角均支持收窄的统一裁决：集中共享正式记录，而不是上传所有数据；统一权威不证明外部执行原子性。

## Consequences

此目标需要前向演进现行ADR-0161中“本机main为BusinessMatter唯一正常业务写入口”及ADR-0174中“全部产品command/projection由Electron main独占编排”的共享事项部分。现行文件在本轮不修改；最终方案须给出明确的替代条款、保留边界和验证后才能另行实施。历史v1记录含义与读取不能被静默重解释。

本机SQLite可作为执行账、缓存或受控未同步记录的候选介质，不自动决定其最终schema与职责。个人未共享正式事项的权威位置、从本地转共享的所有权交接、协作服务部署/数据库/地域、共享文件内容存储及删除传播仍未决定。

必须验证：跨端并发与版本冲突、撤权和过期、发起设备离线下验收、设备恢复后的迟到结果、重复dispatch与结果未知、内容尚未同步完整时不能验收、服务不可用时拒绝越权写入。正式验收回执与执行回执须区分，业务完成仍由明确规则决定。

本决定不授权云资源创建、端口开放、凭据读取、真实同步、远端执行或当前开发仓改动；任务本地执行、手机接线后置的既定方向保持不变。

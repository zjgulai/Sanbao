# ADR-0002 · 按已确认体验受控演进接线合同

- 日期：2026-10-01
- 状态：accepted-design-only（仅方案原则，非源码或迁移授权）
- 编号范围：本轮仓外设计，不占用Sage仓ADR编号。
- 讨论入口：[讨论工作稿](../discussion.md)
- 当前依据：[BusinessMatter合同](../../specs/2026-09-24-businessmatter-contract.md)、[Application Service边界](../../notes/proposed/architecture/2026-09-30-application-service-boundary.md)

## Problem

已确认的草案、多交付项验收、专业Agent协作及关闭窗口后后台继续等体验，超出现有窄首闭环合同的表达范围。若直接给原型按钮绑定现有接口，可能把分项接受误写成整体完成，或用已失效的窗口身份继续执行；若仅用前端状态补齐，则出现第二套业务权威。

## Decision

用户选择按已确认体验受控演进合同。完整接线方案须为每项体验指出对应的领域、编排、公开投影/意图和数据生命周期差距，将必要合同演进列为真实接线前置；不以组件本地状态伪造后端能力。

历史v1事件含义与回放保持不变。新schema、关联子模型或其他具体表达方式需要逐项比较后确定，不由本原则预选；不能复制两套平行业务权威。用户确认的产品行为与尚未批准的技术方案必须分开。

现有合同属于窄首闭环，不因覆盖不足而全部判为代码缺陷。演进分为有依赖、可验证的切片，不要求一次实现全部功能，也不意味着重写已有正确内核。

## Alternatives considered

- 首批仅接现有合同可表达的行为，其余体验延后：首批改动较小，但不能完整承接本轮已确定体验。用户选择将必要演进明确纳入接线方案，而不是默认牺牲体验。
- 前端拼装临时状态或平行业务接口：不能保持唯一状态与权限边界，不作为合法补齐方式。

## Consequences

方案需要包含逐项合同差距、受影响页面/动作、版本与历史兼容、事务/幂等、权限及验收信号；新行为与历史回放均须有验证。多Agent的子执行不必天然等同多个事项attempt，后台任务也不能靠保留旧window/frame身份工作，具体模型待设计。

Sage与Sanbao源仓、现行ADR、执行计划、源码、配置和运行实例保持不动。对现行合同的正式修订、实现文件范围、数据迁移、真实调用与发布均须在本轮设计后另行确认。本记录不解除身份、数据治理、可信能力或产品验收门。

## 三颗示踪弹的信息量

它们排在宽重构**之前**，各自单点贯穿到最高接缝 S-F（装机产物字节）：

- **004 一位头像** → 证明 `worldpilot.pin` + 哈希校验 + L10 改判 + 双轨承载这条链走得通，代价只有一个人
- **005 app 图标** → 除了换图，还补上一条**缺失的判据**：旧 `brand-icons` 只校 IHDR 尺寸，硬边方块会静默出货且照样绿
- **006 启动屏** → 换字标的同时用三条断言证明加载动画仍活着（用户明确要求保留）

任何一颗弹打不穿，都说明后面的宽重构批次需要重排——这比先做完 22 张再发现路径不通便宜得多。

## 拆切片时新暴露的两条事实（规格里没有）

1. **007 不可再拆**：`stylesheet.spec.ts:85` 钉死 `--lute-brand: #58b848`、`layer-icons.spec.ts:61` 钉死 `stroke="#58B848"`——测试复述的就是字面量本身。「只换源值、旧值并存」做不到，换值与测试改读源必须同片。
2. **007 曾有一条假依赖**：初版把 004 列为 007 的前置，理由是「先跑示踪弹」。那是排序偏好不是阻塞关系——`Blocked by` 的语义是「没有它就干不了」。已摘除，并在 007 备注里写明，免得将来又被加回去。

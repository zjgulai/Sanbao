# 0. 目标与非目标

**目标**：把 DSH 侧边栏从「插件注入堆出来的导航」重构为「四带契约导航」，先解决启动带的视觉失调（用户原话：新会话/新应用「统一调小，颜色也不怎么搭」），最终让侧栏成为产品能力图谱的稳定表达。

**非目标**：
- 不当轮改会话列表的既有行为（工作区嵌套会话轴已验证正确，保留）。
- 不改新应用抽屉内部（ADR-0045/0062 的分区与目标函数不动）。
- 不在本轮为「消息渠道」做实现，只预留学籍（P3 登记）。

# 2. 参照系关键证据（摘要，全文见 NOTES.md）

- Codex/Qoder/MiniMax/Accio 四家的启动动作**全部是无 chrome 文本 nav 行**；「双并排胶囊按钮」在参照系中不存在。
- DSH 启动带双按钮（38pt 高、elevated-fill+0.5px 描边、500 字重）是同区域视觉重量 2 倍以上；新应用 active 态另用品牌绿整行填充，与中性新会话按钮并排 = 两套色彩体系——「不搭」的物理根源（`packages/surfaces/dsh-newapp-local/src/client/newapp.module.css:598-648`）。
- DSH 侧栏为五者最宽（~350pt 估算），参照物 175–300pt。
- 会话行 pitch 实测 34pt，不是密度问题；问题是宽度+chrome+色彩双轨。

# 3. 目标结构（侧栏 v1 · 四带）

```
┌─ 启动带 (2 行, 30pt, 文本 nav 行)
│  ✚ 新会话        ← 官方按钮样式降级覆盖为本形态
│  ▦ 新应用        ← split 模式退役，改为同带堆叠行
├─ 能力带 (1 行 + 折叠组)
│  ◉ 工作台 ▸      ← 折叠组，收编：任务板/SSH/技能中心/岗位矩阵
│  🔍 搜索          ← 新行，会话过滤（Qoder 模式；P2）
├─ 内容带 (主体, Codex 同构)
│  置顶            ← P2 新增
│  工作区 ▸（嵌会话，现状保留）
│  最近            ← P2 新增（未分组会话）
├─ 系统带 (沉底)
   ⚙ 设置   👤 账户/状态
```

# 4. 分期与验收

## P0 · 启动带去按钮化（先交付，范围最小）
- **改动面**：`packages/surfaces/dsh-newapp-local`（sidebar-entry-core 的 split 路径改为堆叠同带；newapp.module.css 的 `.entry` 去 chrome）；官方新会话按钮的视觉降级**走样式覆盖**，锚定稳定 data-attribute/slot，**禁止钉哈希类名**（架构红线，docs/architecture.md §2）。
- **目标形态**：两行 30pt 文本 nav 行；icon 16px + label 13px/450 字重；无描边、无 elevated fill；active 态 = 背景极浅 hover + 3px 左指示条（品牌绿只在此出现）。
- **验收**：① 更新 `scripts/geometry-probe.mjs` 与 `reconcile-probe.mjs` 断言（行数 2、高度 30pt、无 border/fill 断言替代按钮断言）② 明/暗双主题各一组真 Chrome 截图对照 ③ `scripts/gates/sidebar-row-axis.mjs` 门禁须适配新结构或通过 ④ `pnpm run gate` exit 0。
- **风险**：官方 shell 升级后覆盖锚失效 → 用 MutationObserver 自愈（沿用 sidebar-entry-core 既有机制）；DSH 当前暗主题为常态，暗主题单独验证。

## P1 · 能力带收编（折叠组）
- **改动面**：新增「工作台▸」折叠组宿主（首选注册 L2 slot 而非纯 DOM 注入；若 slot 不可得则沿用注入机制但收口在一处）；taskboard/ssh/skill-center/role-matrix 四个插件的 `position` 改为组员；杀 99+ 徽章。
- **验收**：侧栏一级可见行 ≤4（新会话/新应用/工作台/搜索可后置）；折叠态记忆；任一插件卸载/重装后骨架不变形；真 Chrome 断言。

## P2 · 内容带增强
- 置顶段（会话 pin，持久化到 profile）；搜索过滤行；工作区行二级信息（会话数）。
- **验收**：31 会话规模下定位目标会话 ≤2 次操作。

## P3 · 系统带与契约定型
- 设置/账户沉底视觉定型；为「消息渠道」（team-hub/飞书）预留行位；**登记 ADR**（侧栏=四带契约，新插件入口必须进能力带，禁止自由 DOM 注入），并增/改门禁守契约。
- **验收**：`pnpm run gate` 全绿；新插件挂载手册同步更新。

# 7. 勘误（2026-09-18 实测复核）

## 7.1 D5 的前提被证伪：DSH 侧栏不在参照带之外

§2 与 NOTES.md 里「DSH 侧栏 ~350pt，是五者最宽」来自截图 OCR **文本框范围估算**（NOTES 表内原标 ⚠️）。
改用像素行扫描实测（`.scratch/sidebar-research/scanrow.swift`，同一批截图、每图 2–3 行复核，设备像素 ÷2 = pt）：

| 产品 | 侧栏宽（实测） | 原估算 | 侧栏底色（实测） |
|---|---|---|---|
| DSH | 557px → **279pt** | ~350pt ⚠️ | #191C1A |
| Accio | 560px → **280pt** | ~175pt ⚠️「最窄」 | #E6E8E8 |
| Codex | 550px → **275pt** | ~300pt ⚠️ | #FEFEFE |
| MiniMax | 544px → **272pt** | ~245pt ⚠️ | #F1F1F3 |
| Qoder | 504px → **252pt** | ~265pt ⚠️ | #F1F2F2 |

独立第二来源：基座 `@deepseek-ai/dsh-client-ui-layout` 布局 store 初值 `layoutInfo.sidebar: 280`
（注释「For the sidebar the preference IS the width」）；宽度硬性夹逼区间 `clampWidth(px, 264, 420)`。
像素实测 279 ≈ 契约默认 280，两个独立来源互证。

**结论：D5 作废。** DSH 侧栏宽度落在参照带（252–280pt）之内，「最宽需收窄」不成立。
此后宽度议题以 ADR-0125 D7（目标 264px）为准。

- 优先级：P1
- 状态：`done`（2026-09-22，EX-10 判型：**两个文件均判「不拆」——热点即设计**）
- 依赖：无（与 DA-07 同族，但无硬依赖）

## Problem

DA-07（源码热点拆分）已推两片：ResearchView 首片、wanzh 列表组装抽离（`d181002`）。
图谱显示下一个热点在 dsh-paper2skills：`eval/lib/load.mjs`（14 导入方）与 `lib/taxonomy.js`
（13 导入方）是全仓最高频的包内聚合点。注意两者分别是 eval 面与库面，**性质不同需分开判**：
eval/lib 的导入方都在 eval 脚本群内（聚合可能是合理的），lib/taxonomy.js 是
「业务单一数据源」设计（出海技能体系当前形态，架构文档已声明）——**拆分前先判这是不是债**。

## 动作

1. 列出两文件的全部导入方与各自消费面（哪些导出被谁用）；
2. 判型三选一：
   - **纯聚合桶**（导入方只用小子集）→ 按消费面拆模块；
   - **真单一数据源**（taxonomy 即契约）→ 不拆，登记为「热点即设计」；
   - **混合** → 拆出高频子集，保留数据源本体；
3. 需拆分的：沿用 DA-07 第二片模式——抽离内部模块 + 该包测试绿 + 门禁接线 + 反向突变 +
   npm pack 核对清单 + 副本同步哈希核对。

## 验收

- 判型结论有导入方清单证据（不是「感觉耦合高」）；
- 拆分片全部过该包测试与 `package-files-coverage`；副本双同步哈希相符；
- 若判「不拆」：本工单落登记理由后关闭。

## 注意

- taxonomy.js 是「勿手改 lib/catalog.js」链路的一环——动它之前重读
  `dsh-overseas-skills` 的 pipeline 约束（阶段 8 tmp+mv 防硬链接双杀）；
- eval/ 面改动不影响出货面，优先级可让位于出货面热点。

## 结算（2026-09-22，EX-10 判型读数）

**两个文件均判「不拆」**。导入方清单证据与判型理由：

### eval/lib/load.mjs（141 行 / 13 个 eval 脚本导入 / 14 个导出）

**判型：eval 基础设施的单点工具箱（结构合理）**。

- **消费面形态**：13 个导入方里 6 个只取 `{ EVAL_OUT }`（一行 import 取一个输出目录常量），
  3 个取标准四件套 `EVAL_OUT + loadInstalledSkills/loadPresets/loadJson`，
  其余各取子集（rng/jaccard 等小工具）。
- **聚合是内聚不是混杂**：全部导出都服务于同一件事——「eval 脚本读取评测对象
  （技能库、preset、数据文件）的标准方式」。14 个导出是**一个关注面的工具集**，
  不是多个关注面的偶然堆放。图谱的「14 导入方」高读数反映的是 eval 脚本群的
  扇入（in-degree），不是文件的扇出复杂度。
- **拆了会怎样**：把 `EVAL_OUT` 常量、frontmatter 解析、加载器拆成三个文件，
  每个文件仍然被同一批脚本导入——导入边不减，只是把一次 import 变三次。
  eval/ 是内部评测面（不出货、无门禁可达性压力），拆分的可维护性收益为零。

### lib/taxonomy.js（220 行 / 15 个消费方 / 16 个导出）

**判型：真单一数据源（热点即设计，架构文档已声明）**。

- **消费面形态**：消费方横跨 test / scripts / lib/axis.js / eval 四个面，
  但全部消费的都是**同一个契约**——分类体系（taxonomy schema、校验规则
  `validateClassification`、槽位解析 `resolveFacets`、gap 审计 `auditGapClaims`、
  常量族 NAME_RE/MAX_DESC/L3_MIN/L3_MAX/EXPECTED_GAPS）。
- **这正是 architecture.md 已声明的形态**：「工具业务清单 `lib/business-meta.js`
  单一数据源」同族——p2s 的 taxonomy 就是分类事实的唯一家（ADR-0009 的应用：
  分类规则写一处，15 个消费方留引用）。拆散它等于给分类契约造第二、第三个家。
- **体量核**：220 行 / 16 导出，平均每个导出 ~14 行——没有巨型函数或巨型常量块，
  不存在「文件太大」的体量压力。

### 结论与遗留

- DA-07 的「源码热点拆分」至此收口：ResearchView（已拆）、wanzh 列表组装（已拆）
  是真聚合桶；**paper2skills 两文件是内聚工具箱/单一数据源，登记不拆**。
  「导入方多」≠「耦合债」——扇入型热点要先判内聚性再动手（本卡的判型三问
  可复用于后续热点评估：消费方取的是同一契约还是各取子集？拆分后导入边减不减？
  体量是否超压？）。
- 无改动、无提交需求；本判型读数即本卡全部产出。

# DA-36 · 回滚演练（超越哈希核对）

- 优先级：P2
- 状态：`open`
- 依赖：无（建议备份机/隔离环境）
- 估算：M
- 来源：DA-18 只做了只读资产核验（2026-09-22：恢复材料字节完整性成立，但「启动成功、数据兼容性、TCC 授权、恢复剧本实际执行均未验证」）

## Problem

DA-18 的哈希核对证明**材料在**（6/6 备份、42,871/42,871 旧 app 文件、242/242 runtime blob 在 Git），
但**剧本没跑过**。回滚面的真实状态：当前工作目录只有 2/242 旧 runtime 物化，恢复需走 Git 取回 +
切换 vendor 分支 + 重打补丁 + profile 回退——每步都有未验证的假设。逃生路径没演练过的系统
等于没有逃生路径（P-01：看起来合理 ≠ 已验证）。

## 动作

1. 在隔离环境（备份机或本机副本目录，**绝不动生产 profile 与生产 app**）执行 2.0.5 回滚剧本；
2. 按剧本步骤逐项记录：每步的命令、输出、与剧本预期的偏差；
3. 验证回滚后的四件事：app 启动（lifecycle 读数）/ 数据兼容（旧版打开当前 userData）/
   TCC 授权存续 / 补丁面恢复（35 锚）；
4. 偏差与坑写回恢复剧本（T-00）；DA-18 依结论收口「保留可执行回滚」或转 ADR 废弃声明。

## 验收

- 演练环境回滚成功且四件事有读数；或失败点明确（失败也是有价值结论，写回剧本）；
- DA-18 状态收口；恢复剧本（T-00）更新为演练过的版本；
- 生产环境零污染（演练前后哈希核对）。

## 注意

- 本机做的话先全量备份当前 profile/userData——演练失败不能带走生产数据；
- 回滚 DMG 用备份里的 2.4.1（哈希已核对），别下载新的；
- 若演练代价过高（无备份机），可降档为「分步干跑」：每步在副本上验证到「能取回、能就位」为止，
  但必须明确登记「未做端到端」——不许把干跑说成演练（P-01）。

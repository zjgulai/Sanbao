# DA-37 · 生产机读数通道方案设计

- 优先级：P2
- 状态：`done`（2026-09-23：用户拍板现场只读取证；脚本+SOP 落地，弃案记录入卡；目标机读数待采）
- 依赖：无
- 估算：M
- 来源：DA-12 收口时遗留的根本问题（architecture.md §1：「本仓与本研究机都没有到那台机器的读数通道（无 SSH/远程面）」）

## Problem

生产机（2026-09-10 观察为 2.0.4/alpha.1 那台）现状至今未核实——不是懒，是**没有通道**：
无 SSH、无远程面。DA-12 只落了「未核实」的诚实记录。但这个洞不补，每次涉及发行线断言
都要加「生产机现状未核实」的脚注，且升级决策（如 2.0.10 是否已到位）永远是盲区。

## 动作（方案设计为主，不实施）

1. 列候选通道并评估：现场人工读数（SOP 化：一次性脚本 + 截图回传）/
   只读远程通道（macOS 屏幕共享/VNC 只读档）/ 出货侧遥测（更新器 feed 的版本上报——
   注意 DA-10 ③–⑦ 挂起中，依赖其形态）/ 明确弃案；
2. 每个候选给出：成本 / 权限面（凭证红线：凭证不落仓库）/ 读数覆盖（能答哪些问题）；
3. 用户拍板选定后，把方案落 SOP 或 ADR；弃案也落记录（下次不用再想一遍）。

## 验收

- 候选矩阵落盘且用户有拍板记录；
- 选定项落地（SOP/ADR/脚本）；弃案项有一句「为什么不再考虑」；
- architecture.md §1 的「未核实」脚注在拿到读数前不动（P-01：没读数就不改断言）。

## 方案候选（2026-09-23，尚未选择/执行）

| 路径 | 成本与权限 | 能验证什么 | 边界 |
| --- | --- | --- | --- |
| 现场只读取证（推荐） | 用户在目标机执行已审阅命令；无需开放网络端口 | app版本/签名元数据、脱敏生命周期结果、profile依赖名与bundles | 不导出settings/凭据/完整日志；读数回传前人工脱敏 |
| 既有受控远程通道 | 需用户提供准确机器与已授权通道 | 同上，可重复采样 | 本轮无主机地址/通道；不启用SSH/VNC，不新增密钥或权限 |
| 新增遥测 | 产品、隐私、出网和服务维护成本高 | 持续版本/启动摘要 | 非本卡范围，不因取一次读数而新增出网 |
| 放弃当前取证 | 不改变任何系统 | 只能保持“生产机未核实” | 必须由用户确认，不自动宣告与开发机相同 |

本轮只有开发机读取权限，未收到生产机身份或读数；建议先选现场只读取证。
待用户提供目标机/选择通道后继续，不能将方案落笔视为生产现状已验证。

## 注意

- 任何通道方案不得引入凭证落仓库或明文回传（红线 3）；
- 更新器遥测方案受 DA-10 后续步骤牵制——依赖关系要在矩阵里写明，别做成死锁等待。

## 拍板与落地（2026-09-23）

用户拍板：**现场只读取证**。落地件：

- `scripts/production-readout.mjs`（零写入：只读 Info.plist / startup.jsonl 脱敏
  字段 / profile 依赖名+bundles 名；不读 settings/凭据/日志/会话，代码路径可查）；
- `docs/sop/production-machine-readout.md`（操作卡：前置自检 / 执行 / 人工复核
  脱敏面 / 读数能答的问题 / 数据源特性=startup.jsonl 每轮冷启动截断只留最近一次）。

本机自测读数：CFBundleVersion `2.0.10-lute.2.5.0`、signingAuthority
`LUTE Code Signing`、最近一次 healthy 15.9s、41 依赖/42 bundles。

弃案记录（不再考虑，除非前提变化）：
- 既有受控远程通道——无主机地址与已授权通道，不新增 SSH/VNC/密钥；
- 新增遥测——产品/隐私/出网成本高，且依赖 DA-10 挂起步骤，不为一次读数新增出网；
- 放弃取证——不自动宣告生产机与开发机相同。

遗留：拿到并采信一次**目标机**读数后，architecture.md §1 的「未核实」脚注才可更新；
本机自测读数不算目标机读数。

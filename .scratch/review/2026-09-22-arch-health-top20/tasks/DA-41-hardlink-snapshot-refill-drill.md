# DA-41 · 硬链接快照补件演练

- 优先级：P2
- 状态：`done`（2026-09-23，隔离 CLI 补件与原子替换演练已复验）
- 依赖：无
- 估算：S
- 来源：architecture.md §1 已知语义（「file: 依赖的副本是安装时刻的硬链接快照——安装之后新增的文件
  不会自动进去，必须按 files 清单补」）；2026-09-11 preset lint 全失效事故即此因

## Problem

「安装后新增文件须按 files 清单补件」是已知语义，且有过事故（preset lint 全失效：功能静默不生效 +
日志一句 warn）。补件动作的要素齐了：判据有（profile-files-sync）、事故有先例、语义有文档——
但**补件的完整链路**（发现缺件 → 按清单补 → 判据闭环）作为一次连贯操作从未演练。
下次踩到时操作者还是要现想步骤，而硬链接语义下每一步都是坑（cat > 双杀、编辑工具破 inode）。

## 动作

1. 在隔离环境模拟缺件：按 DA-28 同型方法制造一个「源码有、副本缺」状态；
2. 按正确语义补件：tmp+mv 原子替换（**禁用 cat > 与编辑工具直写**）；
3. 闭环验证：`sync-profile --check --loadpoint` 绿 + 装载点哈希与源码一致；
4. 把演练步骤写成 SOP 一页（补件操作卡），挂进相关 SOP 文档（唯一家），本工单只留演练读数链接。

## 验收

- 「制造缺件 → 补件 → 判据绿 → 哈希一致」全链路读数落盘；
- SOP 操作卡入库且被 docs 索引可达（docs-link-integrity 绿）；
- 演练环境恢复（无残留 tmp 文件、无破坏的硬链接对）。

## 注意

- 原子替换后目标 inode 可以变化；验收为源未改、目标哈希正确、旧硬链接别名不被连带覆盖。
- 本次演练仅使用独占临时 profile，不修改生产装载点。
